# 网络代理与恢复 · 实现方案

本文说明代码职责、数据与接口、异常恢复和验证方法。功能范围及用户操作见[需求文档](需求文档.md)。

## 各执行面的行为

### 模型与 Core HTTP

`src/networkroute` 是 Core 进程内网络路由 authority。模型 transport 与 Core 默认 HTTP transport 在每次建立新连接前查询当前 route，不再永久使用 Desktop 启动时继承的陈旧 loopback 代理。loopback 可达性默认最多缓存 2 秒；实际 TCP dial 失败会立即清除对应缓存，使后续安全 retry 无需等待 TTL 即重新探测。对于“loopback 代理 TCP 监听仍存在，但 CONNECT/TLS 链路失败”的情况，auto 策略把该代理标记为 30 秒冷却，冷却期内可使用 system route 允许的 direct；proxy-only 策略和非 loopback 企业代理不会因此静默直连。代理状态在请求发送过程中变化时，Awaken 不盲目重放已经写出请求体或已经开始输出的请求；当前请求按各域的 transport/error 合同收口，下一次安全的新连接使用最新 route。

### 后台网页取材

`src/tools/web_fetch/transport.go` 在初始请求及每次重定向读取当前 route。它独立承担 SSRF、TLS、正文大小与类型检查，不直接复用无目标限制的默认 HTTP transport。代理与合成 DNS 的准入条件、剩余信任边界和回归测试由 [WebFetch 合同](../../04_工具权限与审批/工具发现与执行/实现方案.md#webfetch) 定义。

### MCP

- HTTP/Streamable HTTP/SSE transport 的每次新连接都使用 Core 当前 route；
- pending MCP 的每次连接尝试都会重建 transport；
- system route 或 loopback 可达性 generation 变化时，Core 自动重新启用此前处于 `failed` 的 stdio/HTTP/SSE server；`disabled`、`needs-auth` 和 in-process server 不被改变；
- 已连接的 stdio MCP child 无法原地更新环境变量。route generation 变化时，Manager 先将该 server 标记为 `pending`，阻止新调用进入旧 session，等待当前 tool call 结束后只重建该 stdio child；旧 session 退出不得注销新 session 的工具；
- 新启动、重试或因 route 变化重建的 stdio MCP child 取得当前有效代理环境，并保留 PATH、SystemRoot、APPDATA 等宿主变量；MCP config 中显式 `env` 最后覆盖派生环境。
- Core-owned Outlook in-process MCP 的 Graph 与 OAuth HTTP 请求同样使用当前 route。若 auto 策略下已选中的 loopback 代理在 CONNECT/TLS 阶段失败，Graph `GET/HEAD/OPTIONS` 会在记录代理冷却后用新 route 自动重试一次；POST/PATCH/PUT/DELETE 及附件上传等可能有副作用的请求只记录 route 失败，当次不自动重放。OAuth code exchange/refresh 的凭据 POST 在真正发送前先用不带 header/body 的 `HEAD` 验证同一代理隧道；预检失败后只发送一次真实 POST，因此既可切换到 direct route，又不会重放 authorization code 或 refresh token。代理 route 由代理负责目标 DNS，不拿本机 fake-IP 结果误判远端服务；direct route 则解析并固定单个允许地址完成 TLS 请求，仍拒绝普通私网、loopback 重绑定和 link-local。`198.18.0.0/15` 只作为本机代理/TUN 的 synthetic DNS 地址参与已声明公共 HTTPS hostname 的固定连接，不能作为清单中的 OAuth literal endpoint。普通网络/代理失败不得把仍持有 refresh token 的账号写成 `needs_auth`；只有 provider 明确返回 `invalid_grant` 等重新认证错误或 Graph 明确返回 401 才进入重新授权。

已 connected 的 HTTP/SSE 长连接不会仅因 route 观察变化而强杀，后续新连接动态读取 route；只有环境已过期的 stdio child 按 tool-call 边界安全重建。正在执行的调用不被取消或自动重放；如果它恰好发生在代理切换窗口，当次仍按工具的错误与回读合同收口，安全的后续调用使用新 child。401/OAuth 与网络路由不是同一恢复类型，不能通过切换代理自动伪造重新认证。

### CLI Connector

受管 CLI 的版本探测、状态探测、安装辅助命令、授权、logout 与卸载每次 spawn 都读取 Main 当前派生环境；CLI 资产下载继续使用 Electron 网络栈。route generation 变化时 Main 立即刷新 CLI readiness。已经运行中的授权 child 不会被无条件杀死并重复创建授权流程；若它因切换中断，用户点击重试时新 session 使用最新 route，避免重复 device flow 或外部副作用。

## 代码位置 与验证

- `apps/desktop/src/main/network-route-manager.ts`：操作前校准、60 秒 watchdog、loopback 探测、child 环境派生与 generation；
- `apps/desktop/src/main/network-route-observer.ts`：macOS `SCDynamicStore` 信号与 Windows helper 生命周期；
- `cmd/awaken-network-watch`：Windows registry 变化通知 sidecar；
- `apps/desktop/src/main/runtime-control.ts`、`index.ts`：authenticated Core 热同步与 CLI readiness 刷新；
- `src/networkroute`：Core route policy、NO_PROXY、动态 HTTP proxy 与 child 环境；
- `src/llm/client.go`：模型 transport 接入；
- `src/mcpclient/transport.go`、`manager.go`：MCP transport 与 failed server 恢复；
- `apps/desktop/src/main/cli-connectors/manager.ts`：每次 CLI spawn 获取最新环境。

真实 Desktop 至少分别在 macOS 和 Windows 执行：系统无代理、系统代理开启、代理应用退出但环境仍指向 loopback、监听器恢复、运行中切换五种状态；每种状态验证一个最小模型请求、一个远程 MCP handshake/tool list、一个 stdio MCP child 和一个 CLI status/auth retry。记录 route generation、稳定错误码与外部成功证据，不记录代理凭据或 provider secret。

## 当前支持的实现

Main 把无凭据、版本化的 system snapshot 作为 `AWAKEN_SYSTEM_PROXY_SNAPSHOT` 注入新 Core，并在路由或 loopback 可达性变化时，通过 bearer-authenticated `PUT /v1/control/network-route` 热更新已运行 Core。snapshot 只包含 `schema_version / generation / policy / http / https / observed_at`；系统代理 URL 不允许 userinfo、path、query 或 fragment。控制更新有 32 KiB 上限并拒绝未知字段。
