4. [实施顺序与验收策略](中间区域交互需求包/实施顺序与验收策略.md)：分阶段推进顺序、真实 Desktop 验收链路、AC 矩阵和证据要求。
5. [2026-07-05 失败复盘与反模式](中间区域交互需求包/2026-07-05失败复盘与反模式.md)：`codex/workbench-prd-full-implementation` 分支失败记录、用户反馈、反模式和下次重启条件。

## 稳定结论

- `RunStage -> ExecutionFeed -> ComposerDock` 是中间区域的核心契约。
- `RunStage` 是唯一滚动、定位、overlay、composer 容器。
- `ExecutionFeed` 只承载 narrative / turn。
- composer 形态目前只承认 `center` 和 `dock`。
- 涉及 scroll、anchor、sticky、follow、composer 避让、turn marker 或 return-to-latest 的改动，必须经过真实 Awaken Desktop 验收。
- 2026-07-05 的全量实现分支已因破坏中间区域整体滚动而删除，后续不得复用该分支或在其思路上继续叠补丁。
