# AG-UI / A2UI Runtime Boundary

本文描述 Awaken 当前 protocol boundary。它是实现契约，不是历史记录。

## 核心定位

一句话：Awaken 用 AG-UI-compatible event names 和 payload shape 作为对外事件格式，但 runtime、adapter、SSE server 和 desktop consumer 都是 Awaken 自己实现的代码。

- AG-UI 是 Awaken 对客户端输出的事件格式，不是本项目要运行的服务。
- Awaken 不 vendor AG-UI 外部参考仓库，也不让 Agent Core 直接依赖 AG-UI structs。
- 内部协议是 `AwakenEvent`；外部协议是 `src/protocol/agui` 输出的 AG-UI-compatible JSON events。
- A2UI 目前只作为外部参考，不存在 Awaken 运行时 payload、renderer 或 SDK 集成。
- Awaken 保留自己的内部事件模型，位于 `src/agentcore`。
- 协议 adapter 位于 `src/protocol`。
- `Awaken Design System` 里的组件不知道 AG-UI、A2UI、SSE、Electron 或 Agent runtime。

## 当前事件链路

```text
Agent Core
  -> AwakenEvent
  -> runtime session/event bus
  -> protocol adapter
  -> HTTP/SSE
  -> desktop runtime client
  -> renderer reducer
  -> @awaken/design-system props
```

AG-UI 只出现在协议层和 desktop consumer 边界：

```text
src/protocol/agui
apps/desktop/src/shared/agui.ts
apps/desktop/src/renderer/runtime/agui.ts
apps/desktop/src/renderer/runtime/reducer.ts
```

## Human Gate, Ask User And Artifact Contract

Runtime 人工等待位于：

```text
src/runtime/session.go
src/runtime/run_service.go
```

Tool permission decision 位于：

```text
src/tool/permission.go
src/agentcore/tool_runtime.go
```

当前不再有通用工具审批主路径。新 run 不应产生 `AWAKEN_APPROVAL_REQUESTED` / `AWAKEN_APPROVAL_RESOLVED`，也不应依赖旧 `/approvals/{approval_id}/resolve` API。

当前群发消息审核 flow：

```text
ToolRuntime decides needs_mass_message_review
  -> MassMessageReviewAwaiter.AwaitMassMessageReview
  -> runtime emits MassMessageReviewRequested
  -> desktop shows dedicated mass-message review card
  -> user resolves review
  -> POST /v1/runs/{run_id}/mass-message-reviews/{review_id}/resolve
  -> runtime emits MassMessageReviewResolved
  -> ToolRuntime continues or returns rejected result
```

当前主动提问 flow：

```text
LLM calls ask_user
  -> ToolRuntime validates questions_json
  -> UserQuestionAwaiter.AwaitUserQuestion
  -> runtime emits UserQuestionRequested
  -> desktop shows dedicated user-question card
  -> user answers question
  -> POST /v1/runs/{run_id}/user-questions/{question_id}/answer
  -> runtime emits UserQuestionResolved
  -> ToolRuntime returns tool_result with the answer
```

Artifact event 是 runtime 可见记录，不等于自动写文件，也不能当作可信可执行内容。

Artifact v2 在既有字段之外固定携带：

```text
artifactContractVersion = 2
artifactRole = deliverable | preview | support
producer = <typed tool name>
```

`deliverable` 只代表可以进入最终交付卡的业务主文件，仍须同时满足当前 run、`status=ready`、终态已落盘、受支持扩展名和创建/修改动作。`preview` 用于自动校验 PDF/PNG 与 render 结果，`support` 用于源码、脚本、配置和普通 patch。未知 legacy artifact 由 Core 保守分类；不能明确证明是交付物时一律按 `support` 处理，不改写历史。

Renderer 的最终投影不再把 artifact 映射成 `File Changes`。成功、失败和取消三种 terminal 都可以在最终回答后生成幂等 deliverable bundle；失败与取消只改变提示文案，不会把未 ready 或其他 run 的 artifact 带入。

最终卡片的打开与定位只通过 `{threadId, runId, artifactId}` 发给 Electron Main。Main 必须从 durable transcript 反查 artifact，复验 v2 role、ready、终态、扩展名、OutputRoots、realpath、符号链接边界与普通文件状态，Renderer 不能提交文件路径。

## A2UI Reference Boundary

当前 Awaken 没有 A2UI runtime 实现：

- 不生成 `a2ui_surface` artifact。
- 不保留 Desktop A2UI parser 或 renderer。
- 不执行 generated A2UI action。
- 群发消息审核与主动提问只走各自专用 Desktop card 和 runtime resolve API。

没有明确产品需求前，不要重新引入 generated surface。

## Desktop Consumer Boundary

Desktop 代码位于：

```text
apps/desktop/src/main
apps/desktop/src/preload
apps/desktop/src/renderer
apps/desktop/src/shared
```

职责：

- Electron main 创建窗口，并代理 runtime HTTP/SSE 访问。
- Preload 暴露 `window.awaken`。
- Renderer 创建 run、订阅 run events、取消 run、回答主动提问、处理群发审核，并把 events reduce 成 view state。
- Renderer 把普通 props 传给 `@awaken/design-system`。

Desktop app 可以知道 AG-UI event shape，但 UI library components 不可以知道。

## Awaken Design System Boundary

UI package：

```text
Awaken Design System
```

允许：

- Components。
- Tokens 和 styles。
- 局部组件交互。
- Props 和 callbacks。
- Platform-aware visual affordances。

不允许：

- `fetch`。
- SSE 或 WebSocket。
- Electron IPC。
- `window.awaken`。
- AG-UI 或 A2UI imports。
- Agent runtime logic。
