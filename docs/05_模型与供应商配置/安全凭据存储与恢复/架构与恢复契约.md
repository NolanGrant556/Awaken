# 模型 API key 文件存储与恢复契约

## 1. 权威范围

本文唯一拥有模型 API key 在 `~/.awaken/.env` 的变量身份、读写原子性、权限、错误状态和恢复动作。provider catalog、余额和模型参数见 [模型配置与调用](../模型配置与调用.md)。WebSearch 当前只使用免 key 渠道，不适用本文；MCP OAuth token 仍由 06 域的系统 secrets backend 负责，也不适用本文。

## 2. 当前持久化合同

模型 profile metadata 与 key 分离：

```text
~/.awaken/config/models.json
  profile.id, provider/model, base URL, advanced, keyLast4, ...

~/.awaken/.env
  AWAKEN_API_KEY_<profileId>="完整 API key"
```

`.env` 中 API key 是明文。Awaken 不再使用 Electron `safeStorage`、密文 envelope、macOS Keychain 或 Windows DPAPI 保存模型 key，也不读取旧 `model-profiles.json`。这是当前明确的产品取舍：文件权限可阻止其他本机账号的常规读取，但同一登录用户、具有该用户权限的进程、备份程序或取得磁盘访问权的攻击者仍可能读取 key。不得把 `.env` 加入项目、云盘同步或普通备份，也不得把它附到问题报告；文档和 UI 不得把该文件描述成加密存储。

正式根由 Electron Main 解析为用户主目录下 `~/.awaken`；开发版与安装版共享这份模型配置。`AWAKEN_HOME` 只由 Main 注入 Core；普通继承环境不能改变产品数据根。测试通过构造函数注入临时根和 key store。

`awaken-acp --startup=core` 是同一约束下的机器入口：launcher 移除 client 继承环境中的同名覆盖，并把当前用户主目录下的 `~/.awaken` 固定注入受管 headless Core。Core 的 `src/modelprofile/user_store.go` 只读解析该文件，不写回、不向 ACP client 返回 key。Desktop Main 仍是唯一 writer。

## 3. 变量与文件格式

- 每个 profile 只允许一个 `AWAKEN_API_KEY_<profileId>`；profile ID 必须匹配 `[A-Za-z0-9][A-Za-z0-9._-]*`，防止构造额外 assignment。
- value 用 JSON string 形式序列化，换行、引号和特殊字符不会逃逸为另一项变量。
- 读取兼容无引号、单引号、双引号和 `export KEY=...`；无法解析的任意非空行使整份文件 `unreadable`，不能忽略坏行后继续写。
- 读写保留非 Awaken 变量的值语义，但写回按 key 排序并规范化格式；`.env` 不是保留注释与原始排版的文本编辑器。
- 删除 profile 时删除对应变量；其他 profile 与非 Awaken 变量保留。

## 4. 原子写与 mutation 顺序

`AwakenEnvStore` 的写入步骤固定为：

```text
读取并完整解析当前 .env
  -> 在内存修改一个变量
  -> ~/.awaken 内创建唯一临时文件
  -> 0600 写入
  -> 原子 rename 为 .env
  -> chmod 0600
  -> 清理临时文件
```

所有 key mutation 经进程内 queue 串行化。新建/更新 profile 时先写 key，再写 `models.json`；如果 profile 写失败，恢复此前 key。删除 profile 时先删除 key，再写 profile；profile 写失败同样恢复此前 key。回滚失败必须向上报错，不能宣称操作成功。

`.env` 缺失等同尚未保存任何 key；损坏、权限拒绝或其他读取错误不能当作空文件覆盖。`models.json` 和 `.env` 不构成跨进程事务；当前只支持一个 Desktop Main 作为模型配置 writer。

## 5. 明文边界

API key 当前会存在于：

1. `~/.awaken/.env` 明文文件；
2. Electron Main 的读取调用栈和 `ModelProfileRunConfig`；
3. localhost run request；
4. `awaken-core` 的 `AgentConfig.ModelConfig` 与按 thread 缓存的 Agent；
5. provider Authorization header 的请求构造内存。

当前没有显式 zeroization。以下位置禁止出现完整 key：Renderer profile state、Desktop operation issue、日志、SemanticJournal、thread metadata、lifecycle snapshot、MCP metadata、错误事件或测试快照。Renderer 只接收 `has_key`、基于 `models.json.keyLast4` 的掩码和状态；`keyLast4` 不是认证数据，也不能证明 `.env` 中当前仍有 key。

## 6. 状态与恢复

当前 profile 状态只有：

```text
ready | missing_key | disabled | unreadable
```

- `ready`：profile enabled 且本次实际读取到非空变量；
- `missing_key`：变量不存在或为空；
- `disabled`：profile 未启用；
- `unreadable`：`.env` 解析失败、权限拒绝或读取失败。

跨 IPC 的凭据错误只有 `credential_unreadable`；动作是 `retry` 或在 Models 中重新输入。写入失败、无效 profile ID 和回滚失败使用脱敏的 `operation_failed`，只提供 `retry`。不存在 `temporarily_unavailable`、`credential_save_failed`、relaunch 解密恢复或系统重新认证状态。

provider `401/403`、网络错误和额度错误发生在 key 已读取并进入 provider 层之后，不能改写为 `.env unreadable`。

## 7. 当前不支持

- 不支持从旧 safeStorage/Keychain/DPAPI 密文或旧 `model-profiles.json` 自动导入；
- 不支持 workspace/thread 私有 key、session-only key 或多 Desktop writer；
- 不支持对 `.env` 加密、系统钥匙串托管、主动内存清理或 key rotation；
- 不支持通过 Renderer 导出、复制或读取已保存完整 key；
- 不支持把 `keyLast4` 当成真实 key 存在性的替代检查。

## 8. Owner 与验证

- `.env` 解析、权限和原子 replace：`apps/desktop/src/main/awaken-env-store.ts`。
- `.env` 与 `models.json` 的 ACP/headless 只读消费：`src/modelprofile/user_store.go`；解析必须与本文格式 fail-closed，不能修改文件。
- profile/key 协调：`apps/desktop/src/main/model-profile-store.ts`。
- IPC 错误脱敏：`apps/desktop/src/main/desktop-operation.ts`。
- Core 注入：`apps/desktop/src/main/index.ts`、`cmd/awaken-core/main.go`。

自动化至少覆盖特殊字符 round-trip、非法 profile ID、非 Awaken 变量保留、0600、并发 mutation、损坏文件 fail closed、profile 写失败回滚、template profile key 复制、删除回滚、Renderer 不接收明文：

```bash
npm --workspace @awaken/desktop run test -- src/main/awaken-env-store.test.ts src/main/model-profile-store.test.ts src/main/desktop-operation.test.ts src/renderer/runtime/client.test.ts src/renderer/useComposerLifecycle.test.ts src/renderer/ProfileBalancePopover.test.tsx
npm --workspace @awaken/desktop run typecheck
```

真实 Desktop 使用专用测试 key：保存后检查 `.env` mode 为 `0600`、变量名属于对应 profile；完整重启后测试连接、余额和真实最小 run；删除 profile 后变量消失；日志、Renderer 与 journal 无完整 key。验收证据不得记录 key 内容或真实尾号。
