# 全量无审核工具运行时落地方案

## 文档定位

本文档定义 Awaken 下一阶段的完整工具执行目标：所有工具默认删除审核机制，能力不局限 Work 场景，旧审批/审核设计从代码、协议、Desktop UI、测试和文档中同步删除，并把文件、代码、Office/PDF、媒体、本地计算、MCP、连接器、浏览器/app、多代理和安装包分发统一到同一套运行时架构。

全系统只保留两个强制规则：

1. 删除文件必须进入系统回收站，不允许工具默认永久删除。
2. 涉及调用工具进行群发消息，必须经过人工审核通过后才允许发送。

另外，缺授权不是工具调用审核，但必须弹出授权审核/授权确认，由用户点击授权链接完成账号连接后才允许继续。

本文档建立在以下既有文档之上：

- `docs/04_工具权限与审批/当前规范/零审批自动执行策略与落地路线.md`
- `docs/04_工具权限与审批/当前规范/面向小白用户的零审批Work Agent优化方案.md`
- `docs/04_工具权限与审批/当前规范/工具平台规范.md`
- `docs/04_工具权限与审批/当前规范/Shell内置权限执行器设计.md`
- `docs/08_技能/当前规范/技能规范.md`

本文档以新的产品目标为准：旧审核机制不是迁移到内部，也不是换一套 UI 隐藏起来，而是删除。群发消息人工审核是唯一保留的人工审核 gate，必须单独建模，不能复用旧的通用 Approval Center。

2026-07-07 落地更新：`工具平台规范.md`、Workbench 契约、技能规范、MCP 运行时规范、连接器规范已改写为当前无审核口径；旧 `allow | ask | deny`、`always_ask`、`AWAKEN_APPROVAL_REQUESTED` 和 Approval Center 契约只允许作为历史 transcript 只读兼容说明。

## 硬性决策

Awaken 工具执行只遵守以下规则：

1. 除“工具群发消息”外，所有工具调用不得触发人工审核。
2. 工具调用只能由运行时自动执行、自动转换、结构化拒绝、缺授权进入授权审核、缺 runtime 阻断或不支持阻断。
3. 删除文件一律进入系统回收站，不提供永久删除工具路径。
4. 工具群发消息必须先进入专用人工审核 gate，审核通过前不得调用真实发送接口。

## 落地前事实（历史快照）

### 已经具备的基础

- `src/tool/profile/profile.go` 已有 `ExecutionProfile`，包含 approval、permission、sandbox、network、env、visibility 等字段。

- `src/agentcore/tool_runtime.go` 仍保留 `awaitApproval()` 兼容路径。
- `src/tool/permission.go` 仍把 destructive / unknown side-effects 默认转为 `AskPermission`。

- `docs/04_工具权限与审批/当前规范/工具平台规范.md` 仍要求 `ask` 发出 `AWAKEN_APPROVAL_REQUESTED`。

- 当前 `apps/desktop/electron-builder.yml` 只把 `resources/bin` 打进安装包，实际只有 `awaken-core`。

- Word/Excel/PPT/PDF 等能力不能依赖开发机上的 Codex runtime cache，也不能把 Python/Node/依赖源码复制进 Awaken 仓库。
- `read_artifact` 能读部分文件，但缺少完整的 create/edit/render/inspect/export typed artifact tool 链。

## 目标状态

### 用户体验目标

- 普通任务过程中不出现工具审核卡片。
- 文件增删改查、代码修改、Office/PDF 产物生成、图片/视频处理、本地受限计算、MCP/connector 调用都能在内建边界内自动执行。
- 删除文件默认进入系统回收站，用户不需要为普通删除动作审核。
- 工具群发消息必须出现专门的人工审核确认，审核通过后才发送。
- 不能安全执行时，系统直接说明原因，例如越界、敏感路径、缺授权、缺 runtime、平台不支持。
- 用户始终能看到执行记录、文件改动、被拒绝动作、transform 结果和产物位置。

### 工程目标

- 删除旧审批/审核主路径，而不是把审批卡片隐藏起来。
- 删除 `ask`、`always_ask`、`ApprovalPolicy`、`UseApprovalForAsk`、`awaitApproval()` 等现有审核机制。
- 增加独立的 `MassMessageReviewGate`，只服务于工具群发消息。
- 所有工具进入统一 `CapabilityRouter -> PolicyEngine -> Executor` 链路。
- Work runtime 作为 Awaken runtime asset 分发，不进入项目源码，不依赖用户本机环境。
- 打包后的 Awaken 在一台没有开发环境的机器上也能完成核心文件与产物任务。

## 非目标

- 不追求“所有系统级危险动作都自动执行”。
- 不把 OAuth、系统权限、runtime 安装这类用户设置流程伪装成工具审核。
- 不保留“内部 ask / 内部审核 / 高信任时再审批”这类通用审核影子机制。
- 不默认给第三方 MCP 文件桥、全盘读写或开放网络权限。
- 不把 shell 作为通用 Work 入口。
- 不把 Codex/Claude 的源码、Node/Python 依赖树、缓存目录 vendor 到 Awaken 仓库。

## 新执行决策模型

### 对外决策

用户可见和 agent 主路径只保留：

- `allow`：直接执行。
- `deny`：拒绝执行，返回结构化原因。
- `transform`：自动改写为更安全的工具或执行器后执行。
- `needs_auth`：缺授权，弹出授权审核/授权确认，由用户点击授权链接完成账号连接。
- `needs_runtime`：缺本地 runtime，进入安装/修复流程。
- `unsupported`：平台或能力暂不支持。
- `needs_mass_message_review`：仅当工具将执行群发消息时进入人工审核。

### 禁止保留的通用审核信号

以下机制必须从新主路径中删除，不能以“内部信号”名义长期保留：

- `PermissionAsk`
- `AskPermission`
- `PolicyAlwaysAsk`
- `always_ask`
- `ApprovalPolicy`
- `UseApprovalForAsk`
- `awaitApproval()`
- 通用 `ApprovalRequest`
- 通用 `AWAKEN_APPROVAL_REQUESTED`
- 通用 `AWAKEN_APPROVAL_RESOLVED`
- 通用 `/approvals/{approval_id}/resolve`

文件写入、shell mutation、第三方 MCP 高风险能力、系统级能力等风险，不再返回 `ask`。它们只能被决策成：

- `allow`
- `deny`
- `transform`
- `needs_auth`
- `needs_runtime`
- `unsupported`

### 唯一人工审核 gate

工具群发消息是唯一保留的人工审核场景。

群发消息包括但不限于：

- 向多个联系人发送同一条或批量生成的消息。
- 向群聊、频道、邮件列表、客户列表、员工列表发送消息。
- 通过 DingTalk、飞书、企业微信、微信、邮件、短信、CRM、工单系统、社群工具、机器人 webhook 批量通知。
- 由 connector/MCP/browser/app 自动触发的批量站内信、评论、私信、邀请、催办、DING、通知。

不属于群发消息的动作不能借用这个 gate。它们要么自动执行，要么拒绝，要么要求用户先完成授权/安装/设置。

群发审核 gate 的要求：

- 必须展示接收对象范围、数量、渠道、消息正文或模板、附件、发送账号、触发工具。
- 审核通过前不得调用真实发送接口。
- 审核拒绝后不得自动重试发送。
- 审核通过只对当前这一次群发有效，不形成长期工具授权。
- 该 gate 必须与旧 Approval Center 分离，不能复用 `ApprovalCard`、`AWAKEN_APPROVAL_REQUESTED` 或旧 `/approvals` API。

## 全量能力链

### 1. 文件与代码链

覆盖：

- `list_files`
- `grep_search`
- `file_read`
- `apply_patch`
- 新建、修改、移动、重命名、删除
- 代码格式化、测试、构建的受控入口

规则：

- 默认自动执行。
- 写入必须落在 `writable_roots` 或 `output_roots`。
- 删除必须走 TrashAdapter。
- symlink 逃逸拒绝。
- 敏感路径拒绝。
- 能用 `apply_patch` 的文件变更不走普通 shell。

### 2. Office/PDF/媒体 Artifact 链

覆盖：

- 表格：`xlsx`、`xls`、`csv`、`tsv`
- 文档：`docx`、`md`、`txt`
- 演示：`pptx`
- PDF：提取、渲染、拆分、合并、导出
- 图片：查看、裁剪、转码、基础分析
- 音视频：元数据、转码、抽帧、字幕、压缩
- 压缩包：列出、解压到任务目录、打包输出

规则：

- 二进制文件不走 `read_file` 猜内容。
- 产物创建、编辑、渲染、检查、导出都通过 typed artifact tools。
- 每类 artifact executor 都必须有 inspect/render/verify 能力。
- 复杂格式允许调用本地受限计算链，但不暴露为任意 shell。
- 结果默认写入 `output_roots`，没有输出根时写入 workspace 下明确的 `output/` 或任务产物目录。

第一批 typed tools：

- `workspace_dependencies`
- `runtime_preflight`

- `artifact_inspect`
- `artifact_render`
- `artifact_export`
- `spreadsheet_create`
- `spreadsheet_edit`
- `spreadsheet_chart`
- `document_create`
- `document_edit`
- `document_render`
- `presentation_create`
- `presentation_edit`
- `presentation_render`
- `pdf_extract`
- `pdf_render`

### 3. 本地受限计算链

覆盖：

- Python
- Node
- LibreOffice
- Poppler
- ffmpeg
- pandoc
- 受控临时脚本

规则：

- 它不是普通 shell。
- 只可访问 TaskScope 内的 readable/writable/output/temporary roots。
- 默认不联网。
- 默认最小环境变量。
- 所有依赖来自 Awaken runtime asset。
- 用户机器没有 Python/Node/LibreOffice 时也应能运行。

### 4. Shell 与工程命令链

覆盖：

- 只读环境检查。
- 代码项目测试、构建、格式化。
- 包管理器只读或受限操作。
- 少量不可替代的工程命令。

规则：

- shell 是兜底能力，不是普通 Work 主路径。
- `inspect_read_only` 可自动执行。
- 文件写入类 shell 优先 transform 到文件链。
- open-world/system 命令默认 deny。
- 不能用“高信任审批”绕过工具审核删除目标；需要扩权的能力必须进入显式配置、独立产品开关或后续新能力设计，但不能回到单次工具审核。

### 5. 外部系统工具链：钉钉、飞书、Outlook 与第三方 MCP

本段约束的是“会访问 Awaken 之外系统的工具”。

定义：

- 钉钉连接器：使用钉钉对应的官方 CLI，即 GitHub `DingTalk-Real-AI/dingtalk-workspace-cli`。
- 飞书连接器：使用飞书/Lark 对应的官方 CLI，即 GitHub `larksuite/cli`。
- 邮件连接器：默认使用 Outlook MCP。用户只需要点击授权链接完成 Outlook 账号授权。
- 第三方 MCP：用户或项目自己接入的 MCP server，来源、权限边界和数据处理方式不由 Awaken 官方完全控制。
- 文件桥：允许外部系统工具读取、上传、下载、转换本地任务文件的通道。
- 云盘、在线文档不作为 Awaken 默认内建连接器；如果钉钉/飞书 CLI 本身暴露相关能力，也必须按钉钉/飞书连接器的 TaskScope 与能力开关约束，不能作为独立默认连接器放开。

覆盖：

- 钉钉 CLI。
- 飞书/Lark CLI。
- Outlook MCP。
- 用户自接第三方 MCP。
- OAuth / API key 授权审核与恢复。
- 外部系统读写。
- 通讯、日程、任务、表格、邮件等业务系统能力。

规则：

- 读写能力必须按 CapabilityClass 注册，不再只靠 `readOnly/destructive/openWorld` 三个粗标签。
- 缺授权返回 `needs_auth`，弹出授权审核/授权确认。
- 第三方 MCP 默认没有本地文件桥。
- 钉钉、飞书、Outlook 可以申请文件桥，但仍受 TaskScope 限制。
- 外部系统写入不能走通用审核。
- 群发消息必须进入专用人工审核 gate。
- 非群发的外部系统写入只有两种结果：在明确配置允许的范围内自动执行，或直接结构化拒绝。
- 远端删除、发布、提交、通知等能力如果没有明确配置允许，直接结构化拒绝；不得弹通用审核卡。

建议 CapabilityClass：

- `artifact_read`
- `artifact_write`
- `local_transform`
- `connector_read`
- `connector_write`
- `browser_read`
- `browser_interaction`
- `mass_message_send`
- `external_publish`
- `system_operation`

建议 TrustedOrigin：

- `builtin`
- `official_connector`
- `official_hosted`
- `user_mcp`
- `project_mcp`

### 6. 浏览器与本地 App 链

覆盖：

- 浏览器页面读取。
- 登录态站点操作。
- 本地 App UI 操作。
- 文件选择、导入、导出。

规则：

- 浏览器只读和浏览器交互分开。
- 本地 App 操作需要明确目标 app 与任务边界。
- 不能把浏览器/app 操作混同为 shell 权限。
- 浏览器/app 链触发群发消息时，必须进入专用人工审核 gate。
- 对外提交、删除、购买、付款等非群发高风险动作默认 deny 或要求用户手动完成，不能回到通用审核。

### 7. 多代理链

覆盖：

- 普通 subagent。
- researcher/planner/operator/reviewer。
- guardian/review agent。

规则：

- 普通 subagent 继承父 run 的 TaskScope 与 ExecutionProfile，不可扩权。
- reviewer/guardian 强制只读。
- 子代理不能绕过敏感路径、回收站、runtime preflight 和 connector trust gate。
- 子代理不能通过 MCP 或 shell 获得父代理没有的文件桥。

### 8. 安装包与运行时资产链

覆盖：

- `awaken-core`
- Work primary runtime
- Python/Node/native dependencies
- artifact helper scripts
- LibreOffice/Poppler/ffmpeg 等 native assets
- runtime manifest 与 checksum

规则：

- Awaken 仓库只保留 manifest、构建脚本、wrapper tools 和少量模板。
- 大型 runtime asset 由 CI 构建，作为安装包资源或首次下载资源。
- 安装后 runtime 解压到 Desktop `userData`，不写入只读/签名 app bundle。
- 运行前必须 preflight。
- 缺 runtime 时工具不暴露给 LLM，UI 显示准备/修复 runtime，而不是让工具执行失败。

推荐路径：

```text
macOS:
~/Library/Application Support/@awaken/desktop/runtimes/primary-runtime/<version>/

Windows:
%APPDATA%\@awaken\desktop\runtimes\primary-runtime\<version>\
```

推荐环境变量：

```text
AWAKEN_RUNTIME_ROOT
AWAKEN_RUNTIME_MANIFEST
AWAKEN_RUNTIME_DEPENDENCIES
AWAKEN_WORKSPACE_DEPENDENCIES
AWAKEN_USER_DATA_DIR
```

## TaskScope 契约

每个 run 必须携带完整 TaskScope：

```text
scope_id
workspace_root
readable_roots
writable_roots
output_roots
protected_roots
attached_files
connector_resources
temporary_work_root
execution_profile
```

规则：

- 用户拖入或选择的文件默认进入 `readable_roots` 或 `attached_files`。
- 用户明确要求修改某个外部文件时，该文件所在路径必须被加入本次 `writable_roots` 或变成明确 output target。
- 所有 artifact 生成必须先确认 output target 在 `output_roots`。
- 临时文件只能写入 `temporary_work_root`。
- `protected_roots` 永远优先于 writable。

## 删除语义

### 普通删除

普通文件删除一律进入系统回收站：

- `apply_patch` delete。
- 文件管理工具 delete。
- artifact executor 覆盖前删除。
- 任务产物清理。
- connector 下载到本地后的落地文件删除。

### 目录删除

目录删除也应进入系统回收站。若当前平台 adapter 只支持文件，则第一阶段必须 fail-closed，并返回结构化 `unsupported_directory_trash`，不得回退到永久删除。

### 永久删除

永久删除不属于 Awaken 工具路径。

即使用户明确要求“永久删除”，Agent 工具也不得执行永久删除。系统应返回结构化拒绝，提示用户如确需永久删除，应离开 Agent 工具链，在操作系统中自行处理。

## 旧审批设计删除清单

### Runtime / Agent Core

- 删除 `UseApprovalForAsk`。
- 删除 `awaitApproval()` 主路径和新 run 可达路径。
- 删除 `PermissionAsk` / `AskPermission` 主路径。
- 删除 `ApprovalDecisionApproved/Rejected` 新 run 主路径。
- run status 删除 `awaiting_approval` 主状态。
- `ToolDecision` 和 `ExecutionDecision` 增加 `needs_auth`、`needs_runtime`、`unsupported`、`needs_mass_message_review` 或等价结构化结果。
- 新增群发消息专用审核状态，但不得复用旧通用 approval 状态。

### Tool / Policy

- 删除 `PolicyAlwaysAsk` 和 `always_ask` override。
- `Decide()` 默认不再返回用户审批语义。
- destructive 不等于 ask，而是进入 capability/profile/task-scope 决策。
- shell 不再返回 `AskPermission`。
- apply_patch 不再返回 `AskPermission`。

## Work Runtime 分发方案

### 推荐默认：混合分发

安装包内置：

- `awaken-core`
- runtime manifest
- 最小 preflight/installer
- 小型核心工具

首次使用或首次启动下载：

- Python runtime
- Node runtime
- native dependencies
- Office/PDF/media helper tools
- artifact tool packages

企业/离线版：

- 将完整 primary runtime 作为安装包 `extraResources`。
- 首次启动复制/解压到 userData。
- 仍按 manifest 校验，不直接从 app bundle 执行可变依赖。

### electron-builder 调整

当前只复制：

```yaml
extraResources:
  - from: resources/bin
    to: bin
```

目标增加：

```yaml
extraResources:
  - from: resources/bin
    to: bin
  - from: resources/runtime-manifest
    to: runtime-manifest
  - from: resources/runtime
    to: runtime
    filter: ["**/*"]
```

若使用首次下载，则只带 `runtime-manifest`，不带完整 `resources/runtime`。

### runtime_preflight

启动或首次任务前执行：

- manifest 是否存在。
- runtime version 是否匹配。
- checksum/signature 是否通过。
- Python/Node/native binaries 是否存在且可执行。
- LibreOffice/Poppler/ffmpeg 是否可用。
- artifact helper package 是否可 import。
- `workspace_dependencies` 是否能返回完整路径。

失败时：

- 对应 typed tools 不注册给 LLM。
- UI 显示准备/修复 runtime。
- agent 收到 `needs_runtime`，而不是工具失败堆栈。

## 验收矩阵

### 基础文件任务

- 新建文本文件，无审核。
- 修改代码文件，无审核。
- 删除文件，进入回收站，无审核。
- 移动/重命名文件，无审核。
- 写出 workspace 被拒绝。
- 写 protected root 被拒绝。
- symlink 逃逸被拒绝。

### 代码任务

- 修改代码后运行测试。
- 格式化代码。
- shell 只读检查自动执行。
- shell 文件写入被 transform 或拒绝。
- open-world/system shell 被拒绝。

- Excel/CSV 读取、分析、写出、验证。
- Word 创建、编辑、渲染、检查。
- PPT 创建、编辑、渲染、检查。
- PDF 提取、渲染、拆分或导出。
- 图片 inspect/convert。
- 视频 probe/抽帧/转码。
- 输出文件落在 output root。

- 开发机 runtime 可发现。
- packaged app runtime 可发现。
- runtime 缺失时工具不暴露。
- runtime 修复后工具恢复。
- 不依赖 Codex cache。
- 不依赖系统 Python/Node。

- 已授权外部系统读取工具自动执行。

- 首次下载或内置 runtime 校验通过。

## 风险与处理

### 风险 1：把通用审核删掉后危险动作被放大

处理：

- 不用通用 approval 兜底。
- 用 deny/transform/profile/sandbox/TaskScope/sensitive path 兜底。
- 高风险动作默认不可自动执行。
- 群发消息保留专用人工审核 gate。

### 风险 2：Work runtime 包太大

处理：

- 默认混合分发。
- 完整 runtime 只做离线/企业版。
- 按能力懒加载。

### 风险 3：第三方 MCP 权限不可控

处理：

- TrustedOrigin 分层。
- 第三方默认无文件桥。
- 外部发布/删除远端数据默认不自动执行。
- 群发消息不管来源是否官方，都必须人工审核。

### 风险 4：旧 transcript 里有 approval event

处理：

- 保留历史只读渲染。
- 不保留新交互入口。
- 迁移后新 run 不再产生 approval event。
- 群发审核事件使用新命名与新 payload，不复用旧 approval event。

### 风险 5：平台 sandbox 能力不一致

处理：

- 上层 contract 统一。
- adapter 分平台。
- 缺可信隔离时 fail-closed 或降级为 deny。

## 最终完成定义

Awaken 完成这轮全量任务时，应满足：

- 用户在普通任务中不再看到审核卡。
- 删除默认进回收站。
- 工具群发消息必须人工审核通过后才发送。
- 文件、代码、Office/PDF、图片、视频、本地计算、外部系统工具、浏览器/app、多代理都进入同一套无审核运行时边界。
- Work runtime 不依赖开发机、不依赖 Codex cache、不 vendor 依赖源码。
- 打包安装给别人后，Awaken 能自检、安装或发现 runtime，并在能力可用时自动执行。
- 不能执行的动作给出清晰原因，而不是把判断推给用户审核。
