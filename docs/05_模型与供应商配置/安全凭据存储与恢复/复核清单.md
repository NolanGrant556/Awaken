# 安全凭据存储与恢复复核清单

## 代码边界

- [ ] 只有主进程凭据适配层直接依赖 Electron `safeStorage`。
- [ ] 模型运行、余额、保存、测试均通过同一异步凭据接口。
- [ ] 没有同步 `safeStorage` 前置判断或明文 fallback。
- [ ] 应用名称、application ID、bundle ID 与 `userData` 位置有稳定常量和回归测试。

## 数据安全

- [ ] 临时不可用、解密失败和迁移失败均保留原密文。
- [ ] 新密文成功并原子持久化后才替换旧密文。
- [ ] API key 和密文不进入日志、错误、transcript 或 Renderer；`last4` 只允许用于明确的掩码展示。
- [ ] 不存在 session-only 或 workspace 级 API key 降级路径。

## 恢复体验

- [ ] 常规恢复不要求用户打开 macOS 钥匙串访问或 Windows 凭据管理器。
- [ ] 临时不可用提供受控 relaunch，而不是同进程无效重试。
- [ ] relaunch 后仍失败可直接跳转到 Awaken 模型设置重新录入。
- [ ] 安全保存失败时明确显示“未保存”，且旧的全局密文保持不变。
- [ ] 余额面板不重复显示每个 provider 的底层系统错误。

## 自动化

- [ ] legacy sync ciphertext 可由 async decrypt 读取。
- [ ] temporary unavailable 被分类为可恢复状态。
- [ ] permanent/corrupt 被分类为重新录入状态。
- [ ] `shouldReEncrypt` 完成安全的先写后换。
- [ ] 安全写入失败的新 key 不落盘、不进入日志或 transcript。
- [ ] IPC 不泄露 Electron 原始异常前缀。
- [ ] macOS/Windows contract tests 均覆盖。

## 真实 Desktop

- [ ] `npm run close:desktop` 后通过 `npm run open:desktop` 启动正式入口。
- [ ] 在 Settings > Models 保存一个测试 profile。
- [ ] 重启后确认 key 可读取且模型状态正确。
- [ ] 余额查询成功或返回 provider 自身的真实错误。
- [ ] 发送真实 prompt，确认请求越过凭据层并到达 provider。
- [ ] 模拟安全存储临时不可用，确认 UI 只提供 Awaken 内恢复动作。
