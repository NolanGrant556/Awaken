# 协议域验收规范

## 1. 权威范围

本文只拥有协议域验证矩阵。事件、route 和 cursor 的预期必须引用本目录相应权威文档，不能在检查清单中重写一套协议。

## 2. 静态一致性

- 从 `src/protocol/agui/events.go` 提取的 event type 和 JSON tags 与 [事件与字段契约](./事件与字段契约.md) 一致。
- `src/server/router.go` 的已注册 route 与 [HTTP 与 SSE 接口契约](./HTTP与SSE接口契约.md) 一致；保留但未注册的 handler 不进入 route 清单。
- Go producer 和 `apps/desktop/src/shared/agui.ts` 的差异要么修复，要么继续列在漂移表，不得静默删除缺口。
- 全库不得把固定 8787、旧通用 Approval、A2UI renderer 或 Skill activation wire 写成当前 Desktop 事实。
- `src/agentcore` 不依赖 `src/protocol/agui`；Design System 不依赖协议、SSE 或 Electron。

## 3. 自动化

至少运行：

```text
go test ./src/protocol/agui ./src/server ./src/runtime
go vet ./src/protocol/agui ./src/server ./src/runtime
npm run typecheck:desktop
```

关键断言：

1. 所有 mapper event family 的 type 和 family-specific 字段正确。
2. reasoning start/finish、assistant durable message 和 tool call 多帧顺序稳定。
3. encoder 的 `id:` 优先 `streamCursor`。
4. `after_cursor` 与兼容 `after_seq` 结果一致；在多帧记录中间重连不丢后续帧。
5. transcript + live SSE 不重不漏文本、工具结果和 terminal。
6. unknown event 保留诊断信息且不破坏 stream。
7. runtime supervisor 使用动态 loopback 端口并把地址传给 core。

## 4. 真实 Desktop 验收

按根 README 打开正式 Desktop，只读确认：

1. 运行中实际 runtime base URL 来自 supervisor，不假定 8787。
2. 发起多轮任务并在文本、reasoning、tool、artifact 和 terminal 事件后观察 reducer 投影。
3. 在允许的测试环境中断开并恢复 event stream，确认同一 run 续传且无重复最终回答。
4. 重启 Desktop 后打开 thread，确认 transcript 重放与上一轮 live 叙事一致。
5. 主动提问和群发审核仅走各自专用 UI；新 run 不出现通用 ApprovalCard。
6. 不存在 A2UI surface 或 generated action 产品入口。

协议字段本身不能只靠肉眼验收；Desktop 结果必须与捕获的 SSE frame 和 Go 测试共同成立。

## 5. 完成门槛

只有 wire producer、耐久 projector、SSE resume、TypeScript consumer 和真实 Desktop 投影形成同一条证据链，且已知漂移未被误写为支持时，才能宣称协议域验收完成。
