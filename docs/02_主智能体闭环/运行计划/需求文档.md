# 运行计划 · 需求文档

主智能体可以维护当前运行的步骤和进度。用户能看到实时计划与运行结束时的历史，计划不等同于个人待办或定时任务。

代码、接口和验证方法见[实现方案](实现方案.md)。

## 实现状态与名称

Workbench 通用布局仍由 [01 中间区域产品与交互契约](../../01_桌面工作台/工作台布局与运行展示/需求文档.md) 拥有，SemanticJournal、工具与 wire 的通用合同分别由 03/04/09 域权威拥有；这些文档只链接本能力，不复制字段和状态定义。

用户截图中的能力更准确地应称为“运行计划”或“任务进度”，而不是传统意义上的 Todo List：

- 它由 Agent 为当前 thread 内的复杂任务建立和更新，用来说明“这项任务打算怎么做、现在做到哪一步”；
- 它不是用户手动维护的跨项目个人待办，不含日期、提醒、优先级或独立导航；
- 产品文案统一使用“计划”、“步骤”和“进度”；代码层使用 `plan` / `plan item`，不使用容易与定时任务、Subagent task 或个人待办混淆的泛化 `task` 名称。

## 当前事实

### 当前支持

Awaken 当前支持截图所示的主 run 运行计划：

- root Agent 可通过内建 `update_plan` 原子创建或替换当前 run 的 1–12 个有序步骤；Subagent child 不暴露该工具；
- Core 以 `plan_updated` 全快照 journal-first 持久化，生产 live recorder 只在 append 与 flush 均成功后发布；版本冲突或持久化失败不移动内存快照；
- `AWAKEN_PLAN_UPDATED` 由同一个 semantic projector 服务 live/replay，Desktop 保留各 run 的耐久事实，并为当前 thread 选取最新快照；
- 计划的 live projection 只显示在 ComposerDock 进度入口和 RunStage overlay；暂停、继续和任务调整在同一位置更新，不进入“执行过程”。成功 run 的完成态保留 5 秒后从 Composer 消失，耐久快照仍保留用于审计和重放；
- 成功 `update_plan` 不重复显示通用 Tool row；失败且没有 receipt 的调用仍保留可诊断错误行；
- 计划面板与上下文用量、Subagent 详情、媒体预览互斥；主动提问、外部授权和 Computer gate 仍位于 ComposerDock，计划面板按完整 composer 实测高度上移，不覆盖 gate。

当前不支持用户手动编辑、依赖 DAG、owner、提醒、优先级和独立待办中心；这些仍属于 [产品目标与非目标](需求文档.md#产品目标与非目标) 的非目标。Core 仍为每个 root run 生成自己的 plan ID，跨 run 连续性由 Desktop 选取 thread 内最新耐久快照提供，不伪造一个 Core 共享可变计划。窄窗、深色、reduced motion、跨重启和第二个模型 profile 的连续人工证据仍是验收缺口，不应写成已通过。

### 与现有能力的边界

| 现有能力 | 与运行计划的关系 |
| --- | --- |
| `planning` 占位 | 只告知“Agent 正在等待下一段输出”，不复用为计划清单 |
| 原生 Subagent 任务组 | 表达 child execution 生命周期，不代表 root 的用户目标分解 |
| 定时任务 | 是跨时间调度和执行历史，不是当前 run 内的步骤进度 |
| ACP plan update | 是外部 Agent protocol 事实；首版不与主 Agent 计划合并 |
| 工具轨迹 / Activity Batch | 回答“已经做了什么”；运行计划回答“目标分成哪些步骤、现在在哪一步” |

## 产品目标与非目标

### 目标

1. 复杂 run 开始后，用户能在不阅读工具日志的情况下看懂整体步骤。
2. Agent 在开始、完成或调整步骤时实时更新，界面原位收口，不制造重复 Tool row。
3. 计划是耐久的任务进度事实；暂停、续跑和重连恢复未完成状态，成功完成的历史快照继续可审计，但超过完成 grace 后不再占据 Composer 上方的当前任务位置。
4. 计划只是进度表达，不改变工具权限、执行顺序、Subagent 调度或 run 终态。
5. 底部紧凑入口接近截图的“第 N/M 步”形态，展开后显示完整清单。

### 首版非目标

- 用户手动新建、勾选或拖拽步骤；
- 跨 thread / 跨项目的长期待办中心；
- 截止日期、提醒、优先级、标签或搜索；
- 依赖 DAG、owner 或根据计划自动 spawn/cancel Subagent；
- 将步骤状态解释为实际副作用已完成；工具 Outcome、文件修改和终态仍有各自 authority；
- 将 ACP plan 与主 Agent plan 混成一张表；
- 在步骤上展示虚假百分比或 ETA。

## 用户操作

### 何时建立计划

`update_plan` 对 root Agent 可用，但不强制每个 run 调用。默认在以下情况使用：

- 需要 3 个或以上可区分的实施/调查/验证步骤；
- 用户一次给出多个要求；
- 任务会持续较长时间，或需要在修改、构建、验证之间保持进度；
- 用户明确要求计划、步骤或进度清单。

纯信息问答、单步命令、局部小修改不建计划，避免 UI 和上下文噪声。

### 底部进度入口

当 dock 形态的当前 thread 存在 plan snapshot 时，`ComposerDock` 的 `composer-dock-stack` 在 ComposerBar 上方显示一个可聚焦的紧凑入口：

- 进度数字使用 `completedCount + 1` 作为当前步，全部完成时显示 `M/M`；
- 文案优先使用当前 `in_progress.activeForm`，缺失时使用 `step`；
- 只显示确定计数，不根据 token、工具数或时间猜百分比；
- 入口是 composer stack 的实测内容，其高度必须进入已有 composer inset、feed bottom reserve、marker 和 return-to-latest 计算；
- 入口最小高度为 44px，保持紧凑但不能退化成难以点击的细条；
- 不得绕过 `RunStage` 创建 fixed window，不得把入口放入 `ExecutionFeed`。

center 空态没有 plan snapshot 时不显示计划入口。文件工作区覆盖期间仍复用同一 ComposerDock；进度入口可见，但不改变 `ExpandedFileComposer` 的五态和草稿 owner。

### 展开面板

点击或用 Enter/Space 激活进度入口后，在 `RunStage.overlay` 显示完整计划：

- overlay 外层 pointer-through，面板本体 pointer-auto；
- 面板底部与实测 `composerContentInsetPx` 保持 12px，宽度不超过 640px；
- 高度不超过 RunStage 可用高度和 360px 中的较小值，超出后只滚动面板 body；
- 步骤按快照顺序显示：已完成为勾选图标和减弱文字，进行中为旋转/动态圆环和强调文字，待处理为空心图标；
- 面板为只读，不在首版提供用户勾选、重排或删除；
- Escape、点击面板外或再次激活入口关闭，关闭后焦点回到触发器；
- 展开/收起不改变 feed 高度、follow 意图、prompt anchor、marker 或 Composer 测量。

### 更新和收口

- 首次成功 `update_plan` 后入口出现；快照更新时行原位变化，不重放整张卡片入场动画；
- 完成项数不得在未有新快照时由 Renderer 乐观增加；
- 用户取消、中断或 run error 时，入口留在原位，当前 `in_progress` 行显示“已暂停”且停止动画，不修改耐久三态快照；
- 同一 thread 启动继续 run 时，未完成旧快照不清空；上一 run 已完成时，新 run 在尚未发布自己的 `plan_updated` 前不得重新显示旧 `M/M`；
- 全部项变为 `completed` 后，入口显示 `M/M · 计划已完成`；Agent 仍在生成最终回答时继续显示，只有 `run finished` 才启动 5 秒 grace；
- grace 内收到更高 plan version 或新的 plan ID 时取消旧隐藏计时，新快照立即重新出现；grace 到期且仍是同一完成快照时关闭面板并隐藏入口；
- 完成态提供独立的“隐藏已完成的运行计划”按钮，用户可立即隐藏当前 version；更高 version 仍会重新出现；
- terminal replay 或重启恢复时，若 `max(plan.updatedAtMs, runCompletedAtMs) + 5s` 已过，完成态在首次绘制前保持隐藏，不闪现旧计划；
- 计划不得创建 `RunNarrativeItem`，不进入 turn body 或“执行过程”，也不在 terminal 时复制第二份卡片；
- 完成计划不代替 `run_terminal=finished`，运行终态也不自动完成计划。

### 可访问性和窄窗

- 入口的可访问名称包含完成数、总数和当前步骤；
- 每项通过文本同时表达“已完成/进行中/已暂停/待处理”，不只依赖颜色和图标；
- 运行中键盘顺序只增加一个触发器；短暂完成态可再增加一个明确命名的隐藏按钮，只读步骤本身不造成 N 个无意义 tab stop；
- `prefers-reduced-motion` 下进行中图标使用静态强调；
- 窄窗面板宽度退化为 RunStage 可用宽度减 safe margin，步骤文字换行，不水平滚动。
