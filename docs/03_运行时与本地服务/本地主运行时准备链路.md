# 本地主运行时准备链路

## 1. 两个不同概念

Awaken 必须区分：

- `ExecutionEnvironmentSnapshot`：每个 run 对当前用户机器和进程 PATH 做只读、有界观察；
- primary runtime：由 Awaken 下载/校验/激活的受管依赖 revision，是一个高可信 provider 依赖源。

环境快照不会安装、修改或 attestation 任何用户机器工具；primary runtime 也不遮蔽用户机器、MCP、Connector 或其他 provider。工具可用性快照把两者的观察与具体 provider manifest 合并，最终 readiness 由 provider 自己报告。

## 2. 环境观察

当前快照记录 OS/arch/native architecture/translation、shell、workspace/cwd、最多 128 个 PATH 诊断 entry、完整 PATH 的 digest/entry count/truncated 状态、可执行文件位置和可选版本、可用包管理器，按 proxy/auth/runtime 分类且只记录变量名称的 references，以及 workspace 内非 symlink 的 venv、node_modules、manifest/lock/version markers、confidence 与 warnings。完整 transport PATH 只在当前进程内随快照固定，不序列化进模型、日志或 receipt；snapshot identity 绑定其 digest，真实 Shell 不因诊断预览有界而截断 PATH。快照还记录最多 64 个带 source 的本地 Skill 绝对路径根元数据、TaskScope 临时执行根和 refresh reason；这些字段进入 snapshot identity 和 run 上下文投影，但探测不读取、preload 或执行 Skill 包。

探测不 source shell rc，不记录环境变量值；PATH lookup 可解析 symlink 时快照保存 canonical real path，`PathIndex` 仍指向原 lookup 目录。单个版本探测默认 750ms，同一 executable fingerprint 使用短期缓存。`--version` 只对 host-trusted system/Developer 根中的非 symlink、有界、不可被 group/world 改写的 executable 执行，且仍要求真实 `inspect_read_only` full sandbox；child 只得到过滤 PATH、空临时 HOME/TMPDIR、`LANG/LC_ALL=C` 和 `NO_COLOR=1`，不继承 token/auth/proxy。其他 PATH executable 保留 canonical path/fingerprint 与 warning，不运行版本命令。

Electron GUI 不能假设 Finder 自然继承用户 Terminal 环境。Desktop supervisor 在启动 Core 前，优先以当前用户 shell 的交互式 login 模式一次性读取 NUL 分隔环境；失败时回退非交互 login 模式，再失败才静默回退 Electron 进程环境。每种 shell 模式的解析均有 3 秒超时、256 KiB 输出上限和 marker framing，stderr/环境值不写日志；shell 探测成功时以其最终环境为准，不与启动前环境合并。Core 的 run snapshot 与 Shell transport 随后共用该已解析进程环境。Core 保留有界 shell-config PATH 静态解析作为显式 API/测试能力，但默认 run 不再二次解析并覆盖 Desktop 已确定的登录 PATH。

该快照回答“本次 run 观察到了什么”，不是普通 Shell 的许可列表。普通 Desktop run 的 Shell 基于 supervisor 已解析并注入 Core 的登录用户环境继承 `HOME`、完整 PATH、代理、证书和用户缓存，再补入常见 Homebrew/用户 CLI 路径；快照中未出现某命令不等于 Shell 政策拒绝它。

环境快照不做无声明的全量 language package inventory；只有 provider 在 dependency manifest 显式声明安全 probe ID 时，run 工具可用性快照才做下述有界只读包观察。run 开始使用 `run_start`，显式刷新使用 `explicit_refresh`，typed 安装后候选快照使用 `dependency_install:<plan_id>`；任何刷新都不原地替换已创建 ToolRuntime 的快照，只供下一 run 或后续显式 refresh 消费。

## 3. Managed primary runtime

准备链继续负责：manifest 校验、平台/架构选择、下载/展开、hash/fingerprint、active pointer 原子发布、并发/恢复，以及 Desktop supervisor 对 active revision 的引用。受管组件的准确清单只以 runtime manifest 和 probe 为准。

只有明确声明依赖 managed runtime 的 provider 才要求 active revision；普通本机文件工具、MCP/Connector、Skill 目录和用户机器 provider 不应因 primary runtime 缺失而整体不可用。

## 4. 安装与依赖恢复

provider `needs_runtime` 的通用 resolver 可以根据 pinned environment 和 provider manifest 生成 host-owned `CandidateInstallPlan`：可重现 `plan_id`、绑定的 `environment_snapshot_id`、实际包管理器 executable、安全 argv/cwd/env delta、workspace/user/system/managed scope、admin/manifest 标志和 provenance。Python plan 强制 `--no-input --only-binary=:all:`，Node plan 强制 `--ignore-scripts --no-audit`；不安全的包名、版本或 source 不产生计划。它们进入 dependency observation 与 `capability_diagnose`，但不自动执行。

language package 必须由 provider 显式声明 `python_import:<module>` 或 `node_resolve:<package>` probe ID。宿主用 pinned Python/Node 做只读 `find_spec`/metadata 或 `require.resolve`，不执行包代码；提供 1 秒超时、有界输出、去敏最小环境、workspace `PYTHONPATH`/`NODE_PATH` 和 30 秒 cache。Node 探测优先解析模块入口，不用 `require.resolve("<package>/package.json")` 作为统一存在判据；`ERR_PACKAGE_PATH_NOT_EXPORTED` 与 `MODULE_NOT_FOUND` 必须分开，版本从已解析入口向上定位同名 metadata。结果分为 ready/missing/mismatch/unknown/error，并支持 exact、`>`/`>=`/`<`/`<=` 和逗号合取的简单数字版本约束；非法 probe 或未支持版本语法保持 unknown，不执行自由文本。

`dependency_install` 仍是一个独立 typed provider：它在 macOS `SandboxFull` + `WorkspaceExecutionBroker` staging 条件下消费当前 run 中 host-generated 的 pinned Python/Node workspace `plan_id`，验证 manager 与 PATH，提交后生成候选快照并复探 requirement。它的 sandbox、scope 和不执行 package scripts 等限制只是该 typed provider 的可重现合同。

通用 Skill 不必须等待 CandidateInstallPlan，也不必须经过 `dependency_install`。Agent 读取 `SKILL.md` 后可使用默认当前用户 Shell 直接执行 Skill 声明的 `npm install`、`pip install`、OS 包管理器或安装脚本，并写用户级 Skill 目录和缓存。raw Shell 不“消费” typed plan，但它可以按普通本机命令执行同类包管理器，并以真实 exit code/stderr 恢复。

## 5. 平台边界

| 能力 | macOS | Windows | Linux |
| --- | --- | --- | --- |
| 环境快照 | 当前代码支持 native arch 与 Rosetta detection；当前 Mac 可自动化，Intel 实机需单独证明 | 当前代码支持 WOW64 detection，已有 cross-build，需实机路径验证 | 当前代码支持，需实机验证 |
| managed runtime manifest/active pointer | 当前开发主路径 | 有 cross-build/路径逻辑，仍缺完整实机验收 | 不能由 macOS 结果推断 |
| pinned workspace Python/Node 依赖安装 | `dependency_install` 有 full sandbox + staging 自动化和 opt-in 真实 pure-wheel smoke；仍需 Desktop 验收 | 缺 full sandbox，transport 前 fail closed | 缺 full sandbox，transport 前 fail closed |
| Agent 按 Skill 指令准备任意依赖 | 默认当前用户 Shell，需真实 Desktop/网络/Skill 验收 | 代码路径支持当前用户 Shell，需 Windows 实机 | 代码路径支持当前用户 Shell，需 Linux 实机 |

## 6. 代码 owner

- `apps/desktop/src/main/runtime-supervisor.ts`：GUI 启动时的登录用户环境解析、超时/输出上限、秘密不落日志与回退。
- `src/tool/environment_snapshot.go`、`environment_path_probe.go`：只读环境观察、完整 transport PATH digest、诊断预览、Skill/临时根元数据和显式 shell-config 静态解析。
- `src/tool/catalog_snapshot.go`：provider readiness 与 run 快照。
- `src/agentcore/agent.go`、`src/runtime/run_service.go`：run-start/显式 refresh 边界与 refresh reason。
- `src/tools/dependency_install`：pinned workspace 依赖计划执行、post-install refresh 与复探。
- `src/tools/shell`、`src/tool/execution_broker.go`：run snapshot 与 transport 共用的 host 环境、当前登录用户直接执行和进程结果。
- `scripts/prepare-primary-runtime.mjs`、`src/tools/artifact_runtime/runtime_resolver.go`、`src/runtime/officerender/managed_runtime.go`：managed runtime 准备、解析和探测。
- Desktop supervisor：进程生命周期与 active revision 注入。
