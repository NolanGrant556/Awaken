# 工具发现与执行 · 需求文档

模型通过统一工具目录使用本机和外部能力。用户需要知道工具能否使用、失败原因以及是否已经产生副作用。

## 工具如何进入任务

- 八个基础工具为 Bash、Read、Edit、Write、Glob、Grep、WebSearch、WebFetch。Desktop 内置浏览器就绪时，另提供 `browser_navigate`、`browser_snapshot`、`browser_click`、`browser_type`、`browser_wait`、`browser_extract`，只驱动当前会话可见的公开网页，不替代 WebFetch/WebSearch，也不进入 Computer Use。后台研究、引用核验与公开 JSON 数据读取使用 WebSearch／WebFetch，不主动展示页面；可见浏览器用于用户要求展示或确需点击／输入的流程。低频辅助工具和 MCP 工具按需检索加载。
- “设置 → 搜索”中的 Exa、Tavily 开关只保存配置，不重启 Core。正在执行的任务继续使用开始时的工具快照和渠道；下一次任务才读取新配置。两个渠道都关闭时，新任务不再提供 WebFetch。
- 后台网页与 JSON 读取使用 Awaken 当前网络路由；启用系统代理时无需另配研究代理。地址被安全检查拒绝或网络失败时明确返回失败，不能算成已取得资料。私网与危险重定向仍被拒绝。
- 缺少依赖、未认证和暂时故障分别显示，不能把未就绪工具当作可用能力。
- 普通工具默认自动执行，不提供通用逐工具审批或消息发送审核。远端权限与幂等性仍由工具和服务负责。
- 需要补充信息时向用户提问；取消回答后主任务可以继续。外部授权和计算机复核使用各自的专门交互。

## 失败与恢复

结果未知或只完成一部分时，先核对实际状态，不能盲目重发。外部授权完成后，由宿主验证，同一调用最多自动重放一次；再次要求相同授权时停止循环。

Bash 以当前用户权限执行，不提供工作区沙箱。只有实际使用文件工具的废纸篓路径时，才能承诺可恢复删除。当前生产审计查询尚不完整，不能把测试记录当作完整审计。

工具定义、权限决策、输出校验和验收见[实现方案](实现方案.md)。

## 完整结果与预览

较长工具结果可以显示有界预览，但完整正文必须先保存在当前 Agent 有权读取的结果存储中。模型拿到读取标识后可以分段核对当前步骤需要的页。已经读过或执行过的较长工具正文不会一直堆在后续请求里；需要同一事实时再跑原工具，或按读取标识 / 当前线程历史取回。预览不能作为已经消费全文的证明，也不要求为了“读完”把全文灌进对话。

## 子 Agent 与并行读取

普通 Agent 可以使用其权限内的完整工具能力，受限角色不会因此获得写入权限。互不依赖的内建只读调用可并行，媒体读取先检查整批预算；写入、外部副作用与可能改写输入的 Hook 继续按各自顺序执行。结果仍按原调用顺序显示和保存。
## 共享依赖与执行路径

模型通过 `tool_find` 获取 `ensure_environment`，按能力或结构化依赖准备非办公扩展环境。旧 Office 细分选项不再展示给新任务，既有调用仍兼容。另已注册固定办公环境入口 `load_workspace_dependencies`，只接受空请求；整包资产尚未交付，缺少平台资源时明确失败。模型不能指定安装位置、下载地址或任意安装命令。目录、来源、安装和回收规则见[依赖与路径管理](../../03_运行时与本地服务/依赖与路径管理/需求文档.md)。
