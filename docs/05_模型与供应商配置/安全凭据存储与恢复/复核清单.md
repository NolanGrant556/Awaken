# 安全凭据存储与恢复复核清单

## 使用方式

本清单只复核 [安全凭据存储与恢复契约](./架构与恢复契约.md) 与 [模型配置与调用](../模型配置与调用.md)，不重新定义状态、字段或恢复流程。

- 标记“当前”项目时，必须能指向本次代码和测试结果。
- 标记“待实现契约”项目时，只有代码、wire、UI、自动化和真实验收全部落地才可勾选。
- macOS 人工钥匙串恢复只按 [专用 QA 案例](./macOS登录钥匙串认证状态失效QA案例.md) 执行。

## 一、当前代码边界

- [ ] `apps/desktop/src/main/secure-credential-store.ts` 是唯一直接依赖 Electron `safeStorage` 的模型凭据适配层。
- [ ] 保存、测试、余额、能力同步和 start-run 都经 `ModelProfileStore` 读取同一全局凭据。
- [ ] 只调用 async encrypt/decrypt；没有同步 safeStorage、availability gate 或 plaintext fallback。
- [ ] 安装版 `Awaken / com.awaken.desktop / @awaken/desktop` 与开发版 `Awaken Dev / com.awaken.desktop.dev / @awaken-dev/desktop` 均有字面量回归；安装版 application ID 还需补 electron-builder parity 测试。
- [ ] Core 不自行读取 Desktop profile 文件；Desktop 只为当次 run 注入 `model_profile`。
- [ ] Renderer 只接收 profile 摘要和 `DesktopOperationIssue`，不接收已保存明文。
- [ ] provider catalog 的 Desktop/Go 两份代码定义及关键默认值完成显式 parity；当前 `volcengine.coding_preset` 漂移未解决时不得勾选。
- [ ] `promptCacheKey`、`supportsVision`、`supportsVideo` 的实际传播边界与模型调用权威一致，不能因 wire 接收字段就声称 Core 已消费。

## 二、当前数据安全

- [ ] 新 key 先 encrypt，成功后才进入 profile store。
- [ ] profile store 使用临时文件 + rename；损坏 JSON 不被当作空 store 覆盖。
- [ ] 临时不可用、解密失败和迁移失败都保留原 credential。
- [ ] legacy/rotation replacement 只有生成成功且旧 credential 仍匹配时才写回；v2 缺失/错误 scheme 前置拒绝而不做 replacement。
- [ ] lazy migration 不覆盖并发保存的新全局 key。
- [ ] API key、密文、Authorization 和底层系统异常不进入日志、错误事件、transcript 或持久 Renderer state。
- [ ] `last4` 仅用于当前 UI 掩码；测试日志、QA 附件和遥测不记录实际尾号。
- [ ] 不存在 session-only、workspace key、环境变量回写或其他明文降级。

## 三、当前状态与恢复

- [ ] 当前 profile 状态只使用契约列出的五项，不把 `system_reauthentication_required` 伪装成现状。
- [ ] temporary error 映射 `credential_temporarily_unavailable + relaunch`，同次操作不循环重试。
- [ ] invalid/version/decrypt failure 映射 `credential_unreadable + reenter`，且原密文保留。
- [ ] save failure 不显示“已保存”，新 key 不落盘，旧 profile 保留。
- [ ] 余额面板将多个相同凭据故障折叠为一个全局恢复状态，并明确同 provider 当前只使用首个 enabled profile 的 credential/Base URL。
- [ ] provider `401`、限流、余额和传输错误不被标成 Keychain/DPAPI 故障。
- [ ] IPC 不泄露 `Error invoking remote method` 或任意未知下游原文。

## 四、当前自动化

- [ ] legacy sync-compatible ciphertext 可由 async decrypt 读取。
- [ ] `shouldReEncrypt=true` 和 legacy envelope 都生成 v2 replacement。
- [ ] replacement encrypt/persist failure 保留原 envelope。
- [ ] temporary unavailable 被分类为 retryable relaunch 边界。
- [ ] malformed base64、unsupported version 和 v2 missing/wrong scheme 在调用 safeStorage 前拒绝；missing/wrong scheme 专项测试尚缺时不得勾选。
- [ ] 安全写入失败的新 key 不落盘；更新既有 profile 时文件逐字节不变。
- [ ] 损坏 profile store 不被覆盖。
- [ ] migration 与用户保存并发时，用户新 key 保持权威。
- [ ] Desktop operation、preload/client、composer 和余额 UI 都覆盖结构化 issue。
- [ ] macOS/Windows 共享状态语义有 contract test；平台适配差异独立测试。

## 五、当前真实 Desktop

- [ ] 按根 README 的正式入口完整关闭并启动 Awaken。
- [ ] 在 Settings > Models 保存专用测试 profile，UI 只在安全写入成功后显示成功。
- [ ] 完整重启后 profile、default、enable 和能力参数保持。
- [ ] 余额查询成功，或明确返回当前 provider 的“不支持/业务错误”。
- [ ] 原 profile 的真实 prompt 越过凭据层并取得 provider 结果。
- [ ] UI、日志和 transcript 不含明文、密文、Authorization、完整 Base URL 或底层系统异常。
- [ ] 日常 smoke 没有执行 Keychain lock/unlock、DPAPI 破坏或密码重置。

## 六、已确认待实现契约

以下项目当前应保持未勾选；勾选意味着已完成代码、协议、UI、测试和真实验收，不是“文档已经写了”。

- [ ] relaunch 后同类认证错误能跨进程升级为 `system_reauthentication_required` 或等价明确状态。
- [ ] 该状态已加入安全的 IPC/wire/Renderer 枚举，并与当前五项 profile 状态分层。
- [ ] 系统重新认证前始终保留旧密文，不自动跳转重录。
- [ ] 只有系统层与应用/条目层分类后确认永久不可恢复，才进入 `reentry_required`。
- [ ] Awaken 内提供跨平台产品引导；普通用户不需要终端、Keychain Access 或 Windows 凭据管理器。
- [ ] 有不含秘密的 `credential_decrypted`、`transport_started`、`provider_response_received` 和 credential write attempt 证据。
- [ ] 明文在 Electron、Core、Agent/thread cache 中的存活、profile 重建、淘汰、退出清理边界已实现并测试。
- [ ] app name、bundle/signing identity、application ID 与 userData 的升级迁移有双平台回归。

## 七、专用故障 QA

- [ ] 先保护配置和 credential 记录，再判断系统层、应用 identity/envelope 层或 provider 层。
- [ ] relaunch 后仍失败时，不删除、清空、覆盖或先重录。
- [ ] macOS 人工 lock/unlock 仅在专用 QA 用户/机器、用户知情且暂停录屏/日志时执行。
- [ ] 不使用 `security ... -w`、`-g`、`dump-keychain`、`delete-generic-password` 或 `unlock-keychain -p`。
- [ ] 证据只记录标准化枚举和脱敏片段，不上传配置文件、密文、last4 或命令原始输出。
- [ ] Windows 不复用 macOS 命令，必须使用独立 DPAPI 手册。
