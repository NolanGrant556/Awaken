## Awaken 当前接入

- 普通 API：provider ID `glm`，Chat Base `https://open.bigmodel.cn/api/paas/v4`，Messages Base `https://open.bigmodel.cn/api/anthropic`。
- Coding Plan：provider ID `glm-coding-plan`，Chat Base `https://open.bigmodel.cn/api/coding/paas/v4`，Messages 仍走套餐指定兼容入口。
- 两个入口当前公开 Chat 与 Messages，不公开 Responses。
- 默认模型 `glm-5.2`；公开稳定目录 API 当前未确认时使用版本化官方清单和手填。

## 三协议兼容矩阵

| 协议 | 官方合同 | Awaken 当前 | 结论 |
| --- | --- | --- | --- |
| Chat Completions | 有 OpenAI 兼容 | API 与 Coding Plan 已接入 | 支持；Base/Key 按产品分开 |
| Responses | 当前未确认官方合同 | 未接入 | 不支持 |
| Messages | 有 Anthropic 兼容/套餐入口 | API 与 Coding Plan 已接入 | 支持当前兼容子集 |

## 鉴权、端点与模型

- Chat 使用 Bearer；Messages 在 Awaken 当前 route 使用 `x-api-key`。
- 普通 API Key 与 Coding Plan Key/套餐计费不可混用；Coding Base URL 不能回退普通 API。
- 模型目录未提供稳定 capability 时，允许手填精确 ID，但不得从模型名推断窗口、多模态或 effort。
- GLM 模型快速迭代，`latest`/别名和精确版本的恢复语义不同；关键 thread 优先保留 exact ID。

## 上下文、多模态与工具

- 上下文、最大输出、视觉和 function calling 按 exact model + protocol 文档判定。
- Messages 兼容不等于 Anthropic 全部 PDF/cache/beta 功能；逐项核对智谱兼容文档。
- PDF Read 若没有原生 document/PDF 合同，使用页面渲染回退。
- Coding Plan 用于 agentic 编程时还要核对套餐允许的工具、并发和客户端范围。

## 提示词缓存

- 官方上下文缓存页说明自动/隐式缓存和 cache token usage；按当前模型与 endpoint 复核。
- 当前 Awaken `src/llm/prompt_cache_capability.go` 尚未为 GLM 内置入口建立 exact 专属合同，因此不应主动发送未确认私有字段。
- 可解析官方已返回的缓存 usage，但缺失时显示未知；不能用供应商原生缓存能力推断 Messages 兼容入口也相同。

## 推理开启关闭

- 官方 thinking 合同使用 `thinking.type=enabled|disabled` 等当前字段；不同模型/协议可能不同。
- Awaken 当前 reasoning-control 白名单未覆盖 GLM，因此辅助请求不得仅凭文档在通用 adapter 注入该字段。
- 接入时要对普通 API、Coding Plan、Chat、Messages 分别建立 provider/base/protocol/model 合同。

## 推理强度

- 官方 `reasoning_effort` 可接受多个标签，但当前模型可能把低/中档归并到 high、把更高档归并到 max；以模型页当前映射为准。
- Awaken 当前普通 API 与 Coding Plan 的 `glm-5.2` 只展示统一 `high | max`，不伪造 low；按官方模型合同默认 `max`。
- Core 在 `src/llm/request_policy.go` 对 `glm` 与 `glm-coding-plan` 的 `glm-5.2` 执行 exact 原生值映射。
- thinking 开关和 effort 分开；改变 effort 必须形成不同缓存 identity。

## 用量、余额、限流与套餐

### 用量查询合同

- `glm` A/E 类：普通 API 的 per-request usage 与 rate limit 按响应/Header 记录；未找到普通推理 Key 可调用的正式公开余额 endpoint，账号余额与账单仍以控制台为准。
- `glm-coding-plan` B 类：官方 `glm-plan-usage` 插件分别请求 `/api/monitor/usage/model-usage`、`/api/monitor/usage/tool-usage` 和 `/api/monitor/usage/quota/limit`，可得到 5 小时 token 百分比与月度 MCP 工具限额等信息。
- 凭据：使用 Coding Plan token；官方插件在 `Authorization` 中直接发送 token，不加 `Bearer`，并按 `api.z.ai` 或 `open.bigmodel.cn`/`dev.bigmodel.cn` 选择 host。当前证据面向个人 Coding Plan，一方源码合同仍需关注版本变化。
- Awaken 当前：普通 API 和 Coding Plan 都未接入用量/余额查询；不得把控制台能力写成普通 API Key 余额接口。

- Coding Plan 的周期额度、并发、模型系数和支持工具以计划页与订阅协议为准。
- 官方条款可能限制套餐仅用于支持客户端或开发用途；Awaken 接入前要确认，不把套餐 Key 当通用商业 API。
- 普通 API 价格与 Coding Plan 套餐不可互相折算。

## Awaken 落地规则

- `glm` 与 `glm-coding-plan` 分开保存凭据、Base URL、profile、缓存和 usage。
- Responses 未确认，不在 UI 提供；不要因 OpenAI SDK 能调用 Chat 就推断 Responses。
- 新增 thinking wire control 时放入 exact capability 白名单并覆盖禁用/默认/effort 测试。
- 目录 API 未确认时明确标“官方清单/手填”，不冒充实时 API 结果。
