# 文件操作与路径安全 · 需求文档

文件工具在授权路径内读取、查找、写入和删除文件。可恢复删除只适用于实际接入 Trash 的工具，不能把 Bash 的任意删除也算作可恢复。

代码、接口和验证方法见[实现方案](实现方案.md)。

## 当前支持

模型基础文件工具固定为 `Read`、`Edit`、`Write`、`Glob`、`Grep`。它们与 `Bash` 分开：路径统一由 `PermissionContext` 解析，roots 提供默认作业位置和搜索范围，附件映射、敏感路径和 symlink 检查仍由宿主强制；用户明确点名的外部绝对路径不因越出 roots 被拒绝。`Bash` 不继承 typed 文件工具的快照、原子写入和结构化结果保证。

| 工具 | 当前合同 |
| --- | --- |
| `Read` | 文本从 1 开始分页，默认/上限 2000 行；PNG/JPEG/GIF/WebP 进入模型媒体；PDF 在 `pdfinfo` 可知且 ≤10 页时省略 `pages` 会整份读取（原生整份或 Poppler 渲全部页），>10 页的渲染页路线省略 `pages` 时由宿主自动归一化为首段 `1-10` 并在成功结果标记 `pages_defaulted=true`，不先返回分页参数异常；`route=native_pdf` 代表原生整份已完整交给模型。渲染页单次最多 20 页，越界页在已知总页数时夹紧忽略。模型从首次成功结果的 `route/page_count` 决定是否读取剩余范围。原生 PDF 或视觉（Poppler 144 DPI）任一可用时阅读，两者皆无返回 `model_pdf_unsupported` 并要求请用户换模型，不得以 Skill/Bash/装包绕过；Office/Notebook 返回 `unsupported_media` |
| `Edit` | 既有文本必须在当前 thread 成功 `Read` 且宿主快照未变化；默认要求 `old_string` 唯一匹配，只有 `replace_all=true` 可替换多处 |
| `Write` | 新文件无需预读并写 UTF-8；覆盖既有文件必须预读且未外部变化；保留可识别的编码/BOM、换行和权限 |
| `Glob` | 使用 run snapshot 固定的真实 `rg`，默认 hidden/no-ignore、稳定排序；默认每页 100 条、`limit` 最大 1000，以 opaque `cursor/next_cursor` 继续枚举并报告 total/truncated |
| `Grep` | 使用真实 `rg` argv，支持 glob/type/output mode/context/line/ignore-case/head/offset/multiline，保留真实无匹配和截断事实；`head_limit/offset` 提供稳定续读 |

自定义 API profile 的视觉能力默认关闭；用户在连接配置中明确开启“视觉多模态”后，`Read` 才可把图片或 Poppler 渲染出的 PDF 页面作为模型媒体发送。该开关不等于原生 PDF 支持，`route=native_pdf` 仍不可用；关闭或旧配置未声明时继续以 `model_pdf_unsupported` fail closed。

缺少 `rg` 时 `Glob`/`Grep` 返回 `needs_runtime`，不回退到语义较弱的 Go 搜索。两者默认按 TaskScope 精确 roots 搜索；共同父目录或项目外路径必须通过 TaskScope 文档定义的 `scope_mode` 明确区分，不得靠退回 `Bash find` 绕过分页。`Edit`/`Write` 使用同目录临时文件、fsync 和原子替换；未知/二进制编码拒绝覆盖。失败不刷新 thread 文件状态，成功会记录新的 SHA-256/size/mtime/type 快照。

上述是 typed 文件工具的可恢复合同。默认 raw Shell 不再将 `rm`/`rmdir`/`unlink` 等命令转换为 `trash_file`，它按当前登录用户的 Terminal 语义直接执行；UI/Outcome 不得伪造可恢复 change。

## 当前缺口

- Windows 当前通过 PowerShell/FileIO 接入 Explorer Recycle Bin，但仍缺 `IFileOperation` 原生 adapter、实际回收站路径和 Windows 实机验收；
- macOS 尚未接入 NSWorkspace，跨卷 Trash 不支持；
- Linux 没有 freedesktop Trash adapter；
- 没有跨平台通用 restore tool 和本轮 Windows/Linux 实机证据。

## TaskScope与路径安全：当前支持

**roots 决定默认在哪儿干活，不决定能不能干。** 每个 run 固定 `WorkspaceRoot`、`WorkingDirectory`、`ReadableRoots`、`WritableRoots`、`OutputRoots`、显式附件/可读文件和敏感/`ProtectedRoots`/`ProtectedRootExceptions` 策略，但这些 root 不再作为路径围栏：

- 相对路径按 `WorkspaceRoot`（主文件夹）解析，这是 roots 仍然承担的职责；
- 绝对路径指哪读哪、指哪写哪，落在项目文件夹之外同样执行，**不触发审批**；
- 不给 `path` 的搜索只覆盖项目文件夹，这是「默认优先」的体现，也避免一次无范围搜索遍历整块磁盘。

之所以不用 root 围栏：`Bash` 的 `CheckPermission` 从来不做路径检查，围栏只约束 `Read`/`Write`/`Edit`/`Glob`/`Grep`，因此它不构成边界，只会把越界工作赶进 shell 调用——那样反而丢掉结构化工具的 diff 记录与结果规范。

写入侧保留的是**按形状**判定的固定拒绝名单，与所在 root 无关：`.git` 内部、`.env`、私钥与凭据文件（`id_rsa`、`*.pem`、`credentials`、`secrets` 等）、home 下的 shell 配置、以及 `~/.awaken` 与运行时 config 目录。理由是写坏这些从来不是指令的本意，而 `~/.awaken` 承载 Awaken 自身的 store generations、config 与 credentials。两个明确例外是 run 自己的 managed session 工作区和 Agent 可创作的 `<AWAKEN_HOME>/plugins` 仓库；插件状态文件 `<AWAKEN_HOME>/config/plugins.json` 不在例外内，仍只能由 PluginStore 原子更新。**读取不套用这份名单**，与围栏时期项目内可读 `.env` 的行为保持一致。

三个 roots 数组本来就是多根的。一个项目有多个文件夹时，Desktop 用 `[主文件夹, ...次文件夹]` 填这三个数组，`WorkspaceRoot` 是主文件夹。线程锚定在次文件夹时，那个文件夹排在数组首位并成为该 run 的 `WorkspaceRoot`。

roots 要生效，模型必须知道它们存在。scope 通过 `workspace.project_id/project_name` 拿到稳定项目身份和展示名，system prompt 以结构化 `<environment_context>` 分开渲染项目 ID/名称、cwd、逐项保留的 `workspace_roots` 和独立的 unrestricted `permission_profile`。Host 不计算或注入多个 root 的共同父目录。默认系统提示的「项目文件夹与作业范围」再声明四条约定：默认在主文件夹作业、文件夹组是一个整体、“本项目”严格等于这组 roots、跨文件夹检索省略 `path`；项目外路径只有在用户明确点名时才进入显式路径模式。模型侧渲染由 [上下文窗口与压缩](../../02_主智能体闭环/上下文与用量/实现方案.md) 拥有；此处只声明它与 roots 语义必须一致。

项目可以没有任何文件夹。此时 Desktop 传 `workspace.project_id` 而 `workspace_root` 为空，Core 把它解析到该项目自己的 session 工作目录：`<AWAKEN_HOME>/sessions/<project_id>`，产出默认落在其下的 `output/`；同一零文件夹项目的 thread 共享这一区域。

独立对话同时省略 `workspace_root` 与 `project_id`。Core 必须先确定稳定 thread ID，再解析到 `<AWAKEN_HOME>/sessions/<thread_id>`，产出同样落在 `output/`。新独立对话由 Core 生成 thread ID，继续对话使用请求中的已有 `thread_id`；不回退到 Core 进程 cwd、用户主目录或 Renderer 记住的项目路径。managed workspace owner ID 只能包含安全的路径组件字符，不能用 `..` 或分隔符逃出 sessions 子树。

`ProtectedRoots` 按 **每个** root 生成 `.git` / `.awaken` / `.vscode` / `.idea` 保护项，不只为主文件夹生成；否则次文件夹仓库的 `.git` 会变成可写。

`ProtectedRootExceptions` 是受保护子树内部的窄口子。每个 run 固定放行 `<AWAKEN_HOME>/plugins`，使 `Edit` / `Write` 能修改已安装包和插件数据；这不等于签收 package digest，未 commit 的包仍由 PluginStore fail closed。只有当本次 scope 的某个 root 落在 `<AWAKEN_HOME>/sessions` 里时，才额外放行 sessions 子树。`config`、`credentials`、`store-generations`、`memory` 依旧不可写，例外内部仍适用 `.git`、`.env`、密钥与凭据等形状规则。例外自身与其任一祖先/叶子 symlink 的 real path 都必须留在同一个例外和原受保护根内；不能借插件仓库里的 symlink 把写权限投射到外部，也不能从仓库外的 symlink 别名反向写入例外。

`Glob` 和 `Grep` 默认使用 `scope_mode=project`。调用方没有显式给 `path` 时覆盖全部 readable roots：cwd 在前，其余按 scope 顺序跟随，嵌套与重复 root 会被去掉，同一个文件不会出现两次。合并多个 root 的结果时输出绝对路径（`path_style=absolute`），只有一个 root 时保持原来的 root 相对路径（`path_style=root_relative`）。project 模式显式收到多个 roots 的共同父目录或项目外路径时返回 `PROJECT_SCOPE_PATH_MISMATCH`，提示省略 `path`；用户明确要求项目外路径时，模型必须使用 `scope_mode=explicit_path`，该模式仍按开放权限合同直接搜索，不触发审批。回执同时记录 `scope_mode/scope_relation/scope_source`，区分 `inside_project/common_ancestor/outside_project` 与默认/显式来源。

`WorkspaceExecutionBroker` 只由 `dependency_install`、`git_remote` 和 MCP Artifact bridge 使用。调用方从 normalized `PermissionContext` 产生 canonical writable/protected scope；workspace 外 root 不进入可发布集，protected roots 同时保留 lexical 位置和 resolved target。`Bash` 不调用该 broker，也没有 `workspace_scope_declared`/staging 分支。

路径判断使用 lexical path 与 realpath/祖先检查：

- 拒绝通过现有叶子或祖先 symlink 逃逸写根；
- 允许 writable root 内尚不存在的叶子；
- 显示名映射到附件时必须唯一，歧义即失败；
- home、根目录、credential、SSH、Git 配置等敏感位置有独立 hard gate；
- recoverable delete 额外拒绝 symlink、特殊文件、根/受保护路径。

上述检查会拒绝调用开始前已经存在的 exception-root、祖先或叶子 symlink 逃逸；当前 typed 文件工具仍是“校验后再以普通路径原子写入”，尚未统一到 dirfd/openat no-follow 事务，因此不能把它写成能抵御另一个本机进程在校验与写入之间并发替换祖先目录。PluginStore 的 snapshot/live digest 复算会阻止把这种不稳定 package 签收为有效状态，但不能撤销已经发生在插件树之外的外部写入；这是当前已知缺口。

WorkspaceRoot 是 typed 文件/Artifact/provider 的默认 run 范围，不是当前登录用户 `Bash` 的操作系统边界。Bash 可通过 thread cwd 进入 workspace 外目录，也可读写 Skill root/用户 cache；Outcome 只证明进程事实，不声称这些副作用经过 TaskScope 观测或提交。外部 provider 的远程资源不伪装成本地路径；其 scope 由 provider manifest 与 typed input/output 契约表达。

## 读、写、删除

| 操作 | 当前边界 |
| --- | --- |
| 读 | 任意路径。相对路径按主文件夹解析，绝对路径指哪读哪；形状名单不套用于读 |
| `Edit`/`Write` | 任意路径，但形状名单（`.git` 内部、`.env`、密钥/凭据、shell 配置、`~/.awaken` 的非例外区）在任何位置都拒绝；`<AWAKEN_HOME>/plugins` 可写但 package 修改后仍须 PluginStore commit；父路径和 symlink 链校验；覆盖还要求当前 thread 的未过期 Read 快照 |
| 删除 | 仅明确普通文件/目录，且必须由 recoverable-delete 路径处理 |
| `Bash` | cwd 可在 workspace 外，以当前登录用户的操作系统权限直接执行；TaskScope 只作运行上下文，不冒充全部副作用检查要求 |
| 保留的 Workspace broker | 只服务 dependency/git/MCP Artifact；每个 staged delta 依据 canonical writable/protected roots 验证，Trash/发布前 fail closed |
| typed Git clone | destination 必须是 writable TaskScope 内非敏感、非 workspace root 的相对路径，父目录必须已存在；broker 的可发布集合固定为该 destination，覆盖前版本进入 Trash |
