# Workbench 中间区域架构契约

## 1. 权威范围

本文是中间区域 ownership、层级边界和不可绕过不变量的唯一权威来源。产品行为见 [产品与交互契约](产品与交互契约.md)，状态与算法见 [交互状态机与滚动布局](交互状态机与滚动布局.md)。

覆盖主链路：

```
AppShell -> WorkbenchShell -> RunStage -> ExecutionFeed / overlay / ComposerDock
```

本文不拥有 runtime tool policy、artifact producer、持久化 schema 或 AG-UI 字段定义；这些事实分别由 04、03、09 功能域拥有。

## 2. 当前代码 owner

- `apps/desktop/src/renderer/App.tsx`：页面编排、runtime 订阅、turn DOM、overlay 和 composer slot 组合。
- `apps/desktop/src/renderer/useRunStageScrollController.ts`：唯一的 RunStage DOM scroll controller、用户意图和布局测量。
- `apps/desktop/src/renderer/workbenchPresentation.ts`：无副作用的 turn、marker、scroll、layout 决策。
- `apps/desktop/src/renderer/run-narrative/`：event 到 narrative item 的 renderer 投影。
- `apps/desktop/src/renderer/styles/workbench.css`：Desktop Workbench 场景样式。
- `Awaken Design System/src/components/Awaken*`：UI-only 壳、组件结构和视觉 token。
- `apps/desktop/src/renderer/App.test.ts`：Workbench 纯决策、输入、附件、Slash 和组件契约测试。

## 3. 唯一容器与插槽

`RunStage` 是中间区域唯一的滚动、定位、overlay 和 composer 容器。它只有三类内容入口：

1. children：center 空态，或运行态 `ExecutionFeed`；
2. `overlay`：notice、turn marker rail、return-to-latest；
3. `composer`：运行态 `ComposerDock`。

禁止在 `RunStage` 外为中间区域新建 fixed/absolute 容器。需要新增悬浮或底部能力时，必须先判断属于 overlay、composer stack 还是 narrative；无法归属意味着契约需要先变更。

## 4. 分层职责

中间区域由以下职责层共同守护；任何改动必须明确自己属于哪一层，不得越层：

| 层级 | 代表 | 职责 | 不可做的事 |
|------|------|------|-----------|
| 设计系统 | `AwakenRunStage`、`AwakenExecutionFeed`、`AwakenComposerDock`、`AwakenComposerBar`、`AwakenUserPromptBlock` 等 | UI-only 结构、视觉、局部受控交互 | 不读取 runtime、Electron、SSE、workspace 或 `window.awaken` |
| Desktop 编排 | `App.tsx` | 组合 slots、订阅 runtime、把 reducer state 转为组件 props、保留 per-turn 局部 UI 状态 | 不定义 tool 安全策略；不把滚动公式重新内联 |
| Scroll controller | `apps/desktop/src/renderer/useRunStageScrollController.ts` | RunStage DOM 引用、wheel/touch/pointer 意图、anchor/follow、ResizeObserver、CSS layout facts | 不生成 narrative item；不渲染业务卡片 |
| 纯决策 | `workbenchPresentation.ts` | turn grouping、process segmentation、marker 采样、scroll/layout predicates | 不访问 DOM、React state 或网络 |
| Narrative projector | `apps/desktop/src/renderer/run-narrative/projector.ts` | 协议 event 到稳定 item、幂等和 tool pairing 表达 | 不操作滚动和布局 |
| runtime reducer | `apps/desktop/src/renderer/runtime/reducer.ts` | 运行状态、thread view、artifacts、tool records、终态 deliverables summary | 不拥有 UI placement |

## 5. 核心不变量

### 5.1 `RunStage` 唯一 ownership

滚动事件、程序滚动、prompt 定位、marker overlay、return overlay 和 dock composer 都必须在同一个 `RunStage` 坐标与滚动体系内。

### 5.2 `ExecutionFeed` 只承载 narrative / turn

`ExecutionFeed` 内只允许 lead narrative、`execution-turn-section`、prompt header、turn body 和 narrative item。输入、toast、marker、return、设置面板和专用 gate 不得进入 feed。

### 5.3 Prompt 始终属于 Turn

prompt 只在对应 `execution-turn-section` 的 header 内渲染。禁止创建 feed 外 sticky 副本、全局 prompt header 或用 marker 点击改写 latest turn 身份。

### 5.4 Composer 只有 `center` / `dock`

新增第三种 variant 前必须同时变更产品、架构、状态与验收文档，并在真实 Desktop 验证所有旧旅程。

### 5.5 Return affordance 不参与布局

return-to-latest 必须是 `RunStage.overlay`。透明容器不拦截 pointer，只有 32px 按钮本体响应点击。它不能成为 ComposerDock 子项，不能进入 composer inset、safe area、output gap 或 wheel 转发链。

### 5.6 用户意图与布局事实分离

wheel/touch/pointer/marker/return 是意图事件；ResizeObserver、markdown 增高、prompt 高度、composer 高度和 viewport resize 是布局事件。布局事件不得直接恢复或暂停 follow。

### 5.7 设计系统保持 UI-only

Desktop 可以给设计系统传 props、controlled state、callbacks 和 CSS variables；不得把 runtime client、AG-UI reducer、Electron IPC、workspace policy 或 thread persistence 放入设计系统。

## 6. Gate 与工具轨迹边界

新 run 不渲染通用 `ApprovalCard`，不通过 composer 恢复 `awaiting_approval`，也不调用旧 `resolveApproval`。工具决策只投影运行时结果。此处只拥有 UI placement，决策枚举和安全语义由 `docs/04_工具权限与审批/索引.md` 路由。

专用 `ask_user` 和 mass-message review 位于 composer stack。legacy approval 只能成为只读 tool-style narrative，不能重新提供按钮。

mass-message review 的 channel/account/recipient/message count/expansion/body/template/attachments/digest 全部来自 runtime reducer；Desktop 只渲染并提交 approved/rejected，不重新分类消息。Skill Slash 也只消费 server catalog，不能在 renderer 根据来源、依赖或文件内容重做 availability/权限判断。

## 7. DOM 与样式边界

以下选择器属于 Workbench 契约触发面：

- `.aw-run-stage-*`、`.run-stage-*`
- `.execution-feed`、`.execution-turn-*`、`.execution-prompt-*`
- `.composer-*`
- `.turn-marker-*`、`.return-to-latest-*`
- `.narrative-*`、`.execution-process-*`

通用结构/token 优先由 Design System 拥有；Desktop 只保留场景级编排和必要覆写。修改上述选择器必须执行 [复核清单](复核清单.md)。

## 8. 禁止事项

- 绕过 `RunStage` 新增中间区域定位容器；
- 在 `ExecutionFeed` 放置输入、toast、通知、设置或业务控制面板；
- 在 `App.tsx` 复制 scroll/marker/inset 计算；
- 用 wheel 代理修复 overlay 挡滚动；
- 让 return affordance 参与 composer 测量；
- 用 React key 或 feed wrapper 变更无意改变 replay/anchor identity；
- 把 renderer 业务逻辑下沉到 Design System；
- 恢复通用 ApprovalCard；
- 修改纯决策但不更新测试；
- 仅凭截图或 DOM render 宣称滚动行为通过。

## 9. 依赖关系

- runtime reducer 和 narrative projector提供 item 身份与终态；
- 09 域拥有 wire event；
- 03 域拥有 transcript 与 replay 数据；
- 04 域拥有工具决策、Outcome 和 artifact producer；
- Design System 拥有纯 UI 组件；
- Workbench 只拥有 Desktop 中心投影、滚动和交互编排。

## 10. 变更与验证门禁

1. 先标出改动触碰的 owner 和不变量。
2. 修改 `workbenchPresentation.ts` 或 scroll controller 时更新 `App.test.ts`。
3. 修改 projector/reducer 时更新对应 replay/terminal tests。
4. 修改 Design System 组件时运行 UI typecheck 和 render smoke。
5. 按 [验收规范](验收规范.md) 执行真实 Desktop 相关 AC。
6. 视觉变更提供当前 HEAD 截图；滚动、sticky、follow、composer 测量提供录屏或连续关键帧。
7. 契约变更必须与实现同一变更集提交；纯文档不得把未实现设计改写为当前事实。

当前 baseline 是轻量截图护栏，不是像素级测试。基线状态与更新门禁由 [验收规范](验收规范.md) 唯一定义。
