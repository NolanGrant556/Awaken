# 插件管理与运行 · 实现方案

本文说明代码职责、数据与接口、异常恢复和验证方法。功能范围及用户操作见[需求文档](需求文档.md)。

## 失败备份与恢复

安装替换、卸载和 MCP Source 编辑在移动原包前写入 `.staging/<transaction>/rollback.json`，保存插件名、旧记录、备份相对目录和候选 digest；凭据只保留 Secret reference。操作失败时该目录保留，错误返回其位置；成功才清理或交给 Trash。

Store 启动及下一次 mutation 在同一个文件锁和 runtime lease 边界下调用恢复逻辑，也可通过 `Store.RecoverPendingOperations` 显式重试。恢复先核对 live package 的 digest；遇到外部修改或 live data 与备份同时存在时保留两份，要求人工核对，不覆盖。仍受权限或 I/O 故障阻塞时保留事务，修复环境后重试。没有事务元数据的旧暂存目录也不再启动即删除，需人工确认用途。Trash 已完成而进程尚未清理时，以当前状态和包 digest 对账后清理事务。

`go test -race ./src/plugins` 覆盖 Trash 故障叠加恢复目录不可用、备份保留、重开 Store 恢复，以及现有安装、替换、源码保存和卸载事务。故障注入只使用临时目录，不对真实已安装插件制造权限故障。

正常安装、MCP 接通、重启后调用和卸载已用只返回本地标记的验收插件走过 Desktop；[卸载回读](../../../apps/desktop/test-fixtures/full-audit-fixes/plugin-uninstall-readback.json) 同时确认目录和登记已移除。复合故障仍以临时 Store 注入验证，未对真实插件目录制造故障。

## 插件图标

Design System 的 `icons/definitions.ts` 持有 16 网格圆形 `at-sign` 几何，使用统一 1.25 描边与 currentColor；`concepts.ts` 将 `plugin` 和 `plugin-default` 都映射到该字形。侧栏、页面标题、普通插件占位、Composer 菜单与结构化 token 复用同一图形，保留各入口原有尺寸与主题文字色。受控 Outlook 品牌图标仍由 `AwakenPluginBrandIcon` 渲染。旧 Agent Plugins 品牌标记与 puzzle 字形仅保留命名兼容，不再作为通用插件概念映射。

验证运行图标库、图标消费、Composer 和插件 token 的聚焦测试，以及 Design System 构建与组件 smoke；真实 Desktop 核对侧栏、插件页和输入框入口，保留品牌插件原图。

## 钉钉与飞书的宿主入口

`ExtensionsView.tsx` 将既有 `CliConnectorView` 与 Connector readiness 投影到 `AwakenPlugins` 的内置列表。`cliConnectorProduct.ts` 维护已注册 provider 的产品文案及 UI 卡片身份；`builtin-connector:dingtalk-workspace` 和 `builtin-connector:lark-cli` 仅用于列表路由，不传给 Plugin Store API、不伪造 `RuntimePlugin`，不改变 Core 的目录或工具身份。

`AwakenPluginCard` 接收可选的 `brandLogoSrc` 和 `connectionStatus`；有连接状态时显示设置按钮，否则保持原包插件开关。Desktop 从本地品牌资源提供钉钉和飞书原图，Design System 不读取 runtime。点击卡片调用原 `refreshCliConnector` 并打开 `AwakenCliConnectorDetailDialog`，全部操作仍委托给 Main 的原安装、授权、取消和退出接口。默认文案与 Main 的安全进度/错误文案只在展示时转换为运行组件与技能，不修改内部错误码和生命周期。无 readiness 时显示加载或可重试错误，不让点击静默失效。

Renderer 按 provider 对列表读取、详情探测及操作结果分配快照版本；更新事件使旧请求失效，旧列表或探测不得覆盖后来的授权状态。详情请求另有代次，关闭或切换 provider 后迟到错误不得出现在另一弹窗。状态订阅在插件页继续工作，Main 对授权 session 的归属与迟到事件处理仍由[连接器管理](../../07_连接器/连接器管理/实现方案.md)拥有。`AwakenConnectors` 支持限制可见分类，Desktop 只传入 MCP，单项分类不渲染标签，原 MCP 配置、开关和设置入口保持原路由。

聚焦验证：`BuiltinConnectorPlugins.test.tsx` 覆盖两项既有连接、插件页签与搜索、安装进度及重开、取消安装、授权关闭取消、成功与退出、未知状态、晚到探测/错误和 Escape 焦点恢复；`CliConnectorDetailDialog.test.tsx` 与 Main `cli-connectors/manager.test.ts`、`auth-ownership.test.ts` 继续验证原生命周期。另执行 Design System typecheck/build/组件 smoke、Desktop typecheck/build、`ExtensionsView.behavior.test.tsx` 和文档检查。

真实 Desktop 通过 `npm run open:desktop` 入口核对迁移前后账号状态、连接器列表、内置插件搜索、详情打开与关闭，并留存[截图与验证范围](../../../apps/desktop/test-fixtures/builtin-connector-entry/verification.json)。该记录单独说明真实调用结果和未执行项；不通过退出真实用户账号来证明自动化里的取消和退出分支。

## 产品与架构说明

插件层拥有方言识别、来源、安装树、配置、组件 inventory、完整性和 run generation；Skill、MCP、Hook、Subagent 与 instructions 的执行语义仍由各自功能域拥有，插件层不得建立第二套 runtime。

Desktop 插件请求由 `apps/desktop/src/main/plugins-ipc.ts` 注册。Plugin Console 使用固定必需的 RuntimeClient 方法，测试替身也须提供正在使用的接口。领域错误采用[本地服务管理](../../03_运行时与本地服务/本地服务管理/实现方案.md)的结构化 IPC 结果，`pluginErrors.ts` 只负责插件的用户提示，不重复解析 Electron 错误前缀。

## 当前支持

Awaken Desktop「扩展 > 插件」支持安装和管理以下 user-scope 包：

- Agent Plugins 1.0.0；
- Codex native `.codex-plugin/plugin.json`；
- Claude Code `.claude-plugin/plugin.json`，以及用户明确选择/来源带可信 Claude hint，或无其他 manifest 且唯一符合 Claude 默认目录形态的合法 manifestless 包；
- Cursor `.cursor-plugin/plugin.json`。

包插件同时存在两类产品来源：用户通过 ZIP 安装的普通插件，以及随 Desktop 发布的 Awaken 内置插件。内置插件的唯一发行源位于 `apps/desktop/resources/builtin-plugins/<name>/`；其中 `plugin.json`、`.awaken/builtin.json` 和该插件声明的 setup/组件资源必须全部进入 Git，Desktop 开发与构建入口先执行 `scripts/validate-builtin-plugins.mjs`，缺失必需元数据时 fail closed，不能用维护者工作区中被忽略的本地文件继续启动或打包。`electron-builder.yml` 必须把该目录作为 `extraResources/builtin-plugins` 原样纳入安装包，Desktop 再通过 `AWAKEN_BUNDLED_PLUGIN_DIR` 交给 Core，用户登录 shell 中的同名变量会被清除。Core 启动时仍使用完整方言、containment 与 digest 校验把它复制到普通 Plugin Store，但会记录 `builtin/brandIcon/builtinOrder` 可信元数据。`.awaken/builtin.json` 只有从该发布目录同步时才生效，普通 ZIP 即使携带同名文件也不能取得内置身份。

内置包插件首次出现时默认关闭；发布版本变化时替换只读 package tree，并保留用户的整体启用状态、组件偏好、变量和账号绑定。插件整体启停只控制该插件的技能、组件与运行时可见性；关闭插件不得调用 host Connector 的断开连接、清理 Keychain 凭据或取消账号绑定，重新开启时直接复用原已连接账号。内置 package 不能通过普通 ZIP 替换、卸载、MCP Source 编辑或 `plugin commit` 改写；用户只控制整体启停和其正常 setup/账号动作。`awaken-outlook` 是首个内置插件，排序为 0，显示名为「Outlook 邮箱」，引用 `catalogPlacement=plugin_only` 的 `awaken.microsoft.outlook` host Connector，并随包提供九个中文 Outlook 邮件 Skill，分别覆盖综合邮件、收件箱整理、回复草拟、订阅清理、任务提取、共享邮箱、附件、定时发送和邮箱组织；连接、审批等待、重连、退出登录和 Outlook MCP 都只在插件页面展示，连接器目录不重复出现。

九个 Outlook Skill 共同定义模型侧邮件操作协议，不建立新的工具权限系统：简单近期、文件夹/未读导航、自由文本搜索分别路由 `get_recent_emails`、`list_messages`、`search_messages`；列表预览足够时不得机械抓取全文，需要多封完整正文时使用一次 `get_messages_batch`；分页原样复用不透明 `nextCursor`，文件夹名称先经 `find_mail_folder` 解析，已读与分类优先使用各自专用工具。读取先限定邮箱/范围并唯一确定 message ID；新邮件、回复、转发与定时发送默认草稿优先，`to/cc/bcc` 使用邮箱字符串数组；真正外发前重新读取草稿和附件，展示发件邮箱、实际收件人、主题、附件、回复范围与发送时间。宿主存在提问用户工具时优先调用，不存在时输出摘要并停止等待；只有用户确认当前摘要后发送一次，摘要变化、批量范围变化或结果未知不得复用确认或自动重发。退订成功不隐含回复、移动或删除授权，整理/任务提取也不隐含发送。该协议只改善模型选工具和调用顺序，MCP tool 在 connected/auth-ready、schema 有效时仍按 07/06 域开放进入 provider。

Outlook 的通用读取／对象与发送确认步骤分别由 outlook-email 包内 references 拥有；专项 Skill 在进入发送时显式调用同插件的 outlook-email，读取其发送参考，避免把提到另一个 Skill 当作自动加载。同一份已展示、已确认且参数未变化的最终摘要不重复提问，原有发送确认与未知结果不重放边界不变。正常批量任务创建的草稿、文件夹、分类与计划保留为业务结果；只有用户明确授权清理的本次测试夹具可按精确 ID 清理。附件读取所需临时副本可写任务目录；明确保存意图与目标目录后由 Agent 解析绝对新路径、准备目录并使用唯一文件名，不能覆盖已有文件或把下载授权扩成外发。

Desktop 安装入口只接受用户点击选择或拖入的本地 ZIP。来源确定后自动完成格式、包内容与 digest 校验：不符合时在安装弹窗明确显示格式错误，通过时单一拖放区变为浅绿色并允许安装，不设置人工“检查插件”步骤。Core 的 `local_path` 目录输入只保留给受控 Plugin Creator 候选校验、安装与替换，不作为 Desktop 安装方式。ZIP 与受控候选目录复用同一 containment、预算、执行意图和 digest 检查要求。多个合法 manifest 且 identity 冲突时必须由用户明确选择方言；不得按扫描顺序取第一个。

插件解析器不得把单一根 `SKILL.md` 加普通资源的包猜成 manifestless Claude Plugin；这种包返回 `SKILL_PACKAGE_SELECTED` 并由 Desktop 切到 Skill 安装、让用户确认 project/global 范围。manifestless Plugin 必须至少具有 Claude 插件专属默认目录或文件（`skills/`、`commands/`、`agents/`、`hooks/hooks.json`、`.mcp.json`）；带正式 Claude/Cursor manifest 的根 `SKILL.md` fallback 仍属于插件。相反，Plugin manifest 或插件 Skill 布局进入 Skills 安装器时由 08 域返回 `PLUGIN_PACKAGE_SELECTED`。两个 Store 都在 Core 边界 fail closed，Renderer 的自动页面路由不能替代这些校验。

安装树位于：

```text
~/.awaken/plugins/packages/<name>/   # PLUGIN_ROOT，只能通过安装/同名替换、受控 MCP Source 编辑或 commit 推进 digest
~/.awaken/plugins/data/<name>/       # PLUGIN_DATA，跨升级保留
~/.awaken/plugins/.staging/          # 隔离物化
~/.awaken/config/plugins.json        # v2 状态、override、变量引用、来源与迁移冲突
```

Core 向插件页提供安装来源、内置身份与排序、品牌图标键、方言、版本、digest、完整性与兼容事实；Skills、MCP Servers、Rules、Agents、Commands、Hooks、Variables、Apps 八组 inventory；`native | adapted | recognized_unsupported | ignored_by_dialect | invalid` 精确状态；以及组件级 desired/configuration/authentication/runtime/integrity。install/list/get 同时返回来源中立的 `setupItems` 与 `setupSummary`。Desktop 的常驻 Console 只投影来源中立的插件身份和紧凑组件目录，不展示厂商方言、物理来源、digest 或状态矩阵。所有组件详情使用与 Skill 一致的固定尺寸 Dialog，内容量只影响正文滚动，不改变窗口尺寸；标题统一只显示类型图标和组件名称，不重复显示第二行组件类型标签。用户点击 Skill 后只渲染 `SKILL.md` Markdown 预览，使用动作固定在预览滚动区之外的右下角 footer；其他组件继续按需提供 Source/Preview、诊断、资源、Variables、MCP tools 与 Rule/Command/Agent/Hook 控制。MCP Source 是安装包对应文件的逐字文本，不替换 `command`、`args`、`url`、`env`、`headers` 或源文件中已经存在的其他字面值；Secret Store 注入值不属于源文件，不得为展示而反向合并。精简展示不改变 Store、运行时校验或 fail-closed 判定，独立变量配置中的 Secret 仍只显示 configured/masked。

Skill/Rule/Command/Agent 的 Composer 动作必须同时满足：父插件启用、组件 desired 启用、完整性有效、配置就绪且 mapping 为 `native | adapted`。不满足条件的组件仍可检查详情、Source 和 Diagnostics，但 Desktop 不显示也不执行插入动作；`recognized_unsupported | ignored_by_dialect | invalid` 不能被 UI 包装成可运行入口。Renderer 的展示检查要求和点击时防御校验只是第一层，Core 的 token/digest/logicalId 复验仍是最终安全边界。

整体 Plugin Composer 目录要求父插件已启用且 digest 有效。App 在 Desktop ready 后主动加载并持有来源中立的 Plugin catalog 快照；输入 `@`、打开 Plugin picker 或进入插件页都同步消费该快照，不能为了重验而清空 action/card 或展示整页 loading，catalog revision 触发的请求只在后台完成后原位替换。普通插件仍只在至少有一个可用 Skill 或 MCP 时进入 `@` 的「插件」分组；内置插件启用后即进入「内置」分组，并按 `builtinOrder` 稳定排序，尚缺账号或必填配置时条目可见但禁用，完成 setup 后原位变为可选择。`awaken-outlook` 为首个内置插件项，菜单使用 Microsoft 官方 Outlook 彩色产品图标；选中后的结构化 token 仍只保存稳定 pluginName/digest，不把图标或本地资源路径写入 prompt。

组件 desired mutation 与 inventory 共用同一 `switchable` 判定：组件必须 valid、配置就绪、属于 native/adapted 映射且不能是 Variable；任一条件不满足时 Core 拒绝 mutation，并返回 409 `COMPONENT_NOT_SWITCHABLE`。Variable 只能通过配置接口修改，不能通过组件开关写 desired。

插件整体 `enabled` 是所有组件的父级有效状态：关闭插件后，inventory 中每个组件的有效 `desiredState`、所有 MCP server 配置与 runtime projection 都必须为 disabled/off，不能被组件 override 或 legacy server toggle 覆盖。组件自身 override 继续持久化但不运行；重新启用插件时恢复这些偏好。父插件关闭期间 Desktop 锁定组件与 MCP tool 开关，避免把“保存将来偏好”误呈现为当前已经启用。

list DTO 不携带正文；详情按组件懒加载。logicalId 由来源路径和方言身份稳定生成，wire 使用无填充 base64url；revisionId 绑定 package digest 与 component source digest。

### 方言发现与优先级

各方言共用 `dialect.parseSkillComponents`，在组件映射阶段调用 Skill 域的入口、frontmatter、保留名称与 schema 校验。子目录 Skill 以实际父目录为名称基准，根 `SKILL.md` 以已解析的插件身份为基准；临时 staging 目录不参与名称判断。失败组件保留 inventory 与 `plugin_skill_invalid` 诊断，标记 `invalid`，不计入可运行 Skill 数量，也不影响有效的兄弟组件。`acceptance_skill_validity_test.go` 覆盖四种方言、根目录安装身份和运行时 schema；兼容夹具保留原始内容，目录名不匹配的既有样例断言为无效。

Console 的无效组件行显示“组件不可用，查看原因”。Skill 仍采用单一正文预览，首条错误在固定 footer 展示且限制长度，不增加详情标签；调用入口保持关闭。`PluginConsole.ui.test.tsx` 同时验证原因可见、正文可读和无调用按钮，有效 Skill 不显示无关诊断。

- Agent Plugins 1.0.0 只按正式 `plugin.json`、`skills/` 和 `mcp.json` closed schema 解析。
- Codex native 按 manifest 声明或默认 `skills/`、`.mcp.json`、`hooks/hooks.json` 解析；根 `hooks.json` 不属于默认 Hook。legacy `commands/` 只接受 Markdown、非空 description frontmatter 与 4000-byte 检查要求，仍以 Command 身份展示。
- Claude Code 的显式 `commands`/`agents` 替代默认目录，显式 `skills` 追加默认 `skills/`，Hooks/MCP 走各自 merge；根 `SKILL.md` fallback 只在默认 Skill 目录为空时使用。
- Cursor 显式声明替代该类默认发现；默认 rules/agents/skills/commands/hooks/MCP/variables 按官方路径和扩展名解析。Cursor Hook 有 `postToolUseFailure`、`sessionEnd` 和 `preCompact`，没有 `postCompact`。
- 来源方言不加载的文件必须保留为 `ignored_by_dialect`；已识别但没有安全 adapter 的组件保留为 `recognized_unsupported`，不能静默丢弃或伪装成可运行。

### Skills

启用且完整性有效的 Skill 组件以精确 package selection 进入 08 域；组件 override 会从 discovery 移除单个 Skill。Catalog identity 为 `plugin__<plugin>__<skill>`。Composer 选择由 Core 重新解析，不信任 Renderer 路径。

Plugin Console 是 plugin Skill 唯一的管理与浏览入口；Skills 页面及统一 `/` Skill 菜单不投影 `sourceOrigin="plugin"`。这不改变 Store 的精确 root 供给、统一 Catalog、模型侧 `skill` 工具或组件启停。Composer 通过 `@ Plugin` 选择整个启用且 digest 有效、至少含一个可用 Skill 或 MCP server 的插件；只含 Skill 的插件仍可选择，Core 在 run start 重验 pluginName/digest 并提供优先使用该插件 Skill/MCP 的 host-owned 引导。Plugin Console 的组件级“在对话中使用”使用 Core 投影的 `plugin__<plugin>__<skill>` Catalog identity 生成普通 `type=skill`、`sourceOrigin=plugin` 的精确 token；Renderer 不按路径或显示名猜 identity，run start 仍由统一 Skill Registry 复验。Console 不提供把 plugin Skill 复制、派生或安装为普通用户 Skill 的入口。

### MCP

四方言 MCP 都归一化为 06 域 `mcpclient` config。server identity 为 `plugin__<plugin>__<server>`；Manager 负责连接、OAuth/readiness、tools/list、调用和自动恢复。配置保存、插件/组件/tool mutation 与网络恢复都会走现有刷新链，刷新按 server identity、scope、插件包 digest 和完整配置做幂等协调：只有四者都匹配的 MCP session 才保持不动；同名插件包替换即使 command/cwd 未变，也必须因 digest 变化停止旧进程并从新包重建。另一个插件的 Skill、setup 或整体状态变化不得重启不相关 MCP。Plugin Console 不提供独立的手工 restart/reload 入口。插件变量只在方言允许的位置插值，未解析引用 fail closed。

插件通过 `host_connector` 声明使用宿主提供的 MCP 时，该引用同样归一化为插件 inventory 中的 `mcp_server` 组件，并在 Plugin Console 的「MCP 服务」分组展示名称、连接状态和真实 tools/list；不能因为 server runtime 由 Connector 域拥有就从插件详情隐藏。该组件保留插件 setup 的 logicalId、来源和 authentication gating，但运行 identity 必须由已注册 Connector ID 解析，不能信任插件伪造的任意 server name。共享账号、server 生命周期、组件/逐 tool 启停和凭据仍由宿主 Connector 拥有，因此此类 MCP 组件在插件页可查看但不可独立编辑、启停或修改 tool override；关闭或卸载一个引用插件也不得断开其他插件共享的宿主连接。Connector definition 的 `catalogPlacement=plugin_only` 表示插件页是该能力唯一用户入口；Core 仍保留共享 owner，`GET /v1/connectors` 与连接器目录不得重复投影。

Plugin Console 允许编辑 MCP 组件所属的整个源文件。保存请求只提交 Core 返回的 logicalId、当前 recorded digest 和完整文本；Renderer 不解析 JSON、不定位物理路径，也不直接写安装树。与当前文件字节完全相同的保存是成功 no-op，返回 `changed=false` 且不更新 digest、状态或运行时；其他修改由 Store 在 `.staging` 中复制完整包、写入候选文件，重新执行 containment、方言、identity、manifest 与 MCP component 校验。候选仍必须由同一方言/manifest 拥有且至少声明一个有效 MCP server。验证通过后 Store 再复核 live tree 与 recorded digest，通过 CAS 原子切换 package、状态与新 digest；旧 package 进入 Trash，失败恢复旧包和旧记录。成功通知统一刷新 Skill/MCP runtime、组件 inventory 与 composer catalog revision。无效文本、stale digest、digest drift 或 active generation 都不能改变 live package。

MCP server 发起 form/URL elicitation 时复用当前 run 的外部交互门；表单提交值只返回正在等待的 MCP call，取消或无可交互 run 时 fail closed。具体 schema、序列化和保密边界由 [06 MCP 配置、传输与生命周期](../../06_MCP运行时/连接配置与认证/实现方案.md)拥有。

逐 tool override 独立于整个 MCP component 的启停 override 持久化和投影：用户只关闭某个 tool 时，不要求先切换 server/component；Store 重载后仍必须把它投影到 `DisabledTools`。它只影响中央工具注册和新 run snapshot，详情仍显示 disabled tool。`mcp_tool` Hook 只能调用当前插件已启用、ready 且未被逐 tool 停用的 server/tool，不能拼 shell。插件 MCP 和 Hook command 以当前登录用户身份运行，没有额外沙盒。

### Rules 与 Commands

Rule Assembler 只产生 instruction fragment；最终排序、16 KiB 单源预算、32 KiB 总预算、digest 和 run 冻结由 `src/instructions` 拥有。优先级是：当前用户请求 > 手动 Plugin Rule > project AGENTS > global AGENTS > 自动 user-scope Plugin Rule。支持 always、file_globs、manual；`model_decides` 当前只允许手动加入。

Command 保留插件 namespace、argument hint 和 prompt template。Renderer 只保存 pluginName、digest、logicalId 与参数；Core 在 run 启动时重验并展开 `$ARGUMENTS`、零基 `$ARGUMENTS[n]`、兼容 `$0` 及既有一基 `$1..$n`。模板没有占位符但用户提供了参数时，按 Claude Code 行为在正文末尾追加 `ARGUMENTS: ...`，不能显示可输入参数却静默丢弃；`<required>` hint 或模板占位符缺参时拒绝，只有 `[optional]` hint 时允许空参数。stale digest、disabled/invalid component 同样拒绝启动。Console 只在 Core detail 明确返回 `acceptsArguments=true` 时显示参数输入，必填且为空时禁用插入动作。

### Hooks

mapped 且 handler 可表达的 Plugin Hook 以 `SourcePlugin` 编译进后续新 run 的同一个 Hook snapshot。支持 Codex command、Claude command/http/mcp_tool/prompt/agent、Cursor command/prompt。事件是显式映射表；厂商 command 在编译期展开允许的根变量并拆为 argv，拒绝 shell operator；输入输出由方言 protocol adapter 转为统一协议。

Plugin Hook 复用 Awaken 统一 Dispatcher。tool event 的 handler 级条件也必须进入 matcher；`Bash(git commit:*)` 只能触发对应命令，不能因只保留外层 `Bash` 而扩大成所有 shell 调用。timeout 采用上游兼容语义：普通事件未声明时默认 600 秒，厂商声明正数 timeout 时原值生效，不再由插件编译层压缩为 10 秒；`SessionEnd` 对应的退出事件单独默认 1.5 秒且最多 3 秒。超时按既有 `timed_out` 回执与 failure policy 收敛，默认 `continue` 不阻塞后续模型运行。Dispatcher 的每 run invocation、累计墙钟和取消边界仍是统一宿主保护，它们不改写已编译 Hook 的单次 timeout。

command Hook 的配置级 `async`/`asyncRewake` 与 Claude stdout `{"async":true,"asyncTimeout":...}` 会建立有界后台 invocation：进程启动成功后立即返回 `scheduled`，完成后再写 durable completion 与 Plugin 回执，且在此期间继续持有对应 Plugin generation lease。异步 Hook 不得追溯阻断或改写触发操作；`asyncRewake` 的 model-facing feedback 作为不可信数据进入同一 thread 下一次 run，不自动发起新模型 run。`SessionEnd` 始终同步。后台 feedback 每 thread 最多 32 项/32 KiB，只在当前 Core 进程内保留；异步 command 最长 10 分钟，父 run 被取消时一并取消。prompt/agent/http/mcp_tool 当前仍同步。

当前只把 package/plugin scope Hook 编入新 run。Agent/Skill-scoped Hook 会保留 scope、owner 与诊断并保持不可运行，不能退化成 package Hook；待对应组件的 run-scoped activation bridge 完成后再进入当前 run。

回执复用 `hook_invocation_started/completed`，携带 plugin name/digest/logicalId/revisionId；异步调用在调度时只有 started，后台真正结束后才产生 completed。插件详情另保留当前 Core 进程内最近 512 条完成回执；不跨重启。失败/超时项可做诊断性重试，但不会重放原 run 输入。

### Plugin Agents

Claude/Cursor Agent 编译成现有 `subagentruntime.Role`，agent type 为 `plugin__<plugin>__<agent>`。插件明确声明的 `maxTurns` 或 `timeoutSeconds` 原值保留；未声明时保持 unset，不再添加 Plugin 专属的 8 turn、32 次工具执行或 5 分钟限制。child 仍服从原生 Subagent 的默认 256 轮/1024 次工具执行、协作组 8 个活动 Agent（包含 root）、128 个排队任务、8 层深度及依赖任务取消边界；这些宿主边界不由插件扩大。system prompt、read-only 与 tool allowlist/denylist 同样只收窄 child；background/isolation/model hint 不能扩大父 run 权限。并发、取消、消息、Journal、Workbench task group 和 Inspector 全部复用原生 Subagent。Composer token 和 invoke route 都重验 digest/logicalId；Plugin Console 只投影插件明确声明的限制，不把未声明的 `0` 解释为厂商要求，也不展示一套 Plugin 专属预算。

### Variables 与配置

Variables schema、普通值和 Secret reference 存于 Store v2；Secret value 只进入 secret store。状态写失败会回滚本轮 secret 变更；reset 在状态提交后清理旧 ref。升级只迁移 key 和 type 都兼容的变量；不兼容值和消失的 override 进入 `migrationConflicts`。Secret Store 值永不进入 Renderer；用户或插件作者已经写在 MCP 源文件里的字面值属于该文件本身，Source 编辑器按原文展示和保存，但不会获得额外的运行时 Secret。

Claude 只按 `sensitive: true` 判定 Secret；Cursor 除显式 `secret/sensitive` 外，还把 key 含 `TOKEN`、`SECRET`、`PASSWORD` 或 `API_KEY` 的字段按 Secret 处理，以避免未标注凭据落入 `plugins.json`。配置 UI 显示 schema default、类型约束和依赖该变量的组件，但不会回显 Secret。

### Setup 与本地鉴权

四方言统一归一化为 `SetupRequirement`，kind 为 `configuration | secret | oauth_pkce | oauth_device | mcp_oauth | cli_login | external_setup | host_connector | app_connector`，状态为 `ready | needs_configuration | needs_auth | authorizing | verifying | pending_admin_approval | expired | failed | unsupported`。Claude `userConfig`、Cursor Variables、远程 MCP OAuth 与 Codex Apps 从原声明生成；Agent Plugins 可使用 `plugin.json.extensions["io.awaken.setup"]`，四方言都可使用 `.awaken/setup.json`。同一 Agent Plugin 同时存在 extension 与 sidecar，或任意来源产生重复 setup ID 时，安装校验直接失败。

Awaken 声明只接受 configuration/secret、Authorization Code + PKCE、Device Authorization、已注册宿主 CLI Connector、已注册 Awaken host Connector 与外部设置页面。`host_connector` 必须只给出稳定 `connectorId` 和受其 gating 的组件，不得覆盖宿主 OAuth endpoint/client/scope/binding；账号由宿主 Connector 拥有，多个插件可以引用，卸载单个插件不退出共享账号。MCP OAuth 由远程 MCP 原声明和 discovery/CIMD/DCR 路径生成，App Connector 只由 Codex App 声明生成。公共 `client_id` 可直接声明；`client_secret` 只能引用 Secret Variable。凭据 binding 只允许 `mcp_transport`、`http_header` 与 `process_env`，且必须指向对应 MCP 或 Hook 组件；Skill、Agent、Command prompt 和模型上下文没有凭据 binding。

Plugin Auth Broker 完全运行在 Core 本机进程。PKCE callback 只监听随机 `127.0.0.1` 端口并校验 state；Device Flow 优先打开 `verification_uri_complete`，只有缺少完整地址时 Electron Main 才用原生弹窗显示 user code。非 loopback endpoint 必须使用 HTTPS；Core 的 OAuth client 对初始请求与 redirect 都执行 DNS/私网检查，并限制 redirect 数。Renderer 只接收脱敏 session 阶段、错误和过期时间，不接收 code、token、refresh token、client secret 或 Secret value。

`authorizing/verifying` session 由 Core 持有，其存活不依赖 Renderer 页面、Awaken 窗口焦点或系统浏览器是否在前台。Plugin Console 卸载时只停止本页轮询，不发送 cancel；重新进入时只能使用当前 `pluginName/setupId/digest/fingerprint` 查询匹配的活动会话并恢复观察，stale 页面不得认领旧会话。仅明确取消动作、会话超时或协议终态能结束授权。

管理员审批是授权会话的独立非就绪状态。provider 明确回调 `admin_consent_required` 等无歧义错误时 Core 自动进入 `pending_admin_approval`；外部系统浏览器停留在审批请求页且不回调时，Plugin Console 在活动 OAuth session 上提供“页面要求管理员审批”，由用户显式记录该事实。该标记只把 plugin/setup/fingerprint 与观测时间写入 `auth/plugin-approvals.json`，不读取浏览器、不产生凭据、不轮询客户租户；关联组件继续 fail closed。管理员批准后用户必须点击“批准后重新连接”完成新的 OAuth，只有真实 token 保存成功才为 ready。插件升级指纹变化、重新发起授权、退出登录或卸载都会清理对应标记。

插件账号 identity 固定由 `pluginName + setupId + requirement fingerprint` 产生。OAuth token、refresh token 与 client secret 保存到系统 Keychain；`auth/plugin-accounts.json` 和既有 credential metadata 只保存 credential ref、fingerprint、scope、expiry、revision 与待清理 tombstone。fingerprint 覆盖 flow、issuer/endpoints、client、resource/audience、scopes 和 bindings；任一变化产生新 identity，不复用旧账号。卸载先取消活动 session，清理变量 Secret 和当前/旧 OAuth ref；Keychain 删除失败且 tombstone 已写入时由下一次启动重试，不把真实凭据写入 tombstone。

`host_connector` 不使用上述 plugin-scoped identity，而是读取 Connector 域的共享账号与 runtime 状态。解析器为每个声明生成受同一 setup gating 的宿主 MCP 引用组件；插件 API 再用 Connector definition/status 解析显示名、真实 server identity、snapshot 和 tools/list。插件 setup 的 start/session/cancel 只是对宿主会话的脱敏代理；“退出登录”明确影响所有引用该 Connector ID 的插件。未知 ID 为 unsupported。Awaken 官方 Outlook 插件使用 `awaken.microsoft.outlook`，其 Outlook MCP 与九个 Skill 都在 Connector overall state 为 connected 时 ready。

configuration/secret 缺失或 authentication 未 ready 时，只阻止引用它的组件；其他已就绪组件仍可运行。普通 configuration 的 `process_env` / `http_header` binding 由 Plugin Store 在 runtime projection 时写入目标 MCP transport；配置 UI 可以回显普通值，但 ready 状态不得与实际 transport binding 分离。Secret/OAuth binding 在 runtime config 中只保留 opaque ref：HTTP Hook header 和 command Hook env 在执行前由 Core 解析，通用 OAuth 的 MCP transport 在每次请求前解析并刷新 token；Renderer、Source、诊断、日志、Journal 与模型都看不到 Secret/OAuth 值。插件进程仍继承当前登录用户本机文件与网络权限，但这不授予它读取其他插件或宿主账号凭据的能力。`cli_login` 只能引用 Registry 已注册的 CLI Connector，插件不能提供任意登录命令；`external_setup` 点击后仍必须用关联 runtime/Connector probe 证明 ready。

明确的 MCP `401`、`invalid_token` 或 `needs_auth` 才进入 Workbench `ExternalActionGate`。用户完成插件详情中的连接后，同一 tool call identity 对读写调用都只重放一次；第二次仍需授权返回 `plugin_auth_replay_exhausted`。timeout、断线、取消和结果未知不归类为鉴权失败，也不自动重放。MCP SDK transport 自身对成功完成的 OAuth handler 同样只执行一次协议级请求重试。

Core-owned host Connector 使用自己的 provider adapter 和错误码；Outlook 的第二次鉴权失败返回 `connector_auth_replay_exhausted`，不冒充插件账号失败。

Codex Apps 不是 OAuth 声明。当前只显示 App 名称、Connector ID、来源和 unsupported 诊断，不显示连接按钮，也不会解析到 OpenAI Connector runtime。

### Generation、替换与卸载

每个 run 启动时先校验 Composer token、编 Hook 快照并组装 Rule，再收集本次绑定的插件名字：Composer 点到的插件/Skill/Rule/Command/Agent，以及已经编进本次 Hook 快照和 instruction 的插件。只对这些名字计算 `plugin_generation`（哈希被绑定插件的 name+digest）并持有 lease，直到 terminal worker 退出；异步 Hook 未结束时继续握住同一批名字。未绑定任何插件的 run 不占 lease。

存在活动 lease 时，只有被占用插件的安装替换、卸载、commit、插件/组件/MCP tool/Rule/Variables 修改返回 409 `RUNTIME_GENERATION_IN_USE`。未占用插件的安装、卸载和配置可以继续。该策略不热切换正在使用的插件，也不让一个 run 混用同一插件的两代。Plugin Console 的卸载确认失败时，错误显示在该弹窗内并保持打开；取消或关闭时清除。这条错误不写到插件列表横幅，也不走 Desktop 全局 toast。

Desktop 安装同名插件时默认进入替换流程，不要求用户勾选确认。替换先把旧包移入 rollback staging；新包和原子状态成功后旧包才进入 Trash，失败恢复旧包。替换成功后的 runtime projection 必须携带新 package digest，使仍指向同一绝对 command/cwd 的 MCP server 也停止旧子进程、注销旧 tools/list 并从新包重建；不能让 Trash 中的旧进程继续服务。卸载同样先将 package/data 合并 stage，状态提交后一次移入 Trash；Trash 或状态写失败时尝试恢复包、数据和记录；若恢复也失败，保留备份，不能声称已完整回滚。`PLUGIN_DATA` 跨升级保留；卸载成功后清理状态/secret。重启从持久状态恢复 override 和变量。

## 必须保持的规则

- Renderer 不解析 manifest、不读安装目录或 Keychain、不拼 URL/command/argv，也不推断 ready；MCP Source 编辑只传递 Core 已读取的原始文本和用户修改后的完整文本。
- 安装检查不执行候选 Plugin component。
- installed tree 直接变化形成 digest drift，runtime projection fail closed；只有 digest-pinned install/replace 或 CAS commit 能签收。
- Secret Store 中的 secret value 不进入 Renderer、日志、Journal、模型、导出或 diagnostics；这不改写安装包源文件中本来存在的字面文本。
- mapping、desired、configuration、authentication、runtime、integrity 是不同状态。
- installed package 禁止任何未签收的直接修改；Plugin Console 的 MCP Source 保存必须经 staging validation、expected digest CAS、原子 package/state 切换和 Trash rollback。Plugin Console 不从插件树生成独立 Skill 副本；模型侧授权直改仍必须以 `plugin commit` 签收 expected digest。
- Plugin runtime 不扩大 TaskScope、Subagent boundary、MCP readiness、Hook budget 或 OS identity。
- 插件组件继承当前登录用户能够使用的本机文件与网络权限是 Awaken 的默认运行模型；安装弹窗不设置权限确认勾选，安全边界仍由零安装时执行、digest/CAS、运行时既有检查要求和 fail-closed 不变量承担。

## 插件页产品与架构：验收

首先验证目录首帧：Desktop ready 后输入 `@` 必须立即出现已有内置/插件项且无 loading 闪屏；从 Workbench 首次进入插件页必须立即显示内存快照，从卡片进入 Console 必须立即显示完整标题，后台刷新期间不得清空页面。

自动化通过后仍需在真实 Awaken Desktop 验证：插件页只保留本地 ZIP 安装入口；点击和拖放均会自动校验；错误态明确、有效态为浅绿色；同名自动替换；普通 Skill ZIP 自动切到 Skills 安装并只写所选 project/global 根，插件 ZIP 从 Skills 安装入口自动切回插件安装且不生成普通 Skill；并继续验证紧凑 Plugin Console 不显示厂商/路径/digest/状态矩阵，顶部没有“检查更新”且整体开关位于操作区最右；首次读取完成后返回插件列表并再次进入同一插件，组件和账号行同步出现、后台刷新且不再显示骨架；发起 Outlook 授权后切到系统浏览器、其他窗口与 Awaken 内其他页面，返回插件详情时仍显示同一授权等待态并继续轮询，不得自动取消或创建第二个会话，再用明确“取消”动作验证会话才终止；Outlook 已连接时显示带官方图标的独立账号行，“已连接”下拉含“重新连接/断开连接”，打开下拉不改变顶部整体开关。点击 Skill、MCP、Rule、Agent、Command、Hook、Variable、App 均打开相同固定尺寸的独立 Dialog，短内容不缩小、长内容不扩大且只滚动正文；所有组件 Dialog 的标题图标、名称和关闭按钮对齐且无第二行类型标签；Skill 正文只呈现 `SKILL.md` Markdown，右下角“在对话中使用”不随正文滚动，点击后返回 Workbench 并插入精确 Skill token 而不是整个 Plugin token；App/unsupported 只显示识别事实且无运行 action；Agent 详情只显示插件实际声明的限制，未声明时没有 8/32/5 分钟占位；Command 只有在 Core 明确声明确实接受参数时才显示输入框，输入可选参数后新 run 的展开正文必须实际包含它；Hook 详情显示普通 600 秒默认、厂商声明值或 `SessionEnd` 退出预算，声明 async 的真实长进程不得阻塞首个模型请求，完成后回执由 started 推进为 completed，异步反馈只进入同一会话下一次中文测试任务。MCP 详情没有重复的“重新加载”按钮，Source 原样显示包内文本，编辑/取消/保存位于固定 footer，保存有效修改后 digest、组件目录和 MCP 运行态自动刷新，无效 JSON、stale digest 与 active run 不改变原文件；格式错误、保存成功、内容未变化及其他已打开组件的操作反馈均位于 Dialog 固定 footer，与操作按钮相邻且垂直居中，弹窗顶部和正文区无大横幅提示；关闭父插件后全部组件与 MCP tool 开关显示关闭并锁定、运行时目录不含该插件，重新启用后恢复原组件偏好。其他组件的 state/config、MCP readiness/tool、Rule/Command/Agent token、Hook 回执/重试、active generation 冲突、重启恢复、同名替换和卸载仍有效。提交结构化 token 后须确认 Chromium console 没有 `Maximum update depth exceeded`；如发生新的 Renderer 渲染异常，界面显示可重新加载的恢复页而不是空白窗口。1440×903 窗口另须检查主页面和 Dialog 均无水平溢出。Gallery/mock 不能替代。

## 插件管理界面的实现

### Plugin Console

Console 首屏保持产品化和来源中立：点击卡片后先用同一 Plugin catalog 快照同步显示顶部身份区，再在后台读取组件、配置与 setup；不能先停留在列表或切换到整页 loading。组件、配置与 setup 第一次读取成功后按当前 runtime client、插件名和 digest 保存只含非敏感 DTO 的内存快照；用户返回列表再进入同一版本详情时必须同步渲染该快照并在后台静默刷新，不得重新显示组件骨架，插件被替换或 digest 变化时不得复用旧快照。顶部只显示插件图标、完整名称、可选版本、可用时的卸载和整体开关，整体开关固定为最右侧操作；名称允许在可用宽度内自然换行，不使用 ellipsis 截断或裁切字形，内置/版本元信息跟随换行。内置插件改为显示「Awaken 内置」且不显示卸载。页面不显示来源方言厂商、安装路径、digest、兼容胶囊、完全访问 notice 或组件状态汇总。顶部身份区下方可显示紧凑的“待完成设置”，只列当前待配置、待连接、进行中、失败或 unsupported 的 setup item；账号 setup 全部 ready 时不显示“待完成设置”或“设置已完成”标签，而显示独立的账号连接行：左侧为受控品牌图标、账号能力名称与简介，右侧“已连接”下拉提供“重新连接”和“断开连接”。该账号行不替代、联动或挤占顶部插件整体开关；关闭插件后仍保留“已连接”状态，只有账号行内的明确“断开连接”动作才能退出账号。安装成功后仍直接进入详情，不自动弹出 setup wizard，也不自动打开网页。只有用户点击“配置”“连接账号”“重新检测”“重新连接”“断开连接”等动作时才经 typed bridge 调用 Core。Desktop 不提供“检查更新”按钮：本地 ZIP 来源不包含可查询的上游版本协议，同名新 ZIP 继续通过安装入口执行安全替换。组件按 Skills、MCP Servers、Rules、Agents、Commands、Hooks、Variables、Apps 分组，标题只显示数量；行只显示类型图标、名称、Awaken 生成的简短用途摘要以及可用的组件开关，不直接投影可能夹带厂商品牌的包内长 description。非 switchable 组件用进入箭头打开详情，不在主页面铺开 mapping、configuration、authentication、runtime、integrity 或诊断状态。

### Plugin Console

Main 是浏览器与原生 device-code UI 的唯一 owner：它取得 Core 返回的一次性 authorization/verification URL 后再次校验 public HTTPS 或 loopback HTTP，再调用系统浏览器；Renderer 不取得 URL 以外的授权材料。只有 Device endpoint 没有 `verification_uri_complete` 时，Main 用原生消息框显示 user code，并向 Renderer 返回已脱敏的 session。Renderer 轮询只读取 `authorizing/verifying/pending_admin_approval/ready/expired/failed/cancelled`、安全错误和过期时间，完成后重新读取 setup、组件与 MCP runtime；若会话终态携带错误但同一次刷新已经证明对应 setup 为 `ready`，当前页面必须立即清除该过期错误，不能要求用户切页重新挂载。授权会话由 Core 持有，不与 Awaken 窗口焦点或 Plugin Console 组件生命周期绑定；切到系统浏览器、其他窗口或 Awaken 内其他页面时，Renderer 只停止当前页观察，不调用 cancel。返回同一插件时，Renderer 必须用 `pluginName + setupId + pluginDigest + requirementFingerprint` 从 Core 重新取回活动的 `authorizing/verifying` 会话并继续轮询；只有用户明确点击“取消”、超时或协议终态才能结束会话。授权活动期间另提供“页面要求管理员审批”，只调用 Core 的 session transition；进入审批等待态后显示“批准后重新连接”，不继续显示无限加载，也不假定远端已经批准。`host_connector` setup 复用相同交互，但账号状态、强制重新授权和断开连接由连接器域拥有；重新连接在新 token exchange 成功前保留当前可用凭据，用户关闭或取消网页不会先退出原账号；插件卸载不退出共享账号。其提供的宿主 MCP 必须继续出现在该插件的「MCP 服务」分组，并展示连接状态和工具；详情明确标记“由 Awaken 连接器管理”，不提供会影响共享 runtime 的组件开关、tool 开关或源文件编辑。若 Connector 声明 `catalogPlacement=plugin_only`，插件页同时是连接/审批/重连/退出登录的唯一 UI，顶层连接器目录不能重复展示；当前 Outlook 即使用此边界。App Connector 的 `unsupported` item 没有可点击的虚假连接动作。

### Plugin Console

- Skill：打开后直接渲染 `SKILL.md` 的单一 Markdown 预览，不显示“详情 / 预览 / 源文件 / 诊断”页签或资源清单；“在对话中使用”固定在 Dialog 右下角 footer，不进入预览滚动区；不提供复制或安装为普通用户 Skill 的入口；
- MCP：local/remote/in-process、connection、error、tools/list，逐 tool switch，以及安装包源文件的原文查看与编辑；`host_connector` 引用的 in-process MCP 复用同一详情结构，但标明由 Awaken 连接器管理，并锁定会影响共享 runtime 的组件、tool 与 Source 编辑。普通插件 MCP 的“源文件”不把 `command`、`args`、`url`、`env` 或 `headers` 替换为占位符。查看与编辑复用同一个源码画布、排版与内部滚动容器，切换时仅改变是否可写，不重建内容并不产生文字位移；编辑按钮与保存/取消动作固定在 Dialog footer。源文件的格式错误、保存成功和内容未变化都作为紧凑文字显示在同一 footer 内的操作按钮旁，与按钮垂直居中，不占用弹窗顶部或正文滚动区。即使内容未变也允许保存并退出编辑，Core 将其作为不改变 digest 或运行时的 no-op；继续编辑、取消或关闭详情都会清除过期错误。有效修改的保存由 Core 在 staging 中完整校验并以当前 digest 做 CAS/原子替换，成功后自动刷新组件与运行态；Renderer 不解析或直接写插件文件，也不提供重复的手工 Reload；
- Rule：always/file_globs/manual/model_decides 和“加入下一次运行”；
- Command：argument hint、带引号参数输入和结构化 Composer token；
- Agent：Properties/Prompt/Source、插件明确声明的 max turns/timeout 和“作为子任务 Agent 使用”；未声明时不展示额外预算，运行仍服从普通 child 的统一边界；
- Hook：event/matcher/handler/scope/failure policy、handler 输入条件、普通事件 600 秒默认或厂商明确声明的单次 timeout、同步/异步执行状态、`SessionEnd` 退出预算、最近回执和失败项诊断性重试；
- Variable：schema、configured/masked、普通值编辑、Secret replacement/reset；变量表单只在相应组件 Dialog 内出现；
- App/unsupported/ignored/invalid：只展示事实和诊断，不提供虚假运行按钮。

### Plugin Console

Hook 重试文案必须说明“不会重放原 run 上下文”；回执 retention 为 memory-only 时必须显示“当前 Core 进程内”。MCP Source 按文件原文展示，源文件本来存在的字面值不会脱敏；Secret Store 的运行时值不反向拼接到 Source，Variable 配置仍只显示 configured/masked。Hook Source 继续屏蔽 command/prompt/header 等可能执行或携带凭据的字段。来源方言、物理路径和 digest 仍保留在 Core DTO、完整性校验与诊断链路中，但不是 Console 的常驻展示字段。

### Plugin Console

HTTP/IPC collection 字段在空集合时必须返回 `[]`，不返回 `null`；Renderer 仍在 typed boundary 做空值归一化，避免旧插件或滚动升级期间的页面级崩溃。

### Composer 与状态刷新

Plugin、Rule、Command、Agent action 都生成结构化 token；Skill 组件保留组件级“在对话中使用”入口并返回 Workbench，不因从 `/` 隐藏而删除。Skill 动作消费 Core 返回的精确 Catalog ID，生成 `type=skill`、`sourceOrigin=plugin` 的 token，不得降级为整个 Plugin token，也不得由 Renderer 从路径猜 ID。普通 Composer 用 `@ Plugin` 选择整个插件；输入 `@` 时直接从 App 已预取的内存 catalog 同步投影内置能力和插件，不清空现有 actions、不再次等待 Plugin list 请求，也不出现 loading 占位；catalog revision 只在后台重验后原位替换。内置插件启用后进入 `@` 的「内置」分组，尚缺账号或配置时可见但禁用，完成 setup 后原位可选择；普通插件进入「插件」分组。Outlook 按内置顺序首先出现，选择目录、当前 Composer 的结构化 token 以及已提交的用户消息都使用卡片相同的 Microsoft 官方 Outlook 彩色图标，不再退化为通用插件 @ 图标。App 负责 caret 插入并返回 Workbench，Plugin Console 不直接改 Composer state。Core 在 run start 复验 pluginName/digest、Skill Catalog identity 与需要的 logicalId，Desktop 不提交可信 prompt/system instruction。`@ Plugin` 成功后由 Core 追加“优先使用该插件提供的 Skill 与 MCP 工具”的 host-owned 引导，只包含 Skill、没有 MCP 的有效插件也继续进入 `@` 目录。

### Composer 与状态刷新

插件整体开关是组件生命周期的父级检查要求：用户点击后列表卡片与详情顶部立即乐观投影目标状态并锁定重复点击，Core mutation 失败时回滚并显示错误；不能在请求期间保留旧值而让开关看起来失效。列表开关成功后直接消费 mutation 返回的 Plugin DTO，不再为了一个插件的启停同步刷新全部 Connector、Skill、MCP 与 Plugin catalog。关闭插件后，所有 Skill、MCP、Rule、Agent、Command 与 Hook 行都显示为关闭且不能单独操作，MCP tool 开关也同步锁定；Core 不再向运行时导出这些组件。组件自身的启停偏好只在 Store 中保留，重新启用插件后按原偏好恢复。整体开关只等待当前 Store mutation 与必要的本插件 runtime 变化，不得同步重启或等待无关插件 MCP；没有自有 plugin-scope MCP 的内置 Outlook 启停不能被其他 MCP session 阻塞。打开组件 Dialog 后，该组件内的保存、切换、重试和配置反馈统一显示在固定 footer，有当前操作按钮时紧邻按钮并垂直居中，不再使用弹窗顶部大横幅或 Desktop 全局 toast。只有不属于已打开组件的页面级反馈才继续使用页面或 Desktop 全局提示。

## Agent 分配时冻结角色

每次分配复制 Role 的 prompt、allowlist/denylist、read-only、预算和超时定义，并保存 role_digest。执行与继续使用同一冻结角色；插件升级、禁用或删除导致当前角色变化时，旧 Agent 的继续失败，不能静默取得新权限。Plugin model hint 通过已配置模型 ID/唯一名称解析完整 profile，不能只替换 model 字符串。底层生命周期和后台规则链接[子智能体协作](../../02_主智能体闭环/子智能体协作/实现方案.md)。
