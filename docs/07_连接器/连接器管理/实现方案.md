## Definition 合并

Registry 按 Connector ID 和 source priority 合并，优先条目胜出；低优先级 definition 当前不会保留完整 shadowed snapshot。normalize 阶段补稳定 `connector:<id>` provider ID、默认 `catalogPlacement=connectors`、去重 capabilities/dependencies。`plugin_only` 只限制顶层目录投影，不影响 definition、状态、账号或 runtime 查询。

## Builtin

connect：factory 生成 MCP config，stamp server provider identity/source/dependencies，写入/覆盖 user config，并调用 Manager start。Registry 随即记录 active entry，但底层 server 可仍 pending 或稍后 failed。

Playwright builtin 使用的第三方 `@executeautomation/playwright-mcp-server` 在 stdio 模式中把日志路径固定到用户主目录。Awaken 只为带稳定 `connector:playwright` owner 且仍使用该受管 package 的配置注入窄加载器，把日志改写到 `AWAKEN_HOME/logs/mcp/playwright-mcp-server.log`；加载器本身位于 `AWAKEN_HOME/runtime/mcp/playwright/`。这条兼容层不得修改 child 的 `HOME`，因此 npm cache、Playwright browser cache 与默认 Downloads 仍沿用当前用户环境；手工同名配置不注入。第三方入口不再匹配受测 logger contract 时连接必须显式失败，不能静默退回用户主目录写日志。

若恢复出的 builtin owner 的全部 server 都是 `disabled`，卡片状态投影为 disconnected；此时 Connect 不是“already connected”，而是重新生成 enabled 配置并启动 runtime，使卡片动作与显示一致。

disconnect：只对当前 active owner 生效；先清理该 user-scoped endpoint 的 OAuth credential identity，再停止 server 并从 user config 删除。由于覆盖前无备份，不能恢复被同名 builtin 覆盖的旧 user config。

## Host OAuth builtin 与 Outlook

`awaken.microsoft.outlook` 的 definition 固定声明 Microsoft authorization/token endpoint、scope、公共 client ID 和 `awaken-outlook` in-process MCP factory。发布构建由 `scripts/build-binary.mjs` 把 `AWAKEN_MICROSOFT_CLIENT_ID` 编译进 Core，开发环境可用同名变量覆盖；插件 setup、HTTP request 和 Renderer IPC 都不能覆盖 redirect、client、secret 或 scope。

connect 在未授权时由 `Connector Auth Broker` 创建单一活动 PKCE session、绑定随机 loopback listener 并把 authorization URL 只返回 Electron Main。callback 先校验 state 和单次消费，再交换 code、将完整 token source 写入系统 secrets backend、把非敏感 ref/contract metadata 写入 `auth/connector-accounts.json`，最后启动 Connector runtime。OAuth contract fingerprint 覆盖 connector ID、authorization/token endpoint、client、resource、scope 与额外授权参数；任一变化不复用旧凭据。

外部浏览器若明确返回管理员同意错误，或用户点击“页面要求管理员审批”，Broker 将 session 转为 `pending_admin_approval`，关闭 loopback listener，并只把 connector ID、OAuth fingerprint 与观测时间持久化到 `auth/connector-approvals.json`。它不读取浏览器页面、不轮询 Entra/客户租户，也不把审批视为凭据。重启后该 Connector 继续显示等待审批；重新连接、OAuth contract 变化或退出登录会清理标记。批准后仍必须重新完成授权 code/token 闭环。

账号 credential identity 以 host Connector ID 为边界，不以插件名为边界；因此多个插件可以引用同一个 Outlook 账号。插件卸载只删除自己的 setup/变量/插件账号，不删除 host Connector 账号；Outlook 为 `plugin_only`，用户只能在任一引用插件中执行“退出登录”，该动作会取消 host auth session、移除 runtime/user config 并删除共享 credential。未来目录可见的 host Connector 仍可从连接器页执行同一动作。

成功授权后 Registry 仍以 Manager snapshot 证明 runtime connected；只有 token 存在而 runtime 启动失败时不得把插件关联组件标成 ready。重启时 user MCP config 的稳定 provider identity 恢复 active owner，host account metadata + Keychain 恢复授权状态，in-process factory 在 Manager 启动前注册；token 只在 Graph 请求前从 broker 解析/刷新，不写进 MCP config、进程 env 或 tool result。

Graph 401 把 token metadata 标为 `needs_reauth` 并原子将当前 Manager server 标为 `needs-auth`。用户重新授权后 Registry 允许从 needs-auth/failed 原位重启；其他 transport 错误不改变账号状态。disconnect 清理 runtime 和共享 credential；Keychain/metadata 删除失败必须返回错误，不伪造退出成功。

## Local/dynamic

connect：生成 config 后以 connector ID 调用 `InjectDynamic`；Manager 在同名冲突时记录 owner/shadowing并替换。disconnect 只移除同一 connector owner 的 dynamic server，防止误删其他 owner。

dynamic state 不持久化；重启后需重新连接/注入。

## 重启边界

重启会从 user/project config 重建 MCP Manager；Registry 同时扫描 canonical user config，并只用 builtin definition 的稳定 provider ID 加 `source=connector` 恢复 active owner：

- 匹配的 builtin 卡片从同一 server snapshot 投影 pending/connected/needs_auth/failed/disconnected；
- 恢复后的卡片可继续执行 connector disconnect；
- 手工配置即使使用相同 server name，只要没有匹配的 provider identity，就不得被卡片认领；
- local/dynamic connector 不从配置恢复，重启后仍需重新注入。

该恢复只解决 builtin durable ownership，不代表统一 live generation 已完成；外部并发编辑配置或运行期跨 source 同名 replace 仍受 06 域 generation 缺口约束。

## CLI 生命周期与迁移

CLI definition 不进入上述 MCP lifecycle。Electron Main 从随 App 发布的只读 manifest 选择当前 `darwin|win32` 与 `arm64|x64` 的精确 CLI 资产，以及与 provider/版本固定绑定的官方 Skill 资产；资产缺失即 `unsupported` 或安装失败，不得回退 npm、Homebrew、`npx skills`、远端 `latest`、安装脚本或其他架构。下载使用 Electron 网络栈和固定 SHA-256。CLI 资产只允许安全单文件解包，完成版本探测后才原子激活到 `AWAKEN_HOME/runtime/cli/<provider>/<version>/<platform>-<arch>/`；Skill 资产限制文件数量与解包大小、拒绝 symlink/路径逃逸，并只把 manifest 声明的直接 Skill 包原子替换到用户级 `~/.agents/skills/<skill-name>`。DWS 固定安装稳定 mono `dws`，Lark 固定安装同版本仓库 `skills/` 下声明的全部 `lark-*` 包，不摄入仓库其他目录或测试 fixture。稳定 CLI 入口位于 `AWAKEN_HOME/runtime/cli/bin`，Core 启动 PATH 预置该目录；Main 始终调用已验证的绝对版本路径。

CLI 的每次 version/status/config/auth/logout/uninstall spawn 以及安装资产下载，都先请求 Main 校准 route，再从 03 域[跨平台网络代理与恢复](../../03_运行时与本地服务/网络代理与恢复/实现方案.md)取得当前派生环境；不能永久复制 Desktop 启动时的陈旧 loopback 代理。CLI 输出命中去敏的 dial/proxy/timeout 故障时，Main 立即重判 route；route generation 改变时 Main 刷新 readiness。已经运行的 auth child 不自动重复创建；切换导致失败后，用户 retry 建立的新 session 使用最新 route。

新受管安装只有在 CLI 与官方 Skill 都成功后才激活稳定 CLI 入口并写入完成记录。Main 在下载、校验、解包、安装 CLI、安装 Skills 与收尾阶段投影单调进度；活动 install session 是安装期间的唯一事实，列表刷新或详情弹窗重开只能返回其当前快照，不得用磁盘重新探测覆盖 `installing` readiness 或清除进度；取消会中止同一 install session、清除进度并回到重新探测后的可操作状态，不写失败残留或暴露未完成入口。多 Skill 替换使用同目录临时备份并在任一交换失败时回滚已交换项，不改动未在 manifest 中声明的其他 `.agents/skills` 包。已有 Awaken-managed 记录若对应官方 Skill 整套不存在，Main 在启动时尝试一次补装；只要检测到部分同名包，就视为外部或用户已有内容并保持不变。网络或校验失败不得让原本可用的 CLI 失效，保留记录并在下次启动重试。

Main 可发现 user/system/managed 候选并验证版本；优先使用已记录路径或 Awaken-managed 副本，否则取首个已验证候选。不得让用户通过文件选择器挑选 executable；若需安装则走固定受管下载。停用、官方 logout 与卸载受管副本是三个独立动作，卸载不得删除 user/system-managed CLI 或凭据。

每个 provider 同时最多一个 install session 和一个 auth session。重复 start 返回同一 session，retry 创建新 ID；旧进程和迟到事件不得影响新 session。临时授权资源只位于 `AWAKEN_HOME/runtime/auth/<provider>/<session-id>/`，终态、取消、重启和 dispose 都清理对应 session；Manager dispose 不删除共享 `runtime/auth` 根目录，所有依赖该目录的状态探测在执行前都会幂等恢复它，避免一个已退出实例把仍运行实例的正常未授权状态误报为 CLI 损坏。显式取消授权时，Main 必须先撤销该 session 的当前 ownership，再终止 child 和清理目录，使 child exit、stdout/stderr 或异步初始化的迟到回调无法重新打开网页或把 `action_required` 覆盖成 `failed`。Renderer 只接收稳定 phase 和安全提示；Main 从官方 CLI 输出中校验 provider 官方 HTTPS 域名并直接打开系统浏览器，不把授权链接、二维码或 device code 投影给 Renderer。原始 stdout/stderr、device code、token、secret 与配置内容不得进入 IPC store、模型、Journal、AG-UI 或 transcript。系统浏览器无法打开时，session 进入可重试失败态，不降级为 Awaken 内嵌授权页。

连接器页 onboarding 直接调用这条 Main 生命周期，不创建或提交 Agent 会话。目录卡只打开连接详情弹窗；弹窗投影安装进度、取消、授权等待/重试与 logout，但网页链接和二维码不在 Awaken 重复展示。关闭详情不影响 install session；关闭或点击遮罩退出活动 auth session 时，Renderer 必须先调用同一 `cancelAuth` 生命周期，目录卡在取消完成前保持 busy，再次打开只能看到 Main 返回的「重新授权」稳定状态。DWS 默认浏览器登录完成后由 `auth status` 验证；Lark 若缺应用配置，单次「点击授权」先执行 `config init --new`，从受限输出中提取并打开官方配置 URL，配置验证成功后自动继续 device flow 登录和 `auth status --verify`。授权等待的 run-bound 投影仍由 Core `interaction_required` 与 Workbench `ExternalActionGate` 拥有，两者不得混为同一会话。

Core 启动只迁移 user scope 的 `AWAKEN_HOME/config/mcp-servers.json`：仅删除 provider identity、source、display name、command、args 与空 cwd/env 都完全匹配旧工厂的 `dingtalk-workspace`/`lark` 记录。修改前写入 `AWAKEN_HOME/backups/migrations/cli-connectors-v1/mcp-servers.<sha256>.json`，沿用 config 锁和原子写入；任一字段不匹配则保留并投影 `legacyMcpReviewRequired`。

## 必须保持的规则

- Connector definition priority 与 MCP config scope priority 是两套不同系统；
- builtin connect/disconnect 会改写 `AWAKEN_HOME/config/mcp-servers.json`，真实验收必须使用隔离 `AWAKEN_HOME`；Electron `userData` 和其他旧路径不承载这份配置，也不参与迁移或 fallback；
- Playwright builtin 日志只写 `AWAKEN_HOME/logs/mcp`，不得通过修改 child `HOME` 连带迁移 npm、browser cache 或 Downloads；手工同名 server 不继承该路径策略；
- local dynamic 不得假装跨重启持久；
- per-tool message/delete safety 不从 Connector aggregate capability 继承；
- 只有当前 Manager snapshot 可证明 readiness。
- CLI readiness 只接受带启动期随机 control token 的 Desktop Main 完整快照；未知 provider、错误 kind、空 token 或非法枚举必须拒绝。
- Renderer、Core 与模型都不能为 CLI lifecycle 提交任意 command、argv、cwd 或 env。

## 自动化

- source priority、稳定 provider ID、capability/dependency 去重；
- 五个目录可见 MCP builtin、两个 CLI builtin、一个 `plugin_only` Outlook host Connector 与 local dynamic manifest；CLI definition 不产生 MCP config，也不调用 MCP Manager；Outlook definition 固定为 host OAuth + in-process MCP，并且 `GET /v1/connectors` 与连接器页都不重复展示；
- Outlook/host OAuth 的明确管理员同意错误与用户显式“页面要求管理员审批”都进入可跨重启恢复的等待审批态；不生成 token，批准后重新连接才 ready；安装 Outlook 插件后，宿主 Outlook MCP 必须作为该插件的 MCP 组件展示并同步 authentication/runtime/tools 状态；
- Outlook PKCE state/code verifier、callback 单次消费、provider error、取消/超时、contract fingerprint、refresh、退出登录清理、恶意 redirect/DNS/私网地址与 Renderer URL/credential 泄漏；缺失 `AWAKEN_MICROSOFT_CLIENT_ID` 时 fail closed；企业 Access/Refresh Token 组合超过 macOS `go-keyring` 4096-byte command 限制时必须在 Keychain 内分片 round-trip，覆盖 SHA-256 完整性、替换回滚、退出登录全分片清理和磁盘 metadata 零凭据泄漏；同一 OAuth contract 的连续 readiness 查询只读取一次 Credential Store，断开、授权成功、contract 变化与 reauth 标记必须使缓存失效或更新；一个 setup 绑定多个插件组件时，单次 component-state 计算只解析一次宿主 readiness；
- Outlook Graph 的 37 个 tool schema 与个人/共享 mailbox 路径，覆盖 recent/list/search/稳定分页、single/batch full-message fetch、递归文件夹解析、文件夹、分类、附件小文件/大文件 upload session/安全下载、draft/update/send/schedule、reply/reply-all、forward、已读/分类专用更新、move/delete、RFC 8058/mailto 退订；list/search 不向模型暴露 Graph nextLink，只返回同源且绑定同 mailbox resource 的不透明 `nextCursor`，续页必须原样复用且不能按页大小推算 `$skip`，真实 Graph `mailFolders('inbox')` continuation 与初始 slash 写法必须续页成功，跨 origin/mailbox/folder cursor 必须拒绝；batch 限制一到 20 个唯一 ID、保留单项失败/Retry-After 且不自动重试，folder resolver 限制遍历并按匹配质量排序，`inbox`/`sentitems` 等 well-known 名称必须解析为租户当前语言的真实文件夹；新邮件、草稿更新、回复草稿额外 CC、转发和定时邮件的 `to/cc/bcc` 必须是邮箱字符串数组并能真实穿过 MCP schema，不能要求或接受 `{item:...}` 包装；`set_message_categories` 的 `clear: true` 必须向 Graph 发送真实空数组，`update_category` 只暴露并验证可写 `color`，不得接受只读 `displayName` 或报告虚假重命名成功；它们的 nullable output schema 必须在 MCP adapter 保留并与 `StructuredContent` 一致投影，真实读取分页和文件夹解析不得出现虚假 `tool_output_schema_mismatch`；定时输出 schema 必须包含稳定字符串时间字段，同一草稿不得重复计划或在计划存在时立即发送，取消后草稿已不存在以 `draftCleanup=already_absent` 成功收敛；固定 Graph base URL、Bearer header、输入/响应上限与安全错误；明确 401 标记 host account 和 Manager `needs-auth`，读写调用经 Workbench 只重放一次，第二次返回 `connector_auth_replay_exhausted`；共享邮箱 403 不冒充 401；
- builtin 只写 `AWAKEN_HOME/config/mcp-servers.json` user config、local InjectDynamic、同 owner disconnect 与跨 owner拒绝；
- connected/needs_auth/failed 到 provider readiness；
- Connector aggregate capability 与 per-tool metadata 都不作为 MCP 调用授权；
- metadata-less/无 annotations 的 read、mutation、message/delete，以及无效 metadata、自相矛盾 annotations，均在 connected/auth-ready、schema 有效时进入 provider transport；
- builtin 重启后只按稳定 provider identity 恢复 active owner、卡片状态跟随 Manager snapshot、手工同名配置不被认领；local/dynamic 重启后不恢复。
- Playwright builtin 为现有及新建 owner config 幂等准备 `AWAKEN_HOME/logs/mcp/playwright-mcp-server.log` 和受管加载器，保留其他 stdio env、不修改 `HOME`、不改手工同名配置；加载器 fixture 证明第三方硬编码路径被替换且用户主目录不产生日志。

## 完成边界

只跑 fake CLI、registry 单测或 cross-build 不能声明真实 OAuth、外部服务、Windows 实机或完整跨重启旅程完成。Linux 是明确 `unsupported`，不要求成功安装；未执行的 macOS/Windows 架构和真实 provider 旅程必须逐项报告。

## 定位的实现

Connector 是 MCP 与 CLI 两类 provider 的统一运行能力；顶层连接器目录只展示 `catalogPlacement=connectors` 的条目。definition 显式携带 `kind: mcp | cli`、`catalogPlacement: connectors | plugin_only`、可见名称、说明、类别、provider、auth type、trust/source、稳定 `providerId`、aggregate capabilities、dependencies 和 provider readiness。`plugin_only` 只改变用户入口，不删除 Registry definition、OAuth 或 MCP runtime；它由引用该能力的插件页面独占展示，避免同一功能在插件与连接器两个页面重复出现。只有 `kind=mcp` 可携带 MCP config factory/inline config 并进入 MCP Manager；`kind=cli` 的安装、配置、授权和启停由 Electron Main 的 `CliConnectorManager` 独立拥有，不生成 MCP config，也不调用 MCP connect/disconnect。需要宿主账号的 MCP Connector 由 Core `Connector Auth Broker` 统一拥有账号、PKCE 会话、Keychain 凭据和 token refresh；插件只能引用稳定 Connector ID 和读取 readiness，不能取得凭据。

CLI 连接器当前固定为 `dingtalk-workspace`（钉钉）与 `lark-cli`（飞书）。目录页使用紧凑的桌面信息密度：宽窗口保持两列、窄窗口降为单列，名称、说明、状态和标签形成克制的文字层级，说明或标签不得把单张卡片撑成大块面板。目录卡展示品牌标识、产品名与能力简介，不展示版本、安装来源或内部 readiness 枚举；整张卡与保留在右侧的「+」都只打开同一个连接详情弹窗，不直接执行安装。弹窗的 X 固定在右上角，保留无障碍关闭名称，鼠标悬停或键盘聚焦时不显示可见 tooltip 或原生 `title` 提示。弹窗拥有完整 onboarding：未安装时显示「安装」；安装中同步显示 Main 上报的阶段与百分比进度，按钮变为「取消安装」；CLI 与官方 Skill 都成功但没有已验证的当前用户身份时显示「重新授权」，不得回退为「安装」或把正常未登录显示成「CLI 操作失败」；授权完成后显示带勾的绿色「已连接」，鼠标悬停或键盘聚焦时切换为「取消登录」，点击调用官方 logout。受管安装同时把与固定 CLI 版本匹配、经过 SHA-256 校验的官方 Skill 安装到用户级 `~/.agents/skills`：DWS 使用官方稳定 mono 包 `dws`，Lark 安装当前官方仓库的全部 `lark-*` 包。已有 Awaken-managed CLI 在升级到本契约后，如果对应官方 Skill 整套尚未出现，会补装同版本官方 Skill，若用户或其他安装器已放入部分同名包则保留现场而不覆盖。登录由 Main 启动官方 CLI 并打开经过校验的官方 HTTPS 页面，用户只在官方网页完成操作；弹窗只显示等待/重试状态，不重复展示授权链接或二维码。DWS 只允许精确的 `https://login.dingtalk.com/oauth2/auth` 用户 OAuth 页面，必须拒绝同属钉钉域名但用于获取 client ID 的 `mcp.dingtalk.com/cli/clientId`、logout 和其他后台 endpoint。Lark URL 校验使用精确的 `accounts.feishu.cn`、`open.feishu.cn` 及 Lark 对应 hostname，并拒绝应用注册、device authorization、revoke 与 token 等服务端 API endpoint；CLI stdout/stderr 中出现这些后台地址时只按失败诊断处理，绝不交给系统浏览器。它们只负责把经过验证的官方命令暴露给现有本机执行环境。具体业务命令仍由 Skill/Bash 与中央 ToolRuntime 契约拥有，Connector 不形成新的任意命令执行旁路。

## UI 状态的实现

Connector 列表显示 `catalogPlacement=connectors` 条目的 source、provider identity、capabilities/dependencies 和当前 readiness。只有当前 MCP server snapshot 可证明 connected/needs_auth/failed；点击过连接或 config 存在都不是 connected 证据。内置 MCP 连接后即使为了重启恢复而持久化为 user config，仍只保留在「Awaken 内置」原卡片中操作；Connector owner 认领的单个 server 一旦存在，原卡片右侧就显示该 server 的启停开关与设置入口，停用后仍留在原位并可重新开启。「用户安装」只列出未被任何 Connector owner 认领、且名称不以 `plugin__` 开头的独立 user/project MCP server，不重复投影 Connector 拥有的底层 server 或插件认领的 server。插件自带 MCP 的启停与详情只在插件页；插件通过 `host_connector` 使用的宿主 MCP 作为只读引用出现在插件详情，展示该插件实际依赖的 runtime 和工具。若宿主 Connector 为 `plugin_only`，其 setup、连接、审批等待、重连与退出登录入口也只出现在引用插件，连接器页不得再投影同一 MCP 或账号卡片。
`authType=oauth2` 且带 host OAuth definition 的用户入口是账号动作，不显示底层 in-process server 的普通配置/启停入口；目录可见 Connector 使用连接器卡片，`plugin_only` 使用引用插件的 setup item。插件整体关闭不属于账号动作，不得调用 Connector `Disconnect`、删除 token 或改变账号 readiness；只有用户在账号行明确选择“断开连接”才能退出账号。未连接时显示连接、授权等待时允许取消并提供“页面要求管理员审批”、等待审批时显示独立状态且允许批准后重新连接；已连接时显示独立账号行和“已连接”下拉，下拉提供强制重新连接与断开连接，不能取代引用插件自身的整体启停开关。强制重新连接即使已有有效账号也必须发起新的 PKCE session，并在新凭据交换成功前保留旧凭据；取消该 session 不得清除原账号。授权会话由 Core 跨窗口焦点和插件页挂载持有；Renderer 页面离开只停止观察，返回后按当前插件/setup/指纹重新认领活动会话，不因切到浏览器、其他窗口或 Awaken 页面自动取消。OAuth 回调在 `verifying` 阶段等待工具运行时就绪时，必须读取忽略账号投影的纯 MCP runtime 状态；不得用包含当前授权会话 `pending` 状态的综合 Connector status 等待自身完成，否则会形成循环依赖并产生虚假超时。Electron Main 取得 Core 的一次性 authorization URL，复用安全 URL 校验后调用系统浏览器并在返回 Renderer 前删除 URL；Renderer 只轮询脱敏 session。断开连接会同时清理共享账号凭据和该 Connector runtime，因此所有引用同一 Connector ID 的插件同步回到 `needs_auth`。
目录卡的辅助说明只有在提供标题之外的信息时才显示；provider 名称或其他文案与产品名等价时必须省略，但后端 definition 的 Description 与 provider identity 仍保留为目录元数据，不因 UI 精简而删除。MCP 配置弹窗使用「本地进程（stdio）」与「Streamable HTTP」两个模式按钮区分命令型和远程 URL 配置；按钮切换说明与安全示例，粘贴可明确判定的本地 JSON、远程 JSON 或裸 URL 时同步当前提示模式，但不取得 schema ownership，也不得在用户已经粘贴内容后静默覆盖或重写输入。用户安装卡片优先显示 Core snapshot 的 `displayName`，设置、启停和工具路由仍使用 canonical server identity。
用户 MCP server 的启停或配置重启只能更新卡片状态，不得改变其在当前目录中的安装顺序与网格位置，也不得因 Manager 重建或列表轮询而短暂清空「用户安装」并闪现空态。持久化启停在写完 config 后原地 Disable/Enable；`RestartWithConfig` 重建时 Snapshot 必须始终保留该 server 条目。

## 产品动作与授权的实现

Outlook 使用 Microsoft identity platform 的 Authorization Code + PKCE：Core 只监听随机 `127.0.0.1` 端口，redirect URI 使用该端口的 `http://localhost` loopback 地址；非 loopback authorization/token endpoint 必须为公共 HTTPS，DNS 解析到私网、link-local、multicast 或与声明 host 不一致的 loopback 必须拒绝。Awaken 发布方使用自有的 Microsoft 公共客户端 ID；该 ID 作为非凭据的发布元数据由 `scripts/build-binary.mjs` 提供默认值，并通过 Go ldflags 编译进 macOS/Windows 发布 binary。开发或私有发行可以用 `AWAKEN_MICROSOFT_CLIENT_ID` 覆盖构建值，运行中的开发 Core 也优先读取同名环境变量。它不是 secret，但不能由插件或 Renderer 覆盖，最终用户不需要填写。未配置时 Outlook 插件 setup 明确失败且不打开网页。当前 scope 固定为 `openid profile offline_access Mail.ReadWrite Mail.Send Mail.ReadWrite.Shared Mail.Send.Shared MailboxSettings.ReadWrite`；shared scopes 只服务 work/school 账号的共享/委托邮箱，用户还必须在 Exchange 中拥有目标邮箱的 Full Access 以及 Send As 或 Send on Behalf 等实际邮箱权限；`MailboxSettings.ReadWrite` 服务主分类的读取、创建、颜色更新和删除。Microsoft Graph 的分类 `displayName` 创建后只读，Awaken 不提供虚假的分类重命名参数。scope 指纹变化会要求既有账号重新连接，普通插件、Renderer 和用户输入不能修改 scopes。企业 Entra token 组合超过 macOS `go-keyring` 单条写入上限时，通用 Credential Store 按随机 revision 分片写入 Keychain 并以 SHA-256 manifest 验证重组；Token 分片与 manifest 均不进入磁盘 metadata。

Outlook 的新邮件、草稿更新、回复草稿额外 CC、转发和定时新邮件输入把 `to`、`cc`、`bcc` 统一声明为邮箱地址字符串数组；Core 再转换为 Graph recipient 对象，不要求模型构造嵌套 `emailAddress` 或 `{address,name}`。`list_messages` 与 `search_messages` 只向模型返回稳定 `hasMore/nextCursor`，不暴露 Graph nextLink；cursor 是 Core 编码的同源、同 mailbox resource 不透明续页地址，后续调用必须原样复用，不能从页大小推算 `$skip`。Graph 把 `/mailFolders/inbox` 续页规范化成 `/mailFolders('inbox')` 时，Core 只把这两种 OData 资源写法视为等价；跨 origin、mailbox、folder 或 collection 仍 fail closed。`get_messages_batch` 使用 Graph batch 一次读取最多 20 个唯一 message ID，保留单项失败与 Retry-After 且不自动重试；`find_mail_folder` 对 `inbox`、`drafts`、`sentitems`、`deleteditems`、`archive` 等 locale-independent well-known 名称直接向 Graph 解析真实 ID，其他名称在最多 500 个已发现文件夹内递归匹配并按精确路径、精确名称、路径后缀、包含关系排序，多个强候选仍由模型展示而非猜测。`set_message_categories` 完整替换分类，清空时使用明确 `clear: true`，不依赖模型正确构造空数组，也不接受空字符串。定时发送先在 Outlook 创建草稿，本机 `AWAKEN_HOME/outlook/scheduled-mail.json` 只保存计划 ID、mailbox、draft ID、UTC 时间、状态和安全错误，不保存主题、正文、收件人或附件路径。同一 mailbox/draft ID 只能存在一个计划；计划存在时 MCP `send_draft` 拒绝立即发送，用户必须先取消计划并重新确认发送方式。取消计划时草稿已不存在按 `draftCleanup=already_absent` 成功收敛；其他草稿删除失败保留“计划已取消、草稿清理失败”的部分结果。Core 运行时发送到期草稿；退出或休眠期间不常驻，重启后处理已到期计划。只有明确的鉴权失效延后重试；断网、timeout、Graph 错误或结果未知一律收敛为 failed，不自动重放写操作，用户检查 Sent Items 后自行决定。后台订阅、Webhook、邮箱离线同步和系统级常驻调度当前不支持。
