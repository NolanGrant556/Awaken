# 安装与激活契约

## 1. 权威范围

本文唯一拥有 Skill 包安装入口、覆盖策略、registry 刷新时点、激活计划、工具池、参数、资源读取和耐久 receipt。包格式与来源见 [技能包与加载契约](./技能包与加载契约.md)；执行模式和 MCP 动态来源见 [执行模式与 MCP 来源边界](./执行模式与MCP来源边界.md)。

## 2. 安装入口与差异

当前有三条不同入口，不能合并成一句“支持/不支持 replace”：

| 入口 | 当前行为 |
| --- | --- |
| Desktop Skill 安装 HTTP 动作 | 接收 Markdown 或 zip、scope、projectRoot 和 `overwritePolicy`；底层安装器支持 `abort` 与 `replace`，但 Desktop UI 默认不请求 replace |
| 模型平台工具 `skill_install` | 支持安装并默认立即 reload；显式 `overwrite_policy=replace` 会以 `skill_install_replace_unsupported` fail closed |
| `skills.InstallSkillPackage` | 底层包安装能力；replace 通过临时目录、旧目录备份和 rename 完成，失败时尝试恢复旧包 |

HTTP 安装成功后，handler 返回磁盘上的新包，但不直接重载 live registry。Skill 列表动作使用磁盘 preview，所以列表可以先看到新包；下一次 run 的 workspace Skill 同步才会刷新执行 registry。模型工具 `skill_install` 默认 `reload=true`，在同一进程内立即触发本地来源 reload。当前 method/path 只查 [09 route 清单](../09_AGUI与A2UI协议/HTTP与SSE接口契约.md)。

安装目标只承认 `project` 和用户级/global 语义。项目安装必须解析出合法 project root；安装器禁止通过包名、zip entry、符号链接或覆盖路径逃出目标 skills 根。

### 2.1 模型平台工具 source contract

`skill_install` 的 `source_type` 与专用字段固定为：

| source_type | 必填/关联字段 | 当前边界 |
| --- | --- | --- |
| `content` | `content`；`file_name` 可指定 `SKILL.md` 或 zip 名 | 原始 Markdown 或 textual package bytes |
| `content_base64` | `content_base64`；`file_name` 可选 | 严格 base64 解码后按 Markdown/zip 验证 |
| `local_path` | `path` | 必须通过当前 TaskScope readable path；文件、含根 `SKILL.md` 的目录或可唯一解析的包 |
| `remote_url` | `url`；`file_name` 可选 | 只接受 HTTP(S)；下载失败为 source unavailable，不把任意 scheme 当文件读取 |
| `remote_git` | `url`；`ref/subpath` 可选 | 只接受绝对 HTTPS repository URL；禁止 inline credential、query、fragment 和逃逸 subpath |

通用字段：`scope=project|global|user`，空值默认 `project`，`user` 是 global alias；`project_root` 为空时由当前 workspace 解析；`overwrite_policy` 默认 `abort`，平台工具识别 `replace` 但 fail closed；`reload_after_install` 默认 `true`。

`remote_git` 还要求安全 ref 字符集，拒绝 `..`、`@{`、双斜线、尾随 `/`/`.`/`.lock` 等危险 ref。Git 运行时只允许 HTTPS protocol、关闭 credential helper/terminal prompt、使用空 template 和收窄后的环境变量；错误输出中的 HTTPS URL 脱敏并有界截断。`subpath` 规范化后必须仍在 clone root 内。

source 字段/包结构错误返回 `skill_install_source_invalid` 或 `skill_install_invalid_input`，不重试；HTTP/Git 取源失败返回可重试的 `skill_install_source_unavailable`。任何失败都不得在目标 skills 根留下半安装包。

### 2.2 Legacy Artifact Skill 平台冲突

[`src/skills/legacy_conflict.go`](../../src/skills/legacy_conflict.go) 会扫描 `SKILL.md`、最多 512 KiB 的文本型包文件、文件名和 tool policy。以下当前模式使 Skill 进入 `unavailable`，code 为 `skill_platform_contract_conflict`：

- `pip/pip3 install`、`npm install`、`pnpm add`、`yarn add`；
- 动态 `generate.py` 引擎；
- 直接 shell 调用 `soffice` 或 `pdftoppm`；
- 手写 Office ZIP/XML 标志，例如 `zipfile/ZipFile`、`[Content_Types].xml`、`ppt/slides/`、`word/document.xml`、`xl/worksheets/`；
- tool policy/requiredTools 直接声明非平台 `soffice` / `pdftoppm`。

检测只标记状态，不改写或删除 Skill 文件。冲突不能通过追加 prompt、自动安装依赖或在原 Skill scope 内静默改路由来覆盖；该次 Skill 激活必须退出。若用户目标仍可由平台 typed Artifact 工具完成，只能由后续新的、显式 recovery plan 在 Skill scope 外重新选择，不能把旧调用伪装成成功。

该检测是 regex 启发式兼容门，不是执行 sandbox：只扫描声明的文本扩展和不超过 512 KiB 的文件，Walk/read 错误会被忽略；正文即使是在说明“不要 pip install”也可能误报。`ApplyPlatformContractConflict` 当前还会把既有 unavailable code 覆盖为 platform conflict，和函数注释“保留既有 code”存在漂移。产品只能把它用于 fail-closed 标记，不能据此证明任意脚本都不会绕过平台边界。

## 3. 激活入口与流程

Skill 有两种生产激活入口：

1. composer 中的显式 Skill token 在首个模型请求前激活；
2. 模型调用注册的 `skill__<normalized_id>` 工具时激活。

单 Skill execute handler 虽然存在，但 router 明确保留给后续工作，当前没有注册相应 route，不能作为产品入口；未注册事实以 09 route 清单为准。

统一激活流程：

```text
run 同步 project/user Skill
  -> registry 解析 available/unavailable/shadowed
  -> 查找 SkillDefinition
  -> 父工具池 ∩ toolPolicy.allow - deny
  -> requiredTools / capabilities / runtime preflight
  -> requiredResources 校验与 preload
  -> 参数校验和正文替换
  -> 生成 SkillActivationPlan
  -> 记录 skill_activated 与 resource_receipt
  -> inline 执行，或 fork 分支后按当前能力降级
```

任一 required 条件失败时，激活在首个模型请求前失败；不得为了“尽量执行”而把父工具池替换成进程全局 registry，也不得跳过 required resource。

## 4. 工具策略和参数

- 当前策略模式只有 `intersect`。
- `allow` 为空继承父池；`deny` 在交集后继续移除。
- `requiredTools` 必须逐项出现在 effective tools。
- `requiredCapabilities` 必须至少由一个 effective tool 满足。
- `requiredRuntimeComponents` 通过已注册的 `runtime_preflight` 能力判断；探针缺失、输出错误、组件缺失或 not-ready 都是失败。
- arguments 按声明类型解析；缺少 required 参数或类型错误阻止执行。
- 工具名由 Skill ID 规范化为 `skill__...`；它是入口工具，不授予 Skill 新权限。

## 5. 资源与记录

`requiredResources` 支持 `preload` 和 `on_demand`，但“是否必须”和“何时读取”是两个维度。[`src/skillruntime/resource_loader.go`](../../src/skillruntime/resource_loader.go) 的当前加载条件是 `required || (loadPreload && mode == preload)`，因此：

| required | mode | 激活前行为 |
| --- | --- | --- |
| `true` | `preload` 或 `on_demand` | 都必须读取、验证并产生 receipt；失败则 fail closed |
| `false` | `preload` 或空值 | 激活时预载；失败也会阻止该次激活 |
| `false` | `on_demand` | 激活时不读，后续由 `skill_resource_read` 按需读取 |

`mode` 空值默认 `preload`。所以只有 **optional + on_demand** 真正留到激活后读取；不得把 `required:true, mode:on_demand` 解释为“可以在首个模型请求后再补读”。声明规则：

- `path` 必须是包根内的相对 regular-file 路径；绝对路径、`..` 逃逸、目录和 symlink 逃逸拒绝；
- `sha256` 可选；一旦声明，必须是 64 位小写十六进制，并与实际内容逐字节匹配；
- `maxBytes` 可选；空值或 `<=0` 时默认 `131072` bytes；这是激活加载器的单资源限额；
- host preload 只接受 UTF-8 文本；缺失、不可读、非 UTF-8、超限或 hash mismatch 不生成 receipt；
- required 或 preload 资源失败会在首个 LLM 请求前使激活 fail closed；不得联网补下载或让模型猜内容。

每次成功加载资源生成 `SkillResourceReceipt`，包含 skill ID/version、相对资源、来源、SHA-256、大小、模式和加载时间。激活计划和 receipt 以 snake_case 写入 SemanticJournal。当前 AG-UI projector 不把 `skill_activated` / `skill_resource_receipt` 投影成 Desktop 事件，协议边界见 [事件与字段契约](../09_AGUI与A2UI协议/事件与字段契约.md)。

preload compatibility error code 固定为：

| code | 触发条件 |
| --- | --- |
| `skill_resource_invalid` | 路径/目录/symlink/UTF-8 或声明格式无效 |
| `skill_resource_missing` | 文件不存在或无法读取 |
| `skill_resource_too_large` | 超过显式或默认 maxBytes |
| `skill_resource_hash_mismatch` | 实际 SHA-256 与声明不一致 |

`skill_resource_read` 的工具级 `*_path_denied/not_found/read_failed` 等 outcome 属于按需读取面，不应与 activation preload code 混成一套枚举。该工具只强制独立的 2 MiB 单次读取上限，当前不查找资源声明，也不复验声明的 `maxBytes` 或 `sha256`。因此 optional + on-demand 声明的较小 `maxBytes` 和 hash 不是按需读取器的当前强保证；这是已知契约缺口。required/preload 资源仍必须在激活前通过加载器的声明检查，不能用该工具绕过。

## 6. 异常、恢复与不支持

| 情况 | 当前结果 | 恢复方式 |
| --- | --- | --- |
| 同名包且策略为 `abort` | `SKILL_ALREADY_EXISTS` 或对应工具错误 | 更名、删除旧包，或在允许的底层/HTTP 入口显式 replace |
| 平台工具请求 replace | `skill_install_replace_unsupported` | 不自动覆盖；由用户选择其他有明确替换语义的入口 |
| 安装成功但 live registry 未刷新 | HTTP 列表可预览，当前执行池未必已有 | 发起新 run 触发同步，或使用带 reload 的平台工具 |
| required 条件失败 | 激活 fail closed | 修复工具、运行时、资源或依赖后重新激活 |
| 可选资源读取失败 | 不得伪造 receipt | 按 required 语义报告并继续或失败 |
| legacy Artifact 平台冲突 | `skill_platform_contract_conflict`、Skill unavailable | 修改 Skill 以使用平台 typed tool；或由新的 Skill-scope-external recovery plan 处理，不自动路由 |

当前不支持包安装后的任意脚本自动执行；scripts/assets 只有被正文和受控工具显式使用时才产生效果。
