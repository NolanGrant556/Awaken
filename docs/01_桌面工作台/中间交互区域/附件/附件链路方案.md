# 附件链路方案

## 目标

Awaken Desktop 的 `+` 是真正的添加附件入口。用户可以多选图片、PDF、Excel、Markdown、Word、代码等本地文件；发送后附件同时进入 UI、run input、transcript 和 task scope。

## 链路

```text
选择附件 -> 生成附件引用 -> composer 小尺寸附件条 -> 发送 run input -> transcript 持久化 -> task scope 授权读取 -> 用户消息气泡小卡片展示 -> Agent 按需用工具读取文件
```

## 运行边界

- 图片附件作为视觉输入：renderer 展示缩略图，run input 携带 base64，模型 provider 正常接收图片内容。
- 文件附件作为本地文件引用：run input 携带绝对路径、类型、大小和显示名；后端合入 `attached_files`，工具通过 task scope 读取。
- 附件数量不设置固定产品硬限制；只保留单张图片大小保护。
- 模型 capability 字段不作为图片发送的硬拦截条件。真实 provider 限制由运行错误或后续降级提示处理。
- 附件事实清单进入系统运行时信息，不写入用户消息正文。

## UI 约束

- `ComposerAttachmentStrip` 语义由 `AwakenComposerBar` 的 `attachments` 承担：固定一行小高度，横向滚动，不纵向撑高 composer。
- 用户消息气泡由 `AwakenUserPromptBlock` 的附件区展示：小缩略图/小文件卡片，不默认展开内容。
- 文件名过长时省略；hover 通过 `title` 展示完整文件名、类型、大小和路径尾部。
- 第一版不实现点击预览/打开，避免把聊天附件卡片和工作区预览能力混在一个切片里。
