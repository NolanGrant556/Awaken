# 长期记忆与 Dream 验收

## 1. 状态

本文同时记录已落地实现的自动化与尚未实现能力的目标验收。当前 macOS Desktop 基线已覆盖 Settings 四开关及 Auto Dream 持久化、用户/项目集合浏览、空列表、完整 Markdown 正文与来源查看、集合变化后立即清空旧详情，以及手动 Dream 的等待和完成中文状态；也覆盖“以后仍然叫我博士，你仍然叫田曦薇”在真实主模型中触发 selector、search/update、无正文 completion receipt、一次简短确认和正常 run terminal。本轮通过 computer use 真实验证 Workbench 的 Memory recall/update 紧凑回执、Dream 中文完成统计，以及完整关闭/重启 Desktop 后同一 Dream receipt 按 durable task identity 重放。自动 Dream idle、删除和 Dream apply 中途 crash 的实机恢复链仍未形成全域 Desktop 基线，不得标为已通过。

当前已执行的聚焦 Go 自动化覆盖 Markdown create/update/revision/supersede/delete、索引重建、权限模式、重复/敏感/source 门禁、symlink topic 排除、工具宿主 identity、journal 无正文投影、RequestBuilder 顺序、主模型 selector 的预算/超时/allowlist/晚到隔离、Memory HTTP/四开关 CAS、AG-UI 映射、手动 Dream plan apply、锁 heartbeat、Dream task 重启恢复与 staged batch crash rollback。Desktop 聚焦测试覆盖四开关、无创建/编辑/搜索/筛选入口、集合到 Markdown 正文的钻取和 Dream 中文状态、Workbench Memory/Dream receipt 投影，以及 Auto Dream 活动计数、去重与 24 小时门槛。新增恢复链的真实 Desktop 中断验收和未列入上段当前基线的路径仍是目标门禁。

## 2. 自动化

### 2.1 Markdown store

- user/project 根解析、canonical workspace 隔离和 symlink 逃逸拒绝；
- frontmatter 必需字段、未知字段保留、UTF-8、大小和 schema version；
- `MEMORY.md` 200 行/25KB 截断、重建、悬空和重复入口；
- create/update/expected revision/supersede/delete；
- temp write、fsync、atomic rename、index failure 和重启恢复；
- secret/system-prompt/raw-transcript 拒绝；
- thread 删除不删除 Memory，project detach 不删除 workspace Memory；
- 数据库/向量索引不存在或删除后仍能从 Markdown 恢复完整能力。

### 2.2 召回

- 排除 `MEMORY.md`、superseded 和非法文件；
- 每 scope 只扫描 newest 200 headers，frontmatter 只读前 30 行；
- selector manifest 不包含正文和秘密；
- selector 最多返回 5 个 allowlisted filename，任意/越界路径被拒绝；
- 每文件 200 行/4,096 bytes、每 turn 20KiB、session 60KiB；
- 已召回/已读取去重、compact 后允许重新召回；
- prefetch 不阻塞首请求，晚到结果不进入已结束 run；
- selector timeout/error/invalid JSON 降级为零召回；
- selector 使用 `memory_recall` purpose、256 token 上限、provider 辅助模型映射和独立 affinity；request/usage 在当前 thread 以同一 ID 封口，fallback 显式记录；
- 选择后 revision/hash 变化时不注入新内容；
- current-state verification/staleness block、user/project 优先级和冲突表达；
- 原生 subagent 当前只读运行时尚未继承父 `MemoryRecallSnapshot`；后续接入时 child 默认只能继承父已召回的相容 scope，不得扩大 user/project 范围。本条仍是 subagent Memory 阶段的完成门禁。

### 2.3 工具、事件与重放

- `memory` search/get/create/update/supersede/delete schema 与固定 run snapshot；
- host 填 source identity，模型伪造字段无效；
- mutation 成功前无成功 receipt，失败不改变内存 truth；
- mutation 的模型可见成功结果包含 `status=completed`、`write_completed=true`、`next_step` 和明确 finish guidance，不包含刚保存的完整正文；模型收到后停止额外 reasoning，不对同一事实重复 mutation；
- SemanticJournal/AG-UI 只保存 identity/action/revision/count，不保存正文；
- live/replay 同一 record 生成相同 Memory frames 和 cursor；
- Memory 删除后重放不恢复正文；
- renderer 不直接读文件，不从文案反推 memory identity。

### 2.4 主动记忆与 Dream

- 主动记忆默认开启，主模型只在正常任务推理中认为值得长期保存时调用 Memory；
- policy 与 `trust="data_only"` 索引分离，索引内容不能覆盖写入规则；
- “以后叫我博士哥，你叫小田”等未来持续指令即使没有“记住”二字，也在同一 turn 创建或更新 user `feedback`，不只询问是否保存；
- 没有本 turn mutation 成功 receipt 时，模型不声称“已记住/已保存/已更新”；文本确认不能替代工具调用；
- 写入成功后的下一次模型迭代只简短确认一次并结束，不在 Thought 中反复改写称呼；
- 稳定姓名/称呼、角色背景、协作偏好、纠正与非显然做法的确认属于正向信号；可能重复时先 search/update；
- 每轮 terminal 后不启动额外 extractor，不存在 extraction cursor 或重复全量对话分析；
- 关闭主动记忆不关闭已有 Memory 召回；用户逐字“记住/忘记”或语义明确的未来持续指令仍可执行，其他宽泛主动判断不执行；
- 临时状态、可推导事实、不确定推断和敏感内容不触发主动写入；
- 24 小时、5 run/20 mutation、Desktop idle、active run 和开关 gate；
- 新 run 或人工取消发生在 Dream 模型请求/响应解码期时，任务终态是 `cancelled + DREAM_CANCELLED`，不误报 `DREAM_PLAN_FAILED`；
- scope lock、heartbeat、1 小时 stale reclaim、取消和失败释放；
- Orient/Gather/Plan/Validate/Apply/Report 顺序；
- Dream 只输出 maintenance plan，普通 Write/Bash/MCP/Connector 调用被拒绝；
- duplicate merge、description/index 更新、relative-to-absolute date、supersede 和 conflict；
- Dream 合并只发生在同 scope、同 type 的明确重复之间，先保全 canonical 的独有事实与 Why/How；同一 identity 最多一个 action；
- Dream 保留稳定姓名、称呼、身份与偏好，recency 不能单独作为淘汰证据；无实质变化时返回空 plan，不产生措辞润色 revision；
- 不确定 user/唯一事实不被自动硬删除；
- expected revision 冲突不覆盖用户新编辑；
- batch apply 失败不留下半套主题/索引；
- 完成 receipt 的 counts 与实际 Markdown 变化一致。
- Dream 使用 `memory_maintenance` purpose、4096 token 上限与独立 task affinity；request/usage 只写 DreamTask authority，不双写 thread，重启为 orphan 请求补 `interrupted + usage_unknown`。

## 3. 相关 package 门禁

实现后至少执行：

```bash
go test -count=1 ./src/memory ./src/agentcore ./src/runtime ./src/server ./src/protocol/agui ./src/tool ./src/tools/...
go vet ./...
npm --prefix apps/desktop test -- --run
npm --prefix apps/desktop run typecheck
npm --prefix apps/desktop run build
git diff --check
```

若实际 package/script 名称不同，以实现后的正式入口为准同步更新本文，不能保留无效命令。

## 4. 真实 Desktop 验收

按根 README 正式入口，在隔离 `AWAKEN_HOME` 和专用 workspace 完成：

1. 打开全窗口 Settings，确认其覆盖内容窗口但保留原生窗口 chrome，左侧“返回应用”和五个现有分区可用，没有外层弹窗卡片、右上角关闭按钮或底部关闭栏；进入“记忆”并关闭 Memory，确认自动召回、主动记忆和 Auto Dream 同步保存为关闭、UI 显示关闭且不可操作，“更新记忆”不可用；重新开启 Memory 后确认三个子开关默认同步保存为开启并恢复独立操作，再分别关闭和重新开启任一子开关。随后分别保存 user/project 四种类型，确认真实 Markdown/frontmatter 与 `MEMORY.md`；
2. 新建 thread，用相关和无关 query 验证命中、零命中、最多 5 条、陈旧提示和 project 隔离；
3. 完整关闭/重开 Desktop，确认同一记忆可召回、来源可定位、receipt 可重放；
4. 通过 Agent 对话更新/supersede，并在 Settings 删除，确认 revision 冲突、索引变化和删除后历史不恢复正文；确认 Settings 没有人工创建或编辑入口；
   同时确认顶部光流仅作为随当前主题变化的装饰层，不新增设置项、焦点或业务回调；光流横向贴满记忆内容区、使用直角边界且没有独立卡片外框或“记忆控制”说明行；记忆组合根节点拥有完整纵向滚动，光流页头参与同一滚动内容，原生滚动轨道不可见，自绘无轨道细滑块只出现在页头下方的白色记忆视口，保持 44–72px 的短尺寸且映射完整滚动范围；Gallery 与 Desktop 共用同一光流标题、单列开关和记忆管理布局，四个开关均消费 `AwakenSwitch`，开启绿色、关闭灰色且禁用态仍可辨识；管理区不显示额外“记忆管理”总标题或互斥视图标签，上方固定显示“最近动态”，不显示附加说明或独立的“最近一次整理”汇总卡片；“更新记忆”与运行中的取消入口位于“最近更新与整理”列表标题栏，按钮尺寸适应该标题栏；下方动态列表仍展示 Memory/Dream 条目并可打开详情，每条记录保持单行，只显示类型、按 32 字符追加 `.....` 截断的标题及时间，不在行内显示描述或 Dream 统计，点击后详情仍展示完整内容。使用至少 20 条动态验证初始只渲染最新 6 条，连续点击“显示更多”后依次渲染 12 条和最多 18 条且第 19 条不出现，到达上限后显示“收起”并恢复为 6 条；列表自身不得新增滚动区，仍由记忆页统一承担纵向滚动。打开记忆详情后确认范围、类型、状态与更新时间排成圆点分隔的紧凑单行元数据，仅状态使用轻量底色，四个字段值与详情接口一致。确认最近动态同时汇总用户和所有已登记 active project 的最近 Memory/Dream，打开记忆库集合或选择项目时，上方记录、顺序和数量保持不变；从全局动态打开项目 Memory 时读取正确项目正文，单个项目读取失败不清空其他动态。下方“记忆库”首页只显示“用户记忆”和“项目记忆”两条集合入口，页面和弹窗均不出现搜索或筛选；用户入口直接进入全部用户主题，项目入口以原子 `AwakenFolder` 的 `compact` 文件夹卡片只展示已有主题 Memory，并按 Desktop 传入顺序从左到右排列、空间不足时换行，长名称单行省略且悬停显示完整名称，再进入该项目全部主题。项目为空时使用明确空状态，项目卡片过多时在限定高度内滚动；单个来源返回 20 条时集合计数显示“至少 20”，不声明完整总数。主题行点击后打开当前完整 Markdown 正文详情，项目主题携带正确项目 identity；项目列表、主题列表与正文须复用同一持续挂载的弹窗遮罩和容器，切换时不得闪现底层设置页、旧正文重影或重复播放入场动画；关闭项目正文必须在原弹窗内恢复到项目文件夹选择，关闭用户正文恢复到用户主题列表，从最近动态打开的正文回到记忆主页；集合或项目变化立即清空旧详情和记忆库结果，但不得清空最近动态，旧列表或详情请求晚到时也不会恢复过期选择；离开记忆分区后动画卸载；
   在 Memory 已开启时单独切换 Auto Dream 并覆盖设置接口等待态，确认保存期间只有 Auto Dream 防止重复点击，另外三个开关与“更新记忆”按钮均持续保持原有禁用态、颜色和透明度；Auto Dream 自身不控制“更新记忆”，只有 Memory 总开关、Dream 启动请求或运行状态可以禁用该按钮；
5. 输入 API key/token/验证码/完整 prompt，确认 Core 拒绝且磁盘/journal/AG-UI 无泄漏；
6. 默认开启主动记忆，先输入“以后叫我验收博士，你叫验收小田”而不出现“记住”二字，确认同一 turn 调用 Memory 并在新 thread 召回；再完成其他值得保存和不值得保存的多个 run，确认主模型只在前者调用 Memory，且没有 terminal 后额外 extractor；关闭主动记忆后确认明确的未来持续指令仍写入、其他宽泛主动判断停止且已有 Memory 仍可召回；
7. 点击“更新记忆”手动启动 Dream，验证重复合并、过时 supersede、冲突待处理、索引压缩和完成统计；
   确认排队、运行、完成、失败和取消提示均为中文；
8. 自动 Dream 满足空闲与阈值后触发；运行中提交新任务，确认分析阶段取消且主 run 不被阻塞；
9. Dream 中断和 Core 重启，确认 lock/staged 恢复，无半套变更；
10. 删除来源 thread、detach project、把项目移到废纸篓，确认各自数据边界；
11. Workbench 的 recall/mutation/Dream receipt 不破坏 prompt anchor、follow、composer、execution-process 折叠或 thread replay；确认 Dream 回执按 `taskId` 去重，同状态的不同任务不互相覆盖，重启后只回放到原绑定线程，无绑定的历史任务不进入新线程；
12. Settings 路由不显示 Workbench Inspector，返回后原布局偏好不变。

动态行为提供录屏或连续关键帧；Markdown 文件、事件 frame 和当前 HEAD 截图共同作为证据。Gallery、mock、直接 HTTP 调用和旧截图不能替代真实 Desktop。

## 5. 平台与阻塞声明

- macOS、Windows、Linux 分别验证路径规范化、原子替换、锁、权限、非 ASCII 文件名和大小写；
- 未执行的平台只能声明自动化/cross-build 层，不声明实机通过；
- 没有可用 selector 模型时必须验证零召回降级，不能用硬编码 fixture 冒充真实召回；
- Desktop、selector、真实 idle 或中断恢复任一不可用时，明确列为阻塞，不更新全量完成基线。
