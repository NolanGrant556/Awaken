# 测试与验收

## 1. 成功定义

Context Compaction V2 完成必须同时满足：

1. 容量：压后完整 provider-visible input 的保守投影不超过有效输入窗口 10%。
2. 连续性：关键用户事实、当前任务、计划、文件、错误、工具和 Subagent 状态不丢失。
3. 耐久性：live、restart、resume、replay 得到同一 provider-neutral bundle。
4. 可恢复性：精确旧内容可以通过有界历史读取恢复。
5. 多模型：跨模型只保留 provider-neutral state，不误用 opaque state。
6. 结构安全：完整 turn、tool pairing、gate 和 handoff 不拆断。
7. 失败安全：任何失败不安装半个新上下文、不切 Epoch。

## 2. Unit 测试矩阵

### 容量数学

- 32K、64K、80K、128K、200K、400K、1M context；
- explicit input limit 小于 context limit；
- 同一 context 分别配置 output max 1K、8K、16K、32K，断言不改变 EffectiveInput 与 10% 目标；
- provider actual > local estimate；
- mandatory floor 刚好等于、低于、高于 10%；
- summary、Skill、Memory、tools 同时接近预算；
- protocol wrapper/media overhead。

断言：

```text
ConservativeProjected <= floor(EffectiveInput × 0.10)
```

不可达 fixture 断言 typed failure，不断言成功。

### 语义连续性

每个场景使用中文、英文混合 canary：

- 用户初始目标；
- 后续纠正；
- 硬性百分比和精确数字；
- 文件路径和行号；
- 执行命令；
- 原始错误码；
- 已完成动作；
- pending ask；
- 未消费 Subagent result；
- Memory fact；
- Skill requirement；
- Hook snapshot/receipt 与 active gate；
- Artifact/change ID。

在 1、3、5 次压缩后验证：

- critical facts 100%；
- important facts >= 95%；
- 不要求用户重复已经给出的信息；
- 不把同一 thread 误判为新会话。

### 结构完整性

- assistant 不脱离对应 user；
- tool result 不脱离 tool call；
- 未闭合 pairing 始终保留；
- active gate 始终保留；
- latest two closed turns 保持完整；
- oversized newest turn 返回 typed code `PROTECTED_TURN_TOO_LARGE`、reason `protected_turn_too_large`，或完整进入 checkpoint；不得截成无效半条。

### 原子性与 crash points

在以下位置注入失败：

- checkpoint generation 前后；
- summary generation 前后；
- coverage repair；
- bundle encode；
- Journal append；
- Journal flush；
- digest sidecar write；
- Memory install；
- Skill install；
- Hook snapshot install；
- Subagent acknowledgement；
- Epoch rotation。

每个 crash point 只允许：

```text
完整旧状态
或
完整新状态
```

不允许半安装。

## 3. Replay 与兼容测试

- v1 `context_compacted` fixture 继续可读；
- v2 Phase 1 `v1_messages` projection fixture 可读，所有未实现 section 均为规范化 `not_materialized`，不能是字段缺失；
- section 的 `not_materialized/materialized/unavailable` 与 value/digest 不一致时 fail-closed；
- Phase 2–5 物化新 section 不改变 v2 envelope shape 或 schema version；
- v2 bundle restart digest 一致；
- live/replay messages、Memory refs、Skill refs、Plan version、Tool ref、Hook snapshot、active gate refs、pending handoff 一致；
- 损坏 v2 record fail-closed，旧 known-good context 不被擦除；
- compact → restart → compact；
- compact → resume → fork/child → compact → restart；
- feature flag 从 v2 切回 v1，不破坏历史读取。

## 4. 三协议测试

| 协议 | 必测行为 |
| --- | --- |
| OpenAI Chat | 完整 messages 重放、tools、usage、context-too-long reactive recovery |
| OpenAI Responses | `store:false` 本地重放；仅 exact official capability 使用 native compaction；opaque identity 校验 |
| Anthropic Messages | tool_use/tool_result、thinking/signature、cache_control、usage 与 compact 后 pairing |

custom endpoint 必须验证：

- 不自动发送 OpenAI native compaction 字段；
- 不继承官方 provider opaque state；
- 只使用 provider-neutral bundle。

## 5. Provider-native 测试

当前自动化已覆盖 exact official route、native success、零个/多个或非法 compaction item、opaque digest、credential/model/protocol/base/endpoint mismatch、native 调用失败回落、native output 超硬 10% 时回落、restart bundle round-trip，以及 Chat/Messages/custom 不继承。prompt-too-long、真实 stream 中断、真实 endpoint 重复 1/3/5 次与真实 model switch 仍属于待验收项。

- native compact success；
- native compact prompt-too-long；
- native stream 中断；
- 返回零个/多个 compaction items；
- opaque state digest mismatch；
- credential revision/model/protocol/base URL 变化；
- native → local fallback；
- 重复 native compact 1/3/5 次；
- restart 后同 identity 恢复；
- model switch 后只使用 local checkpoint。

## 6. 历史读取工具测试

- current thread only；
- sequence/boundary/query pagination；
- byte/token cap；
- no physical store path；
- secret/provider opaque state 不返回；
- old tool payload 只返回安全投影；
- 审计 receipt 写入；
- 大历史不会一次灌满上下文。

## 7. 真实 Desktop 场景

至少覆盖：

1. 长中文编码任务，含三次用户纠正；
2. 多文件 Read、图片/PDF、大工具结果；
3. 5 个 Skills、Memory、RunPlan 同时存在；
4. 4 个并行 Subagents，其中两个压缩时仍运行；
5. compact 后立即继续执行；
6. compact 后完整关闭并重启 Desktop；
7. compact 后切换模型/协议；
8. mandatory floor 超过 10%；
9. native provider compact 成功/失败的 mock/自动化合同；真实 OpenAI 账号不作为收口门禁；
10. 同一 thread 连续压缩五次。

观察：

- 用户不需要重述要求；
- 模型继续正确下一步；
- 当前使用比例与 token 分类一致；
- UI 只有一个稳定压缩中状态；
- 失败不会清空上下文；
- restart 后行为与 live 一致。

当前实机证据：MiniMax-M3 / `openai_chat` 已在 macOS 正式 Desktop 入口完成多 PDF 单次压缩。当前 profile 输入窗口为 `267307`；压缩前面板 254K（95%），诊断回执 target 27K、保守压后 18K、mandatory floor 17K，压缩完成时面板 22K（8%）。模型保留第 1–8 份 PDF 的路径、页数和发现，并从第 9 份继续完成第 9–12 份及三个新文本文件。首次触发发现 checkpoint 类别滚动上限与 coverage 分母不一致；修复后只有被 64 条上限明确淘汰的旧 fact ID 退出分母，其余缺失继续硬失败，同一会话重启续跑通过。
