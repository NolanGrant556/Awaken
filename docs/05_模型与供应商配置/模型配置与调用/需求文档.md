# 模型配置与调用 · 需求文档

用户管理模型供应商、模型配置和生成工具，测试连接并查看可取得的账户用量；每个会话可以选择模型与推理强度。

流式响应在返回部分文字或工具参数后仍可能失败。失败不能被显示为完整回答，也不能把该次失败响应中的工具调用当作成功结果继续执行；是否重试遵守运行恢复规则。

代码、接口和验证方法见[实现方案](实现方案.md)。

## 用户入口

“设置 > 模型”使用两层导航。模型页左侧固定分成四个模型接入类型：

| 接入类型    | 当前 provider                                  |
| ----------- | ---------------------------------------------- |
| Coding Plan | Kimi Coding Plan、MiniMax Token Plan、GLM Coding Plan、火山 Coding Plan、Qwen Token Plan |
| API         | OpenAI、Anthropic、Google Gemini、Kimi、MiniMax、GLM、Qwen、火山方舟、DeepSeek |
| Agent Plan  | 火山 Agent Plan                                |
| 自定义      | 自定义 API                                     |

右侧每个接入类型固定包含两个二级页面：

模型页使用标准 Settings 页头：标题“模型”加一行说明“配置模型接入、连接状态与推理参数。”。当前不使用 168px 轨道、粒子半球、光晕或公转 Logo。页头下方继续使用窄类型导航、紧凑二级页头和受控内容宽度，不随宽窗口无限拉伸，也不再把四类 profile 混成公共表格。记忆页仍保留自己的 168px 光流页头，不在本域改写。

推理强度不在设置页配置。Composer 是唯一面向用户的 effort 入口，thread 内部保存 Awaken 统一的 `low | high | max` 档位；界面标签来自 exact model capability 的 `displayLabels`，例如 Qwen 显示官方原生 `low | medium | xhigh`，但运行时仍以统一档位形成缓存 identity 并由 Core 降低为协议原生参数。模型设置页不显示 profile 默认 effort。

`ModelAccessType` 的当前产品值为 `coding_plan | api | agent_plan | custom`。`custom` 只承载用户自行声明协议、地址和模型 ID 的自定义 API；媒体工具配置仍属于 Agent Plan 页面中的独立配置实体，不是模型接入类型，也不得写入 provider/profile access type。存量 provider ID 和 profile ID 保持不变；旧 `coding_preset` 仅作为读取兼容信号，不再是 UI 分类。

连接保存、本地凭据、重复身份或上游请求异常在配置弹窗内以 `alert` 呈现，弹窗保持打开以便修正和重试，不在 Settings 页面后方或顶部 toast 显示。实时目录返回的精确模型 ID 原样保存，即使它尚未进入版本化内置清单，也不得归一为默认模型。多模型保存中途失败后再次保存必须复用已落盘的 exact profile 身份，不得将重试误判为重复配置。

### 模型列表：官方清单与实时目录

点开厂商卡片后，选择器先展示 Awaken 内置的版本化官方 LLM 清单，不填 Key 也能看、也能勾选。这不是向供应商实时询问的结果。

要换成该凭据此刻能看到的官方最新 LLM ID，必须有可用的推理 Key（弹窗里新填，或该厂商已保存过连接）。有 Key 之后，下面三种操作会请求供应商目录：

1. 再次打开已保存 Key 的厂商卡片，自动刷新；
2. 在弹窗里点「刷新模型目录」；
3. 点「保存连接」（保存前会再刷一次）。

只把 Key 贴进输入框、不点刷新也不保存，目录不会自动更新。没有 Key 时点刷新，弹窗提示先填写 API key，选择器继续留在官方清单。目录失败或返回空列表时，同样保留当前勾选和官方清单，不把空白目录当成“没有模型”。

当前能请求实时目录的入口：OpenAI、Anthropic、Google Gemini、Kimi API、MiniMax API、MiniMax Token Plan、GLM API、Qwen API、Qwen Token Plan、火山 Coding Plan、DeepSeek。火山 Agent Plan 也能探测账户目录，但主模型选择器仍只展示 `ark-code-latest`，图片和视频不进 Composer。

当前不能请求实时目录、只展示官方清单或手填的入口：Kimi Coding Plan、GLM Coding Plan、火山方舟、自定义 API。这三家套餐/Ark 入口没有可由当前推理凭据调用的稳定目录 API；自定义 API 始终由用户手填模型 ID，不显示候选列表或刷新入口。火山方舟按量清单含豆包 Seed 与[模型列表](https://docs.volcengine.com/docs/82379/1330310)的托管第三方精确 Model ID：`deepseek-v4-pro-ga-260813`、`deepseek-v4-flash-ga-260731`、`glm-5-3-flash-260828`、`glm-5-2-260617`。选择器展示名仍是 DeepSeek-V4-Pro / Flash、GLM-5.3-Flash、GLM-5.2；[计价页](https://docs.volcengine.com/docs/82379/1544106)短名只作读取/保存迁移别名，不能直接调用。这些托管模型走 Chat 与 Responses，切换协议后仍留在选择器里。`glm-4.7` 已列入[按量第九批下线](https://www.volcengine.com/docs/82379/1350667)，不进选择器。Kimi、MiniMax 和旗舰 `glm-5.3` 出现在 Coding / Agent Plan，当前按量计价表没有 `glm-5.3`，不写进按量选择器。保存火山方舟模型后，有效上下文默认取模型列表的官方上限（Evolving 1024k，2.1 系列 256k，2.0 系列窗口 256k / 最大输入 224k，托管 DeepSeek/GLM 1024k）；用户只能再调低，不能调高。推理 Key 不能改写这些上限。豆包 Seed 与已列入[深度思考](https://docs.volcengine.com/docs/82379/1449737)的托管 DeepSeek GA、GLM-5.2 在 Composer 展示推理强度；GLM-5.3-Flash 与手填 `ep-*` 不展示。会话标题、上下文压缩和 Memory 召回默认使用当前已保存的火山模型；上述已列入深度思考表的模型会在这些辅助请求里关闭思考。GLM-5.3-Flash、未绑定模型族的接入点，以及 Coding Plan / Agent Plan 的 Chat 或 Responses 不会发送关思考字段；后两个入口若走 Messages，则省略思考块。

实时目录成功且返回非空 LLM 列表后，选择器只展示该次目录结果，不再把已下线的内置 ID 永久拼回去。刷新后只保留用户此前已勾选且仍出现在新目录中的模型；新出现的官方 ID 默认不勾选。取消勾选只表示这次不加入，不删除已有 profile。代码职责、目录接口和各入口默认模型见[实现方案](实现方案.md#当前-provider-catalog)。

### 保存、连接与 effort 验证

模型输入框的候选目录展开时，按 Escape 只关闭目录并把焦点留在模型输入框，不关闭供应商配置弹窗或丢失未保存内容。目录关闭后再次按 Escape，才由外层弹窗处理关闭。

effort 验证可能产生少量供应商消耗，不能与普通连接测试合并或静默触发。

## Reasoning effort

Awaken 的统一内部语义为 `low | high | max`。UI 只显示模型真实支持的档位，并优先显示供应商 API observation 或版本化官方清单给出的原生小写英文标签；未提供原生标签时才显示统一档位。`displayLabels` 只改变展示，不改变 thread 持久化、缓存 identity 或 Core 请求策略。thinking 开关、reasoning effort 和 prompt-cache capability 是三份独立合同，不得因其中一份已知而推导另一份；MiniMax 的 thinking 开关不属于 reasoning effort。Kimi K3 的三档顶层 `reasoning_effort` 以[官方推理强度文档](https://platform.kimi.com/docs/guide/use-reasoning-effort)为准，K2.x/K3 的 thinking 差异以[官方思考模型文档](https://platform.kimi.com/docs/guide/use-thinking-models)为准。

| 接入模型                         | UI 档位        | Provider 实际值    | 默认   |
| -------------------------------- | -------------- | ------------------ | ------ |
| Kimi `kimi-k3`                   | `low/high/max` | `low/high/max`     | `max`  |
| Kimi Coding `k3`、`k3-256k`      | `low/high/max` | `low/high/max`     | `high` |
| Google Gemini 当前内置模型       | `low/high`     | `low/high`         | `high` |
| MiniMax M3                       | 不展示         | 无档位参数         | —      |
| GLM `glm-5.3`、`glm-5.3-flash`   | `low/high/max` | `low/high/max`     | `max`  |
| GLM `glm-5.2`                    | `high/max`     | `high/max`         | `max`  |
| Qwen Token / API `qwen3.8-max`、`qwen3.8-flash` | `low/high/max` | `low/medium/xhigh` | `max`  |
| 火山方舟 Evolving / 2.1 Pro / 2.1 Turbo | `low/high/max`（标签 `low/medium/high`） | `low/medium/high` | `max` |
| 火山方舟 2.0 Code / Pro / Lite / Mini | `low/high/max`（标签 `low/medium/high`） | `low/medium/high` | `high` |
| 火山方舟托管 DeepSeek V4 Pro / Flash（`*-ga-*`） | `low/high` | `low/high` | `high` |
| 火山方舟托管 GLM-5.2（`glm-5-2-260617`） | `high/max` | `high/max` | `high` |
| 火山方舟托管 GLM-5.3-Flash | 不展示 | 官方 effort 表未列入 | — |
| DeepSeek `deepseek-flash`、`deepseek-v4-pro` | `high/max` | `high/max` | `high` |

Agent Plan 精确模型只有在受控验证后才获得对应映射。Provider adapter 是原生值映射的唯一 owner；Renderer 和 Agent Core 只处理 Awaken 档位。

保存或迁移 profile 时，不在 capability levels 内的内部默认值会被拒绝。启动 run 的回退顺序固定为 `thread 会话覆盖 -> profile 内部默认 -> capability 默认`。非法、过期或能力变化后的值按该顺序恢复，并在 Renderer 显示一次非阻断提示；同一会话的同一种失效偏好在本次打开应用期间只提示一次，切换其他会话再返回不重复弹出。提示说明后续发送使用的模型或推理档位，用户可在 Composer 主动调整；打开历史不改写原偏好，不发起模型请求。模型配置尚未完整加载或刷新失败时不判定为失效。这些默认值不会形成第二个用户设置入口。

## Composer 与 thread 选择

Composer 模型与 effort 都是会话级：

当前行为：

模型选择不再调用 `setDefaultModelProfile`。设置页的 default 只决定新会话初值，因此两个 thread 可以稳定使用不同模型和 effort。

thread preference 在写入 metadata 前由 Desktop Main 与 Core 双重校验：profile 必须存在、enabled 且凭据可用，effort 必须位于该 profile exact-scope capability levels 中。已删除、disabled 或不支持档位的请求直接拒绝且不改写 thread；打开旧 thread 时优先按其已保存 profile/effort 重建 snapshot，只在该 profile 不再可运行时回退 default。

## 连接、余额与错误

Google Cloud Monitoring、Qwen Model Studio 高级监控、豆包 Ark `GetInferenceUsage`、火山 Coding/Agent Plan 管理接口都需要独立于推理 Key 的云账号管理鉴权。当前 Awaken 不收集这些高权限凭据；用量窗口必须说明所需的项目、AccessKey/Secret、AK/SK 或只读权限，并提供对应官方授权/控制台入口，不能继续显示无上下文的“暂不支持”。Qwen Token Plan 尚无公开稳定的套餐 Key 直查合同，因此只引导官方套餐页面。普通推理 key 不冒充管理凭据；未实现官方余额的 provider 不能由连接测试或单次 inference usage 推断账户余额。

左侧栏个人入口不直接展示余额或配额，只在左对齐的“外观”与“设置”之间提供“查询用量”入口；打开独立用量窗口后才调用 `getModelProfileBalances()`。窗口左侧按该结果的 provider-scoped 条目列出已启用的 API / Plan，左右两侧均只展示厂商名称与 Logo，不展示模型 ID；右侧详情头也不重复显示“用量”标签，下方只展示供应商返回的余额、配额、组织用量、缺少管理 key、需要额外管理授权、仅能前往平台查看、暂不支持或查询失败状态。需要用户在供应商平台开通授权的条目必须带官方入口，且文案要明确推理凭据与管理凭据的边界。查询链路不额外聚合 Awaken 本地 token、缓存、请求、成本或 rate-limit 记录。左右两侧均通过 Desktop 的统一 provider 品牌映射复用 `AwakenProviderLogo`，未知 provider 显示首字母兜底。新增 LLM provider 时必须同时补齐品牌资源和统一映射，模型设置、Composer 与用量窗口随之同步展示，不允许在用量窗口维护第二套 Logo 对照。该呈现不改变 Main 的 provider 去重、请求超时和错误分类。

| 场景                                     | 行为                                                                             |
| ---------------------------------------- | -------------------------------------------------------------------------------- |
| 无 enabled profile                       | run 创建前失败，提示到设置配置                                                   |
| profile/account 无 key                   | run 创建前失败，不进入 provider transport                                        |
| `.env` 或 metadata 不可读                | fail closed，不覆盖原文件                                                        |
| thread profile 已删除/禁用               | 回退可用 default，并提示一次                                                     |
| thread effort 已失效                     | 按 profile/capability 默认恢复，并提示一次                                       |
| capability sync 失败                     | 保留静态和已有缓存                                                               |
| Agent Plan `/models` 返回 404            | 采用版本化内置官方清单；不把 404 解释为 Key 无效，媒体套餐权限待首次真实调用确认 |
| Agent Plan `/models` 网络错误或其他失败  | 保留内置与已有结构化缓存，不开放任意自定义 ID                                    |
| 媒体配置 kind 与 capability/目录不一致   | Main 拒绝保存；Core 启动再次 fail closed，不注册工具                             |
| 保存媒体配置时存在 active run            | 不写配置、不热刷新 Core 工具注册，提示任务结束后重试                              |
| 媒体配置保存成功但运行时热刷新失败       | 保留已写配置并明确提示重启 Awaken；不得宣称工具已经生效                          |
| 媒体 provider 401/403/429/5xx 或下载失败 | 形成 typed tool Outcome，不改写账户、目录或本地凭据状态                          |
| provider 401/403/429/5xx                 | 作为 provider 错误，不改写成本地凭据文件故障                                     |
| 火山方舟返回 `ModelNotOpen`              | 连接测试说明当前账号尚未开通该模型，引导到方舟控制台开通或改选已开通模型；不写成模型或端点不存在 |

## 一次执行的模型配置

启动执行时一次性解析主模型及用途路由，使用同一配置 revision。省略子模型配置时继承本次实际选择的模型与思考强度；显式选择只能引用已有可运行配置。辅助调用继续按其用途策略降低请求，并在账本记录实际值。不同 Agent 的配置和用量分别显示；并发请求遵守宿主全局及账户上限，等待和重试退避不占请求位。
