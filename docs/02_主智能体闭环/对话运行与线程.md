# 对话运行与线程

## 1. Run 建立

一次 run 固定 thread/workspace、模型 profile、TaskScope、`ExecutionEnvironmentSnapshot`、`RunToolAvailabilitySnapshot` 和 `HookAvailabilitySnapshot`。RequestBuilder 暴露给模型的 tools 与 ToolRuntime 执行的 runtime/provider identity/runtime pointer 来自同一快照；registry catalog、PATH 或 Hook 配置/信任变化只在后续 run 形成新快照。Hook Dispatcher 从该快照按顺序执行同步 command：`RunStart`/`UserPromptSubmit` 可阻断 run 或注入 host-owned untrusted data；`PreToolUse` 位于耐久 tool call 后、真实执行前，可阻断或更新输入；成功/失败 Post 位于耐久 canonical tool result 后；`PreCompact/PostCompact` 分别位于摘要计算前和成功 boundary 后；`SubagentStart/Stop` 由 root 在 child runner 外层触发；`BeforeFinish` 位于无 tool call 候选回答后、run terminal 前；`RunEnd` 位于耐久 terminal 后且不能改写终态。MCP adapter 仍检查 live server state，因此当前 run 中途断线会立即使后续调用返回 needs-auth/runtime/deny/transport failure，但不会换成另一个 provider 或调用旧 session。

run 可以属于项目，也可以是独立对话。Desktop 选择“对话”时不下发 `project_id` 或用户目录；Core 在创建 run ID 后先确定 thread ID，再把空 workspace 解析为 `<AWAKEN_HOME>/sessions/<thread-id>`。继续该 thread 时仍由同一个 thread ID 得到同一路径。项目 run 保持原行为：有文件夹使用选中根，零文件夹项目使用 `<AWAKEN_HOME>/sessions/<project-id>`。

模型 profile 是否支持 tool calling 应在建立请求前判定。当前尚无覆盖所有 provider/model 的统一 tool-support capability，因此不支持 tool calling 的组合必须明确拒绝或降级为无工具对话，不能把发送 schema 失败伪装成工具失败。

## 2. 用户输入与 Skill

composer 提交文本、attachments 和结构化 Skill tokens。Runtime 对 token 重新查当前 registry并核对 loaded/user-invocable/source/path：

- inline Skill 正文进入当前 run 的 SkillContextBlocks；
- fork Skill 创建真实 child，父 run 只接收 child 结果；
- model 在 run 中通过统一 `skill` 工具按需调用其他 Skill；
- Skill 不创建或收窄父 run 工具快照。

含 Skill token 的 composer turn 会先将文本、有序 attachments 和 composer tokens 作为完整 `user_message` 耐久化，再进行 Skill 预激活。成功激活在执行前写 `skill_activated`/按需 resource receipts；激活失败仍保留该次用户输入，但不写伪 activation。Agent 执行时消费已准备的 turn，不重复写入 `user_message`。

成功的 composer 预激活还会生成 host-owned、current-run-scoped 的 `ComposerSkillSelection`，它包含经 registry 重新校验的 Skill ID、source、activation mode、绝对包根和 `SKILL.md` 绝对路径。RequestBuilder 在 Skill 正文之后追加不可由 Skill 正文伪造的选择绑定块：

- 单个 composer Skill 明确标记为用户本轮当前选择，“这个”、“刚选的”等指代直接绑定该 Skill；
- 多个 token 按 composer 顺序保留并明确标记多选歧义，宿主不擅自猜一个；
- token-only turn 不向用户正文注入伪 fallback 文本，选择语义仍由 host block 提供；
- 历史恢复或 model-invoked Skill 正文可继续进入 SkillContextBlocks，但不得冒充本轮 composer 明确选择。

source/path/root mismatch、Skill 已不可读或不再 user-invocable 时，在 provider 请求前失败，不将 renderer 中的旧 chip 当成权威。

继续已有 thread 时，Core 还会从 durable transcript 重建最近 ready media deliverable 的宿主引用清单。清单按 run 与媒体类型保留界面 `display_index -> artifact_id` 映射，并明确“第 N 张/个”只解释为最新相关媒体组的可见序号；该 host block 只进入本次 provider 输入，不改写用户可见文本，也不作为第二条 `user_message` 耐久化。`artifact_id` 仅是查找键，ToolRuntime 仍须在本 run 的 `PermissionContext.MediaArtifacts` 中复验 `deliverable + ready + kind + regular file` 后才能把记录路径交给媒体工具。新生成的 ready 媒体会动态加入同一 run 的许可集合。

## 3. 主循环

Agent 按 model response 执行 assistant text、tool calls、Skill catalog call、context estimate/compact 和后续轮次。每次模型调用先完成一次协议 lowering，耐久并 flush 脱敏 `model_request` 后发送完全相同的 prepared body，结束后用同一 request ID 写 nullable `model_usage`。普通工具默认自动；默认 raw Shell 使用当前登录用户本机权限，不进入通用审批。`ask_user` 只承担任务信息 gate；消息发送（包括多人、群、频道、广播和批量发送）没有 Awaken 人工审核状态。run 对外状态只有 `running`、`cancelling`、`finished`、`error`、`cancelled`，不存在通用 `awaiting_approval`。Journal 恢复使用的 terminal payload `status=interrupted` 会投影为公开 `error`/`RUN_ERROR`，不是第六种对外 run 状态。

ToolRuntime 先校验固定 snapshot/provider readiness，再执行 TaskScope、安全决策、broker 和 tool。canonical Outcome 回到模型；UI/replay 使用独立投影。

Hook 更新后的工具输入重新进入 ToolRuntime 的 schema、snapshot/provider readiness、TaskScope 和安全决策，不继承原输入的校验结果。Hook 阻断生成 `denied + side_effect_state=not_started + decision_source=hook` 的 canonical Outcome。Hook additional context 只作为当前 run 的 runtime context block 进入后续请求，不生成第二条 user message；command executor 不通过 Tool Registry，因此不会递归触发 Hook。Subagent 生命周期 Hook 使用父 run Dispatcher 和预算，回执带 `subagent_task_id`，其 additional context 只进入 child；child 内部工具调用仍不触发 user/project Hook。`BeforeFinish` block 把候选回答保留为 non-final assistant 历史，并把有界反馈作为 host-owned untrusted data 注入下一模型边界；每 run 最多两次，第三次写 `hook_reentry_limit` 并强制完成。

## 4. Thread 与恢复

thread 与 workspace/project 关系耐久保存。`projectId` 为空是独立对话的明确身份，不从 managed workspace 路径反推项目。重开时从 SemanticJournal 重建 user/assistant/tool/artifact/Skill/gate/context snapshot/model usage/terminal，而不是从 renderer local state 恢复。未闭合 run/tool call 由恢复流程标记 interrupted/unknown，不自动重放副作用；有 `model_request` 而无终态 usage 的请求补 `interrupted + usage_unknown`，不伪造 token 或成本。

fork child 的父子 identity、取消和工具继承必须显式；child Skill body 不注入父 run 的后续上下文。

归档会话不会自动进入新 run 上下文。只有当前用户请求引用归档历史、或当前任务明确依赖该历史时，root Agent 才能调用固定快照中的 `archived_history`：先 list 得到 host-resolved `thread_id`，再 read 有界 SemanticJournal 页面。ToolRuntime 从 root `AgentConfig` 注入只读 `ArchivedHistoryService`；Subagent child 不复制该 service，并在 role exposure 中隐藏工具。返回正文是 untrusted historical data，不改变当前指令优先级、TaskScope、工具权限或 thread 状态；物理 FileStore 路径不进入 provider request。

## 5. 不变量

- 同一 run 的 tool/environment snapshot 不变；
- 同一 run 的 Hook snapshot 和 Dispatcher 预算不变；配置或信任变化只影响后续 run；
- Skill hints 不改变权限或工具池；
- side-effect call 必须 append-before-transport；
- model request 必须 prepare once、journal+flush before transport，并以同一 request ID 封口；
- terminal 只能来自 durable run 事实，UI 不自行补成功；
- thread 切换/重开不得改变旧 run provider/readiness 或 Skill 内容。
- 归档历史只通过 root `archived_history` 的精确 archived `thread_id` 读取；不自动注入、不向 child 继承、不把历史内容提升为指令，也不允许模型绕过 Runtime 扫描业务数据根。
- 独立对话不得继承 Renderer 记住的项目路径，也不得被持久化为隐藏项目；同一 thread 的 managed workspace 必须稳定，不同独立 thread 必须隔离。
- 可见媒体序号由宿主从 durable Artifact 投影，模型不得用提示词编号或文件名替代；任意未出现在当前 thread 媒体许可集合中的 `artifact_id` 都不能获得路径能力。

## 6. 代码 owner

- `src/runtime/run_service.go`、`session.go`：run/thread lifecycle。
- `src/agentcore/agent.go`、`runner.go`、`request_builder.go`：主循环与请求。
- `src/agentcore/agent.go`、`runner.go`：child agent。
