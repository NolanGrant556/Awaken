# 左侧栏项目导航与筛选

## 1. 权威范围

本文唯一拥有左侧栏项目选择、展开、线程归属和“Filter projects”入口的当前产品与工程边界。项目添加、移除、删除历史和移到系统废纸篓由 [项目生命周期与删除](项目生命周期与删除/产品与状态机.md) 拥有；线程标题和运行spinner由 [会话标题与线程状态](会话标题与线程状态.md) 拥有。

## 2. 当前用户行为

- “项目工作区”区展示当前 active项目；removed项目不进入列表。侧栏项目行展示项目的主文件夹路径；完整文件夹列表在「编辑项目」弹窗里查看和修改，侧栏树的子节点只有线程。
- 侧栏「+」打开的创建弹窗以项目名称为主：填名字即可创建，选文件夹是可选步骤，可以当场加一个或多个、也可以留空。留空的项目照常出现在列表并能发起会话；它的运行位置与产出目录由 [TaskScope 与路径安全](../../04_工具权限与审批/TaskScope与路径安全.md) 拥有。已经属于其他项目的目录同样可选，同一个文件夹可以出现在多个项目里，共享带来的连带效应由 [项目生命周期与删除](项目生命周期与删除/产品与状态机.md) 拥有。
- 指针停在项目行上会在行右侧展开悬停卡片，列出项目名、对话串数量和这个项目的全部文件夹。点击卡片里的某个文件夹在系统文件管理器中定位它，卡片底部的「编辑项目」直接打开编辑弹窗。悬停卡片是只读入口，不提供设为主文件夹、解绑或废纸篓等写操作；零文件夹项目在卡片里显示占位文案，说明对话会在这个项目自己的工作目录里进行。拖拽排序进行中不弹出卡片；点开项目行 ⋯ 菜单时卡片立即收起，左右不同时出现两个浮层，菜单关闭后需要重新悬停才会再出现。
- 项目行 ⋯ 菜单提供「添加文件夹」「编辑项目」「从 Awaken 移除」「删除 Awaken 历史」。文件夹粒度的操作在创建项目与编辑项目弹窗的文件夹行上完成：切主与移出摊在行内，「移到废纸篓」只在编辑弹窗的行内 `⋯` 里；组成语义与作用范围由 [项目生命周期与删除](项目生命周期与删除/产品与状态机.md) 拥有。
- 启动时不存在隐式默认项目：用户主目录不再被自动注册为 workspace 或项目。没有任何用户明确选择的项目时，“项目工作区”区显示空状态（“暂无项目”）并保留 “Add folder” 入口；Desktop 与 Core 正常 ready，只有真正发起 run 时才要求 workspace。
- 项目列表只从当前 `~/.awaken` FileStore 的 active project 读取。Electron userData registry 和 Renderer localStorage 不再承载项目集合，也不存在读取、迁移或据此 upsert project 的入口；不在 FileStore 中的目录需要用户重新通过 “Add folder” 添加。
- 每个项目节点可展开/收起，子节点是按 thread workspace归属计算的线程。
- 顶层项目支持鼠标按住后上下拖拽排序；拖拽激活后原行淡化，项目名称与文件夹图标以悬浮卡片跟随指针，目标位置显示插入线，释放后立即按目标顺序展示。键盘聚焦项目行时也可用 `Alt + ↑/↓` 移动。子级thread不参与项目排序。
- 排序提交完整active project id序列，经 Desktop typed bridge 写入 FileStore lifecycle journal；刷新与重启后继续使用该顺序。提交失败时Renderer恢复Core返回的顺序并显示稳定notice，不在localStorage另存副本。
- 点击项目会选择该项目的主文件夹作为 workspace；若当前活动thread属于其他workspace，Workbench清空旧活动thread上下文。选中零文件夹项目时不解析出任何路径，也不沿用上一个项目的目录：run 只带 `project_id`，由 Core 解析该项目的 session 工作目录。run 的 readable/writable/output roots 填该项目的全部文件夹。展开按「cwd 所属的项目」判定而不是「cwd 是否等于主文件夹」：锚在次文件夹上的 run（继续旧线程、或切换过主文件夹之后）同样拿到项目的全部文件夹，本次 cwd 排在数组首位，其余文件夹按项目顺序跟随。cwd 不属于任何项目时保持单根。
- 点击线程会同步选中/展开其所属项目，并从 durable transcript重放线程。
- 选择、展开和 workspace 目标只使用当前 Renderer 内存状态；项目集合、removed 状态和 workspace 目标均不得写入 localStorage 形成第二 authority。
- “Filter projects”按钮当前只显示 `Project filters are not available yet.`，没有筛选popover、query、状态或结果集。

## 3. 线程归属

`threadItemsForProject` / `projectIdForThread` 以 FileStore thread metadata 的稳定 `projectId` 归属项目。多文件夹项目、以及同一个文件夹可以被多个项目持有，都让路径不再能唯一标识项目，因此归属只认 `projectId`。新 run 的 `projectId` 优先取侧栏当前选中的项目（前提是它确实持有本次 cwd），只有选中项与这个根无关时才按路径回退查找。不存在稳定 `projectId` 的非默认 thread 不得通过 `workspace:<path>` 合成伪 project id；路径比较只用于把某个文件夹映射回它所属的已有 FileStore project，不从显示 label 推断归属。

当前活动thread在侧栏使用 `thread:<threadId>` 作为active item identity；项目选择使用project id。两者不能混成同一 durable id，也不能因为历史thread仍引用workspace就把removed项目重新激活。

## 4. 代码责任

- 产品编排、选择和提示：`apps/desktop/src/renderer/App.tsx`。
- workspace/project identity helper：`apps/desktop/src/renderer/projectWorkspace.ts`。
- 侧栏树、项目节点、拖拽与键盘排序反馈：`Awaken Design System` 的 `AwakenSidebar` / `AwakenProjectTree`；只通过回调输出完整顺序。
- 文件夹列表、主文件夹徽标与文件夹行菜单：`Awaken Design System` 的 `AwakenProjectFoldersEditor`；创建项目与编辑项目两个 App 级弹窗复用。
- 项目行悬停卡片：`Awaken Design System` 的 `AwakenProjectHoverCard`；用 render prop 交出锚点而不是包裹元素，因为行样式依赖 `.aw-project-node > .aw-project-row` 直接子选择器。
- 在系统文件管理器中定位目录：`awaken:reveal-path` IPC，只接受主窗口发来的绝对路径并在定位前确认目录仍存在；artifact 的 `awaken:reveal-artifact` 绑定 transcript，不适用于项目文件夹。
- durable project/thread数据：03域存储和本域项目生命周期文档指向的Core owner。

## 5. 当前不支持

- 按名称、路径、状态或最近使用时间筛选项目；
- 保存筛选条件；
- 搜索跨项目thread；
- 重启后精确恢复项目选择或展开状态；
- 用历史thread自动复活removed项目；
- 在侧栏树里把文件夹作为项目子行展开；
- 远程、云端或团队项目导航。

## 6. 不变量

1. 筛选未实现时只显示明确提示，不展示假结果或静态mock。
2. 切换workspace不得让旧thread继续把新run写入错误项目。
3. thread归属来自 FileStore `projectId`，不来自 label、DOM 文本或 Renderer 合成 ID。
4. removed/`trash_pending` 语义由durable project状态决定，Renderer本地选择不能覆盖。
5. 未来筛选只改变可见集合，不得改变project/thread durable ownership。
6. 排序必须提交当时全部active project且每个id恰好一次；不得因为拖拽或并发刷新丢失项目。

## 7. 异常与恢复

- 线程重放失败：保留项目选择并显示notice，不伪造空历史。
- 初次项目列表读取失败：显示空项目集合并记录错误，不回退到旧 localStorage/registry；后续显式刷新或重启可重试。
- thread引用未注册workspace：不得据此激活removed项目；只有显式upsert/重新添加可恢复。
- 选择项目时路径缺失：不猜测workspace，不创建run。
- 排序提交失败或项目集合已变化：回滚乐观顺序、重新读取FileStore并显示notice；不得继续显示未落盘顺序。

## 8. 测试与真实 Desktop

自动化应覆盖项目/线程选择、workspace切换清理、thread归属、removed隐藏、完整集合排序、重启重放与筛选提示。当前主要owner是 `apps/desktop/src/renderer/App.test.ts`、`src/runtime/file_desktop_store_test.go`、`src/server/project_handlers_test.go` 与 `projectWorkspace` tests。

真实Desktop只读复核：

1. 展开两个项目并切换线程，确认active项目与thread归属同步。
2. 选择另一个项目，确认旧workspace的活动上下文不会沿用。
3. 点击“Filter projects”，确认只出现未实现提示且没有假筛选UI。
4. 重启后不得把localStorage写入误报为精确选择恢复；按实际行为记录。
5. 把一个顶层项目拖到另一个项目上方或下方，确认插入线、释放后的顺序；重启Desktop后确认顺序保持。
