# 本地主运行时准备链路

Awaken 的 `primary-runtime` 是 Work artifact 工具的本地依赖层，负责支撑 PPT、PDF、图片、Office 预览等非纯文本产物能力。它不是 shell，也不由模型临时安装依赖；启动或打包前必须由固定脚本准备和检查。

## 目录

Manifest 固定在：

```text
apps/desktop/resources/runtime-manifest/primary-runtime.json
```

本地生成的 runtime 固定在：

```text
apps/desktop/resources/runtime/
```

`resources/runtime/` 是本地生成目录，不提交二进制依赖到 git。仓库只保留 `.gitkeep` 和 manifest。`electron-builder` 会把当前本机已经准备好的 `resources/runtime/` 带入本机安装包。

## 脚本

准备 runtime：

```bash
npm run prepare:runtime
```

检查 runtime：

```bash
npm run check:runtime
node scripts/check-primary-runtime.mjs --json
```

当前最小 PPT runtime 要求：

- Python 可执行，并可 `import pptx, PIL`
- LibreOffice / `soffice`
- Poppler：`pdftoppm`、`pdfinfo`
- Node
- ffmpeg
- helper packages 目录

`prepare-primary-runtime.mjs` 会优先复用本机已有可用依赖，并在 `resources/runtime/` 下生成受控入口；如果没有可用 Python，它会在该目录下创建 venv 并安装 `python-pptx` 与 `Pillow`。

## 启动与打包

`npm run dev:desktop` 会在启动 Desktop 前执行：

```text
ensure-desktop-runtime -> prepare:runtime -> build main -> launch desktop
```

`npm run build:desktop` 会执行：

```text
build:ui -> build:binary -> prepare:runtime -> desktop build -> check:runtime
```

`@awaken/desktop` 的 `dist` 会执行：

```text
build:binary -> prepare-primary-runtime -> check-primary-runtime -> build -> electron-builder
```

Electron supervisor 启动 `awaken-core` 时会显式传入：

```text
AWAKEN_RUNTIME_MANIFEST=<resources/runtime-manifest/primary-runtime.json>
```

Go runtime 也会从当前目录向上查找仓库里的 manifest，避免测试或命令行运行因为 cwd 不同而误判 runtime 缺失。

## 边界

- 不允许模型通过 shell 临时安装或扫描系统目录来补 runtime。
- runtime 缺失时工具应返回明确缺口，不能生成坏 PPT。
- `presentation_create` / `presentation_render` 使用该 runtime 生成 PPTX、PDF 与 PNG 预览。
- 当前链路优先跑通 PPT；DOCX/XLSX/PDF/media 的深度渲染可以继续复用同一 runtime 准备机制扩展。
