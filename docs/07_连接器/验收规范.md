# 验收规范

## 1. 自动化

- source priority、稳定 provider ID、capability/dependency 去重；
- 六个 MCP builtin、两个 CLI builtin 与 local dynamic manifest；CLI definition 不产生 MCP config，也不调用 MCP Manager；Outlook definition 固定为 host OAuth + in-process MCP；
- Outlook PKCE state/code verifier、callback 单次消费、provider error、取消/超时、contract fingerprint、refresh、退出登录清理、恶意 redirect/DNS/私网地址与 Renderer URL/credential 泄漏；缺失 `AWAKEN_MICROSOFT_CLIENT_ID` 时 fail closed；
- Outlook Graph 的 list/get/create draft/send/reply/update/move/delete、固定 Graph base URL、Bearer header、输入/响应上限与安全错误；明确 401 标记 host account 和 Manager `needs-auth`，读写调用经 Workbench 只重放一次，第二次返回 `connector_auth_replay_exhausted`；
- builtin 只写 `AWAKEN_HOME/config/mcp-servers.json` user config、local InjectDynamic、同 owner disconnect 与跨 owner拒绝；
- connected/needs_auth/failed 到 provider readiness；
- Connector aggregate capability 与 per-tool metadata 都不作为 MCP 调用授权；
- metadata-less/无 annotations 的 read、mutation、message/delete，以及无效 metadata、自相矛盾 annotations，均在 connected/auth-ready、schema 有效时进入 provider transport；
- builtin 重启后只按稳定 provider identity 恢复 active owner、卡片状态跟随 Manager snapshot、手工同名配置不被认领；local/dynamic 重启后不恢复。
- Playwright builtin 为现有及新建 owner config 幂等准备 `AWAKEN_HOME/logs/mcp/playwright-mcp-server.log` 和受管加载器，保留其他 stdio env、不修改 `HOME`、不改手工同名配置；加载器 fixture 证明第三方硬编码路径被替换且用户主目录不产生日志。
- 旧 CLI MCP 只有完全匹配退役工厂签名才删除；备份、锁、原子写、幂等与修改过/手工同名/project scope 保留。
- readiness control token、未知 provider、错误 kind 与伪造快照拒绝。
- manifest 平台映射、CLI/官方 Skill checksum、安全 archive、Skill 文件数/解包大小/symlink/路径逃逸、只安装声明的 `dws`/`lark-*` 直接包、多包交换回滚、已安装 CLI 缺 Skill 的启动补齐、单调进度、取消后无失败残留与未完成稳定入口、重复安装、绝对路径执行、候选冲突与只卸载 Awaken-managed 副本。
- DWS/Lark fake CLI 覆盖 auth/config/status 的成功、拒绝、超时、取消、错误 JSON 与非零退出；Lark 只有 `identities.user.available=true` 且 `identities.user.verified=true` 才能进入已连接，用户退出后即使 Bot 仍为 ready、顶层 `verified=true` 也必须回到待授权并清除账户展示；CLI/Skills 已安装且官方状态只是未登录时必须保持 `install=installed`、`executable=available`、`authentication=required`，不设置 `safeError`，详情显示「重新授权」而不是「安装」；授权工作根目录缺失时由 Main 幂等恢复，dispose 不删除仍可能被在运行实例使用的共享根目录；授权等待态必须可显式取消，取消后 child 退出与其他迟到事件不得反写失败或重新打开网页，session 临时目录必须清空；DWS 只允许 `login.dingtalk.com/oauth2/auth`，必须拒绝 `mcp.dingtalk.com/cli/clientId`、logout、相似子域和其他后台 endpoint，且先出现后台 URL、后出现有效登录页时仍只打开有效登录页；Lark 配置/授权输出中的真实用户验证页可以打开，应用注册、device authorization、revoke、token 等服务端 API URL 必须拒绝，且先出现后台 API 错误 URL、后出现有效验证页时仍只打开有效页；敏感原始输出不进入公开状态。
- macOS/Windows route fixture 证明每次 CLI spawn/资产下载前先校准 route 并读取最新代理环境：dead loopback 在 auto 模式移除、监听器恢复后重新注入、NO_PROXY 保留本地 bypass、system proxy 变化触发 readiness refresh，dial/proxy/timeout 失败触发立即重判；活动 auth session 不因刷新重复创建。

## 2. Desktop 验收

组件层先在 `http://127.0.0.1:5173/#/components/awaken-product-logo` 确认“原子组件 / 产品 LOGO”默认渲染透明双柱 mark，并保留完整 App Icon PNG 作为 `icon` 变体，再在 `http://127.0.0.1:5173/#/components/awaken-connectors` 检查完整 MCP/CLI 组合、搜索、连接/断开、server 开关、品牌 fallback、浅色/暗色，以及复用同一 `AwakenProductLogo` 的 CLI 详情、MCP 配置和 MCP 设置弹窗；MCP 配置弹窗必须显示「本地进程（stdio）」与「Streamable HTTP」两个模式按钮，切换未编辑示例时同步更换 JSON，已有粘贴内容则保持不变，粘贴可判定的远程 JSON/裸 URL 时自动切到远程提示且不重写原文，并在远程模式说明兼容完整 URL 与 `type: "streamable-http"`。同时确认宽窗口两列、窄窗口单列，首屏信息密度紧凑且名称、说明、状态和标签没有裁切、重叠或异常换行，目录卡不渲染与名称相同的重复说明，但 `stdio · user` 等有效辅助信息仍保留。该结果只证明 Design System 渲染与局部受控交互。随后仍必须使用根 README 的正式入口在真实 Awaken Desktop 复核同一连接器页面，确认 Renderer 传入的真实状态和回调没有偏离 runtime 契约；连接一个内置 MCP 后，它只能在「Awaken 内置」原卡片显示连接状态、启停开关与设置入口，底层持久化 server 不得重复进入「用户安装」，而独立配置的 user/project MCP 仍必须显示在「用户安装」并优先展示配置 `displayName`；内置或用户 MCP 开关从开启到停用再恢复开启的全过程中，当前卡片必须保持原网格位置，不得闪现「暂无用户安装 MCP」空态，设置入口必须打开该卡片实际拥有的 canonical server 配置。

使用隔离 `AWAKEN_HOME` 验证 MCP builtin/local 与旧 CLI MCP 迁移，禁止把真实用户配置当迁移 fixture。macOS 与 Windows amd64/arm64 分别验证无 CLI 安装、已有 CLI 发现、受管安装优先、配置、授权、重启、停用、logout、卸载与 Workbench 往返；还需在授权前后分别关闭/开启系统代理与 loopback 代理监听器，确认 status/auth retry 使用新 route，且切换不会产生重复 auth session。不得出现“选择 CLI”文件选择器。授权临时目录、进程和订阅在所有终态与 Desktop 重启后必须清理；Main 必须拒绝非官方域名、非 HTTPS 地址以及官方域名下的服务端注册/授权 API endpoint，只允许实际用户验证页进入系统浏览器；Renderer 不得收到授权链接、二维码、device code 或 CLI 原始输出，浏览器打开失败必须进入可重试失败态。

Outlook 另用 Awaken 自有 Entra 测试应用与专用测试账号验证：未配置公共 client ID 时卡片显示明确失败；配置后点击 Outlook 只打开 Microsoft 页面，等待态可取消，完成后卡片为已连接且不暴露底层 in-process MCP 设置。安装 `examples/plugins/awaken-outlook` 的 ZIP 后，插件详情显示共享的 Outlook setup；未授权时四个 Skill 都 fail closed，授权后无需重装即可使用。真实执行收件箱读取、创建草稿、发送到受控测试地址、回复、标记已读/分类、移动与删除；再模拟 token 过期/401，确认 Workbench 原位等待、成功授权后相同调用只自动重放一次。重启 Desktop 后账号与 runtime 恢复，退出登录后 connector、插件 setup 和工具同步回到 needs-auth。检查 Renderer DTO、DOM、日志、Journal 与 `connector-accounts.json` 均不含 token、refresh token、code 或 Authorization header。

CLI onboarding 旅程还要验证：点击目录卡主体或保留的「+」都只打开连接详情弹窗，不立即安装且不跳转会话；钉钉与飞书弹窗的 X 固定在右上角，保留无障碍关闭名称，悬停或聚焦不显示可见 tooltip 与原生 `title`；弹窗点击「安装」后 CLI 与同版本官方 Skill 一起安装，显示阶段、单调百分比进度和「取消安装」；安装中点击遮罩或关闭按钮再重新打开，仍显示同一阶段/不倒退的百分比和「取消安装」，再次点击安装入口不得创建重复 session；取消后恢复「安装」且没有红色失败残留；DWS 完成后 `~/.agents/skills/dws/SKILL.md` 可由 Agents Skills 视图发现，Lark 的全部 manifest 声明 `lark-*` 包可发现且仓库其他目录未被复制；安装完成但没有已验证的当前用户身份时，弹窗显示「CLI 与官方 Skills 已安装，当前未授权」和「重新授权」，不得出现「CLI 操作失败」或回到「安装」；在没有项目/workspace 时仍可授权；DWS 打开官方浏览器页并等待，Lark 首次配置完成后自动继续打开用户授权页；弹窗不得显示授权二维码或链接，等待期间按钮必须为可点击的「取消授权」；关闭外部网页后点击取消必须终止当前 session 并恢复「重新授权」，没有红色失败残留，随后可以重新发起新的授权 session；等待授权时直接点击弹窗关闭按钮或遮罩也必须自动取消同一 session，目录卡在取消期间不可重复进入，再次打开只能显示「重新授权」，而安装中的相同关闭操作仍不得取消 install session；验证成功后按钮同步为带勾绿色「已连接」，悬停或聚焦显示「取消登录」，点击后官方 logout 生效并恢复「重新授权」入口、姓名与组织不再展示。整个 onboarding 不得创建 thread、发送 Agent 消息或写入 transcript。

其他业务会话缺权后 `ExternalActionGate` 仍应原位授权并继续；二维码固定占位与原位替换、paused follow、marker、return-to-latest、草稿/焦点/native bottom。run-bound 授权 gate 不得创建 narrative/step，也不得出现在 replay、历史线程或 Desktop 重启后恢复中。

组件与真实 Desktop 都必须确认 MCP/CLI 分类标签分别显示官方 MCP 标记和终端图标，两者在 16px 请求尺寸下光学等重；内置、用户自定义和 project MCP 卡都显示同一官方 MCP 标记，不因名称、运输或连接状态更换；连接器一级导航显示双插脚插头图标。实际调用用户自定义 MCP 后，工具轨迹的 active/done/error 都使用与其它单行工具同为 14px 请求尺寸的官方标记；不得以 server、六边形、通用工具或 compact 伴随字形替代。

## 3. 完成边界

只跑 fake CLI、registry 单测或 cross-build 不能声明真实 OAuth、外部服务、Windows 实机或完整跨重启旅程完成。Linux 是明确 `unsupported`，不要求成功安装；未执行的 macOS/Windows 架构和真实 provider 旅程必须逐项报告。
