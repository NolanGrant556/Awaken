# 连接器产品与架构契约

## 1. 权威范围

本文档唯一定义 Connector 的产品定位、Desktop 入口、当前 builtin 清单、类别与 Connector/MCP 责任边界。具体 transport、MCP server 状态和 OAuth 限制由 [06_MCP 运行时](../06_MCP运行时/索引.md) 持有。

## 2. 产品定位

Connector 是外部能力的产品化快捷入口：它持有可见名称、说明、类别、provider、授权类型、信任等级和 MCP config factory/inline config。它不是第二套工具协议，也不直接执行业务工具；最终执行面仍是 MCP Manager 与中央 ToolRuntime。

用户入口是 Desktop 的“连接器”页：

- 顶部使用 `MCP` / `CLI` 两个分类。
- `MCP` 页面显示“Awaken 内置”和“用户安装”。
- `CLI` 页面显示被 Desktop 名称/ID/provider 启发式判定为 CLI 的 connector。
- `MCP` 页面可打开“配置 MCP”；`CLI` 页面不显示此主操作。

Desktop 的 MCP/CLI 分类是 renderer 的展示规则，Core `ConnectorDefinition.Category` 仍使用 `docs`、`chat`、`code`、`data`、`other` 五类业务枚举。两者不可混为一个枚举。

## 3. 当前七个 builtin

`src/connectors/source_builtin.go` 的 `newBuiltinSource()` 是唯一清单真相：

| ID | Desktop 名称 | 分类 | 底层配置 | 当前授权边界 |
| --- | --- | --- | --- | --- |
| `puppeteer` | Puppeteer | MCP / code | `npx -y @modelcontextprotocol/server-puppeteer` | `none` |
| `chrome-devtools-mcp` | Chrome DevTools MCP | MCP / code | `npx -y chrome-devtools-mcp@latest` | `none` |
| `playwright` | Playwright | MCP / code | `npx -y @executeautomation/playwright-mcp-server` | `none` |
| `github` | GitHub | MCP / code | `npx -y @modelcontextprotocol/server-github` | metadata 为 API key；factory 未注入 PAT/env |
| `dingtalk-workspace` | 钉钉CLI | CLI / chat | `dingtalk-workspace-cli mcp` | metadata 为 OAuth2；Connector API 不完成 OAuth |
| `lark-cli` | 飞书CLI | CLI / chat | `lark-cli mcp` | metadata 为 OAuth2；Connector API 不完成 OAuth |
| `context7` | context7 | MCP / data | `npx -y @upstash/context7-mcp@latest` | `none` |

默认 builtin 不包含 Outlook/Microsoft 365、独立云盘、在线文档市场或通用邮箱 connector。

上表中 `authType` 是 Connector metadata，不是授权已成功的证据。尤其 GitHub factory 未把 `GITHUB_PERSONAL_ACCESS_TOKEN` 写入生成的 stdio env；看到工具列表不代表已能读取私有仓库。

## 4. 架构和责任分层

```text
Desktop ExtensionsView
  -> Connector HTTP actions（method/path 见 09 协议域）
  -> connectors.Registry
  -> ConnectorDefinition / config factory
  -> user MCP config OR Manager.InjectDynamic
  -> mcpclient.Manager
  -> mcp__server__tool
  -> ToolRuntime
```

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| `ConnectorDefinition` | 产品 metadata 与 MCP 配置生成 | 维持 MCP session |
| `connectors.Registry` | 合并来源、记录进程内 active owner、connect/disconnect | 直接调用工具 |
| `mcpclient.Manager` | server 连接、工具注册和 snapshot | Connector 产品分组 |
| Desktop | 展示、发起操作、读取状态 | 自行构造 MCP session/tool result |

Connector connect 动作是快捷配置/启动入口，不是业务授权成功的确认。Handler 目前解析但忽略 OAuth request body，也不调用 MCP auth 动作；具体 method/path 只查 [09 route 清单](../09_AGUI与A2UI协议/HTTP与SSE接口契约.md)。

## 5. 当前支持与不支持

### 当前支持

- 列出 builtin 与 local connector。
- builtin connector 生成一个或多个 MCP config 的接口（当前七个 builtin 均为 1:1）。
- Desktop MCP/CLI 分类、搜索、状态和 connect/disconnect 动作。
- local connector 作为 dynamic MCP server 注入。
- connector 已在当前进程 active 时，状态从其 server snapshot 推导。

### 当前不支持/未完成

- team connector 远程目录；只有 noop source/interface。
- Connector API 端到端 OAuth，包括返回 authorization URL 和 callback 后自动连接。
- 按定义冲突保留被 shadowed connector 供 UI 查看。
- 跨重启重建 connector ownership。
- 将“连接请求已接受”与“底层 server connected/已授权”分开的完整产品反馈。

## 6. 安全与产品边界

- 连接 connector 不得扩大 TaskScope、file bridge 或 network policy；它只增加工具源。
- 缺授权是 `needs_auth`，不得恢复通用 ApprovalCard。
- 群发/批量外发必须经专用 mass-message review；该规则由 04 工具域持有，Connector 不重新定义。
- UI 显示“已连接”必须有当前 MCP snapshot 依据，不得仅根据用户曾点击加号。
