# 本地主运行时准备链路

## 权威范围

本文唯一定义 Awaken primary runtime 的目录、manifest、prepare/probe/publish、打包安装和回退边界。工具何时需要 runtime 属于 04；Office worker 的 job 行为见 [Office 后台渲染](Office后台渲染.md)。

## 目录与 manifest

正式根目录：

```text
<AWAKEN_USER_DATA_DIR>/runtimes/primary-runtime/
├── versions/
│   └── <bundleVersion>/<os>-<arch>/<buildRevision>/
│       └── state.json                             # revision probe/provenance state
├── staging/
└── current.json                                  # active + previous
```

manifest template 位于 [`apps/desktop/resources/runtime-manifest/primary-runtime.json`](../../apps/desktop/resources/runtime-manifest/primary-runtime.json)，当前 schema version 2。`current.json` 通过原子替换发布 active/previous 指针，不使用 symlink；已发布 revision 不原地修改。

## 准备状态机

[`scripts/prepare-primary-runtime.mjs`](../../scripts/prepare-primary-runtime.mjs) 与 [`scripts/primary-runtime-common.mjs`](../../scripts/primary-runtime-common.mjs) 负责：

1. 解析 manifest 与目标平台。
2. 在 staging 组装完整依赖。
3. probe 二进制、版本、动态依赖和关键能力。
4. 写 provenance/state。
5. 把 staging 原子发布为 immutable revision。
6. 原子更新 `current.json`；新 revision 失败时保留旧 active/previous。

系统 Python/Node/LibreOffice 或 `PATH` 只能作为准备时的 seed；生产工具执行必须解析 active revision，不能直接跑系统二进制，也不能依赖 Codex/其他应用 cache。

## 完整性要求

- Python 是可重定位的完整 distribution，不用指向外部 venv。
- macOS 打包需要闭合动态依赖，LibreOffice 使用完整 `.app` 且后台运行，并进入签名/公证覆盖。
- Windows 包必须带齐所需目录和 DLL，不能假设开发机安装了相同 runtime。
- archive 带平台/架构/revision identity 和内容校验；安装先到 staging，校验后发布。

Desktop 打包安装由 [`apps/desktop/src/main/runtime-archive-installer.ts`](../../apps/desktop/src/main/runtime-archive-installer.ts) 及 [`scripts/install-primary-runtime-archive.mjs`](../../scripts/install-primary-runtime-archive.mjs) 协作；archive 构建见 [`scripts/package-primary-runtime-archive.mjs`](../../scripts/package-primary-runtime-archive.mjs)。

## 工具运行时边界

工具执行前 resolver 读取 `current.json`、校验 state/provenance 并返回受管路径。工具调用不能自行传入 Python、Node 或 LibreOffice binary 覆盖 resolver。

当前 ToolRuntime 遇到缺失 runtime 会产生 `needs_runtime` outcome 和 `runtime_prepare_started`/`runtime_missing` 可见事件，但普通工具调用本身不会自动下载、修复或执行 prepare 脚本。开发准备与打包安装是显式宿主流程；不要把“started”事件写成自动修复已实现。

`AWAKEN_PRIMARY_RUNTIME_ROOT` 只用于受控开发/测试 override，不是普通用户配置入口。

## 失败、回退与不支持

- prepare/probe 失败：staging 不发布，保留 active。
- active 损坏且 previous 有效：安装/恢复流程可回退指针；工具不得在一次调用里擅自切换。
- archive 缺项或校验失败：安装 fail closed。
- 不支持从 shell 临时 `pip install`/`npm install` 后把环境当产品 runtime。
- 不支持运行时缺失时直接降级到系统 LibreOffice。
- 不支持依赖开发者机器的全局包、外部 app cache 或可变 symlink。

## 测试与验收

标准命令由根 `package.json` 提供：

```bash
npm run prepare:runtime
npm run check:runtime
npm run test:runtime
```

脚本测试 owner：[`scripts/tests/primary-runtime.test.mjs`](../../scripts/tests/primary-runtime.test.mjs)；Desktop archive 安装测试：[`apps/desktop/src/main/runtime-archive-installer.test.ts`](../../apps/desktop/src/main/runtime-archive-installer.test.ts)。

验收必须验证 clean machine/clean userData 场景、active/previous 原子切换、故障不破坏旧 revision、目标平台动态依赖和签名。仅在开发机上 `command -v python` 成功不构成验收。
