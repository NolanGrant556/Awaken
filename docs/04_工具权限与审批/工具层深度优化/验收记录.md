# Tool Layer v2 验收记录

更新时间：2026-07-11

## 自动化验收

通过：

~~~text
go test -count=1 ./...
go vet ./...
go build ./...
go test -count=1 -race ./src/tool ./src/agentcore ./src/skillruntime
git diff --check
~~~

关键门禁：

- 30 个可执行静态 builtin：strict=30、adapted=0、incomplete=0，全部通过 `strict_builtin` definition validation；3 个 `execute=nil` artifact stub 不再注册或暴露。
- 核心模型描述包含 Do not use when / Effects / Returns 及相邻工具边界。
- RequestBuilder 使用 resolved definition，而不是 legacy description。
- ToolRuntime 使用同一 registered input schema 校验并保持 v2/MCP object shape；显式 v2 与 legacy 参数漂移有跨层回归测试。
- strict definition 的 `details` 会经过 output schema verification；失败保留可能已经发生的 partial/unknown side effects。
- Definition example 走同一 input validator；registry snapshot 不可由返回值反向修改。
- `/v1/tools` 所有 resolved fields 均存在；动态外部工具的 `examples` / `failureModes` 可为空数组，但必须由 `quality` / `warnings` 显式标记 metadata 缺口。
- Outcome golden 覆盖 success、validation、permission、nonzero、timeout、needs-auth/runtime、truncation、artifact、typed trash、partial/unknown 与状态矛盾。
- failed Outcome 的 legacy AffectedPaths 只作 target context，不生成虚假 change。
- permission 预测 path 不会升级成 executor-observed change。
- MCP IsError=true、recursive schema、legacy wrapper 均有真实 in-process MCP 测试。
- MCP OutputSchema、StructuredContent -> Details、canonical 字段冲突包装均有测试。
- read/search/artifact publish/text create/trash 均有聚焦 Outcome tests。
- ModelPayload 深拷贝、typed container 脱敏、循环/深度保护、结构化 8 KiB 预算和并发投影均有测试。
- apply_patch exact add/update/move/trash changes、artifact published/create/update 语义、shell 未观察副作用与非盲重试均有测试。
- 跨层终态测试覆盖：ModelPayload 保留 unknown side effects；strict output mismatch 在 completed/artifact/audit 之前 fail-closed（直接与 transform）；unknown tool 不原样重试；success outcome + Go error 不能覆盖 transport failure。
- 固定 Skill 工具故障注入覆盖 validation/source/runtime 分型、reload 下一步、replace fail-closed、package-root/包内/project-root/`.awaken` 符号链接越界、rooted install 与 remote Git helper/option/ref/ambient env 边界。

## 独立文档读者测试

独立 agent 仅阅读调研与设计文档，能够回答：

- 当前实现并非只有 success/message；
- Definition/Outcome 两条单一事实链；
- raw legacy/external definition 的兼容规则；
- baseline + delta 而非全量环境扫描；
- failed + partial/unknown side effects；
- model/journal/UI 共享 canonical fact 而非同一序列化；
- 第一批 migration 项；
- tool-selection 必须通过固定 prompt matrix 与真实 Desktop 检查。

根据读者反馈，设计补充了状态组合、content/details 优先级、observation provenance、projection 白名单、delivery failure 分层、外部 unknown metadata 和 eval 阈值。

正式入口：

~~~text
npm run close:desktop
npm run open:desktop
~~~

启动成功证据：

- screen：awaken-dev-desktop
- renderer：http://127.0.0.1:5174/
- Electron PID：4551
- awaken-core PID：4569
- 当前 core 监听：127.0.0.1:63535
- 真实窗口：Awaken Desktop 1412x882 at 50,42（由正式入口启动检查返回）

从该 Desktop 自己管理的 awaken-core 做只读补充检查：

- /health：ok
- /v1/tools：99 个当前动态工具全部为 schema version 2
- 当前动态快照：strict=32、adapted=24、incomplete=43
- origin：builtin=31（含运行时注入的 `skill_install`）、MCP=50、Skill=18
- source/quality：builtin strict=31；MCP adapted=24、incomplete=26；Skill strict=1、incomplete=17
- 30 个静态可执行 builtin 均为 strict；运行时 `skill_install` 也是 strict builtin，`skill_resource_read` 是 strict Skill tool。43 个 incomplete 仅来自当前动态 MCP（26）与 Skill（17）metadata 缺口；该快照会随已启用 MCP/Skills 变化。
- 必需 definition 字段缺口为 0；`examples` / `failureModes` 均为数组且无 null；最长 model description 为 1711 字符，低于 1800 字符预算。
- `spreadsheet_chart`、`document_render`、`pdf_render` 在 live catalog 中均不存在。
- 当前 live MCP server 没有声明可适配的 output schema；MCP OutputSchema 路径由 in-process SDK 测试验证，不能把测试支持误报为当前服务器已提供 metadata。

最终重启后的 Computer Use accessibility 复核因 Mac 已锁屏而无法重新抓取；未尝试绕过锁屏。窗口存在性、尺寸、进程与 live core contract 由正式入口检查、`lsof`、`/health`、`/v1/tools` 交叉确认。此前同轮已在解锁状态完成真实窗口检查。

真实 LLM tool-selection smoke 已分别用已配置的 kimi-for-coding 与 deepseek-v4-pro 发起，但两次都在任何 LLM/tool call 之前被 Desktop 凭据层阻断：

~~~text
Error invoking remote method 'awaken:start-run':
Error: Secure credential storage is unavailable on this device
~~~

因此本轮不能诚实宣称“真实 LLM 选择矩阵已通过”。阻断发生在 Model Profile API key 解密阶段，与 Tool Layer 无关；没有工具执行，也没有 fixture 文件修改。本轮未改 Model Provider、credential store 或 UI，以遵守任务范围。

## 验收结论

- Definition、registry、schema、model description、result envelope、error/recovery、state feedback、MCP truth 与静态 existing-tools migration：通过自动化和 live runtime contract 验收。
- 最终代码已通过 Awaken Desktop 正式关闭/重启；真实窗口、进程、监听端口、/health 与 /v1/tools 由同一次启动快照交叉确认。
- 真实模型多次 tool-selection/recovery 统计：被当前设备 secure credential storage 阻断，待凭据层恢复后补跑；当前只能报告 structural/contract smoke，不能报告 LLM selection 通过率。
