# 技能管理与执行 · 需求文档

用户可以浏览、预览、安装和选择技能。运行按需读取技能正文和资源；技能来源、显式选择、执行方式与恢复行为都应可追溯。

代码、接口和验证方法见[实现方案](实现方案.md)。

## 限制与尚未完成的部分

- model-facing `skill` 工具与 fork Skill 当前不注册包 Hook；这是防止模型侧文本选择自行获得当前用户命令执行权的明确限制。只有 composer 显式、host 绑定激活走当前注册链。
- `LastInvokedAt` 在 registry 中是进程内目录状态；运行上下文可由 SemanticJournal 恢复，但目录时间戳本身尚无独立耐久存储。
- 旧字段的兼容解析不表示 Awaken 承诺实现其原宿主的所有语义。

- MCP WebSocket transport 仍不支持；in-process 只用于测试。
- 外部 MCP server 的 prompt/resource 能力、认证和内容可靠性取决于 provider；bridge 不能为 provider 错报内容兜底。
- fork 已有 Agent Core 集成测试，但本轮尚未形成 Windows 实机和真实 Desktop 跨进程证据。

- Typst `PDF_Max` 的真实模型端到端调用（生成文件 → strict compile → 逐页视觉 QA → `artifact_publish`）尚未完成实机验收；本轮 Office 验收不改变该缺口；
- Office 包内工作流目前只有 macOS 真实 Desktop 验收证据；Windows 与 Linux 仍无实机证据；
- 本合同不改变 MCP、Skills runtime、Workbench 布局或 Office 生成依赖；LibreOffice、Poppler 仍是用户机器上的系统依赖，不随 App 分发。

## fork 参数

用户随 fork Skill 提供的输入文件、参数和约束必须进入子 Agent 的本次分配，不依赖 Skill 作者是否写了 `$ARGUMENTS`。这不复制父任务历史，也不把父 Agent 后续负责的步骤交给子 Agent。只选择 Skill、未输入参数时保留空参数；参数形成的分配仍受子任务长度限制，超限明确拒绝，不能静默截断。

## 目录暴露

模型只看到一个 `skill` 工具，而不是每个 Skill 一个 tool schema。其输入是 Skill ID/名称与可选参数。目录描述预算约为模型上下文窗口的 1%，按约 4 chars/token 估算；默认上限约 8,000 字符，单条说明（description 与 whenToUse 拼接后）最多约 250 字符。超出预算时分三级降级：完整描述 → 按剩余预算在全部条目间均摊截断描述（每条不低于约 20 字符）→ 均摊后低于该下限时整体退化为 names-only。这样目录规模不会线性挤占任务上下文，也不会在预算轻微超限时就丢光全部描述。

统一 `skill` 工具使用幂等注册：相同 runtime 实例和相同已解析 definition 的 refresh 保留原 `RegistrationID` 与 Tool Registry generation；模型可见 Catalog 改变、`SKILL.md` 调用 binding 改变或 Manager 的真实 runtime callback/provider binding 改变时才建立新注册。`RegistrationID` 继续作为 run 工具快照的执行 pin，不能为了消除刷新噪声退化成只按工具名或 schema hash 复用。

Desktop 管理面投影 `sourceOrigin`、锚定路径、状态、诊断、deprecated warning、shadowed owner、`userInvocable`、`modelInvocable` 与最近调用时间。Slash 只展示 `loaded && userInvocable != false && sourceOrigin != "plugin"` 的条目；project/user/bundled/agents/MCP 等普通来源维持既有行为。排除 plugin 只是 Composer 的产品展示策略，不改变统一 Skill Catalog、Registry、model-facing `skill` 工具或 Plugin Store 的运行时供给。

Skills 管理页默认打开 Awaken Skills，视图顺序为 Awaken、项目、全局、Agents。bundled 只进入 Awaken Skills，来源标签为“Awaken 内置”，且完全不渲染删除入口。只有由 Awaken 安装生命周期拥有的 project/user 包可执行删除：project 对应某个已发现文件夹的 `<folder>/.awaken/skills/<package>`，user 对应 `~/.awaken/skills/<package>`；MCP、managed、additional 与 legacy 等其他非安装根来源保留卡片入口但明确禁用，不得由 Renderer 根据展示路径直接删除。plugin 来源完全不进入 Skills 管理页，其管理、预览和生命周期只在 Plugin Console 中提供。具体页面行为由 [技能页产品与架构](需求文档.md) 拥有。

Plugin Console 不提供把 Plugin Skill 复制、派生或安装到 user/project scope 的入口。plugin Skill 始终由 Plugin Store 和 Plugin Console 管理；用户需要独立 Skill 时，必须通过普通 Skill 安装或创作入口提供一个独立包，不能从已安装插件树生成副本。

## 安装边界

`skill_install` 当前支持 `content`、`content_base64`、`local_path`、`remote_url` 和 `remote_git`，目标只有 project（默认项目主文件夹的 `<workspace>/.awaken/skills`；用户在 Desktop 明确选择其他文件夹时使用该文件夹）或 global/user（`~/.awaken/skills`）。包可以是 `SKILL.md`、zip 或含唯一根 `SKILL.md` 的目录；最多 1,000 个文件、解包内容 50 MiB，拒绝 symlink、路径逃逸和非法包。

Skill 安装边界会在提取唯一 `SKILL.md` 前识别插件包：存在 Agent Plugins/Codex/Claude Code/Cursor 插件清单、`skills/<component>/SKILL.md` 插件布局，或与根 `SKILL.md` 同根的 commands/agents/hooks/MCP 插件组件时返回 `PLUGIN_PACKAGE_SELECTED`，不得把其中一个组件截取并写入 `.awaken/skills`。反过来，只有根 `SKILL.md` 和普通资源、没有插件清单或插件专属组件目录的 ZIP 是普通 Skill，不得按 manifestless Plugin 安装。Desktop 两个 ZIP 入口消费这两个 typed 结果：Skills 入口选到插件包时保留已选路径并切到插件安装；插件入口选到普通 Skill 时切到 Skill 安装、让用户确认 project/global 范围后从同一已选 ZIP 安装。包类型路由只改变安装入口，不改变 plugin Skill 的 Catalog/Runtime 投影，也不允许两个 Store 互相写入对方的受控根。

`skill_package_export` 是修改本地已安装包的受控准备入口：根据 Registry 的 source root、包 realpath 与 `SKILL.md` 锚点重新校验身份，把完整包原子复制到一个此前不存在、且不属于受保护 `.awaken` store 的作者目录，保留脚本、references 与二进制 assets；在线包和 Registry 不变。目标已存在时 fail closed，不覆盖。导出只是快照，不授予对原 source root 的普通文件写权限。

Desktop 安装弹窗同样只提供 project/global。bundled 是产品构建资源，不是用户安装 scope；不得通过现有安装 API 或页面创建 bundled 包。

`remote_git` 只接受无 inline credential 的绝对 HTTPS URL，可选安全 ref/subpath；Git 禁用 credential helper、交互、file/ssh/git/http protocol，并使用最小环境。这是 `skill_install` typed provider 自身的来源合同，不限制 Agent 在 Skill 已安装后按正文使用默认 Shell 准备依赖。

同 ID 默认 `abort`。显式 `replace` 通过 staging、旧包 backup 和新包原子 swap，再将旧包移入平台 Trash；Trash 失败会回滚新旧包并 fail closed，不永久删除。Outcome 记录 `previous_package_trashed_path`（平台可提供时）。安装后默认 reload registry，也可显式关闭。安装成功的 next action 指向统一 `skill` 工具，并携带 `input_hint.skill`。安装器不得在发现、解包或激活阶段擅自执行包代码；Skill 进入 Agent 上下文后，初始化命令由 Agent 通过普通 Shell 调用显式执行，并以真实命令输出进行恢复。

## 技能管理界面

Skills 管理页有四个固定视图，顺序为 `Awaken Skills`、`项目 Skills`、`全局 Skills`、`Agents Skills`，每次进入页面默认选择 `Awaken Skills`。

项目窗口的文件夹筛选列表必须留在可见窗口内。文件夹较多时，列表内部滚动，顶部说明保持可见；包含零 Skill 的最后一个文件夹仍能选中。打开、滚动或选择筛选项不能让整个应用出现额外滚动条或横向位移，选择后保留项目窗口并显示对应列表或空态。

### Skill 包只读预览

bundled、project、user、agents 等技能页可见且可预览的本地来源统一使用约 `820 × 720` 的固定阅读 Dialog，只有视口不足时才自适应收缩，不随 Markdown 长短改变窗口高度。plugin 来源不进入这条预览链。项目 Skill 在持续挂载的项目窗口内切换到该阅读比例，其他来源使用同尺寸独立预览；项目列表本身仍保持约 `980 × 640`。预览顶部固定展示图标、Skill 名称、紧邻名称的来源小字、说明和启停开关；中间保留一个不绘制公共卡片边框的纵向滚动视口，视口内上方是独立的“包内文件”卡片，下方是独立的 `SKILL.md` 阅读卡片，两者不得嵌套或共用一个卡片表面；project/user 在底部左侧显示删除入口，bundled/agents 不显示。没有“立刻试用”、复制、编辑、文件点击或包内资源正文读取入口。关闭按钮保留 `aria-label="关闭"` 供辅助技术使用，鼠标悬停或键盘聚焦时不显示可见 tooltip 或原生 `title` 提示；Dialog 标题仍以 visually-hidden 形式提供给辅助技术。

中间内容视口是 Dialog 中唯一的纵向滚动容器，并作为初始焦点，因此鼠标滚轮、触控板、方向键、Page Up/Down、Home/End 都作用于“包内文件”卡片与 `SKILL.md` 卡片组成的完整内容流。两张卡片只共享该滚动 owner，不共享可见外框。关闭后恢复卡片焦点；关闭或切换条目时回到顶部，较早请求晚返回时不得覆盖当前条目。

滚动内容固定按以下顺序展示：

1. 独立的 `包内文件` 卡片：按 package-relative POSIX 路径展示目录、普通文件、symlink/other 类型和普通文件字节数，最多 512 项；任何绝对路径、文件内容和执行入口都不进入该树；
2. 独立的 `SKILL.md` 卡片：卡片标题明确标识入口文件，卡内先展示包含原始 `---` 分隔线、字段顺序和未知字段的完整 YAML frontmatter，再展示 frontmatter 之后的完整 Markdown 正文，支持 GFM 标题、列表、表格、代码块、引用和只读任务列表。

frontmatter 只是 `SKILL.md` 卡片内的正文流，不再添加第三张卡片、独立边框、圆角或底色；fenced code block 保留代码容器的边框、圆角和底色。代码块与宽表格只允许自身横向滚动，不建立第二个纵向滚动区。预览关闭 raw HTML、脚本、Mermaid 执行和外部图片请求；相对链接不解析，只有 `http`/`https` 外部链接可点击。主题色、遮罩、代码、表格、引用、链接和滚动条全部来自 Design System token，Dialog 打开时切换浅色/暗色会立即继承新 token。

## 失败与恢复

- 源缺失、源非法或首次同步失败：记录结构化 `system_skills_sync_failed`，Core 以无 bundled Skill 的状态继续启动；
- 已有完整目标但升级失败：保留或恢复旧目标，Core 继续使用它；
- 用户手工修改 Desktop-owned 目标：下一次成功同步按资源源覆盖；
- 目标同步成功但没有实际 Skill 子包：Awaken Skills 保持空态，不生成 invalid 卡片。
- 预览读取与 Catalog 同步之间发生文件消失、身份过期、路径/realpath 校验失败、资源枚举失败、非 UTF-8 或超过 2 MiB：读取请求在正文区域显示明确错误；后续 Catalog 同步确认条目消失后按上文退出该预览。资源树超过 512 项时只显示明确的有界清单与截断提示；`SKILL.md` 正文不展示截断内容，也不回退为 Renderer 直接读文件。
## 共享依赖与执行路径

Office 与 Creator helper 的普通执行依赖统一使用完整办公包入口，切换生成语言不新增另一组基础安装。包内资源仍从 Skill 基准目录读取，安装目录不能跟随业务项目变化。目录、来源、安装和回收规则见[依赖与路径管理](../../03_运行时与本地服务/依赖与路径管理/需求文档.md)。
