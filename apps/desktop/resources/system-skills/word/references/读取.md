# Word 读取

## 阅读固定路线

阅读 `.docx` / `.dotx` 不安装 Pandoc、MarkItDown、LibreOffice 或第三方 Python 包，也不先手工解包。先通过 `load_workspace_dependencies({})` 取得固定办公包的 Python 绑定。以下 Bash 调用都传入该 `environment_ref`，然后执行一次 read route doctor：

```bash
"$AWAKEN_PYTHON" -B "${AWAKEN_SKILL_DIR}/scripts/doctor.py" --route read --json
```

Windows PowerShell 示例为 `& "$env:AWAKEN_PYTHON" -B "$env:AWAKEN_SKILL_DIR/scripts/doctor.py" --route read --json`。这一步只用于取得 `execution_plan.python` 并确认 bundled reader 存在，不探测或安装外部文档依赖。随后用 doctor 返回的绝对解释器路径执行唯一阅读 CLI；路径始终作为一个安全参数引用，PowerShell 调用绝对路径时在前面加 `&`：

```text
"<doctor 返回的 execution_plan.python>" -B "${AWAKEN_SKILL_DIR}/scripts/read_docx.py" input.docx --format json --output ./docx-read.json
```

随后用 `Read` 打开 `docx-read.json`。JSON 中：

- `markdown` 是按文档顺序线性化的正文、标题、列表、超链接、表格、脚注/尾注、批注和页眉页脚；
- `blocks` 保留段落/表格等结构，表格行列分析优先使用这里的 `rows`，不要反解析 Markdown；
- `warnings` 明确指出图片/绘图、文本框、公式、域、修订、合并单元格、嵌套表格、altChunk、嵌入对象、图表或 SmartArt 等未完整覆盖或被线性化的内容；
- `stats` 用于核对实际提取到的对象数量。

有 warning 不等于读取失败，但必须按 warning 限定结论；当任务依赖图片、空间布局、复杂公式或嵌入对象时，不能把线性提取冒充完整理解，应补视觉 QA 或明确报告当前未覆盖内容。旧 `.doc` 不属于该 CLI 支持范围，需先通过 LibreOffice 输出新的 `.docx`。
