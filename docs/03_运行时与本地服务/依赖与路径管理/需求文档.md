# 依赖与路径管理 · 需求文档

Awaken 在用户级目录管理固定办公环境，按任务需要准备，再把实际程序和库路径交给模型。常用 Python、Node 办公库及转换、重算、渲染组件作为一个经过验证的版本交付，跨项目、会话和 Agent 复用。

固定办公包管理、自动恢复、共享引用和设置入口已实现。macOS 的本地候选已通过真实任务、修复、压缩续行及重启复用验证；公开资源尚未发布，Windows 实机未验收。已有健康实例可以复用；需要安装而没有当前平台发行资源时，入口明确报告资源不可用。代码职责、验证方法和证据范围见[实现方案](实现方案.md)。

## 用户问题与目标

用户不应学习 Python、Node、虚拟环境、包管理器或 PATH。相同的 Word 任务不能仅因模型换用另一种生成语言，就再次安装常用办公依赖；新项目也不能变成新一轮环境搭建。

本功能要得到以下结果：

1. 用户提出任务后，缺少固定办公环境时由 Awaken 自动准备，完成后当前任务继续，不要求重新提问或重启。
2. Word、Excel、PPT、PDF 的默认生成、转换、公式重算和页面检查使用同一套已验证的环境。Python 与 Node 的常用路线都可用，切换路线不新增安装。
3. 工具、Skill 和模型使用宿主提供的实际路径，不各自寻找不同的解释器或办公软件。
4. 用户项目保存业务输入、需要保留的代码和交付物。共享安装、下载缓存和安装暂存留在用户级目录。
5. 更新失败或依赖准备失败不破坏健康版本、其他任务和用户数据。

“安装即可用”允许第一次办公任务联网准备独立的依赖包，不要求所有资源都放进 Desktop 安装包。首次准备的时间和下载体积必须如实展示。健康环境可离线复用，不在每个项目或任务中检查并安装最新版。

## 当前能力与目标边界

### 当前支持及缺口

- 官方 Office/PDF/Creator Skill 和基础指令统一请求完整办公包；Python 与 Node 路线共用基础环境，版本和安装位置由宿主决定。
- 已有健康实例优先复用，复用不依赖下载地址。旧绑定损坏时，当前任务再次请求环境会复用健康副本或按原准备流程重建；失败不替换原记录。
- Office helper 与 doctor 使用同一份宿主执行信息，缺少绑定时不扫描系统软件。通用 Shell 和第三方自定义脚本仍保留各自执行语义。
- 就绪检查包含库导入、Word/PPT 转 PDF、Excel 重算与页面渲染；具体交付文件仍须独立检查内容、公式和版式。
- 设置页支持状态检查、准备与修复。新副本通过验证后才切换，保留在用实例和有期限的健康回退。
- 三个平台的办公候选包已构建，尚未公开发布。macOS ARM64 本地验证不能替代全新电脑公开下载或其他平台实机验收。

### 管理范围

| 对象 | 管理行为 |
| --- | --- |
| 固定办公环境 | 包含常用 Python/Node 办公库、LibreOffice、Poppler、中文字体及默认 PDF_Max 所需组件；按平台验证后整体交付 |
| 浏览器、OCR、音视频和非常用库 | 作为独立扩展按需准备，不因普通办公任务安装全部扩展 |
| CLI、MCP、插件与外部 Agent | 保留既有连接和授权入口；明确识别的启动依赖由宿主管理，自定义命令保留外部配置语义 |
| Git、搜索工具等开发组件 | 按工具用途选择明确配置、应用随包、受管或系统入口，不统一套用办公软件的优先级 |
| Core、Electron、OfficeCLI、CUA Host 等应用资源 | 随应用安装与更新，由所属模块解析，不重复安装为办公依赖 |
| 用户自行安装的软件 | 保留原有所有权；不能自动升级、搬动或删除。仅在对应工具明确允许并验证兼容时使用 |

固定办公环境最低系统要求为 **macOS 13.3**，Windows x64 保持 Windows 10 基线。Desktop 原有启动要求保持不变；旧 macOS 可以继续使用其他受支持功能，但新办公包准备会在下载前明确提示系统不支持，不下载后再碰运气。

固定办公环境默认使用受管版本，不以先扫描系统 Python、LibreOffice 等软件来拼成办公包。遇到下载失败，应修复资源交付或环境；不能悄悄换用系统版本后宣称受管环境已经就绪。用户明确要求使用某个外部软件时，按外部执行处理并说明覆盖范围，不把它登记为完整办公包。

该方向对齐本机 Codex Desktop 的固定办公环境、宿主准备和明确路径；不要求复制 Codex 的目录名称、包大小、专有库、平台安装格式或未确认的内部行为。

## 用户入口与执行过程

用户从现有项目和任务输入框提出普通需求，不需要指定能力名称、解释器或安装位置。

1. Desktop 正常打开，办公任务按需检查环境，用户也可从设置 → 环境管理主动检查。状态读取不阻塞无关任务；仅打开应用或设置页不重试上次失败安装，也不重放历史任务。
2. 首次任务请求办公环境时，宿主创建或加入同一个准备操作。模型通过简化入口取得结果，不提交安装目录、任意下载地址、包列表或安装命令。
3. 已有适用的健康包时立即取得路径；缺失时下载、校验、准备并验证完整办公包。
4. 准备完成后返回包版本、能力范围、解释器、库和启动器路径，当前任务继续。
5. 后续项目、会话、子 Agent 和应用重启复用同一适用版本。选择 Python 或 Node 生成 Word 不再改变基础安装内容。

办公转换和公式重算应在后台完成。macOS 的后台 LibreOffice 不应反复显示 Dock 图标或抢占桌面。旧办公副本缺少后台配置时，通过现有环境恢复流程准备兼容副本；不要求用户修改系统设置或应用文件。

办公包按整体管理，设置页分别展示 Python 与 Node.js 的检查状态；生成、内容核对、结构检查、公式重算、页面检查与交付物发布仍分别判断。环境就绪不等于文件已经完成，文件生成成功也不等于视觉检查通过。文件质量规则由[本机依赖与文件生成](../本机依赖与文件生成/需求文档.md)拥有。

### 准备进度、取消与恢复

任务显示真实的检查、等待、下载、校验和准备阶段；有总字节数时才显示百分比。多个使用者共享一次实际准备，但各自有可取消的等待状态。

Python 正常运行产生或刷新字节码缓存，不应使办公环境变成损坏状态。健康检查必须包含执行需要的库源码、模板、配置、模型、字体及原生运行数据；不能只检查解释器能否启动。原任务已有健康环境时继续复用。实际程序或库损坏后，任务再次请求办公环境时，Awaken 自动复用健康副本；没有适用副本时按原准备流程安装，成功后把新路径交给当前任务。用户无需先去设置点击修复。历史回放不触发安装，也不自动重放结果未知的业务命令。

取消一个任务只取消该使用者的等待和后续执行，其他等待者可以继续。没有等待者时停止可取消的工作，保留已校验缓存；取消不删除健康版本。进程退出后，宿主识别未完成状态，用户恢复原任务或新任务提出需要时再继续必要准备，不重放结果未知的业务操作。

当前版本的选择记录缺失或损坏时，从已验证的兼容安装恢复，不要求用户删除记录。磁盘写入失败立即报告磁盘或权限原因，不重复网络下载；中断的下载暂存由宿主安全回收。

任务中显示准备阶段、已下载体积和失败原因；运行中的任务通过原有停止入口取消自己的等待。设置 → 环境管理只列出 Python 环境和 Node.js 环境，每行显示版本和检查状态。检查通过显示勾和“正常”，缺失显示“需要安装”，异常显示“需要修复”；读取失败或旧 Core 未提供独立状态时不打勾。其他组件、安装工具和详细依赖不在页面列明，由宿主继续统一管理。

页面底部仅保留“修复”按钮：缺失时准备环境，异常时重建副本，全部正常时禁用；两行共用同一办公包时只执行一次准备，不分别重复安装。打开页面自动检查，准备结束后自动更新，不保留手动刷新按钮。操作期间显示阶段和已知下载进度，同一按钮切为“取消”，只解除本页等待。打开页面不会自动安装，仍在首次任务需要时准备。原会话再次请求办公环境时自动恢复到健康实例；设置中的修复按钮只是手动备用入口。普通用户无需进入终端执行包管理命令。网络自动恢复与用户手动停止后继续是不同的验收场景。

## 路径、项目与权限

共享环境沿用 Awaken 的用户级数据根，项目位置、会话身份和 Agent 身份不决定办公包版本或安装键。项目改名、移动和 Windows 不同盘符不触发重装；移动整个 Awaken 数据根则必须重新检查路径。

宿主提供真实绝对路径和适合当前平台的启动参数。Office Skill 使用同一执行信息；办公启动器调用包内固定程序，不从系统 PATH 再选一个版本。Node 的 CJS/ESM、Python 导入及命令入口都必须在项目目录之外正常工作。

安装暂存和下载缓存不能进入业务项目。生成脚本、预览和交付物仍按任务工作目录和 output roots 保存，不能把业务文件放入受管依赖目录。Skill 相对资源以宿主提供的 Skill 根解析。

第三方 Skill 如果写死项目 `.venv` 或自行执行安装命令，保留其原有行为；本功能不拦截任意第三方脚本，也不保证这类安装跨项目复用。

环境路径固定不构成操作系统沙箱。Bash 的权限和用户显式命令继续遵守[命令执行](../../04_工具权限与审批/命令执行/需求文档.md)，不能承诺任意脚本绝对无法绕过 PATH。新入口不能扩大文件工具对 Awaken 数据根的写权限。

用户软件项目的构建依赖继续按项目约定处理；办公环境不能全局覆盖该项目的 Python、Node 或包版本。第三方扩展依赖不写入已发布办公包，真实冲突使用独立的受管扩展环境。插件、Skill 的包管理和账号权限继续由[插件管理](../../14_插件/插件管理与运行/需求文档.md)、[技能管理](../../08_技能/技能管理与执行/需求文档.md)及[连接器管理](../../07_连接器/连接器管理/需求文档.md)负责。

## 更新、回收与迁移

办公包版本由产品的兼容清单确定，不因进入项目、重复调用 Skill 或模型选择语言而改变。启动可以做轻量版本状态检查；不在后台擅自中断在用环境或恢复已取消的安装。更新与强制修复由宿主管理入口执行，缺少产品要求版本的任务也可触发准备。

新包先校验并准备完整，再切换新任务的默认选择；已运行任务、后台命令和服务继续持有原实例。更新失败保持原选择。当前版本、最近健康回退和所有在用版本保留，其余实例按延迟回收规则处理。

缓存、失败暂存与健康安装分别清理。删除项目、清理会话或卸载单个插件不删除其他使用者仍需的环境；文件占用时延迟清理，不强行删除。

删除会话历史后，该会话及子 Agent 的环境续行绑定一并清理。共享安装和其他会话不受影响；仍存活的后台进程继续通过自己的使用记录保护环境。归档不清理这些绑定。

已有细分环境先作为旧版本保留，不直接拼装或重命名为新办公包。旧任务继续使用有效绑定，新任务转入固定办公包；旧实例失去引用后才按回收规则处理。CLI、Typst 的既有路径与账号数据保持原所有权，不为统一目录而复制或搬动。

## 失败时的行为

| 情况 | 宿主处理与用户结果 |
| --- | --- |
| 首次缺少办公包 | 自动准备一次，展示阶段，完成后继续任务 |
| 超时、限流或临时网络错误 | 按现有[网络代理与恢复](../网络代理与恢复/需求文档.md)有界重试；网络恢复后可重试准备 |
| 下载地址不存在或平台无资源 | 明确说明资源不可用，停止重复下载；不把换能力名称当成恢复方法 |
| 哈希不符、包缺文件或最小操作失败 | 不激活新包，保留健康版本，提供修复或重试入口 |
| 磁盘不足或目录不可写 | 停止准备，保留有效缓存和旧环境，说明处理方式 |
| 记录丢失而实例文件完整 | 检查包清单和文件后重建索引，不重新安装健康包 |
| 包内程序或路径损坏 | 再次请求环境时自动复用健康副本或准备新实例；成功后当前任务使用新路径，失败保留原记录和其他任务环境 |
| 业务脚本错误、文件内容错误或账号未授权 | 按业务或授权流程处理，不误判为缺依赖并重装 |

## 验收标准

产品验收必须使用真实 Awaken Desktop 和真实 LLM，从正常输入框提交自然语言任务。macOS 覆盖真实流程及发布构建；Windows x64 覆盖实现、交叉编译、测试编译和资源清单检查，实际安装运行仍延期。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 无系统 Python/Node/办公软件，缓存和受管目录为空 | 从真实公开地址准备办公包并完成任务，用户未执行安装命令，测试人员未预置包 |
| 先用 Python 再用 Node 做受支持的办公任务 | 同一办公包版本提供两种路线，无新增基础依赖安装 |
| 新项目、另一个会话、子 Agent 或重启后使用 | 复用适用的包版本与实际文件，不因身份变化重装；健康复用无需联网 |
| Word 页面检查与 Excel 公式重算 | 使用同一办公包的解释器和原生程序，不能借系统软件掩盖包内缺失 |
| 多任务同时首次准备、其中一个取消 | 只有一次实际部署，其余等待者仍成功，取消方不继续业务执行 |
| 下载失败、错误哈希、进程退出、激活中断 | 未完成实例不成为 ready，旧健康选择不受损，恢复不重复业务操作 |
| 中文、空格、项目移动和 Windows 非系统盘 | 安装位置和包选择不变，Python/Node 模块与原生入口可用 |
| 上下文压缩、模型切换、父子 Agent 交接 | 能重新取得原实例的路径，不丢失使用记录，不重复安装 |
| 已绑定环境损坏，原会话继续请求环境 | 自动取得健康环境；已有副本不重装，失败不替换原记录，重启不复活旧绑定 |
| 更新期间有任务、后台命令或服务使用旧包 | 新任务可使用已验证新包，原使用者完成后再回收旧实例 |
| 删除索引、清理缓存、删除项目、卸载插件 | 可恢复健康安装记录，不误删在用依赖和用户数据 |
| 第三方扩展或显式外部软件 | 来源、版本和所有权明确，不篡改基础办公包，不冒充其就绪 |

验证同时检查实际文件、包版本、解释器路径、下载和部署次数，不能用一个操作 ID 掩盖多次安装。只读回读和临时测试输出不另存为几千行一次性验收汇总；有效方法、当前限制和未完成项由这两份文档维护。文档格式检查不构成产品验收。
