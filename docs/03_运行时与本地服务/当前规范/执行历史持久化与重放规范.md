## 1. 当前事实（Phase 0 基线）

当前实现仍是双重事实模型：

1. `thread_<id>.jsonl` 的 `message` 记录保存 conversation，可含 `tool_calls`、`tool_call_id`、`is_error`。
2. 同文件的 `event` 记录只持久化 recoverable 白名单：文本、上下文、TurnFinished、RunFinished、RunError。
3. `ToolCall*`、`ToolResult`、`Artifact*`、`CommandOutput`、`PatchUpdated` 不进入 durable event 账本。
4. 历史 API / Desktop 重放主要消费 events；因此重启后工具卡与 Artifact 会丢失，即使 message 层仍有工具事实。
5. `RunService` 对 `AppendConversation` / `AppendRunEvents` 的错误存在忽略写法。

## 2. 目标契约（Phase 2 必须实现）

### 2.1 Canonical record

唯一 canonical 类型为 `agentcore.SemanticRecord`，`schema_version=2`。

稳定 kind：

- thread
- run_started
- user_message
- assistant_message
- tool_call
- tool_result
- artifact
- file_change
- turn_diff
- permission_decision
- skill_activated
- resource_receipt
- runtime_notice
- recovery_decision
- turn_boundary
- run_terminal
- persistence_warning

每条记录至少包含：`schema_version`、`record_id`、`seq`、`session_id`、`thread_id`、`run_id`、`turn_id`、`parent_id`、`kind`、`timestamp`、`payload`。

### 2.2 耐久与临时边界

必须写入：

- 用户消息与每次完整可见 assistant message
- ToolCall 最终参数、skill_id、call_id、宿主 activity
- ToolResult 完整 ToolOutcome
- Artifact、planned/applied file_change、最终 TurnDiff（单条 unified diff 上限 50,000 字符，超出 truncated=true）
- Skill 激活、resource receipt、runtime/auth/recovery、turn/run 终态

默认不写入：

- stdout/stderr 每个 delta
- reasoning / TextDelta
- spinner、百分比 tick
- tool args streaming delta

### 2.3 写入接口与顺序

- `agentcore.SemanticRecorder`：`Append` / `AppendBatch` / `Flush`，全部返回 error。
- `runtime.ExecutionJournal` 实现该接口；`EventSink.Emit` 只负责成功落盘后的直播广播。
- 正式 `StartRun` 缺少 recorder 时返回 `persistence_unavailable`。
- 顺序：先 SemanticRecorder 成功，再 EventSink；`tool_call` 必须在真实工具执行前写入成功。
- `tool_result` 与 artifacts 同批；applied `file_change` 与它们同批；`turn_diff` 在 `turn_boundary` 前。
- terminal 后 Flush 并 `file.Sync`。
- AppendBatch / terminal Flush 固定重试：50ms、200ms，最多 3 次实际尝试。

### 2.4 故障语义

- `run_started` / `user_message` / `tool_call` 写入失败：立即取消，真实工具不得执行。
- 副作用后的 `tool_result` / artifact / terminal 写入失败：`persistence_degraded`，保留 pending，用户可见警告。
- terminal flush 最终失败：终态 `persistence_error`。
- 禁止忽略 Append / Flush error。

### 2.5 重放

- 服务端用唯一 `SemanticProjector` 将 SemanticRecord 转为 AG-UI events。
- live 与 transcript API 共用该 projector；Desktop `actionsForThreadTranscript` 只按序 dispatch，不得猜测丢失的 ToolCall/ToolResult。
- live/replay 等价测试只允许忽略接收时间、流式 delta 游标、纯动画状态。
- 旧 v1 JSONL 通过 `LegacyTranscriptAdapter` 只读适配：assistant `tool_calls` 与 tool message 投影为语义 item；缺失 Artifact 不伪造；不批量重写用户历史。
- orphan run：未配对 `tool_call` 追加 synthetic interrupted outcome（`ErrorCode=process_restarted_outcome_unknown`），再追加 `run_terminal(status=interrupted, reason=process_restarted)`；不得自动重执行。

## 3. 与相邻规范的关系

- ToolOutcome 字段与状态枚举以实施方案第 6 节为准；本规范只要求 ToolResult 耐久记录携带完整 outcome。
- Skill activation / resource receipt 的耐久 kind 在本规范登记；激活策略见技能规范（Phase 4 同步更新）。
- Runtime prepare/ready/missing/repair 事件必须可耐久；RuntimeManager 所有权见本地主运行时准备链路（Phase 6 同步更新）。
