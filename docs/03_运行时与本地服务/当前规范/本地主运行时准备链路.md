# 本地主运行时准备链路

Awaken 的 `primary-runtime` 是 Work artifact 工具的本地依赖层，负责支撑 PPT、PDF、图片、Office 预览等非纯文本产物能力。它不是 shell，也不由模型临时安装依赖。生产环境由 RuntimeManager v2 拥有、探测并原子激活；文件存在不等于 ready。

## 所有权

生产环境唯一根目录：

```text
<AWAKEN_USER_DATA_DIR>/runtimes/primary-runtime/
├── versions/<bundleVersion>/<os>-<arch>/<buildRevision>/
│   ├── state.json          # resolved state（与模板分离）
│   ├── python/ ...
│   ├── node/ ...
│   ├── libreoffice/ ...
│   ├── poppler/ ...
│   ├── ffmpeg/ ...
│   └── packages/ ...
├── staging/                # 临时准备区；失败不得破坏 current
├── current.json            # active + previous known-good version key
└── state.json              # 可选宿主侧准备进度快照
```

`AWAKEN_USER_DATA_DIR` 解析顺序（Node/Desktop/Go 共用契约）：

1. 显式环境变量 `AWAKEN_USER_DATA_DIR`
2. 与 Electron `app.getPath("userData")` / `@awaken/desktop` 一致的平台规则：
   - macOS：`~/Library/Application Support/@awaken/desktop`
   - Windows：`%APPDATA%\@awaken\desktop`
   - Linux：`${XDG_CONFIG_HOME:-~/.config}/@awaken/desktop`

仅测试/开发允许用 `AWAKEN_PRIMARY_RUNTIME_ROOT` 覆盖 runtime root。禁止各脚本自行回退到 `~/.cache`。

`current.json` 记录 `active` 与 `previous` known-good version key。写入必须 temp write → fsync → atomic rename；**不使用目录 symlink 作为激活指针**。

每次真实 prepare / repair 都生成唯一且不可变的 `buildRevision`。即使 `bundleVersion` 没变，也不得覆盖 active 目录；新 revision 通过 probe 和 provenance 后才切换 `current.json`，旧 active 保留为 `previous`，因此同版本 repair 也能真实回滚。

## Manifest 模板与 resolved state

仓库模板固定在：

```text
apps/desktop/resources/runtime-manifest/primary-runtime.json
```

模板 `schemaVersion=2`，声明 `bundleVersion`、组件 `version` / `source` / `relativePath` / `probe`。平台与 arch 在 prepare 时写入 resolved `state.json`，不把激活路径写回仓库模板。

Node `check-primary-runtime` 与 Go `runtime_preflight` / Artifact 执行路径必须读取同一 `current.json` + `versions/<key>/state.json`，并对 readiness 得出相同结论。

## 准备生命周期

```text
discover sources
-> stage temporary directory under staging/
-> copy/install into staging（真实复制，禁止 wrapper/symlink 回 seed）
-> real probe every required component
-> provenance audit（Python prefix + Mach-O/链接依赖）
-> write resolved state.json
-> atomic rename staging -> versions/<bundleVersion>/<os>-<arch>/<buildRevision>/
-> atomically update current.json（保留 previous known-good）
```

规则：

- executable path 存在但 target 失效、exit nonzero、或 probe 失败 → not ready。
- symlink / wrapper resolve 后必须仍在 Awaken-owned root 内，否则 not ready。
- Python 必须复制完整可重定位 distribution；`sys.executable`、`sys.prefix`、`sys.base_prefix` 都必须落在 active root 内，任何 `pyvenv.cfg` 都判为 not ready。`venv --copies` 不是可重定位分发方案。
- macOS Node、Poppler、ffmpeg 的非系统 Mach-O 依赖必须递归复制，并用 `install_name_tool` 改写为 runtime 内的 `@loader_path`；只允许 `/System/Library` 与 `/usr/lib` 作为系统依赖。`/opt/homebrew`、`/usr/local`、Codex cache 或其他外部绝对依赖一律 not ready。
- macOS LibreOffice 必须复制完整 `.app`；包内版本化 dylib 若缺少运行时需要的 `@rpath` 别名，在 staging 内物化后再审计。
- macOS LibreOffice 副本必须保留 bundle 内相对 symlink，拒绝断链、绝对链接和源 bundle 越界链接；只修改 Awaken 自有副本。专用 bundle 使用 `LSBackgroundOnly=true`、独立 bundle identifier，并移除文档类型、URL scheme、QuickLook 与 Spotlight 注册；不得同时设置 `LSUIElement`。
- LibreOffice bundle 修改后必须从嵌套 Mach-O/bundle 向外重签。开发 revision 使用 ad-hoc；release revision 只接受显式 pristine、原厂签名与 Team ID 校验过的 seed，并在 CI 完成 Developer ID、notarytool、staple、codesign strict 与 Gatekeeper 验证。
- 最终 LibreOffice app tree 必须移除 owner/group/other 写权限；worker 固定注入 `PYTHONDONTWRITEBYTECODE=1`，防止 embedded Python 在 bundle 内生成 `__pycache__` 破坏 sealed signature。连续转换后仍须通过 `codesign --verify --deep --strict`。
- Linux LibreOffice 只复制精确的 `<install>/program/soffice` 所属产品根；Poppler 只复制所需 executable，禁止把 `/usr/lib` 当成组件目录整体复制。
- staging 中途失败不得破坏 current；repair 失败回滚 previous known-good。
- 系统安装与显式 seed 只能作为复制来源，不得成为正式 RuntimeReady / current target。
- Windows Poppler 必须复制完整 `bin` 目录（含 DLL），不能只复制 exe。
- Windows Python 使用完整 distribution 的 `python/python.exe`；Node/ffmpeg 同时复制同目录 DLL。不得生成指向安装机的 venv。
- 生产执行路径默认不扫描 `PATH`，不读取 Codex 或其他产品 cache。

## Seed 与一次性迁移

- prepare 的 source 优先级是显式组件环境变量 / `AWAKEN_PRIMARY_RUNTIME_SEED_DIR`，其后才是受校验的平台发现。Python 的自动发现只接受 `uv python find --managed-python` 返回的完整 distribution；PATH 上的 venv、Homebrew Python 或 Codex wrapper 不能作为 Python seed。组件 source 环境变量不得进入 Go Artifact 执行解析；正式执行只使用经过 probe/provenance 的 managed active revision。
- 仅允许显式 `AWAKEN_PRIMARY_RUNTIME_SEED_DIR` 作为整包 seed；seed 和 PATH 都只是复制来源，删除来源后 active 仍必须通过检查。
- 旧 `AWAKEN_PRIMARY_RUNTIME_CACHE_DIR` 只作一次性迁移别名，并输出 deprecated warning，不参与正式解析。
- 仅当 `current.json` 不存在时，允许把旧 `~/.cache/awaken-runtimes/primary-runtime` 迁入新 root；拒绝 Codex cache、越界 wrapper/symlink、probe 失败组件。
- 迁移结果写入：

```text
<AWAKEN_USER_DATA_DIR>/data/migrations/primary-runtime-v2.json
```

后续启动不重复迁移。

## 脚本

```bash
npm run prepare:runtime
npm run check:runtime
node scripts/check-primary-runtime.mjs --json
npm run test:runtime
npm run package:runtime:archive
npm run install:runtime:archive -- --archive <zip> --manifest <manifest.json> --expected-team-id <Awaken TeamIdentifier>
```

`prepare-primary-runtime.mjs` 在 managed root 内 stage → probe → publish。`check-primary-runtime.mjs` 只验证 Awaken-owned current，不把系统安装或外部 cache 判为 ready。

发布机使用 `package:runtime:archive` 为已 Developer ID 签名、公证并 staple 的 immutable revision 生成保留 symlink/签名的 archive 和 SHA-256/designated-requirement manifest。用户机器的 install 命令只做平台、架构、摘要、内部 symlink、签名、公证票据、Gatekeeper 和 Awaken 宿主 TeamIdentifier 复验，再原子激活；它不包含签名入口，也不读取 Developer ID 私钥。外部 manifest 不能自行声明一个新的信任根。

正式 Desktop 发布使用 `npm run dist:desktop:release`。该入口把唯一匹配当前平台/架构的 archive 与 manifest 放入已签名的 Awaken app resources，并携带只读 installer。Packaged Desktop 在启动 `awaken-core` 之前自动调用 installer；同 revision 已 active 时幂等跳过，校验或安装失败时只保留 Desktop 诊断能力，绝不回退执行用户安装的 LibreOffice。开发 `open:desktop` / `build:desktop` 不要求发布凭据，继续使用 ad-hoc managed revision。

隔离验收必须同时覆盖 prepare 与独立 check，且不能写默认 Desktop root：

```bash
AWAKEN_PRIMARY_RUNTIME_ROOT="$(mktemp -d)" npm run prepare:runtime -- --repair --json
AWAKEN_PRIMARY_RUNTIME_ROOT="<同一隔离目录>" npm run check:runtime -- --json
```

设置 `AWAKEN_PRIMARY_RUNTIME_ROOT` 时 prepare 会跳过旧 cache migration，避免测试把 migration marker 写进真实用户数据目录。

## 启动与打包

`npm run dev:desktop` / `build:desktop` / Desktop `dist` 仍在启动或打包前调用 prepare/check。Electron supervisor 启动 `awaken-core` 时传入：

```text
AWAKEN_USER_DATA_DIR=<Electron userData>
AWAKEN_RUNTIME_MANIFEST=<bundled template primary-runtime.json>
```

Go 正式 Desktop 路径只接受 `AWAKEN_USER_DATA_DIR` 推导 managed root；测试/开发可用 `AWAKEN_PRIMARY_RUNTIME_ROOT`。模板 manifest 仅用于组件声明与 probe 规格，正式执行路径来自 `current.json` 指向的 version 目录。

所有 DOC/XLS/PPT 到其他 Office 格式的转换以及 `.xls` 读取统一调用进程级 `OfficeRenderWorker`。Worker 从 `current.json/state.json` 内部解析 revision 和 soffice，调用工具不得传可执行路径；默认单并发、相同任务 singleflight、输入复制到私有 staging、每 job 独立 `UserInstallation`、最小环境变量、超时/取消进程树清理、输出原子发布。通用 local-compute 不允许直接运行 soffice。

Runtime probe 与 Office worker attestation 以 active revision 为缓存键；同 revision 只执行一次，`current.json.active` 变化时重新探测。工具权限检查只读取这一快照，不在每次工具调用前重复执行 `soffice --version`。

## 可见性

RuntimeManager 产生宿主事件：

- `RuntimePrepareStarted`
- `RuntimePrepareProgress`
- `RuntimeReady`
- `RuntimeRepairFailed`

启动检查与 Artifact 调用前均可触发。内部安装 Python 包等依赖显示为宿主操作，不得伪装成模型主动 `pip`。

## 边界

- 不允许模型通过 shell 临时安装或扫描系统目录来补 runtime。
- runtime 缺失时工具应返回明确缺口，不能生成坏 PPT。
- `presentation_create` / `presentation_render` 使用该 managed runtime 生成 PPTX、PDF 与 PNG 预览。
- 删除或不存在 Codex cache 不得影响 Awaken readiness。
