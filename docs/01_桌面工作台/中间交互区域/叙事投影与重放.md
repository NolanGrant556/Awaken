# Workbench 叙事投影与重放

## 1. 权威范围

本文唯一拥有 Desktop 中 `event -> runtime reducer -> RunNarrative projector -> turn -> live/replay` 的投影规则。09 域拥有 wire event、cursor 与断线续传，03 域拥有 durable transcript 和 journal 语义顺序，04 域拥有 tool Outcome；本文只定义这些事实如何成为 Workbench narrative。

滚动和布局见 [交互状态机与滚动布局](交互状态机与滚动布局.md)。

## 2. 数据链

```text
Go runtime semantic record
  -> AG-UI-compatible Desktop event
  -> runtime/client subscription or transcript replay
  -> runtime/reducer.ts
  -> run-narrative/projector.ts
  -> committedItems + activeItem
  -> App.tsx projects only a trailing busy initial/continuation planning item
     and a turn-top RunElapsedTime from reducer timestamps/final elapsedMs
  -> groupNarrativeByTurns()
  -> ExecutionFeed
```

核心 owner：

- `apps/desktop/src/shared/agui.ts`：Desktop 接收字段类型；
- `apps/desktop/src/renderer/runtime/client.ts`：subscribe/reconnect/replay；
- `apps/desktop/src/renderer/runtime/reducer.ts`：run/thread view 与终态汇总；
- `apps/desktop/src/renderer/run-narrative/types.ts`：UI narrative union；
- `apps/desktop/src/renderer/run-narrative/projector.ts`：幂等投影；
- `apps/desktop/src/renderer/workbenchPresentation.ts`：turn grouping 和 execution-process segmentation；
- `apps/desktop/src/renderer/App.tsx`：组件选择，不重新解释协议。

## 3. Narrative 模型

`RunNarrativeState`：

```ts
{
  committedItems: RunNarrativeItem[];
  activeItem?: RunNarrativeItem;
  inspectorSelection?: InspectorSelection;
  seenEventKeys: string[];
}
```

当前 item：

| kind | 身份与作用 | Workbench 当前投影 |
|---|---|---|
| `prompt` | turn 起点，含文本、附件、tokens | `UserPromptBlock` |
| `planning` | 请求初始活动或 live turn continuation | 仅 busy 且仍为 narrative 尾项时投影为动态 `ThoughtTrace`；initial 使用默认 Thinking，continuation 使用确定性阶段文案并延迟 650ms 出现；首个真实输出或终态出现后过滤 |
| `thinking` | reasoning summary | `ThoughtTrace`：active 自动展开透明 Thinking 状态行和流式正文，done 移除思考球并默认折叠为 `Thought` + 右侧 Chevron 历史入口；正文沿原左边缘向下展开 |
| `exploring` | read-only action group | presentation adapter 先把 `actions` 展平为普通 Tool 行；单动作旁路批次，多动作与相邻 `tool/skill` 共同进入 Activity Batch |
| `tool` | 单个工具或决策轨迹 | `ToolTraceLine`：自然语言短摘要留在内容宽度单行，类型化详情卡从原左边缘展开；相邻活动可进入 Activity Batch |
| `skill` | 已调用 Skill 的 invocation/content/execution-context/failure | `ToolTraceLine(kind=skill)` 或 Activity Batch 子项；catalog discovery 不进入执行叙事 |
| `approval` | legacy approval 历史 | 只读 `ToolTraceLine` |
| `fileChange` | 旧文件变更投影 | 当前返回 null；终态汇总时移除 |
| `memoryReceipt` | Memory recall/mutation 或 Dream terminal 的无正文回执 | `ToolTraceLine` |
| `compactBoundary` | 上下文压缩边界 | compact boundary line |
| `answer` | assistant markdown，含 `isFinal` | `AssistantMessage` |
| `hint` | 取消等中性提示 | hint line |
| `deliverables` | 终态 ready deliverables | `DeliverableList` |

Skill invocation/content/execution-context event 同时进入 reducer 的 Skill 状态，并按 `run + skillId` fold 为一个可重放的 `skill` narrative item；discovery 只属于 catalog，不进入执行叙事，failure 以 error row 保留诊断。这里的 `skill` 只是 Renderer 投影类型，不是新的 ToolRuntime tool kind。tool item 同时保留 environment/tool snapshot ID、provider、capabilities、readiness、dependencies 和 side-effect state；中心显示短摘要与基于既有数据生成的类型化详情卡，完整 provider/依赖诊断仍等待 Inspector 接线。

### 3.1 Activity Batch 展示投影

`projectNarrativeActivitySegments()` 只在 Renderer presentation 层处理连续 `exploring/tool/skill`。批次 ID 是 `turnId + firstItemId`；有效动作总数为一时直接返回单项，两个及以上才返回 `NarrativeActivityBatch`。任何非活动 narrative item 都是硬边界，因此 reasoning、可见说明、gate、Subagent、媒体、Artifact、Final 和下一 Prompt 不会被吞入工具批次。`exploring.actions` 在此层展平，保持 action 自身稳定 ID 和事件顺序。

live 与 replay 共用同一投影。Renderer 从 transcript 恢复 thread 时，必须把有序 replay action 在一次 reducer transition 中原子折叠为完整 view；首个可见帧已经包含当时全部 prompt、thinking、工具、回答和终态，不得把耐久事件逐条 dispatch 成可观察的历史流式播放。replay 恢复出的 narrative item 保留稳定 identity，并关闭 Thought 标题/正文及 Tool 的挂载入场动画；恢复后才收到的 live item 仍按实时语义入场。active Thought 的持续思考状态不属于挂载入场，不因 replay 标记被暂停。active 批次在没有用户选择时自动展开，状态进入终态后自动收起；受控 `open/onOpenChange` 记录按 turn/batch/tool 稳定 ID 留在当前 Renderer 生命周期内，切换 workspace surface 不丢失，应用重启不持久化。Final 之后由外层 `executionProcess` 统一折叠；该 segment 同时携带 final answer 的耐久 `elapsedMs`，使 turn 顶部唯一的 `RunElapsedTime` 在终态原位成为 disclosure 标题。当前最新 turn 可用 reducer 起止时间兜底，旧 replay 无耐久耗时时回退标题“执行过程”。final footer 不显示耗时。Activity Batch 不改变 final 分段、RunStage 滚动或 prompt anchor ownership。

批次摘要只统计现有内容：命令、读取/搜索、文件编辑、Skill、混合工具与异常数；进行中/已完成由标题时态表达，只有异常数作为独立 detail。Tool 主行对文件路径只取 basename，Shell 优先使用完整参数已有的任务描述，结果正文不回流主行。`Glob/Grep/WebSearch` 使用搜索图标；`Glob` 的 `**/*.pdf` 等递归模式在主行翻译为“PDF 文件”等用户语义，Grep 的文件范围同样翻译，不展示 `*`、`**`、`{}` 等工具语法。原始 pattern 只在类型化详情中保留。Tool 详情只展示类型允许的数据；敏感键递归替换为 `••••`，Shell 文本中的敏感环境赋值同步脱敏，未知工具 args 不进入详情。文件 diff 仅按既有 `toolCallId` 与 `patchPreviews` 关联，不新建协议字段。

## 4. Prompt 与 turn

`run/requested` 立即创建 prompt 和 planning，使用户不必等网络返回才看到输入。prompt id 是 turn identity；附件和 `PromptNarrativeToken.leadingText` 必须一起保存。`leadingText` 的 durable owner 是 `ComposerToken` 本体：live `run/requested` 用提交时的 draft tokens 投影，`run/recovered` 与 v2 durable replay 都从 run 的 `inputAttachments` / `composerTokens`（含 `leadingText`）投影同一组结构化输入，canonical 回流不得把正文中间的 token 降级到句首。旧 count-only 记录没有足够事实可恢复，不得用 prompt 文字或磁盘扫描猜造附件对象。

`run/requested.startedAtMs` 同一提交首帧提供 live 计时起点；`RUN_STARTED.timestamp` 到达后 reducer 重基 `runStartedAtMs`，成功终态把同一时间边界计算出的 `elapsedMs` 附着到 final answer 供 replay 使用。`RunElapsedTime` 只在自己的 React 子树内按秒读取当前时间，优先使用 final answer 的耐久 `elapsedMs`，其次使用当前 view 的 started/completed 时间戳；它不创建 narrative item、不写 transcript、不让整个 `App` 以 1 Hz 重渲染。没有耐久耗时的历史 turn 不补造计时。

`App.tsx` 合并 committed + active 后调用 `projectVisibleNarrativeItems()`：只有 run 忙碌且仍处于列表尾部的 planning 会进入可见列表。initial planning 覆盖提交到首个真实输出；live `AWAKEN_TURN_STARTED` 的 `tool_result_continuation`、`reactive_compact_retry`、`max_output_continuation`、`xml_fallback_continuation` 分别创建“正在分析工具结果”“正在整理上下文并重试”“正在继续生成”“正在继续处理工具结果”的 continuation planning。该状态延迟 650ms 出现，一旦 reasoning、tool、answer 或其他 narrative item 排在其后即过滤。随后 `groupNarrativeByTurns()` 按 prompt 分组。该规则只改变 live presentation，不新增 wire event、不把占位写入 durable transcript，也不伪造 reasoning 文本；durable replay 没有 turn-start frame，因此不会恢复瞬时等待状态。第一个 prompt 前的恢复/系统 item 是 lead item，不伪造 turn。

## 5. Streaming item 生命周期

- 新 active item 到来时，旧 active item按适用状态 commit；
- trailing planning 与真实 thinking 复用同一 `AwakenThoughtTrace` 外观；initial planning 不展示自身 `Planning next moves` 文本，continuation planning 只展示确定性阶段 label，真实 reasoning 到达后才出现正文；
- text/reasoning delta 累积到稳定 message/run identity；同 message 的 durable `assistant_message` / `reasoning_summary` 是完整快照，回流时替换已经流式累积的正文，不能再次拼接造成重复；
- message end 或 terminal event把 active answer commit；
- `RUN_FINISHED` 把最新属于该 run 的 done answer 标为 `isFinal=true`；
- transport interruption 不调用 terminal error projector；
- cancellation 先 settle active item，再幂等追加 `hint:run-cancelled:<scope>`；尚未收到 canonical result 的 active tool/action 投影为 `cancelled`，不能伪装成 `done`；
- cancellation 遇到 active media generation时先把原卡片置为 `cancelled`，不得保留无限旋转的 loading态；
- late cancellation 不删除已经 commit 的 answer。

隐藏 chain-of-thought 不由 Workbench自行生成；只显示 runtime 经统一 LLM observer 明确发出的可展示 reasoning。Workbench 不认识 provider、model、`reasoning_content` 或 `thinking_delta`，也不得从 `provider_opaque_state` 补造历史。

## 6. Tool 投影与 pairing

`TOOL_CALL_ARGS_DELTA` 是 live transport 的 partial-JSON 帧，完整参数由 Core/LLM adapter 累积；Desktop reducer 和 narrative projector 对该帧保持 no-op，不保存 fragment、不创建临时 tool identity，也不触发重渲染。`TOOL_CALL_START` 只建立稳定 active identity，完整 `TOOL_CALL_ARGS` 一次性保存参数快照并只按已知类型派生安全摘要；`TOOL_CALL_END` 只结束参数 envelope，不能结束执行。工具终态只由 canonical `TOOL_CALL_RESULT` 决定。durable replay 本来只包含 START、完整 ARGS、END 与 RESULT，因此 live/replay 共用同一可见语义。

### 6.1 Read-only exploration

projector 把当前识别为 read-only 的 tool call 投影为 exploring action。action id 由 scoped tool call id 稳定生成，并另外保留 raw tool-call identity 关联 reducer 数据；完整 args、progress 和 result 更新同一 action，不制造重复行。partial args delta 不创建或更新 action。

中心只显示 title、status 和短 detail。`App.tsx` 从 `runtimeState.toolResults` 选取 command output/result 第一条非空行补 detail；完整数据仍留在 reducer，当前右侧 UI 未接线。`Read` 图片/PDF 的 Base64 不进入 AG-UI/Renderer；Desktop 历史卡片依赖持久化的 tool text/metadata，blob 缺失也不得导致卡片崩溃。

### 6.2 普通工具

非 read-only tool 使用 `tool` item。`toolStatus` 是 Outcome 的 canonical 状态，UI display state 不得靠 content 文本猜测。deny、transform、needs-auth、needs-runtime、unsupported、recovery-required 等状态按 04 域语义投影。

### 6.3 图片与视频生成

`image_generate` / `video_generate` 使用稳定的 `mediaGeneration` item，而不是普通 `tool` item。`TOOL_CALL_START` 建立一次 tool-call identity；完整 `TOOL_CALL_ARGS` 可把合法的 `mode=group,max_images=1..15` 派生为 2–15 张独立小卡，并从图片 `size` 或视频 `ratio` 解析占位宽高比。该数量只是请求上限，不是实际产物数。`AWAKEN_COMMAND_OUTPUT(commandStream=media_status)` 传递 `queued|generating|downloading|ready|partial|unknown`、短消息和可选 task ID/逐项状态；官方没有进度百分比时 UI 不伪造百分比。`TOOL_CALL_RESULT` 结合 canonical tool/transport status 与结构化 `generation_status/paths/items[]` 收口：全部完成为 ready，组图部分完成保留每个 index 的 ready/error 卡，视频轮询未得终态为 unknown“状态待确认”，不能显示成生成失败或继续无限转圈。为了忠实恢复已写入的旧记录，仅当旧结果同时包含可解析的 `status=succeeded` 与非空 `paths` 时，允许纠正旧 output schema 造成的错误 display status；该兼容不用于任意普通工具文本猜测。

媒体卡在 final answer 前实时显示。final 出现后，ready/partial/unknown/error/cancelled 等全部 `mediaGeneration` item 与媒体前后的 planning/thinking/普通工具/非最终 answer 一起进入同一个 execution-process disclosure；媒体不能成为分段边界，也不能因成功、失败或敏感内容拦截而留在最终结果区。媒体 item 自身在 generating 时自动展开；外层过程展开后，组图仍以一个 narrative item 和无卡片表面的布局容器排列 2–15 张独立 `AwakenMediaItemCard`。子项稳定位置由 tool call 与 `items[].index` 派生，真正的预览、打开和定位继续使用各自 Artifact identity 与 opaque media source。ready path 只用于与 Artifact event 配对；Renderer 不得从 tool result 路径拼 `file://`。历史记录不迁移，重放时按同一确定性分段规则恢复媒体执行明细，ready Artifact 的默认可见入口由终态交付列表承担。

### 6.4 通用 approval

新 run 不生成可交互 ApprovalCard。历史 `approval` item仍可从旧 transcript 重放，但只能显示标题、`Legacy approval record` 和只读状态。

`ask_user` 使用专用 reducer/UI，不属于 legacy approval item。消息发送没有专用 reducer、审核卡片或 approved/rejected 轨迹，只按普通 tool call/result 投影。

### 6.5 Memory 与 Dream 回执

`memory_recalled` / `memory_mutated` 由 03 域 SemanticJournal 耐久，09 域投影为 `AWAKEN_MEMORY_*` wire event；projector 按 `recordId` 稳定 upsert `memoryReceipt`，只展示数量、scope/type/revision、action 状态或错误码，不展示主题正文。

Dream task 不写入 thread SemanticJournal，也不伪装成 Core AG-UI/SSE wire event。Main 通过 typed bridge 推送 terminal task；Renderer 在 active thread 中实时收到回执时保存纯展示用的 `taskId -> threadId` 绑定，thread 加载时从 durable Dream task list 只挑选绑定到当前 thread 的终态，无绑定的旧任务不进入任意新线程。`App.tsx` 把 completed/failed/cancelled/interrupted 转为相同 projector 可消费的本地事件形状，projector 以 `taskId` 区分不同任务并幂等忽略同一任务的重复投递，再投影中文状态与 updated/superseded/conflicts 有界统计。展示绑定不是 task 状态 authority；该回执不创建新 turn、不进入右侧 Inspector，也不改变 prompt、follow、marker 或 composer ownership。

## 7. Execution process

`projectNarrativeTurnBodySegments()` 是当前过程折叠的唯一纯决策：

1. 找到第一个 `answer && isFinal === true`；
2. index `<=0` 时 turn body 保持一个 flat items segment；
3. index `>0` 时 final 前缀整体成为 `executionProcess:<turnId>`，包括全部 `mediaGeneration` item；
4. final answer 及其后缀成为 `answer-and-after:<turnId>`；
5. per-turn open state由 `App.tsx` 控制，默认 false。

因此过程在 final answer 标记前实时可见，终态后才折叠。禁止在 projector 中提前删除过程 item，或用 CSS 隐藏来代替可访问 disclosure。

## 8. Artifact 与 deliverables

artifact event 先进入 reducer 的 `artifacts`；run终态时 reducer把交付物汇总作为 turn 尾部 narrative item投影，live与replay走同一分支。具体资格、去重、排序、稳定 identity、terminal状态和安全打开只由 [最终交付物展示与安全打开](最终交付物展示与安全打开.md) 拥有，本文不重复算法。

## 9. Replay 幂等

优先使用 `semanticSeq ?? seq`。一个 semantic record 可能投影 START/CONTENT/END 多帧并共享 seq，因此 seen key 包含：

```text
scope + stableSeq + event.type + frame identity
```

frame identity优先 message/tool/approval/artifact/compact id。不能只按 seq 去重，否则会丢同一 semantic record 的合法多帧。

没有 seq 的 text、reasoning 和 tool progress 不生成粗粒度 seen key，避免误丢合法增量；tool args delta 不参与可见投影；其余无 seq event 使用 type/scope/id/content 组合。

`seenEventKeys` 只保留最近有界窗口（当前 projector 的 `MAX_SEEN_EVENTS`），不是持久化 journal 的替代品。

## 10. Thread view 与恢复

- 每个 thread 可在 reducer 的 `threadViews` 保存一份 runtime/narrative snapshot；
- 切线程前 scroll controller 清除旧 turn identity；
- `actionsForThreadTranscript()` 将 durable transcript 重放为 reducer action；
- 快速切线程由 load sequence 防止旧异步请求覆盖新选择；
- live reconnect 使用最后游标继续订阅，overlap 依赖 projector 幂等；
- terminal replay 恢复 done reasoning、final answer和 deliverables；
- pending 专用 gate按各自 event pair恢复；legacy approval只读；
- 非终态 stream close进入 reconnecting，不提交普通 failed answer。

当前限制：

- WorkBench 不持久化精确 scrollTop、prompt expanded 或 execution-process open state；重开只保证已耐久叙事的身份与内容，不保证像素级阅读位置。
- 修复前没有 `reasoning_summary` 的旧 run 只能恢复当时实际耐久的 prompt、工具与回答，不能从 provider 私有 opaque state 反向生成过程历史。
- 修复前的旧 v2 count-only 记录不含附件 identity/path 和 composer token，因此只能重放其可确认的文本；耐久来源只由 [03 SemanticJournal 与重放](../../03_运行时与本地服务/SemanticJournal与重放.md) 定义。

## 11. Inspector 数据与当前 UI 缺口

reducer 当前已保存：

- tool args/result/status；
- bounded command output + truncated flag；
- 通用 diff/patch preview相关字段；
- turn diff；
- artifacts；
- `inspectorSummary.lastToolDecision`；
- environment/tool snapshot ID、provider ID、capabilities、readiness、dependency observations 和 side-effect state；
- Skill invocation/resource/status/diagnostics；
- narrative `inspectorSelection`。

这些通用 tool/artifact 数据仍未接线，不等于右侧支持通用工具详情。原生 Subagent 是独立的已接线类型：`AWAKEN_SUBAGENT_*` 按 task ID upsert 到当前 turn 的 `subagentGroup`；带 `subagentTaskId` 的普通 reasoning/text/tool frame 进入 reducer-owned `SubagentTaskView.narrative`，不得修改 root 的 thinking/answer/tool records。点击 group row 后，中间区域从该独立 narrative 在 dock Composer 上方的 `RunStage.overlay` 渲染有界执行详情，详情不回流当前 turn；右侧 Inspector 也只消费同一 task truth。见 [原生 Subagent 产品与架构契约](../../02_主智能体闭环/原生Subagent产品与架构契约.md)。

## 12. 异常语义

| 事件/场景 | Narrative 处理 |
|---|---|
| `PROVIDER_AUTH_MISSING` | 清洗为模型 API key 提示 |
| `PROVIDER_REQUEST_FAILED` | 显示 provider 请求失败，不泄露 secret |
| 用户取消 | 保留内容、settle active、追加幂等 hint |
| stream interruption | recovery 状态，不生成 error answer |
| reconnect exhausted | terminal error answer + ready deliverables |
| tool failure | 同一 tool/action进入 error/blocked等 display state |
| duplicate replay | seen key / stable id upsert，不重复 |
