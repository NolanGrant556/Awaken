## 3. 协议静态检查

### 3.1 ToolOutcome

- [x] 仓库只有一个 canonical ExecutionOutcome 定义。
- [x] Status、TransportStatus、SemanticStatus、ProcessStatus、ErrorCategory 枚举与实施方案完全一致。
- [x] ToolExecutionResult 兼容字段由 outcome 派生，不存在反向推断。
- [x] Go error 只代表 transport 或 implementation 异常。
- [x] process nonzero、deny、needs_auth、needs_runtime、unsupported 均通过 outcome 表达。
- [x] ToolResult event 携带结构化状态、错误、重试、进程和耗时字段。
- [x] Anthropic 和 OpenAI provider 均保留失败语义。
- [x] Desktop 不通过 content、中文错误文本或字符串包含关系判断结果状态。

禁止项：

- [x] 不存在新增的第二套 IsError 业务判断。
- [x] 不存在把 exit_code=1 一律标记成功的逻辑。
- [x] 不存在 Runner 和 ToolRuntime 对同一次活动重复发通用进度。

### 3.2 SemanticJournal

- [x] v2 record 有 schema_version、kind、record_id、seq、parent_id。
- [x] user_message、每轮完整 assistant_message、tool_call、tool_result、artifact、file_change、turn_diff、turn_boundary、terminal 均为耐久记录。
- [x] stdout delta、spinner、token tick 没有被无差别永久写入。
- [x] tool_call 在副作用开始前成功落盘。
- [x] tool_result 与 artifacts 使用同一 AppendBatch。
- [x] applied file_change 与 tool_result/artifacts 同批提交；turn_diff 在 turn_boundary 前提交。
- [x] terminal flush 执行 file.Sync。
- [x] Append、Flush、Close 的 error 全部可达调用方。
- [x] agentcore.SemanticRecorder 是耐久写接口；EventSink 只在写成功后负责直播，不隐藏 journal 写入。
- [x] Runner 对 durable fact 的调用顺序固定为 SemanticRecorder 成功后再 EventSink。
- [x] 正式 StartRun 缺 recorder 返回 persistence_unavailable；noop recorder 不进入可执行副作用的产品路径。
- [x] journal 失败后 run fail-stop、停止新的副作用，并以 `persistence_error` terminal 明确结束；不存在虚构的 `persistence_degraded` 状态。

- [x] 不存在 Desktop 历史专用的字符串猜测 projector。
- [x] 不存在破坏性批量重写用户旧 transcript 的迁移脚本。

## 4. 自动化事故场景矩阵

每个场景必须在最低层单元测试和至少一条跨层集成测试中出现。

| 编号 | 输入或故障 | 必须断言的结果 |
|---|---|---|
| A01 | shell 执行明确 exit 7 | Status=failed，ProcessStatus=exited，ExitCode=7，ErrorCode=process_exit_nonzero；模型、事件和重放字段一致，UI 不得显示为 done 且须保留可见退出详情 |
| A02 | 单一 rg 查询无匹配 | Status=succeeded，SemanticStatus=neutral，Diagnostic.reason=no_match |
| A03 | 单一 diff 发现差异 | Status=succeeded，SemanticStatus=neutral，Diagnostic.reason=different |
| A04 | shell timeout | failed、timed_out、process_timeout，保留截断后的 stdout/stderr |
| A05 | shell spawn 失败 | TransportStatus=failed、ProcessStatus=spawn_failed |
| A06 | pip 或 npm install 命令 | 模型不口述也出现宿主 ToolActivity；参数经过去敏 |
| A07 | text_edit 唯一命中 | 修改成功、digest 更新、patch preview 与 artifact 生成 |
| A08 | text_edit 零命中 | text_not_found，文件不变 |
| A09 | text_edit 多命中 | text_not_unique，文件不变 |
| A10 | text_edit stale digest | stale_file_revision，文件不变 |
| A11 | text_edit replace_all=true | 仅显式请求时全部替换 |
| A12 | patch 缺 Begin Patch | patch_missing_begin，零副作用，recovery 指向 text_edit |
| A13 | patch hunk 缺前缀 | patch_invalid_line_prefix，零副作用 |
| A14 | patch context mismatch | 工具返回 patch_context_not_found，Supervisor 归一为 patch_context_mismatch，与语法错误区分 |
| A15 | exact non-retryable patch 重复 | 首次真实失败，第二次 ToolRetryBlocked，不执行工具 |
| A16 | retryable exact call 重复 | 最多执行两次，第三次阻断 |
| A17 | 参数变化但同资源同 error class | 最多真实失败三次，之后必须换策略 |
| A18 | 失败后重新读取新 revision | 允许使用新 call_signature 恢复 |
| A19 | 显式选中 Skill | 首次 LLM 前已有 activation plan、required receipts 和 effective pool |
| A20 | required resource 缺失 | 首次 LLM 请求前失败，不进入 Skill 任务 |
| A21 | Skill 未允许 shell | 模型看不到 shell；伪造直接调用也被 ToolRuntime 拒绝 |
| A22 | legacy PPT Skill 要求 pip/动态 Python | 返回 skill_platform_contract_conflict 并退出 Skill；不得自动路由，后续 typed tool 只能来自 Skill scope 外的新恢复规划 |
| A23 | presentation 参数嵌套错误 | validation error 带准确 JSON path |
| A24 | presentation 未支持/不兼容字段 | 带准确 JSON path 的结构化 validation_error，不静默丢字段 |
| A25 | 中文 PPT | 唯一 CJK helper，OOXML 校验通过，render 字体可见且不乱码 |
| A26 | Poppler 不可用 | needs_runtime 或 verified=false，不得假成功 |
| A27 | wrapper 存在但 target 消失 | RuntimeReady=false，报告 stale target |
| A28 | Codex cache 被删除 | Awaken known-good runtime 仍可用 |
| A29 | staging probe 失败 | current 保持上一 known-good |
| A30 | journal 在 tool_call 前写失败 | 工具不执行，run 以 persistence_error 终止 |
| A31 | journal 在 tool_result batch 写失败 | 停止后续副作用，并以明确的 `persistence_error` terminal 结束 |
| A32 | v1 message 有 tool_calls/result，无 tool event | adapter 恢复完整工具卡和结果 |
| A33 | v2 live 与 replay | 同一 fixture 投影出的语义 item 深度相等 |
| A34 | 最后一行 JSONL 截断 | 仅忽略 partial tail，前序记录完整恢复 |
| A35 | 中间一行损坏 | 明确报告损坏，不静默跳过导致错误顺序 |
| A36 | 取消发生在 tool call 后 | 保持合法 pairing 和 cancelled outcome |
| A37 | 进程在 tool_call 后、tool_result 前退出 | 重启后生成 synthetic interrupted outcome 和 process_restarted terminal，side_effect_state=unknown，不自动重执行 |

注：A20 的“缺失”不能被实现成自动联网下载 required resource；这是 Skill package 完整性错误。
