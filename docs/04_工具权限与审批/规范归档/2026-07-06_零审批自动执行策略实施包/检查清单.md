# Checklist

> 用于系统性验收。每项必须对照代码或真实运行证据勾选。

## Phase 1：文件链成为主路径

- [x] `TrashAdapter` 接口与 Mac/Windows 实现存在且有单测
- [x] `apply_patch` 删除路径调用 `TrashPath`，不再调用 `os.Remove`
- [x] 删除前经过敏感路径检查与 symlink 逃逸检查
- [x] 敏感路径集合覆盖 `.git/`、`.env`、密钥/证书/凭据、Agent 元数据目录、runtime 本地配置目录
- [x] 越界与敏感路径写入返回结构化拒绝结果（非崩溃、非静默）
- [x] `apply_patch` 在 workspace 内非敏感路径自动 allow，不弹审批 UI
- [ ] 通过 Desktop UI 完成文件增删改移动不需要任何审批点击（真实 smoke）

## Phase 2：shell 独立分级

- [x] `ShellTier` 三层分级（`inspect_read_only`/`workspace_mutation`/`open_world_system`）已实现
- [x] 命令分级分类器不再依赖硬编码 `safeReadOnlyCommandPaths` 作为主要安全手段
- [x] `AutoToolPolicy` 支持 `transform` 动作与 `UpdatedInput` 改写
- [x] shell 文件写入请求能 transform 到 `apply_patch`
- [x] `ShellExecutor` + `SandboxAdapter` 抽象存在，`shell` 工具经 executor 执行
- [x] 某平台缺失可信隔离时 fail-closed 或降级，不静默裸奔

## Phase 3：统一执行 profile

- [x] `ExecutionIntent` 类型存在并包含 spec 要求的全部字段
- [x] `ExecutionDecision` 支持 `allow`/`deny`/`transform` 三种动作
- [x] `AutoToolPolicy.Decide` 升级为产出 `ExecutionDecision`
- [x] `ExecutionProfile` 类型与 5 个内建 profile 存在
- [x] `AgentConfig`/`RunService` 携带 profile
- [x] `FileChainExecutor`/`ShellExecutor`/`McpExecutor`/`GuardianExecutor` 存在且 `ToolRuntime` 路由正确
- [x] Agent runtime 能输出稳定的决策来源

## Phase 4：多代理继承与 guardian 收紧

- [x] 普通 subagent 继承父代理的 workspace/profile/sandbox/network 边界
- [x] 普通 subagent 扩权被拒绝（单测覆盖）
- [x] guardian profile 固定为 `never`/`read_only`/`restricted`
- [x] guardian 写入工具调用被拒绝（单测覆盖）
- [x] 任一子代理无法绕过敏感路径保护与回收站删除语义

## Phase 5：双平台 shell 收口与观测层

- [x] Mac 与 Windows 共享同一套上层权限模型
- [x] 平台差异仅体现在 adapter 实现层
- [x] 不存在长期 mac/windows 平台主线分支
- [x] `ToolAuditRecord`/事件流包含 profile 命中、transform、deny、trash、subagent 继承字段
- [x] Desktop 展示：自动执行的工具调用、被拒绝的工具调用、transform 后的执行方式、文件改动列表、回收站提示、profile 摘要
- [x] 用户可随时停止 run（停止能力端到端可用）
- [x] UI 强调「系统已内置保护」，不强调「请你决定要不要继续」

## 跨阶段验收

- [x] 文件链无法写出 `workspace_root`/`writable_roots`
- [x] symlink 逃逸被拦截
- [x] 敏感路径默认拒绝
- [x] 删除默认进入回收站
- [x] Mac 与 Windows 对文件链行为一致
- [x] 某平台缺失 shell 沙箱时系统能明确降级而不静默裸奔
