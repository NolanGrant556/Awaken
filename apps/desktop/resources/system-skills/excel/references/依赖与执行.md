# Excel 依赖与执行

## Awaken 工具与路径合同

| 动作 | 工具 |
| --- | --- |
| Python、LibreOffice、转换和校验 | `Bash` |
| 安装依赖 | `load_workspace_dependencies({})`，复用完整办公包 |
| 读取脚本、CSV/TSV 和校验 JSON | `Read` |
| 修改数据处理脚本 | `Edit` / `Write` |
| 查找数据文件 | `Glob` / `Grep` |
| 发布最终交付物 | `artifact_publish`（交付新建／编辑文件时） |

- 包内脚本一律通过 `${AWAKEN_SKILL_DIR}` 的绝对路径调用。
- Windows 注入到正文的 Skill 路径使用 `C:/...` 形式，可同时作为 Git Bash、PowerShell、cmd 和 Python 参数；不要改回反斜杠路径再交给 POSIX Shell。
- 用户需要的最终表格必须位于当前任务工作区的 output root。
- 编辑用户原文件时默认输出新文件，不覆盖原件。
- Skill 已加载不代表 Python 包或 LibreOffice 已存在；以真实探测和执行结果为准。
- 用户在初始请求中点名表格输入、Excel 输出或跨表分析时，在任何相关 Bash、文件读取或 subagent 派发前加载本 Skill；子任务必须继承表头、类型、空值和分母检查边界。
- doctor 与所有 `--json` helper 必须作为独立命令执行，或放在 `&&` 链的末尾；禁止接 `| tail`、`| head`、`grep`、命令替换等会改变退出码或截断 JSON 的管道。
- 必须同时核对 Bash outcome 与完整 JSON `status`。wrapper 失败时不得改用裸 `soffice` 绕过独立 profile、超时、外链拒绝和原子替换合同。

## 整体准备，按任务路线验证

先通过 `tool_find` 取得 `load_workspace_dependencies`，以空对象 `{}` 调用，拿到完整办公包。生成语言、是否含公式以及是否需要视觉检查，都不改变基础包的安装内容。已有健康绑定直接复用；旧会话的既有引用保持原实例，新办公准备统一使用本入口。

每次 Bash 显式传入 `environment_ref`，使用返回的 Python/Node 绝对入口和启动参数，再运行 `${AWAKEN_SKILL_DIR}/scripts/doctor.py --route <route> --json`。PowerShell 用 `& "<python>"` 调用，其他 Shell 按实际规则引用中文和空格路径。Node 模块解析由固定启动器处理，不向当前项目写入 node_modules。

整包就绪后，doctor 仍按本次任务路线检查能力与输入；环境就绪、文件生成、结构校验、公式重算、页面检查和发布分别判断。doctor 的 `execution_plan` 必须与绑定一致；`--dependency-root` 仅用于用户明确选择的外部诊断，不决定安装目录。缺少整包资源时停止这条受管路线，不能改用细分安装或系统程序后宣称整体就绪。

Excel doctor 的 route 仍为 `read_quick`、`read_precise`、`clean`、`create_edit` 或 `recalc`；有公式且需要缓存结果时选择 `recalc`。这些是验证路线，不是安装能力参数。
