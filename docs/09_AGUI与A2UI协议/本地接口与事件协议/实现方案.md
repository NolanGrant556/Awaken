# 本地接口与事件协议 · 实现方案

本文说明代码职责、数据与接口、异常恢复和验证方法。功能范围及用户操作见[需求文档](需求文档.md)。

## 内部与 wire 职责

| 层 | owner | 约束 |
| --- | --- | --- |
| Agent/Tool | `src/agentcore`、`src/tool` | 产生 canonical outcome、provider/snapshot/Skill 事实 |
| Journal | `src/runtime` | append-before-side-effect、耐久 kind 和恢复 |
| AG-UI | `src/protocol/agui` | 唯一 wire event/tags/semantic projection |
| Desktop | shared type + reducer/projector | 消费，不发明缺失事实 |

MCP wire、Connector definition 和 Skill frontmatter 不是 AG-UI schema；它们只能通过运行时标准化结果进入 AG-UI。

MCP artifact output 的 base64 bytes/hash/path-field mapping 也不是 AG-UI schema。bytes 由 host adapter 消费，只有 Workspace broker 已提交并复核后的 canonical ArtifactDescriptor/change/receipt 能投影；provider-local path、失败结果或未验证 bytes 不得产生 artifact event。

`POST /v1/runs` 的 `workspace` 对象即 TaskScope wire。`workspace_root` 是已绑定项目的主文件夹；只给 `project_id` 表示零文件夹项目；两者都为空表示独立对话。Core 在规范化 workspace 前确定 thread ID：新对话生成 ID，follow-up 使用请求的 `thread_id`，然后解析到 thread 专属 session 工作目录。业务数据根不可用或 managed owner ID 不安全时返回 `INVALID_INPUT`。项目 run 的 `project_name` 使用当前 project authority 的最新 `display_name`，只用于让模型说得出自己在哪个项目里；Core 不从它解析路径、权限或身份，名称变化使后续 run 重建上下文。`session_workspace` 由服务端派生并回写，客户端传入值一律被覆盖。roots 的语义与形状名单由 [TaskScope 与路径安全](../../04_工具权限与审批/文件操作与路径安全/实现方案.md) 唯一拥有。

`GET /v1/instructions/global` 返回 `GlobalAgentsDocument{exists,revision,digest,content,byte_count,updated_at,max_bytes}`。`PUT /v1/instructions/global` 接受 `{expected_revision,content}`，`DELETE` 接受 `{expected_revision}`；revision 不匹配返回 409 `INSTRUCTION_REVISION_CONFLICT`。三条 route 只在 RunService 存在时注册。Renderer 不可通过 `POST /v1/runs` 提交 AGENTS 正文或路径。业务优先级、截断与恢复见 [02 AGENTS 指令与运行快照](../../02_主智能体闭环/规则指令/实现方案.md)。

`POST /v1/threads/batch-delete` 接受 `{"thread_ids":[...]}`，最多 200 个非空 thread ID，按首次出现顺序去重。响应始终区分 `deleted_thread_ids` 与 `failures[{thread_id,error,message}]`；逐项复用单条 durable delete，当前 active thread 以 `THREAD_BUSY` 留在失败集合。该 route 不承诺跨 session 原子性，Desktop 只能移除 `deleted_thread_ids`，不得把失败项乐观隐藏。

`POST /v1/threads/{thread_id}/rewind` 接受 `target_run_id + expected_head_run_id`，成功返回更新后的 `thread`、改写前 canonical `target_run` 与 `removed_run_ids`。它只改写 SemanticJournal v2 普通会话的 active lineage，不回滚工具副作用；busy、stale head、旧 transcript 与特殊会话的错误码和 Desktop 恢复行为只见 [01 用户消息撤销与编辑](../../01_桌面工作台/消息输入与编辑/实现方案.md)。

`/v1/shutdown` 只有注入 shutdown callback 才注册。`GET /v1/runtime/activity` 无条件注册、`RunService` 缺席时返回 503，只读返回 `{active_run_count, cancelling_run_count, observed_at}`（RFC3339 UTC）：`active_run_count` 统计当前 in-flight run（含正在取消的 run；普通、定时与 ACP run 都经 `RunService.StartRun`，统一计入），`cancelling_run_count` 是其中已进入 cancelling 状态的子集。其用途是 Electron Main 在退出/维护类操作（如更新重启）前读取运行时活动快照；Renderer 不直接调用。`/audit` 当前返回空数组，查询链尚未接通；其审计语义由 04 域记录。`POST /v1/threads/{thread_id}/context-snapshot` 接收与 run 相同的 `model_profile`，只重建并耐久化该 thread 的当前下一请求 projection；不发 provider 请求，响应为 204。Desktop 在 GET transcript 前调用它；没有可运行 profile 时直接读取历史 transcript。active lineage 为空时同样 204，不报错、不追加 snapshot。

Hook routes 只有 `RunService` 注入时注册，业务合同由 [Hook 产品与架构契约](../../04_工具权限与审批/钩子/实现方案.md)拥有。GET 的 Settings 检查 DTO 返回 snapshot identity、enabled count、来源 receipt/诊断，以及 Core 严格解析和归一化后的静态 Hook 详情；详情可以包含命令 argv、URL、matcher 或 prompt 供当前用户在信任前审查，但不包含 secret 引用值、运行输入、环境或输出，也不进入 run snapshot/Journal。trust 绑定 `projectId + canonical sourcePath + digest`，revoke 绑定 project/source，均只影响后续 run。run 内 `hook_invocation_started/completed` 分别投影为 `AWAKEN_HOOK_STARTED/COMPLETED`；wire 只含 invocation/Hook/event/source identity、status/action/reason、duration 与有界 preview，不含 command、配置路径、输入正文、secret env 或完整 stdout/stderr。

Subagent list/detail/cancel/message route 只操作请求 run 的当前 task registry；run/task 不匹配返回 404。message body 只接受 `{content, idempotency_key}`，先耐久再入队；终态 task 返回 409 `subagent_not_running`。`POST /v1/threads/{thread_id}/agents/stop` 只取消该会话活动子任务并通知主 Agent，不取消 root run；停止主执行走 `POST /v1/runs/{run_id}/cancel`。完整状态、取消和恢复边界见 [02 原生 Subagent 产品与架构契约](../../02_主智能体闭环/子智能体协作/实现方案.md)。

外部交互 resolve 接受 `resolution=completed|cancelled|expired|failed` 和可选 `content`。`content` 只用于把 MCP form 答案交还当前 run 中正在等待的协议调用，不进入 resolved AG-UI event 或 Journal；普通外部授权不提交该字段。`external_interaction_requested` 对 MCP 表单携带 `interactionKind="mcp-elicitation"` 与 `interactionFormSchema`，schema 只描述输入控件，不携带用户填写值。不存在、已终态或已解析的 interaction 分别按当前 handler 返回 404/409，Renderer 不得乐观移除失败项。

plugin list/get DTO 另固定返回 `builtin:boolean` 与 `builtinOrder:number`，可选返回受控 `brandIcon`；它们只由发布内置目录同步产生，不能由 install request 或普通插件 manifest 声明。内置插件的普通 install/replace、DELETE、commit 和 MCP source mutation 返回 409 `BUILTIN_PLUGIN_IMMUTABLE`，enable/disable 与 setup mutation仍使用原有 route。

`GET /v1/composer-catalog/events` 是 Main 常驻消费的 SSE 失效流。每次连接先发送当前 `{revision, kind:"snapshot"}`；Skill Registry 或 Plugin Store 的成功 catalog mutation 使 revision 单调递增并发送 `kind=skills|plugins`。事件不携带 Skill/Plugin 数据、路径或配置，Renderer 收到后只能通过 typed `listSkills/listPlugins` 按当前 workspace 与 marker 重读权威目录；重新连接不回放历史 mutation，因为 snapshot revision 与每次打开直接重读共同保证当前状态。

## SSE wire

`GET /v1/runs/{run_id}/events` 返回 `text/event-stream`。每个 frame：

```text
id: <stream cursor>
data: <one JSON Event>

```

encoder 优先用 `streamCursor` 生成 `id:`，为零时回退到 `seq`。每个 data 行是独立事件，consumer 不应把多个 reasoning/tool frames 当作一个 JSON 对象。

## Cursor 与重放

当前查询参数：

- `after_cursor=<n>`：正式续传参数；
- `after_seq=<n>`：兼容旧 Desktop 的同义 transport watermark。

两者当前都按“最后已确认的 frame cursor”解释，而不是 SemanticRecord 序号。server 先以 `cursor / 16` 做 coarse EventBus 过滤，再在展开帧后精确丢弃 `cursor <= afterCursor` 的帧。

帧序号公式：

```text
frame cursor = runtime/semantic event sequence * 16 + frame sub-index
```

16 是当前 `agui.FrameSeqStride`。一条记录可产生多帧；重连在其中一帧之后时必须保留同一记录尚未确认的后续帧。`SSE id`、`streamCursor` 和 active `seq` 保持兼容一致；耐久 frame 同时携带 `semanticSeq`。

## Live 与 transcript 一致性

订阅先输出历史，再接 active channel。run 执行期间“transcript snapshot + after_cursor SSE”必须做到每个文本、工具、terminal 和 `AWAKEN_INSTRUCTION_SNAPSHOT` frame 恰好一次。live 与重放都通过同一 semantic projector；任何只修 live mapper、不修 journal projector 的变化都不完整。唯一例外是 live-only `AWAKEN_PROVIDER_RECONNECT`：它不在 transcript snapshot 中，重连订阅后只能靠后续 live 帧恢复，不得从 journal 补造。

用户 prompt 从 run metadata 重建，不由 SemanticKindUserMessage 产生重复 AG-UI frame。terminal、artifact、tool pairing 也必须按相同 record identity 去重。

## 错误与恢复

- 无效 cursor 按 0 处理；consumer 应保存最近成功处理的 `id`。
- run 不存在返回 404；建立 stream 后客户端断开由 request context 终止订阅。
- runtime 重启后的耐久恢复通过 transcript/projector，不保证恢复进程内 active channel。
- Desktop SSE 客户端在 run 未收到 `RUN_FINISHED`/`RUN_ERROR` 前持续重连，退避上限 10 秒；只有 `run_not_found`/404 才把订阅收成失败。这与 02 域的 provider 网络等待/流重试不是同一条链。
- 未知事件仍可通过 `AWAKEN_UNKNOWN_EVENT` 传输；不得中止整个 stream。

## 权威

Go `src/protocol/agui/events.go` 的 `Event` 与 JSON tags 是 wire authority；`src/protocol/agui/semantic_projector.go` 是 live/replay 共用投影。TypeScript `apps/desktop/src/shared/agui.ts` 必须同步，但不能反向定义 Go wire。本文按语义组列字段，不维护容易漂移的“全部 N 个 tag”副本。

## Event family

当前 family 包括：

- run/turn/text/reasoning/tool call/progress/result；
- permission decision、command output、patch/diff；
- context estimate/warning/block/compact；
- auth 与通用 provider dependency/runtime missing 兼容事件；固定办公环境沿用 runtime prepare/ready/failed 状态投影；
- Skill：`AWAKEN_SKILL_DISCOVERED`、`AWAKEN_SKILL_INVOKED`、`AWAKEN_SKILL_CONTENT_LOADED`、`AWAKEN_SKILL_EXECUTION_CONTEXT`、`AWAKEN_SKILL_FAILED_TO_LOAD`；
- `AWAKEN_USER_QUESTION_REQUESTED/RESOLVED`；
- 原生 Subagent：`AWAKEN_SUBAGENT_CHANGED`、`AWAKEN_SUBAGENT_ACTIVITY`、`AWAKEN_SUBAGENT_MESSAGE_QUEUED`；当前产品会产生 lifecycle/activity，message event 为后续兼容字段；
- 深度研究阶段：`AWAKEN_RESEARCH_PHASE`（`researchPhase` 为 `accepted` / `investigating` / `terminal`，以及 `researchRevision`）；业务语义由 [16 深度研究](../../../README.md#16_深度研究) 拥有，Desktop 叙事当前不投影为独立 item。旧四阶段计数字段仅用于历史回放，新产品路径不再填写；
- Memory：`AWAKEN_MEMORY_RECALLED`、`AWAKEN_MEMORY_CREATED`、`AWAKEN_MEMORY_UPDATED`、`AWAKEN_MEMORY_SUPERSEDED`、`AWAKEN_MEMORY_DELETED`、`AWAKEN_MEMORY_REJECTED`；
- 当前下一请求分类快照 `AWAKEN_CONTEXT_SNAPSHOT` 与逐请求 provider 真相 `AWAKEN_MODEL_USAGE`；
- run-scoped AGENTS 安全摘要 `AWAKEN_INSTRUCTION_SNAPSHOT`；
- ACP Client：`AWAKEN_ACP_SESSION_CHANGED`（status=started/closed/interrupted）、`AWAKEN_ACP_TURN_CHANGED`（status=started/finished）、`AWAKEN_ACP_TOOL_CHANGED`、`AWAKEN_ACP_PERMISSION_REQUESTED`、`AWAKEN_ACP_PERMISSION_RESOLVED`；
- Computer Use 控制投影：`AWAKEN_COMPUTER_REVIEW_REQUESTED`、`AWAKEN_COMPUTER_REVIEW_RESOLVED`、`AWAKEN_COMPUTER_HANDOFF_STARTED`、`AWAKEN_COMPUTER_HANDOFF_ENDED`、`AWAKEN_COMPUTER_POINTER_HINT`；前四者来自 Computer SemanticJournal 事实，只承载稳定 ID、摘要、decision 与受控 evidence refs，不携带截图 bytes、Host handle 或控制凭据。`AWAKEN_COMPUTER_POINTER_HINT` 由 `computer_action_started` 投影，只携带视觉用屏幕 DIP 坐标（`computerPointerX/Y`、可选 `computerPointerToX/Y`、`computerPointerKind`、`computerPointerSpace`）；`0` 是合法边缘坐标。Workbench Renderer 必须 no-op，只有 Desktop Main overlay 消费它来移动虚拟鼠标；它不授予输入权限，也不能替代 action digest / fence / checked perform。
- live-only 供应商重连：`AWAKEN_PROVIDER_RECONNECT`；
- artifact、tool recovery/retry-blocked、unknown。

tool call family 中，`TOOL_CALL_ARGS_DELTA` 是 live transport 的临时 partial-JSON frame，不写入 SemanticJournal，也不在 durable replay 中重建；`TOOL_CALL_ARGS` 才是完整参数快照。Core 只对名称精确匹配内置 `Write`/`Edit` 的流式参数做常量内存扫描，并在同一 delta frame 附加 `toolPreparationKind`、仅 basename 的 `toolPreparationPath`、`toolPreparationAddedLines` 与 `toolPreparationDeletedLines`。Renderer 只能用这四个派生字段更新同一 `toolCallId` 的 live active Tool 行，不得读取或投影 `delta` 正文，不得创建 step/tool record 或可展开“工具输出”；缺少合法 kind/name 配对时保持 no-op。Write 准备态只统计正在生成的新内容行，Edit 分别统计 `new_string`/`old_string` 行，均是执行前估算；存在 canonical patch 时最终增删行数以 patch 为准。`TOOL_CALL_END` 只关闭参数 envelope，canonical `TOOL_CALL_RESULT` 才拥有执行终态。

`AWAKEN_USER_QUESTION_RESOLVED` 使用 `questionResolution=answered|cancelled`。answered 必须同时携带非空 `questionAnswer`；cancelled 不携带答案，只关闭当前 question gate，不改变 run 状态。两种 resolution 都保持原 `questionId/toolCallId` identity；迟到 resolution 不得复活已终态 run。

`TOOL_PROGRESS` 只表达 stage/message/percentage，不携带或推断 canonical `toolStatus`。即使 runtime 已在内存得到结果，progress=`completed` 也不能让 Renderer提前把工具判成 succeeded；只有随后耐久的 `TOOL_CALL_RESULT` 能设置终态。

ACP 事件承载 `diagnostic` 中的 `runner_id`、`acp_session_id`、`acp_turn_id` 等净化元数据；`AWAKEN_ACP_TOOL_CHANGED` 使用 `toolCallId` 指向宿主 `delegate_external_agent` 调用，`toolCallName` 为外部 Agent 工具 kind，`content`/`message` 为净化 summary；`AWAKEN_ACP_PERMISSION_REQUESTED/RESOLVED` 使用 `interactionId` 与 ACP permission route 对应。详细实现与边界见 [ACP 智能体协作设计与实施方案：事件、Journal 与 Desktop 投影](../../02_主智能体闭环/ACP协作/实现方案.md#事件journal-与-desktop-投影)。

新 run 不发通用 Approval event，Go wire、TypeScript shared type 与 Desktop reducer 都不再保留交互审批字段。旧 transcript 中的审批类未知字段由通用 legacy card/unknown projection 只读容错，不恢复为可操作审批。

旧 `AWAKEN_CONTEXT_ESTIMATED/WARNING/BLOCKED` 继续承担 aggregate 阈值和 compact 状态；`AWAKEN_CONTEXT_SNAPSHOT.contextUsageSnapshot` 另带 schema/snapshot/estimator/basis、model/protocol/request digest、window/reserve/threshold、`estimatedInputTokens` 和 typed `contributions[]`。`AWAKEN_COMPACT_FINISHED/FAILED` 的结构化诊断另带 target、压前/压后、mandatory floor、本地/保守投影、compact budget `contributionTokens`、native attempted/used/reason 与失败 reason；字段不携带 encrypted compaction item、provider opaque 正文或请求 body。`AWAKEN_MODEL_USAGE.modelUsage` 带 request/purpose/provider/profile/credential/model/endpoint/cache/retry、`sentEstimatedInputTokens`、nullable input/cached/uncached/write/output/total、raw typed usage、pricing/cost、provider request ID、latency 和终态。Desktop 当前总输入直接使用兼容主请求的 inclusive input；发送时估算只用于 Core 把后续本地变化量叠加到 provider total/input 锚点，执行保守 warning/auto-compact/block。旧 model usage 回放缺该字段时，批量 projector 可按 request ID 从不出 frame 的耐久 `model_request.estimated_input_tokens` 恢复。两种 authority 仍不能互相覆盖，详见 [02 提示词缓存、上下文用量与成本治理](../../02_主智能体闭环/上下文与用量/实现方案.md)。

`model_request` 不生成 wire frame；Renderer 由独立 `context_snapshot` 更新。`context_snapshot` 是 thread-scoped 的最新下一请求状态：回放跨越 run 边界时只有后一个合法快照才能替换前值，单纯的 `RUN_STARTED/RUN_FINISHED/RUN_ERROR` 不得清空它。`reasoning_summary` 投影完整的 `REASONING_START -> REASONING_MESSAGE_START -> REASONING_MESSAGE_CONTENT -> REASONING_MESSAGE_END -> REASONING_END` 生命周期，字段只来自统一展示语义，不携带 provider/model 格式。Chat 的 `reasoning_content/reasoning_details/<think>`、Responses reasoning events 和 Messages thinking blocks 必须在 LLM adapter 内先归一化，Renderer 不按 provider 分支。`context_epoch` 和 `provider_opaque_state` 是本地耐久 authority，projector 必须返回空，不得把 baseline、source/path、cache key 或 provider 私有 reasoning 投影到 AG-UI、Renderer、Memory 或 telemetry。

`instruction_snapshot` 投影为单帧 `AWAKEN_INSTRUCTION_SNAPSHOT.instructionSnapshot`。字段固定为 `snapshotId/capturedAt/partial/sources[]/diagnostics[]`；source 只含 `scope/displayPath/scopeRoot/digest/originalBytes/appliedBytes/truncated/status`。该事件可在 start response 后 live 到达，也可经 SSE cursor 和 transcript 重放恢复；不含 AGENTS 正文、模型 prefix 或凭据。

`AWAKEN_PROVIDER_RECONNECT` 只由 live mapper 从 Agent `ProviderReconnect` 发出，不进入 SemanticJournal，durable semantic projector 不得补造。字段只在 `providerReconnect` 对象：`phase` 为 `waiting_for_network` | `reconnecting` | `recovered`，`attempt`，`maxAttempts`（`0` 表示无限等待网络），去敏 `detail`（不含 URL/host/secret），以及 `resetInProgress`。它不是 run 终态，也不把 Desktop `phase` 改成 SSE 用的 `reconnecting`。`resetInProgress=true` 时 Renderer 丢弃当前未耐久 thinking/answer 和尚未执行的 active tool/exploring 并恢复 planning；`recovered` 只清除 live 重连行。Desktop 把它投影为当前执行游标上的 `providerReconnect` narrative item，见 [叙事投影与重放](../../01_桌面工作台/工作台布局与运行展示/实现方案.md)。重试政策由 [02 运行终止与失败编排](../../02_主智能体闭环/对话运行与恢复/实现方案.md) 拥有。

## 公共顺序与身份

公共字段包括 `seq`、`streamCursor`、`semanticSeq`、`recordId`、timestamp、thread/run/turn/query-chain identity 和 parent IDs。

- `streamCursor` 是 live transport resume cursor；
- `SemanticRecord.seq` 经 `FrameSeq` 映射为每个 durable record 的一个或多个稳定 frame seq；
- live 与 replay 必须得到相同语义 frames；
- user message 从 run metadata/结构化 transcript 恢复，不额外产生 AG-UI frame。
- live reasoning delta 与 durable `reasoning_summary` 使用同一 message identity；active transcript 中 durable snapshot 取代同 message 的 ephemeral delta，重启 replay 只需读取 durable lifecycle。
- 原生 child 的 live text/reasoning/tool frame（包括 ToolRuntime 即时 progress、command output、patch 和交互事件）与 durable 对应 frame都携带 `subagentTaskId`、`subagentAgentId`、`subagentParentAgentId`；所有即时帧必须先经过 run-scoped identity sink 再进入 SSE。Renderer 必须按 task 路由到独立 child narrative，不能先写 root 再依靠 replay 修正；缺少既有 root tool-call identity 的孤立 progress/output 不得创建 root 工具。

## 工具与 provider 字段

tool result/recovery 当前投影：

- `toolStatus`、`transportStatus`、`semanticStatus`、`processStatus`、exit/timedOut；
- error code/category、retryable、recovery options、duration、diagnostic；
- `environmentSnapshotId`、`toolAvailabilitySnapshotId`；
- `providerId`、`providerSource`、`capability`/`capabilities`、`readiness`；
- `dependency`/`dependencies`，其中 observation 可含 host-generated `candidate_install_plans`；
- `sideEffectState`、affected/trashed paths。

这些字段来自运行时固定快照和 canonical Outcome，不由 renderer 猜测。`providerSource` 保留 `builtin|mcp|connector|skill|plugin|runtime_provider` 等 ProviderManifest 来源，使中心轨迹能区分 MCP/Connector，而不根据 tool name 或 provider id 猜测。Desktop reducer 已保留这些元数据；右侧 Inspector 尚未消费完整详情。

MCP host-mediated artifact 不新增 provider 私有 wire event。provider base64 bytes 只在 adapter 内存中接受与校验，必须在进入 Outcome、journal、model payload 和 AG-UI 前被消费/替换；下游只收到现有 canonical artifact event/tool result 中的 ArtifactDescriptor、providerId、sideEffectState、affected paths、observed changes 和 broker receipt diagnostic。artifact event 不能据此声称视觉或语义质量已验证。

`AWAKEN_ARTIFACT_CREATED/UPDATED` 在既有 Artifact identity、role/status/path 之外可携带 `artifactGroupId` 与正整数 `artifactGroupIndex`。两字段来自 canonical `ArtifactDescriptor.group_id/group_index`，只表达媒体组及组内稳定位置；live mapper 与 durable semantic projector 必须同值投影。缺失时按旧 Artifact 顺序兼容，Renderer 不得从 title、文件名或 tool call 文案补造分组。

`Read` 的 `model_content` 也不把 Base64 暴露给 AG-UI。Journal 与 compact record 只保存 `storage_key`、MIME、display name、byte size 和 page 等可水合元数据；provider request 在内存水合 blob，缺失时追加 `tool_media_blob_missing` 警告并保持历史工具卡片可回放。

超过 32 KiB 的文本 tool result 同样不把完整正文送入 AG-UI；tool result 只投影首次 admission 已固化的 digest、byte size、stable preview/storage key 语义。blob key 使用 `thread/task-or-agent/run/turn/tool-call` 复合命名空间，避免 root/child、不同 run/turn 的同名 provider tool-call ID 覆盖。Renderer 不能从 storage key 读取完整 blob 或在 replay 时重新截断；下一次 provider request 由 Core 在内存校验 thread ownership、byte size 与 digest 后水合完整正文（包括 canonical Outcome JSON envelope 内的 `content`）。

Subagent lifecycle/activity 的公共计数字段是 `subagentToolUseCount`、兼容的 `subagentEstimatedTokens`，以及 provider-reported `subagentInputTokens`、`subagentOutputTokens`、`subagentTotalTokens`；时间字段使用 `subagentCreatedAt/StartedAt/FinishedAt`。这些值来自 manager 在对应 child `tool_call`/`model_usage` 耐久后的去重累计，Renderer 只能显示和用时间戳计算耗时，不能扫描 child 文案或 root tool rows 补算。

## Skill 字段与 durable projection

Skill 字段包括 ID/version/source/path/status、resource/source/SHA256/size/mode、effective tools 和 diagnostics。

当前 durable 映射：

- `skill_activated` -> `AWAKEN_SKILL_INVOKED`，成功时再投影 `AWAKEN_SKILL_EXECUTION_CONTEXT`；projector 对旧/兼容的 non-ok activation payload 可投影 `FAILED_TO_LOAD`，但当前新失败不会写伪 `skill_activated`；
- `resource_receipt` -> `AWAKEN_SKILL_CONTENT_LOADED`；
- mapper/type 层定义了 discovery 与 load-failure event，但当前 production failure 的 durable truth 是 tool error 或 run terminal/diagnostic，没有独立 Skill failure SemanticKind，也不能保证每次失败都会额外收到 `AWAKEN_SKILL_FAILED_TO_LOAD`；
- Desktop reducer 按 Skill ID 累积状态/诊断，narrative 仅展示与当前 run 相关的调用轨迹。

`skillEffectiveTools` 是兼容/审计提示，不代表 Skill 收窄了父 run 工具快照。

## Memory 字段与 Dream 本地投影

Memory wire event 的 `memories[]` 只包含 `memoryId`、`scope`、`memoryType`、`revision`、可选 `bytes/action/status/errorCode`。`memory_recalled` 与 `memory_mutated` 的 live mapper 和 durable semantic projector 必须生成相同事件类型与无正文 receipt；主题 name/description/content 不进入 AG-UI。只有 create/update/supersede/delete 才可产生 `memory_mutated`；search/get 的失败不能伪造成 rejected mutation。Renderer 以 typed mutation receipt 为同一 tool call 的唯一主要展示，automatic recall 使用独立 record identity。

Dream terminal task 不属于 Go `Event` 或 SSE family。Desktop shared consumer union 额外保留 `AWAKEN_MEMORY_DREAM_COMPLETED/FAILED/CANCELLED/INTERRUPTED`，只用于 typed Main bridge 和 durable task list 在 Renderer 内复用 narrative projector；这四个本地事件标签不得被描述为 Core wire parity，也不得写入 thread SemanticJournal。

## Scheduled notice 字段

`scheduled_notice` 语义记录投影为 `AWAKEN_SCHEDULED_NOTICE`，字段包括 `taskId`、`executionId`、`taskName`、`noticeContent`，payload 仅含任务/执行 identity、任务名和固定提醒正文。该事件 live（SSE）与 replay（transcript）同投影，不伪装成 user/assistant 消息；Renderer narrative projector 以“定时提醒”卡展示。

## Tool permission 字段

`AWAKEN_TOOL_PERMISSION_DECIDED` 记录 static behavior/reason、decision action/source/reason、profile、transform from/to、affected paths、patch summary 和 guardian violation。它表达 allow/deny/transform/auth/runtime/unsupported 等自动策略，不表达通用人工审批或消息审核。

## Auth URL parity

Go wire、TypeScript `AguiEvent`、runtime reducer 和 narrative projector 当前统一使用 canonical `authUrl`；reducer projection test 锁定该字段。新增字段仍应先改 Go contract/mapper test，再同步 TS/reducer/projector，不能在 renderer 建私有别名。

## 自动化

- Go `Event` JSON tags 与 mapper/projector golden；
- live/replay 对相同 SemanticRecord 生成同 frames/seq；
- tool snapshot/provider/readiness/dependency/side-effect 字段端到端；
- 五种 Skill event、activation/resource durable projection；
- Memory recall/mutation 的 live/replay 同类型、同 identity 且 `memories[]` 不含主题正文；Dream terminal 只通过 typed Desktop bridge/task list形成 Renderer 本地投影，不冒充 Core SSE frame；
- 消息工具不会产生 review requested/resolved event 或专用字段；
- unknown event 保留 raw type，不让 consumer 崩溃；

## thread 活动与 child 身份

root run SSE 仍在主执行终态关闭；thread activity SSE 持续承载子任务事件，使用独立 activity_cursor。客户端以 semantic record identity/sourceEventId 去重，不能把 root cursor 用于 activity。活动历史过期返回 ACTIVITY_CURSOR_EXPIRED，客户端重载 canonical transcript。

child 的文本、工具、计划、上下文、用量和 gate 帧必须携带 subagentTaskId/subagentAgentId。生命周期额外携带 attempt、模型/effort、路由来源、配置 revision、background、context mode 和 closed。RunPhase 的等待状态不新增主模型轮次。主回复终态不清除其他 child 的有效问题或复核；答复和控制按原 run/问题身份路由。完整协作状态语义由[子智能体协作](../../02_主智能体闭环/子智能体协作/实现方案.md)负责。

子 Agent 直接对话的 messages/followup/close HTTP 路由已移除，旧调用返回 404。Desktop 同步移除对应 typed IPC 和 bridge。内部协作与上下文恢复仍由[子智能体协作](../../02_主智能体闭环/子智能体协作/实现方案.md)管理，单任务取消、停止全部子任务、活动流和专用授权接口保留。

Renderer 的 run 流与 thread 活动流共用 `runtime/reconnecting-subscription.ts`，统一游标推进、指数退避、连接代次校验和取消清理。run 终态停止重连，活动流继续接收子任务状态与收尾事件；`RUN_NOT_FOUND` 与 `ACTIVITY_CURSOR_EXPIRED` 仍交给各自的恢复策略。旧连接迟到事件或订阅 ID 不得覆盖新连接。

Computer 子任务交互使用事件原 `runId` 与子任务 `taskId` 投影。`POST /v1/control/computer/sessions/{run_id}/return` 的 JSON body 可携带 `session_id`，当前 Desktop 交还控件传原会话 ID；Core 同时核对 run 与会话，已失效的目标不得回退到当前租约持有者。未提供该字段的旧控制调用保持兼容。资源和状态清理规则见[Computer 实现方案](../../10_计算机操作能力/桌面观察与操作/实现方案.md#子任务的资源与控制归属)。

## 共享依赖与执行路径

AWAKEN_RUNTIME_* 增加可选 `runtimeOperationId`、`runtimePrepareStatus`、`runtimeComponent`、`runtimeDownloadedBytes`、`runtimeTotalBytes`、`runtimeInstallCount`、`runtimeDownloadCount`。SemanticJournal 保存对应 snake_case 字段和 Agent/task 身份，投影时恢复；旧事件缺少这些字段继续兼容。`TestManagedEnvironmentProgressPreservesWaiterScopeInReplay` 检查 live/replay 与两个等待者身份。目录、来源、安装和回收规则见[共享环境实现](../../03_运行时与本地服务/依赖与路径管理/实现方案.md)。

环境宿主控制接口全部位于鉴权通路：`GET /v1/control/environments` 返回目录和操作，`POST /v1/control/environments/prepare` 接受严格的共享请求并返回 progress/ready/error NDJSON；连接中断只取消当前等待者。`POST /v1/control/environments/host-leases` 接受宿主 executable、PID 和可选 removal_token，返回 opaque reference；同路径 `DELETE /{reference}` 释放。`POST /v1/control/environments/components/{component}/removal` 接受 Main PID，返回卸载令牌；对应 DELETE 使用 `X-Awaken-Removal-Token` 释放预约。`GET /v1/control/environments/components/{component}` 仅接受已支持的 CLI provider，返回 `{installation: null | {executablePath, version, healthy}}`；读取可恢复历史归属，不下载或执行程序。原独立 GET removal 预检已移除，统一由 POST removal 预约检查；组件 DELETE 使用同一令牌执行受管删除。字段不进入模型工具，Renderer 不取得令牌或自行创建使用者身份。

办公管理增加 authenticated control 的 `GET /v1/control/environments/office` 及 `POST /office/prepare`、`POST /office/repair`。prepare 接受空对象，repair 接受当前实例比较标识；返回 progress/ready/error NDJSON。取消由请求断开表达，作用于单个等待者。Main 通过主窗口和主 frame 校验的 typed IPC 调用，Renderer 不接触 token 或 executable。请求字段、状态与修复切换由[依赖与路径管理](../../03_运行时与本地服务/依赖与路径管理/实现方案.md#desktop-办公环境管理)定义；这些管理动作不重放会话。 状态附带 `runtimes`（Python/Node.js 的 `id/state/version`），由 Core 独立检查后返回；不向 Renderer 暴露启动路径。
