# 凭据存储与恢复 · 实现方案

本文说明代码职责、数据与接口、异常恢复和验证方法。功能范围及用户操作见[需求文档](需求文档.md)。

## 当前持久化合同

模型 profile metadata 与 key 分离：

```text
~/.awaken/config/models.json
  profile.id, provider/model, base URL, advanced, keyLast4, ...

~/.awaken/config/agent-plan-account.json
  version, accountId, providerId, builtinCatalogRevision, keyLast4, credentialRevision, modelIds, catalog, ...

~/.awaken/config/agent-plan-media-tools.json
  provider/account reference, capability, exact model, enabled, configurationRevision

~/.awaken/.env
  AWAKEN_API_KEY_<profileId>="完整 API key"
  AWAKEN_MANAGEMENT_API_KEY_OPENAI="OpenAI 组织用量管理密钥"
  AWAKEN_MANAGEMENT_API_KEY_ANTHROPIC="Anthropic 组织用量管理密钥"
  AWAKEN_AGENT_PLAN_API_KEY_<accountId>="完整 Agent Plan API key"
```

`.env` 中 API key 是明文。Awaken 不再使用 Electron `safeStorage`、密文 envelope、macOS Keychain 或 Windows DPAPI 保存模型 key，也不读取旧 `model-profiles.json`。这是当前明确的产品取舍：文件权限可阻止其他本机账号的常规读取，但同一登录用户、具有该用户权限的进程、备份程序或取得磁盘访问权的攻击者仍可能读取 key。不得把 `.env` 加入项目、云盘同步或普通备份，也不得把它附到问题报告；文档和 UI 不得把该文件描述成加密存储。

正式根由 Electron Main 解析为用户主目录下 `~/.awaken`；开发版与安装版共享这份模型配置。`AWAKEN_HOME` 只由 Main 注入 Core；普通继承环境不能改变产品数据根。测试通过构造函数注入临时根和 key store。

`awaken-acp --startup=core` 是同一约束下的机器入口：launcher 移除 client 继承环境中的同名覆盖，并把当前用户主目录下的 `~/.awaken` 固定注入受管 headless Core。Core 的 `src/modelprofile/user_store.go` 只读解析该文件，不写回、不向 ACP client 返回 key。Desktop Main 仍是唯一 writer。

## 变量与文件格式

- 每个 profile 只允许一个 `AWAKEN_API_KEY_<profileId>`；profile ID 必须匹配 `[A-Za-z0-9][A-Za-z0-9._-]*`，防止构造额外 assignment。
- OpenAI/Anthropic 管理密钥使用 provider-scoped 固定变量，只用于官方组织 usage/cost API，不参与推理、profile ready 判定、推理凭据 revision 或 prompt-cache identity；Renderer 只取得是否存在和掩码。
- Agent Plan 首期只允许固定 `accountId=volcengine-agent-plan-default`，映射到独立的 `AWAKEN_AGENT_PLAN_API_KEY_volcengine-agent-plan-default`；不能复用 profile namespace，也不能由 Renderer 自定义变量名。
- value 用 JSON string 形式序列化，换行、引号和特殊字符不会逃逸为另一项变量。
- 读取兼容无引号、单引号、双引号和 `export KEY=...`；无法解析的任意非空行使整份文件 `unreadable`，不能忽略坏行后继续写。
- 读写保留非 Awaken 变量的值语义，但写回按 key 排序并规范化格式；`.env` 不是保留注释与原始排版的文本编辑器。
- 删除 profile 时删除对应变量；其他 profile 与非 Awaken 变量保留。

## 原子写与 mutation 顺序

`AwakenEnvStore` 的写入步骤固定为：

```text
读取并完整解析当前 .env
  -> 在内存修改一个变量
  -> ~/.awaken 内创建唯一临时文件
  -> 0600 写入
  -> 原子 rename 为 .env
  -> chmod 0600
  -> 清理临时文件
```

所有 key mutation 经进程内 queue 串行化。新建/更新 profile 时先写 key，再写 `models.json`；如果 profile 写失败，恢复此前 key。删除 profile 时先删除 key，再写 profile；profile 写失败同样恢复此前 key。Agent Plan 账户先写独立 namespace key，再原子写 `agent-plan-account.json`；metadata 写失败恢复此前 key。回滚失败必须向上报错，不能宣称操作成功。

Agent Plan key 实际变化时 `credentialRevision` 单调递增；相同 key 不递增。仍有 `provider_account` profile 或任一 enabled/disabled 生成工具配置引用固定账户时拒绝删除账户，不能先删 key 再留下悬空引用。媒体配置文件不保存、复制或缓存 Key；Core 只用固定 account ID 解析同一 `.env` 变量。

`.env` 缺失等同尚未保存任何 key；损坏、权限拒绝或其他读取错误不能当作空文件覆盖。`models.json` 和 `.env` 不构成跨进程事务；当前只支持一个 Desktop Main 作为模型配置 writer。

- `.env` 解析、权限和原子 replace：`apps/desktop/src/main/awaken-env-store.ts`。

## 代码与数据

- [ ] `ModelProfileStore` 只读写 `~/.awaken/config/models.json`，没有旧 profile importer。
- [ ] `AwakenEnvStore` 是模型 key 的唯一持久化 owner；代码不依赖 Electron `safeStorage`。
- [ ] 每个 profile 只映射一个合法的 `AWAKEN_API_KEY_<profileId>`，不能注入额外 assignment。
- [ ] OpenAI/Anthropic 管理密钥只映射固定 provider-scoped 变量，不参与推理、profile ready 或推理 revision；Google 不伪造管理凭据。
- [ ] Agent Plan 固定账户只映射独立的 `AWAKEN_AGENT_PLAN_API_KEY_<accountId>`，不会复制进 profile secret。
- [ ] `.env` 同目录临时写入、原子 rename，并最终为 `0600`。
- [ ] 损坏/不可读 `.env` fail closed，不作为空文件覆盖。
- [ ] 保存、删除、template 复制、测试连接、能力同步、余额和 start-run 都按 profile ID 读取同一 key store。
- [ ] profile 写失败恢复此前 key；删除失败同样恢复。
- [ ] Agent Plan account metadata 为 versioned/原子/`0600`；key 实际轮换递增 revision，写失败恢复旧 key，被 profile 或生成工具配置引用时拒绝删除。
- [ ] `agent-plan-media-tools.json` 只保存账户引用、capability、精确模型、enabled 和 revision，原子写入且为 `0600`，不复制 Agent Plan Key。
- [ ] Core 只有在媒体配置 enabled、model kind 与 Main catalog 一致且固定账户 Key 可读时注册工具；ProviderManifest、tool schema、Outcome 和 Artifact 都不含 Key。
- [ ] `models.json` 只保存 `keyLast4`，不保存完整 key、密文 envelope 或 token。
- [ ] `model-capabilities.json` 位于 `~/.awaken/cache/`，失败不阻断静态能力。

## 状态与泄密边界

- [ ] 当前 profile status 只使用 `ready|missing_key|disabled|unreadable`。
- [ ] `.env` 读取错误映射 `credential_unreadable + retry/reenter`；写入错误映射脱敏 `operation_failed`。
- [ ] provider 401/403/429、网络和余额错误不被标为本地 `.env` 故障。
- [ ] Renderer、日志、Desktop issue、journal、thread metadata、run snapshot 和 lifecycle snapshot 不含完整推理或管理 key；Renderer 只获得账户掩码、状态和 revision。
- [ ] UI 与文档明确 key 是本地明文文件，不宣称 Keychain/DPAPI/safeStorage 加密。
- [ ] `keyLast4` 只用于掩码，真实 `has_key` 来自 `.env` 读取。

## 状态与恢复的实现

```text
ready | missing_key | disabled | unreadable
```

跨 IPC 的凭据错误只有 `credential_unreadable`；动作是 `retry` 或在 Models 中重新输入。写入失败、无效 profile ID 和回滚失败使用脱敏的 `operation_failed`，只提供 `retry`。不存在 `temporarily_unavailable`、`credential_save_failed`、relaunch 解密恢复或系统重新认证状态。
