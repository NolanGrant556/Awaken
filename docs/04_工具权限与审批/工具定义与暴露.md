# 工具定义与暴露

## 1. 三层身份

Awaken 将模型调用名、能力和具体实现分开：

- `ToolDefinition`：模型可见名称、输入/输出 schema、用途、边界、side effects、failure modes；
- `Capability`：与 provider 无关的语义，例如 `file.read`、`presentation.render`、`message.send`；
- `ProviderManifest`：具体实现身份 `provider_id`、来源、能力、依赖、readiness、side effects 和诊断。

同一 capability 可以有多个 provider；模型仍通过稳定 tool name 调用。内部 capability resolver 只为 run snapshot 生成候选、偏好和 readiness 事实，不提供额外模型工具，也不在运行中偷偷换掉已固定 provider。

内建工具使用严格定义校验；外部/MCP 定义可以适配，但缺失 side-effect 或输出事实时必须标为 adapted/degraded，不能补成“已证明安全”。缺失这些声明不阻止已连接 MCP tool 的调用，只降低目录与 Outcome 能证明的事实强度。模型描述按上下文预算裁剪，purpose、side effects、权限边界和返回契约优先保留。

## 2. ToolDefinition v2 与定义质量

`ToolDefinition` v2 将三类事实分开：

- 模型选择：`purpose`、`when_to_use`、`when_not_to_use`、经验证 examples 和稳定 failure modes；
- 执行契约：`input_schema` 与仅描述 Outcome `details` 的 `output_schema`；外部 schema 不能重新定义 canonical status/errors/changes 等 envelope 字段；
- 安全事实：side-effect kind/resources/reversibility、workspace/file/network/auth 需求、annotations 与默认 `policy`。`always_allow`/`always_deny` 参与决策；`Read`/`Edit`/`Write`/`Glob`/`Grep` 经 TaskScope 硬门禁，`dependency_install`、`git_remote` 和 MCP Artifact bridge 经各自 broker 合同，`Bash` 的明示合同是当前登录用户 direct。

注册时产生 `strict` / `adapted` / `incomplete` 质量与 warnings，和 `builtin` / `mcp` / `connector` / `plugin` / `runtime_provider` 等来源是两条独立维度。兼容 adapter 可从 legacy description/parameters/annotations 补出保守视图，但不伪造 examples、failure modes 或已证明的权限范围。

校验模式为 `compat`、`strict_builtin`、`strict_all`。生产内建工具必须达到 strict v2；外部定义在迁移期可 adapted，其 output mismatch 只能降级告警且保留原始 details，不能按 strict 内建工具的证明强度声明成功。

## 3. 模型暴露

单工具模型描述默认上限为 1,800 runes，必保留用途摘要、禁用边界、side effects 和权限，再按预算补用法/返回细节。外部 description 不能无界挤占模型上下文。

`ToolExposurePolicy` 只决定快照中哪些 schema 可见，不授权执行。`default`、`compat`、`grammar_capable` 和 `all` 作为 wire-compatible 通用模式保留，当前没有工具专用隐藏规则；`ExtraVisible` 先于 `ExtraHidden`，调用方不得配置同名冲突。

Computer Use 注册 `computer_observe`、`computer_act`、`computer_verify` 三个 strict-v2 内建工具。它们只有在全局设置开启、模型支持图像且 run-bound Driver 健康时才在该 run 的固定 availability snapshot 中为 `ready`；真实执行只能进入 `LaneComputer -> ComputerExecutor -> computer.Runtime`，不能调用工具对象的通用 `ExecuteOutcome` 旁路。完整产品、安全与 Host 边界由 [10 计算机操作能力](../10_计算机操作能力/索引.md) 拥有。

当前内建模型基础工具固定为：

```text
Bash, Read, Edit, Write, Glob, Grep, WebSearch
```

保留的内建辅助工具为 `artifact_publish`、`trash_file`、`calculator`、`ask_user`、`dependency_install`、`git_remote`、`skill`、`memory`，以及 `delegate_external_agent`。运行期接入 MCP/Connector 工具。`memory` 是 user/project Markdown Memory 的唯一合法 mutation 入口，详细边界由 [11 长期记忆](../11_长期记忆/索引.md) 拥有。`delegate_external_agent` 是 ACP Client 的唯一入口，将任务委派给本地已配置的 ACP runner（如 Codex、Claude Code、OpenCode、Qwen Code），在同一 Awaken thread 中保持会话、观察工具进度并处理 ACP 权限请求；其详细行为由 [ACP 智能体协作设计与实施方案](../02_主智能体闭环/ACP智能体协作设计与实施方案.md) 拥有。注册快照不得出现旧文件/Shell 工具、`apply_patch` 或 typed Office runtime 工具。

`image_generate` 与 `video_generate` 不是无条件内建工具。它们只有在 Agent Plan 对应媒体配置 enabled、配置模型与 Main 分类目录一致、固定账户凭据可由 Core 读取时，才在 Core 进程启动阶段注册；未配置时不占用模型 schema。配置变更通过 Desktop 的 active-run 门禁和 Core 重启从下一 run 生效。

Skill 不建立第二套暴露或求交规则；它通过单一 `skill` 工具提供工作流建议，不增删父 run 的工具快照。

## 4. 执行环境快照

每个 run 开始时进行只读、有界、secret-free 的 `ExecutionEnvironmentSnapshot` 探测，记录：

- snapshot ID、生成时间、OS/arch、native architecture 与 native/Rosetta/WOW64 translation；
- workspace root、cwd、shell、PATH 来源、完整 PATH digest/entry count/truncated 状态和最多 128 个诊断 entries；完整 transport PATH 仅在进程内固定；
- 最多 64 个带 source 的本地 Skill 绝对路径根元数据、TaskScope temporary work root 和 refresh reason；
- 可执行文件位置/版本观察、Python/Node 与包管理器；包管理器和 `git` 额外记录解析后 executable 的 SHA-256，供 typed executor 在 transport 前复核；Darwin 的 typed Git observation 不信任任意 PATH/Homebrew/user Git，而是固定到 root-owned、非 group/world-writable 的 Xcode/CommandLineTools actual Git，并标记 `host_trusted_developer_tool` provenance；
- 仅记录变量名称的 proxy/auth/runtime references，以及 workspace 内非 symlink 的 venv、node_modules、manifest/lock/version marker；
- warnings、confidence 和诊断。

Desktop supervisor 先用当前用户交互式 login shell 解析并向 Core 注入真实登录环境；失败时回退非交互 login shell，再失败才回退 Electron 进程环境。每种 shell 模式的解析均有 3 秒超时、256 KiB 输出上限和 marker framing，不记录环境值；shell 探测成功后采用其最终环境，不与启动前环境做 union。Desktop 再把 `AWAKEN_HOME/runtime/cli/bin` 预置到 Core PATH，使已激活的受管 `dws`/`lark-cli` 无需重启即可被后续 run 发现；Main 自身不依赖该 PATH，而只执行经过版本验证的绝对路径。run 探测以这份 Core PATH 为基线，并显式观察 `dws` 与 `lark-cli`；可解析的 executable symlink 保存 canonical real path，指纹和后续 typed exec 都绑定该路径。显式 API 仍可在 home 根内有界只读 shell config，只合并严格字面 `PATH=` 赋值，但默认 run 不再用它二次覆盖已解析的登录 PATH。完整 PATH 以 digest 进入 snapshot identity，模型/日志只见有界预览，Shell transport 使用进程内 pinned full PATH。

环境快照的通用 `--version` 仍只对 host-trusted system/Developer 根中的有界普通 executable 执行，且使用过滤环境。typed Work provider另按自身窄合同对实际候选 Python、LibreOffice、Poppler、FFmpeg 做组件级能力 probe；这些 probe不安装包、不复制工具、不读取凭据，也不把用户环境晋升为 Awaken runtime。

## 5. 每 run 工具可用性快照

`RunToolAvailabilitySnapshot` 在 run 边界固定以下事实：

- catalog version、environment snapshot ID 和本 run 固定的 snapshot ID；
- tool schema/definition quality；
- runtime instance、provider manifest、readiness 和 dependency observations。

RequestBuilder 暴露给模型的 schema 与 ToolRuntime 真正执行的 runtime 都从同一快照读取，消除“模型看到 A、执行时 registry 已换成 B”的 TOCTOU。运行期间 registry catalog 或机器环境变化只在下一 run 形成新 schema/runtime/provider/environment snapshot；当前 run 不换实现。但 MCP adapter 的 permission/Manager call 仍每次读取 live server connection/auth state，因此中途断开会立即使当前 run 的后续调用返回 auth/runtime/unsupported/transport failure，且不使用旧 session。

Skill 不创建、求交或收窄这个快照；它只给出选择提示。模型供应商是否支持 tool calling 是建立快照/请求前的上游输入；当前 profile schema 没有统一、可验证的 per-model tool-support capability，因此尚不能把所有 provider/model 组合都写成已支持。

## 6. Readiness

Provider readiness 枚举：`ready`、`needs_auth`、`needs_runtime`、`unavailable`。依赖种类包括 OS executable、language runtime/package、package manager、Desktop app、MCP connector、network service 和 packaged resource。

依赖 declaration 与 observation 必须分开。通用 resolver 对 OS executable、language runtime、package manager 和以 executable 表达的 Desktop app 使用 pinned environment；MCP/network 交给具体 provider，packaged resource 由 owner 按需解析。MCP readiness 可由真实 server 连接/认证状态推导；未探测到的依赖保持 unknown/missing，不用文件存在或 connector aggregate capability 猜成 ready。

language package 只在 provider 显式声明安全 probe ID 时做通用只读探测：`python_import:<module>` 使用 `importlib.util.find_spec`/distribution metadata，`node_resolve:<package>` 使用 `require.resolve` 而不加载包代码。探测只使用 pinned Python/Node executable、workspace 的 `.awaken/deps`/`node_modules` 搜索路径、去敏最小环境、1 秒超时、有界输出和 30 秒 cache；并且必须实际应用平台 `inspect_read_only` full sandbox，无法应用时返回 error，不启动 PATH executable。可执行文件 `--version` 探测遵守同一 fail-closed 边界。非法/自由文本 probe ID 不执行。observation 区分 ready/missing/mismatch/unknown/error，并支持 exact、`>`/`>=`/`<`/`<=` 与逗号 AND 的简单数字版本约束；`^` 等未支持语法保持 unknown。

非 ready observation 可携带 host-generated `candidate_install_plans`。resolver 对 Python 只接受规范 distribution name，对 Node 只接受普通 package 或单层 `@scope/name`，拒绝 URL、alias/protocol 和多余 `@`；使用快照中已观察到的包管理器绝对路径，生成可重现 `plan_id`，并绑定完整 dependency requirement fingerprint、`environment_snapshot_id`、解析后 executable 的 SHA-256、结构化 argv/cwd、install scope、requires-admin、是否修改 manifest、source 和 `host_dependency_resolver_v1` provenance。WorkspaceRoot、TemporaryWorkRoot 或任一 SkillRoot 内的 manager 不产生 open-network plan；外部用户安装目录属“用户机当前受信状态 + run fingerprint”，不是 managed attestation。provider/Skill/MCP 返回的自定义 candidate argv 会被丢弃并由 host 重建。Python 计划固定 workspace-relative `.awaken/deps/python`、`--no-input` 与 `--only-binary=:all:`，Node 计划固定 `--ignore-scripts` 与 `--no-audit`；不安全的名字、版本或来源语法不产生计划。plans 只随 provider readiness/next action 投影，不由独立诊断工具刷新当前快照。

Candidate plan 是供模型决策的候选，不是授权或已执行事实。`dependency_install` 是 host-generated `CandidateInstallPlan` 的唯一 typed 消费入口，但不是本机安装动作的唯一合法路径：`Bash` 仍可按 Skill 指令直接运行包管理器和安装脚本。该 typed 工具的模型 input schema 只有 `plan_id`，不接受 command、argv、package、URL、cwd、timeout 或输出上限。工具只执行当前 run snapshot 精确查询出的 `InstallWorkspace`、`RequiresAdmin=false`、`host_dependency_resolver_v1` Python/Node plan；执行前重新校验 requirement/environment/tool snapshot、包管理器 observed path 与 SHA-256、固定安全 argv和当前 TaskScope。进程使用 direct `exec.CommandContext(executable, argv...)`，不经过 Bash；child PATH 从 pinned snapshot 生成，但剔除 workspace/temp/Skill 根内及不可解析目录，防止 `/usr/bin/env` shebang 被项目 runtime 劫持。child 只继承显式 allowlist 的 HOME、proxy、证书及 package-registry/auth 变量，不暴露通用 API key/token 环境。

`dependency_install` 仅在平台 `SandboxFull` 且真实 `open_world_system` sandbox applied 时启动，并复用 `WorkspaceExecutionBroker` private staging。网络可由包管理器使用，但 child 只能向 staging 写；exit 0 且 broker scope/concurrency/Trash commit 成功后才发布。non-zero、spawn failure、timeout、cancel 会显式 discard staging；narrow writable root、protected root 或 workspace 外 delta 在 Trash/publish 前拒绝。`Bash` 无法获得该 broker operation。stdout/stderr 在整体有界收集后统一脱敏 URL userinfo、query/auth assignment 和 token marker，再进入 observer/Outcome，避免分块秘密泄漏。

安装进程 exit 0 不是 dependency ready 的充分证据。提交后会生成 refreshed environment candidate，并在 `inspect_read_only` full sandbox 中复探对应 requirement；非 ready 返回 `needs_runtime` 和已发生 changes，不写伪 success。当前 run 的 tool/environment snapshot 始终保持 pinned，只有显式 refresh 或新 run 才能消费刷新结果。language package 不做无声明的全环境 inventory，也不支持任意 ecosystem 版本语法。

环境快照已记录有界 Skill roots、TaskScope 临时执行根和显式 refresh reason，且三者参与 identity/clone。run 开始、显式刷新、typed 安装后候选快照分别使用 `run_start`、`explicit_refresh`、`dependency_install:<plan_id>`。安装工具返回 refreshed environment/dependency observation 和 `refresh_run_availability` next action，但不原地替换当前 run 的 provider/runtime；旧 ToolRuntime 保留 deep-cloned pinned snapshot，后续消费只能发生在下一 run 或显式 refresh 后创建的新 runtime。

## 7. typed Git 外部读取

`git_remote` 是普通公开 Git 外部读取的宿主拥有入口，能力为 `git.remote_read` 与 `git.clone`。模型只能提交严格字段 `operation`、`url`、可选精确 `ref`，以及 clone 专用的 workspace-relative `destination`/`replace_existing`；不能提交 command、argv、环境、credential、timeout 或任意 Git 子命令。

两种操作都要求当前 `RunToolAvailabilitySnapshot` 中存在 `builtin:git_remote`，并绑定同一 `ExecutionEnvironmentSnapshot` 中的 Git 绝对路径与 SHA-256；执行前 tool 和 broker 各自重新计算 executable fingerprint。Darwin 执行侧再次要求 `host_trusted_developer_tool` provenance、受信 Developer 路径、root ownership 和不可 group/world write；即使用户 PATH Git 的 SHA-256 被快照记录，也不能取得 open-network transport。HTTPS helper 必须位于同一 toolchain 的 root-owned `usr/libexec/git-core`，`git-remote-https` target 的 SHA-256 同样绑定 projection 并在 broker 前复核；child `GIT_EXEC_PATH` 固定到该目录。PATH 会剔除 WorkspaceRoot、TemporaryWorkRoot 和全部 SkillRoots 下的 entry，避免 project/Skill/temp 假 helper 劫持。

进程使用 direct argv，不经过 shell，并隔离 HOME/XDG/global/system Git config；禁用 terminal/askpass/credential helper、hook/template、LFS smudge、submodule recursion、redirect 和非 HTTPS protocol。URL 只接受无 userinfo、query、fragment 的 canonical HTTPS repository path。没有显式代理时，DNS preflight 必须至少返回一个地址且所有地址均不属于 loopback、RFC1918、CGNAT、link-local、benchmark、documentation、multicast、reserved 或 IPv6 ULA 范围。

若当前 host 明确提供非空 `HTTPS_PROXY`/`https_proxy`/`ALL_PROXY`/`all_proxy`，工具只接受可严格解析、带显式端口、无 path/query/fragment 的 `http`、`https` 或 remote-DNS `socks5h` URL，并验证实际 proxy endpoint；用户显式本机 proxy 可以是 loopback/private。Git child 的大小写 HTTPS/ALL proxy 变量被强制设为同一值，同时 `NO_PROXY`/`no_proxy` 被清空，防止目标绕过 proxy；ambient `HTTP_PROXY`、`GIT_CONFIG_*` 和通用 token 不继承。Outcome/journal 只记录 `proxy_routed` 与 proxy source 变量名，不记录 proxy URL 或 credential；stdout/stderr 中回显的 proxy userinfo 在 observer 前整体脱敏。代理模式下 remote hostname 由 proxy 解析，因此不把本机 TUN 的 `198.18/15` fake-IP 当作目标地址。

`ls_remote` 向 broker 声明空 writable roots，因此任何 workspace delta 都会在 Trash/publish 前拒绝。`clone` 固定 `--depth=1 --single-branch --no-recurse-submodules`，只允许一个经 TaskScope 校验且父目录已存在的 destination；子进程只写 private staging。non-zero、spawn failure、timeout、cancel 整体 discard；成功后 broker 再做 destination-only writable/protected/concurrency 校验，覆盖前版本进入系统 Trash 后才发布。`Bash` 无法取得保留的 `git_remote` broker operation，但可以在当前用户环境直接调用 `git`；该路径不获得 typed Git 的 URL/DNS/credential/staging/Trash 保证。

直接模式的 DNS preflight 与 Git 建连之间没有连接级 IP pinning，仍存在 DNS rebinding 时间窗；proxy-routed 模式则依赖用户显式 proxy 对 remote hostname 的解析与转发，同样不是 Awaken 自有连接级 IP pinning。禁 redirect、拒绝直接模式当前全部非公网解析结果、强制 proxy 且清空 bypass 只是缩小风险，不能写成完整 egress gateway。当前入口不支持私有仓库认证、SSH/file/git/http、任意 fetch/push、submodule 或 clone 到缺失父目录；remote checkout 若产生 symlink，会被现有 broker 的 symlink commit 门禁整体拒绝。Windows/Linux 没有 `SandboxFull` 时在 Git transport 前返回 unsupported。

## 8. WebSearch provider

`WebSearch` 保持稳定 schema，通过 `SearchProvider` 接口使用 Exa 与 Tavily 两个免 key 渠道。Exa adapter 固定调用 hosted MCP `https://mcp.exa.ai/mcp?tools=web_search_exa`，兼容 JSON 与 SSE `data:` 响应；Tavily adapter 固定调用 `POST https://api.tavily.com/search` 并发送 `X-Tavily-Access-Mode: keyless`。Brave 不再是产品选项，也没有相关运行时 adapter 或凭据配置。

“设置 > 搜索”对每个渠道提供独立开关和独立连接测试，默认只开启 Exa。只开启一个渠道时直接使用该 provider；两个渠道都开启时先请求 Exa，只有 Exa 返回结构化失败才请求 Tavily，Exa 成功但无结果也不触发 fallback；全部关闭时返回稳定 disabled Outcome。域名经规范化后，Exa 使用查询改写，Tavily 使用原生 `include_domains` / `exclude_domains`，返回 URL 都必须经过二次硬过滤。两个 transport 都使用 30 秒超时和 4 MiB 响应上限；no-results、rate-limit、network、upstream-format、cancel 使用稳定错误码。

非敏感设置保存在 `~/.awaken/config/search.json` version 1 的 `providers.exa.enabled` 与 `providers.tavily.enabled`；文件不保存 endpoint、header 或凭据。Desktop 在无活跃 run 时原子更新该文件并重启 Core，Runtime Supervisor 只注入按固定顺序拼接的 `AWAKEN_WEB_SEARCH_PROVIDERS`。

## 8.1 Agent Plan 图片视频 provider

模型只调用稳定名称 `image_generate` / `video_generate`；具体 provider identity 包含 `volcengine-agent-plan + capability + exact model + configuration revision + credential revision`。配置中的生成模型不进入 input schema，模型也不能提交 provider、账户、Base URL、Authorization、保存绝对路径或 timeout。两项 runtime 分别声明 `image.generate` / `video.generate` capability、固定服务网络 side effect 和本地 Artifact create side effect。

Core 从 Main-owned `agent-plan-account.json`、`agent-plan-media-tools.json` 与 `.env` 建立只读配置。能力、模型 kind、目录分类、固定账户和 Key 任一不匹配时 fail closed，不注册半就绪工具。实际调用只把 Key 放入 provider Authorization header；Outcome、ProviderManifest、Artifact、日志和模型结果不含 Key 或远程 signed URL。

当前图片执行为同步请求，视频执行为 create-task 后在同一个 tool call 内有界查询。图片 schema 允许 `mode=single|group`；single或省略 mode时固定映射 `sequential_image_generation=disabled` 且禁止 `max_images`，group时要求 `max_images=1..15` 并映射 `sequential_image_generation=auto` 与 `sequential_image_generation_options.max_images`。`max_images` 只是上限，不保证上游精确返回该数量；返回数量超过本次上限时整次结果失败。图片生成尚未接入参考图，因此只按最终输出最多 15 张校验；视频生成的本地 ready 图片输入按本节后文的独立合同处理。

媒体字节下载后必须校验非空、单文件上限和真实格式，再原子写入 `output/generated-media/`。每个通过验证的结果独立发布 `ready` deliverable Artifact；组图中某个兄弟结果下载、校验或写入失败时，已完成文件不得被回滚，Outcome 使用 `media_generate_partial + side_effect_state=partial`，返回逐项 `items[index,status,path?]`，失败项不伪造 Artifact。Runtime 只在 `transport=completed`、side effect 为 partial 且 Artifact 状态全部为 ready 时允许失败 Outcome 发布这些已验证产物；实现错误、schema 错误或未知 transport 继续 fail closed。

provider 认证、限流、上游任务失败、无效响应和下载失败使用稳定错误码；远程结果地址只接受 HTTPS（测试允许 loopback HTTP）。图片创建使用独立的长请求时限，不受普通 120 秒客户端总时限约束；创建类 POST 超时可能已经消耗额度，必须记录 `transport=unknown`、`retryable=false`。视频提交没有返回 task ID 时使用 `media_generate_create_unknown`，立即要求用户先核对供应商任务状态；FailureSupervisor 在当前 run 内阻止该工具继续以相同或不同参数提交，不能把“换参数”当作安全重试。GET 下载/查询失败仍按可安全重查的 transport 事实分类。diagnostic 只保留 `timeout | dns | connection_closed | network_dial | network_read | network_write | network | poll_timeout` 等去敏分类，不保存原始 URL、底层错误或凭据；已经收到 HTTP 响应的 4xx/5xx 保持 `transport=completed` 并按状态码分类。Workbench 展示边界只见[中间区域产品与交互契约](../01_桌面工作台/中间交互区域/产品与交互契约.md)。

视频创建返回 task ID 后立即写入 `~/.awaken/state/media-tasks/<request-fingerprint>.json`，只保存账户/模型引用、task ID、provider 状态和时间，不保存 Key、prompt、图片 Base64 或 workspace 路径。同一 workspace、配置和结构化请求在 Core 重启后再次执行时，先恢复未终态 task ID 并继续 GET 查询，不重复 POST；同一 Core 内并发提交同一 fingerprint 时，查找/创建也必须串行化，保证只产生一个 provider task；显式 `task_id` 只续查旧任务。startup recovery 本身不调用外部 provider。轮询窗口耗尽时返回 `media_generate_task_pending + transport=unknown`，UI 停在“状态待确认”，后续继续使用原 task ID。

当前仍没有后台 Detached Tool Execution、Core 启动后主动轮询、基于稳定 Artifact ID 的通用引用解析、图片编辑、完整媒体谱系和按具体模型动态收窄的完整参数矩阵；这些不能写成已支持。`video_generate.source_image_path` 当前只接受可读的 ready PNG/JPEG Artifact 路径；Core 会在不修改原 Artifact 的前提下，把过大的内联输入重新编码为受控大小的 JPEG data URL。`first_frame` 按官方首帧输入结构省略 role，`reference_image` 才显式发送对应 role；Renderer 不参与读取或编码。

## 9. 外部 schema 与当前限制

MCP adapter 会把 external output schema 放入 Outcome `details`：普通 object 保留原形，非 object 使用 wrapper，与 canonical envelope 同名的 object 整包放入冲突安全 wrapper。但当前 `ToolParam` 不支持所有 JSON Schema keyword，`pattern`、`format`、`$ref` 等可能被忽略；`OutputSchemaWarnings()` 也尚未完整进入常规工具目录/诊断投影。

模型描述、标准 MCP annotations 和可选 Awaken metadata 都是选择、目录与兼容信息，不是调用授权。MCP server 处于 connected/auth-ready 且输入通过 schema 校验时，read、mutation、message、delete 及 annotations 自相矛盾的 tool 都可进入 transport；缺失或无效 `io.awaken.tool/provider/v1` 只形成诊断 warning。外部 provider 若误报 capability、side effect 或输出，Awaken 不能通用阻止或撤销其副作用；需要 TaskScope、Trash 或渲染验证时必须显式选择拥有该合同的 typed provider。消息发送不另设 Awaken 审核合同。

## 10. 暴露不变量

- Desktop、MCP、Connector、Skill 均通过同一 Tool Catalog/ToolRuntime，不能各自形成旁路。
- provider aggregate capability 与 per-tool metadata 只用于发现和诊断，不是 MCP 调用授权。
- snapshot ID、environment ID、provider ID、capabilities、readiness、dependencies 和 side-effect state 必须进入 audit/journal/wire 投影。
- tool schema 与实际 runtime 必须来自同一快照；运行中不得重新查 registry 选择另一个实现。
