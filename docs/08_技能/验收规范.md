# 技能域验收规范

## 1. 权威范围

本文只拥有技能域的验证矩阵，不重新定义包、安装、激活或 MCP bridge 行为。验收结论必须引用 [技能包与加载契约](./技能包与加载契约.md)、[安装与激活契约](./安装与激活契约.md) 或 [执行模式与 MCP 来源边界](./执行模式与MCP来源边界.md) 的条款。

## 2. 静态检查

- 所有代码和测试路径存在；文档不得出现 bundled/system Skill 当前来源。
- 本地目录必须写为 `<workspace>/.awaken/skills/<package>/SKILL.md` 与 `~/.awaken/skills/<package>/SKILL.md`。
- “name 必填”必须保留本地 fallback 与底层 schema 两层语义。
- replace 必须区分 HTTP/底层、Desktop 默认行为和平台工具 fail-closed。
- fork、model/effort/agent/hooks、requiredConnectors 和 MCP bridge 缺口不得写成已完成能力。
- 09 协议域标记为未注册的单 Skill execute handler 不得被验收为产品 route。

## 3. 自动化

至少运行：

```text
go test ./src/skills ./src/skillruntime ./src/server
go vet ./src/skills ./src/skillruntime ./src/server
```

关键断言：

1. project 覆盖 user，同 ID 的低优先级条目为 shadowed。
2. 平铺 Markdown 被忽略；目录名 fallback 可补齐本地空 name。
3. 保留 `mcp__` 前缀、平台冲突、工具扩权、资源逃逸和 required 条件全部 fail closed。
4. 安装拒绝 zip traversal/symlink；底层 replace 失败恢复旧包；平台工具 replace 被拒绝。
5. 显式和隐式激活生成等价的 activation/receipt 语义。
6. MCP bridge 注册、重连 reconcile 和断开清理的现有单元行为通过；未覆盖的真实消息/参数/resource 路径继续作为缺口列出。

### 当前事故回归矩阵

| A19 | composer 显式 Skill 在首个 LLM 请求前生成 activation plan、required receipts 与 effective pool；多 Skill 记录原子持久化 | `src/runtime/skill_activation_test.go:TestPreActivateComposerSkillsBeforeLLM`、`TestComposerMultiSkillActivationPersistenceIsAtomic` |

A20 的“缺失”不能实现成自动联网下载 required resource；它是 Skill 包完整性错误。

## 4. 真实 Desktop 只读验收

按根 README 的正式入口打开 Awaken，进入扩展页：

1. 核对项目级和全局级分组与真实目录一致。
2. 核对已连接且可桥接的 MCP 来源单独显示，不混入本地包。
3. 核对 shadowed/unavailable 原因没有被 UI 伪装为可执行。
4. 在不修改 userData 的验收轮次，不点击安装、覆盖、连接或断开。

需要验证执行时，应在专用临时 workspace 创建最小包，完成：显式 token、模型 Skill 工具、required tool/resource 失败、reload 时点和 fork 降级警告。不得在用户真实 skills 目录做破坏性验收。

## 5. 完成门槛

只有自动化、临时 workspace 执行和真实 Desktop 展示三者一致，且所有已知缺口仍被明确记录时，才能宣称技能域文档与当前实现一致。
