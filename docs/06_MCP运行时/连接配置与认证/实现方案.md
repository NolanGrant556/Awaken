# 连接配置与认证 · 实现方案

本文说明代码职责、数据与接口、异常恢复和验证方法。功能范围及用户操作见[需求文档](需求文档.md)。

## 订阅关闭

`Manager.Shutdown` 与订阅 context 取消共享 subscriber 锁和成员登记，只有仍登记的 channel 能被关闭。Shutdown 幂等，关闭后新订阅立即结束；后台等待者也通过关闭信号退出。Session.Close 在 Manager 锁外执行，避免回调进入 Manager 时互相等待。`subscription_shutdown_test.go` 以 `-race` 覆盖取消、事件发送、重复关闭及关闭后订阅。

## 配置 scope

| scope | 来源 | 合并优先级 | 持久性 |
| --- | --- | --- | --- |
| `plugin` | Agent Plugins `mcp.json` 或 Codex/Claude/Cursor native MCP 经 `PluginStore.PluginMCPServers()` 翻译 | 最低 | 持久（包 + `plugins.json` server/component/tool override） |
| `user` | `~/.awaken/config/mcp-servers.json` | 覆盖同名 plugin | 持久 |
| `project` | `<workspace>/awaken.mcp.json` | 覆盖同名 user | 持久 |
| `dynamic` | Connector `InjectDynamic` | 最后覆盖 | 仅当前进程 |

`MergeScoped(plugin, user, project, dynamic, logger)` 丢弃无效条目并记录 warning；`enabled:false` 条目必须保留在合并结果中，由 Manager 重建为 `disabled` 且不建立 transport，保证管理面可见并在重启后保持停用。Plugin `DisabledTools` 不从 server tools/list inspection 消失，但不得注册进中央 Tool Catalog。输出顺序确定；启动时按合并结果创建 Manager server。

插件 MCP 的 raw server identity 固定为 `plugin__<plugin-name>__<server>`；manager state、annotations、目录分组与路由解析保留这份原始身份。`src/mcpclient` 另生成只用于中央 Registry 和模型 API 的 canonical 调用名：合法 plugin name 中的 `.` 等长映射为 `_`；不安全或 `x0_` 开头的 component 使用可逆 Base32。这一投影不改写 source manifest、MCP wire tool name 或 UI identity。transport 配置来自已归一化 MCP component；`plugins.json` 只保存 server/component/tool override 和变量引用，不保存 secret 值。Plugin Store mutation 的 live projection 必须先比较当前 Manager entry 的 identity、scope、source revision 与完整配置；四者完全相同才是 no-op，不关闭 session、不注销工具、不发 disconnected 事件。plugin scope 的 source revision 固定取已签收 package digest，因此同名包替换即使 command/cwd 和变量未变也会重建对应 server；同一 digest 下的无关 catalog mutation 继续保留现有 session。tool override 必须独立于 server/component desired override 应用，工具单独停用后重载 Store 仍保留在 inspection 中，但不会进入下一份中央 Registry snapshot。连接器「用户安装」排除 `plugin__`。

正式 Desktop/Core 只从 `AWAKEN_HOME` 下的 `config/mcp-servers.json` 读取和保存 user scope。Electron `userData`、旧配置目录及其他历史位置不参与读取、写入、导入、迁移或 fallback；旧文件即使仍留在磁盘也没有配置 authority。测试必须注入隔离的 `AWAKEN_HOME`，不能依赖真实用户目录。

user config 的管理写入使用同目录跨进程锁、`0600` 临时文件、文件 `fsync`、原子 rename 与父目录 `fsync`；authority 目录收紧为 `0700`。HTTP 管理面与 builtin Connector 的增删改都必须通过同一 locked read-modify-write owner，不能各自执行无锁的 load/save。

`project` scope 只在 core 拥有有效 default workspace 时参与初始加载和 scope 合并。`AWAKEN_DEFAULT_WORKSPACE` 为空表示本次进程没有 project scope：不得回退 cwd、用户主目录或最近项目，也不得因为 project scope 缺席而阻止 user scope 的读取、保存、更新、启停或删除。用户后续选中的 run workspace 仍按 run 合同传入，不会反向把该目录提升成本次 core 的隐式 default workspace。

当前 live-update 仍不是全量 scope generation 重算：user/builtin 的增删、project 初始配置和 dynamic owner 可能在运行期发生同名替换；旧 session 清理虽按 connector owner 防止部分误删，但尚无统一 generation/原子 replace 证明。因此“project 永远覆盖 user、dynamic 永远最后”只对一次 `MergeScoped` 成立，不是所有时刻的运行时不变量。

## Transport

当前生产支持：

- stdio；
- HTTP/Streamable HTTP；
- SSE。

管理 API 的 `mcpServers.*` URL 简写同时接受 `type: "http"`、`type: "streamable-http"` 或省略 type；也接受以 `http://` 或 `https://` 开头的单个完整 Streamable HTTP URL。四种输入都必须规范化为内部 `http` transport，并由同一个 Streamable HTTP client 执行。裸 URL 以去掉 query/fragment 的 endpoint 生成稳定 `remote_<hash>` 内部 identity，query 中的 key/token 轮换不会改变该 identity；显示名默认取 host。外部 JSON server 名可包含中文等非 ASCII 字符：原名进入 `displayName`，内部 identity 仍保持工具名安全；当名称完全无法产生 ASCII identity 时生成稳定 `server_<hash>`。磁盘 canonical shape 始终使用 `servers.*.http`，不得把外部客户端的 transport 别名或裸 URL 保存成第二套持久格式。Desktop 配置入口以「本地进程（stdio）」和「Streamable HTTP」两个模式帮助用户选择正确示例；粘贴可判定的 JSON/URL 时可以同步提示模式，但模式不取得 schema ownership，最终校验、identity 生成与规范化仍由 Core 拥有。

WebSocket 不支持；in-process transport 只用于测试，除非生产显式注入。Manager 负责 initialize、capability snapshot、tools/prompts/resources list_changed、重连/停用和局部失败。单个 server 失败不能阻止 `awaken-core` 启动。

HTTP/Streamable HTTP/SSE 的新连接和 stdio child 使用 03 域的[跨平台网络代理与恢复](../../03_运行时与本地服务/网络代理与恢复/实现方案.md)。Desktop 在 MCP 配置、更新、启用或 connector connect 之前先校准 route；pending server 每次尝试都会重新构造 transport；Desktop route generation 改变时，Manager 自动重新启用 failed 的 stdio/HTTP/SSE server，不改变 disabled、needs-auth 或 in-process server。已 connected 的 stdio child 因无法原地更新环境，会先转 `pending`，等当前 tool call 结束后单独重建；新调用不进入旧 session，在途调用不取消也不自动重放。已 connected 的 HTTP/SSE 保持 session，后续新连接使用当前 route。MCP config 的显式 stdio env 最后覆盖宿主派生环境。插件 stdio 在该步骤之后由宿主写入 filesystem-resolved `PLUGIN_ROOT` / `PLUGIN_DATA`，覆盖配置里的同名项；配置 `env` 出现按当前平台环境变量名语义等价的保留名会使该 server 条目 invalid。占位符 `${PLUGIN_ROOT}` / `${PLUGIN_DATA}` 只在插件 `mcp.json` 的 `args`、`env` 值与 `cwd` 中单遍展开，由 `src/plugins` 在翻译时完成；`MergeScoped` 对 plugin scope 保持翻译结果原样，不再执行 user/project 的通用环境变量展开。

Agent Plugin 声明的 HTTP/SSE fixed headers 由 transport 只附加到配置 URL 的同 origin 请求；同 origin redirect 继续携带，不同 scheme/host/effective-port 的 redirect 或 legacy SSE endpoint event 不携带。请求已有的 MCP、OAuth 或宿主同名 header 优先，插件值不能覆盖。user/project 原生 MCP 配置仍沿用其既有 `${VAR}` 展开合同，两者不能混用。

### Elicitation

MCP transport 声明 form 与 URL elicitation capability。server 在一次 tool call 内发起 `elicitation/create` 时，Manager 将请求绑定到该 server 当前的 active call context；同一 server 的 tool call 为此串行执行，避免无 parent call ID 的协议请求串到另一调用。请求经 ToolRuntime 的 run-scoped event sink 投影为 `external_interaction_requested`，Desktop 在当前运行中展示确认卡；没有 active call、没有交互 run 或 run 已终态时一律安全返回 `cancel`，不得在后台隐式接受。

form 当前展示顶层 `properties` 中的 string、number、integer、boolean 和 enum 字段，支持 title、description、required 与 default；确认时只把用户填写的 `content` 返回给正在等待的 MCP session，取消返回 `cancel`。URL 模式沿用外部交互链接、完成确认与取消动作。表单答案只保存在 pending interaction 内存中，不写入 AG-UI 事件、Journal、模型上下文或日志；请求 schema 可以进入 AG-UI 供 Renderer 构造表单，但不得包含 credential value。嵌套 object/array、自定义 widget 与跨字段校验当前不属于 Desktop form renderer 的支持范围。

## Server 状态与 provider readiness

Manager snapshot 记录 pending、connected、needs-auth、failed、disabled 等 server 事实。`McpToolAdapter` 把当前 server 状态投影为 provider readiness：ready、needs_auth 或 unavailable，并附带 `mcp_connector` dependency observation。

Connector 写入 server-level `ServerProviderManifest`，提供稳定 provider identity/source/dependencies；它不授予 per-tool 消息或删除能力。每个 tool 的 capabilities、安全映射和 side effects 只来自 tool 自己的标准 annotations、保守推断和版本化 `_meta`。

## 动态工具注册

连接成功后，Manager 将每个 MCP tool 注册为 canonical `mcp__<model-safe-server>__<model-safe-tool>`；原始 server/tool 身份保留在 annotations 与 adapter 内。list_changed、断开与移除都按 definition 中的 raw `ServerName` 精确注销，不得只对 canonical 字符串做 `startsWith`；合法 server `...__local` 与 `...__local__nested` 可同时存在，刷新前者不能误删后者。调用路由不能假设 server name 不含 `__`：Manager 以当前 registry 中最长匹配的 canonical server 前缀解析 owner、反解 tool component，adapter 则直接携带独立 raw `serverName + toolName` 调用，保证 `plugin__<plugin>__<server>` 不被误拆；Manager 还兼容本机旧路径构造的 raw-qualified 名称。server wildcard permission override 以 canonical 拼写为当前入口，并保留 raw 拼写兼容。adapter 进入中央 registry，run 开始时被固定进 `RunToolAvailabilitySnapshot`。运行中 list_changed 或断开不改变已开始 run 的 provider identity/runtime pointer，但 adapter 的 `CheckPermission`/Manager call 仍读取 live server state：needs-auth 返回 auth Outcome，非 connected/已移除返回 needs-runtime/unsupported 或 transport failure，且不调用旧 session。下一 run 才取得新的 catalog/readiness snapshot。

## 代码位置

- `src/mcpclient/config.go`：user config 路径、scope 解析/合并（含最低优先级 `plugin`）。
- `src/server/handlers_mcp.go`：管理 API 输入解析、外部 server 名规范化、裸 Streamable HTTP URL 适配与 canonical 写入。
- `src/mcpclient/manager.go`、`transport.go`：server 与动态工具生命周期；stdio 最后注入 `PLUGIN_ROOT` / `PLUGIN_DATA`。
- `src/tool/elicitation.go`、`src/agentcore`、`src/runtime/session.go`：MCP elicitation 的 call-context 路由、run-scoped 等待与内存答案。
- `src/mcpclient/provider_manifest.go`、`tool_adapter.go`：provider/readiness 接入。
- `src/plugins`：`mcp.json` 合规解析与 canonical 配置翻译，不拥有 transport。
- `src/hookruntime` 的 Plugin `mcp_tool` handler 通过 Host 注入的 Manager executor 调用准确 plugin server/tool；必须先经 Store digest、component state、tool override 和 Manager readiness 复核。

## 认证与运行边界

- `connected` 只由当前 Manager session snapshot 证明，不能由“曾认证”或 metadata 存在证明；
- metadata state `authorized|needs_reauth` 是恢复提示，不证明当前 token 可读、未过期或业务权限充足；
- server `needs_auth` 时 tool provider readiness 为 `needs_auth`，当前 run 返回 next action，不发起业务 transport；
- OAuth 完成只证明认证流程已完成，不证明 provider tool 的 recipient 语义、业务权限、可恢复删除或副作用安全；MCP tool 不要求这些 Awaken per-tool contract，实际保证由 server 自身提供；
- builtin Connector 的 persisted user MCP config 携带稳定 provider identity；重启时 Registry 只据此恢复 active owner，再以当前 Manager snapshot 投影卡片状态。手工同名配置不能被认作 builtin owner；local/dynamic owner 不持久。
- host Connector account 使用同一 secrets backend 和 metadata store，但 identity 由稳定 Connector ID + account slot 生成，与插件名和 MCP server credential identity 分离。`src/connectorauth` 拥有 PKCE/refresh，`src/outlook` 只能按请求解析短期 access token；token 不注入 in-process MCP config 或子进程。

## 异常与恢复

- metadata 缺失：该 server 未保存认证；不扫描 keyring 猜 ref；
- metadata 损坏/version 不支持：读写失败并保留原文件；
- credential ref 对应 secret 缺失/不可读：返回 credential not found 或 secrets backend 错误，进入 needs-auth/恢复路径，不用空值覆盖；
- 明确 MCP OAuth challenge 的只读调用执行下述有界刷新；通用写调用不自动重放。Core-owned Outlook/插件保留合同确认未执行的授权续接，和 SDK 共用原始 tool call 的一次额外发送预算；
- refresh 或调用出现 unknown/partial side effect：先检查 provider 状态，再决定是否重试；
- 日志、AG-UI、journal 和 JSON metadata 只投影 ref/状态与非敏感连接事实，不投影 token、client secret、headers 或 secret env value。

## User stdio

`~/.awaken/config/mcp-servers.json`：

```json
{
  "servers": {
    "playwright": {
      "stdio": {
        "command": "npx",
        "args": ["-y", "@playwright/mcp@latest"]
      },
      "enabled": true
    }
  }
}
```

这是 user scope 的唯一配置文件，也是磁盘 canonical shape。管理 API 可接收 `mcpServers` 的 `command`/`url` shorthand，但保存前会规范化为上述 `servers` + transport block；磁盘 loader 不把 API shorthand 当成第二种持久格式。Awaken 设置页对 user MCP 的读取、保存、修改和删除都操作这一路径，不使用 Electron `userData` 或其他旧路径。

## Project stdio

`<workspace>/awaken.mcp.json`：

```json
{
  "servers": {
    "context7": {
      "stdio": {
        "command": "npx",
        "args": ["-y", "@upstash/context7-mcp"]
      },
      "enabled": true
    }
  }
}
```

secret 不得写入示例或仓库；需要 env 时只引用运行环境中已存在的变量名。

该文件只在 core 配有有效 default workspace 时作为 project scope 参与加载；没有 default workspace 时不读取任何 project MCP 文件，user scope 仍独立可管理。

## HTTP/SSE

外部客户端常见的 Streamable HTTP 简写可以直接粘贴到 Desktop：

```json
{
  "mcpServers": {
    "remote-example": {
      "type": "streamable-http",
      "url": "https://mcp.example.test/mcp"
    }
  }
}
```

`type` 也可写成 `http` 或省略；管理 API 保存时统一规范化为下面的 Awaken canonical shape：

```json
{
  "servers": {
    "example": {
      "http": {
        "url": "https://mcp.example.test/mcp"
      },
      "enabled": true
    }
  }
}
```

OAuth access/refresh token 与 client secret 由 credential store 管理，不写入 config；provider 强制绑定在 endpoint query 中的 opaque access key 只能随完整 URL 保存，并按敏感配置处理。

只有一个 Streamable HTTP endpoint 时，也可以直接粘贴完整 URL：

```text
https://mcp.example.test/server/example?key=<credential>
```

Core 会生成稳定的 `remote_<hash>` 内部 identity、以 endpoint host 作为默认显示名，并规范化为 `servers.*.http`。identity 的 hash 不包含 query/fragment，因此同一 endpoint 的 key/token 轮换会更新原 server，而不是创建第二个身份。URL 仍可能包含远端要求的 query credential，Desktop 不得在提示、日志或验收截图中复述。

外部 JSON 的 server 名可以使用中文等非 ASCII 显示名：

```json
{
  "mcpServers": {
    "远程文档": {
      "type": "streamable-http",
      "url": "https://mcp.example.test/mcp"
    }
  }
}
```

原名称保存为 `displayName`；内部 server/tool identity 继续使用 ASCII-safe 名称。纯非 ASCII 名称会得到稳定 `server_<hash>`，不能因名称归一化为空而拒绝整份配置。

## Connector provider identity

Connector factory 可在生成的 server config 中附加 server-level `provider`：

```json
{
  "providerId": "connector:example",
  "displayName": "Example",
  "source": "connector",
  "dependencies": [
    {"kind": "mcp_connector", "name": "example"}
  ]
}
```

这只提供稳定 identity/dependency。MCP tool 是否可调用不依赖 server config 或 per-tool Awaken metadata；connected/auth-ready 且 schema 有效即可执行。若 server 希望让返回 bytes 进入 Awaken host Artifact 发布链，可在对应 `tools/list` item 的 `_meta["io.awaken.tool/provider/v1"].artifact_output` 中选择性声明，不能在 Awaken config 中替 tool 伪造结果契约。

## 禁止项

- 不提交 token、cookie、Authorization header 或 client secret；
- 不把 Electron `userData`、旧配置目录或任意自动发现路径写成 user MCP 配置来源，也不设计迁移或 fallback；
- 不用 `insecureSkipVerify` 作为常规配置；
- 不把 in-process 或 WebSocket 写成生产 transport；
- 不把 connector aggregate capability 或 per-tool metadata 当成 MCP 调用授权；实际远端权限由 MCP server 自身负责。

## 自动化

至少覆盖：

- plugin/user/project/dynamic 四 scope 合并（plugin 最低，用户/项目同名覆盖）、invalid/disabled、同名 owner 和 remove safety；plugin scope 保持 Agent Plugins 翻译后的字面 command/URL/headers/args/env/cwd 与未知 placeholder，不进入 user/project 通用 `${VAR}` 展开；`enabled:false` 在 Manager 中恢复为 disabled 且不连接，toggle 写回 effective scope；删除 project override 后恢复同名 user fallback；user config 唯一读写 `AWAKEN_HOME/config/mcp-servers.json`，Electron `userData` 与其他旧路径不读取、不迁移、不 fallback；stdio 在配置 env 之后写入 filesystem-resolved `PLUGIN_ROOT` / `PLUGIN_DATA` 并覆盖同名项；
- Codex/Claude/Cursor MCP adapter 的 stdio/HTTP/SSE config、vendor root/data/userConfig variables、未解析 placeholder fail closed、component/server/tool override 恢复；Agent Plugins 只设置 tool override、未设置整个 server desired override 时，Store 重载后仍保持该工具停用；plugin runtime reconcile 对 identity/scope/config 完全相同的 server 是 no-op，不关闭 session或注销工具，删除插件配置时只移除 `plugin__` owner、不影响 user/project/dynamic；disabled tool 保留 inspection 但不进入 Registry；Plugin Hook `mcp_tool` 只调用同插件 ready tool；
- `AWAKEN_DEFAULT_WORKSPACE` 为空时 user MCP 配置读取、保存、更新、启停、删除和连接仍可用，project scope 不参与且不回退 cwd、用户主目录或最近项目；配置有效 default workspace 时才加载 `<workspace>/awaken.mcp.json` 并验证同名覆盖；
- 管理 API 接受纯中文/非 ASCII `mcpServers` 名称，保存原始 `displayName` 并生成稳定 ASCII-safe identity；接受单个裸 `http://`/`https://` Streamable HTTP URL，生成不含 query credential 的稳定 `remote_<hash>` identity，并拒绝缺 host 或非 HTTP(S) URL；server snapshot 与 Desktop 卡片显示 `displayName`，内部 tool route 仍使用 canonical identity；

## 当前支持的实现

```text
~/.awaken/auth/connector-accounts.json
  scope + server name + canonical endpoint hash
              -> credentialRef、state、server/auth/token/redirect URL、
                 client ID、scopes、updatedAt、expiresAt

系统 secrets backend（macOS Keychain / Windows Credential Manager / Linux secret service）
  service=awaken-mcp, user=<credentialRef>
  -> access token、refresh token、client secret 与完整 StoredTokenSource
```

`go-keyring` 在 macOS 上通过 `security -i` 写入并限制单条命令大小；企业 Entra token 较长时，完整 `StoredTokenSource` 不得因单条 Keychain payload 超限而保存失败。大 payload 使用随机 revision 分片为多个 `awaken-mcp` Keychain 条目，主 `credentialRef` 只保存版本、分片数和 SHA-256 manifest；读取时必须验证完整性。新分片全部写入后才切换主 manifest，metadata 发布失败时按完整旧 payload 恢复；删除必须同时删除 manifest 和所有分片。分片、manifest 和 payload 仍全部位于系统 secrets backend，磁盘 metadata 不增加任何凭据字节。

## 只读 OAuth challenge 与共享发送预算

`auth_call.go` 在 Manager 原始工具调用 context 中绑定配置/credential identity 与连接 generation；HTTP transport 与 SDK OAuthHandler wrapper 共同拦截恢复。只接受 bearer challenge，业务 JSON 中的 401 不参与。复用 McpToolAdapter 静态与混合读操作判断；配置或连接身份改变则拒绝旧调用重放。`persistentOAuthHandler` 的可取消授权锁合并同一身份的并发刷新，刷新前后核对 credential store，使用同一 token endpoint 与 scopes；已由并发调用更新的 token 直接复用。

`src/tool/auth_replay.go` 保存原始调用的一次额外发送预算；ToolRuntime ExternalActionGate 和 SDK 授权恢复共享。`NeedsAuthError.CallStarted/ReadOnly` 传给 Outcome：发出请求后写操作保留 unknown，只读保留 none；初始未发出才是 not_started。`io.awaken.tool/error/v1` 不承担认证控制。

`auth_call_test.go` 使用真实 SDK Streamable HTTP 和本地 OAuth token endpoint，核对只读 401 的 2 次发送/1 次刷新、写操作 1/0、403、新增 scope、重复 401、刷新失败、业务 401 与并发合并。运行 `go test -race ./src/mcpclient -run 'Test(.*Auth|.*Refresh|HTTPCallAuth|RejectedToken)'`。这证明受控协议行为，不等于第三方实际 OAuth 账号或跨平台已验收。

## Manager 有界关闭

`shutdown.go` 的 BeginShutdown 同步关闭准入并取消 operation context，call gate 等待可被取消。Shutdown(ctx) 幂等可再次等待，在全局锁外并行关闭 session，等待连接循环、调用与排队者退出后关闭订阅；deadline 到达立即返回错误，不能把阻塞 Close 当作成功。Core 负责总期限与最终 Journal flush，见[本地服务管理](../../03_运行时与本地服务/本地服务管理/实现方案.md)。`shutdown_test.go` 覆盖阻塞 Close、回调获取 Manager 锁、排队取消、deadline 与再次 join。

### 运行可靠性的验证范围

SDK 的取消通知及 elicitation 响应可能携带原工具调用 context，但不是 tools/call 重放；transport 仅对工具调用计数，取消优先返回 context 错误，不能因退出时连接关闭而污染 needs-auth。回归测试覆盖关闭状态下通知仍可发送且不消耗预算。macOS Desktop 的活动表单、排队调用与子任务复合退出已复验，没有新的认证误报或退出后调用，见[受控证据](../../../apps/desktop/test-fixtures/run-reliability/verification.json)。OAuth 的 401/403、并发刷新与发送次数由真实 SDK 加本地 token endpoint 验证；第三方实际账号、真实 scope 升级和跨平台凭据后端未执行。
