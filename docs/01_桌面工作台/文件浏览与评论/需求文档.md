# 文件浏览与评论 · 需求文档

用户在右侧文件工作区浏览项目文件、预览内容，并把代码或文本行评论随消息发送。项目 Markdown、HTML、已知代码和安全纯文本支持编辑与自动保存；其中只有 Markdown 默认渲染预览，其他文本一律显示源码。临时 Artifact、Office、PDF、图片和视频保持只读。

代码、接口和验证方法见[实现方案](实现方案.md)。

## 编辑内容的归属

自动保存始终属于产生该修改的文件和项目。输入后立即切换或关闭文件，保存不能转发到新选中的文件；开始、结束 Agent 运行或暂时禁用评论不能重置编辑内容。未知扩展名或无扩展名文件经安全文本检查获准编辑后，也必须能在相同大小和路径限制内保存。

## 当前用户行为

主 Workbench 保留右侧 rail、折叠按钮、拖拽/键盘 resize 和响应式自动折叠。普通展开态始终按固定顺序提供“文件”和“浏览器”；子任务行直接在顶栏打开独立执行标签，不再提供右栏“子任务”列表入口；ready 文档、图片和视频交付物统一进入右侧“文件”工作区的临时 Artifact 文件标签，运行过程媒体继续留在 `RunStage.overlay`：

“浏览器”是同一 Inspector 里的独立标签：只展示可编辑地址栏与网页，不显示右侧文件树。公开网页留在应用内。当前没有审阅、终端、侧边任务等其他入口。点击“文件”后进入带目录树的项目文件工作区；点击“浏览器”只铺满网页。

“当前项目”优先采用当前活动 thread 的稳定 `projectId`，没有活动 thread 时采用侧栏当前选择的项目；独立对话或未选项目显示选择项目空态。项目没有绑定文件夹时显示无文件夹空态，不回退到默认 workspace、进程 cwd 或用户主目录。

点击中心子任务行后在右侧标签页打开执行详情，具体规则见[子智能体协作](../../02_主智能体闭环/子智能体协作/需求文档.md)。文件预览在切换子任务期间保持挂载，返回文件标签恢复原预览和目录状态。

连接器和技能是独立功能页，不使用 Workbench Inspector。进入这两个页面时，Desktop 必须同时隐藏 Inspector、resize handle、分隔线和顶栏展开/收起按钮，不为右栏保留空白宽度。返回主 Workbench 后恢复用户原有的右栏宽度和折叠偏好，不因路由切换改写它们。

浏览器标签始终显示可编辑地址栏与后退/前进/刷新（加载中切停止），内容区只显示网页，不显示文件树。空态提示输入网址或本地 HTML 路径。尚未开始对话时地址栏仍可打开公开网页或本机 HTML，不要求先有 thread。公开网页只允许 http(s)；本地 HTML 接受 `file:` 和本机绝对路径（例如 `/tmp/index.html`），在隔离 guest 中渲染页面，相对 CSS/脚本/图片按普通浏览器文件页加载。`mailto:` / `tel:` 交给系统；`javascript:`、`awaken-preview:` 和其他自定义 scheme 被拒绝。项目 `.html` / `.htm` 从文件树打开时仍留在文件标签，按源码编辑并自动保存，不渲染预览，也不自动切到浏览器。本地 HTML 页内点到 http(s) 会切到内置公开网页，不再打开系统浏览器。每个 Inspector 浏览器标签各自一页。切换标签或会话不能把上一页交给新标签；切回同一会话和标签时按最新地址重新加载，不保留已卸载页面的表单与滚动状态。公开网页使用 `persist:awaken-browser`；地址栏打开的本地 HTML 使用非持久 `awaken-local-html-*` 分区；Office 转换后的 HTML 仍用独立 `awaken-preview` 分区，三者不能混在一个持久化分区。网页画在地址栏下方同一层的页面槽里，不使用盖住整窗的覆盖层。切到文件/子任务/交付物、折叠 Inspector 或进入连接器/技能页时卸载该页。打开 Dialog/菜单时页面槽仍显示当前页（最后一帧占位），弹窗叠在前面，不能把网页藏成空白。关闭浏览器标签即销毁该页，不能留下无法点击的覆盖层。

Agent 的 `browser_navigate` / `snapshot` / `click` / `type` / `wait` / `extract` 只驱动公开网页，不读取或修改地址栏本地 HTML 与 Office guest。首次导航会打开浏览器标签并加载目标网址，不要求用户先手动打开网页。当前是本地 HTML 时，Agent 导航到 http(s) 必须切到公开网页分区。无 Desktop Host 时这些工具不进入 run 快照。可见租约要求当前屏幕是该 thread 的浏览器标签；click/type 还要求真实 viewport。明确的用户地址栏导航或 Agent 导航准入 origin；页内跳转与重定向跨 origin 后取消操作准入，click/type 需重新导航。下载管理、书签、历史 UI 和浏览器内部多页标签当前不做。

因此旧“Right Inspector Rail”切片中下列描述已经失效：

- 完整InspectorTabs；
- selected tool args/result面板；
- Changes patch/turn diff面板；
- Files详情；
- Browser disabled tab；
- approval detail selection。

## 当前壳与布局

文件工作区内部不再显示路径栏。「文件」和「浏览器」入口位于顶栏标签与标签栏 `+` 弹出的选择菜单。空浏览器显示可编辑地址栏，文案为输入网址或本地 HTML 路径；从文件树选择项目 HTML 仍留在文件标签，显示可编辑源码。在浏览器地址栏输入 `file:` 或本机绝对路径则渲染该 HTML。浏览器标签不显示右侧文件树，切回文件标签后恢复原目录树宽度。

右侧标签栏统一显示 `+`（新建标签）。当前打开 subagent、项目文件、文件夹目录或浏览器时，点击它在按钮下方弹出「文件」「浏览器」两项菜单，不把 Inspector 整页换成入口页，也不做成命令面板。菜单打开期间保留已有标签和当前预览；选中一项后才新增对应空槽位。也可直接点击已有标签返回原预览。没有关联项目时仍可打开菜单，选择后再提示选择项目。

折叠文件工作区只隐藏面板和顶栏展开/收起控制，不关闭文件标签；重新展开仍回到同一文件工作区并恢复“展开面板”。连接器/技能等独立功能页继续隐藏整个 Inspector。

## 已有但未接线的数据

Desktop reducer/projector当前持有：

- `narrative.inspectorSelection` union；
- tool args、result、status、bounded command output和truncated flag；
- artifacts和role/status/path；
- patch/turn diff数据；
- `inspectorSummary.lastToolDecision`；
- context window摘要。

上述通用 tool/artifact 数据当前仍未接线，不等于右侧已经支持通用工具详情。子任务执行标签是独立的入口，只消费 reducer-owned `SubagentTaskView`，不从 root narrative 或通用 tool record 反推 task。

终态 ready 媒体标签只保存 `threadId + runId + artifactId + title + mediaKind`，不保存 opaque `src`；`useArtifactMediaSources.ts` 从 `awaken-artifact://` source cache 派生可用 source/metadata，并在解码失败时按同一 Artifact identity 有限次续签。图片和视频由 `ArtifactMediaPreview` 直接渲染，视频启用 `controls`、`playsInline` 和 `preload="metadata"`。该入口不消费 `narrative.inspectorSelection`，不从标题或可见路径反查 artifacts，也不恢复旧的专用“媒体”侧栏。

## 当前不支持

- Office、PDF、图片与二进制预览中的行评论；项目 Markdown 在源码态已复用连续行评论，渲染态可从文本选择跳转到源码评论，范围与安全边界见[文件行评论设计契约](实现方案.md)；
- 通用 tool/artifact Inspector tabs 和 selection；
- 命令输出详情；
- patch/turn diff详情；
- Word、Excel、PowerPoint 或其他非安全文本文件的编辑和保存；
- 从交付卡打开的临时 Artifact Markdown 编辑和保存；
- Markdown 另存为、未保存冲突合并、从 Inspector 新建 `.md` / `.markdown` 文件；
- `.doc` / `.xls` / `.ppt`、HEIC、TIFF、RAW 等非首期格式预览；
- 文件标签跨项目保留和标签跨重启恢复；
- 同时打开多个会话标签、关闭会话标签或在顶部新建会话标签；
- 未展开目录的递归/全项目搜索；
- 下载管理、书签、历史 UI、浏览器内部多页标签，以及用搜索框打开任意文件；相对项目路径（例如只输入 `index.html`）不会自动解析为当前项目文件；
- 本地 HTML 与公开网页不共用同一套后退/前进历史；离开本地页需再输入 http(s) 或点到页内链接；
- 完整互联网浏览器能力中的上述未做部分；Office HTML 不进入联网浏览器；
- approval恢复；
- Inspector状态跨thread持久化。
- Subagent 完整 transcript、完整 cost 统计、窄屏专用 sheet 和 selection 跨重启恢复。

## 范围与实现状态

状态分层：

- **当前支持**：项目代码/纯文本（含 HTML）和 Markdown 源码支持单行与连续多行整行高亮、选区末行 `+`、评论编辑/只读卡；Markdown 渲染预览还支持选择文本后“添加到对话”或跳转源码评论。评论与已选文本片段作为 thread Composer 的结构化文件上下文，可与正文、token、附件一起发送；评论还可独立发送。Composer 与历史用户消息分别显示“`N 个评论`”和“`N 个已选文本片段`”，悬浮详情展示文件、行号、选中内容及可选评论正文。Core 在创建 run 前复验项目、路径、digest、行范围和 excerpt，把评论指令、选择上下文与不可信源码片段分开注入模型，并随 `user_message` 耐久重放。
- **当前不支持或已知缺口**：Office、PDF、图片与二进制预览不支持行评论或选择上下文；未发送草稿不跨 Desktop 重启；已提交评论不能原位编辑或回复；不支持多光标、不连续选区、跨文件拖选和协作 code review。评论详情当前由 hover 立即打开、离开后短延迟关闭，尚未实现 300ms 打开延迟、Prompt 复制时追加评论纯文本，以及切换非空未提交编辑卡前的防丢确认。
- **已确认但尚未实现的设计约束**：上述已知缺口只有在代码、测试和 Desktop 验收同时实现后才能改写为当前能力。

本文覆盖代码/纯文本项目文件预览与 Workbench Composer 的跨 surface 协作。既有 Composer 文本、Slash、token 和附件规则仍由[输入、斜杠菜单与附件](../消息输入与编辑/实现方案.md)拥有；文件读取与预览安全仍由[右侧栏当前支持边界](需求文档.md)和[文件预览架构契约](实现方案.md)拥有；中间区域容器边界仍由[架构契约](../工作台布局与运行展示/实现方案.md)拥有；`user_message` 耐久顺序与 route/wire 分别仍由 03、09 功能域拥有。

文件选区末行左侧显示 `+`，点击后在选区下方打开评论输入卡。提交后保留文件内评论卡，并在输入区显示评论汇总；悬浮汇总可查看文件、行号、选中内容和评论正文。

## 当前目标与首版范围

### 用户目标

用户无需复制文件路径、行号和代码，即可完成以下闭环：

1. 在项目代码或纯文本预览中选择连续的一行或多行；
2. 通过选区末行 gutter 左侧的 `+` 打开评论输入卡；
3. 提交一条非空评论；
4. 在原文件相同行范围看到评论卡，在当前 thread 的 Composer 看到“`N 个评论`”汇总；
5. 悬浮或聚焦汇总，核对每条评论的项目相对文件、行范围、选中内容和评论正文；
6. 与普通正文、token、附件一起发送，或仅发送评论；
7. AI 收到经过 Core 复验的文件 identity、行范围、当前选中内容和用户评论；历史 prompt 可耐久重放这些评论。

### 首版支持矩阵

| Surface / 文件类型 | 选择行并评论 | 原因 |
| --- | --- | --- |
| 项目文件树打开的代码与纯文本，包括 HTML 以及 Main 有界探测确认的安全文本 | 当前支持 | 当前统一进入 CodeMirror，存在稳定的 1-based 行模型和选择范围 |
| 项目 Markdown 源码 | 当前支持 | 与代码/纯文本共用 CodeMirror 行模型、整行高亮与评论 widget |
| 项目 Markdown 渲染预览 | 当前支持选择上下文与跳转评论 | 只使用 Markdown parser 的 source position 映射源码行；评论先切到源码态并恢复完整行 selection |
| 临时 Artifact Markdown | 当前不支持项目评论/选择上下文 | Artifact identity 与项目文件 identity 不同，保持只读且不接项目 draft |
| Office、PDF、图片 | 当前不支持 | 当前查看器没有统一的文本行与选区协议，Office 还位于隔离 guest 中 |
| 二进制、解码失败或超过 2 MiB 的文本 | 当前不支持 | 文件本身不会进入文本预览 |

首版只允许一个连续 CodeMirror selection。多光标、多段不连续 selection、跨文件一次拖选、对评论回复、编辑已提交评论、跨设备协作和服务端 code review 不属于本期。

## 产品交互契约

### 选择与 `+` 入口

- 普通鼠标拖选、Shift+Click、Shift+方向键均沿用 CodeMirror 原生选择；评论扩展不得接管或清除编辑器原生 selection。
- collapsed 光标所在行视为单行候选；非空选择覆盖从 `from` 到 `to` 实际触达的连续行。如果 `to` 正好等于后一行的 `line.from`，则末行取前一行，避免只因 selection endpoint 落在行首而多选一行。
- selection settled 后，若预览属于支持范围、当前 run 非 busy、当前 thread 可接收草稿且没有评论输入卡正在提交，则在 `endLine` gutter 左侧显示一个 24×24 的 `+` 按钮。拖动 selection 的过程中不追逐指针闪烁，下一次 animation frame 稳定后再定位。
- 单行时按钮与该行垂直居中；多行时按钮与选区最后一行垂直居中，符合“在选区末端添加评论”的空间关系。
- 点击 `+` 不改变 CodeMirror selection，打开选区下方的评论输入卡并把焦点移入 textarea。键盘路径为 `Cmd/Ctrl+Shift+M`，作用于当前有效 selection；按钮 accessible name 为“评论第 X 行”或“评论第 X 至 Y 行”。
- 预览切换、文件标签关闭、项目切换、thread 切换或 preview identity 变化时关闭未提交的评论输入卡；已经提交到 Composer 草稿的评论不因此删除。

### 评论输入卡

- 输入卡使用 CodeMirror block widget 锚定在 `endLine` 之后，属于代码内容滚动坐标，不使用 `RunStage.overlay`、`position: fixed` 或新的页面级滚动容器。
- block widget 必须忽略 CodeMirror 的编辑器级事件处理，由卡片内 textarea 和按钮自行接收 pointer、keyboard、input 与 focus 事件；焦点进入 textarea 后不得被编辑器抢回。
- 卡片 header 显示当前用户与“评论于第 X 行 / 第 X–Y 行”；正文为普通多行 textarea，placeholder 为“添加评论”。
- 评论正文 trim 后为空时“评论”按钮禁用；最大 4 KiB UTF-8，超过后保留草稿并显示明确计数错误。
- `Cmd/Ctrl+Enter` 提交，Escape 取消未提交输入，`Shift+Enter` 换行。点击“取消”或 Escape 不创建 draft comment，也不清除文件 selection。
- 同一时刻只允许一个未提交输入卡。用户在另一 selection 点击 `+` 时，如果现有输入为空则直接移动；如果已有非空正文，保留原卡并提示先评论或取消，不能静默丢弃。

### 文件内已完成评论

- 点击“评论”后立即创建一条当前 Composer owner 的 draft comment，并把输入卡原位替换为只读评论卡；同一行范围可存在多条评论，按 `createdAt + id` 稳定排序并在同一 block widget 内堆叠。
- 评论卡显示用户、项目相对路径、`Lx` 或 `Lx–Ly`、评论正文，并提供“删除”。首版不原位编辑；需修改时删除后重新添加。
- 仅当前 active Composer owner 的 draft comments 投影在文件中。切换 thread 后，同一文件只显示新 thread 的评论；返回原 thread 后恢复其内存草稿。
- 成功创建 run 后，评论离开草稿并进入该 turn 的耐久 prompt，文件内 draft 评论卡随 Composer 清空。发送失败则连同正文、token、附件一起恢复；若失败原因是文件变化，评论卡保留并标记“文件已变化，需要重新选择”。
