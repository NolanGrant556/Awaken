# Awaken 工具平台规范

本规范是 `docs/04_工具权限与审批/当前规范/全量无审核工具运行时落地方案.md` 的执行口径。Awaken 的正式方向不是更聪明地弹审批，而是：默认自动执行或直接拒绝，危险动作由运行时内建边界拦截或转换，删除默认进系统回收站，缺依赖/缺授权进入安装或授权恢复流程；除工具群发消息外，不再让用户在任务中途审核工具调用。

Shell 专项执行口径见 `docs/04_工具权限与审批/当前规范/Shell内置权限执行器设计.md`。shell 是 Awaken 内置本机执行面，不以项目文件夹、`readable_roots`、`writable_roots`、sandbox support、open-world 分类或敏感路径规则作为权限边界；shell 保留三类产品级硬边界：永久删除命令直接拒绝并引导使用回收站工具，工具群发消息进入专用人工审核，直接启动 `soffice` / `libreoffice` 则拒绝并改走受监督的 typed Office artifact tool / `OfficeRenderWorker`。第三类是运行时路由约束，不是用户审批；`command -v soffice`、搜索或输出名称等诊断性引用仍允许执行。

旧 `allow | ask | deny`、`always_ask`、通用 Approval Center、`AWAKEN_APPROVAL_REQUESTED` / `AWAKEN_APPROVAL_RESOLVED`、`/v1/runs/{run_id}/approvals/{approval_id}/resolve` 只允许作为历史 transcript 只读兼容概念，不得作为新 run 的可达路径。

## ToolDefinition v2 能力契约

`ToolDefinition v2` 是工具能力的单一事实源，来源包括 `builtin`、`mcp`、`connector`、`skill`、`plugin`。Registry 保存 runtime 与 resolved definition 的不可变快照；RequestBuilder、`GET /v1/tools`、permission/audit 投影都从该快照派生，不再分别读取 `Description()` 和 `Definition().Description`。

Resolved definition 必须包含：

- `name`：全局唯一工具名，保留 `mcp__`、`skill__` 等命名空间。
- `display_name`：面向 UI 的名称。
- `source`：工具来源。
- `description`：不重复 purpose 的短摘要。
- `purpose`、`when_to_use`、`when_not_to_use`：选择工具和相邻工具边界。
- `input_schema`：与执行前 validator 共用的递归 JSON Schema。
- `output_schema`：只描述 canonical Outcome 内的 tool-specific `details`，不得重复 `status/errors/changes` 等 envelope 字段。
- `side_effects`：资源类型、影响与 `reversible/conditional/irreversible/unknown`。
- `permissions`：capability、workspace/file bridge/network scope、auth/review 声明；声明不替代 runtime 授权。
- `examples`：通过同一 input validator 的调用示例。
- `failure_modes`：稳定 error code、cause、retryability 与 recovery。
- `annotations.readOnly`：是否只读。
- `annotations.destructive`：是否会删除、替换现有资源，或发起不可逆/高风险外部动作；普通可恢复的创建或更新不因“发生写入”自动标记 destructive。
- `annotations.openWorld`：是否访问外部网络。
- `annotations.requiresAuth`：当前调用是否依赖授权。
- `capabilityClass`：能力类别，固定为 `artifact_read`、`artifact_write`、`connector_read`、`connector_write`、`browser_read`、`browser_interaction`、`local_transform`、`mass_message_send`、`external_publish`、`system_operation`、`unknown` 之一。
- `trustedOrigin`：信任来源，如 `builtin`、`official_connector`、`third_party_mcp`、`local_skill`。
- `fileBridgeScope`：文件桥范围，第三方 MCP 默认 `none`。
- `networkScope`：网络访问范围。
- `requiresAuth`：授权需求及 provider 信息。
- `massMessageMetadata`：仅 `mass_message_send` 必填，包含渠道、收件范围、数量、正文/模板、附件、发送账号、来源工具。

注册模式：

- `compat`：legacy/MCP/Skill 可由 `ResolveDefinition` 保守补齐，记录 `origin`、`strict/adapted/incomplete` quality 和 warnings；不得编造 example/failure mode。
- `strict_builtin`：30 个可执行静态 builtin 与运行时 `skill_install` 使用该模式；缺任一 v2 契约或 schema/example lint 失败时拒绝注册。
- `strict_all`：用于受控一方扩展，当前包括固定系统工具 `skill_resource_read`；第三方 MCP 仍允许 conservative adapter。

模型描述由 resolved purpose/when/not/effects/returns 编译，并在 provider 预算内优先保留 when-not、安全副作用和 permission 边界。缺元数据不能降级成通用人工审批。

`GET /v1/tools` 对每个工具返回全部 resolved fields。动态外部工具的 `examples` / `failureModes` 在缺少可验证元数据时保持空数组，不编造内容，并由 `quality` / `warnings` 表达缺口。

## 决策模型

`Decide()` 的唯一输出动作是：

- `allow`：自动执行。
- `deny`：结构化拒绝，工具不执行。
- `transform`：自动转换到更合适的安全链路，例如永久删除意图转换为回收站删除。
- `needs_auth`：缺授权，工具不执行，发起授权确认/授权链接流程。
- `needs_runtime`：缺 runtime，工具保持对模型可见，调用时在执行前返回结构化 `needs_runtime`，并进入 runtime 准备/修复流程。
- `unsupported`：当前平台或能力不支持，结构化拒绝。
- `needs_mass_message_review`：仅 `mass_message_send` 可进入的专用群发消息审核 gate。

`Decide()` 不得返回 `ask`，不得创建通用审批请求。用户 override 只能配置 allow/deny/能力范围，不允许配置 `always_ask`。

默认规则：

- 只读、workspace 内、安全 file/artifact/connector read 按 `TaskScope` 自动执行。
- typed file/artifact tools 的文件写入只能在 `writable_roots` 或 `output_roots` 内执行；越界、protected root、symlink 逃逸直接 `deny`。
- shell 可以读取、写入和操作项目外本机路径，是否成功由操作系统权限和命令退出码决定。
- 删除文件和目录必须经 `TrashAdapter` 进入系统回收站；TrashAdapter 失败时 fail-closed，不得永久删除。
- 远端删除、发布、提交、付款等未明确配置能力范围的外部写入直接 `deny`。
- 缺授权统一 `needs_auth`，由 Desktop 展示授权确认和授权链接。
- 缺 runtime 统一 `needs_runtime`，相关 typed artifact tools 保持注册与可见，调用时在产生副作用前返回 runtime 缺口和恢复动作。
- 群发消息统一 `needs_mass_message_review`，审核通过前不得调用真实发送接口。
- shell 不需要 `require_escalated`、`dangerouslyDisableSandbox`、`allow_unsandboxed`、`full_access`、`extra_writable_roots`、`network_open` 等模型输入扩权语义；这些字段不得绕过永久删除、群发审核或 Office runtime 受监督启动边界。

## TaskScope

每个 run、subagent、connector/file bridge、typed artifact tool 都必须携带 `TaskScope`：

- `scope_id`
- `workspace_root`
- `readable_roots`
- `writable_roots`
- `output_roots`
- `protected_roots`
- `attached_files`
- `connector_resources`
- `temporary_work_root`
- `execution_profile`

工具执行必须基于 `TaskScope` 做路径归一化、附件名解析、文件桥约束和产物落点约束。第三方 MCP 默认没有文件桥；官方 connector 也只能按当前 `TaskScope` 申请受限文件桥。

Awaken 内置 shell 和内置本地读工具是例外：shell 以本机路径和操作系统权限为准，不使用 `TaskScope` 作为读写边界；`read_file`、`read_artifact`、`list_files`、`grep_search`、`pdf_extract`、`image_inspect` 等本地读输入不使用 `readable_roots` 作为拒绝边界，可读取本机路径、相对当前工作区路径或已上传附件文件名。TaskScope 仍用于记录附件、workspace、输出目标和 typed tool/file bridge 的边界。

- `AWAKEN_MASS_MESSAGE_REVIEW_RESOLVED`

## 群发消息审核

`mass_message_send` 是唯一允许人工审核的工具能力。审核 payload 必须包含：

- 收件范围
- 收件数量
- 渠道
- 正文或模板预览
- 附件
- 发送账号
- 来源工具

审核通过只对本次工具调用有效。拒绝后不发送、不重试、不改道其他工具。非群发工具不得进入该 gate。

## Typed Artifact Runtime

Work 场景必须优先使用 typed artifact tools 和打包 runtime，不依赖开发机 Python/Node、Codex cache 或临时复制源码。

第一批内建工具：

- `workspace_dependencies`
- `runtime_preflight`
- `artifact_read`
- `artifact_inspect`
- `artifact_render`
- `artifact_export`
- `spreadsheet_create`
- `spreadsheet_edit`
- `document_create`
- `document_edit`
- `presentation_create`
- `presentation_edit`
- `presentation_render`
- `pdf_extract`
- `image_inspect`
- `image_convert`
- `media_probe`

Office/PDF/图片/音视频工具运行前必须经过 `runtime_preflight` 或工具内置 runtime resolver。缺 runtime 时发出 `AWAKEN_RUNTIME_MISSING` 或明确执行错误，工具保持可见并给出缺口，避免模型改道 shell。shell 不得直接启动 `soffice` / `libreoffice`，包括通过常见 wrapper 间接启动；必须改用相应 typed Office artifact tool，由 `OfficeRenderWorker` 统一管理进程、环境和结果。只查询可执行文件位置或搜索相关文本等诊断动作不属于启动。OCR、扫描 PDF 文字识别和 searchable PDF 不属于当前计划。

### PPT 生成与渲染边界

`presentation_create` / `presentation_edit` 不是普通文件写入工具，而是 PPT artifact executor。模型必须用结构化参数描述演示稿，不得用 shell、`apply_patch`、ZIP/XML 拼装 `.pptx`，也不得手写 CJK/XML font helper。

当前结构化输入至少覆盖：

- `theme`：`background`、`surface`、`primary`、`accent`、`text`、`muted`、可选 `font_latin` / `font_ea`。
- `slides[]`：`title`、`subtitle`、`body`、`bullets`、`images`、`notes`、`layout`。
- `layout` 固定 enum：`title`、`section`、`bullets`、`two_column`、`image_right`、`comparison`、`metrics`、`timeline`、`closing`；未知 layout 执行前失败，不得静默回退。
- `slides[].images[]`：`path`、`fit`、`caption`、`alt`、`x/y/width/height`。
- `render_preview`：默认保留 PDF/PNG 预览文件；`false` 只表示不保留预览路径，**不得跳过技术验证**。

`presentation_edit` 必填 `source_path` 与非空 `edits`，只允许增量 `update|replace|delete|insert`；未修改 slide 必须保留。禁止把全量重写继续描述成 edit。

本地图片素材可使用本机路径、相对当前工作区路径或已上传附件文件名；预览输出目录必须位于 `writable_roots` 或 `output_roots` 内。

### PPT 验证等级

工具结果必须返回 `verification_level`：

- `package`：PPTX 包可重新打开。
- `pdf`：LibreOffice 转 PDF 成功。
- `png`：Poppler 全部页转 PNG 成功，且 slide/PDF/PNG count 一致。
- `visual`：预留给后续视觉检查。

`verified=true` 至少要求 package + pdf + png，且 slide count、PDF page count、PNG count 一致。Poppler 失败、count 不一致或 runtime 缺失时：

- `verified` 必须为 `false`
- 可返回 `needs_runtime=true` 与 warnings
- 不得伪装成功

overflow、空白页、缺图进入 warnings；严重 package 损坏直接失败。

`presentation_render` 是独立的渲染检查工具，负责将已有 `.pptx` 转成 PDF 与 PNG 页面预览。它会写预览文件，因此按 artifact write 能力治理，不得伪装成只读工具。LibreOffice/Poppler 缺失时返回明确 runtime 缺口，不能改道 shell，也不能把失败标成 `verified=true`。

默认单元测试必须使用 temp runtime + fake probe/renderer，不得依赖用户 cache、Codex cache 或本机已安装 Office。真实 LibreOffice/Poppler integration smoke 属于 Phase 6 / Desktop 验收。

## ExecutionOutcome v2

工具与 executor 返回给 `ToolRuntime` 的唯一结构化结果是 `tool.ExecutionOutcome`（协议名 ToolOutcome）。业务失败、process nonzero、deny、needs_auth、needs_runtime、unsupported 必须写在 outcome 中；Go `error` 只表达 transport/implementation 异常。

固定 Status：`succeeded`、`failed`、`denied`、`cancelled`、`interrupted`、`needs_auth`、`needs_runtime`、`unsupported`、`review_required`。

固定 TransportStatus：`not_started`、`completed`、`failed`、`cancelled`、`unknown`。

固定 SemanticStatus：`success`、`failure`、`neutral`、`unknown`。

固定 ProcessStatus：`not_applicable`、`exited`、`timed_out`、`signaled`、`spawn_failed`、`unknown`。

兼容字段：

```text
IsError =
  Status in failed, denied, cancelled, interrupted, needs_auth, needs_runtime, unsupported
  OR SemanticStatus == failure
```

禁止用 `IsError` 反向推导完整 Outcome。`ToolExecutionResult` 的兼容字段全部由 outcome 派生。

所有工具结果在唯一 finalizer 归一化为 `schema_version=2`，新增字段：

- `summary`
- `operation.type/target/side_effect_state`
- `changes[]`（resource/action/certainty/reversibility/details）
- `artifacts[]`
- `environment`（observation/observed_at/scope/source/unobserved）
- `warnings[]`
- `errors[]`（type/category/stage/cause/possible_fixes/retry_strategy）
- `next_actions[]`
- `details`（工具专属机器 payload）

对 v2/`OutcomeTool`，`content` 只保留 legacy/人类可读兼容，永不作为状态、错误、trash path 或文件变化的事实源。只有 legacy result adapter 可为旧返回保守推断变化，且必须标记 `ChangeInferred`。`side_effect_state` 固定为 `not_started/none/applied/partial/unknown`；失败不等于无副作用。permission 预测路径与 executor 实际路径必须分开，只有 executor-observed path/change 可进入 `changes[]`。

RequestBuilder 与 ToolRuntime 必须使用 registry snapshot 中同一份 `input_schema`；v2/MCP object 参数不得在执行前被 legacy 单参数逻辑改形。已迁移 strict definition 的 `details` 必须通过其 `output_schema`，否则返回 `tool_output_schema_mismatch`、stage=`verification`，并保留可能已经发生的 partial/unknown side effects。声明可变更但没有 executor-observed delta 的成功调用必须返回 `side_effect_state=unknown`，不能猜为 `none`。

Normalize/output verification 必须早于任何 completed progress、artifact 发布和 success audit，直接与 transform 路径共用同一 terminal gate。ModelPayload 对已规范化 v2 Outcome 只做去敏限长投影，不得用缺失 declared side effects 的空 context 重新 Normalize。

Model、journal、AG-UI 与 audit 共用同一 canonical Outcome 事实基础：model 在深拷贝后递归去敏并限长，单个结构化字段最大 8 KiB，超限仍返回合法 JSON truncation envelope；journal 当前仍持久化 canonical Outcome，字段级 sensitivity/retention/access policy 是后续项；AG-UI 不从 content 反推状态，telemetry 不记录 secret/content 全文。MCP `CallToolResult.IsError=true` 必须映射为 transport completed + semantic failure，不得以文本前缀冒充成功；成功 `StructuredContent` 进入 schema-backed `details`。

`ToolResult` / `ToolProgress` 事件必须携带：`toolStatus`、`transportStatus`、`semanticStatus`、`processStatus`、`processExitCode`、`processTimedOut`、`errorCode`、`errorCategory`、`retryable`、`recoveryOptions`、`durationMs`，以及宿主活动字段 `toolProgressStage` / `toolProgressMessage` / `toolProgressPercentage`。

Desktop 保留 canonical `toolStatus`，显示状态映射为：succeeded→done，failed→error，denied→denied，cancelled→cancelled，interrupted→interrupted，needs_auth/needs_runtime/review_required→blocked，unsupported→unsupported；仅有 ToolCall 尚无 ToolResult 时为 active。禁止用 content 是否为空或中文错误子串判断状态。

宿主活动描述由 `ActivityDescribingTool` + `ToolRuntime` 在执行前生成；Runner 不得再发通用 “Executing tool” / “Tool execution complete/failed” 双发进度。

完整字段、枚举与场景映射见 `docs/02_主智能体闭环/智能体能力与执行稳定性提升/实施方案.md` 第 6 节。

## 文本编辑与 apply_patch 降级（Phase 3）

普通单文件精确修改默认使用 `text_edit`，参数固定为：

- `path`
- `old_string`
- `new_string`
- `replace_all`（可选，默认 false）
- `expected_sha256`（可选，来自 `read_file` Diagnostic）

规则：

1. `path` 必须通过现有 `PermissionContext` / writable roots。
2. `old_string == new_string` → validation 失败。
3. 零匹配 → `text_not_found`。
4. 多匹配且未 `replace_all` → `text_not_unique`。
5. `expected_sha256` 不匹配 → `stale_file_revision`。
6. 同目录临时文件、保留权限、fsync、atomic rename；失败不得破坏原文件。
7. 成功结果包含 affected path、replacement count、before/after digest、unified diff。

文件工具路由：

| 场景 | 工具 |
|---|---|
| 普通单文件精确修改 | `text_edit` |
| 新建/覆盖普通文本 | `text_file_create` |
| 显式删除 | `trash_file` |
| 多文件 / 移动 / 删除 / 高级 diff | `apply_patch` |

`read_file` 的 `ExecutionOutcome.Diagnostic` 必须包含 `sha256`、`size`、`mtime`；模型 payload 可通过 `expected_sha256` 拿到 digest。纯文本 `Content` 保持兼容。

### ToolExposurePolicy

`RequestBuilder` 通过 `tool.ToolExposurePolicy` 过滤模型可见工具池：

- 普通 provider 默认隐藏 raw `apply_patch`，保留 `text_edit` 与其他 file tools。
- `ExposureCompat`：内部 transform / 兼容测试可继续暴露 `apply_patch`。
- `ExposureGrammarCapable`：仅当 provider transport 真正支持 grammar constrained decoding 时暴露 grammar 版 `apply_patch`。
- 不得在 prompt 中声称 `apply_patch` 已 grammar constrained，除非 transport 真实支持。

`apply_patch` parser/matcher 错误码：

- `patch_missing_begin`
- `patch_missing_end`
- `patch_invalid_hunk_header`
- `patch_invalid_line_prefix`
- `patch_context_not_found`
- `patch_context_ambiguous`
- `patch_stale_file`

并保留 `invalid_patch_format` / `patch_context_mismatch` 作为 FailureSupervisor 恢复映射的粗分类。

## FailureSupervisor 与硬预算（Phase 7）

每个 run 由 `FailureSupervisor` 在真实工具执行前/后监督重复失败，不依赖模型自律。

追踪维度：

- `call_signature` = toolName + canonical arguments hash（JSON key 排序；patch 内容规范化换行与尾部空白）
- `failure_fingerprint` = toolName + errorCode + normalized primary diagnostic（去除时间戳、临时目录、随机 ID、绝对 workspace 前缀）
- `resource_revision`（来自 digest / Diagnostic sha256 / expected_sha256）
- `same_call_attempts` / `same_failure_attempts` / `total_tool_failures_in_turn` / run 累计失败

固定阈值：

| 规则 | 阈值 |
|---|---|
| `retryable=false` 的相同 call_signature | 真实执行 1 次；第二次执行前阻断 |
| `retryable=true` 的相同 call_signature | 最多真实执行 2 次；第三次执行前阻断 |
| 同 tool + resource revision + error class | 最多真实失败 3 次 |
| 同一 failure_fingerprint 连续 2 次 | 下一轮必须携带 `recovery_required` |
| 单 turn 工具失败 | 达到 6 终止该 turn（并以 `repeated_tool_failure` 结束 run） |
| 单 run 工具失败 | 达到 12 终止 run |
| `MaxAgentTurns` | 产品默认 128；配置 `0` 使用默认，不再表示无限 |
| `MaxToolExecutions` | 产品默认 512；配置 `0` 使用默认 |

固定恢复映射（写入 Outcome.RecoveryOptions 与语义事件，进入下一模型轮）：

| 错误类别 | 恢复要求 |
|---|---|
| `invalid_patch_format` / patch 语法码 | 切换 `text_edit` / `text_file_create` 或重新读取；禁止原样 patch |
| `patch_context_mismatch` 及 context/stale 码 | 重新 `read_file`，再使用 `text_edit`；禁止直接重放 |
| `text_not_unique` | 扩大 `old_string` context 或显式 `replace_all` |
| `process_exit_nonzero` | 先解释 exit code/stderr，再改变命令或停止 |
| `needs_runtime` | 调用宿主 RuntimeManager；Artifact Skill 不得 shell 安装 |
| `skill_tool_not_allowed` | 重新编译 activation plan；不得换壳调用同一能力 |
| `skill_platform_contract_conflict` | 停止并退出该 Skill；后续只能由 Skill scope 外的新恢复规划调用平台 typed tool |
| `persistence_error` | 停止新副作用，等待 journal 恢复或终止 |
| `retryable=false` | 不允许自动重复相同 call |

新增事件与终态：

- `ToolRecoveryRequired` / AG-UI `AWAKEN_TOOL_RECOVERY_REQUIRED`
- `ToolRetryBlocked` / AG-UI `AWAKEN_TOOL_RETRY_BLOCKED`
- `TerminalReason`：`repeated_tool_failure`、`persistence_error`

成功调用重置同一工具的 consecutive failure，但不清除 run 累计失败数。读取到新 resource revision 后允许新的 call_signature 恢复。UI 必须展示被阻断的工具、重复次数、error code 与允许的下一步。

## Audit

每次进入工具决策的调用都必须产生 `ToolAuditRecord`，包含：

- `toolCallId`
- `runId`
- `toolName`
- `source`
- `annotations`
- `decision`
- `decisionReason`
- `decisionOrigin`
- `startedAt`
- `completedAt`
- `outcome`
- `affectedPaths`
- `trashedPaths`
- `taskScope`

Audit 只能记录决策来源和运行时边界，不得暗示存在通用人工审批 fallback。
