# 上下文窗口与压缩

## 1. Request envelope

模型上下文由稳定 system prompt、结构化历史、attachments、inline SkillContextBlocks、runtime snapshot 和 tool schemas 组成。runtime snapshot 记录 workspace/cwd、模型、tool snapshot ID、environment ID 和 Skill summary；tool schemas 来自本 run 固定可用性快照。

Skill 不在估算前与 tools 求交。目录只暴露统一 `skill` 工具及有预算的 Skill catalog；调用后的 inline 正文才进入上下文。

## 2. 预算

上下文窗口由 model window、output reserve、effective window、warning/auto-compact threshold 和 compact target 决定。估算与实际 token 可能不同，事件必须同时保留估算/实际和 model identity，不能把字符数当精确 token。

Skill catalog 预算约窗口 1%；inline Skill 压缩内容预算为单 Skill 最多约 5,000 tokens、合计最多约 25,000 tokens，最近调用优先。例如 6 个都达到单包上限的 Skill 只保留最新 5 个，系统块按恢复后的调用时间排序。截断保留 Skill ID、锚定路径和受控重读提示，其中必须包含可精确交给 `read_file` 的原始 Skill 路径，不能只留描述性名称。

## 3. 压缩

压缩保留最新用户意图、未完成工具配对、active gate、canonical tool outcome、artifact/change identity、最近 Skill 上下文和必要的恢复事实。大 tool output 可裁剪为结构化摘要，但不能把 failed/unknown side effect 改成成功。

fork body 属于 child 上下文，不纳入父压缩；父只保留 child result/identity。attachments 通过 runtime storage key 恢复，不重复内联 image base64。

## 4. 失败与降级

- summary model 失败可使用标记清楚的 fallback；
- 无法安全裁剪 tool pair 或最新用户意图时 block，而不是静默丢失；
- Skill 正文截断时提示重新读取锚定路径；
- provider/tool snapshot 只保存 ID/摘要，不能在压缩后重新选择当前 registry implementation。

## 5. 当前缺口

- per-model tool-support capability 尚未统一；
- catalog/Skill token 预算是估算，不是 provider tokenizer 精确值；
- Windows/Linux 的大路径、非 ASCII attachments 与重开压缩尚无本轮实机证据。
