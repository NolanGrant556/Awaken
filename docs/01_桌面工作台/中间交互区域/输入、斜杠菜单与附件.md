# Workbench 输入、斜杠菜单与附件

## 1. 权威范围

本文唯一拥有 Desktop composer 的文本输入、键盘、`/` 与 `@` 命令 provider/action/token、附件选择/粘贴/展示和提交结构。Skill 加载与执行由 08 域拥有；TaskScope 文件读取由 04 域拥有；本文只定义 Workbench入口与 Desktop wire。

## 2. 代码 owner

- `Awaken Design System/src/components/AwakenComposerInput/`：无结构化 token 时的受控 textarea、键盘提交、粘贴图片和自动高度。
- `Awaken Design System/src/components/AwakenComposerBar/`：center/dock 输入表面、center 首页项目低栏、插件快捷入口、单一 plaintext token editing host、DOM ↔ structured state adapter、palette、token、附件、模型/effort 二级面板、meta 和 send/stop；负责快捷入口的本地开合、composition guard、逻辑选区以及原子 token 的 Backspace/Delete 边界。
- `apps/desktop/src/renderer/composerSlash.ts`：trigger、provider、filter、token placement 与纯状态删除判定 helper。
- `apps/desktop/src/renderer/composerStructuredDraft.ts`：按逻辑 caret 删除 trigger、插入 token、拆分前后正文和协调结构化 segment 的共享纯函数；Workbench 与定时任务不得各自维护一套句中插入算法。
- `apps/desktop/src/renderer/composerAttachments.ts`：draft attachment、image data URL、view model、run input转换。
- `apps/desktop/src/renderer/App.tsx` 与 `useThreadComposerDraft.ts`：provider注册、Desktop file picker、按 thread 隔离的 draft state、会话模型/effort preference、提交/恢复。
- `apps/desktop/src/shared/runtime.ts`：`ComposerToken`、`RunInputAttachment`、thread model preference 和 start-run request。

## 3. Composer 形态与高度

center 和 dock 使用同一个 `ComposerBar` API。当前产品传入：

- dock：`minRows=1`、`maxRows=8`；
- center：`minRows=3`、`maxRows=6`；
- 无结构化 token 时，value 变化读取 computed line-height，以 `scrollHeight` clamp 原生 textarea 高度；
- 存在结构化 token 时，ComposerBar 切到单一 `contenteditable="plaintext-only"` editing host：token 前文、token 间正文和最后尾文都可编辑，token 是 `contenteditable="false"` 原子节点；整个表面仍按同一 minRows/maxRows 预算增长和内部滚动；
- 两种输入面超出 maxRows 后都只在 composer 内部滚动；
- 两种形态只改变高度预算，不改变输入语义；
- center 可接收受控 `projectPicker`，在输入面下方形成独立低栏；低栏只回调选择/创建动作，不进入 editing host，也不改变 draft、token、附件和提交结构；dock 忽略该 props；
- center 与 dock 可接收受控 `pluginPicker`，在 `+` 右侧显示插件快捷胶囊；胶囊最多预览三个统一拼图默认图标，点击后展开只含默认图标与插件名的紧凑可滚动列表。Design System 只保存弹层开合，插件目录、已选状态和 token 写入仍由 Desktop 拥有；没有已安装插件时入口仍显示，弹层呈现“还没有安装插件”；`embedded` 与定时任务编辑器不渲染该入口；
- dock 高度变化由 RunStage controller测量。
- 扩展文件 surface 的横线/紧凑/执行/完成只是 Desktop 包装层对同一 `dock` ComposerBar 的呈现状态，不改变 `minRows/maxRows`、结构化输入或提交规则；只有 value/各 token 的 `leadingText`、token 与附件共同构成的结构化草稿为空时，文档主键单击才可进入横线态，任一草稿事实存在时必须保持完整输入面；紧凑时 ComposerBar DOM 保持挂载但不可交互，恢复完整态时继续使用同一 value、token、附件、Slash 和 focus request。

### 3.1 会话模型与推理强度

Composer 的模型和 reasoning effort 都是 thread preference，不修改设置页全局 default：

- 模型弹层选择支持 effort 的模型后进入二级面板；当前模型按钮、模型列表与二级面板标题复用同一枚供应商 Logo。档位通过 Codex 式单行离散轨道选择，不显示 `Effort`、Apply 或档位文字；最低档直接落在轨道左端且不重复画圆点，其余真实档位圆点始终保留在中性轨道层，最高档提示点在右端内侧留出间距，而选中最高档后的白色滑块仍到达轨道右端。彩色光流从上层覆盖已经过的点，白色圆形滑块覆盖当前点，只让滑块右侧尚未选择的中性灰点露出。往回拖时光流裁切边界后退，被覆盖的档位点自然重新出现，不通过隐藏节点模拟。左侧为增强线宽、亮度和局部辉光的连续光流填充，右侧为无彩色的中性轨道；普通档复用 `AwakenMemoryLightFlow` 的紧凑绿色光流，最右 `max` 档使用同一绘制器的红色色调；Composer 只持有档位状态和交互，光流 primitive 不读取 thread preference；
- 模型菜单打开时由 Design System 让底部模型触发按钮执行同一套 240ms 横向伸展动效：右端保持稳定，胶囊从当前内容宽度向左拉长到菜单宽度，内容随胶囊居中，宽态 Chevron 同步旋转并在关闭时反向收回；模型列表卡片保持原有尺寸和定位，不参与伸展。`center` 首页与 `dock` 对话页共享实现，只在点击时读取一次按钮宽度，不新增计时状态、运行时订阅或持续循环，`prefers-reduced-motion` 下直接显示展开后的按钮并停用 Chevron 过渡；
- 模型菜单仍锚定在 ComposerBar 当前层级内：`center` 优先向下、`dock` 优先向上；首选方向空间不足且另一侧空间更大时自动翻转，并按可用高度内部滚动。菜单打开期间窗口缩放或祖先滚动必须重新计算，不得把某一形态永久固定成向上或向下；
- Composer 自身可用宽度不超过 `440px` 时，Design System 通过容器查询把模型触发按钮收为只显示供应商 Logo 的 32px 圆形胶囊，隐藏可见模型名与 Chevron；完整 `模型名 · effort` 继续作为按钮 accessible name 与 hover title，菜单内仍显示完整模型信息。宽度恢复后文字与 Chevron 自动恢复，不读取 Inspector 状态、不新增 Renderer 尺寸状态；
- 指针按下和拖动期间，滑块及填充边界使用轨道内的精确指针位置；松手、取消、键盘选择或面板重开后收敛到当前 capability 档位圆点。`max` 只在进入轨道最右区域并跨过像素回差后触发，反向拖回使用对称回差防止抖动。点击、拖动或 Arrow/Home/End 只能落在 capability 真实存在的档位并立即写入 thread preference；单纯悬停或移动不变更档位；`prefers-reduced-motion`、页面隐藏、离屏和卸载时沿用光流 primitive 的静态/停绘策略；
- 不支持 effort 的模型直接选择，不显示空入口；MiniMax thinking 开关不作为 effort；
- 应用后标签为 `模型名 · effort`，无档位模型只显示模型名；
- 有历史消息时只在模型与推理强度二级面板内显示“切换模型或推理强度会重建对话缓存，下次发送消息时生效”的说明，不再触发全局提示条；
- run busy 时模型与 effort 控件禁用，选择只影响下一次 run；
- 已有 thread 通过 typed model-preference IPC 立即持久化；未建 thread 的 center 草稿在首次 run 时原子写入；
- profile 失效或档位变化时回退有效 default，并只提示一次，不批量改写历史 thread。

Renderer 启动请求只携带 `modelProfileId + reasoningEffort`。Key、Base URL、完整 profile 和 provider 原生 effort 值不得进入 Composer state；Main 与 provider adapter 分别拥有凭据解析和原生值映射。

## 4. 键盘与 IME

`shouldSubmitComposerInputKey()` 是唯一基础规则：

| 输入 | 行为 |
|---|---|
| Enter | 非 composing 且无 Shift 时提交 |
| Shift+Enter | 插入换行 |
| IME composing + Enter | 不提交 |
| macOS `Cmd+A` / Windows、Linux `Ctrl+A` | 只全选当前 textarea 或单一 plaintext token editing host；应用壳与非编辑焦点的范围由 [产品与交互契约 §7.1](产品与交互契约.md) 统一定义 |
| 外层 handler `preventDefault()` | 由 Slash/token 等交互接管，不再提交 |

busy 时主按钮是 stop；文本与辅助控件可禁用，但 stop必须仍可调用 cancel。空文本在没有 token/附件时不能启动 run；token-only提交允许。

统一 token editor 以浏览器 DOM 为编辑期事实源，但不把 React children 当作受控正文。非 composition 的 `input` 把每个 token 前的文本回传为该 token 的 `leadingText`，最后一个 token 后的文本回传为 `composerValue`；composition 期间不向 DOM 回写。外部 draft 真正变化时才重建 DOM，并用“正文 UTF-16 offset + 每个原子 token 计 1”的逻辑位置恢复 selection。该逻辑位置不包含 token label，也不写入持久化数据。selection listener 必须通过稳定 callback/ref 读取最新上层回调；上层 render 产生的新函数 identity 不能重新注册 listener 或立即回写一份等价 selection，draft owner 对逻辑位置和 caretRect 都相同的更新返回原 state。

提交开始会暂时清空 composer；startRun 失败必须恢复原文本、token、附件和必要 placement，不得让用户输入丢失。

未提交草稿按 `activeThreadId` 归属；尚未创建 thread 的输入使用独立的 `new-thread` owner。切换会话只切换草稿 owner，正文、token、附件、placement、`leadingText` 和逻辑 selection 都不得复制到目标会话；返回原会话时恢复其内存草稿。新建任务只清空 `new-thread` 草稿，不得顺带清空正在离开的历史会话草稿。该隔离当前只保证同一次 Desktop 进程内的会话切换，不声明重启后恢复未提交草稿。

### 5.1 `SlashAction`

```ts
{
  id: string;
  type: "skill" | "file" | "workflow" | "prompt" | "connector" | string;
  label: string;
  description?: string;
  keywords?: string[];
  disabled?: boolean;

  payload: unknown;

```

### 5.2 `SlashProvider`

provider接收 `workspaceRootForRun`，只负责取数、可见性、action 和可选 token。palette只负责 active、hover preview、键盘和选择；runtime只消费认识的 token type。

当前 App 与定时任务 Agent 编辑器都为 `/` 注册排除 plugin 来源的 Skill provider。Workbench `@` 注册 Deep Research workflow token、内置 Computer Use capability provider 与已启用 Plugin provider；定时任务 Agent 编辑器的 `@` 只注册 Computer Use 与 Plugin，不注册 Deep Research。file/prompt/connector 仍是扩展类型，不是已支持产品能力。`SlashAction.type = "workflow"` 当前只用于 Workbench `@deep-research` / `@研究` token，见 [16 深度研究](../../16_深度研究/索引.md)；token 选择后必须再输入研究问题才能提交，提交后由宿主固定执行规划、调研、核验和报告四阶段。不得把 `/` Skill、plugin Skill 或同名用户 Skill 写成深度研究。定时任务选择 Computer Use 只持久化同一个 capability token，不提前授予工具权限，也不允许无人值守自动通过 review、handoff、系统授权或其它安全 gate。

## 6. Trigger 与过滤

trigger 以当前 collapsed 逻辑光标为结尾。检测只读取光标之前的当前文本 segment，并选择离 caret 最近的 `/query` 或 `@query`；marker 必须位于该文本 segment 行首，或由一个 whitespace 字符直接引导。用户可以先写中文、英文或数字，再把光标移到任意句中位置补入空格并输入 marker；不要求从左到右顺序输入。光标之后可以已有正文。逻辑位置把每个原子 token 计为 1，因此 trigger 可以位于 token 前文、token 间正文或最后尾文；紧邻普通文字、数字、URL 或路径字符的 `/`、`@` 不触发：

```text
/(?:^|\s)\/([^\s/@]*)$/
/(?:^|\s)@([^\s/@]*)$/
```

实现返回的 `start` 仍指向 marker 本身，不把前导 whitespace 纳入 query 删除或 token 替换范围。

因此：

- `/` 只显示当前可调用且 `sourceOrigin != "plugin"` 的普通 Skill；Workbench `@` 显示 Deep Research workflow、内置 Computer Use capability action 及已启用 Plugin；定时任务 Agent 编辑器的 `@` 显示 Computer Use 与已启用 Plugin，但不含 Deep Research。即使 Plugin 目录为空，Computer Use 仍保持可选；
- `@` 查询对 Computer Use 与 Plugin 使用同一过滤；两类结果都无命中时显示“没有匹配的能力或 Plugin”，不得把仍可用的 Computer Use 误报成空 Plugin 目录；
- `@` palette 按来源显示两个连续分区：`内置` 只包含宿主拥有的 Deep Research 与 Computer Use（定时任务只显示其中的 Computer Use），`插件` 包含其余已启用 Plugin；分区只改变目录层级展示，不改变 action 顺序、过滤、键盘导航、token identity 或运行时复验；
- Workbench 与定时任务 Agent 输入提示都把 `@` 描述为选择“内置功能或插件”，不能继续把整个入口写成只选择 Plugin；
- `/doc` 过滤；
- `@computer`、`@电脑` 可过滤到 Computer Use；
- `/doc`、`@computer`、`你好 /doc`、`中文123 @computer` 可触发；`你好/doc`、`中文123@computer`、`我们/`、`我们@` 不触发；把光标放在 query 后时，marker 后已有后续正文也不妨碍当前 caret 对应的 trigger；
- 先输入整句、再把光标移回句中补空格后输入 `/`、`@`，与从左到右顺序输入使用同一规则；只补 marker 而没有空格不触发；非 collapsed selection 不触发；
- Escape 或选择只删除当前光标对应的 trigger，保留前文和光标后的正文；选择 action 后 token 插入 trigger 原位；
- filter 匹配 label、description、preview description/path、keywords，不区分大小写；
- provider 的完整过滤结果都必须保留；palette 只通过 88–210px 可视窗口、内部滚动和后续可选的虚拟化控制渲染成本，不得用固定条数截断能力目录；
- Core 对 Skill Registry 或 Plugin Store 的成功 mutation 递增 composer catalog revision 并通过 `/v1/composer-catalog/events` 发布失效事件。Desktop 常驻订阅，palette 保持打开时按当前 marker、workspace 和 revision 重新读取对应 provider；旧异步请求卸载或 revision 变化后不能覆盖新结果。每次重新打开仍直接读取当前目录，不依赖事件没有丢失。

## 7. Skill provider 当前规则

- 调用 `listSkills(workspaceRootForRun)`；
- 只展示 `status=loaded && userInvocable !== false && sourceOrigin !== "plugin"`；
- managed/project/additional/user/agents/MCP/bundled/legacy 满足条件时继续进入 Slash；plugin Skill 只从这条产品入口隐藏，仍保留在统一 Catalog/Registry 和 model-facing `skill` 工具中；
- `invalid`、`shadowed`、`disabled_by_policy` 不进入可选列表，并在 Skills 管理面保留诊断；
- keywords包含 id/name/displayName/description/whenToUse/path；
- preview path是 `skillFilePath`。

Skill token payload：

```ts
{
  skillId: string;
  sourceOrigin: string;
  skillFilePath: string;
  rootDir?: string;
}
```

Runtime按 `skillId` 查当前 registry，并核对条目仍为 loaded/user-invocable，且当前 source/path 与 token 的锚定事实一致。renderer 路径仍不是授权字段；正文由 Runtime 从当前锚定 `SKILL.md` 或 MCP fetcher 按需读取。Skill 的工具/依赖声明只作为提示，不改变父 run 的工具可用性快照。

### 7.2 Computer Use capability provider

在 Workbench 或定时任务 Agent 编辑器输入 `@`、`@computer`、`@电脑` 或其他匹配关键词时，palette 提供 `Computer Use`；`/` 菜单不提供该选项。选择后创建 `type=capability`、`capabilityId=computer-use` 的原子 token，并把光标交还输入面。输入框与 prompt bubble 只显示带显示器图标的 `Computer Use` token，不能显示或持久化模型引导词。

提交或定时触发时 Core 都校验 capability identity，并只在 model-facing effective input 的 token 位置加入固定 Computer Use 引导；display input、SemanticJournal `user_message` 和 thread replay 仍保存结构化 token 与用户正文。该 token 不直接启用工具，也不绕过模型视觉能力、全局开关、TCC 与 Driver readiness；模型只能在当前 run 的固定工具快照内决定是否调用 `computer_observe`、`computer_act` 和 `computer_verify`。定时 run 遇到 Computer review/handoff 时继续使用原有 run-bound gate 并受任务 timeout 约束，不能自动批准、自动接管或自动授予系统权限。未知 capability token 必须以 invalid input 拒绝，不能作为任意隐藏 prompt 注入通道。

### 7.3 Plugin mention provider

输入 `@` 或插件名称关键词时，provider 调用 `listPlugins()`，只把当前 `enabled=true`、有 digest 且至少含一个可用 Skill 或 MCP server 的 Plugin 放入目录；只包含 Skill 的有效插件同样可选。没有任何 Skill/MCP 组件、被禁用或缺少有效 digest 的包只留在插件管理页，不生成 action。选择后创建 `type=plugin` 原子 token：

```ts
{
  pluginName: string;
  pluginDigest: string;
}
```

Renderer 的名称、digest 和组件数量不是授权事实。普通 run 与每次定时任务触发都由 Core 通过 Plugin Store 重新核对包仍存在、已启用、digest 未变化，并至少有一个 loaded Skill 或 enabled/valid MCP server；失败则在启动模型前结构化拒绝。成功后宿主只在 model-facing effective input 的 token 原位加入固定“优先使用该 Plugin 的 Skill 与 MCP 工具”引导，display input、SemanticJournal、prompt bubble 和 replay 仍保存结构化 token 与用户正文。Plugin 选择不复制 Skill/MCP runtime，不改变已经开始的 run，也不信任 Renderer 提交的组件列表或路径。

首页与对话 Composer 的 `+` 右侧还投影同一 provider 的快捷入口，不维护第二份插件目录。胶囊默认最多显示前三个当前可选插件的统一拼图默认图标；弹层取消搜索，只以紧凑的“默认图标 + 插件名”行滚动展示全部结果。没有插件时入口仍保留并给出空状态。选择结果继续调用同一 `composerTokenFromSlashAction()` 与逻辑 caret 插入算法，因此形成的仍是 `pluginName + pluginDigest` 的 `@` Plugin token。已存在同一 digest token 时只把焦点移回该 token 后方，不重复插入。Plugin Store 的 catalog revision 会同时刷新 `@` palette 与快捷入口；定时任务只保留文本内 `@` 入口，不显示快捷胶囊。

### 7.1 项目路径 token

右侧项目文件树的“添加任务”可为普通文件或文件夹创建 `type=file` token：

```ts
{
  path: string;
  entryKind: "file" | "directory";
  projectId: string;
  folderPath: string;
  relativePath: string;
}
```

Desktop 先用 typed Main IPC 对当前 active project、精确绑定文件夹、lexical/realpath containment、存在性、条目类型与 symlink 做校验，再把返回 identity 插入当前逻辑 selection。token label 只使用 basename，绝对路径不进入 editing host 或复制出的可见正文。StartRun 时 Core 必须按当前 `projectId` 与精确 `ReadableRoots` 再校验相对路径、真实路径和类型；项目切换、文件夹解绑、删除、类型变化或 symlink 都使旧 token 结构化失败。成功后 Core 才在 model-facing effective input 的原 token 位置写入绝对路径，持久化的 display input 与 prompt bubble 仍只显示名称 token。

## 8. Token 顺序与删除

token 不写入 textarea 明文。Desktop分别维护：

- `composerTokens`（token 本体携带可选 `leadingText`，是顺序事实的唯一 durable owner）；
- token placement (`before|after`)；
- Renderer 侧 `composerTokenLeadingTexts` map 只作为编辑期镜像，不是事实来源。

在纯 `/doc`、`@computer` 或 `@plugin` 选择时 token 位于后续文本前；在句中 trigger 末尾放置光标并选择时，前文写入该 token 的 `leadingText`，后文保持为 token 后正文。提交后 prompt bubble 按同一顺序渲染；用户正文不包含 Skill 文件路径、Computer Use 隐藏引导或 Plugin 宿主引导。

`leadingText` 随 token 贯通 StartRun wire（`composer_tokens[].leadingText`）、Runtime `ComposerToken`、SemanticJournal `user_message.composer_tokens` 与 thread transcript。canonical user_message 回流、线程切换和 Desktop 重启重放都从同一 durable token 恢复顺序，不得把位于正文中间的 token 降级到句首。`leadingText` 只承载展示顺序，不进入 Skill/Plugin 授权判断；Skill token 不改变 model-facing user text，已复验的项目路径 token 在同一位置替换为隐藏的绝对路径，已校验的 Computer Use capability 与 Plugin token 在同一位置替换为各自固定的宿主引导。

统一 editor 中的正文 segment 可重新定位和编辑。每次结构化回调按当前 token 顺序更新 durable `leadingText`，最后 segment 更新 `composerValue`；React 普通 rerender 不重建 editing DOM，因此光标不会因为状态同步跳到末尾。

当前键盘删除规则：collapsed selection 紧邻 token 时，Backspace 删除前一个原子 token，Delete 删除后一个原子 token；跨 token 的非空选区按原子边界删除，正文 segment 在原位置合并，因此 token 的 `leadingText` 不丢失、不重复，也不会被错误搬到整段尾文之前。`Cmd/Ctrl+A` 选中整个 editing host 时，token 以逻辑长度 1 进入选区，图标、间距和 label 共用原子 token 的完整选中底色；选区离开 token 后底色立即清除。Slash palette 打开时 palette 键盘规则优先接管。drag/drop 被禁用。复制/剪切为纯文本时写入可见正文与 token 标签（文件名、Skill/插件名、capability 名），保留用户输入的硬换行，但不把软换行或 token 视觉换行写成额外 `\n`；Skill 路径与 Computer Use 隐藏引导仍不进入剪贴板。token identity 与顺序仍只由结构化状态拥有。

## 9. Palette 交互

- ArrowDown/ArrowUp 在可选项移动；
- active 项变化时列表把该项滚入当前可视窗口；可视窗口之外的结果仍可由键盘和滚动访问；
- Enter/Tab 选择 active；
- Escape 关闭并清理 trigger；
- mouse hover显示 preview，键盘 active不自动打开 preview；
- 行为一行 icon+label，长文本 ellipsis；
- 带 `sectionLabel` 的 `@` action 由同一个列表按连续分区渲染 `内置` / `插件` 标题；`/` Skill action 不传该字段并保持原单列表；
- Deep Research workflow action、选择后的原子 token 与提交后的 Prompt bubble 统一显示 `search` 概念对应的 `magnifying-glass`，不得在 token 阶段回退成通用 `package`；
- Skill action 与选择后的原子 token 统一显示打开的书图标；同一 token 在提交后的 Prompt bubble 保持该图标，不退化为通用 package 图标；
- Plugin action、快捷胶囊选择后的原子 token 与提交后的 Prompt bubble 统一显示 `plugin-default` 实心拼图，不使用包装盒或 Agent Plugins 官方标记；文件包 token 仍使用 `package`；
- preview最大约 220px 宽、150px 高，优先放右侧，不足时放左侧，并 clamp viewport；
- palette最大高度根据 composer上方空间计算，88–210px；
- palette 主面板以当前 `/` 或 `@` 的 caret rect 为锚点，优先让面板左下邻近 trigger，并在窗口左右边缘 clamp；无法取得 caret rect 时才回退到 composer 左侧和上边缘；面板在首次定位完成前保持不可见，并在浏览器绘制前完成位置提交，不能先按 `left: 0` 显示再横向跳到 caret；
- palette/chip都在 `ComposerBar` 内，不进入 ExecutionFeed 或 RunStage独立 overlay。

## 10. 附件选择与粘贴

### 10.1 文件选择

Desktop `+` 通过 Electron picker支持多选本地图片和文件。picked file转换成 `ComposerDraftAttachment`：

```ts
{
  id;
  kind: "image" | "file";
  path?;
  mimeType;
  dataBase64?;
  displayName?;
  width?;
  height?;
  byteSize?;
  previewURL?;
}
```

### 10.2 粘贴图片

只接受 PNG、JPEG、WebP。优先读取 clipboard items，fallback到 files；如果有可接受图片则阻止默认粘贴，转为 draft image。单张图片大小保护为 8 MiB。

图片读取为 data URL/base64并探测自然尺寸；普通文件以本地 path引用，不把整个文件内容塞进 prompt文本。

## 11. UI 投影

Composer token/text：

- `leadingText`、原子 token、token 间正文与最后尾文共同位于一个 `contenteditable="plaintext-only"` editing host，不得使用多个 DOM 编辑区、独立 flex 文本块或 textarea 拼接；
- 长前缀换行后，token 和后续输入在剩余宽度允许时继续同一行，光标紧跟尾文，不能把编辑面整体推到 token 下方；
- token 边界使用 Design System 视觉间距，不得通过改写 `composerValue` 或最终 prompt 注入空格；
- token 内部使用 `16px` 线性图标、`5px` 图标/label 间距和 `8px` token 后间距；整个 token 通过 `14/20px` 行盒的几何中心与相邻中英文、英文和数字对齐，不应用图标下沉，也不得按 token 类型各自补偏；
- token DOM 使用稳定 `data-composer-token-id` 与 `contenteditable="false"`；token label、Skill 路径、Computer Use 隐藏引导和 caret 辅助字符均不得进入可见正文或复制结果；项目路径与 capability token 的 identity 会结构化持久化，但只有复验后的绝对路径或固定 capability 引导进入 model-facing effective input，不回写 display input；当前实现不使用 zero-width caret sentinel；
- composition start/update/end 期间浏览器独占编辑 DOM；composition 完成后再同步结构化状态。外部 draft restore 可重建 DOM，但必须恢复逻辑 selection；
- 无 token 时继续使用原生 textarea；移除最后一个 token 后恢复其 `leadingText` 并回到普通文本输入面。

Composer附件条：

- 一行、42px 高的小卡；
- 文件卡约 148px 宽；
- 横向滚动，不纵向撑高；
- 文件名省略，tooltip包含类型、大小和路径尾部；
- 可在提交前删除。

Composer 插件快捷入口：

- 只在首页 `center` 与对话 `dock` 出现，位于 `+` 的右侧；定时任务和 `embedded` 表单不出现；
- 快捷胶囊始终保留；有插件时最多展示三个紧凑标记和“插件”标签，完整数量通过可访问名称表达，没有插件时弹层展示空状态；
- 展开列表内容宽度为 `216px`，单项最小高度 `30px`、内边距 `2px 6px`，内部使用 `20px` 图标底板、`12px` 默认图标和 `11/16px` medium 文字；该紧凑规格不改变 `+` 右侧快捷胶囊自身的尺寸；
- 弹层优先向上展开，不含搜索框并展示完整可滚动列表；插件安装、启停、升级或卸载后的 catalog revision 必须原地刷新列表；
- 选择只回调 Desktop 写入现有结构化 Plugin token，不把插件组件、路径、Skill 正文或 MCP 配置写进 Design System state。

Center 首页项目低栏：

- 位于 ComposerBar 输入 surface 之后，只在 `variant="center"` 且父级传入 `projectPicker` 时显示；
- 当前项目名称直接从 `options[].selected` 派生，不在组件内保存第二份选中项目；
- 菜单选项和「创建项目」只触发父级回调，组件不读取 workspace、FileStore 或 Electron；
- 低栏不是输入正文、附件条、metaItems、overlay 或 dock stack，不参与 run payload。

Prompt bubble：

- 附件位于 token/text上方；
- token 与前后正文必须投影为同一个连续文本流，保留 `leadingText` 的原始空格/换行并按气泡实际宽度自然换行；不得把 token 前缀或后缀拆成独立 flex 文本块，也不得在投影边界再次 `trim`；
- 首页、对话、定时任务 Agent 编辑器和 Prompt bubble 共用同一 token 排版：`14/20px` 正文、`16px` 线性图标、`5px` 图标/label 间距、`8px` token 后间距和 medium 字重；token 整体以行盒几何中心对齐中英文、英文和数字，不得按入口缩小图标、添加下沉偏移或把 Plugin 品牌标记压到其 `20px` 可读下限以下；
- `Cmd/Ctrl+A` 或局部拖选穿过 token 时，Prompt 组件必须把选区映射到整个原子节点，让图标、间距与 label 共用完整选中底色；该视觉补齐不得改变系统 Selection 的文字范围或复制序列化结果；
- image显示缩略图，file显示文件图标、名称和扩展；
- collapsed只显示前三个，更多以 `+N`；
- 默认不点击打开/预览，避免绕过交付物安全打开链。

上述投影在 live run 和 v2 durable replay 中共用。`actionsForThreadTranscript()` 使用耐久 run 的 `inputAttachments` 和 `composerTokens` 重建附件小卡、token 与原有顺序。旧 v2 count-only 记录因为当时未保存这些结构化事实，只恢复文本且不猜造小卡。具体耐久字段和 blob 恢复规则由 [03 SemanticJournal 与重放](../../03_运行时与本地服务/SemanticJournal与重放.md) 拥有。

## 12. 提交与运行边界

`toRunInputAttachment()` 移除 renderer-only previewURL。run input：

- image可携带 base64、mime、尺寸，作为视觉输入；
- file携带绝对路径、mime、大小和显示名；
- runtime把文件加入 attached-files/TaskScope后，Agent按需用工具读取；
- 附件事实不拼进用户正文；
- provider capability不在 renderer硬拦图片，真实不支持由运行错误/降级表达；
- 不能把附件路径本身视为授权写入边界。

## 13. 当前不支持

- 除 Skill `/`、Plugin `@`、内置 Computer Use `@` 与 Workbench 内置 Deep Research `@` 之外的命令 provider；
- 通用富文本或样式化 prompt 编辑；带结构化 token 时虽然前后正文共享一个 editing host，仍只接受 plaintext；
- prompt附件卡点击预览/打开；
- 固定产品级总附件数量上限；
- 远程 URL附件；
- 对旧 v2 count-only 记录补回当时未持久化的附件/token 事实；
- 由 renderer绕过 runtime直接读取任意本地文件。

## 14. 异常与恢复

| 场景 | 行为 |
|---|---|
| 支持格式的粘贴图片超过 8 MiB | 拒绝该附件并提示，不影响已有 draft |
| 剪贴板图片 MIME 不受支持 | ComposerInput在交给App前静默过滤；当前没有专用“不支持格式”提示 |
| picker选择未知扩展名 | “All Files”允许选择，按普通file与 `application/octet-stream` 接收，不冒充inline image |
| file picker取消 | 无状态变化 |
| 命令 provider 加载失败 | palette 显示 error；文本保留 |
| Skill 不是 loaded/user-invocable，或 `sourceOrigin="plugin"` | 不进入 `/` 可选列表，不生成 token；plugin Skill 仍由 Plugin Console 与模型侧 Catalog 保留 |
| startRun失败 | 恢复 draft输入；Main 按 Core 稳定错误码显示输入、Skill、Plugin component、Plugin package 或 thread/project conflict 的安全文案，不透传路径、header 或凭据 |
| token registry不匹配 | runtime结构化拒绝，不按路径猜 Skill；Plugin Console 精确 Skill action 使用 Core Catalog ID，不退化为整个 Plugin token |
| Plugin token 对应包被禁用、删除、升级或失去全部可用组件 | Core 在 StartRun 前拒绝；不按名称猜包、不回退到普通文本，也不启动模型 |
| 项目路径 token 与当前项目/ReadableRoots/真实类型不匹配 | Core 在 StartRun 前拒绝；不读取、不启动 run，也不把旧路径降级为普通文本 |
| attachment 历史重放 | 新 v2 记录恢复有序附件与 token；旧 count-only 记录只恢复可确认文本，不伪造或从磁盘/prompt 猜附件 |
