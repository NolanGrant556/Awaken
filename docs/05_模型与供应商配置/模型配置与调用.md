# 模型配置与调用

## 1. 权威范围

本文是 Awaken 当前模型目录、profile、会话模型选择、推理强度、能力验证和 run 注入链的唯一权威。模型与 Agent Plan API key 的文件格式、权限和恢复由[安全凭据存储与恢复契约](安全凭据存储与恢复/架构与恢复契约.md)拥有；Composer 通用输入由[输入、斜杠菜单与附件](../01_桌面工作台/中间交互区域/输入、斜杠菜单与附件.md)拥有；prompt cache 与用量由[提示词缓存与成本治理](../02_主智能体闭环/提示词缓存与成本治理.md)拥有。

## 2. 用户入口

“设置 > 模型”使用两层导航。模型页左侧固定分成四个模型接入类型：

| 接入类型    | 当前 provider                                  |
| ----------- | ---------------------------------------------- |
| Coding Plan | Kimi Coding Plan、MiniMax Token Plan、GLM Coding Plan、火山 Coding Plan、Qwen Token Plan |
| API         | OpenAI、Anthropic、Google Gemini、Kimi、MiniMax、GLM、Qwen、Doubao Ark、DeepSeek |
| Agent Plan  | 火山 Agent Plan                                |
| 自定义      | 自定义 API                                     |

右侧每个接入类型固定包含两个二级页面：

- 连接配置：Coding Plan 显示“配置 Token”，API 与自定义显示“配置 API Key”，Agent Plan 显示“配置账户”；当前类型的 provider 以固定三列、统一高度的紧凑卡片展示官方产品 Logo、名称和“配置”动作。点击卡片在屏幕中央打开配置弹窗，连接状态紧邻供应商名称右侧。弹窗只展示连接必需的协议、模型、密钥与目录状态，不提供图片、视频、PDF、工具、缓存、上下文或推理强度等“高级能力”开关。协议选择按供应商约束：OpenAI 仅公开 Chat Completions 和 Responses，Anthropic 仅公开 Messages，自定义 API 可选三种协议；其他国内计划按其官方合同显示可选协议，不把默认官方地址当万能三协议网关。存量 MiniMax `minimax_chat` profile 只保留读取迁移兼容，新配置不再使用该协议。
- “API 密钥发送方式”只决定 HTTP 认证 Header，不是第四种模型协议：Bearer 发送 `Authorization: Bearer <API_KEY>`，其余合同分别发送 `x-api-key`、`api-key`、`x-goog-api-key`，无鉴权不发送认证 Header。内置厂商的 Header 与 Base URL 由 Main 按所选协议固定；连接弹窗以只读字段展示当前实际 Base URL，切换协议时同步显示对应官方地址。只有自定义 API 的鉴权和 Base URL 可编辑，由用户声明网关合同。不接受任意秘密 Header。OpenAI/Anthropic 可另存只用于组织用量与成本的管理密钥；它与推理密钥分开保存、轮换和掩码，Renderer 不取得明文。
- 打开已保存凭据的内置供应商配置弹窗时，Main 按 profile、凭据 revision、Base URL、协议与 endpoint contract 自动刷新模型目录；新配置填写 API Key 后可直接点击“刷新模型目录”。同步过程显示 loading、成功条数、失败原因、缓存来源和观测时间，不再静默用旧目录冒充最新。目录候选按 `供应商模型目录 API → 版本化官方清单 → 手填模型 ID` 合并；支持手填的官方供应商使用 Awaken 自己控制的可编辑组合框，展开时完整展示当前协议可用目录，同时允许直接输入未收录 ID，不依赖 Electron 原生 `datalist`。目录失败或返回空列表时继续展示版本化官方清单。自定义 API 不请求 `/models`、不显示候选列表或刷新入口，模型 ID 始终由用户在纯文本输入框填写。
- LLM 设置：Coding Plan、API 和自定义只展示当前类型已经配置的模型卡片，并显示对应产品 Logo；标题固定按“厂商名：模型展示名”单行展示，同模型存在多协议 profile 时同时显示协议，管理默认模型、启停、上下文、输出上限和删除。供应商要求日期后缀等精确调用 ID 时，Main 同时保存不参与请求的展示名映射；连接弹窗、LLM 卡片、Composer 与定时任务只显示稳定产品名，请求、profile identity 与能力查找仍使用精确 ID。未收录和用户手填 ID 原样显示。已知上下文显示滑杆和精确输入；供应商 API 与官方清单都未提供时显示手填输入，保存为该 profile 的有效上下文限制。展开参数导致页面超过窗口高度时，模型页是右侧唯一纵向滚动 surface，滚轮移动整张模型页且左侧一级设置导航保持固定；模型卡片内部不创建嵌套滚动。滚动指示与记忆设置保持同一行为：隐藏系统滚动条，窄指示条只在 168px 顶部模型视觉下方活动，不覆盖顶部 UI。图片、PDF、视频、工具、reasoning 与缓存能力不在此处编辑。
- 辅助调用不在前端提供独立“用途模型”设置。`thread_title`、`compact_summary`、`subagent`、`hook_prompt`、`hook_agent` 默认继承 thread/父 profile，定时任务使用任务显式 profile 或 Host 默认；Host 仍负责凭据、成本和失效回退，Renderer 不创建第二套模型目录。
- 模型与工具：Agent Plan 的第二页使用该名称。页面上部沿用相同的主模型卡片，下部直接展示“图片生成”和“视频生成”两张生成工具卡片；每张卡只保留模型单选、保存、启停和删除。模型单选统一使用 Design System `AwakenSelect`，与连接配置中的模型列表共享触发器、列表表面、选中态、键盘操作、前述视口自适应和无可见轨道的滚动样式，不使用操作系统原生 `<select>` 菜单。API Key 只在“配置账户”保存一次，生成工具区不重复出现凭据表单、供应商弹窗或“已配置工具”子页。图片和视频每类最多保存一个精确模型；媒体配置不创建 `ModelProfile`，不进入 Composer 模型选择器。配置并启用后，用户无需在会话中选择媒体模型，直接在输入框描述需求，由主 Agent 调用稳定工具。

模型页使用与记忆页同高的 168px Design System 页头，以三层圆形轨道、粒子半球和六个 API provider 官方 Logo 表达模型生态；Logo 沿各自轨道连续完成 360 度公转，内外层速度和方向不同，Logo 自身保持正向；轨道超出页头的下半部由页头裁切，Logo 随公转自然隐藏并重新出现。该装饰不承载连接状态或选择。页头下方继续使用窄类型导航、紧凑二级页头和受控内容宽度，不随宽窗口无限拉伸，也不再把四类 profile 混成公共表格。

供应商 Logo 作为本地静态资源随 Design System 打包，Renderer 不在运行时请求远程图片；同一套 Logo 同时用于连接卡片、LLM 设置卡片、Composer 当前模型按钮、模型选择器和推理强度二级面板标题。连接配置区固定为三列、统一卡片高度，入口只展示 Logo、供应商名称和“配置”动作；API 类型已经由左侧接入分类明确，厂商名称和配置弹窗标题不再重复附加 `API` 后缀。卡片右侧的“配置”文字与箭头统一使用主文字色，不继承供应商 Logo 的品牌强调色。连接状态只在居中配置弹窗标题区、紧邻名称右侧展示，不在入口卡片重复展示模型数量。连接卡片和 LLM 卡片统一使用纯色表面与细边框，不使用渐变炫光、悬浮阴影或上浮位移。Logo 使用带细边框的浅色内衬容器，品牌图保持克制比例；Kimi 官方 App Icon 因原图自带安全留白而使用更高的容器占比，不裁切官方资源。位图至少使用 640 × 640 原图，其余使用可缩放 SVG。Kimi 与 Kimi Coding Plan 共用从官方 Kimi App 提取的 1024 × 1024 App Icon；Qwen 与 Qwen Token Plan 共用 Qwen Logo；Doubao Ark 使用 Doubao Logo，火山 Coding Plan 与火山 Agent Plan 使用火山引擎 Logo。资源与来源清单由 `Awaken Design System/src/assets/model-providers/README.md` 维护。

推理强度不在设置页配置。Composer 是唯一面向用户的 effort 入口，thread 内部保存 Awaken 统一的 `low | high | max` 档位；界面标签来自 exact model capability 的 `displayLabels`，例如 Qwen 显示官方原生 `low | medium | xhigh`，但运行时仍以统一档位形成缓存 identity 并由 Core 降低为协议原生参数。模型设置页不显示 profile 默认 effort。

`ModelAccessType` 的当前产品值为 `coding_plan | api | agent_plan | custom`。`custom` 只承载用户自行声明协议、地址和模型 ID 的自定义 API；媒体工具配置仍属于 Agent Plan 页面中的独立配置实体，不是模型接入类型，也不得写入 provider/profile access type。存量 provider ID 和 profile ID 保持不变；旧 `coding_preset` 仅作为读取兼容信号，不再是 UI 分类。

### 2.1 保存、连接与 effort 验证

1. Renderer 从 Main 取得非敏感 provider catalog 和 profile 摘要。
2. `测试连接` 对当前表单执行协议正确的最小请求：Chat 使用 `/chat/completions`，发送 `model + messages + stream:false`；Responses 使用 `/responses`，发送 `model + input + stream:false + store:false`；这两种探针都不再强制 1 token 输出预算。Messages 使用 `/messages`，因协议必填而发送安全的小预算 `max_tokens:64` 并关闭 thinking。完整推理地址覆盖时不再拼接路径。除显式“无鉴权”外，测试只在当前弹窗输入非空 API key 时可用；Main 不得隐式回退已保存 key 来伪造当前表单验证。上游失败只向 Renderer 返回 status、provider code 和有界脱敏 message，不返回 Key、Authorization、完整请求体或原始响应。测试只证明 endpoint/key/model 可以响应，不证明工具、PDF、缓存或 effort；动态模型不得因此被强制标记为支持工具。
3. 推理强度只在配置完成后的 Composer 展示；只有 exact-scope API observation 或版本化官方清单给出 Awaken 可映射的档位时才出现。未知模型不展示 effort，单次 HTTP 200 不能推导全部档位可用。`ark-code-latest` 不展示 effort。
4. 提交先保存凭据，再原子保存非敏感 metadata；成功前 UI 不显示已完成。
5. Agent Plan“模型与工具”中的生成工具配置只允许在没有 active run 时保存、启停或删除；成功后 Main 重启 Core，使新注册从下一次输入开始生效。已开始 run 的工具快照不被改写。

effort 验证可能产生少量供应商消耗，不能与普通连接测试合并或静默触发。

| --- | --- | --- | --- |

OpenAI 最新模型及窗口来自 [OpenAI Models](https://developers.openai.com/api/docs/models)，Anthropic 当前模型和 Models API 字段来自 [Anthropic models overview](https://platform.claude.com/docs/en/about-claude/models/overview) 与 [Models list](https://platform.claude.com/docs/en/api/models/list)，Google 当前模型与可编程 token 上限来自 [Gemini models](https://ai.google.dev/gemini-api/docs/models) 与 [Models API](https://ai.google.dev/api/models)。Qwen 的三协议合同分别以 [Qwen API reference](https://help.aliyun.com/en/model-studio/qwen-api-reference/)、[Responses compatibility](https://help.aliyun.com/en/model-studio/compatibility-with-openai-responses-api) 和 [Anthropic Messages compatibility](https://help.aliyun.com/en/model-studio/anthropic-api-messages) 为准；普通 API 与 [Token Plan](https://help.aliyun.com/zh/model-studio/token-plan-personal-quick-start) 使用不同 Base URL 和凭据。目录 API 未公开稳定元数据、当前套餐未开放模型列表或凭据不能列出 endpoint 时明确保留“官方清单/手填”，不把静态候选标成 API 实时结果。

三协议由 profile 显式保存，Core 不按 URL 猜测；未知非空协议 fail closed。同一供应商、Base URL 和模型可以分别创建 Chat 与 Responses profile。三种 adapter 都投影为统一文本、思考、工具开始/参数增量/完成、usage、完成或失败事件；上层不解析供应商 SSE。Responses 固定 `store:false` 且不依赖 `previous_response_id`；Messages 处理 system/content blocks、图片/PDF、`tool_use/tool_result`、thinking/signature、`cache_control`；Chat 处理兼容消息、图片/文件 block、工具、reasoning 和 usage。Chat/Responses 的 function parameters 在 adapter 边界从 canonical tool schema 生成兼容副本：根保持 object 并去掉根级组合关键字，真实执行仍使用未改写的 canonical schema 校验。

`temperature` 是可选 wire 参数：只有请求 purpose 的明确策略、显式 request override 或 profile 中非零配置提供值时才发送，显式 override `0` 仍会保留；没有已知值时三个 adapter 都省略该字段，由目标模型使用自身默认值。Core 不再为未知/自定义模型注入通用 `0.7`。Kimi、DeepSeek、Ark 等已有 purpose/provider 策略继续通过明确 override 生效，不受该缺省变化影响。

DeepSeek 官方 Responses API 当前只支持 `deepseek-v4-flash`，尚不支持默认模型 `deepseek-v4-pro`。provider 仍公开 Responses 协议，但模型 capability 明确把 Pro 收窄为 Chat/Messages、把 Flash 标为三协议；连接弹窗在选择 Responses 时不把 Pro 列为候选，也不得用 Chat 成功推断 Pro 的 Responses 可用性。

协议能力分为 provider 与 model 两级。provider 的 `supported_protocols` 决定连接弹窗可声明的 adapter；具体模型的 `model_capabilities[].supported_protocols` 只记录 API observation 或版本化官方清单已经确认的组合。目录候选会排除“明确不支持当前协议”的模型，缺少模型级事实的未来模型与手填 ID 仍可输入，不因静态清单过期而硬拦截；连接探针和正式 run 返回才是当前 endpoint 的最终事实。同模型不同协议继续形成独立 profile、usage 与 cache identity。

Qwen 普通 API 与 Token Plan 是两个独立入口：普通 API 默认使用 `qwen3.8-max`，Token Plan 使用 `qwen3.8-max-preview`，不能用同一 endpoint/profile 混合解释。两类凭据都可按官方合同选择 Chat、Responses 或 Messages，但 Base URL 与 API Key 必须按计费入口成套使用。Token Plan 的目录同步只使用 Token Plan Key 请求 `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1/models`，不得回退普通 DashScope 目录；请求失败或返回空目录时保留版本化官方清单，并继续允许手填模型 ID。

MiniMax API 与 Token Plan 的内置入口固定为中国区：Chat/Responses 使用 `https://api.minimaxi.com/v1`，Messages 使用 `https://api.minimaxi.com/anthropic`。中国区与国际区 Key 不保证互通；读取存量 profile 时只把已知旧预置 `api.minimax.io` 地址归一化为中国区地址，用户显式填写的完整推理地址不被改写。MiniMax Chat 请求发送 `reasoning_split:true`，adapter 把累计 `reasoning_details` 快照去重为统一 reasoning delta；兼容端点仍把思考嵌在 content 时，由跨 SSE chunk 的前导 `<think>...</think>` 状态机分流。Renderer 永远只消费统一 reasoning/text 事件；存量 journal 中以 `<think>` 开头的完整 assistant 快照在重放时拆成 Thought 与清理后的回答，原标签和 Host policy 不再进入普通回答。

## 4. Profile、能力与持久化

`~/.awaken/config/models.json` 当前写入 version 3，version 1/2 继续兼容读取并在首次成功读取后无损迁移。`protocol` 是必填身份字段；旧 profile 只按所属 provider 的既有固定协议补齐，不按 URL 推测。每个 profile 的非敏感事实包括：

```text
id / providerId / displayName / modelId
baseURL / protocol / authScheme
enabled / isDefault
advanced.maxInputTokens / contextWindow / maxTokens / temperature
advanced.endpointId / inferenceEndpoint
advanced.supportsVision / supportsNativePDF / supportsVideo
advanced.supportsTools / supportsPromptCache / defaultReasoningEffort
credentialRevision / credentialReference / keyLast4
purposeRoutes.thread_title / compact_summary / subagent / scheduled_task / hook_prompt / hook_agent
```

其中 capability 与 purpose 字段保留为存量 schema、Core 快照和 Host 内部路由合同，不代表连接弹窗存在对应开关。Desktop 当前只允许用户编辑有效 `contextWindow`、`maxTokens`、模型启停与默认项；媒体、工具、缓存和 reasoning 由 API observation、官方清单和协议合同决定。

凭据引用分为 `profile_secret(profileId)` 与 `provider_account(providerId, accountId)`。存量 profile 缺少该字段时解释为 `profile_secret`；Agent Plan profile 固定引用 `volcengine-agent-plan-default`，不复制账户 key。

profile 去重身份为 `providerId + normalized Base URL + model/endpoint selector + protocol`；因此同模型的 Chat 与 Responses 可以共存，同协议同 endpoint 的重复项被拒绝。disabled profile 不能是 default；删除 default 后选择剩余可用项。默认模型只是新会话的初值，不是既有 thread 的强制覆盖。

`defaultReasoningEffort` 继续作为 capability 派生值和存量 schema 兼容字段存在，但 Desktop 设置页不提供编辑入口。用户可见选择只发生在 Composer；没有 thread 覆盖时由内部 profile/capability 默认值兜底。

### 4.1 能力来源与合并

能力事实合并为：

```text
版本化官方 MODEL_CAPABILITIES
  -> exact-scope 供应商 Models API observation 覆盖同字段
  -> 未提供字段保持 unknown
```

每个能力字段（包括模型级 `supportedProtocols`）同时携带 `source` 与可用时的 `observedAt`。供应商 API 返回值覆盖旧 observation 和官方兜底；用户只可把有效上下文/输出预算设得更低，或在最大窗口未知时手填该 profile 的运行限制，不能在前端声明图片、PDF、视频、工具或缓存支持。OpenAI `/models` 只提供基础目录，因此上下文与能力由版本化官方清单补齐；Anthropic/Google/Qwen 的 token 上限和嵌套 `capabilities/features/limits` 在 API 返回时直接归一化。模型原生能力不等于当前协议能力：Google 本轮经 OpenAI-compatible Chat 调用，官方兼容文档只确认图片输入，因此原生 PDF/video 与 `cached_content` 不被冒充为当前 Chat/file 或 `prompt_cache_key` 合同；PDF 走页面渲染回退。

动态缓存为 v2 scoped cache，严格 identity 至少包含 `provider + normalized Base URL + protocol + profile + credential revision + selector kind + endpoint contract`；相同 provider/model 但不同凭据、代理、自定义 Base URL 或接入点不得复用。v1 的 provider-global 缓存只能当冷缓存忽略，不迁移为新作用域事实。`/models` 只返回 context 时，不能覆盖同作用域内经过验证的 effort。新鲜 observation 在自己的 exact scope 内合并，不投影到其他 profile。

provider catalog 可以把同一 provider 已观测到的模型 ID 合并进候选列表，并标记 API 来源与最新观测时间；Main 先按上游 type/task/category/method 和已知模型族把目录条目归一化为 `llm | image | video | audio | embedding | unknown`，官方 LLM 选择器只接收 `llm | unknown`，不会把 Qwen `happyhorse-*` 等视频模型混入对话模型。稀疏标准 `/models` 返回的 unknown ID 继续允许选择，避免错误删掉未来 LLM。目录不得把某个 profile 的 scoped capability 值传播给其他 profile。Renderer 展示能力时优先使用 profile 摘要上的 exact-scope `effectiveCapability`，缺失时才回退版本化官方 catalog。

`default_max_tokens` 是新 profile 和缺省配置的输出预算，`max_output_tokens` 是不可突破的模型上限；Desktop、Desktop 启动的 Core、ACP 和定时任务必须遵守同一优先级与 clamp 规则。

`supportsTools` 不再对动态模型强制写 `ready`。API/官方清单未提供时保持 `unknown`；`unsupported` profile 不下发 function tool schema，未知时由运行时保守处理。连接测试不改写该字段。

## 5. Agent Plan 账户、目录分流与生成工具

当前只有固定账户 `volcengine-agent-plan-default`。非敏感 metadata 原子写入 `~/.awaken/config/agent-plan-account.json` version 2，保留旧 `modelIds` 读取兼容，并增加结构化 `catalog[]` 与 `builtinCatalogRevision`；文件权限为 `0600`。Key 使用 `.env` 中独立的 `AWAKEN_AGENT_PLAN_API_KEY_<accountId>` 命名空间；Renderer 只获得 `hasKey`、掩码、`credentialRevision`、结构化目录和更新时间。

`catalog[].kind` 只允许 `llm | image | video | unsupported | unknown`。分类由 Electron Main 完成：Main 先装载版本化的官方精确模型清单，再兼容消费上游未来可能提供的 `/models` 类型字段和已知模型族规则；Renderer 不按名称猜测。当前内置媒体清单包含 `doubao-seedream-5.0-lite` 与官方列出的 Seedance 2.0 / 2.0 Fast / 2.0 Mini / 1.5 Pro 精确 ID。两个选择器严格分流：

- Agent Plan 新建连接的主模型候选固定只展示 `ark-code-latest`；账户目录中的图片和视频条目不进入主模型选择和 Composer；
- Agent Plan“模型与工具”中的生成工具卡片只接收 `image | video`；每种 capability 最多一个配置；
- `unsupported | unknown` 默认不进入任一选择器；Agent Plan 主模型当前不提供任意自定义 ID 输入；
- Core 再读取账户 catalog 防御性校验，旧 profile 不能绕过 Main 把媒体模型作为主模型；`ark-code-latest` 始终作为已知 `llm` fallback。

保存账户或点击更新清单会对固定 endpoint 的 `/models` 做兼容探测。主模型候选始终固定为 `ark-code-latest`；完整目录继续分类、持久化并把最新的 `image | video` 条目提供给“模型与工具”页。火山 Agent Plan 当前对该路径返回 `404` 时，Main 写入版本化内置媒体清单；这表示供应商未提供目录接口，不表示 Key 无效。网络错误或其他上游失败保留内置与已有缓存。内置媒体清单只证明模型 ID 与类型受支持，具体套餐权限在首次真实工具调用时确认。旧 version 2 文件在读取时自动补齐内置条目并原子回写，保证 Core 与 Renderer 消费同一目录。`ark-code-latest` 的实际路由模型不固定，永远不展示 effort。Key 实际变化时 revision 单调递增；metadata 写入失败恢复旧 key。

媒体工具非敏感配置由 Main 独占写入 `~/.awaken/config/agent-plan-media-tools.json` version 1、`0600`：每条只保存固定账户引用、`media.image.generate | media.video.generate`、精确模型、enabled 和 configuration revision，不复制 Key。重复保存相同模型与状态是幂等操作；换模型、启停或 Key revision 变化都会形成新的后续 run provider identity。账户仍被任一 profile 或任一 enabled/disabled 媒体配置引用时拒绝删除。

配置保存、启停或删除在无 active run 时重启 Core。账户仍有媒体配置引用时，保存/轮换 Key 或刷新目录也走同一 active-run 门禁并重启 Core，避免旧 credential/catalog 工具继续留在运行时。Core 启动时只为同时满足“配置 enabled、能力与模型 kind 一致、固定账户 Key 可读”的条目注册稳定工具：

| 配置 capability        | 模型可见工具     | Provider capability |
| ---------------------- | ---------------- | ------------------- |
| `media.image.generate` | `image_generate` | `image.generate`    |
| `media.video.generate` | `video_generate` | `video.generate`    |

工具 schema 不含 provider、账户、Base URL、Key、生成模型或保存绝对路径；这些事实由配置快照固定。`image_generate` 当前支持文本生成单图或最多 15 张组图、可选 size/output format/watermark，调用 Agent Plan 图片生成接口，下载或解码结果并原子写入 `output/generated-media/`；组图逐项返回状态，单项失败时保留并发布已验证的 ready Artifact。图片创建使用独立 10 分钟上限，POST 超时按 unknown side effect 收口，禁止盲目重发。

`video_generate` 支持文本生成视频、可选 ratio/resolution/duration/audio/watermark，也支持把 ready PNG/JPEG Artifact 路径作为 `source_image_path`。Core 会为内联上传压缩过大的图片副本；`first_frame` 使用官方省略 role 的首帧结构，`reference_image` 显式发送 role。视频任务创建后立即耐久保存 task ID；同一 workspace、账户/模型和结构化请求在 Core 重启后再次执行会续查旧任务而不重复创建，也可显式传 `task_id` 续查。官方任务状态只投影 `queued/running/succeeded/failed/cancelled`，不伪造百分比；轮询窗口结束但 provider 未给终态时返回“状态待确认”，保留 task ID。提交超时且没有 task ID 时返回“创建状态未知”，当前 run 禁止再次提交视频任务，必须由用户先核对火山控制台。401/403、429、上游失败、部分成功、任务待确认与下载失败保持不同稳定错误码；未收到 HTTP 响应的网络故障只保留去敏 transport 分类，具体 Outcome 语义由[工具定义与暴露 §8.1](../04_工具权限与审批/工具定义与暴露.md)拥有。

当前已知缺口：尚未实现图片编辑、基于稳定 Artifact ID 的通用参考解析、按具体模型动态收窄全部参数矩阵、Core 启动后主动轮询、detached completion、完整媒体谱系与历史版本回选。现有恢复是在相同请求再次进入 `video_generate` 或显式携带 task ID 时续查，不在没有 run 的后台自行完成。图片/视频的 Workbench 过程卡和终态交付能力由[中间区域产品与交互契约](../01_桌面工作台/中间交互区域/产品与交互契约.md)拥有。搜索、Embedding 等其他 Agent Plan 独立工具不因本节自动获得支持。

## 6. Reasoning effort

Awaken 的统一内部语义为 `low | high | max`。UI 只显示模型真实支持的档位，并优先显示供应商 API observation 或版本化官方清单给出的原生小写英文标签；未提供原生标签时才显示统一档位。`displayLabels` 只改变展示，不改变 thread 持久化、缓存 identity 或 Core 请求策略。thinking 开关、reasoning effort 和 prompt-cache capability 是三份独立合同，不得因其中一份已知而推导另一份；MiniMax 的 thinking 开关不属于 reasoning effort。Kimi K3 的三档顶层 `reasoning_effort` 以[官方推理强度文档](https://platform.kimi.com/docs/guide/use-reasoning-effort)为准，K2.x/K3 的 thinking 差异以[官方思考模型文档](https://platform.kimi.com/docs/guide/use-thinking-models)为准。

| 接入模型                         | UI 档位        | Provider 实际值    | 默认   |
| -------------------------------- | -------------- | ------------------ | ------ |
| Kimi `kimi-k3`                   | `low/high/max` | `low/high/max`     | `max`  |
| Kimi Coding `k3`、`k3-256k`      | `low/high/max` | `low/high/max`     | `high` |
| Google Gemini 当前内置模型       | `low/high`     | `low/high`         | `high` |
| MiniMax M3                       | 不展示         | 无档位参数         | —      |
| GLM `glm-5.2`                    | `high/max`     | `high/max`         | `max`  |
| Qwen Token `qwen3.8-max-preview` | `low/high/max` | `low/medium/xhigh` | `max`  |
| Doubao `doubao-seed-2-1-pro-260628` | `low/high/max` | `low/medium/high`  | `high` |
| DeepSeek `deepseek-v4-pro`、`deepseek-v4-flash` | `high/max` | `high/max` | `high` |
| Qwen `qwen3.8-max`               | `low/high/max` | `low/medium/xhigh` | `max`  |

Agent Plan 精确模型只有在受控验证后才获得对应映射。Provider adapter 是原生值映射的唯一 owner；Renderer 和 Agent Core 只处理 Awaken 档位。

保存或迁移 profile 时，不在 capability levels 内的内部默认值会被拒绝。启动 run 的回退顺序固定为 `thread 会话覆盖 -> profile 内部默认 -> capability 默认`。非法、过期或能力变化后的值按该顺序恢复，并在 Renderer 显示一次非阻断提示；这些默认值不会形成第二个用户设置入口。

## 7. Composer 与 thread 选择

Composer 模型与 effort 都是会话级：

```text
RuntimeThread.selectedModelProfileId
RuntimeThread.reasoningEffortByProfile[profileId]
```

当前行为：

- Composer 当前模型按钮和模型列表只显示模型 ID，不追加 `Chat`、`Responses` 或 `Messages`；协议继续保存在 profile 中并参与调用、持久化和缓存 identity，但不作为输入框模型名称的一部分。
- 既有 thread 的 effort 吸附到档位后立即通过 typed IPC/API 持久化；
- 尚未创建 thread 时先保存在 Renderer 草稿，首次 run 与 thread 创建一并写入；
- 支持 effort 的模型从模型列表进入二级面板；卡点轨道与即时保存交互由[输入、斜杠菜单与附件 §3.1](../01_桌面工作台/中间交互区域/输入、斜杠菜单与附件.md)统一定义；
- 不支持档位的模型直接选择，不显示入口或占位；
- 标签显示 `模型名 · max` 等当前有效选择；
- run 期间禁用模型/effort 修改，变化只影响下一次 run；
- thread 已有消息时提示切换会重新建立上下文缓存；
- profile 被禁用、删除或能力变化时忽略失效 preference，回退当前可用 default，不批量改写历史 thread。

模型选择不再调用 `setDefaultModelProfile`。设置页的 default 只决定新会话初值，因此两个 thread 可以稳定使用不同模型和 effort。

thread preference 在写入 metadata 前由 Desktop Main 与 Core 双重校验：profile 必须存在、enabled 且凭据可用，effort 必须位于该 profile exact-scope capability levels 中。已删除、disabled 或不支持档位的请求直接拒绝且不改写 thread；打开旧 thread 时优先按其已保存 profile/effort 重建 snapshot，只在该 profile 不再可运行时回退 default。

## 8. Run 注入和缓存边界

Renderer 启动请求只传 `modelProfileId + reasoningEffort`，不传 Key、Base URL 或完整 profile。Electron Main 重新验证所选 profile enabled/ready，解析 profile/账户凭据、能力和有效 effort，再构造只发往本机 Core 的 `model_profile`。Renderer hints 在 Main 中清除，不进入 Core 的严格 create-run decoder。

Core 将有效选择写入：

- `AgentConfig.ModelConfig`；
- model profile/Agent cache key；
- prompt-cache affinity 与 reasoning policy；
- thread metadata；
- run snapshot 的 `model_profile_id` 与 `reasoning_effort`。

Doubao Ark 的 `model` 参数接受两类 transport selector：按量调用使用版本化精确 Model ID（例如 `doubao-seed-2-1-pro-260628`），自建推理接入点使用 `ep-*` Endpoint ID。设置弹窗在同一输入控件中提供官方 Model ID 候选并允许手填 Endpoint ID，不再把 `doubao-seed-2.1-pro` 这类展示名当成可调用 ID，存量该值读取/保存时迁移为当前精确 ID；也不强制按量用户先创建 endpoint。直接 Model ID profile 的 `model_id`、`capability_model_id` 相同且 `model_selector_kind=model`；`ep-*` profile 使用 `model_selector_kind=endpoint`，在没有明确 family 绑定时能力保持未知。Context Epoch、usage、Agent/profile cache identity 包含实际 selector 与 selector kind。旧 profile 若已经同时保存 family 和 `advanced.endpointId`，仍按原绑定读取，不破坏既有 endpoint。火山官方文档将 [Model ID 与 Endpoint ID](https://www.volcengine.com/docs/82379/1298459) 都定义为合法调用身份。

主 Agent turn 才发送 Composer effort。标题、compact、Subagent、`hook_prompt` 与 `hook_agent` 默认继承 thread/父 profile；Host 内部存在有效 route 时可以先解析该 route，但不在 Renderer 暴露用途选择器。Hook 配置最多覆盖已解析 profile 内的 model selector，不能选择 profile 或凭据。定时任务先使用任务显式 profile，未 pin 时才使用 Host 默认；显式 pin 失效时 fail closed，不静默换供应商。模型工具的 Subagent schema 不接受任意 `model_profile_id`，Host 决定凭据和成本。标题、Memory recall、compact、Dream、Subagent、两类模型 Hook 与定时任务使用各自 purpose/cache identity；切换用途、协议、profile 或凭据 revision 形成新的缓存 identity。

## 9. 连接、余额与错误

连接测试请求正文、key 和 Authorization 不进入 Renderer、SemanticJournal 或 thread metadata。连接探针允许最多 30 秒等待供应商完成非流式最小响应；超时只表示本次探针未在时限内完成，不改变已经保存的 profile、协议或凭据状态。profile-scoped usage ledger 只保存 request identity、脱敏 shape、nullable usage、最近一次白名单 rate-limit observation 和结果。用量窗口只展示供应商官方 API 返回的余额、套餐额度或组织用量：DeepSeek `GET /user/balance`、Kimi 普通 API 余额、Kimi Coding 套餐窗口、MiniMax Token Plan `GET /v1/token_plan/remains`，以及 OpenAI/Anthropic 组织用量与成本接口已接入。MiniMax Token Plan 复用用户保存的套餐 Key，按中国区 `www.minimaxi.com` 与国际区 `www.minimax.io` 的显式合同查询；文字模型 profile 只消费返回值中的 `general` 资源桶，并归一化为“5 小时额度”和“周额度”，不把 `video` 等媒体工具额度混进文字模型用量。计数型窗口展示计数，时间型套餐按供应商返回的 remaining percent 展示百分比；`status=3` 的窗口显示为无限，不用 `0 / 0` 或有限的 100% 伪装额度。若厂商未提供稳定公开 API，则不把未确认接口写死，也不扫描或汇总本地 journal、profile usage ledger、token、请求次数、rate-limit observation 或本地成本作为替代。

Google Cloud Monitoring、Qwen Model Studio 高级监控、豆包 Ark `GetInferenceUsage`、火山 Coding/Agent Plan 管理接口都需要独立于推理 Key 的云账号管理鉴权。当前 Awaken 不收集这些高权限凭据；用量窗口必须说明所需的项目、AccessKey/Secret、AK/SK 或只读权限，并提供对应官方授权/控制台入口，不能继续显示无上下文的“暂不支持”。Qwen Token Plan 尚无公开稳定的套餐 Key 直查合同，因此只引导官方套餐页面。普通推理 key 不冒充管理凭据；未实现官方余额的 provider 不能由连接测试或单次 inference usage 推断账户余额。

正式模型 run 的 Core transport 使用 03 域的[跨平台网络代理与恢复](../03_运行时与本地服务/跨平台网络代理与恢复.md)：macOS/Windows Desktop 在系统代理或继承的 loopback 代理开启/关闭后热同步 route，并在 model run 真正发起前完成一次有界校准；新连接自动选择可用代理或 direct。已写出请求体、已经产生 assistant stream 内容或可能计费的请求不因 route 变化盲目重放；其重试与单一 terminal 仍以 02 域运行失败合同为准。模型设置中的连接测试、余额与 Agent Plan 目录探测也先请求 Main 校准 route，但仍是 Electron Main 拥有的独立请求路径，不能单独证明正式 run route 已恢复；无论哪条路径都不得把代理失败改写为 key 无效或本地 `.env` 故障。

左侧栏个人入口不直接展示余额或配额，只在左对齐的“外观”与“设置”之间提供“查询用量”入口；打开独立用量窗口后才调用 `getModelProfileBalances()`。窗口左侧按该结果的 provider-scoped 条目列出已启用的 API / Plan，左右两侧均只展示厂商名称与 Logo，不展示模型 ID；右侧详情头也不重复显示“用量”标签，下方只展示供应商返回的余额、配额、组织用量、缺少管理 key、需要额外管理授权、仅能前往平台查看、暂不支持或查询失败状态。需要用户在供应商平台开通授权的条目必须带官方入口，且文案要明确推理凭据与管理凭据的边界。查询链路不额外聚合 Awaken 本地 token、缓存、请求、成本或 rate-limit 记录。左右两侧均通过 Desktop 的统一 provider 品牌映射复用 `AwakenProviderLogo`，未知 provider 显示首字母兜底。新增 LLM provider 时必须同时补齐品牌资源和统一映射，模型设置、Composer 与用量窗口随之同步展示，不允许在用量窗口维护第二套 Logo 对照。该呈现不改变 Main 的 provider 去重、请求超时和错误分类。

| 场景                                     | 行为                                                                             |
| ---------------------------------------- | -------------------------------------------------------------------------------- |
| 无 enabled profile                       | run 创建前失败，提示到设置配置                                                   |
| profile/account 无 key                   | run 创建前失败，不进入 provider transport                                        |
| `.env` 或 metadata 不可读                | fail closed，不覆盖原文件                                                        |
| thread profile 已删除/禁用               | 回退可用 default，并提示一次                                                     |
| thread effort 已失效                     | 按 profile/capability 默认恢复，并提示一次                                       |
| capability sync 失败                     | 保留静态和已有缓存                                                               |
| Agent Plan `/models` 返回 404            | 采用版本化内置官方清单；不把 404 解释为 Key 无效，媒体套餐权限待首次真实调用确认 |
| Agent Plan `/models` 网络错误或其他失败  | 保留内置与已有结构化缓存，不开放任意自定义 ID                                    |
| 媒体配置 kind 与 capability/目录不一致   | Main 拒绝保存；Core 启动再次 fail closed，不注册工具                             |
| 保存媒体配置时存在 active run            | 不写配置、不重启 Core，提示任务结束后重试                                        |
| 媒体配置保存成功但 Core 重启失败         | 保留已写配置并明确提示重启 Awaken；不得宣称工具已经生效                          |
| 媒体 provider 401/403/429/5xx 或下载失败 | 形成 typed tool Outcome，不改写账户、目录或本地凭据状态                          |
| provider 401/403/429/5xx                 | 作为 provider 错误，不改写成本地凭据文件故障                                     |
