## 真实 Desktop 场景

| 场景 | 操作 | 必须观察 |
| --- | --- | --- |
| 新线程与续轮 | 新建线程问答，再在同线程追问 | 第二轮能引用第一轮；thread identity 不变 |
| 同线程互斥 | 第一轮运行中再次提交 | 明确 busy/禁用，不创建第二条同 thread run |
| 主动提问 | 触发 1–3 个选项问题并回答 | 原 run 继续；回答只入账一次；无通用 ApprovalCard |
| 取消 | 分别在流输出与工具阶段取消 | 终态和未闭合 tool result 符合位置语义 |
| 上下文压缩 | 执行足够长的多轮任务 | 最近目标、关键结果和工具配对不丢失 |
| 工具失败恢复 | 让一个工具以可恢复方式失败 | 下一轮收到 recovery directive；不无限重复 |
| 重启恢复 | 完成多轮后关闭并从正式入口重开 | 历史重放无重复；中断执行标为未知而非重跑 |

所有 Desktop 验收通过 README 正式入口完成。直接调用 Go API 或 provider 只能作为分层诊断，不能替代产品验收。

## 证据要求

验收报告记录当前 commit、Desktop 版本/启动方式、workspace、实际步骤、自动化命令与退出码、预期和实际差异。截图只证明可见状态；thread/journal/终态判断还要有相应日志或测试证据。若当前行为与本文引用的契约冲突，应报告产品差异，不修改文档来掩盖。
