# 本地服务管理 · 需求文档

Desktop 负责本地 Core 的启动、连接、监督和关闭。用户从正式 Desktop 入口使用 Awaken，不需要自行维护另一个 Core。

## 启动和连接

打开应用后，Desktop 启动 Core，或校验身份后接管已有的受管 Core。启动中不能提前发送任务；接管或自己拉起成功后，工作台按已连接处理，不能继续显示“正在启动 Awaken”，技能/插件页也不能显示“Awaken runtime 未启动”。失败时显示原因和重启提示，不能显示成任务仍在运行。

应用自动处理本地端口和服务地址。Windows 的代理变化监听进程由 Desktop 一并管理，不是第二个 Core。

运行期间暂时无法刷新服务或模型信息时，保留上一次成功结果并提示刷新失败；成功返回空列表时才显示空状态。Core 停止或切换进程后清空旧进程信息，迟到响应不能覆盖新进程状态。

## 退出和恢复

退出时按所属关系关闭进程；不能误杀其他应用、不同身份或不同数据目录的 Core。断线后恢复已有记录，不自动重放已发生副作用的操作。

进程归属、身份校验、状态变化和异常恢复见[实现方案](实现方案.md)。

## 退出期间的准入与完成

接受退出请求后立即拒绝新运行。退出响应只表示已接受；只有实际 Core 进程结束，Desktop 才显示 stopped。关闭失败或超时必须阻止更新安装。收尾等待包括工具结果、终态与 Journal 末尾写入；超时保留未闭合记录，重开按 interrupted/unknown 恢复，不自动重跑。
## 共享依赖与执行路径

共享依赖由 Core 按任务需要准备，启动应用不自动安装 Office 依赖。管理器不可用时保留诊断，不阻断无关任务启动。目录、来源、安装和回收规则见[依赖与路径管理](../../03_运行时与本地服务/依赖与路径管理/需求文档.md)。
