# 产品与架构契约

## 1. 定位

Connector 是 MCP 与 CLI 两类 provider 的统一产品目录。definition 显式携带 `kind: mcp | cli`、可见名称、说明、类别、provider、auth type、trust/source、稳定 `providerId`、aggregate capabilities、dependencies 和 provider readiness。只有 `kind=mcp` 可携带 MCP config factory/inline config 并进入 MCP Manager；`kind=cli` 的安装、配置、授权和启停由 Electron Main 的 `CliConnectorManager` 独立拥有，不生成 MCP config，也不调用 MCP connect/disconnect。

CLI 连接器当前固定为 `dingtalk-workspace`（钉钉）与 `lark-cli`（飞书）。目录卡展示品牌标识、产品名与能力简介，不展示版本、安装来源或内部 readiness 枚举；整张卡与保留在右侧的「+」都只打开同一个连接详情弹窗，不直接执行安装。弹窗拥有完整 onboarding：未安装时显示「安装」；安装中同步显示 Main 上报的阶段与百分比进度，按钮变为「取消安装」；CLI 与官方 Skill 都成功后变为「点击授权」；授权完成后显示带勾的绿色「已连接」，鼠标悬停或键盘聚焦时切换为「取消登录」，点击调用官方 logout。受管安装同时把与固定 CLI 版本匹配、经过 SHA-256 校验的官方 Skill 安装到用户级 `~/.agents/skills`：DWS 使用官方稳定 mono 包 `dws`，Lark 安装当前官方仓库的全部 `lark-*` 包。已有 Awaken-managed CLI 在升级到本契约后，如果对应官方 Skill 整套尚未出现，会补装同版本官方 Skill，若用户或其他安装器已放入部分同名包则保留现场而不覆盖。登录由 Main 启动官方 CLI 并打开经过校验的官方 HTTPS 页面，用户只在官方网页完成操作；弹窗只显示等待/重试状态，不重复展示授权链接或二维码。它们只负责把经过验证的官方命令暴露给现有本机执行环境。具体业务命令仍由 Skill/Bash 与中央 ToolRuntime 契约拥有，Connector 不形成新的任意命令执行旁路。

aggregate capability 用于目录发现和解释“这个 Connector 大体能提供什么”，不是具体 MCP tool 的授权来源。具体 tool 在 server connected/auth-ready 且输入 schema 有效时即可调用；standard annotations、tool `_meta` 和 capability 只改善模型选择、目录与诊断，缺失、无效或互相矛盾都不形成 transport 前 gate。远端消息、删除及其他副作用权限由 MCP server 自身负责。

## 2. 当前来源

- builtin：五个 MCP definition 与两个 CLI definition；MCP 连接时生成并持久化 user MCP config，CLI 不写 MCP config；
- local：本地定义，连接时通过 `InjectDynamic` 注入当前进程，不持久化 dynamic state。

内建 capability/dependency 目前包括：DingTalk/Lark 聚合 `message.send` 并分别依赖 `dws`/`lark-cli`，browser connectors 聚合 `browser.interact`，Context7 聚合 `web.search`。这些仍不代表所有子工具都具备对应 per-tool 安全契约。

## 3. UI 状态

Connector 列表显示 source、provider identity、capabilities/dependencies 和当前 readiness。只有当前 MCP server snapshot 可证明 connected/needs_auth/failed；点击过连接或 config 存在都不是 connected 证据。

Desktop 的 MCP/CLI 展示分类只读取 Core `kind`，不得按名称或依赖关键字推断。CLI readiness 独立表达 activation、install、executable、configuration、authentication、overall、版本、ownership 与稳定安全错误；不得复用 MCP connected 状态。`ConnectorDefinition.Category` 仍是业务类别，不能与 kind 合并。

## 4. Ownership

| owner | 负责 | 不负责 |
| --- | --- | --- |
| Connector Registry | definition 合并、connect/disconnect、进程内 active owner 与 builtin provider identity 重启恢复 | MCP transport、tool schema/Outcome 与可选 Artifact bridge |
| MCP Manager | server/session、snapshot、tools/Skills 注册 | Connector 产品分组 |
| Tool Catalog/Runtime | provider snapshot、决策、Outcome | Connector 安装 UI |
| Desktop Main `CliConnectorManager` | 固定 manifest、CLI 与官方 Skill 下载校验、安全解包、`~/.agents/skills` 中固定官方包的原子安装、绝对路径探测、配置/授权子进程、激活入口与非敏感 readiness | 任意 renderer command/argv/cwd/env、业务命令和 MCP session |
| Desktop Renderer | 列表、连接详情弹窗、Main 投影的安装进度与 onboarding 动作、Workbench `ExternalActionGate` | 连接器 onboarding 授权链接/二维码、文件路径读取、CLI stdout/stderr、device code/token/secret、任意子进程参数或“选择 CLI”文件选择器 |

## 5. 产品动作与授权

连接器目录卡与其右侧「+」只负责打开连接详情弹窗。弹窗中的「安装」调用固定受管安装；Main 以 `CliInstallProgress` 事件投影真实阶段与单调百分比，安装期间同一按钮为「取消安装」，取消是正常终态并恢复到可重新安装，不显示失败残留。CLI 与官方 Skill 均完成后按钮变为「点击授权」，直接调用 Main 的固定 provider 授权生命周期，不创建 thread、不提交 Agent 消息，也不要求 workspace。DWS 默认打开钉钉官方浏览器登录页；Lark 在首次使用时先打开官方应用配置页，配置完成后自动进入用户授权。授权期间弹窗只显示「等待网页登录」，不展示链接或二维码；失败后显示「重新授权」。每个阶段完成后 Main 都以官方 `auth status` 重新验证并通过 CLI state 事件同步弹窗，只有验证成功才显示绿色「已连接」；该按钮悬停/聚焦显示「取消登录」，点击执行 provider 官方 logout 并重新探测 readiness。

Agent 或业务 Bash 在执行具体业务命令时若收到官方 CLI 的结构化授权要求，仍由 Tool Runtime 进入通用 `interaction_required` 等待，Workbench 以 `ExternalActionGate` 展示安全 HTTPS 链接/受控二维码；用户完成后由 Core 验证并最多自动重放原调用一次。连接器 onboarding 与 run-bound 授权是两条独立入口，但共享同一安全边界：device code、token、secret、原始 stdout/stderr 与二维码本地路径不得进入模型、Journal、AG-UI transcript 或历史 replay。

## 6. 当前缺口

- MCP builtin 连接会覆盖同名 user MCP config，当前没有通用的被覆盖副本/undo；DingTalk/Lark 旧内建 MCP 记录只在精确匹配退役工厂签名时迁移并先备份，修改过或手工同名记录保留并提示复核；
- builtin active owner 可由 canonical user MCP config 中匹配的 provider identity 重建；local/dynamic active owner 仍只在进程内；
- OAuth/401/WS 边界沿用 06；
- aggregate capabilities 与依赖是声明；MCP readiness 来自 MCP connection/auth，CLI readiness 来自 Main 的绝对路径版本/config/auth 探测；`dws doctor` 仅作内部诊断，不得覆盖已验证的授权可用事实；
- CLI 当前支持 macOS/Windows manifest 条目，Linux 为 `unsupported`；当前固定受管版本为 DWS `1.0.32` 与 Lark CLI `1.0.71`，官方 Skill 与相同版本一并固定，不解析在线 latest，也不调用 CLI self-update；
- 真实 macOS/Windows 安装、授权、过期、取消、重启与卸载旅程仍需按验收规范逐项完成；自动化与 fake CLI 不能单独声明完成；
- per-tool metadata 是可选目录/Artifact 扩展，不为 provider 执行后的诚信或可撤销性背书，也不授权或禁止 MCP 调用；
- 团队/远程 Connector source 如未接入真实 provider，不能以 UI placeholder 写成支持。

## 7. 代码 owner

- `src/connectors/types.go`、`source_builtin.go`、`source_local.go`、`registry.go`。
- `src/mcpclient`：最终 MCP server/tool provider。
- `apps/desktop/src/main/cli-connectors/`：CLI manifest、安装、探测、配置与授权生命周期。
- `src/agentcore/external_interaction.go`、`tool_runtime_external_interaction.go`：CLI 授权信号检测、`interaction_required` 等待与一次性重放。
- `apps/desktop/src/renderer/ExternalActionGate.tsx`：Workbench 外部操作 gate。
