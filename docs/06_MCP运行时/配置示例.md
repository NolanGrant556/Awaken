# MCP 配置示例

## 1. 用途与边界

本页只给出当前生产 `awaken-core` 可使用的 `stdio`、`http` 和 `sse` 配置外形。完整语义见 [配置、传输与生命周期](./配置、传输与生命周期.md)。

不要在文档、提交、截图或示例中放入 token、API key、cookie 或内网真实地址。

## 2. project native 配置

将以下内容保存为 `<workspace>/awaken.mcp.json`：

```json
{
  "servers": {
    "filesystem_read_example": {
      "stdio": {
        "command": "npx",
        "args": [
          "-y",
          "@modelcontextprotocol/server-filesystem",
          "${EXAMPLE_DOCUMENT_ROOT}"
        ],
        "env": {
          "NODE_NO_WARNINGS": "1"
        }
      },
      "displayName": "Filesystem example"
    },
    "remote_http_example": {
      "http": {
        "url": "https://${EXAMPLE_MCP_HOST}/mcp"
      },
      "displayName": "HTTP example"
    },
    "legacy_sse_example": {
      "sse": {
        "url": "https://${EXAMPLE_MCP_HOST}/sse"
      },
      "displayName": "SSE example"
    }
  }
}
```

该示例只说明 schema。使用 filesystem server 不会自动绕过 Awaken 的 TaskScope/file-bridge 策略。

## 3. Desktop 简写配置

Desktop “配置 MCP”可接受：

```json
{
  "mcpServers": {
    "example_stdio": {
      "command": "npx",
      "args": ["-y", "mcp-server-example"]
    },
    "example_http": {
      "url": "https://example.invalid/mcp",
      "transport": "http"
    },
    "example_sse": {
      "url": "https://example.invalid/sse",
      "transport": "sse"
    }
  }
}
```

当前 Desktop 会把这批条目写入 user MCP config，而不是 project `awaken.mcp.json`。

## 4. 明确不可使用的示例

下列形式不能作为当前生产配置：

```json
{
  "servers": {
    "not_supported_ws": {
      "ws": {"url": "wss://example.invalid/mcp"}
    },
    "not_wired_in_process": {
      "inProcess": {"serverName": "echo"}
    }
  }
}
```

`headers` 和 `headersHelper` 也不应出现在“已验证可用”配置中，因为当前 transport 没有将它们装入请求。
