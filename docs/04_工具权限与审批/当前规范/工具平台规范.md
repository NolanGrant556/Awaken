# Awaken 工具平台规范

本规范是 `docs/04_工具权限与审批/当前规范/全量无审核工具运行时落地方案.md` 的执行口径。Awaken 的正式方向不是更聪明地弹审批，而是：默认自动执行或直接拒绝，危险动作由运行时内建边界拦截或转换，删除默认进系统回收站，缺依赖/缺授权进入安装或授权恢复流程；除工具群发消息外，不再让用户在任务中途审核工具调用。

Shell 专项执行口径见 `docs/04_工具权限与审批/当前规范/Shell内置权限执行器设计.md`。shell 是 Awaken 内置本机执行面，不以项目文件夹、`readable_roots`、`writable_roots`、sandbox support、open-world 分类或敏感路径规则作为权限边界；shell 只保留删除进回收站与工具群发消息人工审核两条产品硬约束。

旧 `allow | ask | deny`、`always_ask`、通用 Approval Center、`AWAKEN_APPROVAL_REQUESTED` / `AWAKEN_APPROVAL_RESOLVED`、`/v1/runs/{run_id}/approvals/{approval_id}/resolve` 只允许作为历史 transcript 只读兼容概念，不得作为新 run 的可达路径。

## ToolDefinition 元数据

每个注册到中央工具池的工具必须提供完整 `ToolDefinition`，来源包括 `builtin`、`mcp`、`connector`、`skill`、`plugin`。

必填字段：

- `name`：全局唯一工具名，保留 `mcp__`、`skill__` 等命名空间。
- `displayName`：面向 UI 的名称。
- `source`：工具来源。
- `description`：给 LLM 使用的自然语言描述。
- `inputSchema`：JSON Schema。
- `annotations.readOnly`：是否只读。
- `annotations.destructive`：是否会写入、删除或通知外部系统。
- `annotations.openWorld`：是否访问外部网络。
- `annotations.requiresAuth`：当前调用是否依赖授权。
- `capabilityClass`：能力类别，如 `file_read`、`file_write`、`artifact_read`、`artifact_write`、`connector_read`、`connector_write`、`mass_message_send`。
- `trustedOrigin`：信任来源，如 `builtin`、`official_connector`、`third_party_mcp`、`local_skill`。
- `fileBridgeScope`：文件桥范围，第三方 MCP 默认 `none`。
- `networkScope`：网络访问范围。
- `requiresAuth`：授权需求及 provider 信息。
- `massMessageMetadata`：仅 `mass_message_send` 必填，包含渠道、收件范围、数量、正文/模板、附件、发送账号、来源工具。

工具缺少必填元数据时，registry 必须拒绝注册并记录结构化日志；不可降级成通用人工审批。

## 决策模型

`Decide()` 的唯一输出动作是：

- `allow`：自动执行。
- `deny`：结构化拒绝，工具不执行。
- `transform`：自动转换到更合适的安全链路，例如永久删除意图转换为回收站删除。
- `needs_auth`：缺授权，工具不执行，发起授权确认/授权链接流程。
- `needs_runtime`：缺 runtime，工具不注册或调用前阻断，进入 runtime 准备/修复流程。
- `unsupported`：当前平台或能力不支持，结构化拒绝。
- `needs_mass_message_review`：仅 `mass_message_send` 可进入的专用群发消息审核 gate。

`Decide()` 不得返回 `ask`，不得创建通用审批请求。用户 override 只能配置 allow/deny/能力范围，不允许配置 `always_ask`。

默认规则：

- 只读、workspace 内、安全 file/artifact/connector read 按 `TaskScope` 自动执行。
- typed file/artifact tools 的文件写入只能在 `writable_roots` 或 `output_roots` 内执行；越界、protected root、symlink 逃逸直接 `deny`。
- shell 可以读取、写入和操作项目外本机路径，是否成功由操作系统权限和命令退出码决定。
- 删除文件和目录必须经 `TrashAdapter` 进入系统回收站；TrashAdapter 失败时 fail-closed，不得永久删除。
- 远端删除、发布、提交、付款等未明确配置能力范围的外部写入直接 `deny`。
- 缺授权统一 `needs_auth`，由 Desktop 展示授权确认和授权链接。
- 缺 runtime 统一 `needs_runtime`，相关 typed artifact tools 不应注册给 LLM。
- 群发消息统一 `needs_mass_message_review`，审核通过前不得调用真实发送接口。
- shell 不需要 `require_escalated`、`dangerouslyDisableSandbox`、`allow_unsandboxed`、`full_access`、`extra_writable_roots`、`network_open` 等模型输入扩权语义；这些字段不得绕过删除或群发硬约束。

## TaskScope

每个 run、subagent、connector/file bridge、typed artifact tool 都必须携带 `TaskScope`：

- `scope_id`
- `workspace_root`
- `readable_roots`
- `writable_roots`
- `output_roots`
- `protected_roots`
- `attached_files`
- `connector_resources`
- `temporary_work_root`
- `execution_profile`

工具执行必须基于 `TaskScope` 做路径归一化、附件名解析、文件桥约束和产物落点约束。第三方 MCP 默认没有文件桥；官方 connector 也只能按当前 `TaskScope` 申请受限文件桥。

Awaken 内置 shell 和内置本地读工具是例外：shell 以本机路径和操作系统权限为准，不使用 `TaskScope` 作为读写边界；`read_file`、`read_artifact`、`list_files`、`grep_search`、`pdf_extract`、`image_inspect` 等本地读输入不使用 `readable_roots` 作为拒绝边界，可读取本机路径、相对当前工作区路径或已上传附件文件名。TaskScope 仍用于记录附件、workspace、输出目标和 typed tool/file bridge 的边界。

## 事件与 HTTP API

新 run 不得发出通用 approval 事件，也不得进入 `awaiting_approval` 状态。

当前工具相关事件：

- `AWAKEN_TOOL_PERMISSION_DECIDED`
- `AWAKEN_TOOL_PROGRESS`
- `AWAKEN_AUTH_REQUIRED`
- `AWAKEN_RUNTIME_PREPARE`
- `AWAKEN_RUNTIME_READY`
- `AWAKEN_RUNTIME_MISSING`
- `AWAKEN_MASS_MESSAGE_REVIEW_REQUESTED`
- `AWAKEN_MASS_MESSAGE_REVIEW_RESOLVED`
- `AWAKEN_PATCH_UPDATED`
- `AWAKEN_TURN_DIFF`

当前专用群发审核 API：

- `POST /v1/runs/{run_id}/mass-message-reviews/{review_id}/resolve`

旧通用审批 API 不得注册到新 server surface。历史 transcript 中的旧事件只能只读展示，Desktop 不提供按钮、bridge、恢复交互或 fallback。

## 群发消息审核

`mass_message_send` 是唯一允许人工审核的工具能力。审核 payload 必须包含：

- 收件范围
- 收件数量
- 渠道
- 正文或模板预览
- 附件
- 发送账号
- 来源工具

审核通过只对本次工具调用有效。拒绝后不发送、不重试、不改道其他工具。非群发工具不得进入该 gate。

## Typed Artifact Runtime

Work 场景必须优先使用 typed artifact tools 和打包 runtime，不依赖开发机 Python/Node、Codex cache 或临时复制源码。

第一批内建工具：

- `workspace_dependencies`
- `runtime_preflight`
- `artifact_read`
- `artifact_inspect`
- `artifact_render`
- `artifact_export`
- `spreadsheet_create`
- `spreadsheet_edit`
- `spreadsheet_chart`
- `document_create`
- `document_edit`
- `document_render`
- `presentation_create`
- `presentation_edit`
- `presentation_render`
- `pdf_extract`
- `pdf_render`
- `image_inspect`
- `image_convert`
- `media_probe`

Office/PDF/图片/音视频工具运行前必须经过 `runtime_preflight` 或工具内置 runtime resolver。缺 runtime 时发出 `AWAKEN_RUNTIME_MISSING` 或明确执行错误，工具保持可见并给出缺口，避免模型改道 shell。OCR、扫描 PDF 文字识别和 searchable PDF 不属于当前计划。

### PPT 生成与渲染边界

`presentation_create` / `presentation_edit` 不是普通文件写入工具，而是 PPT artifact executor。模型必须用结构化参数描述演示稿，不得用 shell、`apply_patch`、ZIP/XML 拼装 `.pptx`，也不得手写 CJK/XML font helper。

当前结构化输入至少覆盖：

- `theme`：`background`、`surface`、`primary`、`accent`、`text`、`muted`、可选 `font_latin` / `font_ea`。
- `slides[]`：`title`、`subtitle`、`body`、`bullets`、`images`、`notes`、`layout`。
- `layout` 固定 enum：`title`、`section`、`bullets`、`two_column`、`image_right`、`comparison`、`metrics`、`timeline`、`closing`；未知 layout 执行前失败，不得静默回退。
- `slides[].images[]`：`path`、`fit`、`caption`、`alt`、`x/y/width/height`。
- `render_preview`：默认保留 PDF/PNG 预览文件；`false` 只表示不保留预览路径，**不得跳过技术验证**。

`presentation_edit` 必填 `source_path` 与非空 `edits`，只允许增量 `update|replace|delete|insert`；未修改 slide 必须保留。禁止把全量重写继续描述成 edit。

本地图片素材可使用本机路径、相对当前工作区路径或已上传附件文件名；预览输出目录必须位于 `writable_roots` 或 `output_roots` 内。

### PPT 验证等级

工具结果必须返回 `verification_level`：

- `package`：PPTX 包可重新打开。
- `pdf`：LibreOffice 转 PDF 成功。
- `png`：Poppler 全部页转 PNG 成功，且 slide/PDF/PNG count 一致。
- `visual`：预留给后续视觉检查。

`verified=true` 至少要求 package + pdf + png，且 slide count、PDF page count、PNG count 一致。Poppler 失败、count 不一致或 runtime 缺失时：

- `verified` 必须为 `false`
- 可返回 `needs_runtime=true` 与 warnings
- 不得伪装成功

overflow、空白页、缺图进入 warnings；严重 package 损坏直接失败。

`presentation_render` 是独立的渲染检查工具，负责将已有 `.pptx` 转成 PDF 与 PNG 页面预览。它会写预览文件，因此按 artifact write 能力治理，不得伪装成只读工具。LibreOffice/Poppler 缺失时返回明确 runtime 缺口，不能改道 shell，也不能把失败标成 `verified=true`。

默认单元测试必须使用 temp runtime + fake probe/renderer，不得依赖用户 cache、Codex cache 或本机已安装 Office。真实 LibreOffice/Poppler integration smoke 属于 Phase 6 / Desktop 验收。

## ToolOutcome（Phase 1）

工具与 executor 返回给 `ToolRuntime` 的唯一结构化结果是 `tool.ExecutionOutcome`（协议名 ToolOutcome）。业务失败、process nonzero、deny、needs_auth、needs_runtime、unsupported 必须写在 outcome 中；Go `error` 只表达 transport/implementation 异常。

固定 Status：`succeeded`、`failed`、`denied`、`cancelled`、`interrupted`、`needs_auth`、`needs_runtime`、`unsupported`、`review_required`。

固定 TransportStatus：`not_started`、`completed`、`failed`、`cancelled`、`unknown`。

固定 SemanticStatus：`success`、`failure`、`neutral`、`unknown`。

固定 ProcessStatus：`not_applicable`、`exited`、`timed_out`、`signaled`、`spawn_failed`、`unknown`。

兼容字段：

```text
IsError =
  Status in failed, denied, cancelled, interrupted, needs_auth, needs_runtime, unsupported
  OR SemanticStatus == failure
```

禁止用 `IsError` 反向推导完整 Outcome。`ToolExecutionResult` 的兼容字段全部由 outcome 派生。

`ToolResult` / `ToolProgress` 事件必须携带：`toolStatus`、`transportStatus`、`semanticStatus`、`processStatus`、`processExitCode`、`processTimedOut`、`errorCode`、`errorCategory`、`retryable`、`recoveryOptions`、`durationMs`，以及宿主活动字段 `toolProgressStage` / `toolProgressMessage` / `toolProgressPercentage`。

Desktop 保留 canonical `toolStatus`，显示状态映射为：succeeded→done，failed→error，denied→denied，cancelled→cancelled，interrupted→interrupted，needs_auth/needs_runtime/review_required→blocked，unsupported→unsupported；仅有 ToolCall 尚无 ToolResult 时为 active。禁止用 content 是否为空或中文错误子串判断状态。

宿主活动描述由 `ActivityDescribingTool` + `ToolRuntime` 在执行前生成；Runner 不得再发通用 “Executing tool” / “Tool execution complete/failed” 双发进度。

完整字段、枚举与场景映射见 `docs/02_主智能体闭环/智能体能力与执行稳定性提升/实施方案.md` 第 6 节。

## 文本编辑与 apply_patch 降级（Phase 3）

普通单文件精确修改默认使用 `text_edit`，参数固定为：

- `path`
- `old_string`
- `new_string`
- `replace_all`（可选，默认 false）
- `expected_sha256`（可选，来自 `read_file` Diagnostic）

规则：

1. `path` 必须通过现有 `PermissionContext` / writable roots。
2. `old_string == new_string` → validation 失败。
3. 零匹配 → `text_not_found`。
4. 多匹配且未 `replace_all` → `text_not_unique`。
5. `expected_sha256` 不匹配 → `stale_file_revision`。
6. 同目录临时文件、保留权限、fsync、atomic rename；失败不得破坏原文件。
7. 成功结果包含 affected path、replacement count、before/after digest、unified diff。

文件工具路由：

| 场景 | 工具 |
|---|---|
| 普通单文件精确修改 | `text_edit` |
| 新建/覆盖普通文本 | `text_file_create` |
| 显式删除 | `trash_file` |
| 多文件 / 移动 / 删除 / 高级 diff | `apply_patch` |

`read_file` 的 `ExecutionOutcome.Diagnostic` 必须包含 `sha256`、`size`、`mtime`；模型 payload 可通过 `expected_sha256` 拿到 digest。纯文本 `Content` 保持兼容。

### ToolExposurePolicy

`RequestBuilder` 通过 `tool.ToolExposurePolicy` 过滤模型可见工具池：

- 普通 provider 默认隐藏 raw `apply_patch`，保留 `text_edit` 与其他 file tools。
- `ExposureCompat`：内部 transform / 兼容测试可继续暴露 `apply_patch`。
- `ExposureGrammarCapable`：仅当 provider transport 真正支持 grammar constrained decoding 时暴露 grammar 版 `apply_patch`。
- 不得在 prompt 中声称 `apply_patch` 已 grammar constrained，除非 transport 真实支持。

`apply_patch` parser/matcher 错误码：

- `patch_missing_begin`
- `patch_missing_end`
- `patch_invalid_hunk_header`
- `patch_invalid_line_prefix`
- `patch_context_not_found`
- `patch_context_ambiguous`
- `patch_stale_file`

并保留 `invalid_patch_format` / `patch_context_mismatch` 作为 FailureSupervisor 恢复映射的粗分类。

## Audit

每次进入工具决策的调用都必须产生 `ToolAuditRecord`，包含：

- `toolCallId`
- `runId`
- `toolName`
- `source`
- `annotations`
- `decision`
- `decisionReason`
- `decisionOrigin`
- `startedAt`
- `completedAt`
- `outcome`
- `affectedPaths`
- `trashedPaths`
- `taskScope`

Audit 只能记录决策来源和运行时边界，不得暗示存在通用人工审批 fallback。
