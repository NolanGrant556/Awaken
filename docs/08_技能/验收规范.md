# 验收规范

## 1. 自动化

至少覆盖：

- plugin 来源 root 只来自 `skills.SetPluginSkillRoots` / `PluginStore.EnabledSkillRoots()`，不再读取 `AWAKEN_PLUGIN_SKILL_DIRS`；plugin Catalog ID 为 `plugin__<plugin-name>__<skill-id>`（plugin-name 中 `.` 变为 `-`），`ValidateNameReserved` 拒绝本地包冒用 `plugin__`；
- 多来源路径、确定性优先级、同名/realpath shadow、无 Core bundled 隐式 fallback；多文件夹项目必须验证主文件夹优先、次文件夹按项目顺序发现、同 ID 次文件夹保留 shadowed、独有 Skill 保留真实 `ProjectPath`，同时证明次文件夹 `.agents/skills` 未被误并入 project 来源；`system-skills` 大小写保留目录在普通来源中直接跳过，而 bundled root 指向其内部时加载直接子包；project/user 覆盖 bundled、bundled 保留 shadowed，移除覆盖后恢复；
- 宽松 frontmatter、未知字段保留、四种状态和 source policy；
- Skill 正文中的 npm/pip、`generate.py`、`soffice`、`pdftoppm`、prompt-injection、删文件或群发文字都只是工作流内容，不在 discovery 阶段置灰/改写正文/执行包内脚本；当前负面回归是 `TestImplementationWordsAndScriptsDoNotDisableSkill`；
- 单一 `skill` 目录预算、用户/模型调用边界、调用时正文重读；`TestRequestBuilderInjectsSkillTriggerRulesAndCatalogIntoFinalToolSchema` 直接检查最终 provider request 的 `skill` tool schema，必须同时携带唯一一份固定触发规则、model-invocable Catalog 条目，并排除 `disable-model-invocation` Skill；触发规则本身不参与 Catalog 预算测试；
- Skill Registry 与统一工具注册的幂等性：同一 source、同一内容的连续 local reload 不触发 `onChange`，`MarkInvoked` 和 readiness 诊断不改变工具状态指纹；Manager 连续 `RefreshTools` 和无差异 reload 保持同一 `RegistrationID`/Registry generation，真实 Catalog 变化和正文-only 调用 binding 变化分别产生新执行 pin；
- Catalog 三级降级：预算充足时保留完整描述（`TestCompileCatalogUsesOnePercentAndNamesOnlyFallback`），project 条目同时保留实际文件夹 `source_path`（`TestCompileCatalogIncludesProjectFolderProvenance`）；预算不足但按条目均摊仍不低于约 20 字符下限时进入 `truncated_descriptions` 模式（`TestCompileCatalogDegradesToUniformlyTruncatedDescriptionsBeforeNamesOnly`）；低于下限时退化为 names-only（`TestCompileCatalogFallsBackToNamesOnlyBelowTruncationFloor`）；
- Skill 不注册工具、不改变父 `RunToolAvailabilitySnapshot`；`TestSequentialComplementarySkillsNeverIntersectParentToolPool` 使用 allowed-tools 完全互补的两个 Skill 顺序调用，必须证明两次都保留同一 pinned parent pool，不彼此求交；
- `TestAgentRefreshRunAvailabilityCarriesTaskAndSkillMetadataWithoutLoadingSkill` 必须证明 run 环境快照携带有界 source/root、TaskScope 临时根和 refresh reason，且这一步骤不注入 SkillContextBlock、不读取正文、不执行包内脚本；`TestExecutionEnvironmentSnapshotCapsSkillRootsAndRejectsInvalidTemporaryRoot` 必须证明根数量上限和非绝对路径拒绝；
- `skill_resource_read` 对 project/user/managed/additional/plugin/bundled/nested-legacy 的 host-owned SourceRoot、单包 realpath/symlink、root replacement、2 MiB、UTF-8 和 binary 分流；flat legacy/MCP 本地资源拒绝；
- fork 必须创建 child，缺 starter 显式失败；
- `skill_activated`/resource receipt 的压缩、重启恢复和父子隔离；同一 run 内重复激活同一 Skill 必须替换而非追加 `SkillContextBlocks`，与重启恢复路径的按 SkillID 取最新语义一致（`TestRepeatedImplicitSkillActivationReplacesInsteadOfDuplicatingBlock`、`TestRepeatedImplicitSkillActivationPreservesOriginalOrderPosition`）；
- composer selection 从 `StartRunRequest.ComposerTokens` 到最终 provider request 的完整合同：单选明确 `skill_id/source/activation_mode/invocation=user_composer/absolute root/absolute SKILL.md`，“这个”可稳定指向当前选择；多选保序且标记歧义；token-only 不注入伪用户文本；fork child、历史恢复和 model-invoked Skill 不冒充父 run 的 current selection；source/root/path mismatch 在 provider 前失败；
- 定时任务 Agent 编辑器复用首页 Slash provider：项目多文件夹 roots、目录筛选、结构化 token、create/patch/HTTP/FileStore round-trip 与 `StartScheduledRun.ComposerTokens` 透传均保持 identity、顺序和 `leadingText`；每次触发重新校验当前 Registry，提醒任务拒绝 token；
- MCP 动态注册、调用时 fetch、disconnect 注销和 re-register。
- `skill_install` 的 project/global target、五种 source、包上限/逃逸、`validate_only` 零写入/零 reload 与 proposed target、默认 abort、replace 原子 swap + 旧包 Trash receipt，以及 Trash 失败回滚且无 staging/backup 残留；
- `skill_package_export` 对 project/user 本地包的 source-root/realpath 锚定、完整资源与二进制 asset 保留、此前不存在的普通作者目录、在线包零修改，以及目标存在/受保护路径/包根替换 fail closed；
- project/user Skill 删除必须从受控安装根重新解析 ID、只接受直接子包、把完整目录移动到 Trash 并在响应前同步 Registry；Trash 失败保持原包不变，MCP/plugin/managed/additional/bundled/legacy 等非安装生命周期来源拒绝删除，bundled HTTP 删除返回 `SKILL_DELETE_SOURCE_UNSUPPORTED`；
- `SKILL.md` 预览覆盖 bundled/project/user/managed/additional/plugin/legacy、同名 winner 与 shadowed 条目的独立 `catalogEntryId`，并逐项验证原始 frontmatter/完整正文、路径伪造、root/symlink 替换、文件消失、非普通文件、非 UTF-8 和超过 2 MiB 整体失败；MCP 动态条目不得获得预览 identity；
- Desktop system-skills importer 使用临时 home 覆盖 dev/packaged 路径、首装、清单命中、app 版本和源变化、目标修改/缺失/额外文件、空资源根、中断恢复、交换回滚、缺失源与 symlink 拒绝；Runtime Supervisor 必须清除继承的 `AWAKEN_BUNDLED_SKILL_DIRS` 并注入固定目标；打包配置包含 system-skills，清理脚本不删除源资源；
- bundled Office 脚本回归使用 `scripts/tests/system_skills_office_test.py`：三包正文必须保持中文 Awaken 合同、`${AWAKEN_SKILL_DIR}`、`artifact_publish`、禁止管道吞错和禁止裸 LibreOffice 降级；可用的当前 Python 与 Python 3.9 必须真实导入三包 `office_runtime` 并完成临时目录生命周期。Word 覆盖独立 route、绝对执行计划、合法包、断裂 relationship、ZIP 路径逃逸和保守 run 合并；PPT 覆盖 route-scoped structural QA、页面注册、孤立 slide 与堆积图非法标签位置；Excel 覆盖 Windows `py -3` 启动说明、Shell 安全正斜杠路径、route-scoped recalc、表头/混合类型/零值输入剖面、公式识别、动态函数风险和外链在进入 LibreOffice 前的拒绝。该测试不依赖 Desktop userData，也不把本机 LibreOffice 真实转换冒充单元测试；
- Renderer 自动化断言默认 Awaken Skills、Awaken → 项目 → 全局顺序、bundled 独占分组、紧邻名称的“Awaken 内置”小字、所有小卡片都无删除和“可预览”文案、空态文案，以及 MCP 等无本地文件来源不提供详情入口；
- CLI 连接器受管安装 fixture 同步产生用户级 `~/.agents/skills/dws` 或声明的 `lark-*` 包，重启缺包补齐后 Registry 以 `agents` 来源发现；连接器只替换 manifest 声明的官方包，其他用户包保持不变，通用 Skill 删除 API 仍拒绝 `agents` 来源；
- Renderer/Design System 自动化断言四个来源直接复用 `AwakenSkillCard`、compact 开关、卡片不含删除入口；项目视图以 `project_id/display_name/folders` 建卡，零文件夹项目立即显示 `0 Skill`，多文件夹项目一次提交主文件夹优先的 roots。项目窗口默认只显示文件夹数量与主文件夹名称，展开紧凑 Popover 后只出现“全部文件夹”、文件夹名称、主标记和各自 Skill 数量，任何状态都不展示路径；每个文件夹在零 Skill 时仍可选择，选中后显示 `0 Skills` 与文件夹空态，切回“全部文件夹”恢复聚合卡片；每张 Skill 卡只显示实际来源文件夹名称。Agents 视图把全局与项目级 agents 条目直接铺在同一个 Skill 卡片网格中，不渲染来源根标题、路径、数量徽标、折叠控制或外层分组卡片。独立预览直接消费 `AwakenSkillPreviewDialog`，项目预览消费同目录的共享预览内容与删除按钮，Desktop 不保留 `skill-preview-*` 私有视觉 DOM/CSS。project/user/agents 预览统一固定 Dialog 尺寸与“信息区 + 文档阅读区 + 底部操作区”，正文初始焦点、旧请求隔离和 Escape；Skills 页面可见期间的 Catalog 同步需覆盖项目新建/改组、任一文件夹外部删除后卡片/数量更新、项目窗口保持挂载、失效预览退出和空态恢复；Markdown 覆盖 GFM 标题、列表、表格、代码块、引用、只读任务列表，并证明 raw HTML、脚本、危险/相对链接、外部图片与 Mermaid 不执行；

市场兼容验收使用固定、可审计的 [market manifest](../../src/skills/testdata/market_skills_manifest.json) 与 [market acceptance test](../../src/skills/market_acceptance_test.go)：20 个不同 GitHub owner/repo 的固定 commit/hash/license，以 opt-in fixture 原包执行 `LoadDir`，并分别通过 `PackageFromPath`/`InstallSkillPackage` 安装到隔离临时 project 后从 `.awaken/skills` 重新发现；核对安装后 `SKILL.md` hash、资源目录、scope/source/projectPath 与隔离 HOME sentinel，覆盖 scripts/assets/references 结构但不执行包内脚本、hook 或命令。清单与断言只以这两个文件为权威，文档不复制第三份表。

这 20 个是自动化中的真实上游包 fixture 加载/安装验收，不表示 Awaken Desktop 默认预装了 20 个 Skill，也不证明 Skills 管理页、Slash、inline/fork 或包内工作流已在真实 Desktop 逐包操作通过。这些产品事实只能由下节的实机 Desktop 验收证明。

脚本执行另有本机 Shell 自动化，不与上述“安装时不执行代码”冲突：

- `TestPinnedMarketSkillScriptExecutesThroughSupervisedShell` 保留作为显式 Workspace broker + Seatbelt 的可选受限 provider 回归，不代表 Desktop 默认路径；
- `TestInstalledSkillPythonNodeAndShellScriptsUseCurrentUserShell` 正式安装含 `.py`/`.mjs`/`.sh` 的 fixture Skill，三类脚本由默认 `local_user_direct_v1` 在真实 Skill 包路径执行，可向 workspace 产生结果，Outcome 必须保持 unobserved/unknown side-effect 语义而不伪造 staging changes；
- Node 依赖 probe 覆盖 package 主入口存在但 `package.json` 未导出的包，`ERR_PACKAGE_PATH_NOT_EXPORTED` 不得被当成 `MODULE_NOT_FOUND`，且探测不执行包入口代码。

这些自动化证明“安装/激活阶段不擅自运行代码，Agent 明确调用后按所选 provider 执行”。它们不代替真实 Desktop、网络、包管理器和第三方 Skill 端到端验收。

聚焦命令：

```bash
go test -count=1 ./src/skills ./src/skillruntime ./src/agentcore ./src/runtime ./src/server ./src/prompt
go vet ./src/skills ./src/skillruntime
npm run test:system-skills
```

只可报告本次实际通过的包；共享工作区被其他改动阻塞时要记录阻塞测试和错误，不能沿用旧摘要。

## 2. Desktop 验收

按根 README 正式入口打开真实 Awaken Desktop，在隔离 workspace 验证：

当前 macOS 验收基线已覆盖内置 Word、Excel 和 PPT 在真实 Workbench 中的模型触发、文件生成、内容/结构/视觉 QA 与 `artifact_publish` 交付卡片；也已在 Desktop 按正式入口关闭并重开后，核对原线程叙事、Word/Excel/PPT 交付卡片和 QA 结论仍能完整回放。后续改变该链路时仍必须重复本项验收，不得用重启前的可见状态代替。

1. Skills 管理页显示来源、锚定路径、四种状态、诊断和最近调用；
2. 页面默认打开 Awaken Skills，Tab 顺序为 Awaken、项目、全局；模拟 bundled 源为空或首次同步失败时显示“内置 Skills 未就绪，重启 Awaken 后重试”，项目与全局视图仍可用；
3. 首页与定时任务 Agent 编辑器的 Slash 都显示所选项目范围内所有 `loaded && userInvocable != false` 来源，选择后形成结构化 token；定时任务保存、重开编辑和真实触发后仍保持同一选择，提醒编辑器不显示 Slash；
4. 在 `qoderwork-ppt`、`pptx` 和其他 PPT Skill 同时存在时选择 `pptx`，只输入“这个啊”；模型请求中必须明确标记当前选择的 `pptx` identity/root/SKILL.md，不再追问或改选其他 Skill；
5. 用户显式调用可调用 model-disabled Skill，模型调用被拒绝；
6. inline 调用后继续对话，压缩和重开仍能恢复上下文；
7. fork 产生真实 child 行为，缺 starter 时展示结构化失败；
8. MCP Skill 连接后出现、调用时取正文、断开后消失；
9. 复制一个未带 `node_modules` 的真实 npm Skill 到隔离的用户级 Skill root；Agent 能根据 `SKILL.md` 在包根运行 `npm install`，联网执行安装脚本并写用户 Puppeteer 缓存，再从用户 workspace 以绝对脚本路径生成产物；新 run 复用已安装依赖；
10. 再以需要 Python、外部 CLI 或其他用户目录写入的 Skill 复验，确认不是 PPT/npm 专项放行；
11. 上述过程不出现权限提示、逐项审批、安装白名单或 typed-tool 阻断；
12. **模型调用触发规则**：安装若干可区分的 Skill 后，新线程内不做 composer 选择、直接用自然语言描述一个明显匹配某个已安装 Skill 的任务（尤其是同时要求多种交付物类型、各自匹配不同 Skill 的场景），核对模型在对应普通工具动作之前调用 `skill` 激活匹配 Skill，`skill_activated` 记录先于对应交付物的普通工具调用；
13. 用户在自然语言中显式点名一个已进入 model-invocable Catalog 的 Skill（非 Slash token）时，模型必须调用它；`disable-model-invocation` Skill 不得因自然语言点名而绕过边界，仍需用户通过 Composer/Slash 结构化 token 显式调用；
14. 与任何已装 Skill 均无关的任务（如修改一个代码文件）不应产生多余的 `skill` 调用；
15. 反复执行第 12 条至少 3 次独立会话，核对匹配 Skill 均在相关普通工具动作前被激活；未达到 3/3 时只能如实报告比率，不得声明该场景已通过；
16. bundled 卡片只出现在 Awaken Skills，“Awaken 内置”以小字紧跟名称；所有来源的小卡片都没有删除图标。project/user 必须先打开预览，再从预览底部点击删除并进入确认；取消不改变目录和列表，确认后对应完整包从 `.awaken/skills` 消失、进入系统 Trash、卡片同步消失且刷新后不再出现。bundled、agents、MCP 与其他非 project/user 来源不显示删除入口。
17. 仓库已随附 `word` / `excel` / `ppt` / `pdf` / `code-search` / `PDF_Max` / `skill-creator` / `plugin-creator` 八个 bundled 包：需逐包验证 Awaken Skills 视图加载与卡片展示、`${AWAKEN_SKILL_DIR}` 路径替换、user/project 同 ID 覆盖与移除后恢复；Office 包还需验证 `skill_resource_read` 读取 references、doctor 对已安装/缺失依赖的 route JSON 与绝对执行计划、Python 3.9 helper 执行、模型在任何相关 Bash/subagent 前激活所需 Skill，以及真实端到端调用（生成文件 → 内容/结构/视觉 QA → `artifact_publish` 卡片）和重启后回放。helper/validator 故意失败时不得通过 `tail/head/grep` 等管道变成 canonical success，也不得裸用 LibreOffice/Poppler 绕过 wrapper。Word 额外验证外部 DOCX 安全解包、read route 在 Pandoc/MarkItDown/LibreOffice 等外部依赖缺失时仍可用、正文/标题/列表/安全超链接/表格/注释/页眉页脚提取、复杂内容 warning、危险 ZIP/XML/链接拒绝、高保真模板基线和接受修订超时不得成功；PPT 额外验证旧预览目录拒绝、注册页数与渲染页数一致、模板/图表结构错误可定位，且最终版本每一页均有实际 Read 证据；Excel 额外验证输入剖面、重算前后公式缓存变化、外链拒绝、错误位置和高风险函数提示。`code-search` 需验证带语言、版本、具体符号、最小片段、风险和来源的真实 WebSearch 调用；`PDF_Max`（调用 ID：`pdf-max`）需分别验证固定路径/PATH 复用、缺失时固定版本安装、报告与 Markdown strict compile、逐页视觉复核和 `artifact_publish`，并确认通用 PDF/PPT 请求仍分别路由到 `pdf`/`ppt`。两个 Creator 还需在隔离 workspace 由真实模型完成 new + modify：完整候选导出、dry-run 零写入、同名 abort、明确 replace、旧包 Trash receipt、新 run 发现/调用，以及 Plugin 内 Skill/MCP 诊断与 stdio 权限披露。包含失败恢复的运行还必须核对中心 Activity Batch 的工具数、异常数与 canonical `TOOL_CALL_RESULT` 一一对应；recovery required / retry blocked 只出现在恢复状态或 Inspector 事实中，不得重复形成工具行。未执行的项只能如实声明基础设施自动化覆盖，不得声明相关工作流已验收。
