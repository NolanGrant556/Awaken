# 会话管理 · 需求文档

用户可以重命名、归档、恢复和删除会话。归档只改变会话入口；运行中的会话不能归档。

代码、接口和验证方法见[实现方案](实现方案.md)。

## 当前产品行为

- 新 thread 首轮提交成功后立即出现：带 `projectId` 的在所属项目下，空 `projectId` 的在独立“对话”分区。
- LLM标题生成前，展示首轮用户输入/附件/token推导的可读兜底标题。
- 后续 follow-up不会覆盖已有标题。
- `thread_title` 用途 profile 或当前 thread profile 可用时，runtime 按该 profile 的显式协议在后台生成短标题；生成不阻塞主 run、SSE 或 Workbench。
- 自动标题失败静默保留兜底，不显示错误徽标。
- 手动重命名使用Desktop内部dialog；Enter提交、Esc取消、空标题不可提交。
- 手动标题优先级最高，后续prompt、自动任务和普通列表刷新不得覆盖。
- 左侧 14px 方形点阵指示只表示该thread有active `running|cancelling` run，不表示标题生成。
- 当前左侧不显示 `needs input`、`ready for review`、`done` 等文字状态；旧切片中这些状态标签不是当前UI事实。
- 单条和批量删除会话共用 Desktop 统一确认 Dialog 与 typed bridge。项目 thread 走项目生命周期 cleanup，独立对话直接删除其 FileStore thread 记录；批量入口当前只在独立“对话”分区提供，运行中的独立 thread 禁选。批量结果按 thread 返回成功/失败，成功项刷新 durable 列表，失败项不从 UI 假删除。线程 `…` 菜单另含“归档”项（位于“重命名”与“删除会话”之间），归档语义、禁用规则与 Settings 归档页由 [会话归档设计契约](实现方案.md) 拥有。

## 当前不支持

- 用户配置自动标题prompt/长度；
- 自动标题失败重试按钮；
- thread metadata实时推送（当前为短期轮询）；
- 左侧文字状态标签；
- scheduled/cloud thread；
- 跨project合并thread；
- 精确scroll位置随thread导航恢复。

## 范围与实现状态

本文定义 Awaken 会话归档当前支持的产品、架构、状态、数据、异常恢复与验收契约。当前 Core、FileStore、HTTP、Desktop typed bridge、侧栏、Settings 与 Design System 已贯通归档能力；本文中的“当前支持”仍须由当前工作区代码、自动化测试和真实 Desktop 行为共同证明。

本节说明以下当前事实：

- 左侧项目线程与独立“对话”线程菜单中的归档入口；
- Settings 最后一个导航入口“已归档的聊天”及其项目分组列表；
- 归档、取消归档和从归档页删除的状态与交互；
- root Agent 通过内建只读工具列出归档会话、按 `thread_id` 分页读取历史的产品与安全边界；
- `archived` / `archived_at` 的持久化、查询和 HTTP/typed bridge 合同；
- 自动化与真实 Desktop 验收。

会话标题、运行指示和普通删除合同继续由 [会话标题与线程状态](实现方案.md) 拥有；项目与独立对话归属由 [项目与对话导航](../项目管理/实现方案.md) 拥有；FileStore、SemanticJournal 和物理删除边界由 [全局数据与会话存储](../../03_运行时与本地服务/数据存储与重放/实现方案.md) 拥有。归档不建立第二套会话存储，也不改变 transcript、附件、工具结果或项目 ownership。

当前版本不提供“全部删除”和额外“全部聊天”筛选器；这些能力不得作为归档首版的隐含范围。

## 目标与非目标

目标：

1. 用户可把已停止的项目会话或独立对话从日常侧栏中收起，但保留全部 Awaken 历史和产出引用。
2. 用户可在 Settings 的固定末项统一查找归档会话，并按原项目归属查看。
3. 用户可取消归档，使会话回到原项目或独立“对话”分区；也可沿用现有不可撤销删除合同永久删除。
4. 归档状态在 Desktop 完整重启后保持，且只有 FileStore metadata 是 authority。
5. 用户要求引用旧归档会话时，主 Agent 或当前权限允许的普通子 Agent 能先发现稳定 `thread_id`，再经 Runtime 读取有界历史。该工具不接受物理存储路径，也不返回其他子 Agent 的私有记录。

历史条目的来源身份和精确回读规则遵守[上下文与用量](../../02_主智能体闭环/上下文与用量/需求文档.md#每个-agent-的窗口与压缩模型)，归档不会使合法的来源字段变成读取错误。

首版非目标：

- 自动归档、保留期限、云同步、团队归档和导入导出；
- 多选归档、批量取消归档、全部删除和跨页批量操作；
- 定时任务专属 thread 的归档；其后续执行会继续复用固定 thread，首版由 [12 定时任务](../../../README.md#12_定时任务) 继续管理，不允许用普通会话归档打断调度链；
- 修改项目归属、标题、模型偏好、transcript 或产出文件；
- 从归档页直接打开或继续对话；恢复后才能从正常侧栏进入会话；
- 读取其他子 Agent 的私有历史、把归档正文自动注入所有 run，或让归档内容成为当前指令；
- 把归档实现为逻辑删除、cleanup job、移动 session 目录或复制到另一数据根。

## 用户操作

### 侧栏归档入口

- 项目会话与独立“对话”的单条 `…` 菜单按“重命名”“归档”“删除会话”排列；“删除会话”继续使用危险色，“归档”使用普通中性色。
- `running | cancelling` 会话的“归档”保持可见但禁用，辅助说明为“请先停止正在运行的任务”。Core 仍必须做同样校验，不能只依赖 Renderer 禁用。
- `source=scheduled_task` 的专属 thread 保持可见但禁用归档，辅助说明为“定时任务会话由定时任务管理”；Core 返回 `THREAD_ARCHIVE_UNSUPPORTED`。实现为这项判断补齐 shared/Renderer 的 `source` 投影，但不改变 source 的现有 owner。
- 点击“归档”不弹确认框；Desktop 调用归档 mutation，成功后才从普通侧栏 authority 列表移除。失败时保留原行并显示稳定 notice，不做无法核实的乐观删除。
- 若归档的是当前 active thread，mutation 成功后清理该 thread 的 Workbench 活动态、草稿 owner、Inspector 和文件 surface，进入“新建任务”空态；项目选择本身保持不变。mutation 失败则当前会话和所有输入保持不变。
- 归档成功不取消任务、不删除记录、不删除 Awaken 管理附件、不删除外部文件或会话产出。

归档或删除请求等待期间，用户可以切换到其他会话。原请求成功后只清理目标会话；只有完成时目标仍是当前会话，才进入新建任务空态。后来选中的会话及其文件区不能被迟到的响应关闭。

### 页面列表、搜索与分组

- 顶部提供本地受控搜索框“搜索已归档聊天”和项目筛选“所有项目”。搜索匹配归档会话标题，使用 Unicode 大小写不敏感的子串匹配；项目筛选只改变可见集合，不改变 durable 状态。
- 首版不增加第二个“全部聊天”筛选器：当前只有归档会话这一种列表类型，没有可执行的第二维语义。
- 列表始终按 `projectId` 分组。已知项目显示项目名称；空 `projectId` 使用“对话”；仍存在但已从侧栏移除的项目也使用 lifecycle 中的名称；若 metadata 引用无法解析的非空 `projectId`，以该 ID 独立成组并显示“未知项目（ID 后 8 位）”，不得把不同未知项目合并。
- 已知项目组沿用 FileStore 项目顺序，removed 项目接在 active 项目之后；“对话”组随后；未知项目组最后按稳定 `projectId` 排序。空组不渲染。
- 组内按 `archivedAt DESC, updatedAt DESC, createdAt DESC, threadId ASC` 排序。每行显示标题和归档日期；日期使用 Desktop 当前 locale，辅助技术名称包含完整日期时间。
- 空库显示“还没有已归档的聊天”；搜索或项目筛选无结果时显示“没有匹配的已归档聊天”，并保留清除条件入口；载入失败显示可重试错误态，不伪装成空库。

## 活动任务的归档与删除

主任务收尾必须等待子任务退出。兼容旧执行记录时，归档、回退和清理仍检查实际写入者；仍有活动执行或尚未退出的进程时必须等待其停止。界面切换不会停止任务；用户可在右侧顶栏停止全部任务，再进行历史管理。
