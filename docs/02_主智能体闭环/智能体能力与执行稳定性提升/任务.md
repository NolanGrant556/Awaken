OutcomeTool 固定接口：

~~~go
type OutcomeTool interface {
    ExecuteOutcome(
        ctx context.Context,
        input string,
        observer ToolObserver,
    ) (ExecutionOutcome, error)
}
~~~

约束：

- Go error 只表达 transport/implementation 异常。
- 业务失败、process nonzero、deny、needs_runtime 必须存在于 outcome。
- legacy tool 可以继续使用 Execute，但 ToolRuntime 必须统一适配。

## Phase 7：FailureSupervisor 和硬预算

### 进入条件

- ToolOutcome error code 稳定。
- Journal 可记录 recovery decision。
- text_edit 已可作为 patch 恢复工具。

### 7.1 新增 supervisor

新增：

- src/agentcore/failure_supervisor.go
- src/agentcore/failure_supervisor_test.go

修改：

- src/agentcore/runner.go
- src/agentcore/types.go
- src/agentcore/events.go
- src/context/context.go

实现：

- [ ] canonical call signature。
- [ ] normalized failure fingerprint。
- [ ] resource revision。
- [ ] per-turn 和 per-run 预算。
- [ ] BeforeCall 和 AfterOutcome。

固定规则：

- retryable=false 的 exact duplicate，第二次调用直接阻断，不真实执行。
- retryable=true 的 exact call 最多真实执行 2 次。
- 同 tool/resource/error class 最多真实失败 3 次。
- 每 turn 最多 6 次工具失败。
- 每 run 最多 12 次工具失败。
- 产品默认 MaxAgentTurns=128。
- 产品默认 MaxToolExecutions=512。
- 配置 0 表示使用产品默认值，不再表示无限。

### 7.2 Recovery policy

- [ ] invalid patch -> read + text_edit。
- [ ] context mismatch -> read + text_edit。
- [ ] process nonzero -> inspect exit/stderr + change command。
- [ ] needs_runtime -> RuntimeManager。
- [ ] skill conflict -> stop Skill/use typed platform tool。
- [ ] persistence error -> stop new side effects。
- [ ] non-retryable -> change strategy。

recovery 指令必须作为结构化 ToolOutcome 和语义事件进入下一模型轮，不只写日志。
