# Plan: ExecutionProfile 执行层落地 + Runtime 契约兑现

## Summary

本轮修复 code review 发现的 4 个缺口（2 P1 + 2 P2），将已定义的 profile/intent/decision/executor 契约从"文档级"变为"运行时不可绕过"的执行语义：

4. **P2: Shell 三层分级进入决策主路径** — CheckPermission 改用 ClassifyShellCommand，删除旧分类器，明确 Ask 仅为内部风险信号不触发用户审批

### Part 4: Shell 三层分级进入决策主路径 (P2)

#### 4.0 零审批与 Ask 语义说明

**关键设计决策**：`CheckPermission` 返回 `Ask` 在本系统中**仅为内部风险信号**，不触发用户审批 UI。零审批主路径由 `DecideExecution` 保证：

- `CheckPermission` 产出 `PermissionDecision`（Allow/Ask/Deny + RiskTone）→ 这是**输入信号**
- `DecideExecution` 消费该信号，产出最终 `ToolDecision`（Allow/Deny/Transform）→ 这是**最终决策**
- `ApprovalPolicy` from profile 控制是否在 Deny 时生成用户审批事件：
  - `ApprovalNever`（WorkspaceWrite/GuardianReadOnly/WorkspaceReadOnly 默认值）：Deny 即终局，不弹审批
  - `ApprovalOnDeny`（OpenWorldRestricted/DangerFullAccess）：Deny 后可生成 ApprovalRequest（future work，当前未实现该路径）

因此在零审批模式下，`CheckPermission` 返回 `Ask` 的唯一效果是让 `DecideExecution` 进入 `decideShellTransform` 分支（而非直接 Allow），最终产出 `Allow`/`Deny`/`Transform`。用户永远不会看到审批弹窗。

#### 4.1 重写 ShellTool.CheckPermission

**File:** `src/tools/shell/shell.go`

- 将 `CheckPermission` 改为使用 `ClassifyShellCommand`：
  ```go
  func (t *ShellTool) CheckPermission(ctx context.Context, input string, permissionContext tool.PermissionContext) tool.PermissionDecision {
      // ... parse params, validate ...
      cwd := resolveExecutorCwd(params.Workdir, permissionContext)
      tier := ClassifyShellCommand(params.Command, cwd)
      switch tier {
      case ShellTierInspectReadOnly:
          // Safe read-only: auto-allow. DecideExecution will hit the
          // StaticBehavior==Allow branch and allow without transform.
          return tool.AllowPermission()
      case ShellTierWorkspaceMutation:
          // Internal risk signal: routes to decideShellTransform which
          // will transform file writes to apply_patch or allow workspace
          // mutations per the profile. Ask does NOT trigger user approval
          // under ApprovalNever (the zero-approval default).
          return tool.AskPermission("shell command may mutate files within the workspace", tool.ApprovalRequest{
              Title: "Approve shell command",
              Description: shellApprovalDescription(params, "workspace mutation"),
              RiskTone: "warning",
          })
      case ShellTierOpenWorldSystem:
          // Internal risk signal: routes to decideShellTransform which
          // will deny open-world commands (or transform if applicable).
          return tool.AskPermission("shell command reaches outside the workspace or affects the system", tool.ApprovalRequest{
              Title: "Approve shell command",
              Description: shellApprovalDescription(params, "open-world system command"),
              RiskTone: "danger",
          })
      }
      return tool.AllowPermission()  // fallback
  }
  ```

## Assumptions & Decisions

1. **Profile 来源控制策略**：客户端只能请求 built-in profile by name。字段值被篡改时用 built-in 版本覆盖。`danger_full_access` 需要服务端环境变量 `AWAKEN_ALLOW_DANGER_PROFILE=true` 才允许，否则回退到 `DefaultProfile()`。
2. **EnvPolicy 白名单**：`EnvMinimal` 模式保留 `PATH`, `HOME`, `USER`, `SHELL`, `TMPDIR`, `LANG`, `LC_ALL`。这些是命令执行的最小必要环境。白名单可后续扩展。
3. **VisibilityPolicy 执行点**：在 observer 包装层执行，不是在 routeToExecutor 返回后。`visibilityFilterObserver` 在构造 observer 时就包装好，从源头控制流式输出。`VisibilityHidden` 丢弃所有 delta；`VisibilitySummary` 丢弃 delta，在完成后发截断摘要；`VisibilityFull` 透传。
4. **Shell Ask 语义**：`CheckPermission` 返回 `Ask` 仅为内部风险信号，不触发用户审批。零审批由 `DecideExecution` + `ApprovalPolicy=Never` 保证。用户永远不会因 `Ask` 而看到审批弹窗。
5. **ApprovalPolicy 执行**：当前由 `DecideExecution` 隐式执行（`ApprovalNever` → 不生成 ApprovalRequest）。`ApprovalOnDeny` 的 ApprovalRequest 生成路径为 future work，在注释中记录。
6. **Subagent spawner 范围**：`CreateSubagent` 是一个纯函数，不包含实际的 agent 生命周期管理（不启动 runner loop）。它只负责构建正确的 `AgentConfig`。调用方负责后续的 agent 创建和运行。
7. **旧 shell 分类器删除**：完全删除 `shellPermissionReason` 及其辅助函数，不做 deprecation。TODO 已明确标注它们是临时代码。
8. **TrashedPaths 双通道**：保留 `emitToolPermissionDecided` 上的 TrashedPaths 字段（始终为空），同时在 `emitToolResult` 上新增。前端从 `TOOL_CALL_RESULT` 读取。这样不破坏现有事件结构。
9. **SandboxPermissions 子集检查**：child 的 SandboxPermissions 必须是 parent 的子集。例如 parent=[read,write], child=[read] OK；parent=[read], child=[read,write] error。
10. **routeToExecutor 中 TrashedPaths**：从 `ToolExecutionOutput.TrashedPaths` 读取（由 executor 填充），替代当前的 `extractTrashedPaths` 文本解析。如果 executor 没有填充，回退到文本解析。
