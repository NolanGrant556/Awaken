# Typst 环境与编译

## 1. 获取共享环境

先调用 `load_workspace_dependencies({})`，取得包含 Typst 与字体的完整办公包。成功后每次 Bash 显式传入 `environment_ref`，使用返回的 Python 与 Typst 绝对路径。可运行包内 `scripts/typst_runtime.py resolve --json` 核对 `AWAKEN_TYPST` 与实际版本。PowerShell 调用路径时使用 `&`，按实际 Shell 规则引用中文和空格路径。

缺失或损坏时由 Core 统一准备，helper 不再自行下载或 force 替换版本。已有旧受管版本由管理器验证后登记；新实例不覆盖仍在使用的旧路径。准备失败时说明具体原因，不循环安装或改用项目私装。

## 2. 字体预检

`pdf_max` 提供共享的 Noto Sans CJK SC 字体，绑定中的 `TYPST_FONT_PATHS` 指向受管字体目录。未指定品牌字体的中文任务优先使用它，保证换电脑也能得到同样的结果。即使使用 Typst 绝对路径，Bash 也必须传入 `environment_ref`，否则不会携带字体目录。

使用已解析的 Typst 绝对路径列出字体；核对受管字体时关闭系统字体搜索：

```bash
"${TYPST_BIN}" fonts --ignore-system-fonts
```

- 不猜测字体名称；从真实输出选择完整 family name；
- 中文文档必须选择实际存在的 CJK 字体，并通过 `--cjk-font` 传给准备脚本；
- 模板要求的字体缺失时，先说明保真度影响，再选择用户允许的替代字体；
- 不把字体文件复制进 Skill，也不声称系统未安装字体已经嵌入。

## 5. 最小预编译与正式生成

只编译已经选择的唯一 base 和确切 imports，不遍历编译全部候选。

```bash
python3 "${AWAKEN_SKILL_DIR}/scripts/generate_pdf.py" \
  ./typst-work/report/main.typ \
  --typst-bin "${TYPST_BIN}" \
  --workspace-root . \
  --output ./deliverables/report.pdf \
  --strict
```

脚本使用同目录临时 PDF 编译；失败、超时、warning 或签名异常时不会替换已有最终文件。正式交付必须使用 `--strict`。

大型文档按章节或主要结构增量编译，但最终必须再执行一次完整 strict build。普通 Agent 任务不启动 watch 模式。
