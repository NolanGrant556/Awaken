## Awaken 当前接入

- 普通 API：provider ID `qwen`；Chat/Responses Base `https://dashscope.aliyuncs.com/compatible-mode/v1`，Messages Base `https://dashscope.aliyuncs.com/apps/anthropic`。
- Token Plan：provider ID `qwen-token-plan`；Chat/Responses Base `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1`，Messages 使用套餐专用 `/apps/anthropic`。
- 两个入口都公开 Chat、Responses、Messages；Key、Base URL、模型和计费分开。
- 普通 API 默认 `qwen3.8-max`，Token Plan 默认 `qwen3.8-max-preview`。

## 三协议兼容矩阵

| 协议 | 官方合同 | Awaken 当前 | 结论 |
| --- | --- | --- | --- |
| Chat Completions | 有 | 普通 API 与 Token Plan 已接入 | 支持 |
| Responses | 有 | 普通 API 与 Token Plan 已接入 | 支持；Awaken 当前仍 `store:false` 本地重放 |
| Messages | 有 Anthropic 兼容 | 普通 API 与 Token Plan 已接入 | 支持当前兼容子集 |

## 鉴权、端点与模型

- Chat/Responses 使用 Bearer；Messages 在 Awaken 当前 route 使用 `x-api-key`。
- 普通 API 与 Token Plan 的 Key/Base URL 必须成套使用；Token Plan 目录只请求套餐专用 `/models`，失败不回退普通 DashScope。
- 官方现在可能推荐 workspace/地域专用 endpoint；若与 Awaken 内置 generic Base 不同，先记录迁移影响并实测，不能静默改写已有 profile。
- 模型、区域和协议支持不完全相同，精确 model ID 是 capability key。

## 上下文、多模态与工具

- 图片、视频、原生文件和 tool calling 按 exact Qwen model + region + protocol 文档判定。
- Messages/Responses 兼容页没有确认的原生能力不得从 DashScope 原生 API 推导。
- Responses 的 tool call、stream event 和 `previous_response_id` 语义需与 Awaken adapter 分开验证。
- PDF Read 没有当前协议的原生文件合同则走页面渲染回退。

## 提示词缓存

- 官方文档区分隐式缓存与显式上下文缓存，支持范围、模型、最小 token、TTL 和计价各异。
- 当前 Awaken exact prompt-cache registry 尚未为 Qwen 内置入口建立专属 wire contract；因此不能仅凭官方原生能力显示已命中。
- Responses/Chat/Messages 的缓存请求字段和 usage shape 需分别落地；不要把 `previous_response_id` 当 prompt cache。
- 普通 API 与 Token Plan 即使模型名相近，也必须使用不同缓存 identity。

## 推理开启关闭

- Chat 常见 `enable_thinking`，Responses/兼容协议可能使用不同字段；按官方页面和模型逐项核对。
- Awaken 当前仅对 exact Qwen Chat provider/base/model 白名单注入 `enable_thinking`。
- 辅助请求可按合同关闭 thinking；未知模型不得自动注入。

## 推理强度

- Qwen 模型/协议可能支持 `reasoning_effort` 或通过 thinking 参数控制；原生档位随模型变化。
- Awaken 当前对 `qwen3.8-max` 和 Token Plan `qwen3.8-max-preview` 映射统一 `low | high | max` 到展示 `low | medium | xhigh`，默认 max。
- 官方更新档位后要同时改 capability、wire lowering、缓存 identity 和 UI 标签测试。

## 用量、余额、限流与套餐

### 用量查询合同

- A 类：per-request usage 按三协议分别归一化；区域、模型、batch/cache 和服务层级影响价格。
- `qwen` D 类用量：Model Studio 高级监控把数据保存在私有 Prometheus 实例，可请求 `{HTTP API}/api/v1/query_range` 查询 `model_usage`，并按 workspace、model、API Key ID、protocol 与 `usage_type`（input/output/cache 等）过滤。用户须先启用高级监控、从控制台复制实例 HTTP API 地址；高级监控按官方说明可能收费，数据为分钟级。
- `qwen` D 类资金：阿里云 BSS `QueryAccountBalance` 与账单 API 可查云账号层的余额/账单；基础 Model Studio 模型用量统计也可在控制台查看，通常约一小时延迟。
- `qwen-token-plan` E/D 类：个人/团队套餐可在控制台查看 5 小时、7 日等窗口；官方 `AliyunTokenPlanReadOnlyAccess` 策略公开 `QueryMembersUsage`、`QueryModelUsage`、`GetSubscriptionStats` 等控制面 action，但未找到足够完整的公开 endpoint/request schema，不能只凭 action 名实现。
- 凭据：Prometheus HTTP API 使用同一阿里云账号的 AccessKey/AccessKey Secret 做 Basic 鉴权；BSS 与 Token Plan 控制面也使用独立 AccessKey/RAM 权限。它们都不是 DashScope 推理 Key 或 Token Plan 调用 Key，优先最小只读权限。
- Awaken 当前：两类 provider 均未接入高权限管理查询；BSS 账户余额也不能表述成某个 Qwen 模型或套餐的剩余额度。普通 Qwen 用量页明确提示须启用高级监控并另行准备 AccessKey/Secret 与 Prometheus HTTP API 地址，提供官方监控入口；Token Plan 因套餐 Key 无公开直查合同，只提供官方套餐入口，不探测私有 API。

- 普通 API 账单与 Token Plan 周期额度不可互相折算。
- Token Plan 的团队/个人套餐、模型系数、并发、周期和支持工具以当前官方页为准。
- 429 要区分模型并发、RPM/TPM、账号额度和套餐限制；保留 `Retry-After`/错误码。

## Awaken 落地规则

- `qwen` 与 `qwen-token-plan` 是两个 provider identity，禁止目录、Key、Base、cache 和计费回退。
- Responses 当前不使用供应商服务端历史作为 authority；继续发送 `store:false` 并由 Awaken 重放。
- 官方 workspace endpoint 更新是迁移任务，需要兼容旧 profile、凭据 scope、缓存和目录。
- 三协议必须分别做连接、stream、tools、reasoning、usage 测试。
