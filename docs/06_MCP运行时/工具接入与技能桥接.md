# 工具接入与技能桥接

## 1. MCP tool 调用边界

MCP server 处于 `connected` 且不需要重新认证时，`tools/list` 返回的每个 tool 都会进入中央 Tool Catalog、run snapshot 和 ToolRuntime。调用只保留以下通用边界：

- server/session 必须仍然 connected/auth-ready，断开、移除或 needs-auth 不使用旧 session；
- 输入必须是合法 JSON object，并通过当前 adapter 支持的 input schema 校验；
- 调用遵守 run 取消、timeout、调用预算、失败监督和结构化 Outcome；
- MCP protocol/transport error 与 server `isError=true` 分开记录。

`tools/list` 的 external input/output schema 在注册前做保守归一化：Go MCP SDK 产生的 `type: ["null", "array"]` 等紧凑 nullable 联合等价转为 `oneOf`，包括嵌套字段；input 的完整 properties/items/required 继续进入模型工具定义与执行前校验，不能退化为只有 `type: object` 的空合同。output 的普通 object 保持原根，与 canonical Outcome 字段冲突的 object 整包放入 `mcp_payload` 后，返回的 `StructuredContent` 使用相同投影。adapter 不得因一个 nullable 嵌套字段无法直接反序列化为 `ToolParam` 而丢弃整个 schema。

模型可见投影支持渐进披露：启用时 MCP tool 定义不长期占用模型上下文，由统一的 `tool_find` 按需检索加载；该投影收窄由 [04 工具定义与暴露](../04_工具权限与审批/工具定义与暴露.md#31-工具渐进披露) 唯一拥有，不改变本节的注册、调用边界或 Manager 生命周期——deferred 工具仍完整进入 Tool Catalog 与 run snapshot，直接调用照常执行并触发自动激活。

Awaken 不再根据 tool 名称、标准 annotations、capability 或自定义 metadata 对 mutation、message、群发、broadcast、delete 等调用建立额外 transport 前 gate。无 annotations、无 `io.awaken.tool/provider/v1`、metadata 无效或 annotations 自相矛盾，都不阻止 `Manager.CallTool`。这使 OfficeCLI 一类只暴露一个通用 `officecli(command)` tool 的标准 MCP server 能直接工作。

版本化 `_meta["io.awaken.tool/provider/v1"]` 现在是可选目录/Artifact 扩展，只读取：

- `provider_id`、per-tool `capabilities` 和 dependencies，用于目录、诊断和 provider identity；
- `artifact_output`，用于选择性把 provider 返回的 bytes 提升为 host-owned Artifact。

缺失或无效 metadata 只产生 warning；capability 推断也只用于模型选择和诊断，不是调用授权。MCP tool 的远端权限、幂等性、副作用和删除恢复由 server 自身负责。若任务要求 Awaken 的 TaskScope 或 Trash，模型必须改用显式拥有这些合同的 typed provider；不能把这些保证写到普通 MCP 调用上。消息发送没有另一个 Awaken typed 审核合同。

## 2. 消息与删除

MCP message/send/broadcast/batch 和 delete tool 与其他 MCP tool 使用相同直通规则。adapter 不解析收件人、不要求消息审核、不消费一次性发送 grant，也不要求 `recoverable_delete` 或调用后 recovery evidence。标准 annotations 和 capability 仍可投影到目录，帮助模型理解用途，但不改变调用资格。

Awaken 不再提供 typed message review；`trash_file` 可恢复删除仍然存在，只属于 04 域明确接入该合同的 provider。MCP server 可能在自身实现中提供确认、回收站、权限或审批；这些属于 server 语义，Awaken 当前不验证，也不转换成 host Trash 或 host review 事实。

## 3. Host-mediated artifact output

声明 `artifact_output` 的 per-tool metadata 必须同时声明 artifact-writing capability；所有配置字段必须是 output schema 中的 required string。声明无效时仅停用 host Artifact bridge、记录 warning，并把调用结果按普通 MCP Outcome 返回；不得在 transport 前拒绝 tool。声明有效时，provider 只能返回 bytes，不能返回其本机 path 或“已发布”标记作为本地交付事实。adapter 对结果执行：

- strict base64 与 host 32 MiB 上限，provider `max_bytes` 只能进一步收窄；
- exact lowercase SHA-256；
- canonical forward-slash relative path，拒绝 volume/absolute/traversal/backslash；
- publishable extension、exact MIME、derived Artifact kind，以及 UTF-8/PDF/OOXML/OLE 基础签名；
- 显式 TaskScope 的 writable roots 与 output roots 双重解析、workspace real-path、sensitive/protected 和任何 workspace 内 symlink component。

全部通过后，host 以 provider/capability、relative path、digest、size、MIME、kind 生成不可变 `host_artifact_publish` projection，在 `WorkspaceExecutionBroker` private snapshot 写入 bytes。broker 复核 staged digest/size 与 exact single-file delta；replace 先把 live preimage 移入 Trash，再发布并返回 receipt。取消发生在 commit 前时只做 bounded background discard/cleanup；一旦 broker 已提交，即使后置验证失败，Outcome 也必须按 receipt 保留 applied/partial changes，不能倒写 `not_started`。成功 Outcome 不携带原始 base64，也不透传 contract 之外的 provider StructuredContent；只携带 canonical ArtifactDescriptor、由 contract 安全字段重建的 sanitized details、provider/hash/size/content-type 和 broker receipt。

该链路证明的是 bytes/hash/基础容器签名与 host-owned recoverable commit，不证明内容语义、版式、字体、公式、逐页视觉或 Office 兼容性。Awaken 当前不提供 typed artifact inspect/render；质量验证必须由文件格式自身的外部校验工具与真实 Desktop 视觉验收完成。

## 4. Prompt/resource Skill bridge

bridge 将 MCP prompt/resource 动态注册为 `mcp__<server>__...` Skill：

- 目录阶段只注册元数据和 fetcher；
- 调用时才请求 prompt messages/resource content；
- list_changed 触发重新注册；disconnect/disable/reconcile 注销；
- 最近调用时间在同一进程 re-register 时保留；
- server readiness 只作为执行提示，不把本地 Skill 置灰；
- server 正文中的 shell 只作为文本，不在 bridge 内执行。

动态 Skill 走 08 的统一 `skill` 工具、inline/fork 和 journal；MCP bridge 不反向控制 server lifecycle。

## 5. 不变量

- MCP tool 必须经中央 registry、run snapshot、ToolRuntime 和 Outcome；connected/auth-ready 与 schema 是进入 transport 的必要边界；
- 渐进披露只改变模型可见投影，不得成为第二套调用授权或注册旁路；deferred 与激活状态不影响本域任何调用边界；
- server-level provider identity、per-tool metadata、capability 和 annotations 都不授权或禁止 MCP 调用；
- MCP 不继承 typed provider 的 TaskScope、egress review 或 recoverable-delete 合同；
- disconnect 时工具和动态 Skill 都必须卸载；
- 外部 provider 的声明与实际结果冲突必须保留诊断，不能升级为成功。
- external output schema 的 nullable 联合、canonical 字段冲突 wrapper 与 `StructuredContent` 必须使用同一个确定性投影；不得因 adapter 表示差异产生虚假 output mismatch。
- 只有有效 `artifact_output` 声明走 host bridge 时，原始 artifact bytes 才必须从 model content、diagnostic 和 AG-UI 中移除；host commit 后只投影 canonical artifact/change/receipt。未启用 bridge 的普通 MCP 结果按通用 MCP output 处理，不获得 ArtifactDescriptor。

以上不变量不等价于已沙箱化任意 MCP server 进程。当前 stdio child 尚未接入 WorkspaceExecutionBroker/Seatbelt；server 可在工具调用内外自行读写/联网，边界见 [配置、传输与生命周期](配置、传输与生命周期.md#6-当前缺口)。

## 6. 代码 owner

- `src/mcpclient/provider_manifest.go`、`tool_adapter.go`：可选 provider metadata、连接检查与 MCP 调用 adapter。
- `src/mcpclient/tool_safety.go`：仅拥有可选 Artifact output contract 校验，不拥有普通 MCP 调用 gate。
- `src/mcpclient/artifact_bridge.go`：artifact result 校验、stage/commit、Outcome redaction。
- `src/tool/execution_broker.go`、`execution_broker_workspace.go`：host artifact exact-delta 与 recoverable commit。
- `src/skills/mcp_bridge.go`：动态 Skill。
- `src/tool/permission.go`、`src/agentcore/auto_tool_policy.go`：统一工具调用决策；不包含消息专用审核分支。
