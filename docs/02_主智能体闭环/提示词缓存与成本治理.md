# 提示词缓存、上下文用量与成本治理

## 1. 权威范围与当前状态

本文是 Awaken 当前模型请求投影、提示词缓存、上下文用量和逐请求成本口径的唯一权威。模型 profile、凭据和连接测试入口由 [05 模型与供应商配置](../05_模型与供应商配置/索引.md) 拥有；上下文压缩由 [上下文窗口与压缩](上下文窗口与压缩.md) 拥有；Workbench overlay、composer 和滚动不变量由 [01 中间交互区域](../01_桌面工作台/中间交互区域/架构契约.md) 拥有；SemanticJournal 与 wire 字段分别由 03、09 域拥有。

当前已支持：

- 以最终 provider-visible request 为基准的版本化分类估算；
- Composer“上下文窗口”入口和中文分类面板；
- DeepSeek 自动前缀缓存、Kimi CN/Kimi Coding Plan affinity key 与 cached usage 解析；
- byte-stable Context Epoch、append-only host delta 和 Kimi provider-opaque reasoning state 安全重放；
- 主调用、标题、Memory recall、compact、Dream、retry 和连接测试的作用域隔离账本；
- 大文本 tool result 在首次 model admission 前的一次性耐久 offload；
- DeepSeek 当前官方美元 token 价格的 request-time snapshot 与成本计算。

本文提到的 `subagent_definitions` 只是兼容分类。Awaken 当前仍没有正式 subagent runtime，不能据此声明已经支持子智能体。

## 2. 产品行为

### 2.1 Composer 与中文面板

- dock Composer 的入口文案为“上下文窗口”，值只显示“当前累计 / 可用输入窗口”两个数值，不追加“可用输入”文字；`可用输入窗口 = 模型总窗口 - 输出预留`。最近一次成功且 usage 完整的主调用与当前 model/protocol 兼容，且没有跨越 provider/model/compact 等不兼容 Context Epoch 边界时，当前累计值优先使用 provider `total_tokens`，缺失时依次使用 `input_tokens + output_tokens`、`input_tokens`，或完整的 cached/uncached/cache-write/output 分项和；重启或当前工具 schema 更新导致的 `tool_schema_changed` 只改变本地 projection，不丢弃同一供应商和模型最近一次已经完成的实报。没有可用的 provider 实报时才回退当前 `ContextUsageSnapshot` 本地估算。
- center 空态没有上下文快照时不显示假 0。
- 入口是 button，支持鼠标、Enter、Space，并暴露 `aria-haspopup="dialog"`、`aria-expanded` 和锚定关系。
- 面板不显示“本地估算”徽标或占比文案；标题“上下文用量”与“当前输入 / 可用输入窗口 Token”位于进度条上方同一行，不显示“约”、模型总窗口、输出预留或自动压缩阈值文案。分类只有系统提示词、内置工具、MCP、技能、记忆、对话六项；不展示多次调用账本或主/辅助调用分类。
- 面板在分类明细下方追加“上次请求”一节，只展示最近一条 `ModelUsageRecord` 的缓存与成本摘要，不累加多条调用，不展示 `raw_typed_usage`：
  - 缓存徽标由 `cache_mode` 与 `cached_input_tokens` 联合判定。`undocumented`（火山 Coding Plan）固定显示“未确认”，不声称命中或未命中；`automatic_prefix`/`affinity` 在 `cached_input_tokens` 缺失时显示“未知”，`> 0` 显示“已命中”，`= 0` 显示“未命中”；无 `cache_mode` 不显示徽标。
  - 命中/未命中 Token、输出 Token 行仅在对应字段非 null 时显示；缺失不折 0、不显示。
  - 成本行：`calculated_cost_usd` 非 null 显示 `$<amount>`（4 位小数）；为 null 显示“未知”，覆盖 Kimi Coding Plan、火山套餐与 custom endpoint 等无 token-to-plan 换算合同的情形。
  - 失效原因行：`invalidation_reason` 非空时显示，承载 prefix 冷边界或 append-only host delta 的 segment 级诊断（见 §6.2）。
  - 整节仅在该 record 携带 cache、cost 或 invalidation 信号时渲染；只有 status/purpose/inputTokens 的 record 不渲染该节，避免噪声。
- provider usage 仍以 nullable typed records 进入调用账本；它不改写 `ContextUsageSnapshot` 或内部压缩估算，但会成为 Desktop 当前累计汇总的优先数据权威。缺失 cached/cost 不折 0。

当前累计值与六项分类的显示投影遵守以下规则：

1. provider 实报只使用 `purpose=agent_turn`、`status=succeeded`、`usage_complete=true` 的最近记录；model、protocol 或 provider profile identity 不兼容时不得复用旧值；epoch 不一致时，只有当前 snapshot 的稳定创建边界为 `tool_schema_changed`，或旧记录尚无该边界字段时，才可在 identity 一致的前提下保留最近实报；`compact` 等已知不兼容边界必须回退本地估算；
2. 六项 typed 分类仍由 Core 本地 estimator 生成，provider 不提供分类；
3. provider 当前累计值高于六项本地和时，差额并入“对话”，与 provider-visible 协议开销、输出和 tokenizer 偏差使用同一归属；低于六项本地和时先从“对话”扣减，仍不足才按原分类占比非负缩放；
4. 因此面板保持原有六个字段、进度条和文案不变，同时保证显示分类和严格等于当前汇总；该显示 reconciliation 不回写 journal，不参与成本计算，也不替换压缩 governor 的本地估算。

### 2.2 交互与 placement

`App.tsx` 独占面板 open state、当前数据、触发器 ref 和 overlay 编排；`AwakenContextUsagePanel` 是纯 props/callbacks 的 Design System 组件。

面板位于 `RunStage.overlay`，外层 pointer-through、面板 pointer-auto；它不进入 `ExecutionFeed` 或 `composer-dock-stack`，不参与 ComposerDock 高度测量。面板使用实测 `composerBarInsetPx + 12px` 贴合输入框，不继承最终输出使用的 72px output safe gap。Escape、关闭按钮和点击外部均可关闭，关闭后焦点返回触发按钮。窄窗口保留安全边距并在面板内部滚动；主题只使用现有 Design System token。开关和原位数据更新不得改变 draft、IME composition、follow/paused、marker、return-to-latest、native tail、active turn 或 thread identity。

## 3. 当前上下文估算合同

Core 在最终请求投影完成后生成 `ContextUsageSnapshot`：

```text
schema_version / snapshot_id / estimator_id
basis: current_projection | sent_request
request_id? / request_sequence?
model_id / protocol_family / context_epoch_id? / context_epoch_boundary_reason? / request_shape_digest
model_window_tokens / output_reserve_tokens / effective_input_window_tokens
estimated_input_tokens
warning_threshold_tokens / auto_compact_threshold_tokens / compact_target_tokens
contributions[]: kind / estimated_tokens / source_count
generated_at
```

当前估算器 ID 为 `awaken_leaf_v4`，snapshot schema 为 v4。它统计 provider-visible leaf；发送请求时工具分类优先使用协议 lowering 后的最终工具 JSON，媒体使用本地模型估算，JSON/协议结构开销并入对话。以下不变量不可绕过：

1. `sum(contributions.estimated_tokens) == estimated_input_tokens`；
2. debug-only projection 不计入；
3. Memory context 单独计数；Skill 只统计统一 `skill` 工具中模型可见的 catalog name/description/when-to-use，`skill` 工具自身的触发规则与参数 schema 仍属内置工具；已激活 Skill 正文、host selection binding、附件和 tool result 均进入对话且同一内容只能计入一次；
4. 分类来自 prompt section、message origin/identity 和 tool provenance，不由 Renderer 按字符串猜测；
5. `ContextActualTokens`、最近 provider total 或 output 不参与 Core 本地窗口估算和压缩估算；它们只按 §2.1 参与 Desktop 当前累计显示；
6. 历史附件和 tool-result media 先按当前 pinned profile 的 vision/native-PDF 能力生成请求副本；不支持的二进制媒体仍留在 thread storage，但不进入 provider body，也不计媒体 payload token。稳定文本说明与 metadata 仍归对话；
7. 打开 thread 时，Desktop 先用当前可运行的默认模型 profile 请求 Core 重建当前下一请求的 v4 projection；Core 从耐久 conversation、当前工具/MCP、Skill catalog/已激活正文和 Memory 生成并 flush `context_snapshot`，再读取 transcript。旧记录没有 breakdown、只有 v1 `skills_memory` 合并值或来自 `awaken_leaf_v2` 时不得拆分旧数值；无法取得可运行 profile 时才保留已有汇总和“暂无分类明细”。已耐久的 `awaken_leaf_v3` 不原地改写，成功生成的 v4 新 record 作为后续 authority；
8. 算法版本变化必须通过 `estimator_id` 显式呈现。

当前 wire kind：

| Kind | 中文标签 | 内容 owner |
| --- | --- | --- |
| `system_prompt` | 系统提示词 | base instructions、host/project rules 与当前兼容性 authority definitions |
| `builtin_tools` | 内置工具 | 源码注册的稳定 builtin tool schema，以及内置 `skill`/Skill resource 工具自身的触发规则与参数 schema；不含 Skill catalog metadata 和任何 MCP adapter tool |
| `mcp` | MCP | 用户在连接器/MCP 配置中接入、由 MCP server 当前返回且实际下发模型的工具 name/description/input schema；connector-backed adapter 的 model-facing origin 仍为 `SourceMCP`，connector ownership 只保留在 provider manifest；MCP 调用结果进入对话 |
| `skills` | 技能 | 统一 `skill` 工具实际下发模型的 catalog name/description/when-to-use；工具包装和完整 Skill 正文均不在此项 |
| `memory` | 记忆 | 已准入当前请求的 Memory context |
| `conversation` | 对话 | runtime/environment、history、tool result、attachment/media、本轮输入和 provider-visible 协议结构开销 |

v1 的 `rules_project/runtime_context/mcp_dynamic_tools/skills_memory/subagent_definitions/conversation_history/tool_results/attachments_media/current_input/other` 只作旧 SemanticJournal 读取兼容，新 snapshot 不再写入。新 v4 snapshot 的六项始终全部返回到 Renderer，0 也是真实值；v3 只按 journal 中原数值展示，不伪装成 v4 计算。回放多个 run 时，后续 run 未产生快照不得清空该 thread 最后一个合法快照。

## 4. 请求准备与 provenance

prompt section 保留稳定 ID 和 typed kind；`context.Message` 保留 host-owned origin、message/turn identity；model-visible tool schema 通过不下发 provider 的 wrapper 保留 builtin/MCP/dynamic、provider、registration 和 Skill catalog provenance。provider 仍只看到普通协议工具定义，不看到这些 host 字段。

`conversation_continuity` 是位于 system prompt 尾部的稳定 `system_prompt` section 与 Context Epoch source。它只声明同一任务历史的解释规则，不复制历史正文、不携带历史数量或任何 thread/run/session/message/turn identity；内容不随消息轮数变化，因此同一版本不会产生逐轮 `append_only_host_delta`，也不会因会话增长破坏已建立的稳定前缀。会话指代行为由[上下文窗口与压缩](上下文窗口与压缩.md)拥有。

LLM transport 使用 prepare-once 合同：adapter 只做一次协议 lowering，产出不可变 `PreparedRequest`，其中包含最终 endpoint、精确 HTTP body、request-shape digest、stream 属性和 prompt-cache metadata。`InvokePrepared` / `StreamPreparedWithObserver` 只能发送该 body，不能在 journal fsync 后再次重建或改变请求。

真实模型请求前必须先耐久并 flush 脱敏 `model_request`；响应、错误或取消使用同一 request ID 写 `model_usage`。对话状态变化后写当前下一请求的 `context_snapshot`。打开旧 thread 时，`POST /v1/threads/{thread_id}/context-snapshot` 使用当前模型 profile 只重建并耐久化 current projection，不调用 provider、不生成 model usage；相同 projection 不重复追加。终态 session 仍在内存时，transcript 合并器必须补入该耐久 snapshot，不能因它未经过旧 run 的 live EventBus 而过滤。以上 records 不包含 prompt、规则正文、tool 参数、Memory、路径、cache key、API key 或 reasoning。

## 5. Provider 缓存 capability

唯一 `PromptCacheCapability` 由规范化 provider ID、精确 Base URL、protocol family 和 endpoint contract 联合匹配。仅完整匹配已核验厂商 endpoint 时可发送厂商私有字段；custom/兼容 endpoint 只发送协议通用字段并探测响应。

| Provider / endpoint | 当前模式 | 请求行为 | usage 语义 |
| --- | --- | --- | --- |
| DeepSeek `https://api.deepseek.com` | `automatic_prefix` | 不发送 cache key 或私有缓存字段 | 解析 hit/miss；input 为二者可验证组合 |
| Kimi CN `https://api.moonshot.cn/v1` | `affinity` | host 自动发送 `prompt_cache_key`，stream 请求 `include_usage` | 解析 `cached_tokens`；缺失保持 unknown |
| Kimi Coding Plan `https://api.kimi.com/coding/v1` | `affinity` | 必须发送 host key，stream 请求 `include_usage` | 解析 `cached_tokens`；缺失保持 unknown |
| 火山 Coding Plan `https://ark.cn-beijing.volces.com/api/coding/v3` | `undocumented` | 不发送缓存私有字段，只做响应探测 | 未确认字段保持 unknown |
| custom Base URL | 无厂商 capability | 禁用厂商私有字段 | 只保留 provider 实际返回的通用字段 |

DeepSeek 合同依据为[自动前缀缓存文档](https://api-docs.deepseek.com/guides/kv_cache/)，Kimi 请求合同依据为[Chat API](https://platform.kimi.com/docs/api/chat)。厂商合同变化时先更新 manifest、最终-body fixture 和 usage normalizer，再修改 transport。

`llm.Usage` 采用与 OpenCode 相同的双层语义：厂商回报是用量事实，协议 mapper 只做归一化；本地 `awaken_leaf_v4` 不参与计费。`input` 与 `output` 是 inclusive total，分别包含 cache read/write 与 reasoning；`uncached input`、`cached input`、`cache write` 和 `reasoning` 是互不重叠的 breakdown，raw typed usage 保留厂商原字段供审计。字段均为 nullable，缺字段不能折 0。

OpenAI Chat/兼容协议从 prompt/completion details 归一化 cached、cache write 与 reasoning；`uncached = input - cached - cache_write` 仅在关系合法时生成。Anthropic 的 `input_tokens` 是 non-cached，归一化时使用 `inclusive input = input_tokens + cache_read_input_tokens + cache_creation_input_tokens`，并合并 stream `message_start` 与最终 `message_delta` usage。当前尚无 Gemini、OpenAI Responses 或 Bedrock protocol mapper，不得宣称已覆盖。

## 6. Affinity、凭据 revision 与 Context Epoch

### 6.1 Affinity key

需要 affinity 的 endpoint 使用：

```text
aw1_ + base64url(SHA-256(
  provider_id + profile_id + credential_revision
  + endpoint_contract_id + affinity_scope_id
  + model_id + reasoning_policy + prompt_schema_version + purpose
))
```

同一 root thread、profile、credential、model、endpoint、reasoning policy 和 purpose 的 resume/restart 保持稳定；任一 identity 变化形成冷边界。标题、Memory recall、compact 和 Dream 使用独立 purpose/scope，不污染 `agent_turn`。

`models.json` 的 `credentialRevision` 单调递增：新 profile 为 1，API key 实际变化才递增；旧 profile 缺字段时稳定解释为 1。兼容字段 `promptCacheKey` 仅可读取，不再作为 transport override。journal、telemetry 和 UI 只保留 key 是否 applied 与摘要，不保存 key 正文。

### 6.2 Context Epoch

system、rules 和初始 canonical tools 构成 byte-stable baseline；日期为日粒度。Memory、Skill、MCP、runtime 和跨日变化只在安全 provider-turn boundary 追加 typed host delta。

exact baseline、source snapshots、canonical tools 和动态 trailing partition 耐久写入 `sessions/<thread>/context/epochs/` 的 `0600` 原子 sidecar。SemanticJournal 只保存 epoch ID、digest、状态和边界原因，不把 prompt、规则正文或路径投影到 wire。

builtin tools 按类别/名称固定排序；dynamic tools 按首次发现顺序耐久追加。更新、删除或 authority 不兼容等无法 append-only 表达的变化建立新 epoch，绝不降成普通 user message。compact 只有在摘要校验、journal append 和 flush 成功后才以 `compact_succeeded` 切换 epoch；失败或中断继续使用旧 epoch。

`ContextEpochReceipt.BoundaryReason` 携带本次 projection 的 prefix 变化诊断，写入 `ModelUsageRecord.InvalidationReason` 并在面板“失效原因”行展示；`CreationBoundaryReason` 在新 epoch 创建时固化并跨重启保留，随 `ContextUsageSnapshot.context_epoch_boundary_reason` 进入 Desktop，用于区分可保留最近实报的工具 schema 更新与 provider/model/compact 等不兼容边界：

- 硬边界返回 `initial_baseline`、`prompt_schema_incompatible`、`workspace_moved`、`provider_credential_changed`、`model_changed`、`provider_authority_incompatible`、`compact_succeeded`。
- source/tool 触发重建返回 `system_prompt_changed`、`tool_removed`、`tool_schema_changed`、`canonical_tool_added`。
- append-only host delta 返回 `append_only_host_delta:<segment1>,<segment2>`，segment label 为变化的 source key（如 `runtime_context`、`skills`、`memory`）或 `tool:<name>`（新接入的动态工具）。空 detail 退化为 `append_only_host_delta`。这让“MCP/技能/日期变化导致缓存打冷”可以从 reason 直接定位到具体 segment，而不是一个笼统的 host delta。

provider 私有 reasoning/续接状态作为 assistant record 的 `provider_opaque_state` 保存。只有 provider/profile、credential revision、model、protocol 和 endpoint 全匹配时才重放给 provider；普通 projector、Memory、日志和 telemetry 忽略其正文。面向用户的过程历史是另一条 provider-neutral 路径：transport 归一化的可展示 reasoning 在 SemanticJournal 写为 `reasoning_summary`，只用于 AG-UI/Desktop 重放，不参与 provider cache/history 续接，也绝不从 opaque state 降级生成。

## 7. 逐请求账本与成本

`ContextUsageSnapshot` 是当前 provider-visible 内容的本地分类估算；`ModelUsageRecord` 是一个已结束 provider 请求的用量事实。二者必须继续独立耐久化，Desktop 只在显示投影中按 §2.1 以最近实际累计值校准六项分类，不把两类 authority 合并成一条 record。

`ModelUsageRecord` 保存 request/purpose/provider/profile/credential/model/protocol/endpoint、cache mode/applied、epoch/prefix digest、retry/fallback、nullable normalized usage、raw typed usage、完整性、pricing snapshot/cost、provider request ID、latency、status/error 与完成时间。

作用域互斥：

- thread-bound `agent_turn`、`thread_title`、`memory_recall`、`compact_summary` 和 retry 写当前 thread SemanticJournal；
- Dream 的 `memory_maintenance` request/usage 嵌入独立 DreamTask authority，不双写 thread journal；
- `connection_test` 写 profile-scoped `~/.awaken/usage/model-profiles/*.jsonl`，不写 thread 或 Dream authority。

启动恢复发现 `model_request` 没有终态 usage 时，补 `status=interrupted`、`error_code=usage_unknown`，不伪造 token。provider request ID 只有响应确实提供时才保存。

辅助模型策略：

| 主 provider | 辅助模型 | fallback |
| --- | --- | --- |
| DeepSeek | `deepseek-v4-flash` | 否 |
| Kimi CN | `kimi-k2.6` | 否 |
| Kimi Coding Plan | `kimi-for-coding` | 否 |
| 火山或 custom | 复用主模型 | `auxiliaryFallback=true` |

预算为：标题 48、Memory recall 256、compact 8192、Dream 4096、连接测试 1。标题先使用本地规则：attachment/Skill label，或无问号换行且不超过 12 个中文字符/8 个英文词的短输入；其余才调用辅助模型。

DeepSeek `deepseek-v4-flash` 与 `deepseek-v4-pro` 使用随 record 固化的官方美元 pricing snapshot；实现中的当前 snapshot 生效日为 2026-07-19，来源为[官方价格页](https://api-docs.deepseek.com/quick_start/pricing/)。Kimi Coding Plan、火山套餐和 custom endpoint 不做 token-to-plan 换算，`calculated_cost` 保持 unknown。

## 8. 大 tool result admission

超过 32 KiB 的文本 tool result 在第一次进入 journal/model context 前完成一次性 offload：完整内容写入 `sessions/<thread>/tool-results/<tool-call>/content.txt`，目录 `0700`、文件 `0600`；journal/context 只使用含 digest、字节数、稳定 preview 和 storage key 的 admission projection。恢复消费已经投影的 record，不重新截断，也不在请求后事后替换。

媒体 tool result 继续使用同一 thread-owned tool-results authority 和 storage key 水合；Base64 不进入 journal、AG-UI 或日志。

## 9. 当前不支持与未知

- 火山 Coding Plan 是否存在透明缓存、是否返回稳定 cached usage，官方尚未确认；Awaken 不发送未文档化字段。
- Kimi Coding Plan 的 `cached_tokens` 可能缺失；缺失保持 unknown。缓存如何折合会员套餐额度没有 token-to-plan 换算合同。
- 服务端 TTL、驱逐、路由和命中率不受 Awaken 控制；Awaken 不承诺固定节省百分比。
- custom endpoint 不继承官方 DeepSeek/Kimi 私有字段或官方价格身份。
- 当前没有正式 subagent runtime；分类预留不改变该事实。
- provider 尚未返回完整 usage、实际记录与当前身份不兼容或刚完成 compact 时，当前汇总回退本地计数；请求前计数不是 provider tokenizer 的精确计数，record 保留 estimator version，UI 不显示“约”或“本地估算”徽标。
- Windows/Linux 尚无本能力的真实 Desktop 当前基线，不能由 macOS 自动化推断为跨平台通过。

## 10. 真实 Desktop 验收

| ID | 操作 | 当前验收合同 |
| --- | --- | --- |
| AC-CU-01 | 打开有上下文的 dock thread，鼠标/键盘打开面板 | 只有系统提示词/内置工具/MCP/技能/记忆/对话六项；存在同 identity 的完整主调用 usage 时，汇总等于 provider 当前累计且显示 reconciliation 后六项求和与汇总一致；没有实报时回退本地分类和；面板紧贴输入框，无新增说明文案、徽标、占比文案和模型调用账本 |

| AC-CU-06 | DeepSeek 与 Kimi 的同构多轮工具请求 | provider usage 驱动 Desktop 当前累计但不覆盖 Core estimator/journal snapshot；切 provider/model/protocol 或跨 compact 等不兼容 epoch 时不复用旧 usage，纯 `tool_schema_changed` epoch 仍保留同一供应商和模型最近实报；DeepSeek/Kimi capability/key/nullable cached 语义与 SemanticJournal 及脱敏 canary 一致 |

AC-CU-02/03/05/07 必须提供录屏或连续关键帧；静态截图、Gallery、浏览器 renderer、直接 provider API 或自动化 fixture 只能辅助。上下文 overlay 同时适用 Workbench [AC-007～AC-010、AC-021](../01_桌面工作台/中间交互区域/验收规范.md)。

真实 provider canary 对每个 endpoint 使用 5 组稳定/冷对照、每组三轮，共 30 次调用；保存 request digest、key applied、typed usage、provider request ID、状态和延迟，不保存 prompt/key。transport/key/usage 关联必须 30/30 正确，10 个 warm turn 至少一个非零 cached read；官方未返回 cached 字段时只能标 unknown。运行必须设置费用/额度上限，并在 429、余额不足、路由或合同漂移时立即停止。
