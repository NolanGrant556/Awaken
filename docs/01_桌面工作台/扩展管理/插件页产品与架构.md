# 插件页产品与架构

本文唯一拥有 Desktop「扩展 > 插件」的列表、安装、组件控制台和失败展示。包格式、Store、digest、generation 与 runtime projection 由 [14 插件](../../14_插件/索引.md) 拥有。

## 1. 当前支持

插件与技能、连接器并列。Renderer 只通过 typed Main/Preload bridge 调用 Core，不读取 `~/.awaken/plugins`、manifest、Keychain 或 runtime config。

### 1.1 Catalog

列表使用 Design System `AwakenPlugins`：

- 使用「内置插件 / 已安装插件」两个页签，首次进入显示内置插件；切换按钮复用连接器页 MCP/CLI 的轻量分段视觉，不使用包围整组的底板或选中项白色卡片阴影；搜索只作用于当前页签；
- 搜索、双列/窄屏单列、empty/error；App 在 Desktop ready 后预取一次来源中立的 Plugin catalog，插件页挂载时同步使用这份内存快照，后台重验不得先清空卡片或展示整页 loading；
- 名称、格式标签和描述；格式标签固定紧邻名称右侧，列表不展示版本、Skill/MCP/其他组件数量或“兼容 / 部分可用”等包级兼容胶囊；真实加载错误继续使用诊断文案表达；
- 内置卡片显示「Awaken 内置」而不是方言标签，整体开关是用户的激活入口；内置插件不能从 Console 卸载；
- 整体启停；
- 卡片主体进入完整控制台；
- “安装插件”是唯一新增入口。

普通图标只从 Design System registry 消费 `plugin` / `plugin-default`，Renderer 不内联 SVG。内置插件可消费 Core 投影的受控品牌键；当前只有 `outlook`，Design System 使用 Microsoft 官方彩色 Outlook SVG，并固定为 Composer 14px、36px 卡片容器内 28px、52px 详情容器内 34px 三档光学尺寸，不裁剪、不拉伸、不改色。未知品牌键必须回退通用插件图标。

### 1.2 直接安装

`AwakenPluginInstallDialog` 只支持本地 ZIP 文件。弹窗固定说明“兼容 Codex、Cursor、Claude Code、Agent Plugins 格式”，并只展示一个 ZIP 拖放区和取消/安装动作：

1. 用户点击拖放区打开 Main 的 ZIP-only picker，或直接把单个文件拖入该区域；
2. Preload 使用 Electron `webUtils.getPathForFile` 解析拖入文件，Main 对点击与拖放来源执行相同的本地文件和 `.zip` 限制；Renderer 不读取或猜测文件路径；
3. 来源确定后 Desktop 自动调用 Core 校验，不提供“检查插件”按钮；
4. 若 Core 返回 `SKILL_PACKAGE_SELECTED`，关闭插件弹窗并切到 Skill 安装弹窗，保留同一 ZIP，用户只需确认 project/global 范围；普通 Skill 不写入 Plugin Store；
5. 非 ZIP、不可访问或包格式不符合时，拖放区显示错误态并在弹窗内给出有界错误；校验通过且 digest 非空时，拖放区变为浅绿色并允许安装；
6. 安装使用该次自动校验的 expected digest；来源变化时自动重新校验，不复用旧结论。Skills 安装入口选择到插件 ZIP 时执行反向路由，仍回到本弹窗完成 digest 校验。

安装弹窗不展示包详情、组件统计、进程/网络意图、同名替换勾选或权限确认勾选。同名插件固定使用安全替换事务，旧包先进入 rollback staging，新状态提交成功后才进入 Trash；插件数据按 14 域契约保留。插件运行组件继承当前登录用户权限是 Awaken 默认运行模型，不由 Renderer 建立第二套可选权限状态。

### 1.3 Plugin Console

`PluginConsole` + Design System `AwakenPluginConsole` 是详情 owner，也是 plugin Skill 唯一的管理与浏览入口。plugin Skill 不进入「扩展 > 技能」四个视图、搜索、数量、空态或该页面的预览状态。

Console 首屏保持产品化和来源中立：点击卡片后先用同一 Plugin catalog 快照同步显示顶部身份区，再在后台读取组件、配置与 setup；不能先停留在列表或切换到整页 loading。组件、配置与 setup 第一次读取成功后按当前 runtime client、插件名和 digest 保存只含非敏感 DTO 的内存快照；用户返回列表再进入同一版本详情时必须同步渲染该快照并在后台静默刷新，不得重新显示组件骨架，插件被替换或 digest 变化时不得复用旧快照。顶部只显示插件图标、完整名称、可选版本、可用时的卸载和整体开关，整体开关固定为最右侧操作；名称允许在可用宽度内自然换行，不使用 ellipsis 截断或裁切字形，内置/版本元信息跟随换行。内置插件改为显示「Awaken 内置」且不显示卸载。页面不显示来源方言厂商、安装路径、digest、兼容胶囊、完全访问 notice 或组件状态汇总。顶部身份区下方可显示紧凑的“待完成设置”，只列当前待配置、待连接、进行中、失败或 unsupported 的 setup item；账号 setup 全部 ready 时不显示“待完成设置”或“设置已完成”标签，而显示独立的账号连接行：左侧为受控品牌图标、账号能力名称与简介，右侧“已连接”下拉提供“重新连接”和“断开连接”。该账号行不替代、联动或挤占顶部插件整体开关；关闭插件后仍保留“已连接”状态，只有账号行内的明确“断开连接”动作才能退出账号。安装成功后仍直接进入详情，不自动弹出 setup wizard，也不自动打开网页。只有用户点击“配置”“连接账号”“重新检测”“重新连接”“断开连接”等动作时才经 typed bridge 调用 Core。Desktop 不提供“检查更新”按钮：本地 ZIP 来源不包含可查询的上游版本协议，同名新 ZIP 继续通过安装入口执行安全替换。组件按 Skills、MCP Servers、Rules、Agents、Commands、Hooks、Variables、Apps 分组，标题只显示数量；行只显示类型图标、名称、Awaken 生成的简短用途摘要以及可用的组件开关，不直接投影可能夹带厂商品牌的包内长 description。非 switchable 组件用进入箭头打开详情，不在主页面铺开 mapping、configuration、authentication、runtime、integrity 或诊断状态。

Main 是浏览器与原生 device-code UI 的唯一 owner：它取得 Core 返回的一次性 authorization/verification URL 后再次校验 public HTTPS 或 loopback HTTP，再调用系统浏览器；Renderer 不取得 URL 以外的授权材料。只有 Device endpoint 没有 `verification_uri_complete` 时，Main 用原生消息框显示 user code，并向 Renderer 返回已脱敏的 session。Renderer 轮询只读取 `authorizing/verifying/pending_admin_approval/ready/expired/failed/cancelled`、安全错误和过期时间，完成后重新读取 setup、组件与 MCP runtime；若会话终态携带错误但同一次刷新已经证明对应 setup 为 `ready`，当前页面必须立即清除该过期错误，不能要求用户切页重新挂载。授权会话由 Core 持有，不与 Awaken 窗口焦点或 Plugin Console 组件生命周期绑定；切到系统浏览器、其他窗口或 Awaken 内其他页面时，Renderer 只停止当前页观察，不调用 cancel。返回同一插件时，Renderer 必须用 `pluginName + setupId + pluginDigest + requirementFingerprint` 从 Core 重新取回活动的 `authorizing/verifying` 会话并继续轮询；只有用户明确点击“取消”、超时或协议终态才能结束会话。授权活动期间另提供“页面要求管理员审批”，只调用 Core 的 session transition；进入审批等待态后显示“批准后重新连接”，不继续显示无限加载，也不假定远端已经批准。`host_connector` setup 复用相同交互，但账号状态、强制重新授权和断开连接由连接器域拥有；重新连接在新 token exchange 成功前保留当前可用凭据，用户关闭或取消网页不会先退出原账号；插件卸载不退出共享账号。其提供的宿主 MCP 必须继续出现在该插件的「MCP 服务」分组，并展示连接状态和工具；详情明确标记“由 Awaken 连接器管理”，不提供会影响共享 runtime 的组件开关、tool 开关或源文件编辑。若 Connector 声明 `catalogPlacement=plugin_only`，插件页同时是连接/审批/重连/退出登录的唯一 UI，顶层连接器目录不能重复展示；当前 Outlook 即使用此边界。App Connector 的 `unsupported` item 没有可点击的虚假连接动作。

点击任一组件统一打开居中的独立 `AwakenDialog`，不在页面右侧创建 Inspector，也不因宽屏改变为分栏。所有组件 Dialog 的标题行只显示类型图标和组件名称，不在名称下重复显示“技能 / MCP 服务 / 规则 / 命令”等类型标签；图标、名称和关闭按钮统一对齐。除 Skill 外，Dialog 按需加载 Details/Preview/Source/Diagnostics，并继续提供完整组件能力：

- Skill：打开后直接渲染 `SKILL.md` 的单一 Markdown 预览，不显示“详情 / 预览 / 源文件 / 诊断”页签或资源清单；“在对话中使用”固定在 Dialog 右下角 footer，不进入预览滚动区；不提供复制或安装为普通用户 Skill 的入口；
- MCP：local/remote/in-process、connection、error、tools/list，逐 tool switch，以及安装包源文件的原文查看与编辑；`host_connector` 引用的 in-process MCP 复用同一详情结构，但标明由 Awaken 连接器管理，并锁定会影响共享 runtime 的组件、tool 与 Source 编辑。普通插件 MCP 的“源文件”不把 `command`、`args`、`url`、`env` 或 `headers` 替换为占位符。查看与编辑复用同一个源码画布、排版与内部滚动容器，切换时仅改变是否可写，不重建内容并不产生文字位移；编辑按钮与保存/取消动作固定在 Dialog footer。源文件的格式错误、保存成功和内容未变化都作为紧凑文字显示在同一 footer 内的操作按钮旁，与按钮垂直居中，不占用弹窗顶部或正文滚动区。即使内容未变也允许保存并退出编辑，Core 将其作为不改变 digest 或运行时的 no-op；继续编辑、取消或关闭详情都会清除过期错误。有效修改的保存由 Core 在 staging 中完整校验并以当前 digest 做 CAS/原子替换，成功后自动刷新组件与运行态；Renderer 不解析或直接写插件文件，也不提供重复的手工 Reload；
- Rule：always/file_globs/manual/model_decides 和“加入下一次运行”；
- Command：argument hint、带引号参数输入和结构化 Composer token；
- Agent：Properties/Prompt/Source、插件明确声明的 max turns/timeout 和“作为子任务 Agent 使用”；未声明时不展示额外预算，运行仍服从普通 child 的统一边界；
- Hook：event/matcher/handler/scope/failure policy、handler 输入条件、普通事件 600 秒默认或厂商明确声明的单次 timeout、同步/异步执行状态、`SessionEnd` 退出预算、最近回执和失败项诊断性重试；
- Variable：schema、configured/masked、普通值编辑、Secret replacement/reset；变量表单只在相应组件 Dialog 内出现；
- App/unsupported/ignored/invalid：只展示事实和诊断，不提供虚假运行按钮。

组件级 Composer 动作只对父插件已启用、组件 desired 已启用、完整性有效、配置与 authentication 就绪且映射为 `native | adapted` 的可运行组件开放。`recognized_unsupported | ignored_by_dialect | invalid` 以及父插件关闭、组件关闭、完整性漂移、缺少配置或缺少账号的组件仍可打开详情、Source 和 Diagnostics，但不能生成 Skill/Rule/Command/Agent token；Renderer 在显示动作与执行动作两处都要 fail closed，Core 继续在 run start 做最终复验。

Hook 重试文案必须说明“不会重放原 run 上下文”；回执 retention 为 memory-only 时必须显示“当前 Core 进程内”。MCP Source 按文件原文展示，源文件本来存在的字面值不会脱敏；Secret Store 的运行时值不反向拼接到 Source，Variable 配置仍只显示 configured/masked。Hook Source 继续屏蔽 command/prompt/header 等可能执行或携带凭据的字段。来源方言、物理路径和 digest 仍保留在 Core DTO、完整性校验与诊断链路中，但不是 Console 的常驻展示字段。

Console 始终使用单列组件目录；标准桌面窗口下内容列约束在 780px，组件行使用紧凑的 28px 图标框和约 38px 行高，不把少量组件拉成横跨工作区的宽卡。Skill、MCP、Rule、Agent、Command、Hook、Variable 与其他组件统一使用 780×760 桌面基准尺寸的 Dialog，不随内容量收缩或扩大；视口不足时按窗口边距受限。Dialog 头部和可选 footer 固定，只有正文区域独立纵向滚动。标准 1440×903 窗口下，页面根、组件目录和 Dialog 都不得出现水平滚动；长 description/source 在各自容器内截断或换行。

HTTP/IPC collection 字段在空集合时必须返回 `[]`，不返回 `null`；Renderer 仍在 typed boundary 做空值归一化，避免旧插件或滚动升级期间的页面级崩溃。

### 1.4 Composer 与状态刷新

Plugin、Rule、Command、Agent action 都生成结构化 token；Skill 组件保留组件级“在对话中使用”入口并返回 Workbench，不因从 `/` 隐藏而删除。Skill 动作消费 Core 返回的精确 Catalog ID，生成 `type=skill`、`sourceOrigin=plugin` 的 token，不得降级为整个 Plugin token，也不得由 Renderer 从路径猜 ID。普通 Composer 用 `@ Plugin` 选择整个插件；输入 `@` 时直接从 App 已预取的内存 catalog 同步投影内置能力和插件，不清空现有 actions、不再次等待 Plugin list 请求，也不出现 loading 占位；catalog revision 只在后台重验后原位替换。内置插件启用后进入 `@` 的「内置」分组，尚缺账号或配置时可见但禁用，完成 setup 后原位可选择；普通插件进入「插件」分组。Outlook 按内置顺序首先出现，选择目录、当前 Composer 的结构化 token 以及已提交的用户消息都使用卡片相同的 Microsoft 官方 Outlook 彩色图标，不再退化为通用插件拼图图标。App 负责 caret 插入并返回 Workbench，Plugin Console 不直接改 Composer state。Core 在 run start 复验 pluginName/digest、Skill Catalog identity 与需要的 logicalId，Desktop 不提交可信 prompt/system instruction。`@ Plugin` 成功后由 Core 追加“优先使用该插件提供的 Skill 与 MCP 工具”的 host-owned 引导，只包含 Skill、没有 MCP 的有效插件也继续进入 `@` 目录。

Store mutation 通过 composer catalog revision 使打开的目录和插件页重拉。mutation 响应中的 revision 只用于失效，不作为 Renderer 自己推断的 runtime state。

插件整体开关是组件生命周期的父级门禁：用户点击后列表卡片与详情顶部立即乐观投影目标状态并锁定重复点击，Core mutation 失败时回滚并显示错误；不能在请求期间保留旧值而让开关看起来失效。列表开关成功后直接消费 mutation 返回的 Plugin DTO，不再为了一个插件的启停同步刷新全部 Connector、Skill、MCP 与 Plugin catalog。关闭插件后，所有 Skill、MCP、Rule、Agent、Command 与 Hook 行都显示为关闭且不能单独操作，MCP tool 开关也同步锁定；Core 不再向运行时导出这些组件。组件自身的启停偏好只在 Store 中保留，重新启用插件后按原偏好恢复。整体开关只等待当前 Store mutation 与必要的本插件 runtime 变化，不得同步重启或等待无关插件 MCP；没有自有 plugin-scope MCP 的内置 Outlook 启停不能被其他 MCP session 阻塞。打开组件 Dialog 后，该组件内的保存、切换、重试和配置反馈统一显示在固定 footer，有当前操作按钮时紧邻按钮并垂直居中，不再使用弹窗顶部大横幅或 Desktop 全局 toast。只有不属于已打开组件的页面级反馈才继续使用页面或 Desktop 全局提示。

### 1.5 失败与安全展示

- Store 缺失/损坏：插件页错误，Desktop 其他域继续；
- digest drift：详情显示诊断，所有 runnable component fail closed；
- active run lease：mutation 显示 `RUNTIME_GENERATION_IN_USE`，提示等待或取消 run 后重试；
- MCP needs-auth/failed/stopped：展示真实 state，不伪造 connected；
- App/recognized_unsupported：详情明确说明“仅识别、不会交给模型调用”，不出现使用或插入动作；
- Composer 组件或包在选择后失效：Main 只把 Core 稳定错误码映射为 Skill、Plugin、Plugin component、run conflict 等安全产品文案，不向 Renderer 透出路径、header 或凭据；
- Secret Store 值：永不回显；MCP 源文件原有字面文本按原文展示；
- uninstall：普通插件确认 package/data 进入 Trash，Trash 不可用则 fail closed；内置插件没有卸载入口，Core 也拒绝直接调用。

## 2. 当前不支持或已知缺口

- 不支持 project/managed scope 插件。
- 不提供 URL/Git 或本地目录的 Desktop 安装入口；本地目录只用于受控 Plugin Creator 候选流程。
- 不提供 Marketplace、插件目录聚合或候选索引。
- 不提供插件上游版本发现或“检查更新”；用户重新选择新 ZIP 时按同名替换安装。
- Apps 没有可运行 UI。
- Hook receipt 查询不跨 Core 重启。
- Plugin Agent model hint 不提供 Renderer endpoint/profile picker。
- Windows/Linux 的 ZIP picker、Trash、Hook/MCP 子进程和完整 Desktop 矩阵未验收。

## 4. 验收

首先验证目录首帧：Desktop ready 后输入 `@` 必须立即出现已有内置/插件项且无 loading 闪屏；从 Workbench 首次进入插件页必须立即显示内存快照，从卡片进入 Console 必须立即显示完整标题，后台刷新期间不得清空页面。

自动化通过后仍需在真实 Awaken Desktop 验证：插件页只保留本地 ZIP 安装入口；点击和拖放均会自动校验；错误态明确、有效态为浅绿色；同名自动替换；普通 Skill ZIP 自动切到 Skills 安装并只写所选 project/global 根，插件 ZIP 从 Skills 安装入口自动切回插件安装且不生成普通 Skill；并继续验证紧凑 Plugin Console 不显示厂商/路径/digest/状态矩阵，顶部没有“检查更新”且整体开关位于操作区最右；首次读取完成后返回插件列表并再次进入同一插件，组件和账号行同步出现、后台刷新且不再显示骨架；发起 Outlook 授权后切到系统浏览器、其他窗口与 Awaken 内其他页面，返回插件详情时仍显示同一授权等待态并继续轮询，不得自动取消或创建第二个会话，再用明确“取消”动作验证会话才终止；Outlook 已连接时显示带官方图标的独立账号行，“已连接”下拉含“重新连接/断开连接”，打开下拉不改变顶部整体开关。点击 Skill、MCP、Rule、Agent、Command、Hook、Variable、App 均打开相同固定尺寸的独立 Dialog，短内容不缩小、长内容不扩大且只滚动正文；所有组件 Dialog 的标题图标、名称和关闭按钮对齐且无第二行类型标签；Skill 正文只呈现 `SKILL.md` Markdown，右下角“在对话中使用”不随正文滚动，点击后返回 Workbench 并插入精确 Skill token 而不是整个 Plugin token；App/unsupported 只显示识别事实且无运行 action；Agent 详情只显示插件实际声明的限制，未声明时没有 8/32/5 分钟占位；Command 只有在 Core 明确声明确实接受参数时才显示输入框，输入可选参数后新 run 的展开正文必须实际包含它；Hook 详情显示普通 600 秒默认、厂商声明值或 `SessionEnd` 退出预算，声明 async 的真实长进程不得阻塞首个模型请求，完成后回执由 started 推进为 completed，异步反馈只进入同一会话下一次中文测试任务。MCP 详情没有重复的“重新加载”按钮，Source 原样显示包内文本，编辑/取消/保存位于固定 footer，保存有效修改后 digest、组件目录和 MCP 运行态自动刷新，无效 JSON、stale digest 与 active run 不改变原文件；格式错误、保存成功、内容未变化及其他已打开组件的操作反馈均位于 Dialog 固定 footer，与操作按钮相邻且垂直居中，弹窗顶部和正文区无大横幅提示；关闭父插件后全部组件与 MCP tool 开关显示关闭并锁定、运行时目录不含该插件，重新启用后恢复原组件偏好。其他组件的 state/config、MCP readiness/tool、Rule/Command/Agent token、Hook 回执/重试、active generation 冲突、重启恢复、同名替换和卸载仍有效。提交结构化 token 后须确认 Chromium console 没有 `Maximum update depth exceeded`；如发生新的 Renderer 渲染异常，界面显示可重新加载的恢复页而不是空白窗口。1440×903 窗口另须检查主页面和 Dialog 均无水平溢出。Gallery/mock 不能替代。
