# 回到最新输出按钮需求

## 1. 用户意图

用户主动向上滚动、点击旧 marker 或阅读历史时，Awaken 必须暂停 latest-output follow。若 latest run 仍在输出，系统需要提供一个明确但轻量的恢复入口，让用户可以回到最新输出并恢复 follow。

这个入口是“回到最新输出” affordance。它不是新的 composer 形态，不是 narrative item，也不是改变 scroll tail 的布局事实。

## 2. 视觉形态

- 形态为白色圆形按钮。
- 只显示黑色向下箭头图标。
- 不显示“回到最新输出”文字。
- 尺寸应比早期 34px 方案更克制，优先约 32px。
- 视觉上应轻量，不抢占 composer 主操作。

## 3. 位置要求

- 按钮位于 dock composer 输入框上方的中轴位置。
- 位置参考用户标注的输入框上沿上方位置。
- 不得放在输入框内部。
- 不得远离输入框形成新的独立浮层区。
- 输入框多行增高时，按钮必须随 composer 整体上移，始终保持在输入框上方。

## 4. 布局与滚动边界

- 按钮周围的浮层区域必须允许内容视觉穿过，不得作为新的布局占位推挤 ExecutionFeed。
- 只有圆形按钮本体可点击；按钮周围透明区域不得阻断中间区域内容和滚动。
- 按钮不得作为 `ComposerDock` 的普通直接子元素参与 flex 布局、子项宽度规则、composer 高度测量、`composerContentInset`、dock safe area 或 scroll tail 计算。
- 按钮不得捕获、转发或改写中间区域 wheel / scroll 事件。
- 中间区域滚动仍只由 `RunStage` 的滚动容器负责。
- 按钮实现必须保留本项目输出内容与输入框之间的既有间距。
- 不得为了放置按钮改变 output tail / composer inset 的同一布局事实。

## 5. 挂载层级

按钮必须属于 `RunStage overlay` 视觉层：

```text
RunStage
  -> ExecutionFeed
  -> ComposerDock
  -> overlay
     -> return-to-latest button
```

按钮不得属于：

- `ComposerDock` 内容层。
- `ExecutionFeed` narrative / turn 层。
- `RunStage` 外部 fixed / absolute 层。

## 6. 交互要求

- 仅在用户明确退出 latest follow 后显示。
- 用户点击后，视图回到 latest output tail，并恢复 follow。
- 用户向下滚回 final output bottom 后，也可恢复 follow。
- passive layout scroll、markdown 增高、ThoughtTrace 增高、composer 高度变化，不得自动触发恢复 follow。
- 若 latest run 已结束且用户已经处于 tail，按钮应消失。

## 7. 验收

| ID | 优先级 | 旅程 | 前置状态 | 操作步骤 | 预期行为 | 证据 |
|----|--------|------|----------|----------|----------|------|
| AC-008A | P0 | return affordance 视觉与滚动边界 | AC-007 后且 dock composer 可见 | 让“回到最新输出”出现；把 composer 输入内容改为多行但不发送；随后在中间内容区滚动 | 白色圆形下箭头位于输入框上方并随多行 composer 上移；按钮不进入输入框，不改变输出与输入框间距，不破坏中间区域滚动 | 保存到 `验收文件夹/` 的真实 Desktop 录屏或关键帧 |

专项验收还必须确认：

- 按钮出现时，中间区域仍可正常滚动。
- 按钮消失后，输出内容与输入框之间的原有间距不变。
- 多行输入框增高时，按钮位置跟随，而不是停在旧高度。
- 点击按钮恢复 follow 后，后续输出以助手最终输出内容底部为 tail。

## 8. 反模式

- **把按钮当作 `ComposerDock` 内容。** 会让按钮参与 composer 的布局、高度测量和 safe area 计算，容易破坏中间区域滚动。
- **用 wheel 转发修复遮挡。** 如果按钮或浮层挡住滚动，再通过转发 wheel 补救，说明挂载层级已经错了。
- **为了按钮改变 output tail / composer inset。** 按钮只是恢复入口，不应该创造新的布局事实。
- **把按钮视觉需求和 scroll controller 重构混在一刀里。** 按钮应单独实现、单独验收。

## 9. 已确认产品决策

1. return-to-latest affordance 的视觉形态为白色圆形、黑色向下箭头、无文字、约 32px。
2. 按钮位于 dock 输入框上方中轴，并随多行输入框上移。
3. 按钮不得作为 `ComposerDock` 普通内容。
4. 按钮不得参与 composer inset / safe area / scroll tail 计算。
5. 按钮不得拦截或转发中间区域滚动事件。
