# 本机依赖与文件生成 · 需求文档

文件生成使用当前用户、项目和技能已有的工具环境。缺少依赖时按真实错误处理，Desktop 启动不以 Office 生成依赖齐全为前提。

代码、接口和验证方法见[实现方案](实现方案.md)。

## 当前产品模型

Awaken 不下载、复制、版本化或打包 Python、Node、LibreOffice、Poppler、FFmpeg 等完整 Work runtime。Desktop/Core 先正常启动；Agent、`Bash` 与 Skill 复用当前登录用户已经拥有的项目、Skill、用户级和系统级环境。

依赖按实际安装语义自然复用：项目 `.venv`/`node_modules` 属于项目，Skill 依赖属于 Skill 包，pip/npm 用户依赖属于用户，Homebrew/winget/系统应用属于当前电脑。Awaken 不维护独立 Work runtime revision。

## 当前依赖发现

当前没有 `workspace_dependencies`、`runtime_preflight` 或 typed Work runtime 工具。run-start snapshot 只观察固定 PATH 中的通用 executable、Python/Node、包管理器和 workspace marker；`Read` 的 PDF fallback 另外从固定 snapshot 查找 `pdfinfo`、`pdftoppm`。bundled Word/Excel/PPT doctor 在 Agent 激活目标 Skill 后按 route 真实探测依赖，并返回当前解释器版本、最低 Python 3.9 合同、依赖根和可复用的绝对 executable plan；其他 Office/媒体依赖仍由 Skill 或 Bash 命令真实发现。

Agent 或用户安装依赖后，新的 run/显式环境 refresh 才能形成新 snapshot；当前 run 不热换已经固定的 executable identity。Skill doctor 的绝对执行计划从同一固定环境和明确 dependency root 中产生，后续 helper 必须复用它，不能因 `cd` 或重复裸命令重新选择解释器。用户明确指定另一个绝对 executable 时仍可直接使用，但这不改变 snapshot。

## 缺失与恢复

生成工具缺少依赖不是权限 gate。`Read` 缺 Poppler 返回 `needs_runtime`；Skill/Bash 返回真实 spawn/exit/stderr。Agent 可按 Skill 指令执行 `brew`、`winget`、`pip`、`uv`、`npm` 等正常安装命令，再在新 run/刷新后重试。

保留的 typed `dependency_install` 只负责 provider 明确声明的 workspace Python/Node plan，继续使用 pinned executable、full sandbox、private staging、post-probe 和 recoverable commit；它不是通用 Work 环境管理器。

## 平台边界

- macOS：当前支持 login PATH、Homebrew 与当前用户应用；必须用真实 Desktop 验证依赖复用和安装后重试。
- Windows：代码只把已验证的 Git Bash 作为 POSIX Shell，明确排除系统 WSL `bash.exe` 启动入口，再按 pwsh/powershell/cmd 做执行前健康回退；环境快照同时观察 `py`、`python3` 与 `python`，Office doctor 从实际可用启动器进入并返回后续固定使用的绝对解释器。cross-build 不代替实机。
- Linux：遵循 PATH 与用户环境，不能从 macOS 验收推导发布结论。

## 当前事实

Core 当前没有 Office 后台 worker，也不注册 typed Office/PDF 生成或渲染工具。Awaken 不复制、维护或托管 LibreOffice、Python、Poppler、FFmpeg 等完整 Work runtime。Agent Plan 的 `image_generate` / `video_generate` 是独立媒体 provider，不属于 Office/PDF Work runtime 或 `artifact_publish` 文档发布链。

Agent 可按 Skill 使用当前用户环境中的 Python/Node/LibreOffice/Pandoc 等工具，通过 `Bash` 或 `Write` 处理和生成 Office/PDF 文档。bundled Office helper 支持 Python 3.9 及以上，并由各格式 doctor 按 route 返回本轮应复用的 Python/Node/LibreOffice/Poppler 绝对执行计划；这只是 Skill 内的依赖探测，不是 Core typed preflight。当前 Word 阅读由纯 Python 标准库 `read_docx.py` 解析 DOCX/DOTX OOXML，并把未完整覆盖的视觉或复杂结构写入 warning；接受修订、Excel 重算和 Word/PPT 视觉 QA 脚本各自拥有独立 LibreOffice profile、超时和结果合同。这些能力只在 Agent 显式执行对应 Skill route 时成立，也不意味着 Desktop 启动时已经准备 Python、LibreOffice 或 Poppler。其他缺失依赖仍按目标 route 的真实 doctor/执行错误恢复；没有执行对应脚本和逐页检查时，不获得版式验证或视觉 QA 证明。

受支持文档生成完成后必须调用 `artifact_publish`，由 04 域验证普通文件、symlink、扩展名和基础签名，并生成 deliverable Artifact；文件目录不是发布边界。发布证明文件身份和交付状态，不证明 Office 视觉质量。图片/视频不走这条链：专用媒体工具成功时自行产生 ready 媒体 Artifact，Bash/Skill 单独生成的任意媒体文件当前没有通用手动发布入口。
