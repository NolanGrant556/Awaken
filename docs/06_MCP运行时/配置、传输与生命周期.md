# 配置、传输与生命周期

## 1. 配置 scope

| scope | 来源 | 合并优先级 | 持久性 |
| --- | --- | --- | --- |
| `plugin` | Agent Plugins `mcp.json` 或 Codex/Claude/Cursor native MCP 经 `PluginStore.PluginMCPServers()` 翻译 | 最低 | 持久（包 + `plugins.json` server/component/tool override） |
| `user` | `~/.awaken/config/mcp-servers.json` | 覆盖同名 plugin | 持久 |
| `project` | `<workspace>/awaken.mcp.json` | 覆盖同名 user | 持久 |
| `dynamic` | Connector `InjectDynamic` | 最后覆盖 | 仅当前进程 |

`MergeScoped(plugin, user, project, dynamic, logger)` 丢弃无效条目并记录 warning；`enabled:false` 条目必须保留在合并结果中，由 Manager 重建为 `disabled` 且不建立 transport，保证管理面可见并在重启后保持停用。Plugin `DisabledTools` 不从 server tools/list inspection 消失，但不得注册进中央 Tool Catalog。输出顺序确定；启动时按合并结果创建 Manager server。

插件 MCP 的 raw server identity 固定为 `plugin__<plugin-name>__<server>`；manager state、annotations、目录分组与路由解析保留这份原始身份。`src/mcpclient` 另生成只用于中央 Registry 和模型 API 的 canonical 调用名：合法 plugin name 中的 `.` 等长映射为 `_`；不安全或 `x0_` 开头的 component 使用可逆 Base32。这一投影不改写 source manifest、MCP wire tool name 或 UI identity。transport 配置来自已归一化 MCP component；`plugins.json` 只保存 server/component/tool override 和变量引用，不保存 secret 值。Plugin Store mutation 的 live projection 必须先比较当前 Manager entry 的 identity、scope 与完整配置；完全相同的 entry 是 no-op，不关闭 session、不注销工具、不发 disconnected 事件，只有新增、移除或真实配置变化才重建对应 plugin server。tool override 必须独立于 server/component desired override 应用，工具单独停用后重载 Store 仍保留在 inspection 中，但不会进入下一份中央 Registry snapshot。连接器「用户安装」排除 `plugin__`。

正式 Desktop/Core 只从 `AWAKEN_HOME` 下的 `config/mcp-servers.json` 读取和保存 user scope。Electron `userData`、旧配置目录及其他历史位置不参与读取、写入、导入、迁移或 fallback；旧文件即使仍留在磁盘也没有配置 authority。测试必须注入隔离的 `AWAKEN_HOME`，不能依赖真实用户目录。

user config 的管理写入使用同目录跨进程锁、`0600` 临时文件、文件 `fsync`、原子 rename 与父目录 `fsync`；authority 目录收紧为 `0700`。HTTP 管理面与 builtin Connector 的增删改都必须通过同一 locked read-modify-write owner，不能各自执行无锁的 load/save。

`project` scope 只在 core 拥有有效 default workspace 时参与初始加载和 scope 合并。`AWAKEN_DEFAULT_WORKSPACE` 为空表示本次进程没有 project scope：不得回退 cwd、用户主目录或最近项目，也不得因为 project scope 缺席而阻止 user scope 的读取、保存、更新、启停或删除。用户后续选中的 run workspace 仍按 run 合同传入，不会反向把该目录提升成本次 core 的隐式 default workspace。

当前 live-update 仍不是全量 scope generation 重算：user/builtin 的增删、project 初始配置和 dynamic owner 可能在运行期发生同名替换；旧 session 清理虽按 connector owner 防止部分误删，但尚无统一 generation/原子 replace 证明。因此“project 永远覆盖 user、dynamic 永远最后”只对一次 `MergeScoped` 成立，不是所有时刻的运行时不变量。

## 2. Transport

当前生产支持：

- stdio；
- HTTP/Streamable HTTP；
- SSE。

管理 API 的 `mcpServers.*` URL 简写同时接受 `type: "http"`、`type: "streamable-http"` 或省略 type；也接受以 `http://` 或 `https://` 开头的单个完整 Streamable HTTP URL。四种输入都必须规范化为内部 `http` transport，并由同一个 Streamable HTTP client 执行。裸 URL 以去掉 query/fragment 的 endpoint 生成稳定 `remote_<hash>` 内部 identity，query 中的 key/token 轮换不会改变该 identity；显示名默认取 host。外部 JSON server 名可包含中文等非 ASCII 字符：原名进入 `displayName`，内部 identity 仍保持工具名安全；当名称完全无法产生 ASCII identity 时生成稳定 `server_<hash>`。磁盘 canonical shape 始终使用 `servers.*.http`，不得把外部客户端的 transport 别名或裸 URL 保存成第二套持久格式。Desktop 配置入口以「本地进程（stdio）」和「Streamable HTTP」两个模式帮助用户选择正确示例；粘贴可判定的 JSON/URL 时可以同步提示模式，但模式不取得 schema ownership，最终校验、identity 生成与规范化仍由 Core 拥有。

WebSocket 不支持；in-process transport 只用于测试，除非生产显式注入。Manager 负责 initialize、capability snapshot、tools/prompts/resources list_changed、重连/停用和局部失败。单个 server 失败不能阻止 `awaken-core` 启动。

HTTP/Streamable HTTP/SSE 的新连接和 stdio child 使用 03 域的[跨平台网络代理与恢复](../03_运行时与本地服务/跨平台网络代理与恢复.md)。Desktop 在 MCP 配置、更新、启用或 connector connect 之前先校准 route；pending server 每次尝试都会重新构造 transport；Desktop route generation 改变时，Manager 自动重新启用 failed 的 stdio/HTTP/SSE server，不改变 disabled、needs-auth 或 in-process server。MCP config 的显式 stdio env 最后覆盖宿主派生环境。插件 stdio 在该步骤之后由宿主写入 filesystem-resolved `PLUGIN_ROOT` / `PLUGIN_DATA`，覆盖配置里的同名项；配置 `env` 出现按当前平台环境变量名语义等价的保留名会使该 server 条目 invalid。占位符 `${PLUGIN_ROOT}` / `${PLUGIN_DATA}` 只在插件 `mcp.json` 的 `args`、`env` 值与 `cwd` 中单遍展开，由 `src/plugins` 在翻译时完成；`MergeScoped` 对 plugin scope 保持翻译结果原样，不再执行 user/project 的通用环境变量展开。

Agent Plugin 声明的 HTTP/SSE fixed headers 由 transport 只附加到配置 URL 的同 origin 请求；同 origin redirect 继续携带，不同 scheme/host/effective-port 的 redirect 或 legacy SSE endpoint event 不携带。请求已有的 MCP、OAuth 或宿主同名 header 优先，插件值不能覆盖。user/project 原生 MCP 配置仍沿用其既有 `${VAR}` 展开合同，两者不能混用。

### 2.1 Elicitation

MCP transport 声明 form 与 URL elicitation capability。server 在一次 tool call 内发起 `elicitation/create` 时，Manager 将请求绑定到该 server 当前的 active call context；同一 server 的 tool call 为此串行执行，避免无 parent call ID 的协议请求串到另一调用。请求经 ToolRuntime 的 run-scoped event sink 投影为 `external_interaction_requested`，Desktop 在当前运行中展示确认卡；没有 active call、没有交互 run 或 run 已终态时一律安全返回 `cancel`，不得在后台隐式接受。

form 当前展示顶层 `properties` 中的 string、number、integer、boolean 和 enum 字段，支持 title、description、required 与 default；确认时只把用户填写的 `content` 返回给正在等待的 MCP session，取消返回 `cancel`。URL 模式沿用外部交互链接、完成确认与取消动作。表单答案只保存在 pending interaction 内存中，不写入 AG-UI 事件、Journal、模型上下文或日志；请求 schema 可以进入 AG-UI 供 Renderer 构造表单，但不得包含 credential value。嵌套 object/array、自定义 widget 与跨字段校验当前不属于 Desktop form renderer 的支持范围。

## 3. Server 状态与 provider readiness

Manager snapshot 记录 pending、connected、needs-auth、failed、disabled 等 server 事实。`McpToolAdapter` 把当前 server 状态投影为 provider readiness：ready、needs_auth 或 unavailable，并附带 `mcp_connector` dependency observation。

Connector 写入 server-level `ServerProviderManifest`，提供稳定 provider identity/source/dependencies；它不授予 per-tool 消息或删除能力。每个 tool 的 capabilities、安全映射和 side effects 只来自 tool 自己的标准 annotations、保守推断和版本化 `_meta`。

## 4. 动态工具注册

连接成功后，Manager 将每个 MCP tool 注册为 canonical `mcp__<model-safe-server>__<model-safe-tool>`；原始 server/tool 身份保留在 annotations 与 adapter 内。list_changed、断开与移除都按 definition 中的 raw `ServerName` 精确注销，不得只对 canonical 字符串做 `startsWith`；合法 server `...__local` 与 `...__local__nested` 可同时存在，刷新前者不能误删后者。调用路由不能假设 server name 不含 `__`：Manager 以当前 registry 中最长匹配的 canonical server 前缀解析 owner、反解 tool component，adapter 则直接携带独立 raw `serverName + toolName` 调用，保证 `plugin__<plugin>__<server>` 不被误拆；Manager 还兼容本机旧路径构造的 raw-qualified 名称。server wildcard permission override 以 canonical 拼写为当前入口，并保留 raw 拼写兼容。adapter 进入中央 registry，run 开始时被固定进 `RunToolAvailabilitySnapshot`。运行中 list_changed 或断开不改变已开始 run 的 provider identity/runtime pointer，但 adapter 的 `CheckPermission`/Manager call 仍读取 live server state：needs-auth 返回 auth Outcome，非 connected/已移除返回 needs-runtime/unsupported 或 transport failure，且不调用旧 session。下一 run 才取得新的 catalog/readiness snapshot。

## 5. 管理面

HTTP 管理面可读取 snapshot、增删改 effective config、启停 server、发起认证，以及读取 builtin/MCP tool 摘要。有有效 default workspace 时，同名 project 配置是读取、修改、启停和删除的 effective owner；删除 project override 后必须恢复同名 user fallback。没有 project override 时操作 user config；即使没有 default workspace，user scope 仍必须完整可用。enable/disable 写回 effective owner 的 `enabled` 并用同一配置重建 Manager entry；POST/PATCH 收到 `enabled:false` 时只建立 disabled entry，不连接 transport。route/method 的唯一清单在 09 域。Desktop 不得直接持有 MCP session 或绕过 ToolRuntime 调用。

OAuth authorization code session 由 Manager/Core 监听随机 loopback callback、校验 state、完成 PKCE、CIMD/DCR、token exchange 和持久化，不再依赖 Electron 跨进程安装 `AuthorizationCodeFetcher`。管理面 start 返回一次性 authorization URL 与 session ID；Main 打开网页，Renderer 只轮询脱敏状态并可取消。插件 MCP 原声明可用 `oauth_resource`、公开的 `oauth_client_id`、非根路径 public HTTPS `oauth_client_metadata_url` 与 `oauth_scopes` 补充 discovery；没有预注册 client/CIMD 时，DCR 按 public native client 请求 `token_endpoint_auth_method=none`。credential identity 按 scope、server、endpoint、client、resource 与 scopes 指纹隔离；插件声明的通用 OAuth binding 则由 Plugin Auth Broker 以 plugin/setup/fingerprint identity 提供 host-owned OAuthHandler，token 不写入 MCP config。OAuth HTTP client 对初始 discovery/registration/token 请求和 redirect 执行 public HTTPS/loopback、DNS 与私网检查。

SDK transport 收到明确 401/403 时只在 OAuthHandler 成功后自动重试原 HTTP 请求一次；Handler 再次失败由 Manager 投影 needs-auth，不循环重放。Plugin MCP tool 的 live needs-auth 进一步进入 ToolRuntime ExternalActionGate，用户完成插件 setup 后原 tool call 只重放一次；timeout、断线与不确定结果不会走该路径。

## 6. 当前缺口

- live scope replacement 尚无统一 generation owner；
- stdio server child 当前仍由 MCP transport 直接 `exec.Command` 启动，尚未接入 WorkspaceExecutionBroker/Seatbelt。connected/auth-ready 的 MCP tool 默认可自由调用，adapter 不对 message/delete/mutation 建立额外宿主 gate；该子进程也可在启动代码、后台任务或实现内部自行读取/写入宿主文件或联网。MCP 路径不具备 typed provider 的 TaskScope、Trash 或完整副作用观测保证；消息发送则在所有 provider 路径上都没有 Awaken 人工审核门；
- WebSocket 不支持；
- production in-process 注入不属于当前能力；
- route generation 变化可重新启用 failed server，但已 connected 长连接不会仅因系统 route 变化被强杀；任意中途断网的透明续流和多实例 OAuth session owner 仍未提供；
- Windows/Linux 真实 MCP CLI、PATH 和 Desktop 生命周期未在本轮实机验收。

## 7. 代码 owner

- `src/mcpclient/config.go`：user config 路径、scope 解析/合并（含最低优先级 `plugin`）。
- `src/server/handlers_mcp.go`：管理 API 输入解析、外部 server 名规范化、裸 Streamable HTTP URL 适配与 canonical 写入。
- `src/mcpclient/manager.go`、`transport.go`：server 与动态工具生命周期；stdio 最后注入 `PLUGIN_ROOT` / `PLUGIN_DATA`。
- `src/tool/elicitation.go`、`src/agentcore`、`src/runtime/session.go`：MCP elicitation 的 call-context 路由、run-scoped 等待与内存答案。
- `src/mcpclient/provider_manifest.go`、`tool_adapter.go`：provider/readiness 接入。
- `src/plugins`：`mcp.json` 合规解析与 canonical 配置翻译，不拥有 transport。
- `src/hookruntime` 的 Plugin `mcp_tool` handler 通过 Host 注入的 Manager executor 调用准确 plugin server/tool；必须先经 Store digest、component state、tool override 和 Manager readiness 复核。
