# MCP 配置、传输与生命周期

## 1. 权威范围

本文档是 MCP server 配置来源、transport 支持、Manager 状态机、工具注册时机和管理动作业务语义的唯一权威。当前 HTTP route 注册清单及条件由 [09 协议域](../09_AGUI与A2UI协议/HTTP与SSE接口契约.md) 唯一拥有。

本文档不定义 connector 的产品分类，不定义 Skill 执行语义，也不把配置 schema 已接受的字段等同于生产运行时已支持。

## 2. 用户入口与配置来源

Desktop 的当前入口是“连接器 > MCP”，其中可查看 server 状态、打开设置、启用/停用、编辑或删除配置，也可通过“配置 MCP”粘贴 JSON。这些都是会修改本地数据的操作。

启动装配通过 `MergeScoped` 合并三类来源：

| 来源 | 路径/创建方 | 优先级 | 持久性 |
| --- | --- | --- | --- |
| `user` | `desktopdata.Detect().MCPConfigPath()`；Desktop 当前“配置 MCP”和内建 connector 都写此处 | 低于 project | 持久 |
| `project` | `<workspace>/awaken.mcp.json` | 同名时覆盖 user | 持久 |
| `dynamic` | connector 调用 `Manager.InjectDynamic` | 合并时最后应用 | 仅当前进程 |

旧用户路径 `~/.awaken/mcp.json` 只是一次性迁移来源；目标用户配置路径由 `src/desktopdata` 决定。当目标已存在时不再从旧路径覆盖。

上表优先级**只对启动时的 `MergeScoped` 结果成立**。live管理当前没有统一scope resolver：

- live 新增/修改 MCP 配置动作和 builtin connector 会直接调用 `Manager.Start`；对应 method/path 只查 09 route 清单；
- `startOne` 对同名条目无条件覆盖 `m.servers[name]`，不会先取消旧session；
- 运行中的user/builtin因此可能覆盖project或dynamic owner；
- 旧连接goroutine稍后退出时还可能按同名前缀反注册新连接的工具；
- 重启后又会按 `MergeScoped` 恢复另一owner。

这是当前高风险owner/双连接竞态，不能把“project覆盖user、dynamic最后”写成所有时刻都满足的运行时不变量。修复需要为live update统一重算scope、原子替换并按generation隔离旧session清理。

`MergeScoped` 对无效条目记录 warning 并丢弃，其他条目继续加载。`enabled: false` 也会在合并时被过滤；它不会作为 `disabled` snapshot 出现。

Desktop 配置 API 接受两种 JSON 外形：

- Awaken native：顶层 `servers`，每项使用 `stdio` / `http` / `sse` / `ws` / `inProcess` 之一。
- 常见简写：顶层 `mcpServers`，每项使用 `command`/`args` 或 `url`/`transport`。

server 名会归一化为小写字母、数字和下划线。归一化后冲突会拒绝整次请求。

## 3. 当前 transport 支持矩阵

| transport | 配置可解析 | 生产 `awaken-core` | 说明 |
| --- | --- | --- | --- |
| `stdio` | 是 | 支持 | 启动本地子进程，通过 stdin/stdout 运行 MCP |
| `http` | 是 | 支持 | 官方 Go SDK `StreamableClientTransport`，HTTP client 超时 60 秒 |
| `sse` | 是 | 支持 | 官方 Go SDK legacy SSE client |
| `ws` | 是 | **不支持** | Manager 直接进入 `failed`，原因为 `ws transport not supported in v1` |
| `in-process` | 是 | **未接线** | SDK/in-memory transport 和测试 registry 存在；生产 `buildMCPManager` 没有注入 `WithInProcRegistry`，因此会失败 |

不可将 `TransportKind` 枚举中存在 `ws` 或 `in-process` 解释为生产能力。

### 3.1 transport 字段的实际边界

- `${ENV_VAR}` 会展开到 stdio command/cwd/args/env、HTTP/SSE/WS URL/header 值和 in-process server name；缺失环境变量被展开为空串。
- `insecureSkipVerify` 对 HTTP/SSE 的 TLS client 生效，并记录 warning。
- `headers` 虽然可解析和展开，当前 `buildTransport` 没有把它们装入 HTTP request；不能依赖。
- `headersHelper` 当前只被解析/展开，没有执行链；不能依赖。
- stdio 只在配置显式给出 `env` 时基于当前进程环境追加这些变量。

## 4. 连接状态机

Manager snapshot 的状态枚举是：

```text
pending | connected | failed | needs-auth | disabled
```

当前转移：

```text
有效配置 -> pending
pending --initialize 成功--> connected
pending --握手认证错误--> needs-auth
pending --5 次重试耗尽/不可恢复错误--> failed
connected --session 结束--> failed
pending/connected/failed/needs-auth --Disable--> disabled
disabled/failed --Enable--> pending
failed/disabled --Reconnect--> pending
```

连接重试最多 5 次，间隔依次为 1、2、4、8、16 秒。进入 `connected` 后 Manager 保存 initialize capability，调用 `tools/list` 并注册工具；离开 connected 时按 server 前缀反注册。

`notifications/tools/list_changed` 只刷新该 server 的工具；`prompts/list_changed` 和 `resources/list_changed` 转给 Skill bridge。Manager 订阅通道是 64 项非阻塞 buffer；慢订阅者可能丢事件，不得把它当耐久队列。

## 5. 当前管理动作语义

具体 method、path 与注册条件只查 09 域 route 清单。MCP 管理面当前提供：读取 snapshot；新增、读取、修改和删除配置；启用、停用与认证引导；以及读取 builtin/MCP 工具摘要。新增或修改会写 user config 并启动或重启 server；读取单项配置按 user、project 顺序查找；删除会移除配置与 Manager 条目；停用只改变当前 Manager 状态；认证限制见 [认证、持久化与恢复边界](认证、持久化与恢复边界.md)。

新增或修改动作当前会触发上述 live 同名覆盖竞态；API 成功不证明最终 owner 符合启动优先级。请求/响应实现在 `src/server/handlers_mcp.go`。

## 6. 不可绕过的边界

- MCP server 失败不能使 `awaken-core` 启动失败；局部失败必须留在 server snapshot。
- MCP 工具只能通过中央 tool registry 与 ToolRuntime 暴露，不得从 Desktop 直接调用 MCP session。
- `InjectDynamic/RemoveDynamic` 自身要求owner connector ID，但其他live `Manager.Start` 路径仍可覆盖同名entry；完整owner隔离尚未实现。
- 不得把已解析但未接线的 transport/header/auth 能力写为可用事实。
