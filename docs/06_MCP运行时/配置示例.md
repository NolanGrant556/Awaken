# 配置示例

## 1. User stdio

`~/.awaken/config/mcp-servers.json`：

```json
{
  "servers": {
    "playwright": {
      "stdio": {
        "command": "npx",
        "args": ["-y", "@playwright/mcp@latest"]
      },
      "enabled": true
    }
  }
}
```

这是 user scope 的唯一配置文件，也是磁盘 canonical shape。管理 API 可接收 `mcpServers` 的 `command`/`url` shorthand，但保存前会规范化为上述 `servers` + transport block；磁盘 loader 不把 API shorthand 当成第二种持久格式。Awaken 设置页对 user MCP 的读取、保存、修改和删除都操作这一路径，不使用 Electron `userData` 或其他旧路径。

## 2. Project stdio

`<workspace>/awaken.mcp.json`：

```json
{
  "servers": {
    "context7": {
      "stdio": {
        "command": "npx",
        "args": ["-y", "@upstash/context7-mcp"]
      },
      "enabled": true
    }
  }
}
```

secret 不得写入示例或仓库；需要 env 时只引用运行环境中已存在的变量名。

该文件只在 core 配有有效 default workspace 时作为 project scope 参与加载；没有 default workspace 时不读取任何 project MCP 文件，user scope 仍独立可管理。

## 3. HTTP/SSE

```json
{
  "servers": {
    "example": {
      "http": {
        "url": "https://mcp.example.test/mcp"
      },
      "enabled": true
    }
  }
}
```

OAuth/token 由 credential store 管理，不写入 config。

## 4. Connector provider identity

Connector factory 可在生成的 server config 中附加 server-level `provider`：

```json
{
  "providerId": "connector:example",
  "displayName": "Example",
  "source": "connector",
  "dependencies": [
    {"kind": "mcp_connector", "name": "example"}
  ]
}
```

这只提供稳定 identity/dependency。消息 recipient mapping 和 recoverable delete 必须由 MCP server 在每个 `tools/list` item 的 `_meta["io.awaken.tool/provider/v1"]` 中声明，不能放在 Awaken config 里替工具伪造。

## 5. 禁止项

- 不提交 token、cookie、Authorization header 或 client secret；
- 不把 Electron `userData`、旧配置目录或任意自动发现路径写成 user MCP 配置来源，也不设计迁移或 fallback；
- 不用 `insecureSkipVerify` 作为常规配置；
- 不把 in-process 或 WebSocket 写成生产 transport；
- 不因 connector aggregate capability 自动给任意 MCP tool 发送/删除权限。
