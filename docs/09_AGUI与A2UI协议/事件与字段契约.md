# AG-UI 事件与字段契约

## 1. 权威范围和 authority

本文唯一拥有当前 wire event family、JSON 字段、内部/耐久语义记录到 wire 的映射和已知 consumer 漂移。Go `src/protocol/agui/events.go` 的 `Event` 结构与 JSON tags 是 wire authority；journal 的记录种类、写入和耐久顺序仍由 03 域拥有，Desktop narrative 由 01 域拥有。

## 2. 公共帧字段

所有字段均为 JSON camelCase，`omitempty` 字段只有适用且非零时出现。公共字段分组如下：

| 维度 | 字段 |
| --- | --- |
| 类型与身份 | `type`、`seq`、`streamCursor`、`semanticSeq`、`recordId`、`timestamp` |
| run/turn | `threadId`、`runId`、`turnId`、`queryChainId`、`depth`、`turnCount`、`status`、`terminalReason`、`transitionReason` |
| message | `messageId`、`parentMessageId`、`parentRunId`、`role`、`name`、`delta`、`content`、`result`、`message`、`code` |
| tool correlation | `toolCallId`、`toolCallName` |
| unknown fallback | `rawType`、`rawEvent` |

`timestamp` 是 Unix milliseconds。`seq` 在 active/live frame 上为传输兼容 cursor；`semanticSeq` 是 journal 记录展开后的稳定帧身份。两者不能互换作数据主键。

### 3.1 Run 与 turn

| Wire event | 来源/语义 | 专用字段 |
| --- | --- | --- |
| `RUN_STARTED` | run 开始 | 公共身份 |
| `RUN_FINISHED` | 成功终态 | `result`、`outcome.type=success` |
| `RUN_ERROR` | 失败、取消或重启中断 | `message`、`code`、`terminalReason` |
| `RUN_STATUS_CHANGED` | runtime 状态事件直接投影 | `status`、`message`、`content`、`code` |
| `AWAKEN_TURN_STARTED` | turn 开始 | turn 公共字段 |
| `AWAKEN_TURN_FINISHED` | turn 结束/耐久 boundary | `terminalReason`、`transitionReason` |

### 3.2 Text 与 reasoning

| 内部事件 | Wire frames |
| --- | --- |
| `TextMessageStarted` | `TEXT_MESSAGE_START`，缺 role 时默认 assistant |
| `TextDelta` | `TEXT_MESSAGE_CONTENT` + `delta` |
| `TextMessageFinished` | `TEXT_MESSAGE_END` |
| `ReasoningStarted` | `REASONING_START` + `REASONING_MESSAGE_START(role=reasoning)` |
| `ReasoningDelta` | `REASONING_MESSAGE_CONTENT` + `delta` |
| `ReasoningFinished` | `REASONING_MESSAGE_END` + `REASONING_END` |

一条内部/语义记录可以展开成多帧；这正是 frame sub-index 和 16 步长存在的原因。

### 3.3 Tool 生命周期、决策和结果

| Wire event | 专用字段 |
| --- | --- |
| `TOOL_CALL_START` | `toolCallId`、`toolCallName`、`parentMessageId` |
| `TOOL_CALL_ARGS_DELTA` | correlation + `delta` |
| `TOOL_CALL_ARGS` | correlation + 完整 arguments 放在 `delta` |
| `TOOL_CALL_END` | correlation |
| `TOOL_PROGRESS` | `progress`、`toolProgressStage`、`toolProgressMessage`、`toolProgressPercentage` 及 Outcome 字段 |
| `AWAKEN_TOOL_PERMISSION_DECIDED` | static behavior/reason、decision action/source/reason、profile、transform、affected paths、patch summary、guardian violation |
| `TOOL_CALL_RESULT` | `content`、`role=tool`、`trashedPaths` 及 Outcome 字段 |
| `AWAKEN_COMMAND_OUTPUT` | `commandStream`、`delta`、`truncated` |
| `AWAKEN_PATCH_UPDATED` | `patch`、`patchSummary`、`affectedPaths`、`truncated` |
| `AWAKEN_TURN_DIFF` | `diff`、`truncated` |

Tool Outcome 字段固定为：`toolStatus`、`transportStatus`、`semanticStatus`、`processStatus`、`processExitCode`、`processTimedOut`、`errorCode`、`errorCategory`、`retryable`、`recoveryOptions`、`durationMs`、`diagnostic`。`trashedPaths` 是执行成功后从 tool result 得到的事实，不应预先从 permission 事件推断。

### 3.4 Context 与 compact

事件为 `AWAKEN_CONTEXT_ESTIMATED/WARNING/BLOCKED` 和 `AWAKEN_COMPACT_STARTED/FINISHED/FAILED`。

字段组：

- context 窗口：`contextModelWindow`、`contextOutputReserve`、`contextEffectiveWindow`、`contextEstimatedTokens`、`contextActualTokens`、`contextWarningThreshold`、`contextAutoCompactThreshold`、`contextCompactTarget`、`contextEstimatedDeltaTokens`；
- boundary：`contextCompactMode`、`contextCompactBoundaryId`、`contextCompactPreEstimateTokens`、`contextCompactPostEstimateTokens`，以及兼容的 `compactMode`、`compactBoundaryId`、`compactPreEstimate`、`compactPostEstimate`；
- compact 结果：`compactSummaryModel`、fallback/pruned 布尔与计数、summary token/retry/raw chars/section quality、latest-user pin、fallback marker、failure reason。

### 3.5 Pairing、认证、运行时和恢复

| 事件族 | Wire events | 字段 |
| --- | --- | --- |
| tool 配对修复 | `AWAKEN_TOOL_PAIRING_REPAIRED` | `message` |
| 认证 | `AWAKEN_AUTH_REQUIRED` | correlation、`authProvider`、`authUrl`、`message` |
| runtime 准备 | `AWAKEN_RUNTIME_PREPARE/PREPARE_PROGRESS/READY/REPAIR_FAILED/MISSING` | correlation、`runtimeName`、`runtimeVersion`、`message`、适用时 `progress` |
| 失败监督 | `AWAKEN_TOOL_RECOVERY_REQUIRED`、`AWAKEN_TOOL_RETRY_BLOCKED` | correlation、`code` 和 Tool Outcome/恢复字段 |

### 3.6 专用 gate

群发事件：

- `AWAKEN_MASS_MESSAGE_REVIEW_REQUESTED`：`reviewId`、channel、recipient scope/count、body preview、`massMessageTemplatePreview`、`massMessageAttachments`、`massMessageSendingAccount`、source tool；
- `AWAKEN_MASS_MESSAGE_REVIEW_RESOLVED`：`reviewId`、`reviewDecision`。

主动提问事件：

- `AWAKEN_USER_QUESTION_REQUESTED`：`questionId`、`content` 和 tool correlation；
- `AWAKEN_USER_QUESTION_RESOLVED`：`questionId`、`questionAnswer` 和 correlation。

它们是专用 gate，不是旧通用 approval 的字段别名。

### 3.7 Artifact

`AWAKEN_ARTIFACT_CREATED/UPDATED` 携带：`artifactContractVersion`、`artifactRole`、`artifactProducer`、`artifactId`、title/description/kind/path/content/status 和 tool correlation。mapper 会为 legacy contract/role 走保守归类，但 wire consumer 不能据 `artifactPath` 直接执行 OS 打开。

### 3.8 Unknown

未映射 `AwakenEvent` 变成 `AWAKEN_UNKNOWN_EVENT`，并携带 `rawType`、`message` 和可序列化 `rawEvent`。未知 SemanticKind 通常只保留 `rawType`；这是兼容和诊断机制，不是新事件已获支持的证明。

## 4. Durable semantic projection

`src/protocol/agui/semantic_projector.go` 是 live/replay 共用转换器。当前投影：

- run started/terminal、assistant message、tool call/result、artifact、turn diff/boundary、permission decision、runtime notice 和 recovery decision；
- user message 从 run metadata 恢复，不产生 AG-UI frame；
- thread、file change、`skill_activated` 和 `resource_receipt` 当前不产生 AG-UI frame；
- persistence warning 投影为 unknown 诊断事件。

因此 SemanticJournal 中存在 Skill 记录，不等于 Desktop wire 已支持对应 Skill event。

## 5. 当前 Go/TypeScript 漂移

以下是已确认缺口，修复前以 Go producer 为真实 wire：

| 领域 | Go 当前发送 | TypeScript 当前期待/缺失 | 影响 |
| --- | --- | --- | --- |
| 认证 | `authUrl` | `authLink`、`authScope` | Desktop 可能无法显示链接/范围 |
| runtime | `runtimeName`、`runtimeVersion` | 主要读 `runtimeComponent`、required/detected version、prepareStatus、missingReason，且没有 `runtimeVersion` | runtime narrative 字段可能丢失 |
| 群发 | template preview、attachments、sending account | templateId、attachmentNames、account | review 卡字段不完全对齐 |
| 通用审批 | Go 新 wire 无旧 approval 字段 | TS 仍保留若干 legacy approval 可选字段 | consumer 声明过宽，不能当产品能力 |
| Skill | durable kind 存在但 projector 抑制 | TS event union 无 Skill activation/resource receipt | 当前无 Desktop Skill event |

新增或修复字段时应先改 Go contract 与 mapper/projector 测试，再同步 TypeScript、reducer 和投影测试；不得只在 renderer 增加别名。
