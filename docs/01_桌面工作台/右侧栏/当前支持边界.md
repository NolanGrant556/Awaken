# 右侧栏当前支持边界

## 1. 权威范围

本文唯一拥有 Awaken Desktop右侧 Inspector的当前产品状态、已有数据和未接线边界。文件预览的技术组合、`awaken-preview` 协议与资源上限见 [文件预览架构契约](文件预览架构契约.md)。中间叙事的数据投影见 [叙事投影与重放](../中间交互区域/叙事投影与重放.md)。

## 2. 当前用户行为

主 Workbench 保留右侧 rail、折叠按钮、拖拽/键盘 resize 和响应式自动折叠。普通展开态始终按固定顺序提供“文件”和“浏览器”；当前 thread 存在原生 Subagent 记录时，同时出现带任务数 badge 的“子任务”入口；用户从媒体卡更多菜单明确选择“在右侧栏查看”后，临时增加“媒体”入口并直接显示该媒体：

```text
文件
浏览器
子任务 3
媒体
```

“浏览器”只承载从项目文件树选中的本地 HTML，不是通用互联网浏览器或 browser automation surface。“媒体”只承载用户主动固定的一张 ready 图片或视频，不是通用 Artifact 列表，也不替代中间 `RunStage.overlay` 的默认预览。当前没有审阅、终端、侧边任务等其他入口。点击“文件”或“浏览器”后进入同一项目文件工作区：

- 顶栏左侧在未选文件时显示“打开文件”或“浏览器”占位标签；文件标签使用紧凑尺寸，并与顶栏上、下、左边缘保留间距；每次打开新文件会新增对应文件标签，重复打开同一项目、文件夹组中的同一文件只激活已有标签，不重复创建，本期不提供新增标签的 `+`；
- 点击文件标签会切换活动预览；关闭后台标签不影响当前预览，关闭活动标签后优先激活其右侧相邻标签、没有右侧标签时激活左侧标签，关闭最后一个文件标签后保留文件工作区并回到“打开文件”空态；标签只存在于当前项目的本次 Desktop 会话，切换项目、关闭文件工作区或重启后清空；
- Inspector 临时扩展到文件工作区宽度，关闭文件标签后恢复进入前的用户宽度；
- 路径栏右上角在文件夹按钮左侧提供“展开面板”；点击后文件工作区在 `WorkbenchShell` 内覆盖完整主舞台但不覆盖左侧项目栏，外层 Inspector resize handle 暂停，文件区内部 240–400px 列表分隔线继续可用；
- 扩展态顶部中间显示当前会话标签，右侧继续显示已有文件标签；会话标签与文件标签使用相同的紧凑高度、宽度和纵向留白；点击会话标签显示原 `RunStage`，点击文件标签显示覆盖态文件工作区，两侧切换不改变 thread、run、文件标签、目录树或预览会话 identity；
- 文件工作区覆盖叙事内容时仍复用原 `ComposerDock`；首页原本使用 `center` composer 时临时改用现有 `dock` variant，退出文件覆盖态后恢复原形态，不创建第三种 composer 或第二份草稿；仅文件 surface 激活时不显示输入面下方的项目名和“上下文窗口”，模型选择仍可用；点击会话标签后即使仍保持展开，项目名与上下文也应立即恢复；
- 文件 surface 的完整 composer 仅在正文、token、附件均为空时，完成一次非拖选的预览主键单击后收为短横线，再按“横线 → 继续对话 → 完整输入面”两级唤起；按下、正文拖选、预览工具按钮或任一结构化草稿存在时都不收起，Office guest 的有效单击通过带 `previewId` 的受限单向通知回到宿主；运行中收为可停止的“正在执行”，最近一次从扩展文件 composer 发起的任务成功后收为含耗时的“已完成”，历史 finished thread 不产生该入口；所有状态共用原 draft/run authority，点击会话标签时不套用该紧凑呈现；
- 扩展态顶栏提供“收起面板”按钮；收起后恢复 720px 文件工作区分栏，当前文件、预览、目录展开、筛选和内部列表宽度保持不变；
- 点击路径栏右上角的文件夹按钮可收起或展开完整文件列表；收起时左侧文件区域占满工作区，再次展开恢复原有文件夹组、筛选、目录展开和文件选择状态；
- 文件区域与文件列表之间的竖向分隔线支持左右拖拽调宽，文件列表首次展开默认使用 240px 最小宽度，可在 240–400px 内调整，文件区域至少保留 240px；普通拖拽到 240px 只停在最小宽度，短距离快速移动或中等力度不会收起，只有从最小宽度边界继续明显长距离、高速向右甩动才会收起文件列表；分隔线获得焦点后可用左右方向键按 12px 微调，收起再展开时保留收起前的宽度；
- 工作区左侧是只读内容区域；未选文件时“打开文件”空态与浏览器空态一样在内容区水平、垂直居中，打开文件后显示当前活动标签对应的预览；
- 在“文件”与“浏览器”之间切换只改变当前可见内容层，不销毁已打开文件的查看器或其预览会话；切回后必须立即显示原预览，不需要重新点击文件；
- 工作区右侧依次显示当前项目文件夹组选择器、文件名筛选框和目录树；
- 文件夹组选择器只切换**同一个当前项目**已绑定的文件夹，不切换项目 identity；主文件夹默认优先；选择器和下拉选项只展示文件夹组名称与选中状态，不展示本机物理路径；
- 目录树按需读取：打开文件工作区时读取根目录，展开目录时再读取该层；文件工作区存续期间由 Electron Main 监听当前文件夹组，Agent、外部应用或用户新增、删除、重命名项目文件后，Renderer 重新走受控目录 bridge 刷新根目录和已加载层级，保留仍然存在的展开目录；目录排在普通文件前；文件夹沿用左侧项目树的 `Folder` / `FolderOpen` 状态，展开时箭头旋转、文件夹轻动和新出现子项淡入，系统要求减少动态效果时关闭这些动画；
- 对普通文件或文件夹点击右键只显示“添加任务”“复制路径”“打开方式”三类动作，不提供删除、重命名、新建或其他文件管理动作；符号链接不显示该菜单；主菜单与“打开方式”子菜单使用渲染后的实际尺寸约束在当前可视窗口内，靠近底部时上移、右侧空间不足时向左展开，不被窗口边缘裁切；
- “添加任务”把条目作为当前 Composer 的原子 `file` token 插入当前逻辑光标位置，界面只显示文件名或文件夹名，不显示绝对路径；它与 Skill token 共用同一个 plaintext editing host、定位、编辑、删除和重放规则，已有同一项目路径 token 只聚焦而不重复添加；运行中禁用该动作；
- “复制路径”把 Main 重验后的当前绝对路径写入系统剪贴板；“打开方式”在 macOS 与 Windows 提供 WPS Office、匹配文件类型的 Microsoft Office、VS Code、Cursor、TRAE，以及平台支持时的 Xcode，每一行左侧显示对应应用的等比例品牌图标，Microsoft Office 使用统一 Microsoft 365 图标而不拆成 Word、Excel、PowerPoint 三项；文件夹不提供 WPS/Office；Main 在 macOS 按固定 bundle id、在 Windows 按固定 executable identity 从 App Paths 注册表、常见安装目录和 `PATH` 解析应用，未安装、平台不支持、不匹配格式或启动失败都返回带应用名的稳定结果，Renderer 在左侧文件预览区上部居中显示按文案自适应的紧凑错误提示，不依赖整个面板或右侧文件列表定位；Xcode 在 Windows 明确提示不受支持；
- 筛选只作用于本次已经加载的树节点，并保留命中节点的已加载祖先；它不是全盘文件搜索；
- 点击 `.docx` / `.xlsx` / `.pptx` 后由内置 OfficeCLI 生成缓存 HTML，再在隔离 webview 中显示；原 Office 文件不改动；
- 所有已支持格式共用一条 44px 高的预览头部：左侧单行显示文件名与格式，右侧依次放置该格式必要的紧凑控制以及重新载入、系统打开和文件管理器定位，宽度不足时先隐藏格式文字、文件名省略，控制区不换成第二行；Markdown 由右侧栏独立 `react-markdown + remark-gfm + rehype-sanitize` 管线渲染；已知代码/文本格式以及 Main 有界探测为安全文本的未知扩展名或无扩展名文件，统一使用 CodeMirror 6 只读模式，提供行号、可用时的语法高亮、选择复制和自动换行，不提供独立搜索按钮或搜索面板；文本预览上限为 2 MiB，二进制、无法安全解码和超限内容仍明确拒绝；
- PDF 通过支持 byte-range 的 `awaken-preview:` 流进入按文件类型延迟加载的 PDF.js 查看器，提供上/下一页、页码跳转、缩放、适应宽度和旋转；图片使用 Chromium 原生解码与缩放；
- 点击 `.html` / `.htm` 会自动切换“浏览器”；未选 HTML 时内容区居中显示“浏览器 / 预览 Html 文件”空态；本地 CSS、JavaScript、图片和页面跳转通过项目范围的 `awaken-preview:` 协议读取，HTTP/HTTPS 导航交给系统默认浏览器；
- 不支持的格式、超限、转换失败或加载失败显示明确错误，并保留系统打开和在文件管理器中显示的回退；查看器组件异常必须被局限在文件预览区，不得卸载整个 Desktop Renderer；
- 已知扩展名在目录树与顶部文件标签中同步显示 Word、Excel、PowerPoint、PDF、Markdown、代码、数据、图片、压缩包、音频、视频或文本图标，未知格式回退通用文件图标；目录符号链接显示为不可展开的文件项。

“当前项目”优先采用当前活动 thread 的稳定 `projectId`，没有活动 thread 时采用侧栏当前选择的项目；独立对话或未选项目显示选择项目空态。项目没有绑定文件夹时显示无文件夹空态，不回退到默认 workspace、进程 cwd 或用户主目录。

点击“子任务”后进入 Subagent Inspector：

- 首次点击“子任务”展开详情，再次点击当前“子任务”入口收回详情；展开与收回沿用用户当前 Inspector 宽度，不额外向左扩张；
- 顶部显示选中 task 的 agent type、description 和 canonical status；
- task switcher 按创建顺序列出当前 thread 已投影的任务，切换选择不改变 task runtime；
- 详情从 reducer-owned `SubagentTaskView` 显示最近活动、Markdown 结果或稳定错误码，并显示工具次数、provider-reported token 累计和按 started/finished 时间计算的耗时；中心 group 与执行详情卡使用同一 task truth；
- 只有 `queued/running` task 显示取消入口；进入 `cancelling` 后按钮消失，取消通过 typed Main/preload bridge 调用 Core，Renderer 不直接改状态；
- 切换 thread 时清理旧 `selectedSubagentTaskId`，默认选中新 thread 的首个 task；
- 中心 Subagent row 只打开/切换所属 turn 内的执行详情卡，不自动打开右侧 Inspector；右侧 `selectedSubagentTaskId` 与中心 `openSubagentTaskId` 是两份独立 UI state，关闭任一 surface 都不取消 child；
- 当前不支持向 child 追加消息、完整 cost 统计、跨重启 selection 或窄屏专用 sheet；provider 未报告 usage 时不补造 token。

连接器和技能是独立功能页，不使用 Workbench Inspector。进入这两个页面时，Desktop 必须同时隐藏 Inspector、resize handle、分隔线和顶栏展开/收起按钮，不为右栏保留空白宽度。返回主 Workbench 后恢复用户原有的右栏宽度和折叠偏好，不因路由切换改写它们。

因此旧“Right Inspector Rail”切片中下列描述已经失效：

- 完整InspectorTabs；
- selected tool args/result面板；
- Changes patch/turn diff面板；
- Files详情；
- Browser disabled tab；
- approval detail selection。

## 3. 当前壳与布局

- `WorkbenchShell` 接收 `inspector` slot、`inspectorCollapsed`、`inspectorExpanded` 和 `inspectorSurfaceActive`；后两者只控制 UI-only 覆盖与可见性，不读取 thread 或文件状态。
- 默认宽度 300px，允许在配置的 min/max 范围内 resize；文件工作区打开时使用 720px 宽右栏，当前 resize 上限为 760px，关闭后恢复进入前宽度。
- 宽度和折叠状态写入renderer localStorage。
- resize handle支持pointer和键盘。
- 文件覆盖态不改写 `inspectorWidth`；退出覆盖态后直接回到进入前的文件工作区宽度。
- 窄窗口媒体查询自动折叠；恢复宽度时回到自动折叠前状态。
- 顶栏按钮可手动折叠/展开。
- 上述壳与布局只在主 Workbench 渲染；连接器/技能页只渲染自身主内容。

折叠文件工作区只隐藏面板，不关闭文件标签；重新展开仍回到同一文件工作区。连接器/技能等独立功能页继续隐藏整个 Inspector。

## 4. 当前文件目录数据链路

Renderer 通过专用 `listProjectDirectory` bridge 请求一个目录层级。文件工作区挂载后再通过 `watchProjectDirectory` 为当前选中的项目文件夹组建立 Main-owned 订阅；Main 合并短时间内的重复文件系统事件，只返回不含物理路径和文件内容的 subscription invalidation。Renderer 收到 invalidation 后刷新根目录和当前已经加载的目录层级，切换项目/文件夹组、关闭文件工作区或窗口时立即释放订阅。Electron Main 在订阅建立时和每次目录读取时都会重新从 Core 获取当前 active projects，并依次验证：

1. `projectId` 当前仍存在且 active；
2. 请求的 `folderPath` 与该项目当前绑定的文件夹精确对应；
3. 相对目录不含绝对路径或 `..`；
4. lexical target 与 realpath target 都留在注册文件夹内；
5. 目录可读。

Main 只在目录列表 bridge 返回 `name`、项目文件夹相对路径和 `directory/file/symlink` 类型。预览 bridge 不接受任意绝对路径：Renderer 只提交 `projectId + folderPath + relativePath`，Main 每次重验项目、精确文件夹 membership、lexical/realpath containment、普通文件类型和 symlink 边界。Markdown、已知代码以及经 Main 有界内容探测确认的安全文本以 typed IPC 文本返回；未知格式不能由 Renderer 自行读取或绕过二进制、解码与 2 MiB 上限。Office、PDF、图片和 HTML 只获得短生命周 opaque preview handle，不向 Renderer 暴露根绝对路径。目录符号链接可以显示，但不能遍历或预览；此链路不改变 Agent `TaskScope` 对工具调用的语义。

右键动作同样只接受 `projectId + folderPath + relativePath + kind`。Main 在“添加任务”“复制路径”和“打开方式”执行时逐次复用当前 active project 解析并返回或消费一条已验证绝对路径；外部应用在 macOS 只通过固定 bundle id 启动，在 Windows 只解析固定 executable identity，并把已验证条目路径作为单独参数直接启动 `.exe`，两端都不拼接 shell 命令。“添加任务”得到的路径 identity 进入结构化 Composer token 后，Core 在每次 StartRun 前还会按当前 `projectId`、精确 `ReadableRoots`、relative path、真实路径、条目类型和 symlink 边界再次验证；验证成功才在模型 effective input 的原 token 位置恢复绝对路径，展示正文仍只保留名称 token。

## 5. 已有但未接线的数据

Desktop reducer/projector当前持有：

- `narrative.inspectorSelection` union；
- tool args、result、status、bounded command output和truncated flag；
- artifacts和role/status/path；
- patch/turn diff数据；
- `inspectorSummary.lastToolDecision`；
- context window摘要。

上述通用 tool/artifact 数据当前仍未接线，不等于右侧已经支持通用工具详情。Subagent Inspector 是独立的已实现入口，只消费 reducer-owned `SubagentTaskView`，不从 root narrative 或通用 tool record 反推 task。

媒体固定查看器也是窄范围独立入口：`App.tsx` 只在用户从已投影媒体卡发出明确动作后保存该卡已有的 `threadId + runId + artifactId/sourceKey`，随后从当前 `awaken-artifact://` source cache 派生临时地址。图片/视频固有尺寸和视频时长来自 Renderer 的原生解码事件；解码失败时按同一 Artifact identity 有限次续签。切换 thread 会清理固定状态。该入口不消费 `narrative.inspectorSelection`，不扫描 artifacts，不把通用 Artifact tab 写成已支持。

## 7. 硬边界

- 右侧详情不得进入 `ExecutionFeed`。
- 新Inspector必须消费已有reducer identity，不从DOM或文本重新解析tool/artifact。
- 媒体固定查看器只能消费媒体卡已经绑定的 durable Artifact identity；不得从标题、序号、DOM、可见路径或最终回答文字重新寻找文件，也不得改用项目文件 `awaken-preview` 授权链路。
- Browser 只能渲染 Main 签发的当前项目 HTML handle，不得直接接受 `file:///`、Renderer 绝对路径或任意网络 URL。
- Terminal不得变成交互式shell或绕过tool/runtime策略。
- Changes不得把preview等同已执行diff。
- 右栏交互不得改变run streaming/replay state。
- 文件扩展态仍是 Inspector surface，不得进入 `ExecutionFeed`、复制 Composer、卸载 `RunStage`，或用 `100vw` 越过左侧项目栏；文件 surface 激活时只让叙事滚动区 inactive，原 Composer 继续负责当前 thread 草稿与提交。
- 详情组件如进入Design System，仍需UI-only；runtime lookup留在Desktop。
- Renderer 传入的 `projectId`、folder path 和 relative path 不是授权事实；目录读取必须在 Main 按当前项目重验。
- 右键动作不得接受 Renderer 任意绝对路径、跟随 symlink 或使用 shell 字符串启动应用；隐藏路径 token 在项目或根目录变化后必须由 Core 拒绝，不能依赖添加时的一次校验继续生效。
- 文件工作区不得从 label 或物理路径反推项目 identity；同一物理文件夹可以属于多个项目。
- 预览 bridge 不能演化成不受约束的任意 `readFile(path)`；每个 protocol 子资源请求也必须重验当前项目边界。

## 8. 当前不支持

- 通用 tool/artifact Inspector tabs 和 selection；
- 命令输出详情；
- patch/turn diff详情；
- Word、Excel、PowerPoint、Markdown、代码、HTML 或其他文件的编辑和保存；
- `.doc` / `.xls` / `.ppt`、HEIC、TIFF、RAW 等非首期格式预览；
- 文件标签 `+`、标签跨项目保留和标签跨重启恢复；
- 同时打开多个会话标签、关闭会话标签或在顶部新建会话标签；
- 未展开目录的递归/全项目搜索；
- 完整互联网浏览器、下载管理、持久历史和 browser automation surface；
- approval恢复；
- Inspector状态跨thread持久化。
- Subagent message、完整 transcript、完整 cost 统计、窄屏专用 sheet 和 selection 跨重启恢复。

## 9. 验收

- 真实 Desktop 依次点击“文件”和“浏览器”，确认 Inspector 扩展、左侧只读内容区与右侧文件夹组/筛选/目录树都在同一文件工作区；未选 HTML 时“浏览器”显示空态。
- 打开 Office、PDF、图片、Markdown 或代码文件后切到“浏览器”，再切回“文件”；原预览必须立即恢复，不重新选择文件，Office/HTML webview 不因入口切换被销毁或重建。
- 在普通文件工作区点击“展开面板”，确认文件预览和目录树覆盖完整 Workbench 主舞台但左侧项目栏保留，顶部出现当前会话标签和带上、下、左侧留白的紧凑文件标签，底部仍是当前会话的原输入框；空草稿时分别在宿主正文和 Office guest 内单击，确认完成手势后收起，拖选正文不收起；输入正文或添加 token/附件后再次点击预览，确认输入面保持展开。往返点击会话/文件标签，确认 run 继续、草稿不丢、文件查看器不重建、目录树状态不变；切入旧 finished thread 不显示历史“已完成”；点击顶栏“收起面板”后恢复 720px 分栏与此前文件状态。
- 拖动中间分隔线并用方向键微调，确认文件列表只能在 240–400px 内变化；普通拖拽到 240px 不隐藏，短距离快速移动和中等力度也不隐藏，再从最小宽度明显长距离、高速向右甩动才平滑收起；连续点击文件夹按钮，确认树状态和上次宽度均不丢失。
- 为同一项目绑定两个测试文件夹，确认默认选中主文件夹，下拉选项不显示本机物理路径，切换后只展示对应树；切换项目或 thread 后不串用上一项目目录。
- 展开两层目录并筛选已加载文件，确认目录按需读取、文件夹动效和祖先保留；保持文件工作区打开，在当前根目录和已展开子目录中分别通过 Agent/命令新增、删除、重命名文件，确认目录树自动同步且仍存在的展开层级不收起；分别打开 DOCX、XLSX、PPTX、Markdown、已知代码、`go.mod`、`go.sum`、无扩展名或未知扩展名的安全文本、PDF和支持图片，确认各格式只出现一条不换行的预览头部，格式控制、系统打开和显示回退均位于同一行，代码没有搜索入口但自动换行仍可切换；同时确认只读内容、新文件新增标签、重复文件不重复、标签切换和逐个关闭行为；二进制与超过 2 MiB 的文本仍显示明确拒绝。
- 从文件树选中 HTML，确认自动切换“浏览器”，相对 CSS、JavaScript、图片和页面跳转可用，后退/前进/刷新有效，外部链接不留在内置 webview；手动切回“文件”不得在文件内容区继续渲染 HTML。
- 使用 traversal、未绑定文件夹和指向项目外的目录 symlink fixture，确认 Main 返回 typed deny，Renderer 不展示项目外内容。
- 分别右键普通文件、文件夹和符号链接，确认菜单只有“添加任务”“复制路径”“打开方式”，符号链接无菜单；在目录顶部、底部和窗口左右边缘分别打开主菜单与“打开方式”，确认两层菜单按实际尺寸上移或左右反向展开并始终完整留在可视区域；把文本光标放在句中后添加文件与文件夹，确认 token 原位显示名称而非路径、前后正文和 Skill token 顺序不跳、复制/删除规则一致，复制路径得到当前绝对路径；文件夹的 WPS/Office 禁用，macOS 按固定 bundle id、Windows 按固定 executable identity 打开已安装应用，Windows 路径含空格时仍作为单独参数传递；未安装、平台不支持和启动失败均显示带应用名的稳定错误提示；切换项目或解绑文件夹后旧 token 提交被拒绝。
- 关闭最后一个文件标签后确认回到居中的“打开文件”空态，再关闭占位标签后确认退出文件工作区并恢复此前宽度；折叠/展开/resize 仍可用。
- 折叠和窗口缩窄不能遮挡中间composer。
- 从主 Workbench 切换到连接器和技能，确认右栏、分隔线、resize separator和顶栏按钮全部消失；返回后原宽度/折叠偏好不变。
- reducer测试只能证明数据存在，不作为右栏功能验收。
- 真实 Desktop 创建 Subagent，确认中心 group、任务 badge、task switcher、running/completed/result、工具数、token 与运行/终态耗时；再取消一个运行中 task，确认 cancelling/cancelled、按钮消失与稳定错误码。只读/可写/message 的当前 Core 语义见 [02 原生 Subagent 产品与架构契约](../../02_主智能体闭环/原生Subagent产品与架构契约.md)；本次对齐未重做该真机步骤。
- 连续点击两次“子任务”，确认 Inspector 详情先展开再收回且分隔线位置不变；从中心 Subagent group 选择任务只打开/切换中间执行详情卡，卡片关闭不取消 child，也不改变右侧选择。
- 在包含不同宽高比图片和视频的真实任务中，确认媒体卡主键仍打开中间预览；从更多菜单选择“在右侧栏查看”后才出现“媒体”入口，图片/视频按真实比例 `contain` 展示并显示 `宽×高 · 时长 · 格式`，视频可在右侧直接播放。关闭媒体查看器或切换 thread 后固定状态清除；媒体 source 失效时自动续签，不要求刷新 Desktop。
- 新增文件编辑或任何其他详情前，必须同步更新本文、相关测试，并提供真实 Desktop 截图/录屏。
