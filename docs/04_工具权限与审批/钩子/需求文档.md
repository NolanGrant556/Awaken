# 钩子 · 需求文档

用户可以在设置中或通过自然语言配置钩子，在指定运行边界执行检查、更新输入或阻止后续动作。

代码、接口和验证方法见[实现方案](实现方案.md)。

## 文档地位

- 04 域拥有配置、检查、信任、匹配、执行器、安全策略和 canonical outcome；
- 02 域拥有 Hook 进入 run、工具循环、压缩、Subagent 和结束循环的时机；
- 03 域拥有运行事实的耐久化、恢复和重放；
- 08 域拥有 Skill 的发现与显式激活，Skill 激活后仍注册到本文定义的同一运行时；
- 09 域拥有本地 HTTP 和 AG-UI wire，不重新定义Hook 业务语义；
- Desktop Renderer 只展示 Core 返回的检查结果，不自行解析 `hooks.json`、判定信任或执行命令。

## 解决的问题与用户入口

Hook 允许用户在确定的任务生命周期边界执行本机命令、受控 HTTP 请求、模型提示词或只读智能体，用于校验工具输入、补充模型上下文、记录外部系统，或在受支持的前置边界阻止操作。

用户入口是 Desktop `设置 > 钩子`。页面当前提供：

- 用户配置或一个当前项目范围的选择；
- 来源路径、规范化摘要、启用/停用/待信任/无效状态和诊断；
- 按事件分组的 Hook 列表和可展开静态详情；
- 项目配置的“信任当前配置”和“撤销信任”；
- Hook 以当前用户身份在沙盒外运行的固定风险说明。

详情来自 Core 对当前配置的严格解析结果。页面展示 `id`、事件、执行器类型、精确 matcher、timeout、输出上限和失败策略，并按执行器展示：

| 执行器 | 详情字段 |
| --- | --- |
| `command` | 完整 argv、host-owned cwd 选择 |
| `http` | URL、是否允许 loopback、secret header 名称；不展示引用名和值 |
| `prompt` | prompt、可选 model selector |
| `agent` | prompt、可选 model selector、最大轮次 |

该页面是检查和信任界面，不是表单配置编辑器。用户既可以直接维护对应 JSON，也可以在普通对话中用自然语言要求主智能体调用 `configure_hook`。该工具只接受结构化配置、由 Core 校验整个下一版本并原子落盘；项目共享/本地配置仍必须由用户在设置中显式信任。任何配置或信任变化只影响后续新 run，不能热改已经固定的 run。

## 当前支持与当前缺口

### 当前不支持或未完成验证

- 不提供设置表单编辑器、managed/CLI settings、SDK callback、任意 session function Hook、`once`、通用并行 Hook、自动发起新模型 run 的异步唤醒和 child 内部 tool Hook；
- 当前异步执行只适用于 Plugin command Hook；prompt/agent/http/mcp_tool 仍同步。Claude `asyncRewake` 的完成反馈进入同一 thread 的下一次 run，不在没有用户请求时擅自启动模型；进程重启前尚未被下一次 run 消费的异步反馈不持久化；
- stdout/stderr 超限时直接形成 protocol failure，不保存大型 result blob；
- 模型调用 `skill`、fork Skill 或仅发现 Skill 不注册包内 Hook；
- HTTP proxy-only DNS 不能工作：当前在交给代理前仍要求本机解析目标；
- HTTP 代理只按首个 URL 选择，重定向后不会按新目标重新计算 proxy/`NO_PROXY`；
- 代理实际解析和连接的目标 IP 没有 Awaken 自有连接级 pinning；
- redirect/proxy-only/`NO_PROXY` 尚无完整真实网络矩阵；
- Windows amd64/arm64 可以交叉编译，但尚无当前版本的真实 Desktop 准入；user config 和 secret store 仍使用 POSIX mode 判断，在原生 Windows 上不能作为用户 ACL 的正确实现，因此不能宣称 Windows Hook 可用。

### Plugin Hook 当前边界

只把安装后已归一化、完整性有效、组件启用且配置完整的 Hook 编译进后续新 run。`SourcePlugin` 绑定插件名、安装摘要、`logicalId` 和 `revisionId`；现有 run 不热更新。方言 adapter 显式映射事件和输入输出协议，尤其不得为 Cursor 构造不存在的 `postCompact`。

插件 command 在编译期完成变量解析和 argv 拆分，不把厂商 command 交给隐式 shell。tool event 的厂商 handler 条件必须进入统一 matcher；例如 Claude `Bash(git commit:*)` 只匹配对应 Bash command，不能退化成所有 Bash 调用。无法安全解析的 handler 条件使该 Hook 不可运行。`mcp_tool` 只调用该插件已注册、当前 ready 且未被逐 tool 停用的 MCP tool。Plugin Hook 的普通事件未声明 timeout 时默认 600 秒，厂商声明正数时按原值编译；`SessionEnd` 退出事件单独默认 1.5 秒并限制为最多 3 秒。超时记录 `timed_out` 回执并按 failure policy 继续或阻断。所有执行复用本域 Dispatcher、每 run 64 次、单事件 16 次、累计墙钟 120 秒的 admission gate、取消、失败策略与耐久事实，不建立第二套 Hook runtime；累计墙钟只决定后续 invocation 是否获准开始，不会把已经开始的单次 Hook timeout 改写回 10 秒。

Plugin command Hook 声明 `async`/`asyncRewake`，或 Claude command 首个 JSON 行声明 `{"async":true,"asyncTimeout":...}` 时，Dispatcher 在进程成功启动后立即把本次 invocation 标记为 `scheduled` 并放行触发它的操作；后台进程仍受取消、输出预算和最多 10 分钟的异步 timeout 约束。异步 handler 永远不能追溯阻断、改写已启动操作或改变已返回的 candidate；完成后才写 `hook_invocation_completed` 和 Plugin 回执。后台任务开始前会引用 run 的 Plugin generation lease，run terminal 只提出释放请求，最后一个异步 Hook 完成或取消后才真正释放，避免插件包在子进程仍执行时被替换或卸载。`SessionEnd`/`sessionEnd` 一律强制同步并服从退出预算。

Claude stdout adapter 按厂商协议逐行读取 JSON：异步声明只负责切换执行模式，完成后采用第一个非 async JSON 响应；metrics-only 完成结果视为 `continue`，`hookSpecificOutput.additionalContext`、或 `asyncRewake` exit 2 的 reason/stderr 作为不可信 Hook data 写入有界 thread 队列。下一次同 thread run 在首个模型请求前一次性消费该队列；静态 `rewakeMessage` 只作为插件数据前缀，不获得 host instruction 权限。该队列每 thread 最多 32 项/32 KiB，只存在当前 Core 进程内，不自动创建新 run。

## Hook 是什么

Hook 是在固定产品生命周期边界自动触发的规则。普通工具由模型在当前任务中临时决定是否调用；Hook 在配置、启用并满足 matcher 后，由 Awaken 在对应事件边界确定性触发。

一个 Hook 由三部分组成：

1. **事件**：何时触发，例如 run 启动、工具执行前、最终回答形成前；
2. **matcher**：工具事件要匹配哪些 canonical tool name；非工具事件没有 matcher；
3. **执行器**：触发后运行 `prompt`、只读 `agent`、本机 `command` 或受控 `http`。

完整事件、字段、输出协议、安全和恢复规则只以 [Hook 产品与架构契约](实现方案.md) 为准。本文只提供当前能力的入门路径和可复用示例。

## 推荐使用流程

1. 在 Awaken Desktop 选择目标项目；
2. 在普通对话中描述需求，并明确要求主智能体调用 `configure_hook`；
3. 新手优先选择 `project_local`，避免影响其他项目；
4. AI 写入配置后打开 `设置 > 钩子`，展开检查事件、matcher、执行器、timeout、输出上限和失败策略；
5. project/project-local 来源会显示“待信任”，确认内容安全后点击“信任当前配置”；
6. 新建任务验证行为。配置和信任变化只影响后续新 run，不热改当前 run；
7. 配置内容变化会使原摘要信任失效，需要重新检查和信任。

三个持久 scope 的用途：

| scope | 配置路径 | 适用场景 |
| --- | --- | --- |
| `project_local` | `<project>/.awaken/hooks.local.json` | 个人项目差异，推荐入门；如不提交 Git，应自行加入 `.gitignore` |
| `project` | `<project>/.awaken/hooks.json` | 团队共享并随仓库审查的规则 |
| `user` | `~/.awaken/config/hooks.json` | 对所有项目生效的本机通用规则 |

设置页是检查与信任界面，不是表单编辑器。除直接维护 JSON 外，当前推荐通过 `configure_hook` 完成查看、upsert、删除和整来源启停。

## 推荐从这个 Hook 开始

### 最终回答质量检查

`BeforeFinish + prompt` 不运行本机命令，效果容易观察，是风险最低的入门组合。可以在项目对话中发送：

> 请调用 configure_hook，为当前项目创建一个 project_local Hook。ID 为 `review-before-finish`，事件为 `BeforeFinish`，使用 prompt 执行器。检查候选回答是否完整满足用户要求、是否存在未经验证的完成声明；满足则返回 ok=true，不满足则返回 ok=false，并通过 reason 和 additionalContext 给出简短修改建议。超时 10 秒，Hook 自身失败时继续。

检查不通过时，Awaken 会把反馈交回主模型再修改回答；单次 run 最多允许两次 `BeforeFinish` 阻止结束。

适合：

- 防止遗漏用户明确要求；
- 检查测试、Desktop 验收和剩余缺口是否如实报告；
- 避免未验证却声明完成。

## 查看、修改、停用与删除

可以直接在普通对话中发送：

> 请调用 configure_hook，列出当前项目 project_local 中的所有 Hook。

> 请调用 configure_hook，把 project_local 中 ID 为 `review-before-finish` 的超时改为 15 秒，其余行为保持不变。

> 请调用 configure_hook，停用当前项目的整个 project_local Hook 来源。

> 请调用 configure_hook，删除 project_local 中 ID 为 `review-before-finish` 的 Hook。

项目配置每次变化都会产生新摘要并回到“待信任”。AI 不能替用户信任配置，也不能通过自然语言授权推导永久信任。

## 安全建议

- 从 `project_local + prompt + onFailure=continue` 开始；确认收益后再考虑 command、HTTP 或阻断；
- command 以当前登录用户身份在沙盒外运行，配置前必须审查完整 argv 和脚本；
- `onFailure=continue|block` 描述执行器自身失败后的策略，不等同于 Hook 正常返回的 `block_*` 控制决定；
- matcher 是 canonical tool name 精确匹配或 `*`，不是正则表达式；
- user scope 会影响所有项目，通知之外的规则优先使用项目 scope；
- 不把 token、密码或 API key 写入 command、URL、prompt 或 header；HTTP header 只能引用 Core secret store；
- Hook 变更只影响后续新 run。测试时新建任务，并同时观察 Workbench Hook 回执和 `设置 > 钩子` 状态；
- Windows 当前只有交叉编译证据，POSIX mode 尚未替换为正确的 Windows 用户 ACL，不能视为已实机支持。
