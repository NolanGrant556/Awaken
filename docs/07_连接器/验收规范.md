# 验收规范

## 1. 自动化

- source priority、稳定 provider ID、capability/dependency 去重；
- 七个 builtin manifest；local dynamic manifest；
- builtin 写 user config、local InjectDynamic、同 owner disconnect 与跨 owner拒绝；
- connected/needs_auth/failed 到 provider readiness；
- Connector aggregate capability 不授予 per-tool send/delete；
- metadata-less 明确 read-only 可自动；非 read-only/自相矛盾 tool 缺失或无效 per-tool metadata 时返回 `unverified_mcp_provider_metadata` 且 external calls=0；有效 metadata 的普通 mutation 进入统一自动执行；
- 重启后 active owner 缺失的现状有回归测试或明确缺口。

```bash
go test -count=1 ./src/connectors ./src/mcpclient ./src/server
```

## 2. Desktop 验收

使用隔离 profile 逐个验证 builtin/local：连接、pending/connected/needs_auth/failed、具体 MCP tool/Skill、断开、重启与 MCP 管理面一致性。任何 config 覆盖/删除前后都保留 fixture 快照。

## 3. 完成边界

只跑 registry 单测不能声明 OAuth、外部服务或跨重启 ownership 完成；未执行 Windows/Linux CLI 路径和真实 provider 连接时逐项报告。
