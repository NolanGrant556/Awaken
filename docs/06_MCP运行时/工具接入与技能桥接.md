# 工具接入与技能桥接

## 1. MCP tool provider contract

Awaken 使用版本化 MCP `_meta` 扩展 `io.awaken.tool/provider/v1` 描述标准 MCP annotations 无法证明的执行语义：

- `provider_id`、per-tool `capabilities` 和 dependencies；
- `message_egress`：channel/account、recipient(s)、recipient kind/scope、message count、expansion、body、attachments 的字段映射；
- `recoverable_delete`：是否可恢复及 output 中 confirmation/restore-handle 字段。
- `artifact_output`：base64 bytes、SHA-256、相对 output path、content type 与可选 title 的 output 字段映射，以及不大于 host 上限的 provider `max_bytes`。

仅当标准 annotations 明确且自洽地声明真正 read-only 时（包括 open-world search/read），tool 才可以在没有 Awaken metadata 时自动执行。任何非 read-only tool，或 `readOnly=true` 同时又声明 destructive 的自相矛盾 tool，都必须提供可解析的 per-tool `_meta`；缺失/无效时在 transport 前返回 `unsupported` + `unverified_mcp_provider_metadata`，external calls=0。因此非明显 mutation 别名不再能仅凭“名称看起来普通”绕过门禁。

具有有效 metadata 的普通 mutation 仍默认自动执行；metadata 是进入 typed policy 的最小契约，不是通用 Approval。如果其 capabilities 声明消息发送或删除，还要分别通过 typed recipient envelope 或 recoverable-delete 契约；provider 在 transport 后撒谎仍只能被检测，无法通用撤销已发生的外部副作用。

## 2. 消息发送

adapter 在 transport 前构造 typed `MessageEgressEnvelope`：

- 一个明确 individual、单条、不扩展：自动允许；
- multiple/group/channel/broadcast、message count > 1 或扩展：进入唯一 mass-message review；
- recipient identity/kind 缺失或 unknown：`unobservable_message_recipients`，external calls=0。

Manager 可用 `WithMessageEgressGateway` 注入中央 gateway。Connector aggregate `message.send` 只用于发现，不授予某个 tool 发送权限。

`McpToolAdapter.Execute` 与 `ExecuteOutcome` 自身也是强制门禁，不能假定调用方一定先经过 `CheckPermission`。群发调用只有在 ToolRuntime 完成耐久 review 后携带同一 run/tool call/tool/provider 与 envelope/body/recipient digests 的一次性 grant 才能进入 `Manager.CallTool`；无 grant、参数变异或 grant 重放均在 transport 前返回 `mass_message_review_required`。用户可控的 MCP `serverName` 不是 provenance：只有 host 注入且携带 `SourceConnectorID` 的 server 可标为 official connector；名为 `github`、`playwright` 等的普通 MCP 仍是 third-party。

## 3. Remote recoverable delete

per-tool 具备 `file.delete` 时必须声明 `recoverable_delete.recoverable=true`，并在 output schema 中声明 confirmation 或 restore handle。缺失时返回 `unsupported_recoverable_delete`、transport `not_started`、external calls=0。

调用成功后 adapter 再验证实际结果；无 recovery evidence 返回 `recoverable_delete_result_unverified` 并提示检查 provider Trash、不要重试。该后置检测无法撤销一个撒谎 provider 已执行的远程副作用，这是明确缺口。

## 4. Host-mediated artifact output

声明 `artifact_output` 的 per-tool metadata 必须同时声明 artifact-writing capability；所有配置字段必须是 output schema 中的 required string。provider 只能返回 bytes，不能返回其本机 path 或“已发布”标记作为本地交付事实。adapter 对结果执行：

- strict base64 与 host 32 MiB 上限，provider `max_bytes` 只能进一步收窄；
- exact lowercase SHA-256；
- canonical forward-slash relative path，拒绝 volume/absolute/traversal/backslash；
- publishable extension、exact MIME、derived Artifact kind，以及 UTF-8/PDF/OOXML/OLE 基础签名；
- 显式 TaskScope 的 writable roots 与 output roots 双重解析、workspace real-path、sensitive/protected 和任何 workspace 内 symlink component。

全部通过后，host 以 provider/capability、relative path、digest、size、MIME、kind 生成不可变 `host_artifact_publish` projection，在 `WorkspaceExecutionBroker` private snapshot 写入 bytes。broker 复核 staged digest/size 与 exact single-file delta；replace 先把 live preimage 移入 Trash，再发布并返回 receipt。取消发生在 commit 前时只做 bounded background discard/cleanup；一旦 broker 已提交，即使后置验证失败，Outcome 也必须按 receipt 保留 applied/partial changes，不能倒写 `not_started`。成功 Outcome 不携带原始 base64，也不透传 contract 之外的 provider StructuredContent；只携带 canonical ArtifactDescriptor、由 contract 安全字段重建的 sanitized details、provider/hash/size/content-type 和 broker receipt。

该链路证明的是 bytes/hash/基础容器签名与 host-owned recoverable commit，不证明内容语义、版式、字体、公式、逐页视觉或 Office 兼容性。质量验证仍由 typed artifact inspect/render 和 Desktop 视觉验收拥有。

## 5. Prompt/resource Skill bridge

bridge 将 MCP prompt/resource 动态注册为 `mcp__<server>__...` Skill：

- 目录阶段只注册元数据和 fetcher；
- 调用时才请求 prompt messages/resource content；
- list_changed 触发重新注册；disconnect/disable/reconcile 注销；
- 最近调用时间在同一进程 re-register 时保留；
- server readiness 只作为执行提示，不把本地 Skill 置灰；
- server 正文中的 shell 只作为文本，不在 bridge 内执行。

动态 Skill 走 08 的统一 `skill` 工具、inline/fork 和 journal；MCP bridge 不反向控制 server lifecycle。

## 6. 不变量

- MCP tool 必须经中央 registry、run snapshot、ToolRuntime、TaskScope/egress/delete safety 和 Outcome；
- server-level provider identity 不能替代 per-tool side-effect contract；
- metadata-less MCP 只允许明确自洽的 read-only；其他调用必须在 transport 前 fail closed；
- disconnect 时工具和动态 Skill 都必须卸载；
- 外部 provider 的声明与实际结果冲突必须保留诊断，不能升级为成功。
- MCP artifact bytes 永不进入 model content、diagnostic 或 AG-UI；只有 host commit 后的 canonical artifact/change/receipt 才能进入下游。

以上不变量覆盖进入 `McpToolAdapter` 的 host 调用路径，不等价于已沙箱化任意 MCP server 进程。当前 stdio child 尚未接入 WorkspaceExecutionBroker/Seatbelt；server 在工具调用之外自行读写/联网仍是 [配置、传输与生命周期](配置、传输与生命周期.md#6-当前缺口) 明列的安全缺口。

## 7. 代码 owner

- `src/mcpclient/provider_manifest.go`、`tool_safety.go`、`tool_adapter.go`：provider/safety adapter。
- `src/mcpclient/artifact_bridge.go`：artifact result 校验、stage/commit、Outcome redaction。
- `src/tool/execution_broker.go`、`execution_broker_workspace.go`：host artifact exact-delta 与 recoverable commit。
- `src/skills/mcp_bridge.go`：动态 Skill。
- `src/tool/egress.go`：中央消息 envelope 决策。
