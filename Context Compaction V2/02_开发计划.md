# 开发计划

## 总体策略

按连续性基础 → 原子 bundle → typed checkpoint → 完整 turn/recovery → 硬 10% → provider-native 优化 → Desktop 验收推进。不得把硬 10% 提前到连续性修复之前。

建议拆成独立、可回滚的阶段；是否拆 PR 由用户决定，Agent 不自行创建分支或 worktree。

## Phase 0：锁定基线与失败测试

### 目标

在不改变行为的前提下，把当前缺陷写成自动化失败基线。

### 任务

- 为完整请求分类增加 deterministic fixture。
- 增加以下当前缺口测试：
  - compact 后 Memory snapshot 不应消失；
  - live 与 restart 后 Skill blocks 应一致；
  - 未消费 Subagent terminal result 压缩后仍可获得；
  - summary 栏目非空但遗漏用户纠正时必须失败；
  - recent tail 不得保留 assistant 而丢失对应 user turn；
  - post 高于 CompactTarget 时不得成功。
- 记录 current v1 journal/replay fixture，供兼容测试使用。

### 退出条件

- 新测试能够稳定暴露缺口；
- 未修改生产行为；
- 用户 dirty work 未受影响。

## Phase 1：原子 `PostCompactContextBundleV2`

### 目标

把压缩从“替换 messages”升级为“一次安装完整压后上下文状态”。

### 任务

- 定义 bundle schema、digest、version 和 semantic record。
- 一次冻结稳定 v2 envelope 和 `MaterializedSection` 状态机；禁止后续阶段引入临时 schema 或靠字段缺失表达未实现。
- Phase 1 使用 `ConversationProjection.Format=v1_messages` 保存当前 summary+tail；TaskCheckpoint/SemanticSummary/RecentTurns/TranscriptLocator/Budget/Coverage/ProviderOpaque sections 写入规范化 `not_materialized` 状态。
- canonical digest 必须覆盖 section state、`EMPTY_SECTION_DIGEST`、reason、projection format 和兼容 messages。
- 从 conversation、Instruction、Memory、Plan、Skill、Tool、Hook、active gate、Subagent authority 采集引用。
- Journal append + flush 成功后才安装全部 in-memory state。
- 失败时不得执行 Memory reset、Skill compact 或 terminal handoff consumption。
- replay/restart 使用同一 bundle 恢复同一 provider-neutral context。
- 增加 bundle corruption、partial write、flush failure、digest mismatch 测试。

### 退出条件

- live/replay provider-neutral bundle digest 100% 一致，且 Instruction/Memory/Plan/Skill/Tool/Hook/active gate/Subagent refs 逐项相等；
- 每个 crash point 恢复到旧 bundle 或完整新 bundle，不出现半安装；
- v1 records 继续可读。
- Phase 2–5 能在不改变 schema version/envelope shape 的前提下逐项物化 sections。

## Phase 2：宿主 `TaskCheckpointV2` 与 coverage gate

### 目标

让任务连续性不再依赖自由文本摘要。

### 任务

- 从 Journal、RunPlan、Memory receipts、Skill activation、tool outcomes、Subagent state 抽取 typed facts。
- 为用户要求、纠正、约束、路径、命令、错误、数字、Artifact/task ID 生成 stable fact IDs。
- 实现 rolling checkpoint：`prior checkpoint + new compacted range`。
- summary prompt 引用 fact IDs；新增 coverage receipt。
- 实现最多两次 missing-fact repair。
- fallback 或 critical fact 缺失不得提交 bundle。

### 退出条件

- critical facts 100% 覆盖；
- 1/3/5 次重复 compact 后 checkpoint active facts 一致；
- 中文无冒号/等号的用户纠正也能保留；
- summary 模型输出不同措辞时，宿主事实仍稳定。

## Phase 3：完整 turn tail 与当前线程历史回读

### 目标

保护近期交互结构，并为旧精确内容提供有界恢复路径。

### 任务

- 定义 user-task turn grouping。
- 至少保留当前 turn、最近两个闭合 turns、未闭合 pairing、active gate、未消费 handoff。
- 大 tool/media 继续使用 durable stub，不重新内联。
- 实现 current-thread root-only `thread_history_read` 或复用当前 HEAD 已有等价 owner。
- checkpoint 记录 boundary 和 Journal sequence locator。
- 历史读取支持 query、sequence、分页、byte/token cap 和审计 receipt。

### 退出条件

- 不存在 question/answer、tool call/result 被拆断；
- 模型能按 locator 找回旧错误、代码片段和用户精确措辞；
- 默认请求不加载完整 transcript。

## Phase 4：Global Budget Allocator 与硬 10%

### 目标

完整 provider-visible input 在压缩后不超过 `EffectiveInput × 10%`。

### 任务

- 统一模型 `context/input/output` limit normalization。
- 在 exact envelope/protocol projection 上统计全部分类。
- 引入 provider-actual calibration ratio。
- 删除固定 8192 summary、25K Skill 等互不协调的独立预算；改为 global allocator 配额。
- 扩大 tool/MCP progressive disclosure。
- Skill/Memory/历史工具结果降为 refs + on-demand retrieval。
- 增加 mandatory floor、typed code `COMPACT_TARGET_UNACHIEVABLE` 和 lower-snake-case reason 分类。
- postcondition 改为 `ConservativeProjected <= CompactTarget`。
- 重试只逐级移除 supporting/retrievable 内容，不删除 critical facts。

### 退出条件

- 所有可达 fixture 压后完整请求 <= 10%；
- 不可达 fixture 返回 typed 原因和分类；
- 没有 false success；
- provider 实报高于本地估算时下一次使用校准值。

## Phase 5：Provider-native compaction adapter

状态：exact OpenAI Responses adapter、opaque identity/digest/restart、native→local fallback、prepared-body 硬 10% 门禁和 Chat/Messages/custom 负向自动化已实现。真实 OpenAI 账号调用不属于本次收口要求；重复 3/5 次本地 V2、完整重启与真实模型/协议切换仍按通用稳定性场景验收。

### 目标

在不破坏多模型 authority 的前提下，吸收 Codex 的原生 compaction 优势。

### 任务

- 为 exact provider capability 定义 `native_compaction`，默认关闭。
- OpenAI official Responses 支持路径单独实现；custom endpoint 不继承。
- opaque state 绑定 provider/profile/credential/base/protocol/model/endpoint identity。
- 同 identity 继续时可重放 opaque state；切模型/协议时丢弃 opaque state、保留 TaskCheckpoint。
- native 失败回退 provider-neutral compact，不双重提交 boundary。
- 不把 `previous_response_id` 当持久 thread authority。

### 退出条件

- local checkpoint 能重复 compact/restart；native 重复与 restart 由 mock/自动化证明合同，不要求真实 OpenAI 账号；
- 模型切换不重放不兼容 opaque state；
- Chat/Messages/custom 不收到未声明字段。

## 推荐提交边界

1. tests + bundle schema；
2. atomic install/replay；
3. typed checkpoint/coverage；
4. complete turns/history read；
5. global allocator/hard 10%；
6. provider native compaction；
7. Desktop/telemetry/docs。

每个提交必须 task-scoped staging，不得夹带当前 Plugin/MCP dirty work。
