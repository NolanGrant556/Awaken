# 工作台布局与运行展示 · 需求文档

工作台按轮次展示用户输入、运行过程和结果。布局、滚动与历史重放必须让用户能继续阅读，也能随时回到最新内容。

代码、接口和验证方法见[实现方案](实现方案.md)。

## 产品定位

Workbench 中间区域是本地 Agent 的执行叙事空间，不是普通聊天窗口，也不是原始日志查看器。它持续回答：

1. 用户这一轮要求什么；
2. Agent 正在思考、探索或执行什么；
3. 当前是否需要用户补充任务信息；
4. 本轮最终回答是什么；
5. 哪些最终交付文件可以安全打开。

原始协议帧、完整 tool result、调试 JSON、命令全文和 patch/diff 明细不应被平铺为中心主叙事。当前右侧 Inspector 接通独立的项目文件目录与文件预览工作区：项目 Markdown 源码、HTML、代码和安全纯文本支持编辑与自动保存；其中只有 Markdown 默认渲染预览。Office、PDF、图片和临时 Artifact 标签保持只读。文件工作区可以在 `WorkbenchShell` 内覆盖中间叙事，但不消费通用 reducer 详情数据，也不改变 RunStage 的 turn、滚动、overlay 或 composer ownership。完整产品边界由 [右侧栏当前支持边界](../文件浏览与评论/需求文档.md) 唯一拥有。

首页启动时，AWAKEN 品牌标识上方显示无卡片背景的中文小字“正在启动 Awaken…”，服务与 runtime info 就绪后淡出；顶栏不再重复显示英文启动文字；已有会话内使用 Composer 上方的紧凑提示。品牌字标是静态装饰，不能拖出页面或当作可移动图层。提示不参与首页品牌/输入框的几何测量，不提前解除发送禁用。需要重启时也在品牌标识上方显示无背景、无边框的中文说明“Awaken 需要重新启动，请退出后重新打开。”，替换启动文字，不在图标与输入框之间插入卡片；对话页使用 Composer 上方的同类文字提示。错误期间发送仍不可用，提示样式不能改变运行状态。完成任务的普通与文件 surface 输入框统一使用“输入后续任务…”，不暗示已完成任务仍在运行。

## 当前主形态

通用单选下拉菜单展开时，Escape 只关闭当前菜单并恢复触发按钮焦点，不同时关闭承载它的弹窗。菜单关闭后再次按 Escape，才交给外层弹窗处理；未保存的内容在第一次关闭菜单后保留。

中间区域只承认两种 composer 形态：

| 形态 | 出现条件 | 用户看到的内容 |
|---|---|---|
| `center` | 没有可见 narrative，且没有当前 run | `TaskWelcome`、运行时提示、专用 gate、居中的 composer，以及输入面下方与侧栏同步的项目作用域低栏 |
| `dock` | 已有 narrative、已有 run，或扩展文件 surface 正覆盖原 center 空态 | 会话 surface 的 `ExecutionFeed`、底部 composer、必要的 overlay；文件 surface 激活时重型叙事视图暂停挂载 |

历史线程重放仍使用 `dock`；“历史态”不是第三种 composer variant。

`shouldUseCenterComposer()` 只依据 `hasNarrative` 和 `hasRun` 判断标准场景。`hasRun` 在存在 `runId` 或 run 仍处于 `starting | running | reconnecting | cancelling` 时为真，因此编辑发送后的替换首帧即使还没有新的 `runId`，也不会掉回 center 首页。文件工作区扩展且文件 surface 激活时，Desktop 在该结果之上临时选择现有 `dock`，保证同一个输入框仍可使用；notice、error、runtime restart 提示本身不强制切换成 dock。center 输入提示为“描述任务，或 / 选择 Skill、@ 选择内置功能或插件”；dock 和文件工作区为“输入后续任务…”。

Desktop 的短暂操作反馈统一作为不参与页面布局和滚动计算的浮动 toast，定位在当前主区域顶部居中，使用 `pointer-events: none`，不进入 `ExecutionFeed`。设置页可继续由其 UI-only shell 提供同位置 toast；扩展页与 Workbench 复用 Desktop-owned 的全局反馈层，不在右下角创建第二种反馈位置。

## 用户流程

### 第一轮任务

1. 用户在 center composer 输入文本、选择附件或 Skill token。
2. 提交后，界面切换到 dock。
3. 新 prompt 立即成为一个 turn 的起点，并锚定到 RunStage 顶部。
4. 同一首个可见转换中，turn body 立即显示由 `思考中` 文字和三点节奏动效组成的透明行内状态，不等待 Core 或 provider 发出首个 reasoning/tool/text 事件。
5. runtime 发出 reasoning summary 后，同一状态行提供思考正文展开入口；正文默认收起，用户展开后继续流式更新；首个可见输出若是 tool 或 answer，则状态行直接让位给该内容，不伪造 reasoning。
6. 供应商在响应前断网或握手失败时，run 保持忙碌和思考中；执行时间继续走。Wi-Fi「正在等待网络」出现在当前已经执行到的内容后面、思考中前面，不是计时行下的固定槽；细节可展开且只有去敏英文短句。流断开则在同一游标写入「正在重新连接 n/5」，并丢掉未耐久的思考/回答正文，以及尚未执行的进行中工具行，回到思考中。同一状态只保留一行并原位更新次数，不同状态（等待网络 / 重新连接）才各占一行。恢复成功后重连行消失并继续输出。这不是 SSE `reconnecting`。历史 replay 不补造该行；同一会话切回仍在跑的 run 会保留离开前的 live 行。
7. run 忙碌期间，主按钮进入 stop 语义；不支持在同一 thread 中排队第二个 run。
8. thinking、tool、answer 等内容在同一 turn 内追加。
9. 工具结果完成且 Core 明确进入下一次模型 turn 时，最后一个工具批次下方由临时思考状态接棒；工具结果续接显示“正在分析工具结果”，继续生成和 XML fallback 使用各自确定性文案。上下文压缩开始后只显示一条带轻量三点动效的“上下文压缩中”，同一 run 内的 started、finished 与 reactive retry 共用稳定展示身份，不平铺开始/完成边界、Token 数或内部 boundary ID；收到 reasoning、answer、下一次 tool 或 run 终态后立即让位并继续原任务。临时状态延迟 650ms 出现，不把模型等待误写成工具仍在运行，也不显示虚假百分比。
10. 压缩失败仍保留 Core/AG-UI/Journal 的完整诊断，但 Renderer 的最终错误回答、timeline 和 inspector 不展示 `COMPACT_TARGET_UNACHIEVABLE`、projected/target/mandatory floor、reduction/threshold 或其它内部压缩原因，只显示通用“本次任务未能继续，请重试。”；普通 provider/auth/tool 错误继续按各自产品文案展示。
10. run 终态后 composer 恢复可输入；再次提交沿用当前 thread。

这里的“立即”是首个用户可见帧的原子语义：新 turn 第一次可见时，prompt header 已经位于 RunStage 顶部锚点。不得先在旧 final answer 或 deliverables 下方以自然 append 位置出现，再在后续帧跳转到顶部。

### 多轮任务

- 每个用户 prompt 开启一个新 turn。
- 新 turn 获取最新 prompt ownership；旧 prompt 仍属于旧 turn，不产生 feed 外副本。
- 相邻 turn 之间保持 38px 的垂直边界：`ExecutionFeed` 的 14px 基础间距之外，Desktop 只在后一 turn 增加 24px；因此前一轮 final answer 或交付物与下一轮 prompt 不会紧贴，同时不改变 turn 内部、Composer output gap 或首轮顶部布局。
- 三轮及以上时，右侧 marker rail 按可用高度显示 regular、compact 或 summary 形态。
- 点击 marker 跳到对应 prompt，并将 latest-output follow 置为用户暂停。

### 阅读运行中输出

- 用户没有表达阅读历史意图时，最新 turn 持续跟随本机滚动底部。
- 用户向历史方向滚动、触摸、在 feed 中 pointer down 或点击旧 marker 后，自动 follow 暂停。
- 只有暂停且已经离开最新内容时，才显示使用 `--aw-surface-raised` 与 `--aw-text-primary` 主题 token 的圆形向下箭头；其可访问名称为“回到最新输出”。仅暂停但仍停在最新输出附近或本机滚动底部时不显示该按钮。
- 点击按钮或明确滚回最新 tail 后恢复 follow。
- markdown 增高、tool 内容增长、窗口 resize、prompt 展开、composer 增高等被动变化不能替代用户恢复意图。
- 打开交付卡或改变右侧栏宽度时，已经暂停跟随的会话保留当前轮的可见正文位置。文件覆盖态暂时卸载正文后，返回会话仍恢复该阅读位置，不跳到第一条消息；开始新任务或切换会话后不套用旧位置。
- RunStage 叙事滚动区在滚动条两侧稳定预留等宽空间；展开执行过程、Tool 输出、媒体明细或 Prompt 后即使纵向滚动条从无到有，居中的 prompt、turn body、final 和交付物也不得横向位移。

### Prompt 气泡

- prompt 文本超过 3 行或 160 个字符时，默认折叠到 3 行等价高度。折叠溢出用约一整行的 mask 把末行字形淡出到气泡底色，不用省略号，折叠态底部内边距为 0，气泡下沿不留一整段空白。
- 单击后展开；拖选正文、token 标签或附件文件名不触发展开。展开文本最大高度为 9 行等价高度，更多内容在气泡内部滚动。
- 展开后点击气泡外部会收起。
- 可改写的普通会话在 prompt 首帧就显示「撤销、编辑、复制」操作栏；复制是与撤销/编辑相同的透明图标，不套底卡。展开态仍提供复制入口。复制内容为气泡可见输入的纯文本：附件显示名（每行一个）、再接含 Skill/文件/capability 等 token 标签的正文流。不包含 Skill 路径、Computer Use 隐藏引导或其它非可见元数据。
- 气泡内正文、token 标签与附件文件名允许鼠标局部选择与系统复制；选区穿过原子 token 时，图标、间距和 label 必须共用完整选中底色，不得在 SVG 图标位置留下白洞；侧栏与其它 chrome 仍不可选。
- 附件默认显示前三个；更多附件以 `+N` 表示，展开后显示全部。
- token、附件和文本共同属于用户原始输入，必须在历史重放中保持可见顺序。

当前 v2 耐久输入会恢复结构化附件小卡、附件顺序和 composer token。修复前已写入的旧 v2 记录只有附件数量，没有可恢复的 identity/path/token；历史重放必须忠实显示其中的文本，不得从 prompt 文字或磁盘目录猜造附件。耐久字段与恢复边界只由 [SemanticJournal 与重放](../../03_运行时与本地服务/数据存储与重放/实现方案.md) 定义。

普通 v2 会话的耐久用户消息支持撤销与原位编辑；操作栏、因果后缀失效、结构化草稿恢复、重新生成以及“不回滚文件或外部操作”的完整边界只见[用户消息撤销与编辑设计契约](../消息输入与编辑/实现方案.md)。

每个已有计时事实的 turn 在 prompt 下只显示一处“执行时间”。新提交在 `run/requested` 首帧立即从 `0 秒` 开始，运行中按秒递增；收到耐久 `RUN_STARTED` 后以服务端时间戳校准起点。最终回答出现且前面存在过程项时，这一行原位成为过程 disclosure 的标题，例如“执行时间 17 秒”加 Chevron，不再另起“执行过程”；成功终态用 final answer 的 `elapsedMs` 冻结，当前终态也可由 `runCompletedAtMs - runStartedAtMs` 冻结。没有过程项时计时仍保持普通行。计时文本自身更新，不重投影 narrative。历史重放只使用已经保存的终态耗时，不从当前时间猜造；旧历史没有耐久耗时时，disclosure 回退显示“执行过程”。final answer footer 不重复显示耗时。

### 阶段活动与工具详情

执行过程以 Agent 实际输出的进展说明串联。两段说明之间的读取、搜索、编辑、命令、技能、普通钩子和思考归入同一活动组；普通模型续接不切断活动组。没有进展说明时从本轮第一个活动建立分组。界面不生成进展结论，也不增加模型调用。

- 单个活动直接显示一行；多个活动默认显示组合摘要，例如“读取 3 个文件 · 搜索 1 次”“修改 2 个文件 · 累计 +2 −2”。运行中在摘要后显示当前活动；并行活动显示最近一项及其他进行中的数量。展开组后，由内部活动行显示状态，不重复显示组外当前活动。
- 思考正文、工具记录和阶段组均由用户按需展开。用户选择在后续输出、终态和当前 Desktop 生命周期内的会话往返中保持；没有正文的思考不提供空展开按钮，没有可靠记录不显示思考秒数。
- 已读取、已修改的文件按路径去重，搜索和命令按调用去重；只有已确认成功的工具进入完成统计。缺少文件身份时显示操作次数。修改行数是本组成功调用的累计变化，不是 Git 净差异；缺失或截断时不展示不完整的合计。
- 命令详情原位展开，优先展示命令用途与已保留的输出；长输出在详情内阅读。编辑结果以带行号、增删底色和代码文字高亮的差异展示；长差异可展开已保留部分，截断状态明确标注。覆盖写入没有修改前内容时，不补造 diff。
- 文件名与详情展开按钮是两个独立目标。文件名打开当前磁盘文件，历史输出和 diff 仍代表那次执行。文件定位范围与失败行为见[文件浏览与评论](../文件浏览与评论/需求文档.md)。MCP 的可读结果优先展示，参数和诊断按需展开。
- 异常在折叠组外保留短提示。用户问答、授权、恢复、媒体、原生子任务与 ACP 会话保持自己的入口；它们不能被成功摘要掩盖。
- 常规过程行与思考标题统一为 13px / 20px、最小 28px 行盒，正文使用 14px 和约 1.65 行高。正文到所属活动间隔 8px，相邻阶段间隔 24px；过程透明无底卡，常规完成行不保留固定图标列。子任务同样采用轻量文本摘要，详情仍进入右侧标签。
- 活动只保留轻量三点动效；展开收起为 180ms，透明度为 120ms。历史步骤一次显示，不逐行重播。减少动态效果时直接切换状态。次要文字仍使用可读的主题色。

### 执行过程折叠

当一个 turn 已出现被标记为 `isFinal` 的最终回答，并且其前面存在过程项时：

- 最终回答之前的 thinking、exploring、普通 tool、旧 approval 记录、非最终 assistant 说明和全部图片/视频生成明细归入同一个“执行过程” disclosure；媒体不能成为分段边界，成功、失败、敏感内容拦截和其后过程项都不能泄漏到结果区；上下文压缩的瞬时状态不进入终态执行过程；
- 图片/视频生成在执行中为每个请求结果建立一张独立紧凑媒体卡；生成前使用请求比例占位，媒体加载后切换为真实宽高比。final 前媒体组实时可见并按状态自动展开；final 后整组随“执行过程”默认折叠，用户展开外层过程后才能查看各次生成明细及卡片网格；
- disclosure 默认收起，可按 turn 独立展开；有计时事实时标题直接使用该 turn 唯一的“执行时间”，没有耐久耗时的旧历史才回退为“执行过程”；
- 用户展开终态“执行过程”时，已完成的 Tool、MCP、Skill 和终端轨迹在首个展开帧同时可见，不重播逐项入场延迟；入场动态只用于 final 之前实时新增的工具轨迹；
- 最终回答及其后的交付物继续平铺显示；
- 在最终回答出现前，阶段说明与活动摘要保持实时可见；活动组内部的思考、工具及详情可默认折叠，不把整轮过程提前收起；
- 如果最终回答是 turn body 第一项，则不创建空的“执行过程”。

该能力是当前已实现的产品行为，不再写成未来 work packet 计划。当前聚合单位是“最终回答前的 turn 过程”，不是任意并发工具 DAG 或跨 turn 工作包。

### 文件工作区覆盖与会话切换

- 用户在已展开右侧栏的顶栏点击紧邻 Inspector 开关、并与其落在同一水平中线的“展开面板”后，文件 surface 覆盖 Workbench 主舞台，左侧项目栏与当前 thread 保持不变；右侧栏折叠时该控制隐藏，文件标题或标签过多时只让标签带横向溢出，不能推动该控制与 Inspector 开关；
- 顶部中间显示当前会话标签，右侧显示当前项目的已有文件标签；会话标签恢复原 RunStage，文件标签恢复同一个文件预览 surface；
- 文件 surface 激活时，run/reducer 继续接收并归并事件，但重型 `ExecutionFeed` 视图暂停挂载，避免长任务叙事与 Office 预览同时占用并提交 Renderer 内存；切回会话 surface 时从当前 reducer 原子重投影，不丢 turn、过程、终态或 disclosure identity。底部仍使用当前 thread 的原 composer authority，可停止或提交；只在文件 surface 激活期间保留当前可见的输入呈现与模型选择，隐藏输入面下方的项目名和“上下文窗口”元数据；切换到会话 surface 或收起后立即恢复；
- 文件 surface 内的 composer 使用同一个五态呈现：仅当结构化草稿为空且没有专用面板时，对文档预览非交互区完成一次未越过拖选阈值的主键单击才收为短横线；运行中也遵守同一缩小规则。正文拖选、预览工具按钮、已有正文、token 或附件都不得触发收起。第一次点击横线显示紧凑入口，再次点击恢复完整输入面；提交后收为“正在执行”胶囊，停止只能点独立停止按钮，点胶囊本身只展开输入面。成功终止后显示含耗时的“已完成”状态，点击后回到完整输入面；
- 五态只是 Desktop 对现有 `dock` ComposerBar 的呈现控制，不新增第三种 composer variant；非完整态只保留横线/紧凑/执行/完成呈现，不挂载背后的完整 ComposerBar。草稿、token、附件、Slash 与模型选择由 `App.tsx` / thread draft authority 持有，恢复完整态时重新投影且不得丢失；“已完成”只属于最近一次从当前扩展文件 composer 明确提交并已结束的 run，历史 thread 的 finished replay、进入文件 surface 前已经完成的 run 或其他 thread 的终态不得投影为该完成入口；专用问答、外部授权或 runtime 异常面板出现时强制保持完整态；
- 从已有会话换到另一会话时，不把上一会话的右侧栏展开带到新会话；未展开过的会话保持收起。返回原会话时恢复该会话自己的右侧栏；去左侧功能页再回来也不改当前会话的展开。新任务首次获得会话身份不因此收起；
- 切换 surface 不重建 Office、PDF 等查看器，不清空目录展开、筛选、文件标签或内部列表宽度；
- 收起扩展后恢复普通中间会话加 720px 文件工作区分栏。其余文件能力与验收只见 [右侧栏当前支持边界](../文件浏览与评论/需求文档.md)。

## 当前 narrative 表达

中心区域当前可见的主要内容：

- prompt；
- thinking；
- read-only exploration group；
- tool trace；
- 图片/视频生成的加载、排队、生成、载入、就绪、失败或取消卡；
- Memory recall/mutation 与 Dream terminal 的紧凑回执；
- 仅 live 压缩期间出现的一条“上下文压缩中”动态状态；
- legacy approval 的只读轨迹；
- final answer；
- cancelled hint；
- ready deliverables。

已完成的 final answer 底部操作区固定在回答正文之后，只在右侧显示无底卡的复制图标；悬停或聚焦不显示 Tooltip、原生 title 或其它可见文字，只保留颜色、焦点轮廓和纯图标复制成功/失败反馈，无障碍名称继续存在。该按钮只复制最终回答 Markdown。执行时间位于 turn 顶部，终态有过程项时同时承担过程 disclosure 标题。流式回答、错误回答和非最终 answer 不显示该操作区。

## 专用用户 gate

当前仍允许出现在 composer stack 的用户 gate 只有专用产品流程：

- `ask_user` / 主动提问；
- 通用 `ExternalActionGate`（首个使用者为官方 CLI 授权）；
- 兼容期内 Main 内存 CLI auth session 的紧凑投影；
- runtime 启动、崩溃或 run error 的状态面板。

`ask_user` 出现时作为专用 gate 位于既有 `composer-dock-stack`，普通 ComposerBar 固定保留在 gate 下方，不卸载、不隐藏，也不转移 draft authority。运行仍为 busy 时输入面保持现有禁用/停止态，不能借保留输入框并发提交第二条用户消息；面板保留当前单题/多题分页、单选/多选、“其他”文本和统一提交逻辑。面板的关闭图标与“取消”只取消本次回答，通过独立 question-cancel bridge 把 `resolution=cancelled` 回传模型并继续当前 run；主 Stop 仍是唯一取消 run 的入口。gate 出现、回答或问题取消只改变 stack 实测高度，不新增 modal、overlay、第二个输入系统或第三种 composer variant。

长问题和选项在同一个有界区域滚动，保留换行并允许长路径换行；完整问题不能被标题栏裁切。翻页、关闭和提交按钮保持可见，正文支持键盘滚动。切换题目回到该题顶部，已选答案保留。

`ExternalActionGate` 由当前 run 的 `interaction_required` 等待驱动，放入既有 `composer-dock-stack`。它展示安全 HTTPS 链接、受控二维码占位、说明与完成/取消/重试；二维码容器固定尺寸，加载、过期和失败在原位替换。出现与移除不得破坏草稿、焦点、follow/paused、marker 或 return-to-latest，也不得改变 turn identity。它不进入 ExecutionFeed、narrative step、transcript 或历史 replay；页面往返后仅当前活跃 run 的 gate 仍可见，其他会话不显示。迟到的 completed/cancelled 不得恢复已终态 run。

连接器页「+」只安装 CLI；安装完成后的「发起登录」通过 product-action handoff 进入普通新会话并自动提交受控 Agent 登录指令；授权交互不在连接器卡片内嵌完整二维码，也不提供“选择 CLI”文件选择器。

这些 gate 可以使 dock 高度变化，但必须由 composer stack 承载并进入统一高度测量。它们不得复用旧通用 approval endpoint、旧 `ApprovalCard` 或 `awaiting_approval` 恢复语义。

Computer session 常态状态不作为 gate 放在输入框上方，也不属于 RunStage。模型在一个 run 中第一次执行 `computer_observe`、`computer_act` 或 `computer_verify` 时，Electron Main 在当前屏幕工作区顶部居中显示独立的系统级置顶深色胶囊悬浮条，透明窗口画布不得显示额外的矩形边框或被裁切的外投影；胶囊包含简短“Awaken 正在操作您的计算机”状态和唯一的停止按钮。同一阶段另有一枚黑底白边、始终点击穿透的虚拟鼠标，与用户系统光标分开，随 `AWAKEN_COMPUTER_POINTER_HINT` 移动到指针坐标或 accessibility 控件中心；handoff 时隐藏虚拟鼠标。后续 Computer 调用及其间的模型推理阶段保持连续显示，直到 Computer session 关闭、run 进入终态或事件流关闭后自动隐藏。单次工具的参数流或 result 不能证明它是最后一次 Computer 调用，因此不得使提示闪退。停止动作只通过 Main 的专用控制链中断并终止当前 run 的 Computer Use，禁止该 run 自动重开 Computer session；它不得取消 run 或停止模型回答，也不依赖当前 Awaken Renderer、选中 thread 或 RunStage 是否可见。暂停、接管等内部控制语义不在常态条上扩展为多个按钮。需要用户处理的 review/handoff 仍使用专用 gate。

- 项目筛选当前未实现；侧栏当前提供的是全部展开/收起，不是筛选。见 [项目与对话导航](../项目管理/实现方案.md)。
- Context picker 未实现。
- 不存在第三种 composer variant。
- 不提供通用工具审批恢复。
- execution-process disclosure 不是完整 tool DAG、并发时间线或虚拟列表。

## 异常与恢复

| 场景 | 当前用户行为 |
|---|---|
| Desktop runtime starting/stopped/stopping | composer stack 显示启动中，提交不可用 |
| runtime crashed | 显示“Awaken 需要重新启动”，需要按正式入口重启 |
| run create 失败 | 恢复提交前输入，错误只投影到当前 turn 的对话流，不在 Composer 上方重复显示错误卡片 |
| 上下文压缩失败 | 当前 turn 只显示通用失败文案；内部 reason、预算与 floor 只留在 Core/AG-UI/Journal，不进入对话正文、timeline、inspector 或上下文面板 |
| SSE 非终态中断 | Desktop 订阅持续重连，phase 可进 `reconnecting`，不提交普通失败回答，已有思考/回答保留 |
| SSE `run_not_found` | 进入 terminal error，错误只在当前 turn 对话流显示，并保留已就绪交付物 |
| Provider 等待网络 / 流重试 | 保持 running 与思考中；当前已执行内容之后、思考中之前显示 live「正在等待网络」或「正在重新连接 n/5」；同一状态原位更新，不同状态各一行；未耐久正文和尚未执行的工具行可被 reset 丢掉；恢复后或模型继续输出后重连行消失。历史 replay 不补造；同一会话切回仍 running 时保留离开前的 live 行 |
| 用户取消 | 保留已生成回答片段，追加取消提示；ready deliverables 仍可见 |
| 历史 legacy approval | 只读展示，不可恢复 |
| 旧 context record 无分类 | 先以当前可运行 profile 重建并 flush v4；无法重建时保留已有汇总并显示“暂无分类明细”，不猜测分类或 provider usage |
| CLI 授权过期/失败 | gate 原位显示稳定安全提示与 retry/cancel；不输出原始 CLI 内容 |
| 文件打开失败 | 显示稳定领域错误；不绕过安全反查 |

## 子任务的持续活动

点击子任务行在右侧标签页查看该次分配的模型、思考强度、上下文、用量、计划、执行过程与结果；没有子任务输入框、追加、继续或关闭 Agent 的入口。用户只与主 Agent 交谈，子任务缺少信息时交回主 Agent。运行中的子任务可停止，中间区域 subagent 面板右侧可停止全部子任务，不停止主 Agent；这次用户停止会交给主 Agent。关闭标签只关闭视图。主回复须等待子任务汇总后完成；点击输入框停止运行才同时取消本次主执行和所有后代，清理期间显示正在停止，面板正文独立滚动，不再覆盖中心叙事或 Composer。文件标签与主草稿在切换时保留。

子任务完成、失败、取消或中断后，自己的“思考中”、等待与工具活动动画立即结束，已收到的思考正文仍可展开查看，错误说明保留。停止动画不表示工具执行成功；未收到结果的工具显示停止或中断。切换标签、恢复历史或收到迟到的流式片段不能重新播放已终止任务的动画，也不能停止其他仍在运行的任务。

## 停止文案与提问键盘行为

| 宿主证据 | 展示 |
| --- | --- |
| 用户主动停止 | 你停止了本次运行 |
| 主 Agent 停止子任务 | 主任务已停止此子任务 |
| 应用退出 | 应用关闭，运行已中断 |
| 超时 | 本次运行已超时 |
| 模型流断开且重试耗尽 | 模型连接中断，本次运行未能继续 |
| 来源缺失或未知 | 本次运行已中断 |

Stop 发出后问题卡立即只读，显示“正在停止，问题已撤回”，仍可阅读全部原问题；终态后移出 Composer，工具历史显示“问题已撤回”。不保留答案草稿。Escape 等同取消本次回答，输入法组合输入期间不触发，内层菜单先消费。

关闭问题后，仅在原会话、原问题拥有焦点且窗口仍活动时恢复焦点。可输入时恢复 Composer 原光标；仍 busy 时只聚焦 Composer 容器，输入保持禁用。问题卡改变只影响现有 stack 高度，不能改变草稿、跟随滚动或会话身份。
