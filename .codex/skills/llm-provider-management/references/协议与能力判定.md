## 1. 三协议不是三个名称别名

| 协议 | 最小请求语义 | 工具调用 | 推理内容 | usage 常见字段 |
| --- | --- | --- | --- | --- |
| OpenAI Chat Completions | `messages[]`，`POST /chat/completions` | `tools` + `tool_calls` | `reasoning_content`、扩展字段或无 | `prompt_tokens`、`completion_tokens`、`prompt_tokens_details.cached_tokens` |
| OpenAI Responses | `input[]`，`POST /responses` | typed output items + function call/output | reasoning output items/summary | `input_tokens`、`output_tokens`、`input_tokens_details.cached_tokens` |
| Anthropic Messages | content blocks，`POST /v1/messages` 或兼容路径 | `tool_use` / `tool_result` blocks | `thinking` block + signature | `input_tokens`、`output_tokens`、`cache_read_input_tokens`、`cache_creation_input_tokens` |

“兼容 OpenAI”通常只说明某一 endpoint/shape，不自动包含 Chat 和 Responses。支持 Messages 也不代表兼容 Anthropic 全部 beta header、Files、Batch 或 Admin API。

## 2. 判定协议支持

只有同时满足以下条件才把协议写成 Awaken 当前支持：

1. 供应商当前官方文档明确给出 endpoint、鉴权和请求/响应合同；
2. Awaken provider catalog 对该入口公开该协议；
3. 对应 adapter 能 lower system、history、tools、media、reasoning、usage；
4. 有聚焦自动化，必要时有真实 endpoint/Desktop 证据；
5. 套餐条款允许 Awaken 这一用法。

某一项缺失时分别写“官方支持但 Awaken 未接入”或“Awaken 声明但官方未确认”，不要写成绿色兼容。

## 3. Provider route 与 adapter 分层

Provider route 只拥有：

- Base URL、region、auth scheme、key scope；
- protocol 可选项；
- model/catalog endpoint；
- API、Coding Plan、Token Plan、Agent Plan 分类。

Protocol adapter 只拥有：

- endpoint path；
- request body 和 stream lowering；
- tool/media/reasoning block 转换；
- error 和 usage 归一化。

模型 capability 只拥有 exact model 在 exact protocol 上的窗口、多模态、tools、cache、thinking 和 effort。不要因为修改方便而把私有字段无条件塞进通用 adapter。

## 4. 上下文与 Responses 状态

Awaken 当前由本地 durable transcript 重放历史。Responses adapter 固定 `store:false`，未把 `previous_response_id` 作为 thread authority。供应商支持服务端 state、conversation、compaction，不等于 Awaken 当前使用这些能力。

评审 Responses 更新时检查：

- 是否改变 `store:false` 和数据保留边界；
- 是否引入 provider state 与本地 transcript 的双 authority；
- tool call/result 能否跨 response 正确关联；
- compact、重试、重启和 fork 如何恢复；
- prompt cache identity 是否因状态策略改变。

## 5. 提示词缓存

### 模式

- **automatic prefix**：服务端按相同前缀自动命中，客户端不发私有字段。
- **affinity**：客户端发送稳定 `prompt_cache_key` 或等价字段，帮助路由同一前缀。
- **explicit breakpoint**：请求 content/system block 带 `cache_control`。
- **undocumented/probe**：只能解析响应观察值，不声称存在稳定合同。

### 必须记录

- exact provider/base/protocol/model；
- 最小可缓存 token、TTL 与续期方式；
- 请求字段和可放置位置；
- cached/read/write/uncached usage 口径；
- system/tools/images/thinking/effort 改变时是否失效；
- 流式 usage 是否需要额外开关。

缓存命中 token 是输入 token 的子集时，不得再与总输入相加。Messages 的 cache read、cache creation 和 non-cached input 应按官方口径拆分。

## 6. Thinking 开关与 reasoning effort

把以下三件事独立建模：

1. **是否允许 thinking**：如 `thinking.type=enabled|disabled|adaptive`、`enable_thinking`。
2. **推理强度**：如 `reasoning_effort=low|medium|high|xhigh|max` 或 `output_config.effort`。
3. **是否返回/如何返回推理内容**：如 split 字段、content block、signature。

Awaken UI 内部档位是 `low | high | max`。供应商原生标签由 exact model capability 映射；不能把缺少档位参数的模型伪造成三档。标题、压缩、Memory 等辅助请求可按 request policy 禁用或收窄 reasoning，但必须以供应商确切开关合同为前提。`DisableReasoning` 是逻辑意图：有关思考合同时发线字段，Messages 以省略 thinking 块为 off，没有合同时只能走已公布的最低 effort 或保持不发送私有字段；省略 Responses `reasoning` 不能写成已经关闭思考。

## 7. 多模态与 Read

判定顺序：

```text
文件类型 -> Read route -> exact profile capability -> protocol lowering -> provider limits
```

- 图片支持要核对 MIME、URL/base64、大小、数量和当前协议 content shape。
- 原生 PDF 支持必须有 file/document block 合同；只有图片输入时走页面渲染回退。
- 供应商原生 SDK 支持视频，不代表 OpenAI-compatible Chat endpoint 支持视频。
- 工具结果中的媒体和 Composer attachment 都要经过同样的 capability gate。

## 8. 用量、余额、成本和套餐

分别维护：

- **per-request usage**：随推理响应返回，进入 Awaken usage journal；
- **余额**：账户剩余金额/额度的管理 endpoint；
- **组织用量/成本**：通常需要管理 key，权限高于推理 key；
- **速率限制**：RPM/TPM/并发、响应 Header 和 `Retry-After`；
- **套餐额度**：按周期、席位、模型系数或工具范围消费，通常不能按 token 单价直接换算。

价格和套餐是高频变化信息。供应商文件只保存官方入口、计费单位和 Awaken 的换算边界；确需数字时注明币种、区域、模型、服务层级、生效日期和来源。

## 9. 更新证据优先级

1. 官方 API reference / model page / pricing / plan terms；
2. 当前代码与正式文档；
3. 本次自动化和真实 endpoint/Desktop 证据；
4. SDK 源码或 changelog；
5. 社区文章只能帮助定位，不能建立正式合同。

官方页面失效或互相冲突时保留旧结论为“待复核”，记录日期与 URL，不用搜索摘要替代正文。

### 模型资料的持续更新规则

模型会持续发布、改名、下线，同一服务别名也可能升级背后的模型。模型 ID、可用协议、推理档位、上下文上限、价格和套餐权限，以使用时对应产品、区域、套餐的实际官方文档为准；不要把本文或供应商资料里的例子当成永久清单。

- **供应商当前提供什么**：从供应商资料中的官方模型总览、API reference、更新公告或相应 Models API 核对。页面迁移时优先从官方索引重新定位；文档与实测冲突时保留差异，不能单靠旧资料判定不支持，也不能绕过接口实际限制。
- **Awaken 当前接入什么**：读取 [Desktop provider catalog](../../../../apps/desktop/src/main/model-profile-store.ts)、[Desktop 能力表](../../../../apps/desktop/src/main/model-capabilities.ts)、[Core registry](../../../../src/modelprofile/registry.go) 和对应 adapter/test。供应商新增能力不会因这一条说明自动进入 Awaken。
- **默认模型不重复抄写**：资料不维护一份与代码相同的默认模型列表。需要当前值时，从仓库根运行 `python3 .codex/skills/llm-provider-management/scripts/check_provider_docs.py --list-defaults`，直接读取当前 checkout。该输出表示代码默认值，不代表官方最新推荐，也不替代用户已保存的会话选择。
- **按实际变化维护**：仅默认模型名称变化，不要求挨份补写资料。新增或改变协议、鉴权、参数映射、能力限制、恢复策略时，仍须同步代码、测试及对应正式文档；对照精确模型与协议验证。保持用户原有配置和会话选择，不因发现新模型静默切换。
- **复核日期有范围**：旧日期只表示当时检查过的范围。仅调整链接或维护规则不刷新整份资料的复核日期；局部事实更新注明局部范围，未复核的价格、用量、套餐与协议不能写成已更新。

资料校验检查目录、provider ID、章节、官方资料入口和本规则引用，不再要求每个默认模型名出现在正文，也不依赖联网结果判断构建是否通过。可变外部事实应在实际接入任务中复核，不制造定期手工抄写清单的工作。
