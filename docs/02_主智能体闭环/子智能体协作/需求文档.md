# 子智能体协作 · 需求文档

主智能体可以把独立任务交给普通 Agent 或明确受限的角色，继续同一 Agent 的上下文。subagent 是本次主任务内部的并行执行单元，不能脱离主任务独立运行。用户只与主 Agent 交谈。点击工作台子任务分组中的一行，会在右侧标签页打开该次分配的执行面板，查看模型、思考强度、当前上下文、工具与用量、计划、过程、结果和错误。子任务面板没有输入框、追加或继续入口。

实现与验证方法见[实现方案](实现方案.md)。这里的能力以当前实现为范围；真实 Desktop 验收只覆盖实施方案中实际记录的场景，不能由自动化或旧截图推导其他平台已通过。

## 身份与范围

- 一个会话拥有一个协作组，包含主 Agent 和全部后代。切换工作台会话不会停止正在执行的主任务及其子任务。
- Agent 身份对应持续的上下文。一次分配产生新的任务身份，一次实际执行另有执行身份；继续任务不会新建用户会话，也不会冒充主 Agent 的用户消息。
- 普通角色默认是 general，可以使用权限范围内的通用工具、计划、历史和递归协作。explore、plan、review 以及插件声明的限制仍然生效。
- 默认同时推进 8 个 Agent，包含主 Agent；最多排队 128 个任务，递归深度最多 8 层。完成任务的历史身份不占执行位，也不再限制一个会话只能创建 8 个任务。
- 每个 Agent 默认最多 256 个模型轮次、1024 次工具执行。继续同一 Agent 不会偷偷重置已使用预算。explore、plan、review 以及插件声明的限制仍然生效。深度研究的调研员默认走普通 general，不再另设研究专用短预算。

执行位、模型请求位、工具资源和历史身份分别管理。等待子任务或用户答复时，由宿主等待通知；模型不会为了查询进度反复生成回答。

## 分配任务和选择模型

普通任务可以省略角色；代码修改使用 general。只读角色不能因任务提示词要求而获得写权限。

子任务默认继承宿主解析的模型与本次实际思考强度。需要明确指定时，先查询可运行配置，再使用精确配置 ID 与该模型支持的档位。未配置、已删除、缺少凭据、不支持的档位或有歧义的名称都应明确失败。模型不能提供任意 endpoint、协议或密钥。

上下文方式有三种：

| 方式 | 子 Agent 得到什么 |
| --- | --- |
| fresh | 新任务内容和当前有效的规则、工具、权限；不复制父任务对话 |
| full | 工具结果已经配对闭合的父语义历史、有效压缩检查点和有界历史引用 |
| recent | 最近 N 个已闭合用户任务及其结果，同时保留更早和当前仍有效的用户约束 |

fork 是创建新的 Agent。复制内容不会继承父 Agent 的运行对象、用量、未完成工具、待答问题或供应商 opaque 状态。子 Agent 的下一请求按自己的模型窗口检查。

## 主 Agent 调度与停止

主 Agent 向运行中的子 Agent 发送指令后，宿主先保存消息，再在下一模型轮次边界放入其上下文。正在执行的工具不会被插入的消息打断。已接收、已进入模型请求、已完成上下文提交是不同阶段；中断恢复不能把仅已接收的消息当作已经处理。

主 Agent 继续空闲子 Agent 时创建新任务，恢复同一 Agent 的历史和计划上下文。模型、角色、权限和工作区必须重新校验。角色或工作区已变化时要求新建 Agent；保留的 worktree 还须属于同一仓库与原分支。

任务完成和停止遵守以下规则：

- 主 Agent 正常完成前，必须等子任务完成并整合结果；后代任务递归遵守同一规则。
- 点击“停止运行”同时取消本次主执行、所有后代和排队任务，禁止派生或续派新执行。
- 停止请求封住执行入口后，仍在排队的任务不能趁其他任务退出、执行位释放而启动；取消信号尚未传播到该任务时也遵守此规则。
- 停止一个子任务取消该次执行，保留 Agent 供之后明确继续。宿主把这次取消写入主 Agent 上下文。
- 中间区域 subagent 面板右侧的“停止全部任务”只取消该会话内所有活动子任务和排队子任务，不停止主 Agent，也不封住主 Agent 继续派发。宿主把这次用户停止写入主 Agent 上下文；迟到结果不会恢复这些子任务。主 Agent 仍须整合这次停止并决定下一步。
- 关闭 Agent 后不能再追加或继续，释放其驻留上下文。关闭右侧标签或折叠右栏只关闭视图。关闭 Agent 由主 Agent 调用内部协作工具完成，用户面板不提供该动作。

停止请求发出后显示“正在停止”；执行、工具进程与资源清理实际完成后才进入终态。超时仍未退出时继续显示正在停止，不能把仍活着的执行标成已停止或已中断。此时不能开始同一会话的新一轮执行。当前停止是取消，不是可以原地恢复的暂停；用户后续要求继续时，由新一轮主 Agent 明确续派并恢复已保存上下文。

等待子任务、等待用户答复以及暂时让出桌面资源仍属于任务进行中，不触发整棵任务树的停止。全部指定子任务已结束时，重复等待应立即得到结束状态，不因结果已读过而卡住。等待前主 Agent 已生成的分析保留在子结果之前，供后续汇总使用。fork Skill 完成后，同一主任务仍能继续派发普通子任务，并继续受原停止规则约束。

## 文件、工具和交互

共享工作区中的不同文件可以并行处理。Write/Edit 等类型化文件工具使用文件级锁和读取版本检查，同一文件冲突要求重读后协调。Bash 的包管理、Git 索引和整仓命令仍需明确分工，不能把这种约定说成对任意 Bash 写入的技术限制。

git_worktree 由宿主创建和校验；继续使用原 worktree，不自动合并，也不丢弃已有改动。非 Git 工作区请求 worktree 时明确失败。保留路径、分支、提交和 dirty 信息供检查。变更文件名须保留空格、中文及其他合法字符；无法可靠读取 Git 状态时保留目录并提示检查，不按干净目录清理。

Computer 使用独立绑定与现有设备租约，同一桌面只能由一个控制者操作。子任务等待资源时可取消；父 Agent 等待依赖任务前释放已闲置的 Computer 会话。操作权限、复核、接管和未知结果仍遵守[桌面观察与操作](../../10_计算机操作能力/桌面观察与操作/需求文档.md)。

子 Agent 不直接向用户提问。缺少必要信息时，它把具体缺口作为结果交回父 Agent，由主 Agent 与用户确认后再续派。停止子任务不会替用户回答问题。MCP、ACP 授权与 Computer 安全复核仍使用各自专用控件，不能借移除对话入口绕过授权。

## 结果、上下文与恢复

每个 Agent 的对话、计划、压缩、epoch 和模型用量独立。详情中的累计 token 不表示当前窗口占用；未获得供应商用量时不能虚构数值。

子任务正文不直接并入主对话。父 Agent 只通过结果交接或明确的历史授权读取所需内容；fork 的父历史引用截至创建时的序号，不能访问兄弟任务或之后的新消息。

Core 重启时，未结束的执行记录为 interrupted，不自动重跑模型、研究或工具。主 Agent 收到用户后续要求、明确续派普通 Agent 后才恢复历史。深度研究 run 本身不借普通 followup 自动重开；该 run 内部的调研员续派走普通协作。Skill 等专用宿主流程仍由原宿主控制阶段。副作用结果未知时先读回事实，不能通过换 Agent 或重发任务规避幂等规则。

归档、回退、删除和项目清理必须考虑后台任务及尚未退出的写入者。正在停止且执行尚未退出时，仍然不能回收其数据。

## 工作台布局

中心叙事的分组标题为 `subagent`。每项只用一行显示名称和状态，例如“进行中”“完成”；长名称截断，状态保持可见。列表不显示角色类型、结果摘要、工具次数、token、耗时或汇总计数。子任务的思考、工具和结果仍进入自己的右侧详情，点击、运行与恢复逻辑不变。打开详情不增加主对话高度，不改变主输入框、锚点或跟随状态。

子任务详情只在右侧标签页显示。重复点击同一次分配复用已有标签；同一 Agent 的不同分配按原任务身份分别查看，失败记录不因后来成功而被替换。关闭活动标签选择相邻标签，关闭最后一个后回到文件工作区或右栏入口。切换会话清除子任务标签，不把上一会话的右侧栏展开带到新会话；返回原会话时恢复该会话自己的右侧栏。折叠右栏本身仍保留标签。

面板正文独立滚动，标题和统计适应侧栏宽度；不再有中心子任务浮层或右栏任务列表表单。右栏服从既有窄窗口折叠和用户宽度设置；窄窗口再次打开子任务时采用分栏，不能覆盖主输入框的发送和停止按钮。切换文件与子任务保留文件标签、预览、目录状态及主输入框草稿。运行中的任务仍有停止按钮，中间区域 subagent 面板右侧可停止全部子任务；这些动作不发送用户对话，也不继续或关闭 Agent。停止全部子任务由宿主写入主 Agent 上下文。该按钮不放在右侧栏开关旁边，右侧栏关闭时也不能与顶栏按钮重叠。

## 验收标准

需要验证身份保持、模型与强度一致、递归共享容量、等待不轮询、两种 fork、独立压缩、主 Agent 消息恢复、主任务等待全部子任务收尾、主 Agent 统一提问、独立停止、主 Agent 关闭与冷启动续派以及共享文件冲突。自动化检查失败恢复、持久化顺序和串扰；真实 Desktop 检查入口、可操作状态、滚动、正文、控制效果和重启读回。研究的验收仍由[研究报告](../../16_深度研究/研究报告/需求文档.md)负责。
