# 验收

## 1. 自动化

- run 固定 environment/tool availability snapshot，RequestBuilder 与 ToolRuntime 同源；
- registry/PATH 变化不替换当前 run 已固定的 tool schema、runtime/provider identity 和 environment snapshot；MCP adapter 的 live connection/auth state 仍立即改变当前调用结果，model-facing `skill` 调用也按当时 registry 重查定义/正文；
- composer token 校验、inline context、真实 fork child 和 model-facing `skill`；StartRun 到最终 provider request 的合同必须确认当前选择的 Skill ID/source/mode/absolute root/SKILL.md 作为 host-owned block 进入上下文，single/multi/token-only/fork/历史/model-invoked 语义不混同；
- 含 Skill token 的完整 `user_message` 先于预激活耐久化，激活失败保留输入且不写部分/伪 activation，成功执行不重复写入；
- Skill 不改变父 tool snapshot；
- host-owned Memory policy/index/recall block 在请求中保持数据与指令边界，selector 最多 5 条且失败不阻塞主 run，compact 后预算按 11 域复位；原生 child 只继承父已召回的冻结 snapshot，不跑 user-scope selector；
- context estimate/compact、Skill 单包 5k/总计 25k budget、最新 5-of-6 保留、恢复时间顺序和截断块精确 `Read` 源路径提示（`TestCompactInvokedSkillContextEnforcesBudgetsAndKeepsNewest`），以及 tool media storage key、restart 恢复/fork 隔离；
- 低窗口下一批多个媒体 `Read` 只执行剩余预算装得下的前缀，其余合成 `context_admission_exhausted` 且 pairing 仍合法（`TestExecuteToolCallsAdmitsOnlyFittingMediaReads`）；文本 `Read` 不被该入场门拦截；
- 请求投影按当前窗口重算：11 张旧图 + 1 张近尾时本地账仍计媒体，provider clone 只 hydrate 近尾；摘要请求无 image/file payload；14×10 图的超限 tail 被吸收后不再带齐 `DataBase64`；journal replay 只恢复 `storage_key`，重启投影与 live 一致；
- compact 后置条件：摘要成功但重建投影仍高于 auto/block 或未缩 20% 时失败且不切 epoch；三次同类失败才 circuit + `CONTEXT_BLOCKED`；`errors.Is(blocked)` 时 `isPromptTooLongError` 为 false；
- 默认 system prompt 必须把同一任务内已恢复的前序 user/assistant/tool 消息声明为连续历史；“上一个对话”等指代默认落到当前任务最近相关轮次，同时保持供应商 messages 为标准有序 role/content，不下发内部 thread/run/session、时间戳或 message/turn identity；
- `ContextUsageSnapshot` 六项分类和等于总估算、Memory/Skill 不重复、old record 不补造；provider total/input/output 不覆盖 Core local snapshot；identity 一致的完整主调用 inclusive input 直接驱动 Desktop 当前总输入并与面板输入 Token 相等，provider total/input 与 `sent_estimated_input_tokens` 另驱动 Core 保守阈值；正残差单列“其他/协议开销”，分类显示 reconciliation 后仍与汇总严格相等；缓存与 token/cost 明细紧接分类且没有“上次请求”分界；0 值分类不绘制进度 segment 时，后续 segment 与图例仍按分类语义同色；
- prepare-once exact body、`model_request` fsync-before-send、同 request ID terminal usage、orphan `usage_unknown`、purpose/retry/auxiliary fallback 与 live/replay 聚合；
- DeepSeek/Kimi/火山/custom capability、affinity/credential revision、nullable cached usage、Context Epoch/compact 边界、Kimi provider-opaque state 和大 tool result 首次 admission offload；
- ordinary auto、ask_user、needs_auth/runtime/unsupported，以及消息工具不产生审核 gate；
- cancellation、orphan recovery、partial/unknown retry block 和唯一 terminal；Bash `command+cwd` resource revision 不合并不同恢复命令，已观测 mutation 或成功的 Bash 恢复命令后可重跑验证命令，side effects=none 的无关只读成功不清理失败历史；
- live/replay 相同 semantic projection。
- 原生 Subagent 的 tool/model facts 先耐久，`subagent_progress` 再按 tool-call/model-request ID 去重累计；terminal、live/replay 与 Desktop 的工具数、provider-reported token、耗时一致；`wait` 到期返回中性 `retrieval_status=timeout` 与当前 snapshots，不产生失败 Outcome或取消 child；随后耐久的 terminal 在 root 下一模型边界自动交接，且与成功 wait/terminal status 共用一次性消费标记。

## 2. Desktop 验收

按 README 正式入口在真实 Desktop 验证：普通工具回合、多个同类 Skill 下的 composer 当前选择指代、inline/fork Skill、成功/失败压缩、上下文中文面板、主动提问、消息工具直接执行、provider failure、Shell 恢复、取消、切换线程和重开恢复。上下文能力执行 [AC-CU-01～07](提示词缓存与成本治理.md)，并检查 journal/最终 prepared request/wire 与屏幕顺序；旧截图、Gallery、浏览器 renderer 或直接 provider API 不替代本次证据。

低窗口媒体压测必须在真实 Desktop 上作为两个独立样本分别走：MiniMax 与自定义 API。每个样本一次请求多份长 PDF（或等价多页媒体 `Read`），并核对：

- 不得再出现「约 19.5K 一次跳到约 30 万，且多次 `compact_succeeded` 后用量继续上涨」；
- 要么入场门截住后续媒体 `Read`（合成 `context_admission_exhausted`，不切 epoch），要么一次压缩后保守投影落到 auto 线以下并能继续追问；
- 真失败保留旧 epoch，重启后可续（AC-CU-07）；`CONTEXT_BLOCKED` 不得再触发 reactive compact。

正式入口是 macOS `npm run open:desktop`。Linux Cloud / 无 `Electron.app` 的环境不能用 Core-only、Gallery 或浏览器页面代替该基线。
