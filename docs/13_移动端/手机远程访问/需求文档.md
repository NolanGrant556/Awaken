## Awaken 目标产品

手机端定位为“离开电脑时查看、继续和处理 Awaken 任务的原生控制端”，不是手机上的第二个 Agent runtime、完整桌面镜像、云 IDE 或任意远程桌面。

产品不变量，具体规则见[实现方案](实现方案.md)。

## 功能范围

### V1 当前目标

图片附件的远程上传不能让 relay 直接得到本机可写路径。建议采用短生命周期、按 thread/request 绑定的加密对象或经 Gateway 流式转发；Desktop/Core 校验 MIME、大小、digest 和归属后才把它登记为 attachment。

### V1.1 候选

- 项目文件树只读浏览、文本/Markdown/图片/PDF 安全预览；
- 文件变更摘要与 diff；
- Office Artifact 下载并交给手机系统应用打开；
- 定时任务列表、启停、立即执行、取消和历史；
- Memory/Dream 只读状态和手动 Dream 入口；
- 语音转文字；
- 多 Desktop 切换；
- iPad/Android 平板布局。

文件能力必须复用 Desktop 右侧栏的窄边界思想：手机只提交 opaque project/folder/file identity 或绑定根内相对路径，Main/Core 每次重新核对项目 membership、lexical/realpath containment、symlink 和大小。Agent 可以读任意绝对路径的当前能力绝不能传递给远程文件浏览器。

## 前置条件

### 必须先完成的产品决策

- 确认 Awaken 从“Desktop 唯一产品面”扩展为“Desktop 是执行主机，Mobile 是辅助产品面”；
- 确认账号模式：Awaken 托管账号、企业 OIDC/自托管账号，或二者兼容；
- 确认 relay 是否由官方托管，同时必须提供何种自托管发行物；
- 确认离线摘要、通知内容、日志、区域和数据保留政策；
- 确认 V1 平台顺序，建议 iOS first、Android 兼容检查要求并行；
- 确认远程 prompt 具有当前 unrestricted Bash 能力的风险是否可接受；若不可接受，先设计 Core-owned remote execution profile。

### 必须先具备的工程能力

- 账号、设备注册、Desktop 本地配对确认、撤权和 credential rotation；
- 可自托管 Identity/Relay 服务及生产 TLS、域名、数据库/Redis、监控、备份、升级和灾备；
- Electron Main Mobile Gateway 与版本化 capability registry；
- 移动专用 wire schema、协议版本、错误码、frame limits、幂等 request ledger；
- Core/Main 可查询远程 request 的最终结果，解决 mutation 超时后的不确定性；
- AG-UI mobile projection 的字段净化、transcript snapshot/cursor 恢复和跨版本 fixture；
- Artifact/附件的 opaque handle、短生命授权、大小/digest/MIME 校验；
- APNs、FCM；面向中国 Android 分发时还需决定厂商推送或明确无后台通知；
- Apple/Google 开发者账号、签名、隐私清单、商店审核材料、账号删除与数据导出/删除流程；
- Keychain/Keystore、证书固定策略评估、root/jailbreak 风险口径；
- 移动日志脱敏、crash reporting、远程 kill switch 和最低版本强制升级；
- Expo/React Native 构建、真机矩阵、Maestro/Detox 类 E2E、视觉基线和无障碍检查要求。

### 需要先补齐的 Awaken 当前缺口

- 普通 thread/run HTTP surface 目前依赖 loopback 信任，不能直接作为远程 API；
- `/v1/control/*` token 权限过高，不能复用；
- 当前没有账号、设备、relay、移动推送和远程审计 authority；
- `/v1/runs/{run_id}/audit` 当前为空，不能承担远程操作审计；
- 当前 crash 后不保证 active run 自动续跑，手机必须如实显示 Desktop/Core 重启后的中断；
- Subagent message route 当前 unsupported，手机不能补造 child messaging；
- Computer、Hook、Memory、项目删除等 route 需要明确排除，而非依赖 UI 不展示；
- 当前 TaskScope 不约束 Bash 路径，远程 prompt 的安全风险必须在产品上线前获得明确决策。
