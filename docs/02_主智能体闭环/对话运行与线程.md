# 对话运行与线程

## 1. Run 建立

一次 run 固定 thread/workspace、模型 profile、TaskScope、`ExecutionEnvironmentSnapshot` 和 `RunToolAvailabilitySnapshot`。RequestBuilder 暴露给模型的 tools 与 ToolRuntime 执行的 runtime/provider identity/runtime pointer 来自同一快照；registry catalog 或 PATH 变化只在后续 run 形成新快照。MCP adapter 仍检查 live server state，因此当前 run 中途断线会立即使后续调用返回 needs-auth/runtime/deny/transport failure，但不会换成另一个 provider 或调用旧 session。

模型 profile 是否支持 tool calling 应在建立请求前判定。当前尚无覆盖所有 provider/model 的统一 tool-support capability，因此不支持 tool calling 的组合必须明确拒绝或降级为无工具对话，不能把发送 schema 失败伪装成工具失败。

## 2. 用户输入与 Skill

composer 提交文本、attachments 和结构化 Skill tokens。Runtime 对 token 重新查当前 registry并核对 loaded/user-invocable/source/path：

- inline Skill 正文进入当前 run 的 SkillContextBlocks；
- fork Skill 创建真实 child，父 run 只接收 child 结果；
- model 在 run 中通过统一 `skill` 工具按需调用其他 Skill；
- Skill 不创建或收窄父 run 工具快照。

含 Skill token 的 composer turn 会先将文本、有序 attachments 和 composer tokens 作为完整 `user_message` 耐久化，再进行 Skill 预激活。成功激活在执行前写 `skill_activated`/按需 resource receipts；激活失败仍保留该次用户输入，但不写伪 activation。Agent 执行时消费已准备的 turn，不重复写入 `user_message`。

成功的 composer 预激活还会生成 host-owned、current-run-scoped 的 `ComposerSkillSelection`，它包含经 registry 重新校验的 Skill ID、source、activation mode、绝对包根和 `SKILL.md` 绝对路径。RequestBuilder 在 Skill 正文之后追加不可由 Skill 正文伪造的选择绑定块：

- 单个 composer Skill 明确标记为用户本轮当前选择，“这个”、“刚选的”等指代直接绑定该 Skill；
- 多个 token 按 composer 顺序保留并明确标记多选歧义，宿主不擅自猜一个；
- token-only turn 不向用户正文注入伪 fallback 文本，选择语义仍由 host block 提供；
- 历史恢复或 model-invoked Skill 正文可继续进入 SkillContextBlocks，但不得冒充本轮 composer 明确选择。

source/path/root mismatch、Skill 已不可读或不再 user-invocable 时，在 provider 请求前失败，不将 renderer 中的旧 chip 当成权威。

## 3. 主循环

Agent 按 model response 执行 assistant text、tool calls、Skill catalog call、context estimate/compact 和后续轮次。普通工具默认自动；默认 raw Shell 使用当前登录用户本机权限，不进入通用审批。`ask_user` 是任务信息 gate，typed message provider 的 mass-message review 只保护该 provider，不声称覆盖任意 Shell/CLI 外发。run 对外状态只有 `running`、`cancelling`、`finished`、`error`、`cancelled`，不存在通用 `awaiting_approval`。Journal 恢复使用的 terminal payload `status=interrupted` 会投影为公开 `error`/`RUN_ERROR`，不是第六种对外 run 状态。

ToolRuntime 先校验固定 snapshot/provider readiness，再执行 TaskScope、安全决策、broker 和 tool。canonical Outcome 回到模型；UI/replay 使用独立投影。

## 4. Thread 与恢复

thread 与 workspace/project 关系耐久保存。重开时从 SemanticJournal 重建 user/assistant/tool/artifact/Skill/gate/terminal，而不是从 renderer local state 恢复。未闭合 run/tool call 由恢复流程标记 interrupted/unknown，不自动重放副作用。

fork child 的父子 identity、取消和工具继承必须显式；child Skill body 不注入父 run 的后续上下文。

## 5. 不变量

- 同一 run 的 tool/environment snapshot 不变；
- Skill hints 不改变权限或工具池；
- side-effect call 必须 append-before-transport；
- terminal 只能来自 durable run 事实，UI 不自行补成功；
- thread 切换/重开不得改变旧 run provider/readiness 或 Skill 内容。

## 6. 代码 owner

- `src/runtime/run_service.go`、`session.go`：run/thread lifecycle。
- `src/agentcore/agent.go`、`runner.go`、`request_builder.go`：主循环与请求。
- `src/agentcore/agent.go`、`runner.go`：child agent。
