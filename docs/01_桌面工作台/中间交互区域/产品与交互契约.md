# Workbench 中间区域产品与交互契约

## 1. 权威范围

本文是 Awaken Desktop 中间工作区用户行为的唯一权威来源，回答“用户当前看到什么、可以怎样操作、哪些能力明确不支持”。

本文不定义：

- 组件 ownership 和层级边界：见 [架构契约](架构契约.md)。
- anchor、follow、marker、composer inset 的算法和状态转换：见 [交互状态机与滚动布局](交互状态机与滚动布局.md)。
- runtime event 如何变成 turn：见 [叙事投影与重放](叙事投影与重放.md)。
- 输入、Slash、Skill token 和附件字段：见 [输入、斜杠菜单与附件](输入、斜杠菜单与附件.md)。
- 交付物筛选与安全打开：见 [最终交付物展示与安全打开](最终交付物展示与安全打开.md)。

当前事实以 `apps/desktop/src/renderer/App.tsx`、`apps/desktop/src/renderer/useRunStageScrollController.ts`、`apps/desktop/src/renderer/workbenchPresentation.ts`、`apps/desktop/src/renderer/run-narrative/` 和真实 Desktop 行为为准。

## 2. 产品定位

Workbench 中间区域是本地 Agent 的执行叙事空间，不是普通聊天窗口，也不是原始日志查看器。它持续回答：

1. 用户这一轮要求什么；
2. Agent 正在思考、探索或执行什么；
3. 当前是否需要用户补充任务信息；
4. 本轮最终回答是什么；
5. 哪些最终交付文件可以安全打开。

原始协议帧、完整 tool result、调试 JSON、命令全文和 patch/diff 明细不应被平铺为中心主叙事。当前右侧 Inspector 接通独立的项目文件目录与文件预览工作区：项目文件树中的 Markdown 可在受控边界内编辑并覆盖写回，Office、代码/文本、PDF、图片、HTML 以及临时 Artifact Markdown 标签保持只读。文件工作区可以在 `WorkbenchShell` 内覆盖中间叙事，但不消费通用 reducer 详情数据，也不改变 RunStage 的 turn、滚动、overlay 或 composer ownership。完整产品边界由 [右侧栏当前支持边界](../右侧栏/当前支持边界.md) 唯一拥有。

## 3. 当前主形态

中间区域只承认两种 composer 形态：

| 形态 | 出现条件 | 用户看到的内容 |
|---|---|---|
| `center` | 没有可见 narrative，且没有当前 run | `TaskWelcome`、运行时提示、专用 gate、居中的 composer，以及输入面下方与侧栏同步的项目作用域低栏 |
| `dock` | 已有 narrative、已有 run，或扩展文件 surface 正覆盖原 center 空态 | `ExecutionFeed` 或保持挂载但 inactive 的叙事区、底部 composer、必要的 overlay |

历史线程重放仍使用 `dock`；“历史态”不是第三种 composer variant。

`shouldUseCenterComposer()` 只依据 `hasNarrative` 和 `hasRun` 判断标准场景。文件工作区扩展且文件 surface 激活时，Desktop 在该结果之上临时选择现有 `dock`，保证同一个输入框仍可使用；notice、error、runtime restart 提示本身不强制切换成 dock。center composer 的可见 placeholder 为「描述任务，或 / 选择技能」；dock 为「给当前运行追加任务…」；文件 surface 保留「输入后续任务…」。

## 4. 用户流程

### 4.1 第一轮任务

1. 用户在 center composer 输入文本、选择附件或 Skill token。
2. 提交后，界面切换到 dock。
3. 新 prompt 立即成为一个 turn 的起点，并锚定到 RunStage 顶部。
4. 同一首个可见转换中，turn body 立即显示由思考球、`思考中` 文字和三点节奏动效组成的透明行内状态，不等待 Core 或 provider 发出首个 reasoning/tool/text 事件。
5. runtime 发出 reasoning summary 后，思考文本在同一状态行下方流式展开；首个可见输出若是 tool 或 answer，则状态行直接让位给该内容，不伪造 reasoning。
6. 供应商在响应前断网或握手失败时，run 保持忙碌和思考中；执行时间继续走，turn body 在计时行之后、叙事之前显示 Wi-Fi「正在等待网络」，细节可展开且只有去敏英文短句。流在工具开始前断开则显示「正在重新连接 n/5」，并丢掉未耐久的思考/回答正文、回到思考中；恢复成功后重连行消失并继续输出。这不是 SSE `reconnecting`，也不进历史 replay。
7. run 忙碌期间，主按钮进入 stop 语义；不支持在同一 thread 中排队第二个 run。
8. thinking、tool、answer 等内容在同一 turn 内追加。
9. 工具结果完成且 Core 明确进入下一次模型 turn 时，最后一个工具批次下方由临时思考状态接棒；工具结果续接显示“正在分析工具结果”，继续生成和 XML fallback 使用各自确定性文案。上下文压缩开始后只显示一条带动态思考球的“上下文压缩中”，同一 run 内的 started、finished 与 reactive retry 共用稳定展示身份，不平铺开始/完成边界、Token 数或内部 boundary ID；收到 reasoning、answer、下一次 tool 或 run 终态后立即让位并继续原任务。临时状态延迟 650ms 出现，不把模型等待误写成工具仍在运行，也不显示虚假百分比。
10. run 终态后 composer 恢复可输入；再次提交沿用当前 thread。

这里的“立即”是首个用户可见帧的原子语义：新 turn 第一次可见时，prompt header 已经位于 RunStage 顶部锚点。不得先在旧 final answer 或 deliverables 下方以自然 append 位置出现，再在后续帧跳转到顶部。

### 4.2 多轮任务

- 每个用户 prompt 开启一个新 turn。
- 新 turn 获取最新 prompt ownership；旧 prompt 仍属于旧 turn，不产生 feed 外副本。
- 相邻 turn 之间保持 38px 的垂直边界：`ExecutionFeed` 的 14px 基础间距之外，Desktop 只在后一 turn 增加 24px；因此前一轮 final answer 或交付物与下一轮 prompt 不会紧贴，同时不改变 turn 内部、Composer output gap 或首轮顶部布局。
- 三轮及以上时，右侧 marker rail 按可用高度显示 regular、compact 或 summary 形态。
- 点击 marker 跳到对应 prompt，并将 latest-output follow 置为用户暂停。

### 4.3 阅读运行中输出

- 用户没有表达阅读历史意图时，最新 turn 持续跟随本机滚动底部。
- 用户向历史方向滚动、触摸、在 feed 中 pointer down 或点击旧 marker 后，自动 follow 暂停。
- 暂停后显示使用 `--aw-surface-raised` 与 `--aw-text-primary` 主题 token 的圆形向下箭头；其可访问名称为“回到最新输出”。
- 点击按钮或明确滚回最新 tail 后恢复 follow。
- markdown 增高、tool 内容增长、窗口 resize、prompt 展开、composer 增高等被动变化不能替代用户恢复意图。
- RunStage 叙事滚动区在滚动条两侧稳定预留等宽空间；展开执行过程、Tool 输出、媒体明细或 Prompt 后即使纵向滚动条从无到有，居中的 prompt、turn body、final 和交付物也不得横向位移。

### 4.4 Prompt 气泡

- prompt 文本超过 3 行或 160 个字符时，默认折叠到 3 行。
- 单击后展开；拖选正文、token 标签或附件文件名不触发展开。展开文本最大高度为 9 行等价高度，更多内容在气泡内部滚动。
- 展开后点击气泡外部会收起。
- 展开态显示复制入口；复制内容为气泡可见输入的纯文本：附件显示名（每行一个）、再接含 Skill/文件/capability 等 token 标签的正文流。不包含 Skill 路径、Computer Use 隐藏引导或其它非可见元数据。
- 气泡内正文、token 标签与附件文件名允许鼠标局部选择与系统复制；侧栏与其它 chrome 仍不可选。
- 附件默认显示前三个；更多附件以 `+N` 表示，展开后显示全部。
- token、附件和文本共同属于用户原始输入，必须在历史重放中保持可见顺序。

当前 v2 耐久输入会恢复结构化附件小卡、附件顺序和 composer token。修复前已写入的旧 v2 记录只有附件数量，没有可恢复的 identity/path/token；历史重放必须忠实显示其中的文本，不得从 prompt 文字或磁盘目录猜造附件。耐久字段与恢复边界只由 [SemanticJournal 与重放](../../03_运行时与本地服务/SemanticJournal与重放.md) 定义。

每个已有计时事实的 turn 在 prompt 下只显示一处“执行时间”。新提交在 `run/requested` 首帧立即从 `0 秒` 开始，运行中按秒递增；收到耐久 `RUN_STARTED` 后以服务端时间戳校准起点。最终回答出现且前面存在过程项时，这一行原位成为过程 disclosure 的标题，例如“执行时间 17 秒”加 Chevron，不再另起“执行过程”；成功终态用 final answer 的 `elapsedMs` 冻结，当前终态也可由 `runCompletedAtMs - runStartedAtMs` 冻结。没有过程项时计时仍保持普通行。计时文本自身更新，不重投影 narrative。历史重放只使用已经保存的终态耗时，不从当前时间猜造；旧历史没有耐久耗时时，disclosure 回退显示“执行过程”。final answer footer 不重复显示耗时。

### 4.5 执行过程折叠

当一个 turn 已出现被标记为 `isFinal` 的最终回答，并且其前面存在过程项时：

- 最终回答之前的 thinking、exploring、普通 tool、旧 approval 记录、非最终 assistant 说明和全部图片/视频生成明细归入同一个“执行过程” disclosure；媒体不能成为分段边界，成功、失败、敏感内容拦截和其后过程项都不能泄漏到结果区；上下文压缩的瞬时状态不进入终态执行过程；
- 图片/视频生成在执行中为每个请求结果建立一张独立紧凑媒体卡；生成前使用请求比例占位，媒体加载后切换为真实宽高比。final 前媒体组实时可见并按状态自动展开；final 后整组随“执行过程”默认折叠，用户展开外层过程后才能查看各次生成明细及卡片网格；
- disclosure 默认收起，可按 turn 独立展开；有计时事实时标题直接使用该 turn 唯一的“执行时间”，没有耐久耗时的旧历史才回退为“执行过程”；
- 用户展开终态“执行过程”时，已完成的 Tool、MCP、Skill 和终端轨迹在首个展开帧同时可见，不重播逐项入场延迟；入场动态只用于 final 之前实时新增的工具轨迹；
- 最终回答及其后的交付物继续平铺显示；
- 在最终回答出现前，过程项保持实时可见，不提前折叠；
- 如果最终回答是 turn body 第一项，则不创建空的“执行过程”。

该能力是当前已实现的产品行为，不再写成未来 work packet 计划。当前聚合单位是“最终回答前的 turn 过程”，不是任意并发工具 DAG 或跨 turn 工作包。

### 4.6 文件工作区覆盖与会话切换

- 用户从右侧文件工作区点击“展开面板”后，文件 surface 覆盖 Workbench 主舞台，左侧项目栏与当前 thread 保持不变；
- 顶部中间显示当前会话标签，右侧显示当前项目的已有文件标签；会话标签恢复原 RunStage，文件标签恢复同一个文件预览 surface；
- 文件 surface 激活时，RunStage 叙事内容不可交互但不卸载，run 继续接收事件；底部仍使用当前 thread 的原 composer，可继续编辑草稿、停止或提交；只在文件 surface 激活期间保留输入面与模型选择，隐藏输入面下方的项目名和“上下文窗口”元数据；切换到会话 surface 或收起后立即恢复；
- 文件 surface 内的 composer 使用同一个五态呈现：仅当结构化草稿为空且没有运行、专用面板时，对文档预览非交互区完成一次未越过拖选阈值的主键单击才收为短横线；正文拖选、预览工具按钮、已有正文、token 或附件都不得触发收起。第一次点击横线显示“继续对话”紧凑入口，再次点击恢复完整输入面；提交后显示可点击停止的“正在执行”状态，成功终止后显示含耗时的“已完成”状态，点击后回到完整输入面；
- 五态只是 Desktop 对现有 `dock` ComposerBar 的呈现控制，不新增第三种 composer variant；原 ComposerBar DOM 在紧凑态保持挂载但不可交互，草稿、token、附件、Slash 与模型选择不丢失；“已完成”只属于最近一次从当前扩展文件 composer 明确提交并已结束的 run，历史 thread 的 finished replay、进入文件 surface 前已经完成的 run 或其他 thread 的终态不得投影为该完成入口；专用问答、外部授权或 runtime 异常面板出现时强制保持完整态；
- 切换 surface 不重建 Office、HTML、PDF 等查看器，不清空目录展开、筛选、文件标签或内部列表宽度；
- 收起扩展后恢复普通中间会话加 720px 文件工作区分栏。其余文件能力与验收只见 [右侧栏当前支持边界](../右侧栏/当前支持边界.md)。

## 5. 当前 narrative 表达

中心区域当前可见的主要内容：

- prompt；
- thinking；
- read-only exploration group；
- tool trace；
- 图片/视频生成的加载、排队、生成、载入、就绪、失败或取消卡；
- Memory recall/mutation 与 Dream terminal 的紧凑回执；
- 仅 live 压缩期间出现的一条“上下文压缩中”动态状态；
- legacy approval 的只读轨迹；
- final answer；
- cancelled hint；
- ready deliverables。

已完成的 final answer 底部操作区固定在回答正文之后，只在右侧显示无底卡的复制图标；悬停或聚焦不显示 Tooltip、原生 title 或其它可见文字，只保留颜色、焦点轮廓和纯图标复制成功/失败反馈，无障碍名称继续存在。该按钮只复制最终回答 Markdown。执行时间位于 turn 顶部，终态有过程项时同时承担过程 disclosure 标题。流式回答、错误回答和非最终 answer 不显示该操作区。

助手 Markdown 正文使用文章式阅读排版：正文与标题保持明确字号层级和留白；行内代码使用中性灰蓝文字与轻量底色，不用红色强调；普通 fenced code block 使用浅灰 code surface、细边框、顶部小型语言标签，并只按模型显式声明的语言做 token 语法着色，不自动猜测；关键字、函数、字符串、注释和变量使用紫、蓝、绿、灰和青色系区分，未知语言保留原代码和标签。GFM 表格使用横向分隔线、透明表头和加粗首列，不再套圆角卡片或填充表头；窄宽度仍由表格容器横向滚动。Mermaid 继续只在 fence 闭合后进入图表渲染，未闭合或失败时保留统一代码表面。上述正文在浅色、深色、流式增长、历史 replay 和局部文本选择中保持同一结构，模型 raw HTML 仍不渲染。

当前明确行为：

- `planning` item 是实时等待可见输出的 UI 占位来源：提交时的 initial planning 仅当它仍是当前 narrative 尾项且 run 忙碌时显示无正文动态 Thinking；Core 发出带已知 continuation reason 的 `AWAKEN_TURN_STARTED` 时，projector 在已完成工具或前一段输出之后创建带确定性中文 label 的 continuation planning。`AWAKEN_COMPACT_STARTED` 创建“上下文压缩中” planning；随后 compact finished 和 `reactive_compact_retry` 继续复用同一 run-scoped identity，不产生完成行或第二条等待行。它们都在首个 reasoning、tool、answer 或 run 终态出现后立即让位；临时状态延迟 650ms 展示以避免快速请求闪烁。planning 不进入历史过程或 durable replay，也不伪造 reasoning 正文。
- `thinking` item 使用同一透明紧凑状态行；active 时以 20px 思考球和 12px `思考中` 文字显示三点动效，并从文字起点在下方流式追加 runtime 明确提供的 reasoning summary；done 后移除运行态思考球，以静态 `思考过程` 和位于文字右侧的 12px Chevron 保留回看并默认折叠，展开向下、折叠向右。标题触发区按内容宽度收紧，正文从原层级左边缘向下出现，不再额外缩进，开合时标题起点不跳。自动收尾时静态标题必须立即可见，正文高度折叠不能先透明而留下占位空白；同一条 live reasoning/answer 的耐久快照只原位校准内容，不得重新激活已完成 item 或重播其入场/收尾生命周期。用户手动展开/折叠优先于自动状态。最终回答出现后，它与其他过程项一起进入“执行过程”。
- 连续的 `exploring/tool/skill` 先由 Renderer 纯展示投影为 Activity Batch，再使用“执行过程 → 批次摘要 → Tool 单行 → 类型化详情卡”的三级渐进披露。`exploring.actions` 只展平为普通 Tool 行，不得嵌套第二层工具组；只有一个有效动作时旁路批次、直接显示 Tool 行。新 reasoning、用户可见说明、gate、Subagent、媒体、Artifact、Final 或下一 Prompt 都结束当前批次。批次 identity 必须由 turn 与首项稳定 identity 组成，不得使用数组下标；旧历史不迁移，replay 使用同一规则重建。切回已有 thread 或应用重启后的首个可见帧必须原子恢复完整 transcript，历史 Thought 和 Tool 不重播挂载入场；恢复完成后新到达的 live Thought/Tool 仍保留实时反馈。
- 批次标题由内容确定性生成，例如“运行了 N 条命令”“检查了 N 项”“编辑了 N 个文件”“正在使用/使用了 Skill · N 个工具”或“使用了 N 个工具”，不得调用模型生成。进行时/完成时已经由标题时态表达，标题旁不重复显示“执行中/已完成”；只有异常数作为补充状态保留。活动批次默认展开，用户手动收起优先；进入下一阶段后自动收起，历史/replay 默认收起。批次主 Chevron 与最外层执行摘要 Chevron 常驻；单条 Tool 的 Chevron 始终保留布局宽度但默认透明，只在 hover、`focus-visible` 或已展开时显示，因此开合与滚动条变化都不得造成横向跳动。
- Tool、MCP、Skill 与终端共用单行语法，只保留图标、自然语言标题、必要短上下文与语义状态，不展示原始 `{`、重复 Skill/provider 标签或多余完成勾选。文件型 Tool 主行只显示 basename；`Glob/Grep/WebSearch` 使用搜索图标，Glob/Grep 的 `*`、`**`、`{}` 等匹配语法只留在详情，主行把常见扩展名模式翻译为“PDF 文件”“Markdown 文件”等用户语言，并最多补充根目录 basename；Shell 优先使用完整参数中已有的 `description/label/summary`。绝对路径、完整命令和结果摘要只进入单条详情卡。执行中的单例 Tool，或展开批次中的当前 Tool，使用 1.6 秒从左到右的文字扫光；批次收起时由“正在运行 N 个工具”标题扫光。完成、错误、取消和中断立即停止；图标与背景不发光，`prefers-reduced-motion` 下改为静态文字高亮。
- 点击或键盘 Enter/Space 展开 Tool 的类型化详情卡。Shell 展示命令、stdout/stderr 和截断提示；Skill 展示名称、来源、版本与结果；MCP 展示 provider/tool、脱敏参数与结果；Read/Search 展示目标与匹配摘要；文件操作按 tool call identity 展示文件列表与 diff；错误展示错误码、原因和恢复信息。流式 `TOOL_CALL_ARGS_DELTA` 的原始 fragment 只属于 transport；名称精确匹配内置 `Write`/`Edit` 时，Core 可以附加 basename 与增删行估算，前端用同一个 tool call identity 提前显示“写入/编辑 文件名  +N / −N”的单行 active Tool，并在参数继续生成时原位更新数字。该准备态不提供 Chevron、detail/output 或代码正文，Write 不把未知的旧文件行数伪装成删除数；Edit 的 old/new 计数和 Write 的新增计数均为执行前估算，执行产生 patch 后同行改用 patch 的真实增删统计。其他工具或缺少安全派生字段的 delta 不创建 Tool 行；只有完整 `TOOL_CALL_ARGS` 可以按已知工具白名单派生稳定短摘要。参数只按已知类型展示并对 `password/token/secret/apiKey/authorization/cookie` 等敏感键脱敏，未知 Tool 不默认显示原始 args。展开后直接进入正文，不重复显示“Shell 详情/工具详情”等类型标题；该标题只保留为可访问名称。卡片使用主题化灰色 code surface 和终端语义文字：命令为 accent 色，普通输出为当前主题 code 前景的 dim 混色，成功/错误继续使用对应状态色。详情卡最高 320px，正文区是唯一内部滚动 owner，显示细滚动条、支持键盘滚动与文本选择复制；右上角只显示透明背景的复制图标，图标、细滚动条和首段正文分别保留独立空间，不得相互覆盖。卡片内部 wheel/touch 滚动不得驱动 RunStage follow 状态。卡片与批次内容列对齐，不形成多层阶梯缩进。旧 `output/outputLabel` 仅作为终态历史兼容回退，不能把 live active detail 冒充“工具输出”。该展示不改变工具、MCP、Skill 的 runtime ownership 或权限语义。
- `fileChange` item 当前不直接渲染；终态会由 deliverables summary 移除旧 file-change 叙事。
- `image_generate` / `video_generate` 不投影为普通文本 tool trace；同一稳定 tool-call identity 派生相互独立的媒体卡片，消费安全的 `media_status` 进度，完成后在本轮结果区保留可展开摘要，不新建 turn。小卡只显示图片或视频首帧入口，并在媒体加载后显示真实 `宽×高 · 时长 · 格式`（图片省略时长）；单击后在 `RunStage.overlay` 打开图片缩放或带原生 controls 的视频预览，视频立即尝试播放，被平台拒绝时显示明确播放按钮。更多菜单可把当前媒体临时固定到右侧栏查看；菜单按 RunStage 当前可见边界自动翻转和平移，不得被 Composer 遮挡或异常展宽，也不能改变默认单击、Artifact 顺序或 RunStage ownership。视频任务只展示 provider 提供的排队/生成状态，不伪造完成百分比；轮询窗口结束但 task 未终态时停止转圈，明确显示“状态待确认”并保持展开。
- 独立媒体卡宽度为 `128–144px`，以 8px 间距自动换行；组图生成中按 `max_images` 显示 2–15 张独立卡片，占位表示本次请求上限，不承诺最终精确返回 N 张。全部成功后按实际返回的 Artifact 数量删除未返回项；部分成功时仍保留请求位置，逐项显示 ready/error，ready 项立即可预览和交付。每个 ready 项由媒体 `naturalWidth/naturalHeight` 或 `videoWidth/videoHeight` 修正真实宽高比，不裁剪、不拉伸。
- final 后的媒体交付是另一个明确的用户任务：内嵌媒体生成明细随“执行过程”折叠，每个 ready Artifact 在终态交付列表中提供独立预览。媒体单击进入 Awaken 预览；更多操作和预览工具栏提供系统默认应用打开，以及 macOS Finder / Windows 文件资源管理器定位。前者是可回看的执行证据，后者是默认可见的正式交付，不是重复发布 Artifact。
- Subagent group 只在所属 turn 中显示 child 摘要。点击 child row 后，详情在 dock Composer 上方打开独立有界浮层，展示该 child 自己的 Thought、Tool、Markdown 结果、错误和单任务停止入口；不向用户提供向 child 追加指令的输入框。header 左侧同行显示“智能体类型：任务名”，右侧同行显示工具数、token、耗时和末尾状态，不为这些信息新增独立行；面板 surface、边框、文字、阴影、hover 与状态色跟随 Awaken 浅色/深色语义 token，正文滚动只显示 thumb、不显示 track。浮层不扩充对话流、不移动 prompt/marker、不改变 follow，外部区域保持可滚动，关闭只改变本地选择状态。详情仍消费 reducer 中的 `SubagentTaskView.narrative`，不得从 root narrative 或 DOM 拼装 child 过程。Core 内主 Agent 的 `message` action 不投影为 Desktop 用户输入面，具体语义由 [原生 Subagent 产品与架构契约](../../02_主智能体闭环/原生Subagent产品与架构契约.md) 拥有。
- Memory 回执只展示数量、scope/type/revision 或错误码，不平铺主题正文；Dream 回执只展示中文终态和有界统计。
- 新 run 不展示通用可交互 `ApprovalCard`。
- 历史通用 approval 只显示 `Legacy approval record` 工具轨迹，不提供恢复按钮。

## 6. 专用用户 gate

当前仍允许出现在 composer stack 的用户 gate 只有专用产品流程：

- `ask_user` / 主动提问；
- 通用 `ExternalActionGate`（首个使用者为官方 CLI 授权）；
- 兼容期内 Main 内存 CLI auth session 的紧凑投影；
- runtime 启动、崩溃或 run error 的状态面板。

`ask_user` 出现时作为专用 gate 位于既有 `composer-dock-stack`，普通 ComposerBar 固定保留在 gate 下方，不卸载、不隐藏，也不转移 draft authority。运行仍为 busy 时输入面保持现有禁用/停止态，不能借保留输入框并发提交第二条用户消息；面板保留当前单题/多题分页、单选/多选、“其他”文本和统一提交逻辑，取消仍复用当前 run 的停止行为。gate 出现、回答或取消只改变 stack 实测高度，不新增 modal、overlay、第二个输入系统或第三种 composer variant。

`ExternalActionGate` 由当前 run 的 `interaction_required` 等待驱动，放入既有 `composer-dock-stack`。它展示安全 HTTPS 链接、受控二维码占位、说明与完成/取消/重试；二维码容器固定尺寸，加载、过期和失败在原位替换。出现与移除不得破坏草稿、焦点、follow/paused、marker 或 return-to-latest，也不得改变 turn identity。它不进入 ExecutionFeed、narrative step、transcript 或历史 replay；页面往返后仅当前活跃 run 的 gate 仍可见，其他会话不显示。迟到的 completed/cancelled 不得恢复已终态 run。

连接器页「+」只安装 CLI；安装完成后的「发起登录」通过 product-action handoff 进入普通新会话并自动提交受控 Agent 登录指令；授权交互不在连接器卡片内嵌完整二维码，也不提供“选择 CLI”文件选择器。

这些 gate 可以使 dock 高度变化，但必须由 composer stack 承载并进入统一高度测量。它们不得复用旧通用 approval endpoint、旧 `ApprovalCard` 或 `awaiting_approval` 恢复语义。

Computer session 常态状态不作为 gate 放在输入框上方，也不属于 RunStage。模型在一个 run 中第一次执行 `computer_observe`、`computer_act` 或 `computer_verify` 时，Electron Main 在当前屏幕工作区顶部居中显示独立的系统级置顶深色胶囊悬浮条，透明窗口画布不得显示额外的矩形边框或被裁切的外投影；胶囊包含简短“Awaken 正在操作您的计算机”状态和唯一的停止按钮。后续 Computer 调用及其间的模型推理阶段保持连续显示，直到 Computer session 关闭、run 进入终态或事件流关闭后自动隐藏。单次工具的参数流或 result 不能证明它是最后一次 Computer 调用，因此不得使提示闪退。停止动作只通过 Main 的专用控制链中断并终止当前 run 的 Computer Use，禁止该 run 自动重开 Computer session；它不得取消 run 或停止模型回答，也不依赖当前 Awaken Renderer、选中 thread 或 RunStage 是否可见。暂停、接管等内部控制语义不在常态条上扩展为多个按钮。需要用户处理的 review/handoff 仍使用专用 gate。

## 7. 输入与上下文入口

当前支持：

- Enter 提交；Shift+Enter 换行；IME composing 时 Enter 不提交；
- 结构化 Skill token 与前后 plaintext 位于同一个 editing host；token 前文、token 间正文和尾文都可重新定位与编辑，token 本身保持原子不可编辑；
- 从右侧项目文件树“添加任务”的普通文件/文件夹使用同一原子 token 编辑链；只显示条目名称，路径 identity 不进入可见正文，具体授权和 effective input 规则由 [输入、斜杠菜单与附件](输入、斜杠菜单与附件.md) 与 [右侧栏当前支持边界](../右侧栏/当前支持边界.md) 拥有；
- `@` palette 提供 Computer Use capability；选择后输入面与 prompt bubble 只显示带显示器图标的原子 token，隐藏模型引导只由 Core 在提交时按固定 capability identity 注入 effective input；`/` palette 不再提供 Computer Use；
- busy 时主按钮停止当前 run；
- center/dock 复用同一 ComposerBar；
- center 首页在 ComposerBar 输入面下方显示与输入面外缘对齐的项目作用域低栏；字标、说明文案与输入面保持清晰但克制的纵向分隔。空 `projectId` 恢复显示为无图标的“选择项目”，代表电脑全局对话范围，不把“对话”伪装成项目或文件夹；其后列出侧栏同一 active 项目集合并使用文件夹图标。选中项目后，hover 整段控件或键盘聚焦清除按钮时，前置文件夹图标原位变成圆形 `X`；点击 `X` 直接清空项目目标、关闭菜单并回到“选择项目”，点击其余区域仍打开项目菜单。选择与取消项目都和侧栏双向同步，不借用默认 workspace；「创建项目」复用侧栏同一弹窗并支持可选的多文件夹组。dock 不显示该低栏；
- 多选本地附件、粘贴 PNG/JPEG/WebP；
- Slash Palette 由统一 Skill catalog 供数，展示所有 `loaded && userInvocable != false` 的来源；
- `/` 与 `@` 以当前 collapsed 逻辑光标为 trigger 结尾，可插入已有句子或 token segment 中；菜单跟随 trigger caret，选择后仅以原子 token 替换 trigger，前后正文保持原位；
- 未提交正文、token、附件与逻辑 selection 按 thread 在当前 Desktop 进程内隔离；切换到运行中或历史会话不得显示其他会话的草稿，返回原会话恢复自己的草稿；
- 模型选择是会话级 preference，不修改设置页 default；支持 effort 的模型按[输入、斜杠菜单与附件 §3.1](输入、斜杠菜单与附件.md)进入二级面板并选择真实档位；档位吸附时立即保存并把标签显示为 `模型名 · effort`，无档位模型不显示入口；有历史时提示缓存重建，busy 时禁用修改；
- workspace 展示和“上下文窗口”汇总入口；常驻入口为圆环占比指示，不常驻显示 label 或数值；仅指针 hover 展示「N% 当前使用」与「当前总输入 / 可用输入窗口」两行，不追加“可用输入”文字；打开完整面板期间以及关闭后面板焦点回到入口时不展示该 tip，指针离开入口后再 hover 才重新出现；同 identity 的最近完整主调用直接使用 provider inclusive input，不加入 output 或当前本地差量，无法使用实报 input 时回退当前本地估算；
- 点击或使用 Enter/Space 打开中文上下文面板（完整分类面板保留）；首行标题“上下文用量”与关闭按钮同行；其下左侧为「N% 当前使用」、右侧为「当前总输入 / 可用输入窗口 Token」，再下为分类进度条；Core 分类只有系统提示词、内置工具、MCP、技能、记忆、对话六项，当前总输入相对六项本地和存在正残差时追加“其他/协议开销”；存在缓存或成本信号时，缓存状态、输入/命中/未命中/输出 Token 与成本紧接分类明细，不添加“上次请求”标题或分隔线；有兼容完整 input usage 时，汇总与输入 Token 严格相等；无 `~`、“预计”、中文“约”、“本地估算”、模型窗口/输出预留/自动压缩阈值文案，不展示模型调用账本；
- 六项来源由 Core 的 v4 typed snapshot 决定：内置工具只含源码稳定工具和内置 Skill 工具包装；MCP 是用户经连接器/MCP 配置接入、服务器返回并实际下发模型的工具定义，connector provider identity 不改变其 MCP 分类；技能只是统一 Skill catalog 的模型可见 name/description/when-to-use；MCP result 与激活后的完整 Skill 正文进入对话；
- 切换 thread、完整重启或回放多个 run 时，Desktop 先用当前可运行 profile 让 Core 从耐久历史和当前 MCP/Skill/Memory 重建并 flush v4 snapshot，再读取 transcript；相同 projection 不重复写。没有可运行 profile 时保留该 thread 最后一个合法 snapshot，v1/v2 不补造分项；后续 run 因失败、取消或未进入模型而没有新快照时，不能把已恢复的窗口清空；
- Escape、关闭按钮和点击外部关闭面板并把焦点返回入口；亮暗主题与窄窗口均保持可读，窄窗口由面板内部滚动；
- token-only 提交。

当前不支持：

- “添加上下文” picker；点击 `+` 以外的未接线上下文动作只显示提示；
- run 中排队 follow-up；
- 通用富文本或样式化 prompt 编辑器；带结构化 token 时是统一 plaintext 编辑上下文，不支持富文本样式；
- Slash 中的 file/workflow/prompt/connector provider（类型已预留，但产品未接入）。

### 7.1 文本选择与全选

- Awaken Desktop 的应用壳、侧栏、按钮、导航标题、状态文字、上下文用量面板和其他界面 chrome 默认不可选择，鼠标拖动不能把整窗 UI 文案染成文本选区。
- Awaken Desktop 不提供浏览器式 `Tab` / `Shift+Tab` 焦点轮转；Renderer 在 capture 阶段统一消费未修饰 Tab，Electron Main 同时提供窗口与项目 HTML webview 兜底，因此切换页面、设置分区、按钮、链接或表单控件都不会因 Tab 获得焦点或出现外置焦点框。Control、Command 或 Alt 修饰的组合键不由该规则消费。Design System 组件仍保留独立 Gallery、辅助技术和程序化聚焦需要的 `focus-visible` 语义，Desktop 不通过逐组件 `tabIndex` 或删除全局样式实现这项产品策略。
- 最终回答 Markdown、其中的代码、Prompt 气泡内的正文/token 标签/附件文件名，以及其它明确标记为可复制正文的阅读内容允许鼠标局部选择；Composer、设置表单和其他文本编辑控件保持原生编辑选区。
- macOS 的 `Cmd+A` 与 Windows/Linux 的 `Ctrl+A` 只全选当前获得焦点（或当前选区所属）的 textarea、文本 input、单一 `contenteditable` editing host，或带 `data-aw-select-all-root` 的 Prompt 可读根。焦点落在 atomic token 芯片内时仍全选其所属 Composer host。焦点与选区都不在这些宿主时，快捷键不创建跨侧栏、Workbench、overlay 或状态栏的文档级选区，并清除已有的整页 DOM 选区。
- Composer 与 Prompt 的复制纯文本包含可见的文件名、Skill/插件名与正文，按同一行流拼接，不把软换行写成硬换行；不包含 Skill 路径或 Computer Use 隐藏引导。Prompt 展开态复制入口使用同一可见拼装规则。全选快捷键不能把执行过程标题或回答 footer 元数据拼成一份隐式整页复制内容。

## 8. 最终交付物

用户可在 run终态的最终回答之后看到并打开合格交付物。资格、排序、展开、terminal提示、durable identity反查和安全打开全部由 [最终交付物展示与安全打开](最终交付物展示与安全打开.md) 唯一规定，本文不复制其算法。

## 9. 响应式行为

- sidebar 和 inspector 偏好宽度可调整并写入 renderer localStorage。
- sidebar 支持 `Cmd/Ctrl+B` 折叠。
- inspector 在窄窗口按媒体查询自动折叠，恢复宽度后回到折叠前状态。
- 展开态中栏最小阅读宽为 `520px`。有效右栏宽由 `workbenchLayout` 计算：先取当前 cap（普通右栏=用户偏好，文件工作区=720 且不写回偏好），再按 `window - sidebarOrZero - 520 - separators` 压缩，并夹在最小 260 与 cap 之间。窗口再窄则沿用现有 1180 折叠。
- turn 内容列与 center composer 最大宽度为 `760px`。
- marker、composer、return affordance 必须随真实 dock 高度调整，不得靠固定窗口坐标。

## 10. 当前不支持与已知边界

- 右侧 Inspector 的目录、文件标签、预览、浏览器入口和扩展覆盖能力只由 [右侧栏当前支持边界](../右侧栏/当前支持边界.md) 定义；当前只支持项目文件树中的 `.md` / `.markdown` 在格式化编辑态覆盖写回，不支持临时 Artifact Markdown、Office、代码/文本、PDF、图片或 HTML 的编辑，也不支持另存为、新建和未保存冲突合并。
- 项目筛选当前未实现；侧栏当前提供的是全部展开/收起，不是筛选。见 [项目与对话导航](../左侧栏/项目导航与筛选.md)。
- Context picker 未实现。
- 不存在第三种 composer variant。
- 不提供通用工具审批恢复。
- execution-process disclosure 不是完整 tool DAG、并发时间线或虚拟列表。
- tool/provider/environment snapshot、dependency 和 side-effect 元数据已进入 reducer/narrative，但右侧 Inspector 的文件工作区不展示这些详情。
- Workbench baseline 捕获脚本只生成截图和 manifest，不执行像素级 pass/fail。
- 当前不保存每个 thread 的精确 scrollTop；切线程会重建 turn 身份并重新进入锚定路径。
- 修复前的旧 v2 count-only 记录无法补回当时未保存的结构化附件和 composer token。
- 旧 thread 没有 typed context breakdown 且当前没有可运行 profile、因而无法重建 v4 projection 时，只显示已有汇总和“暂无分类明细”，不会按比例补造分类。

## 11. 异常与恢复

| 场景 | 当前用户行为 |
|---|---|
| Desktop runtime starting/stopped/stopping | composer stack 显示启动中，提交不可用 |
| runtime crashed | 显示 `Awaken needs restart`，需要按正式入口重启 |
| run create 失败 | 恢复提交前输入，错误只投影到当前 turn 的对话流，不在 Composer 上方重复显示错误卡片 |
| SSE 非终态中断 | Desktop 订阅持续重连，phase 可进 `reconnecting`，不提交普通失败回答，已有思考/回答保留 |
| SSE `run_not_found` | 进入 terminal error，错误只在当前 turn 对话流显示，并保留已就绪交付物 |
| Provider 等待网络 / 流重试 | 保持 running 与思考中；计时行下显示 live「正在等待网络」或「正在重新连接 n/5」；未耐久正文可被 reset 丢掉；恢复后重连行消失。历史 replay 不恢复该行 |
| 用户取消 | 保留已生成回答片段，追加取消提示；ready deliverables 仍可见 |
| 历史 legacy approval | 只读展示，不可恢复 |
| 旧 context record 无分类 | 先以当前可运行 profile 重建并 flush v4；无法重建时保留已有汇总并显示“暂无分类明细”，不猜测分类或 provider usage |
| CLI 授权过期/失败 | gate 原位显示稳定安全提示与 retry/cancel；不输出原始 CLI 内容 |
| 文件打开失败 | 显示稳定领域错误；不绕过安全反查 |
