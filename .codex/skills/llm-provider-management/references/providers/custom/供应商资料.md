# 自定义 API / 兼容网关

> 官方资料复核日期：2026-08-11

## 官方资料入口

自定义 API 没有统一供应商官方文档。为每个实际网关保存并核对：

- 网关/云厂商官方 API reference；
- 明确协议页，而不是只写“OpenAI compatible”的首页；
- 鉴权、Base URL、区域、模型、缓存、推理、用量、价格和限流页；
- 网关版本、复核日期和最小实测记录。

参考协议原始合同：[OpenAI Chat](https://platform.openai.com/docs/api-reference/chat)、[OpenAI Responses](https://platform.openai.com/docs/api-reference/responses)、[Anthropic Messages](https://platform.claude.com/docs/en/api/messages)。这些链接只定义 shape，不证明自定义网关实现完整。

## Awaken 当前接入

- provider ID：`custom`；access type：`custom`。
- 用户显式选择 `openai_chat`、`openai_responses` 或 `anthropic_messages`，并填写 Base URL、鉴权方式和模型 ID。
- Awaken 不请求 `/models`，不提供官方候选，不从 endpoint 名称自动猜协议。
- 可保存 Bearer、`x-api-key`、`api-key`、`x-goog-api-key` 或无鉴权等受控 scheme；不接受任意秘密 Header。

## 三协议兼容矩阵

| 协议 | 官方合同 | Awaken 当前 | 结论 |
| --- | --- | --- | --- |
| Chat Completions | 由实际网关声明 | 可选 `openai_chat` | 只有用户声明 + 网关官方文档 + 实测后才支持 |
| Responses | 由实际网关声明 | 可选 `openai_responses` | 不能从 Chat 兼容推断 |
| Messages | 由实际网关声明 | 可选 `anthropic_messages` | 不能从 SDK/模型名推断 |

## 鉴权、端点与模型

- Base URL 保存到 profile，adapter 再拼接对应 endpoint；先检查是否已包含 `/v1` 或协议前缀，避免重复路径。
- 模型 ID 始终手填；连接测试只验证当前 ID，不创建目录事实。
- 代理、聚合网关、自托管服务和企业中转都要使用各自官方/内部合同；上游模型厂商文档不等于网关文档。
- 凭据 revision、Base URL、protocol 和 model 任何一项变化都形成新的 capability/cache scope。

## 上下文、多模态与工具

- 默认全部 unknown；视觉输入在运行时按 `false` fail closed。
- 自定义连接弹窗提供唯一受控例外“视觉多模态”：用户开启后，只对当前 exact profile 声明网关、协议和模型接受图片输入，并允许 PDF 页面图片回退；关闭或旧配置未声明时不下发图片。
- 该开关不能声明原生 PDF、视频、tools 或 cache。Core 对自定义 profile 始终保持 `supportsNativePDF=false`；其余能力仍需网关官方合同、受控 capability override 和真实 adapter 测试共同证明。
- 网关可能过滤 tool schema、缩小 context、重写模型或不支持 stream；必须测实际路径。
- 开启视觉输入后 PDF 可走页面图片回退，不绕过 capability gate，也不把成功回退升级成原生 PDF 事实。

## 提示词缓存

- 默认不发送私有 cache 字段，也不显示命中。
- 只有 profile 的受控 `supports_prompt_cache` 事实与所选协议合同一致时，才采用对应通用 wire strategy。
- 即使上游模型支持缓存，网关也可能不透传 `prompt_cache_key`、`cache_control` 或 cached usage。
- 缺失 cached usage 保持未知，不能从低延迟猜命中。

## 推理开启关闭

- 默认无开关合同。不得根据模型名向任意自定义 endpoint 发送 `thinking`、`enable_thinking` 或私有字段。
- 要支持时建立 exact gateway/base/protocol/model 白名单或明确 profile capability，并覆盖拒绝未知 endpoint 的测试。

## 推理强度

- 默认不展示 effort。上游模型支持不代表网关透传。
- 建立映射时记录原生字段、可用档位、默认值、thinking 关系和 stream 返回形态。
- Awaken 内部仍只保存 `low | high | max`，显示标签可来自网关合同。

## 用量、余额、限流与套餐

### 用量查询合同

- A 类：per-request usage 可能被网关重写或省略；原样保留 raw typed usage，并把缺失字段保持 null。
- B/C/D 类只有在实际网关官方文档明确给出 endpoint、鉴权、权限、区域和响应 schema 后才能配置；没有统一余额/账单 endpoint。
- 凭据：管理 API 和推理 API 分开配置，不从 Base URL 自动探测高权限路径，也不把上游厂商的管理合同自动套到代理网关。
- Awaken 当前：`custom` 没有通用余额查询；只记录推理响应 usage，缺失字段不补 0。

- 自定义网关价格、加价、套餐、限流和数据保留以网关合同为准，不使用上游公开单价计算。
- 企业网关还要记录租户、区域、审计、代理、证书和数据出境边界。

## Awaken 落地规则

- 自定义 endpoint 的核心是用户声明协议，不是 Awaken 猜协议。
- 连接测试通过不提升 capability；动态 observation 只在 exact scoped identity 内有效。
- 不把某个自定义网关的私有 workaround 写进通用 OpenAI/Anthropic adapter；先建立 provider-specific route 或 capability。
- 若网关成为正式内置供应商，为它新建独立目录和 provider ID，不长期藏在 `custom`。
