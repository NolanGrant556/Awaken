# 连接配置与认证 · 需求文档

MCP 连接支持不同配置来源和传输方式。用户可以保存、更新、删除连接及完成受支持的认证流程，失败后保留可诊断的状态。

代码、接口和验证方法见[实现方案](实现方案.md)。

## 管理面

HTTP 管理面可读取 snapshot、增删改 effective config、启停 server、发起认证，以及读取 builtin/MCP tool 摘要。有有效 default workspace 时，同名 project 配置是读取、修改、启停和删除的 effective owner；删除 project override 后必须恢复同名 user fallback。没有 project override 时操作 user config；即使没有 default workspace，user scope 仍必须完整可用。enable/disable 写回 effective owner 的 `enabled` 并用同一配置重建 Manager entry；POST/PATCH 收到 `enabled:false` 时只建立 disabled entry，不连接 transport。route/method 的唯一清单在 09 域。Desktop 不得直接持有 MCP session 或绕过 ToolRuntime 调用。

OAuth authorization code session 由 Manager/Core 监听随机 loopback callback、校验 state、完成 PKCE、CIMD/DCR、token exchange 和持久化，不再依赖 Electron 跨进程安装 `AuthorizationCodeFetcher`。管理面 start 返回一次性 authorization URL 与 session ID；Main 打开网页，Renderer 只轮询脱敏状态并可取消。插件 MCP 原声明可用 `oauth_resource`、公开的 `oauth_client_id`、非根路径 public HTTPS `oauth_client_metadata_url` 与 `oauth_scopes` 补充 discovery；没有预注册 client/CIMD 时，DCR 按 public native client 请求 `token_endpoint_auth_method=none`。credential identity 按 scope、server、endpoint、client、resource 与 scopes 指纹隔离；插件声明的通用 OAuth binding 则由 Plugin Auth Broker 以 plugin/setup/fingerprint identity 提供 host-owned OAuthHandler，token 不写入 MCP config。OAuth HTTP client 对初始 discovery/registration/token 请求和 redirect 执行 public HTTPS/loopback、DNS 与私网检查。

具备宿主静默刷新能力的 HTTP/Streamable HTTP 连接，只对已确认只读调用恢复明确 OAuth 401 challenge。相同凭据身份最多刷新一次、原请求最多补发一次，SDK 与授权续接共享同一额外发送预算。403、新增权限、刷新失败或第二次 401 进入 needs-auth。通用写操作不因登录成功自动重放；插件/Outlook 的既有续接仅在确认业务尚未执行、身份未变且预算未使用时保留。工具业务结果中的第三方 API 401 不触发 MCP 凭据刷新。

## 当前缺口

- live scope replacement 尚无统一 generation owner；
- stdio server child 当前仍由 MCP transport 直接 `exec.Command` 启动，尚未接入 WorkspaceExecutionBroker/Seatbelt。connected/auth-ready 的 MCP tool 默认可自由调用，adapter 不对 message/delete/mutation 建立额外宿主 gate；该子进程也可在启动代码、后台任务或实现内部自行读取/写入宿主文件或联网。MCP 路径不具备 typed provider 的 TaskScope、Trash 或完整副作用观测保证；消息发送则在所有 provider 路径上都没有 Awaken 人工审核门；
- WebSocket 不支持；
- production in-process 注入不属于当前能力；
- route generation 变化期间，正在执行的 stdio tool call 不被取消或透明重放；如果它恰好因切换失败，仍由对应工具按回读/幂等合同收口。任意中途断网的透明续流和多实例 OAuth session owner 仍未提供；
- Windows/Linux 真实 MCP CLI、PATH 和 Desktop 生命周期未在本轮实机验收。

## 当前支持

stdio server 可使用 MCP config 中显式 env/args；HTTP/SSE 可使用 headers 与 OAuth。部分 provider 把不可拆分的访问 key 作为固定 endpoint URL 的 query 参数；这类完整 URL 属于 MCP config，随 user/project 配置以 `0600` 保存，并按敏感配置处理，不进入日志、提示或验收截图。它不转换为 OAuth token source。OAuth token source 由 `PersistentCredentialStore` 分层保存：

metadata 文件不保存 access token、refresh token、client secret、Authorization header 或 secret env value。所有 metadata mutation 先取得同目录跨进程锁，再读取最新完整文件并通过 FileStore 原子 replace 写入，目录保持 `0700`、文件保持 `0600`；损坏 JSON fail closed，不当作空 accounts 覆盖。

Desktop/Core 正式使用 `AWAKEN_HOME=~/.awaken`。测试必须注入隔离根与 fake secret backend；没有任何根的独立调用使用临时目录，不隐式触碰真实用户 metadata。

## 保存、更新与删除

保存前必须先完整读取并校验 metadata。credential identity 由 effective scope、server name 与 canonical endpoint 共同确定；同一 identity 的更新复用已有 `credentialRef`，首次保存生成 UUID。secret 写入成功后才原子发布 metadata；metadata 写失败时恢复此前 secret，首次写入则删除未被引用的新 secret。回滚失败与原失败合并上报，不能宣称保存成功。

删除先读取旧 secret 作为回滚值，再删除 secret 和 metadata；metadata 写失败时恢复旧 secret。成功后该 scoped endpoint identity 不再有 credential ref。管理面删除 server、builtin Connector disconnect 或修改 endpoint 时清理旧 identity；删除 project override 不得清理其下方同名 user identity。删除只操作当前 metadata 中该 identity 的 ref，不能按显示名清理其他 scope/endpoint 的秘密。外部直接编辑或删除配置文件不会触发主动清理，但新 identity 无法读取旧 token；加载到 metadata 的 `serverUrl` 与当前 canonical endpoint 不一致时也会 fail closed 并清除该条 metadata/secret。

由于系统 secrets backend 与 JSON 文件不存在共同事务，进程崩溃仍可能发生在两者调用之间；启动只信任已发布 metadata，无法从 keyring 枚举结果发明 account。没有 metadata 的孤立 secret 不获得产品 authority。

## 当前不支持与缺口

- 不支持把 OAuth access/refresh token、client secret、Authorization header 或 secret env 明文写入 `~/.awaken/.env`、`~/.awaken/config/mcp-servers.json`、`awaken.mcp.json` 或 connector metadata；provider 强制绑定在 endpoint query 中、无法拆分为 header/OAuth 的 opaque access key 只作为完整 URL 配置保存，仍按敏感值处理；
- 不支持从当前 metadata 和 secrets backend 之外自动导入 connector account；
- dynamic client registration、特殊 OAuth provider 与浏览器回调尚无完整全平台矩阵；
- WebSocket 认证不支持；
- 多 Desktop 实例/旧 Manager session 的统一 generation owner 未完成；
- 系统 secrets backend 与 metadata 的 crash-atomic transaction 不存在；
- Windows Credential Manager/Linux secret service 的发布验收不能从 macOS Keychain 推断。

## 静默恢复与退出边界

静默路径不打开浏览器、不扩大 scopes、不更换账号，只使用既有 credential store 的 refresh token。只读资格复用静态声明与混合工具读操作规则，声明缺失或矛盾时不重放。SSE、固定 header 和无静默刷新能力的 Handler 保留现有认证入口，不承诺透明恢复。认证失败与副作用状态分开保存，进入 transport 后不能一律标成尚未执行。

关闭时立即禁止新连接、新调用和排队调用启动，取消待答交互并关闭 transport 解除等待；超时报告清理失败，不假称全部调用已退出。表单仍只活在当前连接内存，不跨重连续填，不把答案写入 Journal。
## 共享依赖与执行路径

stdio MCP 的已识别包启动模式可复用共享依赖；连接配置与认证仍独立管理，缺依赖不等于需要重新授权。目录、来源、安装和回收规则见[依赖与路径管理](../../03_运行时与本地服务/依赖与路径管理/需求文档.md)。
