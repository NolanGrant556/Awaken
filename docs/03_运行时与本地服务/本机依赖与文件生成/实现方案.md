# 本机依赖与文件生成 · 实现方案

本文说明代码职责、数据与接口、异常恢复和验证方法。功能范围及用户操作见[需求文档](需求文档.md)。

## 环境观察

`ExecutionEnvironmentSnapshot` 在 run 开始观察 OS/arch、workspace/cwd、登录 Shell、完整 transport PATH digest 与有界诊断预览、可执行文件、包管理器、workspace marker 和 Skill roots。Desktop 由 Finder 等 GUI 入口启动时，supervisor 优先读取当前用户交互式 login 环境，失败后回退非交互 login 环境和 Electron 进程环境；环境值和秘密不写日志。

`Bash` 使用同一固定环境，可访问网络、项目外用户目录、包管理器、Skill 安装脚本与系统 CLI。环境快照是观察，不是安装许可列表。

## 开发、打包与旧数据

`open:desktop`、`dev:desktop`、`build:desktop`、`dist:desktop` 均不准备 Work 环境。安装包只携带 Desktop、当前架构 Core 和产品自身必需资源，不携带 runtime archive。

开发版与安装版使用各自应用身份和 userData；业务根按[数据存储规则](../数据存储与重放/实现方案.md)由 Main 注入。共享依赖由该根解析，不能从应用身份不同推断会话或环境数据全部隔离。旧 `<userData>/runtimes/primary-runtime` 仅是历史可再获得缓存；一次性精确路径清理失败不得阻止 Desktop 启动。

## 代码位置

- `apps/desktop/src/main/runtime-supervisor.ts`：登录环境解析与 Core 注入。
- `src/tool/environment_snapshot.go`、`environment_path_probe.go`：run 环境观察。
- `src/tools/bash`：当前登录用户 Shell。
- `src/tools/read`：PDF 的 Poppler dependency route。
- `src/tools/artifact_publish`：生成后的交付物发布；不负责依赖安装。
- `apps/desktop/src/main/legacy-runtime-cleanup.ts`：旧 primary runtime 一次性删除。

## 必须保持的规则

- Desktop/Core 启动不以 LibreOffice、Poppler 或 Office Python 包存在为前提。
- `Write`/`Edit` 不自动发布 Artifact。
- Bash 进程成功或文件存在不等于格式、版式或业务内容通过。
- Office `--json` helper 不得连接会改变退出码或截断结果的 shell 管道；Bash outcome 与完整 JSON `status/issues` 必须同时通过。helper 失败后不得用裸 `soffice`/`pdftoppm` 绕过独立 profile、超时、原子替换和页数一致性合同。
- 旧 typed Office Artifact 记录继续可重放；兼容 Renderer 不代表旧 producer 仍可调用。
- 固定办公包的目录、取消、激活、已完成验证和剩余缺口见[依赖与路径管理](../依赖与路径管理/实现方案.md)。本地候选通过真实任务不等于公开下载或 Windows 实机验收通过。

## 代码位置 与验收

- `src/tools/artifact_publish` 与 04 域 Artifact 契约：当前发布链。
- `src/tool/environment_snapshot.go`、`src/tools/bash`：当前用户依赖发现与执行。
- `src/runtime/journal_store.go`、Desktop reducer：历史 Artifact 回放。

验收必须区分“生成命令成功”“基础文件校验通过”“Artifact 发布成功”“逐页视觉通过”四层事实。逐页视觉通过还必须能列出本轮实际读取的最终页图；未读取页、旧预览或只打开部分页面不能计入覆盖。没有真实应用打开或渲染证据时，只能声明前三层实际通过项。
## 共享依赖与执行路径

`ExecutionEnvironmentSnapshot` 保持 run 的历史观察；`managedenv.Binding` 只影响之后的执行，不改旧快照。Office doctor 保留虚拟环境中的 Python 启动路径，不解析成基础解释器；Word/Excel/PPT doctor 与执行 helper 共用 `office_runtime.py` 的路径解析，三份独立 Skill 随包副本由一致性测试约束。Awaken 内缺少绑定或路径越出办公根时均不回退系统；Typst helper 只解析宿主路径，旧 install 调用提示统一入口，不自带下载安装器。Node 启动器处理跨项目 CJS/ESM 模块查找。目录、来源、安装和回收规则见[共享环境实现](../../03_运行时与本地服务/依赖与路径管理/实现方案.md)。

简化模型入口、统一 Office 启动器及默认 Skill 路线已经接入；公开资源与平台验证范围由依赖管理域维护，本功能不另行定义包选择、下载或系统软件优先级。生成、结构检查、公式重算、逐页视觉和发布继续分别验收。
