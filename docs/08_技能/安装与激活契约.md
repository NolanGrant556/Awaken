# 安装与激活契约

## 1. 目录暴露

模型只看到一个 `skill` 工具，而不是每个 Skill 一个 tool schema。其输入是 Skill ID/名称与可选参数。目录描述预算约为模型上下文窗口的 1%，按约 4 chars/token 估算；默认上限约 8,000 字符，单条说明（description 与 whenToUse 拼接后）最多约 250 字符。超出预算时分三级降级：完整描述 → 按剩余预算在全部条目间均摊截断描述（每条不低于约 20 字符）→ 均摊后低于该下限时整体退化为 names-only。这样目录规模不会线性挤占任务上下文，也不会在预算轻微超限时就丢光全部描述。

统一 `skill` 工具使用幂等注册：相同 runtime 实例和相同已解析 definition 的 refresh 保留原 `RegistrationID` 与 Tool Registry generation；模型可见 Catalog 改变、`SKILL.md` 调用 binding 改变或 Manager 的真实 runtime callback/provider binding 改变时才建立新注册。`RegistrationID` 继续作为 run 工具快照的执行 pin，不能为了消除刷新噪声退化成只按工具名或 schema hash 复用。

Desktop 管理面投影 `sourceOrigin`、锚定路径、状态、诊断、deprecated warning、shadowed owner、`userInvocable`、`modelInvocable` 与最近调用时间。Slash 只展示 `loaded && userInvocable != false` 的条目，不以来源限制 project/user；MCP、plugin 等来源满足条件时也可以出现。

Skills 管理页默认打开 Awaken Skills，视图顺序为 Awaken、项目、全局。bundled 只进入 Awaken Skills，来源标签为“Awaken 内置”，且完全不渲染删除入口。只有由 Awaken 安装生命周期拥有的 project/user 包可执行删除：project 对应某个已发现文件夹的 `<folder>/.awaken/skills/<package>`，user 对应 `~/.awaken/skills/<package>`；MCP、managed、additional、plugin 与 legacy 等其他非安装根来源保留卡片入口但明确禁用，不得由 Renderer 根据展示路径直接删除。具体页面行为由 [技能页产品与架构](../01_桌面工作台/扩展管理/技能页产品与架构.md) 拥有。

## 2. 调用与正文加载

模型调用触发规则是宿主 Prompt 契约，不是宿主侧词法/语义匹配，且只有唯一权威文本，不在多处重复维护：`catalog_tool.go` 的模型描述在目录清单前固定携带完整触发规则——用户显式点名 Catalog 中可用的 model-invocable Skill 时必须调用；任务明显匹配某个 Skill 的描述时，调用它是阻塞性要求（必须在该部分任务的普通工具动作之前完成）；多个 Skill 匹配时选择覆盖任务所需的最小集合并声明顺序；已在上下文中的 Skill 不重复调用；没有匹配时按正常工具流程执行，不为了调用而调用。这份规则置于 Catalog 的 1% 预算之外，且随统一 `skill` 工具的 schema 每轮请求一起真实注入，不依赖静态系统提示词的一次性内容。系统提示词的“Skill 选择与调用”节只做一句指向，不重复列出规则；File Tool Priority 中 Office 产物一条据此把 typed artifact provider 定位为匹配 Skill 未规定路径时的执行载体，而不是排在 Catalog 匹配之前的默认选择。自然语言点名仍由模型发起 `skill` 工具调用，其 runtime provenance 是 `InvocationModel`，不会绕过 `disable-model-invocation`；只有 Composer/Slash 结构化 token 预激活才是 `InvocationUser`。是否真正匹配仍由模型判断，宿主不做候选生成或子串匹配。

调用有两条入口：

- 用户显式 Slash token：即使 `disable-model-invocation` 为真仍可调用；
- 模型调用统一 `skill` 工具：`disable-model-invocation` 为真时拒绝。

Runtime 以 token 中的 Skill ID 查当前 registry，并核对当前来源与锚定路径；renderer 路径不是授权来源。激活成功后才更新最近调用时间。

正文在调用时从锚定 `SKILL.md` 或 MCP body fetcher 重新读取。注入上下文包含正文、包根和锚定路径，便于后续按需重读；Windows 的本地包根在模型正文和 `${AWAKEN_SKILL_DIR}` 替换中统一使用正斜杠，既保持绝对路径身份，也避免 POSIX Shell 把反斜杠当转义字符。安装时或目录发现时不 preload 全包资源。

用户从 composer 选择 Skill 时，成功的预激活还会产生 host-owned `ComposerSkillSelection`。该绑定只在当前 run 有效，包含 `skill_id`、registry 校验后的 `source`、`activation_mode`、`invocation=user_composer`、Skill 绝对包根和 `SKILL.md` 绝对路径。

定时任务的 Agent 编辑器复用同一 Slash provider 和结构化 token，而不是把 Skill 名称写成普通 prompt 文本。任务定义可以持久保存 token identity，但不保存 Skill 正文；每次计划触发都把 token 作为该次新 run 的 Composer 选择重新预激活，并重新核对当前 Registry、来源和锚定路径。因删除、禁用用户调用或换源而失效的 token 必须让该次定时 execution 失败，不能静默回退到同名或模型自行选择的 Skill。提醒任务不接受 Composer token。

RequestBuilder 在 Skill 正文之后追加该选择块，因此正文不能伪造宿主选择。单选时，用户说“这个”或“刚选的 Skill”直接指向该 identity；多选时按 token 顺序保留并标记单数指代歧义。历史恢复、model-invoked Skill 和 fork child 可持有各自 SkillContext，但不会冒充父 run 的本轮 composer 选择。

## 3. 包资源

`skill_resource_read` 对包内文本资源提供专用读取边界：

- discovery 在 `SkillDefinition.SourceRoot` 记录 host-owned source root，并同时固定包 `ResolvedRootDir`；读取时重新解析当前包 realpath，包根改变即拒绝；
- project/user/managed/additional/plugin/bundled 和 nested legacy 都从 source-root `os.Root` 打开，包必须是该授权 root 的单层子包；flat legacy command 与 MCP Skill 不暴露本地包资源；
- 拒绝 symlink escape、目录、特殊文件和包外路径；
- 单文件最大 2 MiB；
- 只返回 UTF-8 文本；二进制返回 `skill_resource_binary`，调用者改用对应 file/artifact 工具。

`skill_resource_read` 不返回二进制字节；binary assets 仍转交匹配的 file/artifact provider，并继续受其 TaskScope/readiness 契约约束。

## 4. 工具与依赖语义

Skill 激活不会修改 `RunToolAvailabilitySnapshot`，也不会注册 per-Skill 工具。`allowed-tools`、required tools/capabilities/runtime、connector/MCP readiness 都只作为选择提示、诊断或 receipt。真正能否执行由父 run 的固定工具快照、provider readiness 和被选工具的实际合同决定；Skill 不得通过正文扩大 typed provider 的权限，但默认 raw Shell 本身就是当前登录用户的本机执行面，不要求 Skill 专项授权。

这意味着“Skill 可加载”与“它建议的某个执行路径当前可用”是两件事；后者失败时返回结构化工具结果，不回写成 Skill `unavailable`。

Skill 包中的 `.py`/`.mjs`/`.sh` 等脚本在 discovery、安装或激活时都不由宿主自动执行。它们在用户/模型根据 Skill 工作流显式发出 Shell 调用时，以当前登录用户的真实本机环境执行。这条路径可以读写 Skill root、用户缓存和 workspace 外目录，也可以访问网络；它不再依赖 private Workspace staging、Seatbelt 或 TaskScope 先行批准。Shell receipt 只证明直接本机进程事实，不冒充全部脚本副作用的可恢复保证。

首次初始化由 Skill 正文指导 Agent 自行执行，例如在包根 `npm install` 或 `pip install`。依赖可驻留在用户级 Skill 目录中供后续 run 复用；Awaken 不需要根据 `package.json`、requirements 或某个 Skill ID 建立私有安装器。

## 5. SemanticJournal、压缩与重启

成功激活在执行前写入 `skill_activated`；资源读取写 receipt。inline Skill 上下文可从耐久记录重建：

- 压缩时按最近调用优先；
- 单 Skill 最多约 5,000 tokens；全部 Skill 合计最多约 25,000 tokens；
- 被截断的上下文保留锚定路径和重读提示；
- 服务重启从 semantic records 恢复 run 的 SkillContextBlocks。

fork 的正文属于 child，不注入父 run 的后续上下文；父子调用记录不得互相污染。

## 6. 安装边界

`skill_install` 当前支持 `content`、`content_base64`、`local_path`、`remote_url` 和 `remote_git`，目标只有 project（默认项目主文件夹的 `<workspace>/.awaken/skills`；用户在 Desktop 明确选择其他文件夹时使用该文件夹）或 global/user（`~/.awaken/skills`）。包可以是 `SKILL.md`、zip 或含唯一根 `SKILL.md` 的目录；最多 1,000 个文件、解包内容 50 MiB，拒绝 symlink、路径逃逸和非法包。

Desktop 安装弹窗同样只提供 project/global。bundled 是产品构建资源，不是用户安装 scope；不得通过现有安装 API 或页面创建 bundled 包。

`remote_git` 只接受无 inline credential 的绝对 HTTPS URL，可选安全 ref/subpath；Git 禁用 credential helper、交互、file/ssh/git/http protocol，并使用最小环境。这是 `skill_install` typed provider 自身的来源合同，不限制 Agent 在 Skill 已安装后按正文使用默认 Shell 准备依赖。

同 ID 默认 `abort`。显式 `replace` 通过 staging、旧包 backup 和新包原子 swap，再将旧包移入平台 Trash；Trash 失败会回滚新旧包并 fail closed，不永久删除。Outcome 记录 `previous_package_trashed_path`（平台可提供时）。安装后默认 reload registry，也可显式关闭。安装成功的 next action 指向统一 `skill` 工具，并携带 `input_hint.skill`。安装器不得在发现、解包或激活阶段擅自执行包代码；Skill 进入 Agent 上下文后，初始化命令由 Agent 通过普通 Shell 调用显式执行，并以真实命令输出进行恢复。

Desktop 删除使用 `DELETE /v1/skills/{id}`，请求同时携带 host-facing `sourceOrigin` 与项目根。Core 不信任 Renderer 展示的 `rootDir/skillFilePath`，而是根据 project/user 安装根重新发现并锚定对应包；只允许删除该根的直接子目录。确认删除后，完整包同步移出 `.awaken/skills` 并进入平台 Trash，成功响应前重载当前 Registry；Trash 不可用、包是 symlink/特殊文件、来源不是 project/user、包已不存在或路径不属于受控安装根时均 fail closed，不回退永久删除。plugin 来源由 [14 插件](../14_插件/索引.md) 拥有生命周期，Skills 删除 API 拒绝该来源。删除不会从已完成 run 的历史记录中抹除既有 `skill_activated` 事实；后续新 run 与目录刷新不再看到该包。

## 7. 代码 owner

- `src/skillruntime/catalog_tool.go`、`catalog.go`、`manager.go`、`resource_tool.go`：调用、模型调用触发规则文本、目录三级降级、正文和资源边界。
- `src/skillruntime/install_tool.go`、`install_git.go` 与 `src/skills/install.go`：受控来源、包校验、原子安装和 Trash replace。
- `src/skills/delete.go`、`src/server/handlers_skills.go`：project/user 包删除、来源重解析、Trash 与同步 Registry reload。
- `src/agentcore/skill_context.go`、`composer_skill_selection.go`、`request_builder.go`、`agent.go`、`runner.go`：运行上下文、当前 composer 选择绑定、压缩恢复、重复激活去重和 fork 接线。
- `src/prompt/templates/default_system.md`：指向 `catalog_tool.go` 触发规则的最简提示（不复制规则原文），以及 Office 产物生成时 Skill 与 typed tool 的优先级关系。
- `src/runtime` SemanticJournal 链路：耐久顺序与重启恢复。
