# Desktop外观与主题产品及架构契约

## 1. 权威范围

本文唯一拥有 Desktop主题偏好、存储、系统跟随、token边界和真实验收。Design System各token的具体值由其自身文档/源码拥有。

## 2. 当前支持

Settings > 外观提供：

- 跟随系统 `system`；
- 浅色 `light`；
- 黑色 `dark`。

左侧栏个人入口弹层依次左对齐展示“外观”“查询用量”“设置”，默认无卡片表面，仅在悬停或键盘聚焦时显示灰色反馈。点击“外观”后在菜单右侧打开小型竖向主题选择窗，可切换 `system | light | dark`，选择后收起；它与 Settings > 外观读取、保存同一份偏好并同步选中状态，不建立弹层局部主题。“查询用量”点击后打开独立用量窗口。

未有偏好时默认 `light`。选择即时应用到主窗口；保存失败时UI回滚到前一偏好并显示错误。

Desktop 设置当前使用覆盖内容窗口的全窗口工作区：保留 Electron 原生窗口 chrome，左侧固定“返回应用”和模型、搜索、记忆、外观、宠物、ACP 六个现有入口，右侧显示当前设置页。这六个入口连同各自图标由 Design System 的 `AwakenSettingsNavItems` 唯一定义，Desktop 直接消费，不自行追加导航条目。它不再套居中 `AwakenDialog`，也没有 backdrop、外层圆角卡片、右上角关闭按钮或底部关闭栏；返回按钮与 `Escape` 关闭设置并恢复到原工作台。

设置工作区的标题、导航、标签、说明和其他控制文案默认不可被鼠标选择，避免双击界面空白时出现网页式高亮；输入框、文本域、可编辑区域和显式 `.aw-text-selectable` 正文保留选择与复制能力。该边界由 Design System 的 `AwakenSettings` 统一实现，Desktop 不为单个设置页重复覆盖。

## 3. 偏好与生效主题

存储偏好类型：

```ts
type AwakenThemePreference = "system" | "light" | "dark";
type AwakenTheme = "light" | "dark";
```

`system` 不是CSS主题值：

- Electron Main用 `nativeTheme.shouldUseDarkColors` 决定窗口backgroundColor；
- renderer用 `matchMedia('(prefers-color-scheme: dark)')` 决定DOM实际主题；
- 系统外观改变时，只有preference=system跟随更新。

## 4. 存储与启动

最终来源是Electron Main `DesktopPreferencesStore`：

```text
<userData>/config/desktop-preferences.json
{ "version": 1, "theme": "light|dark|system" }
```

无文件、无效JSON或未知值归一到light。Renderer另写localStorage镜像 `awaken:appearance:theme`，用于React初始状态和减少启动闪烁；main加载成功后覆盖镜像状态。镜像不是最终来源。

DOM应用：

```text
html[data-aw-theme="light|dark"]
html[data-aw-theme-preference="system|light|dark"]
style.colorScheme = light|dark
```

主进程保存后只同步更新主窗口背景，避免主窗口在透明/加载阶段露出错误底色；独立透明浮窗（如宠物窗口）保留自身透明背景，不随主题更新。

## 5. 样式ownership

- 颜色、surface、text、border、status、composer等通用语义优先在 `Awaken Design System/src/tokens/` 定义。
- 浅色主题采用接近纯白的中性表面：canvas/work/raised 使用白色，navigation/panel/code 只使用轻量中性灰层级，不以暖石色作为基础；深色主题保持独立 token。
- 全产品布尔启停统一使用 Design System `AwakenSwitch`：开启为成功绿色，关闭为中性灰色。关闭只是状态而不是错误，不得以危险红色表达；业务组件只持有状态和回调。
- Desktop renderer只做场景级覆写，不在业务组件按主题分支渲染不同DOM。
- 设置框架和五个页面的布局/样式由 Design System 的 `AwakenSettings`、`AwakenModelSettings`、`AwakenSearchSettings`、`AwakenMemorySettings`、`AwakenAppearanceSettings`、`AwakenPetsSettings` 拥有；Desktop 只注入真实状态和回调。
- 记忆分区的 `AwakenMemoryLightFlow` 只接收 renderer 已解析出的当前生效 `AwakenTheme`；不得为该装饰新增独立主题偏好或设置入口。
- 新颜色先寻找/补充语义token，禁止到处新增hex/rgb magic value。
- 浮层层级只用 `--aw-z-dialog`、`--aw-z-popover`、`--aw-z-tooltip` 三个token表达，禁止在组件里写裸 `z-index` 数字。`AwakenDialog`、`AwakenPopover`（含 `AwakenDropdown`）、`AwakenTooltip`、`AwakenProjectHoverCard` 都 portal 到 `document.body`，彼此在根堆叠上下文里是兄弟；菜单/提示/悬浮卡随时可能由对话框内部控件触发，必须排在对话框之上，否则会挂载成功但被背板遮住，表现为「点了没反应」。
- brand wordmark使用 `--aw-brand-wordmark-filter`。
- 顶部chrome使用 `--aw-surface-chrome`，dark时不得比主工作区明显更浅。

## 6. Composer主题边界

Dock composer依靠RunStage真实底部留白避让内容；不得用全宽大面积渐变或 `backdrop-filter` 遮住历史。

允许随composer宽度收缩的局部 `--aw-composer-halo` 羽化；禁止重新引入白/灰/黑的全宽矩形雾化区。composer层级使用：

- `--aw-composer-surface`；
- `--aw-composer-border`；
- `--aw-composer-shadow`；
- `--aw-composer-shadow-focus`。

该边界同时受中间区域架构/验收约束。

## 7. 当前不支持

- 自定义主题/色板；
- 除light/dark外的主题；
- workspace级主题；
- 账号云同步；
- 业务组件级独立主题结构；
- 自动高对比模式开关（依赖系统/现有token表现）。

## 8. 异常与恢复

- 主偏好读取失败：保留localStorage镜像或默认light；
- 保存失败：renderer回滚并提示；
- 未知存储值：归一light；
- system matchMedia不可用：renderer fallback light；
- Main与renderer短暂不同步：最终以main返回偏好收敛。

## 9. 测试与真实验收

自动化：

- `apps/desktop/src/main/desktop-preferences-store.test.ts`：默认、dark、system、未知值。
- `apps/desktop/src/renderer/settings/DesktopSettingsDialog.test.ts`：全窗口设置框架、无外层 Dialog，以及三种主题选项和 selected 状态。
- `Awaken Design System/src/components/AwakenThemeChoiceGroup`：Settings 主题选择的 UI-only 实现；Desktop 持有偏好保存与回滚。
- `apps/desktop/src/renderer/settings/MemorySettingsPanel.test.tsx`：记忆光流随当前生效主题渲染，且不改变既有 Memory 设置入口。
- `npm run typecheck:desktop`、`npm run typecheck:ui`、`npm run smoke:ui`。

真实Desktop：

1. 三种偏好逐一切换并确认即时生效；
2. 重启后保持；
3. system下切换OS外观；
4. 检查主工作台、Settings、popover、center/dock composer、按钮、附件；
   同时确认 Settings 覆盖内容窗口、保留原生窗口按钮，左右分栏没有外层弹窗卡片、右上角关闭按钮或底部关闭栏，并可通过“返回应用”和 `Escape` 返回；双击标题、导航、标签与说明不产生文字选择，搜索/配置输入框和显式可复制正文仍可选择；
5. dark下wordmark白色、chrome无浅色横带、附件删除按钮可辨识；
6. light/dark均无全宽矩形composer雾化。
