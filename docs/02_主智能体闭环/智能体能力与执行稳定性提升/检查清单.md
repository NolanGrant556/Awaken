## 3. 协议静态检查

### 3.1 ToolOutcome

- [ ] 仓库只有一个 canonical ExecutionOutcome 定义。
- [ ] Status、TransportStatus、SemanticStatus、ProcessStatus、ErrorCategory 枚举与实施方案完全一致。
- [ ] ToolExecutionResult 兼容字段由 outcome 派生，不存在反向推断。
- [ ] Go error 只代表 transport 或 implementation 异常。
- [ ] process nonzero、deny、needs_auth、needs_runtime、unsupported 均通过 outcome 表达。
- [ ] ToolResult event 携带结构化状态、错误、重试、进程和耗时字段。
- [ ] Anthropic 和 OpenAI provider 均保留失败语义。
- [ ] Desktop 不通过 content、中文错误文本或字符串包含关系判断结果状态。

禁止项：

- [ ] 不存在新增的第二套 IsError 业务判断。
- [ ] 不存在把 exit_code=1 一律标记成功的逻辑。
- [ ] 不存在 Runner 和 ToolRuntime 对同一次活动重复发通用进度。

### 3.2 SemanticJournal

- [ ] v2 record 有 schema_version、kind、record_id、seq、parent_id。
- [ ] user_message、每轮完整 assistant_message、tool_call、tool_result、artifact、file_change、turn_diff、turn_boundary、terminal 均为耐久记录。
- [ ] stdout delta、spinner、token tick 没有被无差别永久写入。
- [ ] tool_call 在副作用开始前成功落盘。
- [ ] tool_result 与 artifacts 使用同一 AppendBatch。
- [ ] applied file_change 与 tool_result/artifacts 同批提交；turn_diff 在 turn_boundary 前提交。
- [ ] terminal flush 执行 file.Sync。
- [ ] Append、Flush、Close 的 error 全部可达调用方。
- [ ] agentcore.SemanticRecorder 是耐久写接口；EventSink 只在写成功后负责直播，不隐藏 journal 写入。
- [ ] Runner 对 durable fact 的调用顺序固定为 SemanticRecorder 成功后再 EventSink。
- [ ] 正式 StartRun 缺 recorder 返回 persistence_unavailable；noop recorder 不进入可执行副作用的产品路径。
- [ ] journal 失败后 run 进入 persistence_degraded 并停止新的副作用。
- [ ] v1 只读 adapter 可从 assistant tool_calls 和 tool message 恢复工具记录。
- [ ] 新 thread 不双写 v1 message 与 v2 journal。
- [ ] live 与 replay 调用同一个 Go projector 和同一个 Desktop reducer。

禁止项：

- [ ] 不存在忽略 Append 或 Flush error 的下划线赋值。
- [ ] 不存在 Desktop 历史专用的字符串猜测 projector。
- [ ] 不存在破坏性批量重写用户旧 transcript 的迁移脚本。

### 3.3 text_edit 与 apply_patch

- [ ] text_edit 参数只有 path、old_string、new_string、replace_all、expected_sha256。
- [ ] 默认要求 old_string 唯一命中。
- [ ] 零命中返回 text_not_found。
- [ ] 多命中且 replace_all=false 返回 text_not_unique。
- [ ] digest 不匹配返回 stale_file_revision。
- [ ] 写入复用 WorkspaceFS、原子写、Trash 和 artifact 逻辑。
- [ ] apply_patch 保留高级能力，但模型默认工具池不再优先暴露。
- [ ] patch 语法在副作用前完成验证。
- [ ] invalid_patch_format 和 patch_context_mismatch 使用不同 ErrorCode。

### 3.4 SkillActivationPlan

- [ ] Composer Skill token 在首次 LLM 调用前完成激活。
- [ ] 模型调用 skill__xxx 时走同一个 SkillActivator。
- [ ] 主文、required resources、resource receipts、runtime requirements、effective tool pool 均在 plan 中。
- [ ] resource receipt 固定含 skill_id、skill_version、resource、source、sha256、size、mode、loaded_at。
- [ ] required resource 缺失，或 frontmatter 指定 sha256 后实际 hash 不符时 fail closed；未指定 expected hash 时仍记录实际 SHA256。
- [ ] effective tool pool 严格等于 base 与 allow 的交集，再减 deny。
- [ ] RequestBuilder 只向模型暴露 effective tool pool。
- [ ] ToolRuntime 对不在 effective pool 的调用再次拒绝。
- [ ] Skill 不得扩大父 run 的 TaskScope、网络和写权限。
- [ ] legacy allowedTools 被映射为 allow，但不能绕过执行侧 gate。
- [ ] legacy Artifact Skill 与平台契约冲突时返回 skill_platform_contract_conflict。

禁止项：

- [ ] 不存在仅靠 prompt 告诉模型“请主动读取 resource”的 required preload。
- [ ] 不存在用户选中 Skill 后只注入一段自然语言提示的激活路径。
- [ ] 不存在 Skill 通过 shell、pip、动态脚本规避 typed Artifact tool 的静默降级。

### 3.5 Artifact 和 schema

- [ ] Tool schema 支持递归 object、array、enum、oneOf、minimum、maximum。
- [ ] 模型侧 schema 与执行前 validator 使用同一份定义。
- [ ] validation error 返回 JSON path、expected、actual。
- [ ] presentation_create schema 能表达页面尺寸、布局、文本、图形、图片、表格、图表和备注的已支持子集。
- [ ] 未支持字段返回 unsupported，不被静默忽略。
- [ ] presentation_edit 是增量编辑或明确拒绝，不得无提示整体重建。
- [ ] PPT 生成引擎从 Go 长字符串拆成独立并由 go:embed 打包的版本化资源。
- [ ] CJK helper 只有一个实现和一个调用入口。
- [ ] XML 使用 lxml.etree.SubElement 或等价正确 API。
- [ ] Artifact verified 只有在结构、渲染和视觉规则全部满足后才为 true。
- [ ] Poppler 缺失时不得把未完成渲染的 PPT 标为 verified。

### 3.6 RuntimeManager

- [ ] Runtime 生产根目录固定为 AWAKEN_USER_DATA_DIR/runtimes/primary-runtime，并具备 versions、staging、current.json 和 state.json。
- [ ] prepare 使用 staging，probe 成功后原子发布。
- [ ] current.json 只引用 Awaken-owned root 内的 version key，并保留 previous known-good。
- [ ] state 记录版本、平台、架构、来源、各组件实际路径、探测结果和时间。
- [ ] ready 判断至少包含存在性、可执行性、版本探测、最小功能探测和 provenance。
- [ ] Node check 和 Go preflight 读取相同 resolved state。
- [ ] Node 只通过共享 userData resolver 定位生产 root，Go 正式 Desktop 路径只接受 AWAKEN_USER_DATA_DIR；测试/开发 override 仅使用 AWAKEN_PRIMARY_RUNTIME_ROOT。
- [ ] 旧外部 wrapper 只被识别为 stale，不被判定 ready。
- [ ] 一次性迁移只读取旧 Awaken cache，拒绝 Codex cache/越界 wrapper，并写 migration marker。
- [ ] 外部来源只能作为复制源，不能成为持久 wrapper target。
- [ ] RuntimeManager 内部安装活动通过宿主事件显示。
- [ ] macOS、Windows 路径和可执行文件 fixture 均有测试。

禁止项：

- [ ] 不存在持久依赖 ~/.cache/codex-runtimes 或其他产品 cache 的新路径。
- [ ] 不存在仅通过 os.Stat 就返回 ready 的路径。
- [ ] 不存在 probe 失败后仍覆盖 known-good current 的路径。

### 3.7 FailureSupervisor

- [ ] call_signature 使用 canonical JSON arguments hash。
- [ ] failure_fingerprint 去除时间戳、随机 ID、临时目录和 workspace 前缀。
- [ ] resource revision 参与同资源失败预算。
- [ ] retryable=false 的 exact duplicate 第二次在执行前阻断。
- [ ] retryable=true 的 exact call 最多真实执行两次。
- [ ] 同 tool、resource revision、error class 最多真实失败三次。
- [ ] 单 turn 失败上限为 6。
- [ ] 单 run 失败上限为 12。
- [ ] 默认 MaxAgentTurns=128、MaxToolExecutions=512。
- [ ] 配置 0 使用默认值，不表示无限。
- [ ] ToolRecoveryRequired 和 ToolRetryBlocked 进入 journal、模型上下文和 UI。
- [ ] 成功或读取到新 resource revision 后允许合理恢复，不误阻断进展。

## 4. 自动化事故场景矩阵

每个场景必须在最低层单元测试和至少一条跨层集成测试中出现。

| 编号 | 输入或故障 | 必须断言的结果 |
|---|---|---|
| A01 | shell 执行明确 exit 7 | Status=failed，ProcessStatus=exited，ExitCode=7，ErrorCode=process_exit_nonzero；模型、事件、重放、UI 一致 |
| A02 | 单一 rg 查询无匹配 | Status=succeeded，SemanticStatus=neutral，Diagnostic.reason=no_match |
| A03 | 单一 diff 发现差异 | Status=succeeded，SemanticStatus=neutral，Diagnostic.reason=different |
| A04 | shell timeout | failed、timed_out、process_timeout，保留截断后的 stdout/stderr |
| A05 | shell spawn 失败 | TransportStatus=failed、ProcessStatus=spawn_failed |
| A06 | pip 或 npm install 命令 | 模型不口述也出现宿主 ToolActivity；参数经过去敏 |
| A07 | text_edit 唯一命中 | 修改成功、digest 更新、patch preview 与 artifact 生成 |
| A08 | text_edit 零命中 | text_not_found，文件不变 |
| A09 | text_edit 多命中 | text_not_unique，文件不变 |
| A10 | text_edit stale digest | stale_file_revision，文件不变 |
| A11 | text_edit replace_all=true | 仅显式请求时全部替换 |
| A12 | patch 缺 Begin Patch | invalid_patch_format，零副作用，recovery 指向 text_edit |
| A13 | patch hunk 缺前缀 | invalid_patch_format，零副作用 |
| A14 | patch context mismatch | patch_context_mismatch，与语法错误区分 |
| A15 | exact non-retryable patch 重复 | 首次真实失败，第二次 ToolRetryBlocked，不执行工具 |
| A16 | retryable exact call 重复 | 最多执行两次，第三次阻断 |
| A17 | 参数变化但同资源同 error class | 最多真实失败三次，之后必须换策略 |
| A18 | 失败后重新读取新 revision | 允许使用新 call_signature 恢复 |
| A19 | 显式选中 Skill | 首次 LLM 前已有 activation plan、required receipts 和 effective pool |
| A20 | required resource 缺失 | 首次 LLM 请求前失败，不进入 Skill 任务 |
| A21 | Skill 未允许 shell | 模型看不到 shell；伪造直接调用也被 ToolRuntime 拒绝 |
| A22 | legacy PPT Skill 要求 pip/动态 Python | 返回 skill_platform_contract_conflict 并退出 Skill；不得自动路由，后续 typed tool 只能来自 Skill scope 外的新恢复规划 |
| A23 | presentation 参数嵌套错误 | validation error 带准确 JSON path |
| A24 | presentation 未支持字段 | unsupported，不静默丢字段 |
| A25 | 中文 PPT | 唯一 CJK helper，OOXML 校验通过，render 字体可见且不乱码 |
| A26 | Poppler 不可用 | needs_runtime 或 verified=false，不得假成功 |
| A27 | wrapper 存在但 target 消失 | RuntimeReady=false，报告 stale target |
| A28 | Codex cache 被删除 | Awaken known-good runtime 仍可用 |
| A29 | staging probe 失败 | current 保持上一 known-good |
| A30 | journal 在 tool_call 前写失败 | 工具不执行，run 以 persistence_error 终止 |
| A31 | journal 在 tool_result batch 写失败 | 停止后续副作用，明确 degraded/terminal |
| A32 | v1 message 有 tool_calls/result，无 tool event | adapter 恢复完整工具卡和结果 |
| A33 | v2 live 与 replay | 同一 fixture 投影出的语义 item 深度相等 |
| A34 | 最后一行 JSONL 截断 | 仅忽略 partial tail，前序记录完整恢复 |
| A35 | 中间一行损坏 | 明确报告损坏，不静默跳过导致错误顺序 |
| A36 | 取消发生在 tool call 后 | 保持合法 pairing 和 cancelled outcome |
| A37 | 进程在 tool_call 后、tool_result 前退出 | 重启后生成 synthetic interrupted outcome 和 process_restarted terminal，side_effect_state=unknown，不自动重执行 |

注：A20 的“缺失”不能被实现成自动联网下载 required resource；这是 Skill package 完整性错误。

### 6.3 工具语义任务

在 UI 中发送一个明确要求执行下列动作的真实任务：

1. 读取一个文本文件。
2. 用 text_edit 修改唯一字符串。
3. 执行一个成功 shell 命令。
4. 执行一个受控 exit 7 命令。
5. 执行一个无匹配的 rg 查询。

验收：

- [ ] 每次工具活动在模型口述之前或没有模型口述时仍可见。
- [ ] exit 7 显示失败和 exitCode=7。
- [ ] rg 无匹配显示 neutral/no_match，不显示系统故障。
- [ ] Inspector 可见去敏参数、状态、错误和耗时。
- [ ] 文件修改卡、artifact 和最终回答顺序正确。

### 6.4 Skill 能力任务

显式选择一份带 required resource、allow/deny 和 runtime requirements 的验收 Skill。

- [ ] 首次 LLM 请求前可观察 activation 完成。
- [ ] 资源 receipt 可在诊断信息中查看。
- [ ] 未允许工具不出现在模型 tool schema。
- [ ] 直接伪造未允许调用时执行侧仍拒绝。
- [ ] 缺 required resource 时任务在副作用前终止。

### 6.5 中文 PPT 任务

使用平台 typed presentation tool 创建至少 5 页中文 PPT，包含标题、正文、表格、图形或图片中的已支持组合。

- [ ] 没有用 shell 手写 OOXML/ZIP。
- [ ] CJK 字体和 XML 验证通过。
- [ ] LibreOffice/Poppler probe 真实通过后才执行需要它们的验证。
- [ ] PPT 可打开，渲染无乱码、无越界、无缺字。
- [ ] UI 中显示 Artifact、路径、验证状态和预览。

### 6.6 重启重放

在上述任务完成后记录直播 UI，然后执行：

~~~bash

~~~

重新打开同一个 project 和 thread：

- [ ] user message 数量一致。

- [ ] 没有重复卡片、缺卡片或状态从 error 变 done。

### 6.7 Runtime 破损恢复
