# AwakenMemorySettings

Awaken 当前设置页的记忆管理视图。上方四个现有开关保持独立；下方管理区不显示额外总标题，也不使用互斥标签切换，而是纵向同时展示两个纯 UI 模块：上方“最近动态”不显示附加说明或独立的“最近一次整理”汇总卡片，直接使用动态列表和紧凑详情弹窗展示当前 Memory 更新时间快照与 Dream task/report；“更新记忆”与运行中的取消入口放在“最近更新与整理”列表标题栏。动态行只显示类型、标题和时间，不在行内重复描述或 Dream 统计；可见标题按 32 个字符截断并追加 `.....`，完整标题、描述和统计仍由点击后的详情弹窗展示。动态列表默认展示最新 6 条，每次“显示更多”增加 6 条，最多展示 18 条；到达当前可见上限后显示“收起”并恢复为 6 条，列表不创建内部滚动区。下方“记忆库”使用搜索、筛选、全宽主题行和大型只读正文弹窗；详情中的范围、类型、状态和更新时间使用圆点分隔的紧凑单行元数据，仅状态保留轻量底色。

搜索、范围、项目、类型、状态、更新时间、按需详情、revision 删除以及 Dream 启动/取消均通过 props/callbacks 投影；`activities` 与受筛选的 `memories` 是两份独立输入，记忆库的搜索和范围切换不会由组件改写最近动态。全局动态聚合、Memory API、数据筛选、Dream authority、revision 与持久化由 Desktop/Core 拥有。全局动态中的项目 Memory 会随打开回调传递项目 identity，Design System 不读取项目 store。组件不提供创建、编辑、打开文件夹、supersede、revision 历史、删除审计或趋势统计。

“更新记忆”只调用既有 Dream callback，不改变维护机制或新增数据请求。筛选浮层、下拉菜单和两类详情弹窗各自消费 Escape，不会把同一次按键继续传给外层设置页。
