# 验收

## 1. 自动化

至少覆盖：

- Definition/provider/capability/dependency 校验、generic observations、host-generated candidate install plan 的可重现 plan ID、environment snapshot 绑定、安全 argv/scope/provenance 与 model-description budget；`TestCandidateInstallPlansAreSnapshotBoundAndDisablePackageScripts` 还必须证明 pip only-binary/npm ignore-scripts 参数与恶意来源语法拒绝；
- explicit language package probe：Python ready/missing/恶意 probe ID 不执行，Node `require.resolve` 不加载包代码，1s/有界输出/去敏最小环境/30s cache/workspace search path、必须 applied `inspect_read_only` full sandbox 且无 full sandbox 时 transport 不启动，以及 exact/比较/逗号版本约束的 ready/missing/mismatch/unknown/error；Node 包主入口可解析但 `package.json` 未导出时仍必须 ready，`ERR_PACKAGE_PATH_NOT_EXPORTED` 不得转为 missing；可执行文件 version probe 还必须限定 host-trusted root、执行前复核 fingerprint 并使用不含 auth/token/proxy 的最小环境；
- Desktop login env 解析覆盖 PATH/HOME/canary，具备超时、输出上限、marker framing、失败回退和 LLM secret 清除；环境快照有界、去敏并带 identity，完整 PATH digest/entry count/truncated 状态进入 identity，130-entry PATH 的末尾 canary 仍能被实际 child 解析；Skill roots/临时根/refresh reason 进入 identity，clone 不共享 slice，非绝对根被拒绝，Skill root 观察不 preload 正文或执行脚本；显式 shell-config PATH 只接受安全字面赋值，取消/非法配置回落 `process_environment` 并记 warning/provenance；run 工具快照固定 runtime/definition/provider/readiness；
- RequestBuilder 与 ToolRuntime 使用同一 snapshot，registry 变化不替换当前 run 的 schema/runtime/provider identity；MCP adapter 仍以 live connection/auth state fail closed，不使用旧 session；
- Skill 调用不改变工具快照；composer 当前选择必须从结构化 token 形成 host-owned、current-run-scoped identity/root/SKILL.md 绑定，并从 StartRun 一直进入最终 provider request；
- ordinary auto、auth/runtime/unsupported、transform 和 typed message provider 的 mass-review gate；raw Shell 不进入该 review；
- typed message 单人自动、多收件人审核、unknown recipient transport 前拒绝；
- 默认 Shell 使用 `local_user_direct_v1`：workspace 外用户目录写入、真实 cwd、npm/pip/安装脚本、本机 socket 网络、raw delete 和协作 CLI 形态均不被 Awaken 默认政策拒绝或转换；子进程继承 HOME、proxy、certificate、XDG/Puppeteer cache 和 Homebrew PATH canary；长任务默认 10 分钟、上限 30 分钟；direct receipt 的未观测副作用为 `unknown`，不伪造 Trash/staging/delta；
- 显式注入的 restricted/Workspace broker 仍覆盖 read-only、macOS/full Seatbelt private staging、canonical writable/protected scope、concurrent guard、Trash preimage 和 commit/discard 合同；这些是可选 provider 回归，不得写成 Desktop 默认 Shell；
- typed `dependency_install`：strict schema 只接受当前 snapshot 的 `plan_id`；plan 同时绑定完整 requirement、environment、provider provenance 和 executable SHA-256；伪造/过期 ID、free command/args/package/cwd、manager 替换、workspace/temp/Skill-root manager 均 transport 前拒绝；执行使用 direct argv、剔除任务可控根的 pinned PATH、显式最小 package auth/proxy 环境与 applied `open_world_system` full sandbox；raw Shell 不能取得 typed broker operation；
- dependency install staging：合法本地 fake manager 成功提交且 post-probe ready；重复执行保持确定；non-zero/timeout/cancel 丢弃 partial tree；narrow/protected/outside scope 在 Trash/publish 前拒绝；exit 0 但 post-probe missing/mismatch 必须是 `needs_runtime` 而非 success，并保留已提交 changes；split token、URL userinfo/query/auth assignment 在 observer/Outcome 前整体脱敏；
- TaskScope、敏感路径、symlink escape、Trash 跨卷 fail-closed；
- Outcome v2 的 transport/process/semantic/side-effect normalization；
- 默认 direct Shell 的 non-zero exit 必须保留 failed/`process_exit_nonzero`/non-retryable 与 `side_effect_state=unknown`；显式 Workspace broker 的 `TestShellNonzeroExitPreservesCommittedWorkspaceSideEffects` 另外证明已提交 delta 保留 applied/observed change；
- `TestPartialSideEffectNeverAutoSwitchesToAlternativeProvider` 必须证明 A 已 transport-completed + partial/observed 时 A 只执行一次、B 为 0，不自动 fallback/replay；只有新的明确 B tool call 才执行 B；
- MCP remote delete contract 与 post-call recovery evidence；
- MCP artifact output：per-tool contract/output schema 缺失在 transport 前 unsupported；正向路径只提交 exact bytes/hash 的一个 publishable regular file；hash mismatch、oversize、base64/字段缺失、扩展名/MIME/容器签名不一致、traversal/absolute/out-of-scope/sensitive/protected/symlink 全部无 artifact/live delta/Trash；replacement preimage 有 recovery path；provider false-success 无伪 artifact；direct adapter 无显式 TaskScope fail closed；取消发生在 host commit 前时 bounded cleanup 丢弃 private stage；commit 后复核失败仍按 receipt 保留 applied/partial change truth；
- `host_artifact_publish` broker operation 不要求虚构 child sandbox，但只允许 host projection、`ProcessNotApplicable`、exact digest/size 与一个 regular-file delta（可含新建 ancestor directories）；额外文件、删除、错误 hash、错误 process status 在 Trash/publish 前拒绝；
- `TestIsolatedTypedMCPSkillScriptAndShellArtifactRoutes` 在临时 workspace 从 Tool Catalog 取得真实 `document_create`（`document.create`）并与同 capability MCP provider 对照执行 Markdown；已安装 Skill 脚本和直接 Shell 则通过明确选定的执行 provider + `artifact_publish` 完成同类 deliverable，它们不是伪装成 `document.create` 的 provider。该 fixture 只证明 registration/execution/host commit/artifact contract，不得记作 Desktop 或视觉验收；
- `TestMCPArtifactBridgePublishesValidDOCXContainer` 额外覆盖真实 ZIP/OOXML container 的 DOCX host commit；本轮没有因此宣称 PDF/PPT 视觉质量或真实 Desktop 已验收；
- MCP metadata-less read-only 自动、非 read-only/自相矛盾 annotations 缺失或无效 metadata 在 transport 前 `unverified_mcp_provider_metadata`、有效 metadata 普通 mutation 自动；
- `capability_diagnose` 只读取 pinned snapshot，展示 dependency/install candidates，不刷新、不安装。
- provider `needs_runtime` 的 install next action 必须指向 `dependency_install` 且 input hint 只有 `plan_id`；run start/explicit refresh/install 后候选快照必须分别携带 `run_start`/`explicit_refresh`/`dependency_install:<plan_id>`；install 返回的 refreshed environment/dependency observation 只能由显式 refresh/新 run 消费，不能替换当前 run snapshot。
- typed `git_remote`：strict schema 不接受 command/argv/credentials/free environment；只接受 canonical HTTPS，拒绝 userinfo、query/fragment、SSH/file/git/http、localhost、RFC1918、CGNAT、link-local、benchmark/documentation/reserved/IPv6 ULA，并在 direct DNS preflight 任一结果非公网时 transport 前拒绝；显式 proxy-routed 模式只接受严格 `http`/`https`/`socks5h` + port，校验 endpoint、强制大小写 HTTPS/ALL proxy 并清空 `NO_PROXY`，只记录 source name，proxy credential 在 Outcome/observer 前脱敏；当前文档必须保留 direct rebinding 时间窗和对用户 proxy remote resolution 的依赖。
- typed Git snapshot/进程：只执行当前 run snapshot 的 Git 绝对路径，path/SHA-256 在 tool 与 broker transport 前复核；Darwin 只接受 root-owned、不可 group/world write 的 Xcode/CLT actual Git 与 `host_trusted_developer_tool` provenance，任意 hash-matched user Git transport=0；`GIT_EXEC_PATH` 固定到同 toolchain 的 root-owned helper 目录并复核 `git-remote-https` target SHA-256，PATH 剔除 workspace/temp/Skill roots；direct argv 带 credential/config/protocol/hook/template/filter/submodule/interaction hardening；最小环境不继承 `GITHUB_TOKEN` 或 ambient `GIT_CONFIG_*`。
- typed Git staging：`ls_remote` 零 publish scope；clone 只发布一个 TaskScope destination，branch/ref 使用结构化 argv，replace 的全部 preimage 有 Trash recovery；重复 replace 保持确定；non-zero/timeout/cancel 丢弃 partial clone；destination 外 delta/protected/symlink 在 Trash/publish 前拒绝；raw Shell/伪造 provider 不能取得 reserved operation；Windows/no-full-sandbox transport 前 fail closed。

## 2. Desktop 验收

在真实 Awaken Desktop 隔离 workspace 验证：

1. 普通读写工具自动执行且显示 provider/snapshot/readiness；
2. 在多个 PPT Skill 同时可用时从 composer 选择 `pptx`，用户只输入“这个啊”；最终 provider 上下文明确含当前选择的 ID/source/mode/root/SKILL.md，Agent 不再追问或改选其他 Skill；
3. 制作一份新的、不含 `node_modules` 的 `qoderwork-ppt` 隔离 Skill 副本，从 Awaken composer 选中它；Agent 能读完整 `SKILL.md` 并知道绝对 Skill root；
4. Agent 能进入 Skill root 执行 `npm install`，npm 可联网、执行 Puppeteer 安装脚本、将依赖写入该 Skill 目录，并将 Chrome for Testing 等资源写入用户缓存；
5. Agent 回到用户 workspace，使用 Skill 脚本绝对路径调用 `run-pipeline.js`，相对输入/输出仍以用户 workspace 为 cwd，生成可校验产物；
6. 新建后续 run 不重新安装，直接复用 Skill 目录中的依赖并成功运行；
7. 再用一个需要 Python、外部 CLI 或其他用户目录写入的 Skill 复验，确认这是通用本机执行能力，不是 PPT/npm 专项放行；
8. 上述 Shell/Skill 过程不出现权限提示、逐项审批、安装白名单或 typed-tool 前置阻断；broker receipt 为 `local_user_direct_v1`，未观测副作用为 unknown，不伪造 staging/Trash 证据；
9. 命令失败时模型能看到真实 npm 网络错误、版本冲突、浏览器下载错误、脚本 stderr 或产物校验错误；不同 Shell 恢复命令不被合并成同一个 `unknown` 失败预算，`pipeline 失败 -> 成功 npm install（unknown side effects，但宿主静态分类为明确 mutation）-> 原样重跑 pipeline` 可解锁；`node --version`、无输出文件的 `curl`、其他无关 CLI 的 unknown side effects 与 `pwd` 等 side effects=none 只读成功均不解锁或清除 pending recovery；
10. 显式选用 `trash_file` 时删除仍进入 Trash；直接 raw Shell 删除按当前用户终端语义执行，UI 不声称它已可恢复；
11. 单个明确个人消息的 typed provider 自动发送，多人/群/频道 typed provider 弹出专用审核，拒绝后 external calls=0；review 重开后不自动发送，digest 不匹配不能复用批准；不把此合同扩大到 raw CLI；
12. provider needs_auth/needs_runtime/unsupported 展示结构化恢复；
13. typed artifact 成功才展示交付物，渲染失败无伪成功。
   MCP artifact 还要验证 provider 只返回 bytes/hash 而非本机 path 声称发布，活动中的 provider、artifact、change、broker receipt 一致；该项只能证明 host commit，不能替代逐页视觉或业务语义验收。
14. 选择一个真实 missing workspace Python/Node typed dependency：readiness next action 只携带 `plan_id`；安装活动显示 provider/tool/environment snapshot 与 staging receipt；当前 run 不立即切换 provider，新 run/显式 refresh 后才变 ready。该 typed 验收与第 3–7 项的通用 Shell 安装互不替代。
15. 在隔离空 workspace 使用公开 HTTPS repository 执行 typed `git_remote ls_remote` 与浅 clone：活动显示 `builtin:git_remote`、tool/environment snapshot、Git fingerprint、sandbox method 与 broker receipt；用 `replace_existing=true` 复验旧 clone preimage 的 Trash recovery。这证明 typed Git 合同；raw Shell `git` 依然是另一条当前用户本机路径。

## 3. 平台结论

本轮文档不把跨平台构建写成实机验收。默认 direct Shell 在三平台的代码合同都是当前用户身份、用户环境和操作系统权限；本轮只能从 macOS 开发机的真实 Desktop 证据宣称 macOS 产品行为。Workspace broker/Seatbelt、typed dependency 和 typed Git 的受限 provider 仍保留自身平台合同。Windows Explorer Recycle Bin adapter/cross-build、Linux 编译和 macOS 自动化都不能代替对应 OS 的 Awaken Desktop 实机；未实际执行的项必须报告为未验证。
