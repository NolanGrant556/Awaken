# 全局数据与会话存储

## 1. 权威范围

本文唯一定义 Desktop 业务数据根、FileStore 布局、thread metadata、项目生命周期状态、per-thread SemanticJournal、输入附件和删除边界。run 的用户语义由 02 域定义，SemanticJournal payload 与重放规则见 [SemanticJournal 与重放](SemanticJournal与重放.md)，模型 API key 见 05 域，MCP 凭据见 06 域。

## 2. 当前数据根与布局

正式 Desktop 由 Electron Main 把用户主目录解析为 `~/.awaken`，并通过 `AWAKEN_HOME` 注入 Core。`AWAKEN_HOME` 是业务数据根，不随开发版/安装版 `userData` namespace 分叉。测试必须显式指向隔离根；没有 Desktop 注入的单元调用使用临时目录，不隐式写真实 `~/.awaken`。

```text
~/.awaken/
├── AGENTS.md                  # 全局用户指令，独立于 FileStore generation
├── CURRENT
├── store-generations/
│   └── gen-001/
│       ├── FORMAT.json
│       ├── sessions/<thread-id>/
│       │   ├── metadata.json
│       │   ├── journal.jsonl
│       │   ├── attachments/...
│       │   ├── tool-results/<tool-call>/...
│       │   └── context/epochs/...
│       ├── lifecycle/
│       │   ├── mutations.jsonl
│       │   └── state.json
│       └── locks/store.lock
├── config/
│   ├── models.json
│   ├── mcp-servers.json
│   ├── hooks.json
│   └── hook-trust.json
├── cache/model-capabilities.json
├── auth/connector-accounts.json
├── usage/model-profiles/*.jsonl
├── sessions/
│   ├── <project-id>/output/...   # 零文件夹项目共享产出区
│   └── <thread-id>/output/...    # 独立对话的专属产出区
└── .env
```

`CURRENT` 只保存活动 generation ID。启动必须读取 `CURRENT` 和对应 `FORMAT.json` 并执行 reader/writer version gate；指针缺失、越界、目标 generation 缺失或格式不兼容均 fail closed。只有全新且不存在 `store-generations` 的根可以初始化 `gen-001`，不能在损坏根旁创建另一份空真相，也不能按目录时间猜“最新” generation。

Electron `userData` 不承载项目、会话或连接器业务 authority；这些数据只能通过当前 FileStore 或各自明确的配置 authority 读写，不存在外部存储的读取、写入、清理、迁移或 fallback 路径。user MCP server 配置的唯一 authority 是 `~/.awaken/config/mcp-servers.json`；user Hook 配置与项目 Hook 信任的 authority 分别是 `~/.awaken/config/hooks.json` 和 `~/.awaken/config/hook-trust.json`。项目 Hook 配置位于已挂载项目文件夹的 `.awaken/hooks.json`，不进入 FileStore。`<workspace>/awaken.mcp.json` 只在该 workspace 被明确配置为 default workspace 时作为 project scope 参与 MCP 合并。原项目目录除这些明确的项目级配置外不属于业务数据根，不会被 Awaken 启动流程处理；不在 FileStore 中的目录需要用户重新添加。

全局 AGENTS authority 固定为 `~/.awaken/AGENTS.md`，项目 authority 固定为主文件夹 `.awaken/AGENTS.md`；业务语义见 [02 AGENTS 指令与运行快照](../02_主智能体闭环/AGENTS指令与运行快照.md)。全局文件由 `src/instructions.GlobalDocumentStore` 使用同目录临时文件、`0600`、文件 `fsync`、原子 rename 和父目录 `fsync` 写入，revision 使用完整内容 digest，删除后同步父目录。项目创建与编辑由 Electron Main 在重新验证 active project/primary root 后执行；这两个 Markdown 文件都不进入 FileStore generation，也不随删除 thread 清理。

FileStore 项目/会话边界不包含 `~/.awaken/config/models.json`、`~/.awaken/config/mcp-servers.json`、Hook 配置/信任、模型能力缓存、余额识别、上下文窗口数据、API 凭据或 MCP 认证 metadata；它们由各自权威路径和功能域继续管理。Hook trust 使用同目录原子 replace；损坏文件 fail closed，不能当作空信任覆盖。

## 3. Thread 与 SemanticJournal

[`src/runtime/file_desktop_store.go`](../../src/runtime/file_desktop_store.go) 是 `ThreadRepository` 与 `ProjectLifecycleRepository` 的唯一产品实现：

- `sessions/<thread-id>/metadata.json` 保存标题状态、workspace/project 关系、最新 run、preview、model profile cache identity、逻辑删除标志和归档标志；
- 归档 authority 是 metadata 的 `archived`（缺失按 `false` 读取，兼容既有 session）与 `archived_at`（仅 `archived=true` 时存在，首次归档与再次归档写当前 UTC，取消归档同时清空；旧数据缺 `archived_at` 时读取侧用 `updated_at` 作展示/排序 fallback）。归档 mutation 不修改 `updated_at`，不改变 `projectId`，普通 upsert 与标题 CAS 不得覆盖归档字段；
- 线程列表查询按 view 过滤：`GET /v1/threads?view=active|archived|all`，query 缺失等价 `active`，非法值返回 `400 INVALID_THREAD_VIEW`；`active = deleted=false && archived=false`，`archived = deleted=false && archived=true`，`all` 只供内部对账和测试；同一 thread 在任一查询时最多属于 active 或 archived 一个集合，deleted 优先于归档；
- `sessions/<thread-id>/journal.jsonl` 保存 SemanticJournal v2，是对话内容的唯一耐久事实源；
- `sessions/<thread-id>/context/epochs/` 保存不进入 wire 的 exact prompt baseline、request-only prefix messages、instruction digest、source snapshots、canonical/dynamic tools 与 append-only delta；
- `sessions/<thread-id>/tool-results/` 保存 runtime-owned 媒体和超过 admission 阈值的完整文本 blob；journal 只持有 storage key/digest/size/preview；
- thread 恢复必须同时读取精确 thread ID 的 metadata 和 journal，不扫描 workspace，不拼接其他 session，也不从附件目录发明消息；
- root Agent 的归档历史读取复用同一 metadata + journal authority：Runtime 先在 archived view 中解析精确 `thread_id`，再返回有界 semantic items；模型只看到 `host_managed_session_store` 逻辑位置和 thread identity，不看到 `CURRENT`、generation 或 journal 物理路径。active/deleted thread 不能通过该只读桥读取；
- `state.json` 不是 thread 内容 authority，renderer cache 不能反向覆盖 FileStore。

业务数据根顶层的 `sessions/` 是 Awaken-managed 工作区，不是 FileStore thread 内容目录。零文件夹项目按 project ID 共享一个工作区；独立对话按 thread ID 使用各自工作区。两类产出默认进入对应的 `output/`，而 transcript 仍只在当前 generation 的 `store-generations/.../sessions/<thread-id>/` 中。

会话 metadata 写入使用同目录临时文件、文件 `fsync`、原子 rename 和父目录 `fsync`。JSONL append 维护已提交 offset；尾部半条记录可截断到最后提交点，中段损坏必须报错，不能跳过后继续重放。

## 4. 项目生命周期与原子性

项目、operation、idempotency key、operation-thread cutoff、cleanup job 和 Desktop state 的 authority 是 `lifecycle/mutations.jsonl`。每次 mutation 先完整 append 并 `fsync`，再更新内存状态、session side files 和可重建快照 `lifecycle/state.json`。

`state.json` 只加速启动；缺失或损坏时从 lifecycle journal 确定性重建。mutation 必须携带已经生成的 operation/job ID 与时间，重放只应用事实，不重新生成身份或重新执行外部副作用。

跨进程 mutation 通过 `locks/store.lock` 串行化；进程内仍由 store mutex 和 project mutation owner 协调。当前 FileStore 还提供 fencing-token lease primitive，但 thread/run 产品路径尚未建立 per-session writer lease，因此当前不支持多个 Core 实例同时写同一活动 thread。

`store.lock` 的 owner JSON 在独占创建后立即写入。进程若在创建与 owner 写入之间终止，可留下空或半条 owner 文件：新鲜且无法解析的锁仍 fail closed，不抢占可能正在初始化的 writer；当文件修改时间已超过本次锁 TTL 时，按与已过期 owner 相同的语义恢复。恢复前必须再读并比较原始字节；如果并发 writer 已完成写入，不得删除新 owner。锁文件时间晚于当前时钟时继续 fail closed，不以时钟回拨为由抢占。

## 5. 输入附件

- 图片支持 PNG/JPEG/WEBP，单个最大 8 MiB，写入当前 generation 的 `sessions/<thread-id>/attachments/`；目录 `0700`、文件 `0600`。
- journal 只保存 attachment identity、MIME、显示信息与相对 `storage_key`，不重复内联 image base64；模型请求按当前窗口在近尾预算内 hydrate，更早附件不以原图进入 provider body。
- 普通文件保存已验证的绝对路径引用，不复制文件，也不归 Awaken 所有。
- 缺失图片 blob 不允许从目录猜替代品；历史卡片仍可保留 identity，但模型 hydration 失败。

## 6. 删除与恢复

删除 active thread 必须先返回 busy。项目 thread 的逻辑删除通过 lifecycle mutation 提交并创建 durable cleanup job；UI 以逻辑提交为准，物理清理由 job 幂等重试。独立对话没有 project lifecycle row，在同一 project-mutation lock 下关闭/逐出 live thread 后直接删除 FileStore session。批量删除复用每个 thread 的同一删除合同并返回逐项结果，不声明跨多个独立 session 的原子回滚；竞态中变为 active 的 thread 返回 `THREAD_BUSY`，其他成功项不回滚。只有标记为 deleted 的项目 session 才能被 cleanup job 移除，过期 job 不能删除 live session。

删除 session 可移除其 metadata、journal、context epoch sidecar、tool-results 和 runtime-owned attachments；外部普通文件引用绝不连带删除。`<AWAKEN_HOME>/sessions/<owner-id>` 中的产出也不随“删除会话”自动删除，避免把用户产物当成历史缓存。项目移到系统废纸篓的 staging、attempt、fingerprint 和恢复状态由 01 域定义。

归档不是删除：`PATCH /v1/threads/{thread_id}/archive` 只原子改写 metadata 的 `archived`/`archived_at`，不进入项目 lifecycle mutation、不创建 cleanup job，也不移动 journal、context epochs、tool results、attachments 或产出目录。归档 active `running | cancelling` thread 返回 `409 THREAD_BUSY`，归档 `source=scheduled_task` thread 返回 `409 THREAD_ARCHIVE_UNSUPPORTED`；归档 thread 不允许作为新 run 的 `thread_id`（`409 THREAD_ARCHIVED`）。从归档页删除复用本节同一删除合同。

`archived_history` 不建立第二份 transcript storage，也不向当前 thread 复制旧 journal。它的 live tool result 可在本轮提供有界历史，当前 thread 的 durable tool result 只保存读取回执；旧正文仍只由目标 thread 的 `journal.jsonl` 拥有。该桥不开放 `AWAKEN_HOME` 普通文件权限，不能被 `Read`/Shell 路径访问替代。

异常规则：

- `CURRENT`/`FORMAT.json`/lifecycle journal 中段损坏：启动失败并保留原数据；
- lifecycle snapshot 损坏：从 journal 重建并重写 snapshot；
- `store.lock` owner 无法解析：未超过 TTL 或文件时间来自未来时 fail closed；超过 TTL 后在字节未变的前提下视为中断的锁初始化并恢复；
- session metadata 缺失或损坏：该 thread 恢复失败，不伪造空会话；
- journal 尾部未提交：回退到 committed offset；中段损坏 fail closed；
- cleanup 失败：保留逻辑删除状态并重试，不让 UI 历史复活。

## 7. 当前不支持与不变量

- 不支持从 FileStore 和当前配置 authority 之外自动导入项目、会话或模型 profile。
- 不支持 FileStore 与其他存储双写、双读或 fallback。
- 不支持从 Electron `userData` 或其他旧路径读取、导入、迁移或 fallback user MCP server 配置。
- 不支持多个 Core 实例并发写同一活动 thread。
- 不支持把内存 cache 淘汰解释为持久删除。
- 归档 mutation 不修改 `updated_at`；同一 thread 在任一 authority query 时最多属于 active 或 archived 一个集合。
- session metadata 损坏的 thread 不得当作 active 显示（fail closed，归档状态同样不豁免）。
- API key、OAuth token、Authorization header 不进入 thread metadata、journal 或 lifecycle snapshot。
- AGENTS 正文不进入 thread metadata、SemanticJournal、AG-UI 或 Renderer state；只有 Context Epoch sidecar 保存当前 run 的冻结 prefix，journal/run wire 只保存安全摘要。
- 所有 authority JSON/JSONL 文件必须 `0600`，authority 目录必须 `0700`；平台不能满足原子 replace、锁或格式 gate 时必须 fail closed。
