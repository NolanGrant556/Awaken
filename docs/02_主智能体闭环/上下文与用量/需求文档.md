# 上下文与用量 · 需求文档

用户可以查看上下文用量并发起压缩。模型缓存、实际用量和费用应区分来源，未知数据不能显示成零或估算成供应商账单。

代码、接口和验证方法见[实现方案](实现方案.md)。

## 主动与被动压缩

provider/tool snapshot 只保存 ID/摘要；压缩后不能重新选择当前 registry implementation。Skill 正文截断必须提示重读锚定路径。

## 限制与尚未完成的部分

- 供应商目录未提供的 per-model tool-support 仍会显示 unknown，只有官方/API 事实或用户纠正后才下发工具；连接测试本身不证明工具能力；
- catalog/Skill token 预算是估算，不是 provider tokenizer 精确值；
- bare unit Runner 没有 recorder 时只做内存压缩；产品 `RunService` 路径必须始终持久化；
- OpenAI official Responses 的 native opaque adapter 已按 exact provider/base/protocol/model capability 接入，并保持 `store:false`、不依赖 `previous_response_id`；native output 只有通过相同完整请求硬 10% receipt 才随 V2 boundary 原子安装，失败或超限回落 provider-neutral checkpoint。当前证据为 mock/自动化，本机没有 ready OpenAI profile；真实 OpenAI 账号调用不属于本次 V2 收口要求。custom endpoint、OpenAI Chat 与 Anthropic Messages 不得继承；
- Windows/Linux 的大路径、非 ASCII attachments 与真实重开压缩尚无本轮实机证据，也不属于本次 V2 收口矩阵；因此不能宣称这些平台已实机通过，但它们不阻塞当前功能收口；
- MiniMax-M3（当前 profile `267307` 输入窗口）的低窗口多 PDF 已在 macOS 真实 Desktop 通过：压缩前 254K，10% 目标 27K，保守压后 18K、mandatory floor 17K，压缩完成时面板为 22K/267K（8%）；模型从压缩前第 8 份 PDF 断点继续完成第 9–12 份并读取新文本。自定义 API 的独立低窗口媒体样本仍未取得，不能由 MiniMax、`go test` 或 Gallery 代替；
- 当前没有多个 Core 实例并发写同一 thread 的产品级 session lease。

- 火山 Coding Plan 是否存在透明缓存、是否返回稳定 cached usage，官方尚未确认；Awaken 不发送未文档化字段。
- Doubao Ark Context API 的缓存创建、cache ID 生命周期、TTL、恢复与删除尚未接入；普通 `/chat/completions` 或 `/responses` profile 当前不显示缓存命中状态。
- Google OpenAI compatibility 只暴露 `cached_content` 扩展，Awaken 本轮未实现原生 cachedContent 资源创建，因此不主动写缓存字段。
- Kimi Coding Plan 的 `cached_tokens` 可能缺失；缺失保持 unknown。缓存如何折合会员套餐额度没有 token-to-plan 换算合同。
- 服务端 TTL、驱逐、路由和命中率不受 Awaken 控制；Awaken 不承诺固定节省百分比。
- custom endpoint 不继承官方 DeepSeek/Kimi 私有字段或官方价格身份。
- 当前已有正式 subagent runtime，但 root/child 原子共享 token/tool/cost 预算和 child 完整成本统计尚未接通；分类预留不等于预算能力已实现。
- provider 尚未返回完整 input usage、实际记录与当前身份不兼容或刚完成 compact 时，当前总输入回退本地计数；请求前计数不是 provider tokenizer 的精确计数，record 保留 estimator version；界面统一写“当前使用”，不添加 `~`、“预计”、中文“约”或“本地估算”徽标。
- Windows/Linux 尚无本能力的真实 Desktop 当前基线，不能由 macOS 自动化推断为跨平台通过；该实机矩阵不属于本次 Context Compaction V2 收口检查要求。

## 范围与实现状态

模型 profile、凭据和连接测试入口由 [05 模型与供应商配置](../../../README.md#05_模型与供应商配置) 拥有；上下文压缩由 [上下文窗口与压缩](实现方案.md) 拥有；Workbench overlay、composer 和滚动不变量由 [01 中间交互区域](../../01_桌面工作台/工作台布局与运行展示/实现方案.md) 拥有；SemanticJournal 与 wire 字段分别由 03、09 域拥有。

当前已支持：

- 以最终 provider-visible request 为基准的版本化分类估算；
- 将逐请求 provider 实报与该请求发送时估算成对保存；Desktop 直接显示最近一次兼容主请求的 inclusive input，Core 另用发送时估算做保守压缩判断；
- Composer“上下文窗口”入口和中文分类面板；
- DeepSeek 自动前缀缓存、Kimi CN/Kimi Coding Plan affinity key 与 cached usage 解析；
- byte-stable Context Epoch、append-only host delta 和 Kimi provider-opaque reasoning state 安全重放；
- 主调用、标题、Memory recall、compact、Dream、retry 和连接测试的作用域隔离账本；
- 大文本 tool result 在首次 model admission 前的一次性耐久 offload；
- DeepSeek 当前官方美元 token 价格的 request-time snapshot 与成本计算。

本文提到的 `subagent_definitions` 只是旧 snapshot 的兼容分类。当前正式 `subagent` 工具定义归入“内置工具”；是否支持原生 Subagent 只由[原生 Subagent 产品与架构契约](../子智能体协作/实现方案.md)判定，不能从上下文分类反推。

## 产品行为

### Composer 与中文面板

缓存率常驻显示，按最近一次兼容请求的缓存命中 Token 除以总输入 Token 计算，保留一位小数。缺失数据或总输入为零时显示“未知”；缓存合同未确认时显示“未确认”。输入、命中、未命中和输出 Token 放在“Token 明细”中，每次打开面板默认折叠，可点击或用键盘展开。缓存状态与成本不随明细折叠。

当前总输入与分类的显示投影遵守以下规则，具体规则见[实现方案](实现方案.md)。

### 交互与 placement

`App.tsx` 独占面板 open state、触发器 ref 和 overlay 编排；`contextUsagePresentation.ts` 拥有兼容性判断与数据纯投影；`AwakenContextUsagePanel` 是纯 props/callbacks 的 Design System 组件。

面板位于 `RunStage.overlay`，外层 pointer-through、面板 pointer-auto；它不进入 `ExecutionFeed` 或 `composer-dock-stack`，不参与 ComposerDock 高度测量。面板使用实测 `composerBarInsetPx + 12px` 贴合输入框，不继承最终输出使用的 72px output safe gap。Escape、关闭按钮和点击外部均可关闭，关闭后焦点返回触发按钮。窄窗口保留安全边距并在面板内部滚动；主题只使用现有 Design System token。开关和原位数据更新不得改变 draft、IME composition、follow/paused、marker、return-to-latest、native tail、active turn 或 thread identity。compact started/failed 只更新后端与 reducer diagnostics；面板在整个进行期冻结最后一份完整快照，成功后只接受新的完整 post-compact `ContextUsageSnapshot` 并一次刷新，失败或取消不改变可见用量。重启回放时，耐久 `compact_summary` / `native_compaction` usage 只重建该冻结状态，不进入面板；没有 live finished frame 时，只有完整 snapshot 的本地估算已不高于其硬 10% target 才能解除冻结，失败后的高位 snapshot 不能覆盖压前值。
