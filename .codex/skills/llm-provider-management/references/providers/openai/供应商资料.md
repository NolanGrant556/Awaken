## Awaken 当前接入

- provider ID：`openai`；access type：`api`。
- 默认 Base URL：`https://api.openai.com/v1`；Bearer API Key。
- 当前默认模型：`gpt-5.6-sol`。
- 当前公开 Chat Completions 与 Responses；默认协议为 Responses。
- 模型目录通过 `GET /v1/models`，窗口、多模态、工具和 effort 仍由版本化官方能力表补齐。
- 推理密钥与组织用量/成本管理密钥分开保存；不能用管理密钥做模型推理。

## 三协议兼容矩阵

| 协议 | 官方合同 | Awaken 当前 | 结论 |
| --- | --- | --- | --- |
| Chat Completions | 有 | 已接入 `openai_chat` | 支持，保留用于兼容；按 exact model 核对能力 |
| Responses | 有，官方推荐新项目优先采用 | 已接入 `openai_responses` | 支持；Awaken 当前固定 `store:false` |
| Messages | 无 OpenAI 原生合同 | 未接入 | 不支持；不要因为 SDK 能连其他服务而推断 |

## 鉴权、端点与模型

- Header：`Authorization: Bearer <OPENAI_API_KEY>`。
- Chat：`POST /v1/chat/completions`；Responses：`POST /v1/responses`。
- 模型 ID、上下文和 effort 以模型页为准；`GET /models` 不提供全部 capability。
- 供应商模型名变更时同步更新版本化 catalog、展示名、能力表和测试；不要只刷新候选列表。

## 上下文、多模态与工具

- 上下文窗口、最大输出和支持的 reasoning effort 都是 exact model 事实。
- Chat 与 Responses 的图片、文件和工具 shape 不同；adapter 必须分别 lowering。
- 原生 PDF/file input 只有对应模型和 Responses/Chat 合同明确支持时才可标为 `supports_native_pdf`；否则 Read 使用页面渲染回退。
- OpenAI 内置工具不是 Awaken 本地 tool schema 的替代品；引入前要单独设计权限、事件和恢复边界。

## 提示词缓存

- 官方缓存对满足条件的相同前缀自动工作；`prompt_cache_key` 可帮助路由同一前缀。
- Awaken Chat 发送稳定 `prompt_cache_key` 并在流式请求要求 usage；Responses 发送 `prompt_cache_key`。
- 解析 Chat 的 `prompt_tokens_details.cached_tokens` 与 Responses 的 `input_tokens_details.cached_tokens`；cached 是 input 子集，不能重复相加。
- profile、凭据 revision、模型、协议、purpose、reasoning policy 或 prompt schema 改变会形成新 Awaken 缓存 identity。

## 推理开启关闭

- 不把 `reasoning.effort=none`、模型默认行为和一个通用 `thinking=false` 混为一谈。
- 标题、压缩和 Memory 辅助请求是否能关闭 reasoning，取决于 exact model/协议合同和 `src/llm/request_policy.go`；未知时不发送私有关闭字段。

## 推理强度

- 官方模型可能支持 `none/minimal/low/medium/high/xhigh/max` 的不同子集。
- Awaken UI 只持久化 `low | high | max`，由 exact model capability 映射为原生值；没有映射时不展示 effort。
- 新增模型必须核对 effort 字段位于 Responses 的 `reasoning` 还是 Chat 的兼容字段，并覆盖非流式、流式和连接测试。

## 用量、余额、限流与套餐

### 用量查询合同

- A 类：每次推理响应的 usage 进入 Awaken 请求账本，但不能据此查询账户余额。
- C 类：组织用量使用 `GET /v1/organization/usage/completions`，成本使用 `GET /v1/organization/costs`；可按时间桶、项目、用户、API Key 或模型等维度聚合。
- 凭据：组织 API 使用 Organization Owner 创建的独立 Admin API Key；不得复用普通推理 Key，也不得把管理 Key 发送到 Renderer。
- Awaken 当前：已用单独保存的 Admin API Key 查询最近约 7 天的组织用量与成本；没有把它展示成普通 API 余额。

- 价格按模型、服务层级、缓存输入、输出和工具变化；只从当前定价页读取，不在此长期抄数值。
- 处理 429 时读取 rate-limit Header 与 `Retry-After`；不要用无限自动重试掩盖配额或 spend limit。

## Awaken 落地规则

- Responses 当前由 Awaken 重放完整历史并发送 `store:false`，不使用 `previous_response_id` 作为 thread authority。
- 官方 Responses compaction 只对 exact official provider/base/protocol/model capability 接入；opaque output 与 profile、credential revision、model、protocol、endpoint contract 和 digest 绑定，失败/超硬 10% target 回落本地 V2，不形成第二 authority。conversation state、`previous_response_id` 与 background mode 仍未成为 Awaken thread authority。
- 连接测试成功只证明当前 Key/Base/model/protocol 的最小请求，不证明图片、PDF、tools、缓存或全部 effort 档位。
- `/models` 的稀疏元数据不能覆盖版本化 capability 的 exact model 事实。
