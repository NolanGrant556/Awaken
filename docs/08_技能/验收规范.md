# 验收规范

## 1. 自动化

至少覆盖：

- 多来源路径、确定性优先级、同名/realpath shadow、无 Core bundled 隐式 fallback；`system-skills` 大小写保留目录在普通来源中直接跳过，而 bundled root 指向其内部时加载直接子包；project/user 覆盖 bundled、bundled 保留 shadowed，移除覆盖后恢复；
- 宽松 frontmatter、未知字段保留、四种状态和 source policy；
- Skill 正文中的 npm/pip、`generate.py`、`soffice`、`pdftoppm`、prompt-injection、删文件或群发文字都只是工作流内容，不在 discovery 阶段置灰/改写正文/执行包内脚本；当前负面回归是 `TestImplementationWordsAndScriptsDoNotDisableSkill`；
- 单一 `skill` 目录预算、用户/模型调用边界、调用时正文重读；`TestRequestBuilderInjectsSkillTriggerRulesAndCatalogIntoFinalToolSchema` 直接检查最终 provider request 的 `skill` tool schema，必须同时携带唯一一份固定触发规则、model-invocable Catalog 条目，并排除 `disable-model-invocation` Skill；触发规则本身不参与 Catalog 预算测试；
- Catalog 三级降级：预算充足时保留完整描述（`TestCompileCatalogUsesOnePercentAndNamesOnlyFallback`）；预算不足但按条目均摊仍不低于约 20 字符下限时进入 `truncated_descriptions` 模式（`TestCompileCatalogDegradesToUniformlyTruncatedDescriptionsBeforeNamesOnly`）；低于下限时退化为 names-only（`TestCompileCatalogFallsBackToNamesOnlyBelowTruncationFloor`）；
- Skill 不注册工具、不改变父 `RunToolAvailabilitySnapshot`；`TestSequentialComplementarySkillsNeverIntersectParentToolPool` 使用 allowed-tools 完全互补的两个 Skill 顺序调用，必须证明两次都保留同一 pinned parent pool，不彼此求交；
- `TestAgentRefreshRunAvailabilityCarriesTaskAndSkillMetadataWithoutLoadingSkill` 必须证明 run 环境快照携带有界 source/root、TaskScope 临时根和 refresh reason，且这一步骤不注入 SkillContextBlock、不读取正文、不执行包内脚本；`TestExecutionEnvironmentSnapshotCapsSkillRootsAndRejectsInvalidTemporaryRoot` 必须证明根数量上限和非绝对路径拒绝；
- `skill_resource_read` 对 project/user/managed/additional/plugin/bundled/nested-legacy 的 host-owned SourceRoot、单包 realpath/symlink、root replacement、2 MiB、UTF-8 和 binary 分流；flat legacy/MCP 本地资源拒绝；
- fork 必须创建 child，缺 starter 显式失败；
- `skill_activated`/resource receipt 的压缩、重启恢复和父子隔离；同一 run 内重复激活同一 Skill 必须替换而非追加 `SkillContextBlocks`，与重启恢复路径的按 SkillID 取最新语义一致（`TestRepeatedImplicitSkillActivationReplacesInsteadOfDuplicatingBlock`、`TestRepeatedImplicitSkillActivationPreservesOriginalOrderPosition`）；
- composer selection 从 `StartRunRequest.ComposerTokens` 到最终 provider request 的完整合同：单选明确 `skill_id/source/activation_mode/invocation=user_composer/absolute root/absolute SKILL.md`，“这个”可稳定指向当前选择；多选保序且标记歧义；token-only 不注入伪用户文本；fork child、历史恢复和 model-invoked Skill 不冒充父 run 的 current selection；source/root/path mismatch 在 provider 前失败；
- MCP 动态注册、调用时 fetch、disconnect 注销和 re-register。
- `skill_install` 的 project/global target、五种 source、包上限/逃逸、默认 abort、replace 原子 swap + 旧包 Trash receipt，以及 Trash 失败回滚且无 staging/backup 残留；
- project/user Skill 删除必须从受控安装根重新解析 ID、只接受直接子包、把完整目录移动到 Trash 并在响应前同步 Registry；Trash 失败保持原包不变，MCP/plugin/managed/additional/bundled/legacy 等非安装生命周期来源拒绝删除，bundled HTTP 删除返回 `SKILL_DELETE_SOURCE_UNSUPPORTED`；
- `SKILL.md` 预览覆盖 project/user/managed/additional/plugin/legacy、同名 winner 与 shadowed 条目的独立 `catalogEntryId`，并逐项验证原始 frontmatter/完整正文、路径伪造、root/symlink 替换、文件消失、非普通文件、非 UTF-8 和超过 2 MiB 整体失败；bundled 与 MCP 动态条目都不得获得预览 identity；
- Desktop system-skills importer 使用临时 home 覆盖 dev/packaged 路径、首装、清单命中、app 版本和源变化、目标修改/缺失/额外文件、空资源根、中断恢复、交换回滚、缺失源与 symlink 拒绝；Runtime Supervisor 必须清除继承的 `AWAKEN_BUNDLED_SKILL_DIRS` 并注入固定目标；打包配置包含 system-skills，清理脚本不删除源资源；
- Renderer 自动化断言默认 Awaken Skills、Awaken → 项目 → 全局顺序、bundled 独占分组、“Awaken 内置”标签、bundled 无删除按钮、空态文案，以及 MCP 等非拥有来源仍保留禁用删除入口；
- Renderer/Design System 自动化断言卡片主体与删除按钮分离、Dialog 大尺寸/隐藏可访问标题/正文初始焦点、旧请求隔离和 Escape；Markdown 覆盖 GFM 标题、列表、表格、代码块、引用、只读任务列表，并证明 raw HTML、脚本、危险/相对链接、外部图片与 Mermaid 不执行；

市场兼容验收使用固定、可审计的 [market manifest](../../src/skills/testdata/market_skills_manifest.json) 与 [market acceptance test](../../src/skills/market_acceptance_test.go)：20 个不同 GitHub owner/repo 的固定 commit/hash/license，以 opt-in fixture 原包执行 `LoadDir`，并分别通过 `PackageFromPath`/`InstallSkillPackage` 安装到隔离临时 project 后从 `.awaken/skills` 重新发现；核对安装后 `SKILL.md` hash、资源目录、scope/source/projectPath 与隔离 HOME sentinel，覆盖 scripts/assets/references 结构但不执行包内脚本、hook 或命令。清单与断言只以这两个文件为权威，文档不复制第三份表。

这 20 个是自动化中的真实上游包 fixture 加载/安装验收，不表示 Awaken Desktop 默认预装了 20 个 Skill，也不证明 Skills 管理页、Slash、inline/fork 或包内工作流已在真实 Desktop 逐包操作通过。这些产品事实只能由下节的实机 Desktop 验收证明。

脚本执行另有本机 Shell 自动化，不与上述“安装时不执行代码”冲突：

- `TestPinnedMarketSkillScriptExecutesThroughSupervisedShell` 保留作为显式 Workspace broker + Seatbelt 的可选受限 provider 回归，不代表 Desktop 默认路径；
- `TestInstalledSkillPythonNodeAndShellScriptsUseCurrentUserShell` 正式安装含 `.py`/`.mjs`/`.sh` 的 fixture Skill，三类脚本由默认 `local_user_direct_v1` 在真实 Skill 包路径执行，可向 workspace 产生结果，Outcome 必须保持 unobserved/unknown side-effect 语义而不伪造 staging changes；
- Node 依赖 probe 覆盖 package 主入口存在但 `package.json` 未导出的包，`ERR_PACKAGE_PATH_NOT_EXPORTED` 不得被当成 `MODULE_NOT_FOUND`，且探测不执行包入口代码。

这些自动化证明“安装/激活阶段不擅自运行代码，Agent 明确调用后按所选 provider 执行”。它们不代替真实 Desktop、网络、包管理器和第三方 Skill 端到端验收。

聚焦命令：

```bash
go test -count=1 ./src/skills ./src/skillruntime ./src/agentcore ./src/runtime ./src/server ./src/prompt
go vet ./src/skills ./src/skillruntime
```

只可报告本次实际通过的包；共享工作区被其他改动阻塞时要记录阻塞测试和错误，不能沿用旧摘要。

## 2. Desktop 验收

按根 README 正式入口打开真实 Awaken Desktop，在隔离 workspace 验证：

1. Skills 管理页显示来源、锚定路径、四种状态、诊断和最近调用；
2. 页面默认打开 Awaken Skills，Tab 顺序为 Awaken、项目、全局；模拟 bundled 源为空或首次同步失败时显示“内置 Skills 未就绪，重启 Awaken 后重试”，项目与全局视图仍可用；
3. Slash 显示所有 `loaded && userInvocable != false` 来源，选择后形成结构化 token；
4. 在 `qoderwork-ppt`、`pptx` 和其他 PPT Skill 同时存在时选择 `pptx`，只输入“这个啊”；模型请求中必须明确标记当前选择的 `pptx` identity/root/SKILL.md，不再追问或改选其他 Skill；
5. 用户显式调用可调用 model-disabled Skill，模型调用被拒绝；
6. inline 调用后继续对话，压缩和重开仍能恢复上下文；
7. fork 产生真实 child 行为，缺 starter 时展示结构化失败；
8. MCP Skill 连接后出现、调用时取正文、断开后消失；
9. 复制一个未带 `node_modules` 的真实 npm Skill 到隔离的用户级 Skill root；Agent 能根据 `SKILL.md` 在包根运行 `npm install`，联网执行安装脚本并写用户 Puppeteer 缓存，再从用户 workspace 以绝对脚本路径生成产物；新 run 复用已安装依赖；
10. 再以需要 Python、外部 CLI 或其他用户目录写入的 Skill 复验，确认不是 PPT/npm 专项放行；
11. 上述过程不出现权限提示、逐项审批、安装白名单或 typed-tool 阻断；
12. **模型调用触发规则**：安装若干可区分的 Skill 后，新线程内不做 composer 选择、直接用自然语言描述一个明显匹配某个已安装 Skill 的任务（尤其是同时要求多种交付物类型、各自匹配不同 Skill 的场景），核对模型在对应普通工具动作之前调用 `skill` 激活匹配 Skill，`skill_activated` 记录先于对应交付物的普通工具调用；
13. 用户在自然语言中显式点名一个已进入 model-invocable Catalog 的 Skill（非 Slash token）时，模型必须调用它；`disable-model-invocation` Skill 不得因自然语言点名而绕过边界，仍需用户通过 Composer/Slash 结构化 token 显式调用；
14. 与任何已装 Skill 均无关的任务（如修改一个代码文件）不应产生多余的 `skill` 调用；
15. 反复执行第 12 条至少 3 次独立会话，核对匹配 Skill 均在相关普通工具动作前被激活；未达到 3/3 时只能如实报告比率，不得声明该场景已通过；
16. bundled 卡片只出现在 Awaken Skills，标签为“Awaken 内置”且没有删除图标；project/user 卡片点击删除后出现确认弹窗，取消不改变目录和列表，确认后对应完整包从 `.awaken/skills` 消失、进入系统 Trash、卡片同步消失且刷新后不再出现；MCP 与其他非 project/user 来源仍展示禁用删除入口并说明来源不受本页安装生命周期管理。
17. 仓库已随附 `word` / `excel` / `ppt` / `pdf` / `code-search` / `typst-pdf-maker` 六个 bundled 包：需逐包验证 Awaken Skills 视图加载与卡片展示、`${AWAKEN_SKILL_DIR}` 路径替换、user/project 同 ID 覆盖与移除后恢复；Office 包还需验证 `skill_resource_read` 读取 references、模型真实端到端调用（生成文件 → 视觉 QA → `artifact_publish` 卡片）以及重启后回放；`code-search` 需验证带语言、版本、具体符号、最小片段、风险和来源的真实 WebSearch 调用；`typst-pdf-maker` 需分别验证固定路径/PATH 复用、缺失时固定版本安装、报告与 Markdown strict compile、逐页视觉复核和 `artifact_publish`，并确认通用 PDF/PPT 请求仍分别路由到 `pdf`/`ppt`。未执行的项只能如实声明基础设施自动化覆盖，不得声明相关工作流已验收。
18. 先验证 bundled 卡片点击后不打开 Dialog、也不能通过目录 DTO 获得预览 identity；再分别打开一个 project 和 user Skill 的预览：顶部只显示固定关闭按钮，滚动区先显示含 `---` 的原始 frontmatter，再完整渲染正文。使用鼠标滚轮、触控板、方向键、Page Up/Down、Home/End 从文件开头浏览到末尾，并逐段与磁盘原文件核对；删除按钮不得打开预览，Escape 关闭后焦点回到原卡片。以 `dws` 或同等级长文验证只有正文纵向滚动，任务列表的 checkbox、长文本与行内代码保持同一内容流，代码和宽表格只横向滚动；在 Dialog 打开时切换浅色/暗色，核对文字、代码、表格、引用、链接、遮罩与滚动条对比度；含 HTML/script、外部图片、Mermaid、相对链接和危险协议的 fixture 均不得执行或发起请求。

## 3. 平台矩阵

| 范围 | macOS | Windows | Linux |
| --- | --- | --- | --- |
| 默认 managed/user/project 路径 | 代码支持 | 代码支持 | 代码支持 |
| OS path-list 扩展 | 自动化可覆盖 | 需 Windows CI/实机 | 需 Linux CI/实机 |
| inline/fork/journal | 需本轮 Desktop 复验 | 尚无实机证据 | 尚无实机证据 |
| 安装后包内 Python/Node/Shell 脚本 | 默认当前登录用户 direct Shell，需本轮 Desktop 交互验收 | 代码为当前用户 direct Shell，尚无 Windows 实机证据 | 代码为当前用户 direct Shell，尚无 Linux 实机证据 |
| replace/Trash | macOS adapter 可自动化并需 Desktop 复验 | Explorer Recycle Bin adapter 已 cross-compile，尚无实机 | adapter 不支持，必须 fail closed |

缺少真实 Desktop 证据时只能声明自动化覆盖，不能声明跨平台产品验收通过。任何未在对应 OS 真实 Awaken Desktop 中操作的平台行都不得写为“已通过”；cross-compile、路径单测和市场包 fixture 都不是实机替代品。
