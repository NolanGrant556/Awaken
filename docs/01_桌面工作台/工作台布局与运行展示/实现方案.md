# 工作台布局与运行展示 · 实现方案

本文说明代码职责、数据与接口、异常恢复和验证方法。功能范围及用户操作见[需求文档](需求文档.md)。

## 响应式行为

- sidebar 和 inspector 偏好宽度可调整并写入 renderer localStorage。
- sidebar 支持 `Cmd/Ctrl+B` 折叠。
- inspector 在窄窗口按媒体查询自动折叠，恢复宽度后回到折叠前状态。
- 展开态中栏最小阅读宽为 `520px`。有效右栏宽由 `workbenchLayout` 计算：先取当前 cap（普通右栏=用户偏好，文件工作区=720 且不写回偏好），再按 `window - sidebarOrZero - 520 - separators` 压缩，并夹在最小 260 与 cap 之间。窗口再窄则沿用现有 1180 折叠。
- turn 内容列与 center composer 最大宽度为 `760px`。
- marker、composer、return affordance 必须随真实 dock 高度调整，不得靠固定窗口坐标。

## 范围

工作台结构：

```text
AppShell → WorkbenchShell → RunStage / Inspector surface
                           → ExecutionFeed / overlay / ComposerDock
```

运行策略由 Core 工具层决定，耐久记录由运行时保存，AG-UI 字段由协议层定义。Desktop 只负责界面状态和展示。

## 运行视图与异步动作

`runtime/reducer.ts` 顶层只保存当前任务的 `ThreadViewState`，`threadViews` 只缓存非当前任务。离开任务时保存视图、进入任务时移除它的缓存；`threadViewFor` 统一读取当前或后台视图，避免维护同一任务的两份可变状态。视图快照复用同一类型并排除全局字段，不手工重复枚举消息、用量和交互字段。

`useDesktopRuntime.ts` 合并手动刷新与轮询；同一进程最多一个刷新请求，完成后再等 3 秒轮询。各读取独立更新成功项，失败保留上一份数据并设置刷新提示；进程 generation 隔离旧响应。`useDesktopRuntime.test.tsx` 覆盖保留旧值、成功空列表、请求合并和迟到响应。

`useProjectRegistry.ts` 通过 `getSubmissionScope()` 返回提交瞬间的项目、工作区与有效性，通过 `onRunStarted(projectId)` 更新项目选择；`useRunSubmission.ts` 不取得项目 hook 的整份返回值或内部 ref/setter。`useRuntimeInteractions.ts` 拥有外部交互、ACP 权限和 Computer review/handoff 的提交与 pending 标识，App 只连接当前运行事实与展示回调。

`runtime/compact-event.ts` 统一解码 canonical 字段、历史别名及旧文本，reducer 和 narrative projector 使用同一结果。完整用量与 compact diagnostics 的分离规则保持不变。`compact-event.test.ts` 覆盖字段优先级、零值与旧记录。

`WorkbenchVisualContracts.behavior.test.tsx` 用真实组件检查按钮和子智能体详情结构；`RunStageLayout.test.ts` 解析 CSS 规则及必要的容器归属，不按函数源码位置截取组件。样式测试通过 `style-test-source.ts` 解析本地 import，组件迁移文件不改变断言含义。

## 唯一容器与插槽

`RunStage` 是中间区域唯一的滚动、定位、overlay 和 composer 容器。它只有三类内容入口：

1. children：center 空态，或运行态 `ExecutionFeed`；
2. `overlay`：notice、turn marker rail、return-to-latest、上下文用量面板、媒体预览层；
3. `composer`：运行态 `ComposerDock`。

禁止在 `RunStage` 外为中间区域新建 fixed/absolute 容器。需要新增悬浮或底部能力时，必须先判断属于 overlay、composer stack 还是 narrative；无法归属意味着契约需要先变更。

唯一例外是 `WorkbenchShell` 已声明的 Inspector 扩展形态：它仍渲染同一个 `inspector` slot，只在 shell 内覆盖 `RunStage` 的叙事内容，不成为中间区域的新 owner。扩展时 `RunStage` 不卸载，`ComposerDock` 继续位于 Inspector surface 上方；会话/文件标签只控制 surface 可见性，不改变 thread、run、scroll identity 或文件预览 identity。

## 分层职责

中间区域由以下职责层共同守护；任何改动必须明确自己属于哪一层，不得越层：

| 层级 | 代表 | 职责 | 不可做的事 |
|------|------|------|-----------|
| 设计系统 | `AwakenRunStage`、`AwakenExecutionFeed`、`AwakenMediaItemCard`、`AwakenMediaPreviewOverlay`、`AwakenDeliverableCard`、`AwakenComposerDock`、`AwakenComposerBar`、`AwakenReconnectStatus` 等 | UI-only 结构、视觉、局部受控交互 | 不读取 runtime、Electron、SSE、workspace 或 `window.awaken` |
| Desktop 编排 | `App.tsx`、`useThreadSession.ts` | 组合 slots、订阅 runtime、把 reducer state 转为组件 props、保留 per-turn 局部 UI 状态 | 不定义 tool 安全策略；不把滚动公式重新内联 |
| Electron Main 媒体桥 | `artifact-media-manager.ts`、`artifact-open.ts` | 以 durable identity 复验 ready media Artifact；历史 run 仅允许按同一媒体 tool result 中的精确 ready path 兼容恢复；签发短时 opaque URL并按 Range流式读取 | 不把真实文件路径或任意 `file://` URL暴露给 Renderer |
| Scroll controller | `apps/desktop/src/renderer/useRunStageScrollController.ts` | RunStage DOM 引用、wheel/touch/pointer 意图、anchor/follow、ResizeObserver、CSS layout facts | 不生成 narrative item；不渲染业务卡片 |
| 纯决策 | `workbenchPresentation.ts` | turn grouping、process segmentation、marker 采样、scroll/layout predicates | 不访问 DOM、React state 或网络 |
| Narrative projector | `apps/desktop/src/renderer/run-narrative/projector.ts` | 协议 event 到稳定 item、幂等和 tool pairing 表达 | 不操作滚动和布局 |
| runtime reducer | `apps/desktop/src/renderer/runtime/reducer.ts` | 运行状态、thread view、artifacts、tool records、终态 deliverables summary | 不拥有 UI placement |

## 核心必须保持的规则

### `RunStage` 唯一 ownership

滚动事件、程序滚动、prompt 定位、marker overlay、return overlay 和 dock composer 都必须在同一个 `RunStage` 坐标与滚动体系内。

### `ExecutionFeed` 只承载 narrative / turn

`ExecutionFeed` 内只允许 lead narrative、`execution-turn-section`、prompt header、turn body 和 narrative item。供应商重连是 turn body 里的 live `providerReconnect` item，出现在当前执行游标，不是计时行下的固定槽，也不是 overlay、gate 或新的 feed 容器。输入、toast、marker、return、设置面板和专用 gate 不得进入 feed。

### Prompt 始终属于 Turn

prompt 只在对应 `execution-turn-section` 的 header 内渲染。禁止创建 feed 外 sticky 副本、全局 prompt header 或用 marker 点击改写 latest turn 身份。

用户消息撤销/编辑的 action bar 与 inline editor 仍属于该 turn header：Design System 只接收受控 props，`DesktopExecutionFeed.tsx` 绑定稳定 `runId`，`usePromptRewind.ts` 编排 Core 改写与 canonical replay。完整历史和副作用边界只见[用户消息撤销与编辑设计契约](../消息输入与编辑/实现方案.md)。

### Composer 只有 `center` / `dock`

新增第三种 variant 前必须同时变更产品、架构、状态与验收文档，并在真实 Desktop 验证所有旧旅程。

`App.tsx` 是 Composer draft 的唯一业务 owner，并通过 `activeThreadId` 选择 `useThreadComposerDraft` 中的 owner bucket；`new-thread` 是未创建会话的独立 bucket。Design System 只回传受控正文、结构化 token 和逻辑/视觉 selection，不能保存第二份 thread draft、读取 active thread 或在 center/dock 切换时复制草稿。会话 replay 与运行 reducer 也不得接管未提交 draft。

### Return affordance 不参与布局

return-to-latest 必须是 `RunStage.overlay`。透明容器不拦截 pointer，只有 32px 按钮本体响应点击。它不能成为 ComposerDock 子项，不能进入 composer inset、safe area、output gap 或 wheel 转发链。

### 用户意图与布局事实分离

wheel/touch/pointer/marker/return 是意图事件；ResizeObserver、markdown 增高、prompt 高度、composer 高度和 viewport resize 是布局事件。布局事件不得直接恢复或暂停 follow。

### 设计系统保持 UI-only

Desktop 可以给设计系统传 props、controlled state、callbacks 和 CSS variables；不得把 runtime client、AG-UI reducer、Electron IPC、workspace policy 或 thread persistence 放入设计系统。

### 上下文面板不改变滚动与 Composer ownership

`App.tsx` 从 runtime 投影 usage 数据；`useWorkbenchPanels.ts` 拥有 open state 与触发器 ref，`WorkbenchOverlays.tsx` 在 `RunStage.overlay` 内编排面板。overlay 外层必须 pointer-through，只有面板本体 pointer-auto。面板不能进入 `ExecutionFeed` 或 `composer-dock-stack`，不能参与 composer inset/height、safe area、native tail、marker 或 return-to-latest 定位；关闭时焦点回到触发器，数据更新不抢焦点。面板的 bottom 定位只使用实测 `composerBarInsetPx` 加 12px overlay gap，不得加入为最终输出、marker 和 native tail 保留的 72px output safe gap。

`runtime/reducer` 必须把完整 `ContextWindowRecord` 与 compact diagnostics 保持为两个独立 authority。`AWAKEN_COMPACT_STARTED`、`AWAKEN_COMPACT_FAILED` 和只含压前/压后估算的 finished event 只能更新后者，不能覆盖最后一份带 typed breakdown 的完整用量快照。live 成功 compact 后由新的完整 `AWAKEN_CONTEXT_SNAPSHOT` 原子替换面板数据；Journal 回放没有临时 started/failed frame 时，Renderer 只把耐久 `compact_summary` / `native_compaction` usage 当作不展示的冻结标记，且只有完整 snapshot 已满足自身 `compact_target_tokens` 才可判为压后原子快照。失败尝试后的高位 snapshot 继续隐藏，直到下一 run 边界。Design System 只消费稳定用量与缓存/成本展示字段，不消费 compact diagnostics、failure reason、invalidation reason 或压缩辅助 usage。

`runtime/error-display.ts` 是 root run 错误文案的 Renderer 单一映射；reducer 与 `run-narrative/projector.ts` 必须共同消费它。内部压缩 reason 只能映射为通用失败文案，不能由 reducer timeline、narrative final answer 或 inspector 另行拼回；原始事件仍保留给 Core/AG-UI/Journal 诊断。

### 媒体预览不转移 Artifact 或滚动 ownership

`useWorkbenchPanels.ts` 持有预览选择与同组顺序，`useArtifactMediaSources.ts` 持有历史媒体兼容请求、Main 签发的 opaque source 与解码元数据，App 只组装当前选择的投影；兼容路径本身不构成授权，Main 必须逐次回查 transcript 精确匹配。opaque source 是短时句柄：切到会卸载 Workbench 的 Skills / 连接器 / 定时任务后返回同一 thread，或卡片、中间预览、右侧文件标签触发 `onMediaError`，由 `useArtifactMediaSources.ts` 负责按同一 Artifact identity 清空并有限次续签，不得把过期 URL 快照到 surface state 或永久缓存为“已有源”。`AwakenMediaPreviewOverlay` 只接收运行过程媒体；`ArtifactPreviewHost` / `ArtifactMediaPreview` 只接收终态 ready 媒体。运行过程媒体小卡的主键预览层必须位于 `RunStage.overlay`，不得 portal 到中间区域之外或成为第二个滚动 owner；终态 ready 媒体交付卡的主键则把同一 identity 放进现有 Inspector slot，并在右侧文件工作区临时文件标签中打开。卡片更多菜单留在当前 RunStage 的 clipping ancestor 内，由 UI-only 定位层按真实可用空间执行 flip/shift，不能越过 Composer 建立新的浮层 owner。图片缩放、视频 controls、元数据读取、右侧查看与 source 续签都不写 runtime；系统打开和定位仍逐次经 Main 按 durable identity 或受限兼容记录复验，Renderer 不得获得绝对路径或拼接 `file://`。

### Activity Batch 只属于 Renderer presentation

`NarrativeActivityBatch` / `NarrativeActivitySegment` 由 `workbenchPresentation.ts` 纯函数生成，只重组 Renderer 已有 `exploring/tool/skill` 的展示顺序，不写 reducer、transcript、AG-UI 或 Core schema。`useNarrativeRenderer.tsx` 与 `StoredExecutionDisclosures.tsx` 按稳定 thread/turn/segment/action identity 保存当前 Electron 生命周期内的批次自动状态与用户展开选择、关联 `toolResults` 与 `patchPreviews`、生成确定性摘要和脱敏 `ToolTraceDetailCard`；不得用数组下标生成 disclosure key，状态不进入 runtime transcript 或磁盘历史。Design System 的 `AwakenToolTraceGroup` / `AwakenToolTraceLine` 只消费 props 并回传开合/复制事件，不读取 runtime 或 Electron bridge。

批次或详情展开产生的高度变化仍只是 RunStage 内容变化；不得调用 follow resume、改写 prompt anchor、建立第二滚动容器或接管 `useRunStageScrollController`。关闭时正文、子行或详情卡必须保持挂载到实际 `grid-template-rows` 过渡完成，再从 DOM 卸载；长历史的 `content-visibility` 只能命中完全折叠态，不能在 closing 态用估算高度截断尾帧或让下方叙事发生第二次位移。减少动态效果时直接进入折叠终态。外层 `executionProcess` 分段、final ownership 和媒体/Subagent/gate 边界保持原 owner。

### 模型续接等待只消费 live turn transition

工具结果后的模型等待由 `run-narrative/projector.ts` 消费 live `AWAKEN_TURN_STARTED.transitionReason`，对 `tool_result_continuation`、`max_output_continuation` 和 `xml_fallback_continuation` 创建临时 `planning` item。上下文压缩从 live `AWAKEN_COMPACT_STARTED` 创建 run-scoped `planning`，compact finished 只保留 reducer/inspector 的耐久边界事实，随后的 `reactive_compact_retry` 复用同一 planning identity；因此 Renderer 只显示一条“上下文压缩中”，不渲染 compact boundary 或完成行。`App.tsx` 只把该 item 的确定性 label 传给现有 `AwakenThoughtTrace`，并用场景 CSS 延迟其出现；Design System 不读取 turn、tool 或 provider 状态。

该状态不得从 tool card 完成时间、`isBusy`、provider/model 名称或本地计时器猜造，也不得把工具改回 running。首个 reasoning/text/tool event 通过既有 active-item ownership 接管；terminal event settle 后由 trailing-planning 过滤规则隐藏。compact boundary 仍可留在 reducer/inspector 供恢复和诊断，但 `projectVisibleNarrativeItems()` 必须过滤它；`AWAKEN_TURN_STARTED` 没有 durable replay 投影，历史加载不得重建已经结束的等待状态；`model_request` 继续只属于 journal 审计，不为本 UI 暴露请求正文或 provider 私有状态。

### Subagent 执行详情属于 Inspector 标签页

`subagentGroup` 只在 `ExecutionFeed` 中展示子任务摘要。分组标题右侧在仍有 queued/running/cancelling 任务时显示“停止全部任务”，由 Desktop 传入既有 `stopThreadAgents` 回调；该回调只取消活动子任务并把用户停止交给主 Agent，不取消当前 root run。Design System 只渲染按钮，不读取 runtime。该按钮不再放进 `DesktopWorkbenchChrome` 右侧 action group，避免与 Inspector 开关重叠。点击 row 后，`useWorkbenchPanels.ts` / `inspectorTabs.ts` 按当前 thread 与精确 TaskID 打开标签，`DesktopWorkbenchChrome.tsx` 在右侧标签带中展示，`SubagentPanel.tsx` 从 reducer-owned `SubagentTaskView` 渲染执行详情。`useFileWorkspaceSession.ts` 按 thread 记住右侧栏折叠；切到未展开过的会话时收起，返回原会话时恢复该会话自己的状态。新任务首次获得 thread id 不因此收起。左侧功能页只隐藏 inspector，不改当前会话的折叠记忆。`WorkbenchOverlays.tsx` 不再渲染子任务浮层，也不再计算子任务与 Composer 的底部间距。右侧标签在顶栏内垂直居中，上、下留白相等，圆角盒完整露出，下方保留与内容区的分界线。

`runtime/reducer.ts` 接受子任务终态时，通过 `settleSubagentNarrative` 同步结束该 TaskID 的 narrative 活动项，移除临时 planning/reconnect，保留静态思考与已有工具结果；没有结果的工具只投影为 cancelled/interrupted，不伪造成功回执。终态之后的非耐久思考、正文和工具准备片段不再进入展示；耐久正文快照与真实工具结果仍可补齐历史，归并后再次按原终态收口。Read 批次按工具身份查找已有分组，迟到结果更新原位置。新分配有独立 TaskID，不继承旧分配的终止展示状态，也不因主回复完成而停止仍在后台运行的子任务。

`runtime/reducer.test.ts` 覆盖缺失 reasoning-end 的四类终态、迟到片段与耐久快照、真实工具结果补齐和分配隔离；`TraceDisclosures.test.tsx` 将 reducer 结果传入子任务面板和真实思考组件，检查终态移除动态思考节点、正文仍可展开、重新挂载不重播。运行 `npm --workspace @awaken/desktop test -- src/renderer/runtime/reducer.test.ts src/renderer/run-narrative/projector.test.ts src/renderer/TraceDisclosures.test.tsx`。这些是自动化组件验证；取消后思考动画修复的真实 Desktop 复验待用户执行，已有窗口截图不作为本项通过证据。

窄窗口自动折叠规则保留。用户点击子任务重新打开时，Desktop 向 WorkbenchShell 传入 `inspectorNarrowLayout=split`，Shell 保持两列，右侧面板不覆盖主输入框；文件视图沿用原布局。该属性只决定 slot 布局，不读取运行或子任务状态。

右栏正文有自己的有界滚动区，标题与模型、工具、token、耗时按可用宽度换行；不挤出关闭标签和 Inspector 控件。不同分配保留各自终态，重复点击同一分配不新增标签。文件预览在子任务激活期间保持挂载并隐藏，返回原文件标签立即恢复。打开、切换、关闭标签或流式增长正文不向主 narrative 添加节点，也不改变主 Composer 草稿或 follow 意图；右栏宽度变化仍交给既有布局控制器。

实际窗口证据见[子任务面板验收](../../../apps/desktop/test-fixtures/subagent-panel/verification.json)，包含窄窗口分栏前后的对照、深浅主题及主输入框保留。

详情不提供子任务输入、追加或继续。停止执行通过原取消接口，关闭标签只改变本地视图。主 Agent 的消息和续派能力由[子智能体协作](../../02_主智能体闭环/子智能体协作/实现方案.md)拥有。

### 选择范围由焦点与正文白名单共同决定

`.desktop-root` 先建立不可选择的应用壳默认值；只有编辑控件、最终回答 Markdown、Prompt 气泡内标记为 `.aw-text-selectable` 的正文/token/附件名，以及其它明确的阅读正文可以恢复 `user-select: text`。`AwakenUserPromptBlock` 拥有可见复制文本的默认拼装与选区复制序列化（附件显示名 + token 标签正文流，避免软换行变硬换行），通过 `data-aw-select-all-root` 承接 `Cmd/Ctrl+A`，在 selection 穿过原子 token 时给图标、间距和 label 组成的完整节点补齐选中底色，并在拖选时抑制单击展开；Desktop 不得再传入仅含 durable 纯正文、丢掉可见 token/附件名的 `copyText`。`AwakenComposerInlineInput` 的 copy/cut 同样写入可见 token 标签。键盘全选由 Main 截获 `meta/control + A`（macOS 与 Windows/Linux 共用判定）后通过 Preload 单向通知 Renderer；`desktop-selection.ts` 解析当前焦点或选区所属的 editing host / select-all root，可穿越 atomic `contenteditable=false` token。该链路不得读取 runtime、修改 narrative、重建 Composer DOM，或接管 `Cmd/Ctrl+C/X/V/Z` 等其他系统编辑快捷键。

### 启动与重启提示

`DesktopStartupStatus` 同时消费 Desktop 的 starting 与 needsRestart 投影，错误优先于启动，恢复就绪后淡出；启动期间到达的错误会取消旧淡出计时器。首页将它放在 `desktop-task-welcome` 内，绝对定位到品牌标识上方，不参与品牌与 Composer 的测量；对话页放在原 composer-dock-stack 中。两处只显示文字，错误使用 alert 和主题错误文字色，不生成 runtime panel 卡片。`useComposerLifecycle` 继续管理发送、停止、可用性和焦点，不再生成错误卡片；文件覆盖态仍通过 desktopNeedsRestart 保持完整 Composer。

`DesktopStartupStatus.test.tsx` 覆盖错误优先级、淡出取消与恢复；`npm run test:composer-layout` 在隔离 Electron 中测量错误文字位于品牌上方且输入框不位移。真实应用只在实际出现对应状态时记录验收，不通过终止用户正在使用的 Core 制造崩溃。

macOS 当前证据见[排版与浮层验证记录](../../../apps/desktop/test-fixtures/composer-visual-layout/verification.json)。记录区分隔离 Electron 几何、真实 Desktop 输入/选择/消息回读与未执行的故障注入；截图不扩大为其他平台通过证明。

### 焦点视觉由真实输入方式决定

`AwakenSelect` 在组件根节点统一处理展开态 Escape，覆盖焦点位于触发按钮和选项的情况：阻止默认行为及事件冒泡、关闭菜单，并以 `preventScroll` 恢复触发按钮焦点。关闭态不消费 Escape，外层 Dialog 的正常关闭行为保持可用；不在 Desktop 全局键盘层猜测当前浮层。`NestedMenuEscape.behavior.test.tsx` 验证首次关闭菜单、草稿保留和第二次关闭弹窗，并以现有 portalled `AwakenDropdown` 作为父弹窗保留的对照。定时任务创建入口的真实操作证据见[浮层验证记录](../../../apps/desktop/test-fixtures/related-popover-layout/verification.json)。

`apps/desktop/src/renderer/main.tsx` 与 Design System Gallery 根入口必须通过公开的 `installAwakenFocusModality` 安装同一输入方式控制器。捕获到 pointer down 时根节点进入 `pointer`，方向键、Home/End、PageUp/PageDown、Enter、Space 或 Escape 可以进入 `keyboard`；普通正文输入和带修饰键快捷键不能把鼠标焦点误标成键盘导航。Desktop 入口在该控制器之前安装 `installDesktopKeyboardPolicy`，capture 阶段直接消费未修饰 `Tab` / `Shift+Tab`，所以 Tab 不会进入 modality 控制器或改变页面焦点；Gallery 不安装这项 Desktop 产品策略。程序化 `focus()` 继承最近一次真实输入方式，不自行抢占 modality。

`tokens/base.css` 在 pointer 模式统一关闭 `:focus-visible` 的外置 outline；keyboard 模式继续由组件提供确定性反馈。当前 `.thought-trace-heading` 在 keyboard 模式关闭自身外轮廓，并把反馈投影为标题文字下划线；其他控件仍沿用已有的组件级 `focus-visible` 样式，后续只有在同一改动中补齐文字、图标、内部 surface、既有 border 或 inset focus 等替代反馈后才能移除外轮廓。不得通过全局永久 `outline: none` 删除键盘导航反馈，也不得在每个组件内复制 pointer/keyboard 事件监听。

### 首页作用域低栏保持单一 thread/project authority

首页项目作用域低栏是 `center` ComposerBar 的 UI-only 子结构，不是第三种 composer variant，也不在 `RunStage` 外新增定位容器。`App.tsx` 必须把“选择项目 + active 项目”投影、当前 `conversationScope` / `selectedProjectId` 和既有作用域选择/创建/清除回调作为受控 props 传入；无项目时的“选择项目”是无图标占位状态，表示空 `projectId` 和电脑全局对话范围，不是项目、文件夹或隐藏 workspace。已选项目的清除按钮与菜单触发器必须是并列交互元素，不能嵌套按钮；清除点击必须阻止菜单触发，只复用 Desktop 既有无项目作用域动作。Design System 只能展示选中项、hover/focus 清除态、菜单与创建入口，不读取 workspace、FileStore、Electron bridge 或另存作用域状态。侧栏继续用“对话”分区承载空 `projectId` 的 thread；两处文案职责不得混合。进入 `dock` 后该低栏卸载，不能进入 `ExecutionFeed`、overlay 或 composer dock 测量。

### Inspector 扩展不转移 Composer ownership

文件 surface 激活时，`AwakenWorkbenchShell` 只把 Inspector 放入 shell-level overlay；RunStage、当前 thread 的 reducer、事件归并和滚动 identity 继续存续，但 `ExecutionFeed` 重型视图不挂载，返回会话 surface 后从当前状态原子重投影。`App.tsx` 必须把展开/收起控制放在文件标签带之外的顶栏固定 action group，并紧邻固定锚定的 Inspector 开关，两者落在同一条 44px 顶栏水平中线上；右侧栏折叠时隐藏该控制，标签标题只能在自身 rail 内收缩或横向溢出，不能改变两个固定按钮的位置。若此时原场景满足 `center` 条件，Desktop 复用现有 `dock` variant 放置同一草稿、token、附件和提交回调；切回会话 surface 后按原条件恢复 `center`。`ExpandedFileComposer` 只根据 Desktop 传入的 surface、run、终态和局部唤起态切换横线/紧凑/完整/执行/完成呈现；运行中仍尊重 `idleMode` 的横线/完整，紧凑才显示“正在执行”胶囊。非完整态不挂载完整 ComposerBar，草稿事实仍由 `App.tsx` / thread draft owner 持有。从文件 surface 提交后切到紧凑胶囊；停止只走胶囊上的独立 `AwakenSendButton` 或完整输入面原停止按钮，点胶囊主体只展开。预览单击缩小不再因 busy 被挡住。“已完成”必须绑定由扩展文件 composer 发起的明确 `threadId + runId`，不能从当前历史 reducer 的任意 `finished` 状态反推。用户问答、外部授权或 runtime 异常面板必须强制完整态。禁止把 Composer 渲染进 `ProjectFilesWorkspace`、复制 draft state，或用文件组件管理 run。

Electron Main 是主 Renderer 进程异常恢复 owner。向 Renderer 投递事件必须把“WebContents 尚存在但 main frame 已销毁”视为发送失败，立即取消该窗口的 SSE 订阅，不得继续产生逐事件错误风暴。`render-process-gone` 为非 clean-exit 时只允许一次有界 `reloadIgnoringCache`；恢复后的 Renderer 从 Core/journal 重新订阅和重放。短时间内再次退出不得形成无限重载循环，正常退出与应用关闭不得触发恢复。

`ProjectFilesWorkspace` 只在主键 pointer down/up 属于同一手势且移动未越过阈值时报告预览单击，不能在 pointer down 阶段收起 Composer，因而代码、Markdown、PDF 等正文拖选仍保留。Office 预览运行在隔离 guest 中，guest DOM 事件不越过 `<webview>`；Main 只能从已授权 preview `WebContents` 的 `before-mouse-event` 识别同一点击手势，经 Preload 暴露的 typed 单向通知回传 `previewId`，Renderer 再与当前 Office handle 核对。该通知不得注入 guest preload、放宽 sandbox/partition/permission 策略，或携带路径和正文。

文件树右键菜单仍由 `ProjectFilesWorkspace` 拥有场景交互，但“添加任务”必须回调 `App.tsx` 的唯一 Composer draft authority，不能在文件组件内另存正文或 token。Main 的 typed IPC 每次按当前 active project 重验条目后才允许复制路径、返回 token identity 或用固定 bundle id 启动外部应用；Renderer 绝对路径不是授权。Core 在 StartRun 前对 `file` token 按当前 TaskScope 再验证，并只在模型 effective input 中恢复路径；Design System 只处理原子 token、逻辑 selection 和视觉，不读取路径或 Electron bridge。终态 ready 图片/视频临时文件标签与运行过程媒体 overlay 分属不同 owner：前者是 `ArtifactPreviewHost` / `ArtifactMediaPreview`，后者是 `AwakenMediaPreviewOverlay`；二者都不复用旧的专用媒体查看器。

### 模型选择不转移凭据与运行策略 ownership

`AwakenComposerBar` 只拥有模型菜单、二级 effort 面板、键盘交互和档位 change callback，不读取 provider catalog、thread store、Electron bridge 或凭据。`App.tsx` 把 enabled profile、有效 capability 和当前 thread preference 投影为受控选项；既有 thread 的保存经 RuntimeClient/typed IPC 进入 Core thread metadata，新 thread 草稿只由 `App.tsx` 暂存。

Renderer start-run 只提交 opaque `modelProfileId` 与 Awaken 档位。Electron Main 必须重新解析 enabled profile、账户 secret 和有效 capability；Core/provider adapter 分别拥有 run snapshot/cache identity 与原生 effort 映射。禁止把完整 profile、Base URL、API key、provider 原生值或 profile store 下沉到 Design System/Renderer。run busy 时 UI 禁用修改，不能通过二级面板热改正在执行的 Agent。

### 文件行评论不转移文件、Composer 或 run ownership

文件行评论与 Markdown 已选文本当前已按[文件行评论设计契约](../文件浏览与评论/实现方案.md)实现。CodeMirror 只拥有 selection、整行高亮、gutter 入口和文件内容坐标内的 block widget；Markdown 渲染层只从 parser source position 派生源码行范围和选择动作。`App.tsx` / `useThreadComposerDraft.ts` 拥有按 thread 隔离的结构化文件上下文、Composer 汇总与提交事务；Design System 只消费 `comment | selection` view model、历史气泡 structured content 和 callbacks；Core 在 `StartRun` 写 journal 和模型调用前拥有项目、路径、digest、行范围与 canonical excerpt 的最终复验，并只把 `comment` 视为指令、把 `selection` 视为上下文。二者不得成为 `RunStage.overlay`、第三种 Composer variant、文件写回或附件/token 的别名，也不得改变叙事滚动、prompt anchor 或文件预览 identity。

## Gate 与工具轨迹边界

新 run 不渲染通用 `ApprovalCard`，不通过 composer 恢复 `awaiting_approval`，也不调用旧 `resolveApproval`。工具决策只投影运行时结果。此处只拥有 UI placement，决策枚举和安全语义由 `README.md#04_工具权限与审批` 路由。

专用 `ask_user`、通用 `ExternalActionGate`、Computer 的 `ComputerReviewGate` 与 `ComputerHandoffIndicator` 位于 composer stack。`ask_user` 显示时普通 ComposerBar 保留在 gate 下方并维持既有忙碌/停止态；具体行为与[产品与交互契约](需求文档.md)一致；`App.tsx` 继续拥有草稿与既有 answer/cancel 回调，问题面板不得复制输入状态、run 状态或 runtime client。Computer gate 只消费 run-bound 的 review/handoff 投影并调用 Desktop Main 受控 resolve/return IPC；不得在 Renderer 重算风险、直接执行输入或把 control token 暴露给页面。常态 Computer 调用提示不属于 Workbench：`ComputerOverlayManager` 由 Electron Main 拥有，独立透明 `BrowserWindow` 只消费 Main 自己订阅的 run event，并通过 overlay 专用 preload IPC 终止当前 run 的 Computer session，而不取消 run；同一 manager 另建一枚始终点击穿透的虚拟鼠标窗口，只根据 `AWAKEN_COMPUTER_POINTER_HINT` 移动，不得成为 stop IPC 发送者。窗口在自身 renderer 与样式加载完成后才显示，并用自身 watchdog 恢复置顶可见性。它可以参考宠物浮窗的 Electron 可见性约束，但不得复用 `PetWindowManager`、宠物 IPC、宠物 placement 或宠物 activity state；这些窗口必须独立创建、独立显示和独立销毁。Renderer、RunStage、composer 测量、feed、narrative 和 replay 均不得拥有或复制该提示或虚拟鼠标。`ExternalActionGate` 只消费 run-bound 的非敏感 interaction 投影（HTTPS URL、受控二维码协议 URL、安全说明与 recoveries），不得读取二维码文件路径、CLI stdout/stderr、device code、token 或配置；这些 gate 都不进入 projector、ExecutionFeed、narrative step、transcript 或历史 replay。兼容期内 Main 内存 `CliAuthSessionView` 仍可投影为同一视觉容器。legacy approval 只能成为只读 tool-style narrative，不能重新提供按钮。

消息发送没有 Desktop 审核卡片、pending review 状态或 resolve IPC；Renderer 不按收件人、工具名或消息数量重做后端权限判断。Skill Slash 也只消费 server catalog，不能在 renderer 根据来源、依赖或文件内容重做 availability/权限判断。

## Turn 身份

`groupNarrativeByTurns()` 按输入顺序处理 narrative：

- 第一个 prompt 前的 item 进入 `leadItems`；
- 每个 prompt 开启一个 `NarrativeTurnSection`；
- 后续 item 进入最近的 prompt turn；
- turn id 等于 prompt item id；
- `latestTurnId` 是最后一个 prompt turn，不受 marker 点击影响。

DOM identity：

```text
section.execution-turn-section
  data-execution-turn-id=<prompt item id>
  div.execution-turn-column
    div.execution-turn-header
    div.execution-turn-body
```

`currentTurnId` 表示 anchor 位置当前采样到的 turn；`latestTurnId` 表示 narrative 顺序最后一个 turn。二者必须分离。

### 派生状态

以下不得另存为第二套真相：

- `latestPromptId`：最后一个 turn id；
- `activeWorkbenchTurnId`：合法 current turn，否则 fallback 到 latest turn；
- `returnToLatestVisible`：`followMode === paused_by_user && hasLatestTurn && 已离开最新输出`（不在 latest tail，也不在 native bottom）；
- `showTurnMarkerRail`：marker display mode 非 hidden；
- `composerSafeAreaPx`、`composerBarSafeAreaPx`；
- `latestTurnMinHeightPx`；
- marker rail 可用高度。

### 局部 UI 状态

`App.tsx` 只另持有 `promptBubbleModeByTurnId: collapsed | expanded`。execution process、Activity Batch 与 Tool disclosure 由独立 store 按稳定的 thread + turn ID + segment ID + action ID 保存；store 同时区分自动状态和用户选择，用户选择优先。活动批次在当前 Electron 生命周期内因 workspace/thread 切换临时卸载时保留离开前的自动可见状态，不能在 replay 首帧无故收起。store 使用 `sessionStorage` 承受 workspace surface 的页面模块重建，但不进入 runtime transcript、用户设置或磁盘历史，也不通过 `App.tsx` state 触发整棵 Workbench 更新。它们的高度变化只能触发布局重测，不能改变 follow 意图；关闭窗口并完整重启后恢复默认折叠。

turn 顶部 `RunElapsedTime` 不是滚动状态。它使用固定行高与等宽数字，只更新本行文本；秒数变化、运行阶段切换和终态冻结都属于被动内容变化，不得进入或退出 `paused_by_user`，也不得触发第二套 follow。

## Reducer 事件与转换

### 准备新 run

`prepare-run-start`：

- 清空 current turn 和 pending anchor；
- `followMode = anchoring`；
- 清空 resume intent 和 programmatic scroll；
- latest turn 出现在 narrative 后，由 `bind-latest-turn` 写入 pending anchor。

`prompt-anchored` 完成后：

- current turn 变为新 turn；
- 清空 pending anchor；
- turn 已有 body 时进入 `following_latest`，否则保持 `anchoring`；
- body 后续出现时 `latest-body-ready` 进入 follow。

#### 首帧 anchor 原子性

`run/requested` 把新 prompt 投影进 narrative，与 `bind-latest-turn` / `anchor_prompt` 共同组成一次用户可见的提交转换。内部状态可以经历 `anchoring`，但必须对用户保持原子性：

- 新 turn 的 prompt DOM 可定位后，controller 必须在浏览器绘制该 turn 的首个用户可见帧前，以 `anchor_prompt` 原因完成顶部锚定；
- 新 prompt 的首个用户可见帧必须已在 `containerTop + anchorOffset` 锚点；
- 旧 final answer 或 deliverables 下方的自然 append 位置不得成为可见帧；后续 effect、animation frame 或 body-ready follow 再把 prompt 移到顶部，不算完成首帧 anchor；
- `latest-body-ready` 只负责进入 latest-output follow，不得补做或掩盖提交时未完成的 prompt anchor。

### 新任务空态

`prepare-new-task` 和没有任何 prompt 时的 `reset-empty` 恢复 initial state：`followMode=idle`，无 current/pending/programmatic 状态，latest min-height 归零。`AwakenTaskWelcome` 字标使用 `draggable=false` 与 `-webkit-user-drag: none`，避免 Chromium 把 `<img>` 当成可拖文件；这不是窗口拖动，也不是可独立位移的图层。

### 切换 thread

`prepare-thread-switch` 当前与 run start 一样进入 `anchoring`，先清空旧 thread 身份；replay 建立 latest turn 后重新绑定并锚定。当前没有按 thread 持久化/恢复精确 scrollTop，也没有恢复旧 thread 的 prompt 展开状态。

### 用户暂停

以下直接输入进入 `paused_by_user`：

- wheel `deltaY < -1`；
- touch 当前 Y 比起始 Y 增加超过 4px；
- RunStage `pointerdown`；
- scrollTop 比前次减少超过 1px 且已离开 native bottom（2px 阈值内仍视为贴底）；仍贴底的 scrollTop 下降是 scrollHeight 收缩时浏览器的被动钳制，属于布局事件，按 [必须保持的规则](实现方案.md#必须保持的规则) 不变量 3 不算用户上滑；
- marker click。

wheel/touch/pointer 可取消 pending prompt anchor；普通 scroll event 只暂停，不一定清除 pending anchor。暂停会清空 resume intent。

### 用户表达恢复意图

- wheel `deltaY > 1` -> `wheel_down`；
- touch 向最新方向超过 4px -> `touch_to_latest`；
- paused 状态到达 latest tail 且 native bottom -> `scroll_to_tail`；
- 点击 return -> `return_button`。

一般滚动恢复必须同时满足：

1. 当前是 `paused_by_user`；
2. latest body tail 位于阈值范围；
3. RunStage 已到 native bottom（阈值 2px）；
4. 已有明确 resume intent。

点击 return 是显式命令：有 body 时直接滚到 native bottom 并 `resume-follow`；prompt-only 或仍 pending 时先 anchor prompt。

## Programmatic scroll 防误判

所有系统滚动必须调用 `scrollRunStageTo(element, scrollTop, reason)`：

1. clamp 到 `[0, scrollHeight - clientHeight]`；
2. reducer 记录 reason 和目标 scrollTop；
3. `element.scrollTo({ behavior: "auto" })`；
4. scroll handler 在 2px 内识别为程序滚动，更新 active turn 后直接返回；
5. 下一帧清理 programmatic 标记。

禁止直接在 `App.tsx` 写 `element.scrollTop = ...` 或新增第二套 programmatic flag。

## Prompt anchor

anchor 目标：

```text
currentScrollTop + promptTop - containerTop - anchorOffset
```

- prompt anchor element 优先 `.execution-turn-header`，否则 turn section；
- offset 读取 RunStage 的 `--aw-prompt-anchor-offset`，无效时为 0；
- 结果最小为 0；
- `activeTurnIdForAnchor()` 在 `containerTop + offset + 1` 处采样最后一个 top 不超过 anchor 的 turn；
- marker click 复用同一个 `scrollPromptToAnchor()`。

## Latest tail 与 follow

当前程序 follow 的唯一目标是 RunStage 的 native max scrollTop：

```text
max(0, scrollHeight - clientHeight)
```

只有 latest turn 有 body 且 pending prompt anchor 已结束时才 follow。

tail proximity 使用 latest turn body 最后一个元素的 bottom；如果该元素包含 `.assistant-message-footer`，优先使用 footer bottom；没有 body 时使用 header bottom。可视高度扣除 output gap，阈值为 48px。

这意味着：最终回答后的 ready deliverables 也是 turn 尾部的一部分。不得把 follow 目标另算成 turn min-height 底部、composer padding 底部或 return button 底部。

## Composer 布局事实

当前常量：

```text
RUN_STAGE_COMPOSER_SAFE_GAP = 72px
RETURN_TO_LATEST_BUTTON_GAP = 12px
```

Dock 内分别测量：

- `composerContentInsetPx`：dock bottom 到 `.composer-dock-stack` top；包括 runtime panels、`ask_user`/`ExternalActionGate` 等专用 gate 和 ComposerBar；
- `composerBarInsetPx`：dock bottom 到固定保留的 `.composer-bar` 输入 surface top，用于 return 和上下文 overlay 与输入框对齐；`ask_user` 作为其上方的 stack gate 只进入 `composerContentInsetPx`，marker 另使用包含 output gap 的 `composerBarSafeAreaPx`；
- `composerSafeAreaPx = contentInset + 72`；
- `composerBarSafeAreaPx = composerBarInset + 72`。

上下文面板的 bottom 为 `max(28, composerBarInsetPx + 12)`；这个 12px 只是面板与输入框的视觉间距，不得复用 72px output gap。

controller 把以下变量同时写到 RunStage 和其父元素：

```css
--aw-composer-content-inset
--aw-output-gap
--aw-composer-safe-area
```

测量由 ResizeObserver 监听 dock、stack 和 ComposerBar。center 形态全部归零。

`ask_user` 出现和移除属于 composer stack 的被动布局变化。普通 ComposerBar 始终挂载并保持可见，草稿 authority 仍在 `App.tsx`；问题面板位于输入框上方并计入 `composerContentInsetPx`，但不接管 `composerBarInsetPx`。运行等待 resolution 期间 ComposerBar 沿用 busy 禁用/停止态；回答或问题取消只移除 gate，后者不改变 run 的 busy/terminal 状态。gate 增删不得改变 follow/paused 意图、turn identity 或 native bottom。

`UserQuestionPrompt` 的标题控制行和回答操作行固定，完整题目、可选 header 与选项共同放入可聚焦的正文滚动区。CSS 为整卡设置视口内最大高度，使用 `auto minmax(0, 1fr) auto` 三行与正文 `min-height: 0`，避免长问题撑高 composer stack；保留正文换行并允许长路径折行。换题时只复位正文 scrollTop，不重置答案。`App.test.ts` 覆盖长正文未被裁短且位于滚动区、按钮在滚动区外；真实 Desktop 还需验证长摘要首尾、键盘滚动、多题答案保留与窄窗口中的按钮可达。

`AWAKEN_USER_QUESTION_REQUESTED` 的正文沿用 Core 工具 JSON，字段为 `multi_select`。Reducer 在进入 UI 状态时显式转换为 `UserQuestion.multiSelect`，缺省或 false 保持单选；不能用 TypeScript 类型断言代替实际转换。`runtime/reducer.test.ts` 使用真实 wire 字段覆盖多选、单选和缺省，Desktop 复测还需连续选择两项、翻页返回并核对最终工具回答。

扩展文件 surface 的横线、紧凑入口、执行和完成态仍位于同一 `ComposerDock > .composer-dock-stack`；这些非完整态不挂载完整 ComposerBar，只由当前可见 pill/rail 决定 dock/stack 高度。草稿内容、token、附件和 selection 继续属于 `App.tsx` / thread draft owner，恢复完整态时重新投影。只有空结构化草稿的完整态可由一次非拖选预览单击转入横线态；pointer down、本次手势发生拖动或草稿含正文/token/附件都保持原高度。因此 `.composer-bar` top 只在完整态参与测量；状态切换只是 ResizeObserver 可观测的被动布局变化，不得改变 follow/paused 意图、turn identity 或 native bottom 定义。

`ExternalActionGate` 的出现、二维码加载、刷新、失败与移除都只属于被动布局变化：ResizeObserver 可更新 inset、output gap 和 marker 可用高度，但不得改变 paused/follow 意图、turn identity 或 anchor。gate 移除后 native bottom 仍是 `scrollHeight - clientHeight`，不得保存第二个授权专用滚动目标。

Computer session 常态悬浮条是 `RunStage.overlay`，不属于 composer stack，也不进入 `composerContentInsetPx`、`composerBarInsetPx`、output gap、marker safe area 或 native bottom 计算。只有悬浮条和停止按钮响应 pointer，其余 RunStage 行为保持不变。

### Latest turn min-height

当前公式：

```text
latestTurnMinHeight = max(0, viewportHeight - anchorOffset - outputGap)
```

`latestTurnMinHeightBottomReserve()` 对 prompt-only、pending anchor 和已有 body 都统一只保留 output gap；`latestTurnPromptAnchorSlack()` 恒为 0。这样程序 follow 与用户手动滚到底只有一个 native bottom，不产生第二个空白滚动目标。

## Return-to-latest

当前可见条件是 paused + latest turn + 已离开最新输出。不要求 run 仍在输出。pointer down、轻微上滑或仍贴着 latest tail / native bottom 时不显示按钮；用户继续上移或最新内容在暂停期间增高并离开视口后才出现。terminal turn 中只要用户仍 paused 且已离开最新内容，按钮也会保留到恢复。

位置：

```text
bottom = max(16px, composerBarBottomInset + 12px)
```

要求：

- `RunStage.overlay` 子项；
- overlay 容器宽高 32px，位于中轴；
- 使用 `--aw-surface-raised` 圆面与 `--aw-text-primary` 箭头，随主题变化且无可见文字；
- 透明区域 pointer-through；
- 不计入 dock、safe area、latest min-height 或 marker rail 高度；
- 多行 composer 增高时跟随 `composerBarBottomInsetPx` 上移。

## Turn marker rail

显示阈值为 3 turns。可用高度：

```text
(scrollViewportHeight + composerContentInset)
  - topInset(28)
  - max(minimumBottom(28), composerBarSafeArea)
```

密度规则：

| 模式 | 条件 | item / gap |
|---|---|---|
| regular | turn <= 12 且可放下 | 18 / 14px |
| compact | turn <= 24 且可放下 | 12 / 8px |
| summary | 其余，最多 24 个且按高度裁剪 | 8 / 5px |
| hidden | capacity < 3 或 center/turn<3 | — |

summary 必须保留首尾、active/latest 焦点及相邻项，再均匀采样；不得仅取前 N 项。marker click 更新 current、暂停 follow，并以 `marker_jump` 原因滚到同一 prompt anchor。

## 嵌套内容的内部滚动

RunStage 内部需要独立滚动的局部内容使用 `data-aw-run-stage-scroll-boundary` 标记。该边界只阻止局部 wheel/touch 意图进入 RunStage follow 状态机，并配合 `overscroll-behavior:contain` 阻止到达边缘后把滚动链交给 RunStage；不得通过 wheel 代理或手动改写父层 `scrollTop` 模拟内部滚动。

RunStage 主滚动视口可为程序定位保留 `tabIndex=-1`，但它不是用户可操作控件，不得显示覆盖整个视口的 focus outline。可见焦点反馈只属于 RunStage 内的真实按钮、链接和可展开控件，避免全宽 outline 被父层裁切成偶发蓝色横线。

Tool 详情卡最高 320px，结构化 sections 或旧 `output` 正文各自只能建立一个内部滚动 owner；父卡片只负责裁切圆角与浮动复制入口。右上复制入口使用无底卡图标，并在细滚动条左侧保留独立命中空间；首段 label/正文同步预留右侧空间。详情标题不占视觉行，只作为卡片可访问名称。详情卡的内部 wheel/touch 滚动与开合产生的被动高度变化不得恢复或改写 RunStage follow 意图；用户在 feed 内的 pointer down 仍按 [Reducer 事件与转换](实现方案.md#reducer-事件与转换) 表达阅读意图。

### Prompt 折叠与内部滚动

`AwakenUserPromptBlock` 的当前阈值：

- `lineCount > 3` 或 trim 后长度 `>160` -> limited；
- limited 折叠 3 行等价高度（Workbench 最大 48px，折叠态行高 16px），裁切盒本身做 mask：第三行约一整行（16px）字形淡出到透明；折叠态底部内边距为 0，并用 `attachment-gap` 的负边距把裁切盒贴到气泡下沿，不用省略号，也不在气泡内铺底色遮罩；
- expanded 最大 162px（9 行等价），`overflow-y:auto`、`overscroll-behavior:contain`；
- App 以 turn id 控制 expanded；
- 点击外部 pointerdown 收起；
- 超过三个附件也使 block 具备隐藏附件状态。

prompt 内部 wheel/touch 滚动使用同一嵌套滚动边界，不得冒充 RunStage wheel/touch 暂停或恢复意图；pointer down 仍按 [Reducer 事件与转换](实现方案.md#reducer-事件与转换) 表达阅读意图。任何修改 48/162、折叠行高、header sticky 或 attachment grid 的变更都必须重新验证 anchor 与 follow。

## 必须保持的规则

1. latest turn 只由 narrative 顺序决定。
2. current turn 可由 scroll、anchor、marker 和 thread restore 改变。
3. 被动布局事件不得进入/退出 `paused_by_user`。
4. marker 跳转不改变 latest turn。
5. 程序滚动必须带 reason 和目标值。
6. return 只恢复，不创造布局空间。
7. marker 和 return 使用 composer bar 高度；feed bottom reserve 使用完整 composer stack。
8. native bottom 只有一个。
9. prompt 展开和 process 展开只改变测量现实，不改变用户意图。
10. center 无 scroll binding、dock 才绑定 controller。
11. 新 prompt 的首个用户可见帧已完成顶部 anchor，不存在自然 append 后再跳转的中间帧。

## 异常与降级

- 找不到 RunStage、turn 或 prompt anchor 时，scroll helper 返回 false，不猜坐标。
- 当前 controller有未守卫的 `ResizeObserver` 构造；环境缺少该API时不能保证初次测量或正常挂载，属于明确兼容缺口，不能宣称有 fallback。
- marker 可用高度不足时隐藏，不让 rail 覆盖 composer。
- return 点击时 latest turn 已消失则无操作。
- thread replay 产生空 turn 前保持 anchoring，直到 DOM identity 可用。

## Narrative 模型

`RunNarrativeState`：

```ts
{
  committedItems: RunNarrativeItem[];
  activeItem?: RunNarrativeItem;
  inspectorSelection?: InspectorSelection;
  seenEventKeys: string[];
}
```

当前 item：

| kind | 身份与作用 | Workbench 当前投影 |
|---|---|---|
| `prompt` | turn 起点，含文本、附件、tokens | `UserPromptBlock` |
| `planning` | 请求初始活动或 live turn continuation | 仅 busy 且仍为 narrative 尾项时投影为动态 `ThoughtTrace`；initial 使用默认 Thinking，continuation 使用确定性阶段文案并延迟 650ms 出现；首个真实输出或终态出现后过滤 |
| `thinking` | reasoning summary | `ThoughtTrace`：active 自动展开透明 `思考中` 状态行和流式正文，done 移除思考球并默认折叠为 `思考过程` + 右侧 Chevron 历史入口；正文沿原左边缘向下展开 |
| `exploring` | read-only action group | presentation adapter 先把 `actions` 展平为普通 Tool 行；单动作旁路批次，多动作与相邻 `tool/skill/hook` 共同进入 Activity Batch |
| `tool` | 单个工具或决策轨迹 | `ToolTraceLine`：自然语言短摘要留在内容宽度单行，类型化详情卡从原左边缘展开；相邻活动可进入 Activity Batch |
| `skill` | 已调用 Skill 的 invocation/content/execution-context/failure | `ToolTraceLine(kind=skill)` 或 Activity Batch 子项；catalog discovery 不进入执行叙事 |
| `hook` | host-owned Hook started/completed receipt | `ToolTraceLine(kind=terminal)` 或 Activity Batch 子项；只展示 Hook ID、event/source、duration、status、reason 和有界 preview |
| `approval` | legacy approval 历史 | 只读 `ToolTraceLine` |
| `fileChange` | 旧文件变更投影 | 当前返回 null；终态汇总时移除 |
| `memoryReceipt` | Memory recall/mutation 或 Dream terminal 的无正文回执 | `ToolTraceLine` |
| `compactBoundary` | 上下文压缩边界与恢复/诊断事实 | 保留在 reducer/narrative 供 inspector 与重放核对使用，但 `projectVisibleNarrativeItems()` 不把它渲染到中心叙事 |
| `answer` | assistant markdown，含 `isFinal` | `AssistantMessage` |
| `hint` | 取消等中性提示 | hint line |
| `providerReconnect` | live-only 供应商等待网络 / 流重试行 | `AwakenReconnectStatus`：出现在当前已提交内容之后、active 思考中之前；同一 phase 共用稳定 identity 并原位更新，不同 phase 各占一行；`recovered`、run 终态或模型输出恢复后删除；不进 transcript 补造 |
| `deliverables` | 终态 ready deliverables | `DeliverableList` |

`plan_updated` 不是 narrative item。它只进入 reducer 的 thread 任务进度状态，由 ComposerDock 上方的唯一计划入口展示；暂停、terminal 和 replay 都不得在执行过程中生成副本。

Skill invocation/content/execution-context event 同时进入 reducer 的 Skill 状态，并按 `run + skillId` fold 为一个可重放的 `skill` narrative item；discovery 只属于 catalog，不进入执行叙事，failure 以 error row 保留诊断。Hook started/completed 按 `run + invocationId` fold 为一个 `hook` item，started 为 active，success 为 done，所有 `block_*` 为 blocked，失败/恢复分别为 error/interrupted；带 `subagent_task_id` 的 Hook 只进入该 child narrative。`BeforeFinish` 阻断时上一候选回答可以是 done，但在唯一 run terminal 前不得标记为 final；下一 turn 以“正在根据 Hook 反馈完善回答”承接，第三次阻断的 `hook_reentry_limit` receipt 可见且回答随后正常 final。详情禁止显示完整 command、绝对配置路径、输入正文、secret env 或完整 stdout/stderr。这里的 `skill`/`hook` 只是 Renderer 投影类型，不是新的 ToolRuntime tool kind。tool item 同时保留 environment/tool snapshot ID、provider、capabilities、readiness、dependencies 和 side-effect state；中心显示短摘要与基于既有数据生成的类型化详情卡，完整 provider/依赖诊断仍等待 Inspector 接线。

每次真实工具执行在中心叙事中只由 canonical `TOOL_CALL_START` / `TOOL_CALL_RESULT` 形成一个 tool item。`AWAKEN_TOOL_RECOVERY_REQUIRED` 与 `AWAKEN_TOOL_RETRY_BLOCKED` 描述结果之后的监督决策，继续由 reducer 保存为 recovery / Inspector 事实，但不得再投影为第二个 tool item，也不得进入 Activity Batch 的工具数或异常数；否则一次失败会同时被算作“工具失败”和“恢复工具失败”。live 与 replay 均遵守这一身份规则。

### Activity Batch 展示投影

`projectNarrativeActivitySegments()` 只在 Renderer presentation 层处理连续 `exploring/tool/skill/hook`。批次 ID 是 `turnId + firstItemId`；有效动作总数为一时直接返回单项，两个及以上才返回 `NarrativeActivityBatch`。任何非活动 narrative item 都是硬边界，因此 reasoning、可见说明、gate、Subagent、媒体、Artifact、Final、供应商重连行和下一 Prompt 不会被吞入工具批次。`exploring.actions` 在此层展平，保持 action 自身稳定 ID 和事件顺序。

live 与 replay 共用同一投影。Renderer 从 transcript 恢复 thread 时，必须把有序 replay action 在一次 reducer transition 中原子折叠为完整 view；首个可见帧已经包含当时全部 prompt、thinking、工具、回答和终态，不得把耐久事件逐条 dispatch 成可观察的历史流式播放。同一模型轮的耐久 `assistant_message` 可能比 `reasoning_summary` 先追加，Renderer 必须用共享 `turnId` 只把该思考快照放回对应回答前，不得按 run 把所有思考堆到第一个回答前。replay 恢复出的 narrative item 保留稳定 identity，并关闭 Thought 标题/正文及 Tool 的挂载入场动画；恢复后才收到的 live item 仍按实时语义入场。active Thought 的持续思考状态不属于挂载入场，不因 replay 标记被暂停。active 批次在没有用户选择时自动展开；保持挂载并正常进入终态时自动收起，但在当前 Electron 生命周期内切换 surface 或 thread 导致临时卸载时，切回后必须恢复离开前的自动可见状态，不能把已经可见的工具行变成只剩摘要的折叠组。普通历史与完整重启后的 replay 仍默认收起。受控 `open/onOpenChange` 通过独立 disclosure store 按稳定的 thread + turn ID + segment ID + action ID 保存自动状态和用户选择，只通知对应叶组件；用户选择优先于后续自动状态。store 用当前 Electron 窗口的 `sessionStorage` 抵抗 workspace surface 导致的页面模块重建，但不进入 transcript、用户设置或磁盘历史；关闭窗口并完整重启后恢复默认。运行成功的 final answer、运行错误的 final error answer，或取消/中断的 terminal hint 出现后，由外层 `executionProcess` 统一折叠其前的执行内容；该 segment 同时携带 final answer 的耐久 `elapsedMs`，使 turn 顶部唯一的 `RunElapsedTime` 在终态原位成为 disclosure 标题。当前最新 turn 可用 reducer 起止时间兜底，旧 replay 无耐久耗时时回退标题“执行过程”。final footer 不显示耗时。Activity Batch 不改变终态分段、RunStage 滚动或 prompt anchor ownership。

每个 run 的事件回放后须以 terminal run snapshot 收敛终态，防止旧版 Core 的终态前事件快照把已完成任务重放为运行中；实时事件不得跨所选 thread/run 更新其他 view。流不存在或读取失败不能推断为“用户取消”。Core 原子快照由 [SemanticJournal 与重放](../../03_运行时与本地服务/数据存储与重放/实现方案.md) 拥有。

历史改写后的 transcript 已由 Core 过滤为 active lineage；`actionsForThreadTranscript()` 必须继续以单次 `run/replayBatch` 原子替换旧 view，不能在 Renderer 按 `removed_run_ids` 手工 splice。每个 prompt narrative item 保存所属 canonical `runId` 供消息操作绑定，`thread_rewound` 本身不生成 narrative item。详细规则见[用户消息撤销与编辑设计契约](../消息输入与编辑/实现方案.md)。

### 长任务完整历史与有界渲染

长任务的 durable transcript、reducer narrative、顺序、稳定 identity 和详情正文必须保持完整；不得用“最近 N 条”、摘要替换、隐式截断或“加载更多”规避 Renderer 压力。完整历史可查看不等于折叠正文必须同时进入 DOM：终态 execution process 关闭时不挂载过程子树；已完成 Thought、Activity Batch 和 Tool 关闭时分别不挂载正文、子行和详情卡，打开后必须显示与 reducer 数据一致的完整内容，关闭动画结束后才卸载。离开视口的已折叠 trace 可以使用 `content-visibility: auto` 跳过布局和绘制，但滚动回来、文本选择、键盘打开和复制详情时不得缺失内容。

execution-process、batch 与 tool 的开关不得进入 `App.tsx` 普通 React state 并让整个 Workbench 重渲染；独立 store 只更新订阅该稳定 ID 的 disclosure 叶组件，同时在当前 Electron 窗口的 session 内保留选择。该 session 状态只是瞬时 UI 偏好，不能改变 durable/reducer 数据，也不能跨完整重启恢复。Tool 详情展示投影可以按稳定 item/result/patch 输入缓存，但缓存不能修改脱敏、bounded output、状态或 replay 语义。Inspector、Composer、设置入口和其它 shell 状态变化不得重新生成未变化的历史 Markdown、Thought 正文或 Tool 详情 DOM。

批次摘要只统计现有内容：命令、读取/搜索、文件编辑、Skill、混合工具与异常数；进行中/已完成由标题时态表达，只有异常数作为独立 detail。Tool 主行对文件路径只取 basename，Shell 优先使用完整参数已有的任务描述，结果正文不回流主行。`Glob/Grep/WebSearch` 使用搜索图标；`Glob` 的 `**/*.pdf` 等递归模式在主行翻译为“PDF 文件”等用户语义，Grep 的文件范围同样翻译，不展示 `*`、`**`、`{}` 等工具语法。原始 pattern 只在类型化详情中保留。Tool 详情只展示类型允许的数据；敏感键递归替换为 `••••`，Shell 文本中的敏感环境赋值同步脱敏，未知工具 args 不进入详情。文件 diff 仅按既有 `toolCallId` 与 `patchPreviews` 关联，不新建协议字段。

## Prompt 与 turn

`run/requested` 立即创建 prompt 和 planning，使用户不必等网络返回才看到输入。prompt id 是 turn identity；附件和 `PromptNarrativeToken.leadingText` 必须一起保存。`leadingText` 的 durable owner 是 `ComposerToken` 本体：live `run/requested` 用提交时的 draft tokens 投影，`run/recovered` 与 v2 durable replay 都从 run 的 `inputAttachments` / `composerTokens`（含 `leadingText`）投影同一组结构化输入，canonical 回流不得把正文中间的 token 降级到句首。旧 count-only 记录没有足够事实可恢复，不得用 prompt 文字或磁盘扫描猜造附件对象。

`run/requested.startedAtMs` 同一提交首帧提供 live 计时起点；`RUN_STARTED.timestamp` 到达后 reducer 重基 `runStartedAtMs`，成功终态把同一时间边界计算出的 `elapsedMs` 附着到 final answer 供 replay 使用。`RunElapsedTime` 只在自己的 React 子树内按秒读取当前时间，优先使用 final answer 的耐久 `elapsedMs`，其次使用当前 view 的 started/completed 时间戳；它不创建 narrative item、不写 transcript、不让整个 `App` 以 1 Hz 重渲染。没有耐久耗时的历史 turn 不补造计时。

`AWAKEN_PROVIDER_RECONNECT` 在当前执行游标写入 live `providerReconnect` narrative item：已经 commit 的思考、工具或回答保持原位，重连行接在它们后面，active planning/thinking 仍在列表尾部显示思考中。initial planning 即使已被 `RUN_STARTED` 暂时结算，等待事件也必须把该尾部 planning 重新激活并移回 active owner，使真实事件顺序下仍保持“重连行 → 思考中”，不能只在手工排列的 presentation 输入中成立。同一 phase（`waiting_for_network` 或 `reconnecting`）共用 `provider-reconnect:<scope>:<phase>`，后续退避或 n/5 只原位更新 `attempt`/`detail`，不会每跳再堆一行；首次出现的不同 phase 按到达顺序各占一行。`resetInProgress` 时 projector 丢弃 active thinking/answer、尚未执行的 active tool/exploring，以及同一次未完成 stream 中因 thinking→answer 切换而暂时进入 committed 列表的尾部 model output，再恢复 planning，使思考中保留、未耐久正文和未执行工具行不留下半截。`recovered`、run 终态，以及随后真正恢复的 reasoning/text/tool 输出，都删除这些 item。reducer 仍按 phase 保存 `providerReconnectAttempts` 供会话核对，但 `useNarrativeRenderer.tsx` 只渲染投影结果，不在计时行下另开固定槽。durable transcript 不补造重连行；同一 Desktop 会话内切走再切回、且 run 仍为 running/cancelling 时，`run/replayBatch` 从离开前的 thread view 恢复这些 live 行；若 replay 中较重连事件更新的 reasoning/text/tool 时间戳已经证明 provider 恢复，则不得把旧行重新加入。完整重启后要等下一次 live 重连事件。

`App.tsx` 合并 committed + active 后调用 `projectVisibleNarrativeItems()`：compact boundary 始终不进入可见列表，只有 run 忙碌且仍处于列表尾部的 planning 会进入可见列表。initial planning 覆盖提交到首个真实输出；live `AWAKEN_TURN_STARTED` 的 `tool_result_continuation`、`max_output_continuation`、`xml_fallback_continuation` 分别创建“正在分析工具结果”“正在继续生成”“正在继续处理工具结果”的 continuation planning。`AWAKEN_COMPACT_STARTED` 创建“上下文压缩中” planning；compact finished 继续保存 typed boundary 事实但不结束该 planning，随后的 `reactive_compact_retry` 复用同一 `planning:<run>:context-compaction` identity，避免一次或多次压缩产生开始、完成和重试三组 UI。该状态延迟 650ms 出现，一旦 reasoning、tool、answer 或其他 narrative item 排在其后即过滤。随后 `groupNarrativeByTurns()` 按 prompt 分组。该规则只改变 presentation，不新增 wire event、不把 planning 占位写入 durable transcript，也不伪造 reasoning 文本；重放会原子折叠耐久 compact/terminal 事实，非 busy 终态不会恢复瞬时等待状态。第一个 prompt 前的恢复/系统 item 是 lead item，不伪造 turn。

## Streaming item 生命周期

- 新 active item 到来时，旧 active item按适用状态 commit；
- trailing planning 与真实 thinking 复用同一 `AwakenThoughtTrace` 外观；initial planning 不展示自身 `Planning next moves` 文本，continuation planning 只展示确定性阶段 label，真实 reasoning 到达后才出现正文；
- text/reasoning delta 累积到稳定 message/run identity；同 message 的 durable `assistant_message` / `reasoning_summary` 是完整快照，回流时替换已经流式累积的正文，不能再次拼接造成重复；
- message end 或 terminal event把 active answer commit；
- `RUN_FINISHED` 把最新属于该 run 的 done answer 标为 `isFinal=true`；
- transport interruption 不调用 terminal error projector；
- cancellation 先 settle active item，再幂等追加 `hint:run-cancelled:<scope>`；尚未收到 canonical result 的 active tool/action 投影为 `cancelled`，不能伪装成 `done`；
- cancellation 遇到 active media generation时先把原卡片置为 `cancelled`，不得保留无限旋转的 loading态；
- late cancellation 不删除已经 commit 的 answer。

隐藏 chain-of-thought 不由 Workbench自行生成；只显示 runtime 经统一 LLM observer 明确发出的可展示 reasoning。Workbench 不认识 provider、model、`reasoning_content` 或 `thinking_delta`，也不得从 `provider_opaque_state` 补造历史。

## Tool 投影与 pairing

`TOOL_CALL_ARGS_DELTA` 是 live transport 的 partial-JSON 帧，完整参数由 Core/LLM adapter 累积。原始 `delta` 不进入 narrative、step、tool record、详情或 replay；唯一例外是 Core 对名称精确匹配内置 `Write`/`Edit` 时附加的安全准备快照：操作 kind、basename 和当前增删行估算。narrative projector 以同一个 `toolCallId` 提前激活一条 Tool 主行，并只更新该行标题旁的 `+N` / `−N`；后续 `TOOL_CALL_START`、完整 `TOOL_CALL_ARGS`、progress 与 result 沿用该 identity，不得再插入第二行。其他工具、kind/name 不匹配或缺少安全字段的 delta 保持 no-op。准备行是 live-only，切换或重启 replay 不补造生成过程；replay 仍由 START、完整 ARGS、END、patch 与 RESULT 恢复稳定摘要和终态。`TOOL_CALL_END` 只结束参数 envelope，工具终态只由 canonical `TOOL_CALL_RESULT` 决定；存在 patch 时同行最终增删数以 patch 统计替换准备态估算。

`TOOL_PROGRESS`、command output 和 patch 是既有 tool-call 的即时旁路更新，不拥有新工具身份。它们只有在当前 root 或指定 `subagentTaskId` 的 child narrative 已收到匹配 `TOOL_CALL_START/ARGS` 后才能更新；缺少匹配起始帧的孤立更新必须 no-op，不能据此在 root narrative、tool results 或 steps 新建工具。Core 必须在旁路帧进入 SSE 前补齐与相邻耐久 tool records 相同的 child identity。

### Read-only exploration

projector 把当前识别为 read-only 的 tool call 投影为 exploring action。action id 由 scoped tool call id 稳定生成，并另外保留 raw tool-call identity 关联 reducer 数据；完整 args、progress 和 result 更新同一 action，不制造重复行。partial args delta 不创建或更新 action。

中心只显示 title、status 和短 detail。`useNarrativeRenderer.tsx` 经 `toolTracePresentation.ts` 从 `runtimeState.toolResults` 选取 command output/result 第一条非空行补 detail；完整数据仍留在 reducer，当前右侧 UI 未接线。`Read` 图片/PDF 的 Base64 不进入 AG-UI/Renderer；Desktop 历史卡片依赖持久化的 tool text/metadata，blob 缺失也不得导致卡片崩溃。

### 普通工具

非 read-only tool 使用 `tool` item。`toolStatus` 是 Outcome 的 canonical 状态，UI display state 不得靠 content 文本猜测。deny、transform、needs-auth、needs-runtime、unsupported、recovery-required 等状态按 04 域语义投影。

### 图片与视频生成

`image_generate` / `video_generate` 使用稳定的 `mediaGeneration` item，而不是普通 `tool` item。`TOOL_CALL_START` 建立一次 tool-call identity；完整 `TOOL_CALL_ARGS` 可把合法的 `mode=group,max_images=1..15` 派生为 2–15 张独立小卡，并从图片 `size` 或视频 `ratio` 解析占位宽高比。该数量只是请求上限，不是实际产物数。`AWAKEN_COMMAND_OUTPUT(commandStream=media_status)` 传递 `queued|generating|downloading|ready|partial|unknown`、短消息和可选 task ID/逐项状态；官方没有进度百分比时 UI 不伪造百分比。`TOOL_CALL_RESULT` 结合 canonical tool/transport status 与结构化 `generation_status/group_id/paths/items[]` 收口：全部完成为 ready，组图部分完成保留每个 index 的 ready/error 卡；补做失败项时调用必须携带原 `retry_group_id` 与缺失的 `retry_indices`，新 Artifact 复用原组 identity 与位置。视频轮询未得终态为 unknown“状态待确认”，不能显示成生成失败或继续无限转圈。为了忠实恢复已写入的旧记录，仅当旧结果同时包含可解析的 `status=succeeded` 与非空 `paths` 时，允许纠正旧 output schema 造成的错误 display status；该兼容不用于任意普通工具文本猜测。

媒体卡在 final answer 前实时显示。final 出现后，ready/partial/unknown/error/cancelled 等全部 `mediaGeneration` item 与媒体前后的 planning/thinking/普通工具/非最终 answer 一起进入同一个 execution-process disclosure；媒体不能成为分段边界，也不能因成功、失败或敏感内容拦截而留在最终结果区。媒体 item 自身在 generating 时自动展开；外层过程展开后，组图仍以一个 narrative item 和无卡片表面的布局容器排列 2–15 张独立 `AwakenMediaItemCard`。子项稳定位置由 tool call 与 `items[].index` 派生，真正的预览、打开、定位及后续模型引用继续使用各自 Artifact identity 与 opaque media source。ready path 只用于与 Artifact event 配对；Renderer 不得从 tool result 路径拼 `file://`，也不得把视觉序号自行翻译成路径。历史记录不迁移，重放时按同一确定性分段规则恢复媒体执行明细，ready Artifact 的默认可见入口由终态交付列表承担。

### 通用 approval

新 run 不生成可交互 ApprovalCard。历史 `approval` item仍可从旧 transcript 重放，但只能显示标题、`Legacy approval record` 和只读状态。

`ask_user` 使用专用 reducer/UI，不属于 legacy approval item。消息发送没有专用 reducer、审核卡片或 approved/rejected 轨迹，只按普通 tool call/result 投影。

### Memory 与 Dream 回执

`memory_recalled` / `memory_mutated` 由 03 域 SemanticJournal 耐久，09 域投影为 `AWAKEN_MEMORY_*` wire event；projector 按 `recordId` 稳定 upsert `memoryReceipt`，只展示数量、scope/type/revision、action 状态或错误码，不展示主题正文。

只有 create/update/supersede/delete 的 typed mutation receipt 可以占有 mutation 展示；projector 收到该 receipt 时按同一 `toolCallId` 移除通用 Memory tool row，避免一个动作出现两条状态。search/get 的工具失败继续按读取失败展示，不生成“未写入” mutation receipt；后台 automatic recall 使用自己的 record identity，不被主动工具行替换。

Dream task 不写入 thread SemanticJournal，也不伪装成 Core AG-UI/SSE wire event。Main 通过 typed bridge 推送 terminal task；Renderer 在 active thread 中实时收到回执时保存纯展示用的 `taskId -> threadId` 绑定，thread 加载时从 durable Dream task list 只挑选绑定到当前 thread 的终态，无绑定的旧任务不进入任意新线程。`App.tsx` 把 completed/failed/cancelled/interrupted 转为相同 projector 可消费的本地事件形状，projector 以 `taskId` 区分不同任务并幂等忽略同一任务的重复投递，再投影中文状态与 updated/superseded/conflicts 有界统计。展示绑定不是 task 状态 authority；该回执不创建新 turn、不进入右侧 Inspector，也不改变 prompt、follow、marker 或 composer ownership。

## Execution process

`projectNarrativeTurnBodySegments()` 是当前过程折叠的唯一纯决策：

1. 找到第一个终态边界：`answer && isFinal === true` 或 `hint && isTerminal === true`；
2. index `<=0` 时 turn body 保持一个 flat items segment；
3. index `>0` 时终态边界前缀整体成为 `executionProcess:<turnId>`，包括全部 `mediaGeneration` item；
4. 终态 answer/hint 及其后缀成为 `answer-and-after:<turnId>`；
5. per-turn open state由 `usePromptRewind.ts` 与既有 disclosure store 按稳定身份控制，默认 false。

因此过程在终态边界前实时可见，成功、错误、取消或中断后才折叠；切换 workspace surface 或重新进入 thread 时必须按同一终态边界恢复，不得把历史思考或工具平铺回 turn body。计划由 ComposerDock 独立恢复，不参与本分段。禁止在 projector 中提前删除过程 item，或用 CSS 隐藏来代替可访问 disclosure。

## Artifact 与 deliverables

artifact event 先进入 reducer 的 `artifacts`；run终态时 reducer把交付物汇总作为 turn 尾部 narrative item投影，live与replay走同一分支。具体资格、去重、排序、稳定 identity、terminal状态和安全打开只由 [最终交付物展示与安全打开](../交付物展示/实现方案.md) 拥有，本文不重复算法。

## Replay 幂等

优先使用 `semanticSeq ?? seq`。一个 semantic record 可能投影 START/CONTENT/END 多帧并共享 seq，因此 seen key 包含：

```text
scope + stableSeq + event.type + frame identity
```

frame identity优先 message/tool/approval/artifact/compact id。不能只按 seq 去重，否则会丢同一 semantic record 的合法多帧。

没有 seq 的 text、reasoning 和 tool progress 不生成粗粒度 seen key，避免误丢合法增量；tool args delta 不参与可见投影；其余无 seq event 使用 type/scope/id/content 组合。

`seenEventKeys` 只保留最近有界窗口（当前 projector 的 `MAX_SEEN_EVENTS`），不是持久化 journal 的替代品。

## Thread view 与恢复

- 每个 thread 可在 reducer 的 `threadViews` 保存一份 runtime/narrative snapshot；
- 切线程前 scroll controller 清除旧 turn identity；
- `actionsForThreadTranscript()` 将 durable transcript 重放为 reducer action；
- 快速切线程由 load sequence 防止旧异步请求覆盖新选择；
- live reconnect 使用最后游标继续订阅，overlap 依赖 projector 幂等；
- 同一会话切回仍在跑的 run 时，`run/replayBatch` 先按 transcript 重建耐久叙事，再合并离开前仍有效的 live `providerReconnect` 行；replay 中时间戳/stream cursor 更新的模型或工具事件会淘汰旧行，这些 live 行不进入 `replayedItemIds`；
- terminal replay 恢复 done reasoning、final answer 或 terminal hint 以及 deliverables，并按相同 execution-process 边界分段；plan 事实由 reducer 单独恢复到 ComposerDock；
- pending 专用 gate按各自 event pair恢复；legacy approval只读；
- 非终态 stream close进入 reconnecting，不提交普通 failed answer。

当前限制：

- WorkBench 不持久化精确 scrollTop、prompt expanded 或 execution-process open state；重开只保证已耐久叙事的身份与内容，不保证像素级阅读位置。
- 完整重启后无法从 transcript 恢复供应商重连行；要等 Core 下一次 live `AWAKEN_PROVIDER_RECONNECT`。会话内切走期间若已 `recovered` 且该帧未再送达，replay 中较新的模型/工具事件或下一次 live 模型输出会清掉过期行。
- 修复前没有 `reasoning_summary` 的旧 run 只能恢复当时实际耐久的 prompt、工具与回答，不能从 provider 私有 opaque state 反向生成过程历史。
- 修复前的旧 v2 count-only 记录不含附件 identity/path 和 composer token，因此只能重放其可确认的文本；耐久来源只由 [03 SemanticJournal 与重放](../../03_运行时与本地服务/数据存储与重放/实现方案.md) 定义。

## Inspector 数据与当前 UI 缺口

reducer 当前已保存：

- tool args/result/status；
- bounded command output + truncated flag；
- 通用 diff/patch preview相关字段；
- turn diff；
- artifacts；
- `inspectorSummary.lastToolDecision`；
- environment/tool snapshot ID、provider ID、capabilities、readiness、dependency observations 和 side-effect state；
- Skill invocation/resource/status/diagnostics；
- narrative `inspectorSelection`。

这些通用 tool/artifact 数据仍未接线，不等于右侧支持通用工具详情。原生 Subagent 是独立的已接线类型：`AWAKEN_SUBAGENT_*` 按 task ID upsert 到当前 turn 的 `subagentGroup`；带 `subagentTaskId` 的普通 reasoning/text/tool frame 进入 reducer-owned `SubagentTaskView.narrative`，不得修改 root 的 thinking/answer/tool records。点击 group row 后，中间区域从该独立 narrative 在 dock Composer 上方的 `RunStage.overlay` 渲染有界执行详情，详情不回流当前 turn；右侧 Inspector 也只消费同一 task truth。见 [原生 Subagent 产品与架构契约](../../02_主智能体闭环/子智能体协作/实现方案.md)。

## 异常语义

| 事件/场景 | Narrative 处理 |
|---|---|
| `PROVIDER_AUTH_MISSING` | 清洗为模型 API key 提示 |
| `PROVIDER_REQUEST_FAILED` | 显示 provider 请求失败，不泄露 secret |
| 用户取消 | 保留内容、settle active、追加幂等 hint |
| stream interruption | recovery 状态，不生成 error answer |
| SSE `run_not_found` | terminal error answer + ready deliverables |
| `AWAKEN_PROVIDER_RECONNECT` | 不生成 item；reset 时丢掉 active thinking/answer 并恢复 planning |
| tool failure | 同一 tool/action进入 error/blocked等 display state |
| duplicate replay | seen key / stable id upsert，不重复 |

## 完成原则

Workbench改动只有同时满足以下条件才能宣称完成：

1. 相关权威文档已同步；
2. 纯决策/reducer/projector/Design System测试按 owner通过；
3. Desktop typecheck和 UI smoke按改动范围通过；
4. 真实 Awaken Desktop中执行适用 AC；
5. scroll、sticky、follow、composer测量等动态行为有录屏或连续关键帧；
6. 视觉变更有当前 HEAD的截图和 manifest；
7. 发现契约与真实行为不一致时记录产品/代码差异，不用改文档掩盖。

Tool 参数流验收必须覆盖慢速长参数：内置 `Write`/`Edit` 的 `TOOL_CALL_ARGS_DELTA` 到达后，只出现一条与后续 START/ARGS/result 共用 identity 的 active Tool 主行；同行 basename 和 `+N` / `−N` 随安全行数快照原位更新，不出现绝对路径、JSON/token fragment、代码正文、第二条 Tool 行或可展开“工具输出”。非 `Write`/`Edit` delta 保持不可见。完整调用出现后只展示稳定安全摘要，存在 patch 时以真实 diff 统计替换准备态估算，执行终态只由真实 result 收口。live、切线程和完整重启 replay 的最终 Tool identity、摘要与终态必须一致；live-only 准备动画不得在 replay 中伪造。

浏览器直接打开 renderer、Design Gallery、server render、静态 DOM和旧截图都不能代替真实 Desktop动态验收。

### 结构化输入兼容检查要求

Hook command 旅程还必须在 AC-014/015 的真实 Desktop 样本中覆盖 started→completed 原位收口、block/error/interrupted 状态，以及切 thread/重启后的恰好一次重放。Hook 行和展开详情只能显示 Hook ID、event/source、duration、status、reason 与有界 preview；完整 command、绝对配置路径、输入正文、secret env 和完整 stdout/stderr 任一出现即失败。Hook 行加入 Activity Batch 后不得改变 prompt anchor、滚动 follow、Composer 或外层 execution-process disclosure ownership。

AC-014 的开合连续性还必须覆盖 Thought、Activity Batch 和单 Tool 详情的展开后关闭：下方叙事只能随同一高度过渡连续归位，过渡结束不得因 DOM 卸载或 `content-visibility` 估算再发生第二次位移；`prefers-reduced-motion` 下直接进入折叠终态。连续关键帧必须同时证明目标 disclosure 完全折叠前仍处于 closing 而不是 closed 优化态。

AC-015/019 必须使用当前代码新写入的完整 v2 `user_message` 记录，并在同一 thread 完整关闭、重开 Desktop 后比较文本、附件 identity/顺序/小卡和 composer token。修复前的旧 v2 count-only 记录没有这些结构化事实，无法补回，也不得从 prompt 文字或附件目录猜造小卡。

包含 Skill token 的 AC-015/019 样本还必须证明 `user_message` 早于 `skill_activated`；故意使预激活失败时，重开后仍能看到原文、附件/token，且不存在部分或伪 activation。成功路径每个用户 turn 只能重放一条 `user_message`。

若新记录重启后丢失附件或 token，AC-015/019 必须判定失败，不得用文本恢复或旧记录的兼容边界掩盖。只有代码、自动化和真实 Desktop 同时通过时，才能更新 Workbench 基线或删除旧验收证据。

### 任务切换与启动反馈

- 两个隔离任务交替运行/查看，分别核对当前选中 task、Core thread/run 与日志终态；后台完成后侧栏指示自动消失，切回后显示最新结果，不刷新 Renderer。
- 覆盖快速 A→B→A、订阅尚未建立时切换、完成边界回放、断流恢复与重选；晚到响应不得改写当前任务或清除其恢复标记。自动化包括 `thread-session.test.ts`、`client.test.ts`、`thread-transcript.test.ts` 和 reducer 对账测试。
- 正式入口启动时确认中文小字位于品牌上方、就绪后淡出、没有旧英文大卡片；ready 前发送不可用。已有任务及完成任务输入文案不误报运行中。

## 动态行为判定

### Anchor / sticky

- 从提交动作后的第一可见帧开始逐帧判定；新 prompt header 第一次可见时已在 RunStage 顶部锚点。
- 任何一帧先在旧 final answer 或 deliverables 下方显示新 prompt，再于后续帧跳转到顶部，均判定 anchor 失败；即使最终静态位置正确也不通过。
- AC-002、AC-004 和 AC-005 的录屏/连续关键帧必须从提交前最后一帧无剪切地覆盖到新 prompt 的首个可见帧；不得只保留 settle 后的稳定位置。完成声明还必须同时附上 [自动化检查要求](实现方案.md#自动化检查要求) 所列 controller DOM 时序测试结果。
- 以 prompt header在 RunStage顶部锚点的位置判断，不以页面截图裁切猜测。
- 旧 turn滚出锚点后 active marker必须同步。
- 多行prompt高度变化后旧header不得覆盖turn body。

### Follow

- streaming期间先确认自动跟随；
- 再明确向上滚并等待内容增长；
- paused视图不能跳；
- passive layout变化不能让按钮消失；
- 恢复后必须到同一 native bottom，不出现额外空白底部目标。

### Composer测量

分别触发 textarea 多行、runtime panel、ask_user 和 CLI 授权 gate 状态，观察 output、marker、return 随真实 ComposerBar/stack 变化。不得只用 CSS 检查替代。

上下文面板属于 overlay，不属于上述 composer stack 测量对象。打开/关闭面板时必须重复 AC-007～AC-010，并在 AC-021 的窄窗口中确认面板内部滚动、外层 pointer-through、native tail 和 composer inset 不变。

```bash
npm run capture:workbench -- --state dock --no-open
npm run capture:workbench -- --state marker --no-open
npm run capture:workbench:vrt
```

工具只负责抓取真实窗口和写 manifest，不做像素差异判定，也不会证明状态准备正确。每张图必须人工确认对应状态。

### 截图 manifest 必填

- 当前 commit；
- capturedAt；
-平台和实际窗口坐标/尺寸；
- theme preference与生效主题；
- 状态准备步骤；
- screenshot SHA-256；
- capture mode/settle时间；
-人工 reviewer与结论。

### 视觉核对方式

仓库当前不维护固定截图基线。每次视觉验收都按本文步骤准备当前版本的 center、dock、marker 三态，再在真实 Desktop 中核对；历史截图不能替代当前验证。如果任一状态违反契约，记录差异并修复后复验，不能仅以截图成功作为通过依据。

## 证据保全

正式知识库保留验收方法。单次验收的截图、回读、manifest 和过程录屏放在 PR/任务附件或临时验收目录，交付确认后可清理，不在仓库建立永久历史档案。交付报告必须列出实际命令、HEAD、证据位置和未通过项。

## 停止条件

出现以下任一情况不得将本次视觉验收判为通过，应记录问题并修复后复验：

- 中间区域整体滚动失效；
- latest prompt无法锚定或旧header遮挡；
- return层挡住scroll/wheel；
- output被composer覆盖；
- replay产生重复/丢失；
- 需要点击会修改真实 userData 的操作才能继续只读验收；
- 真实Desktop行为与权威文档冲突。

## 自动化与真实 Desktop

复核时列出受影响的功能、代码位置和适用 AC，并附自动化结果。真实 Desktop 证据应标明提交、窗口和主题；动态行为提供录屏或连续关键帧。旧基线、Gallery 和浏览器中的 Renderer 不能替代真实 Desktop。

不涉及工作台时，说明判断依据；涉及容器、滚动、输入、叙事或文件工作区时，执行对应验收项。

## 当前 narrative 表达的实现

助手 Markdown 正文使用文章式阅读排版：正文与标题保持明确字号层级和留白；行内代码使用中性灰蓝文字与轻量底色，不用红色强调；普通 fenced code block 使用浅灰 code surface、细边框、顶部小型语言标签，并只按模型显式声明的语言做 token 语法着色，不自动猜测；关键字、函数、字符串、注释和变量使用紫、蓝、绿、灰和青色系区分，未知语言保留原代码和标签。GFM 表格使用横向分隔线、透明表头和加粗首列，不再套圆角卡片或填充表头；窄宽度仍由表格容器横向滚动。`AwakenMarkdownRenderer` 在进入 `remark-gfm` 前，只对表头下一行分隔符的列数与表头不一致做显示纠偏（补齐或截到与表头相同的列数）；这只影响阅读 DOM，不改 journal、复制按钮或模型原文。右侧文件预览仍走独立 `remark-gfm` 管线，不使用该纠偏。Mermaid 继续只在 fence 闭合后进入图表渲染，未闭合或失败时保留统一代码表面。上述正文在浅色、深色、流式增长、历史 replay 和局部文本选择中保持同一结构，模型 raw HTML 仍不渲染。

- MCP、Skill 与终端工具轨迹优先保持来源身份：MCP 在 active/done/error 等状态始终显示与其它单行工具同为 14px 请求尺寸的官方 MCP 标记，Skill 始终显示打开的书，终端始终显示终端图形；活动与异常继续由文字扫光和语义颜色表达，不用状态图标覆盖来源图标。Core 的 `providerSource=mcp|connector`、`providerId=mcp:|connector:` 或保留的 `mcp__{server}__{tool}` 工具 identity 任一能确认 MCP 来源时，包括用户自定义 server 的准备态与结果态，Renderer 都必须使用该官方标记。
- `planning` item 是实时等待可见输出的 UI 占位来源：提交时的 initial planning 仅当它仍是当前 narrative 尾项且 run 忙碌时显示无正文动态 Thinking；Core 发出带已知 continuation reason 的 `AWAKEN_TURN_STARTED` 时，projector 在已完成工具或前一段输出之后创建带确定性中文 label 的 continuation planning。`AWAKEN_COMPACT_STARTED` 创建“上下文压缩中” planning；随后 compact finished 和 `reactive_compact_retry` 继续复用同一 run-scoped identity，不产生完成行或第二条等待行。它们都在首个 reasoning、tool、answer 或 run 终态出现后立即让位；临时状态延迟 650ms 展示以避免快速请求闪烁。planning 不进入历史过程或 durable replay，也不伪造 reasoning 正文。
- `thinking` item 使用同一透明紧凑状态行；active 时以 20px 思考球和 12px `思考中` 文字显示三点动效，并从文字起点在下方流式追加 runtime 明确提供的 reasoning summary；done 后移除运行态思考球，以静态 `思考过程` 和位于文字右侧的 12px Chevron 保留回看并默认折叠，展开向下、折叠向右。标题触发区按内容宽度收紧，正文从原层级左边缘向下出现，不再额外缩进，开合时标题起点不跳。自动收尾时静态标题必须立即可见，正文高度折叠不能先透明而留下占位空白；同一条 live reasoning/answer 的耐久快照只原位校准内容，不得重新激活已完成 item 或重播其入场/收尾生命周期。用户手动展开/折叠优先于自动状态。最终回答出现后，它与其他过程项一起进入“执行过程”。
- 连续的 `exploring/tool/skill` 先由 Renderer 纯展示投影为 Activity Batch，再使用“执行过程 → 批次摘要 → Tool 单行 → 类型化详情卡”的三级渐进披露。`exploring.actions` 只展平为普通 Tool 行，不得嵌套第二层工具组；只有一个有效动作时旁路批次、直接显示 Tool 行。新 reasoning、用户可见说明、gate、Subagent、媒体、Artifact、Final 或下一 Prompt 都结束当前批次。批次 identity 必须由 turn 与首项稳定 identity 组成，不得使用数组下标；旧历史不迁移，replay 使用同一规则重建。切回已有 thread 或应用重启后的首个可见帧必须原子恢复完整 transcript，历史 Thought 和 Tool 不重播挂载入场；恢复完成后新到达的 live Thought/Tool 仍保留实时反馈。
- 批次标题由内容确定性生成，例如“运行了 N 条命令”“检查了 N 项”“编辑了 N 个文件”“正在使用/使用了 Skill · N 个工具”或“使用了 N 个工具”，不得调用模型生成。进行时/完成时已经由标题时态表达，标题旁不重复显示“执行中/已完成”；只有异常数作为补充状态保留。活动批次默认展开，用户手动收起优先；保持挂载并进入下一阶段后自动收起。当前 Desktop 生命周期内切换 surface/thread 时，离开前仍自动展开的活动批次返回后保持可见；普通历史与完整重启 replay 默认收起。批次主 Chevron 与最外层执行摘要 Chevron 常驻；单条 Tool 的 Chevron 始终保留布局宽度但默认透明，只在 hover、`focus-visible` 或已展开时显示，因此开合与滚动条变化都不得造成横向跳动。
- Tool、MCP、Skill 与终端共用单行语法，只保留图标、自然语言标题、必要短上下文与语义状态，不展示原始 `{`、重复 Skill/provider 标签或多余完成勾选。文件型 Tool 主行只显示 basename；`Glob/Grep/WebSearch` 使用搜索图标，Glob/Grep 的 `*`、`**`、`{}` 等匹配语法只留在详情，主行把常见扩展名模式翻译为“PDF 文件”“Markdown 文件”等用户语言，并最多补充根目录 basename；Shell 优先使用完整参数中已有的 `description/label/summary`。绝对路径、完整命令和结果摘要只进入单条详情卡。执行中的单例 Tool，或展开批次中的当前 Tool，使用 1.6 秒从左到右的文字扫光；批次收起时由“正在运行 N 个工具”标题扫光。完成、错误、取消和中断立即停止；图标与背景不发光，`prefers-reduced-motion` 下改为静态文字高亮。
- 点击或键盘 Enter/Space 展开 Tool 的类型化详情卡。Shell 展示命令、stdout/stderr 和截断提示；Skill 展示名称、来源、版本与结果；MCP 展示 provider/tool、脱敏参数与结果；Read/Search 展示目标与匹配摘要；文件操作按 tool call identity 展示文件列表与 diff；错误展示错误码、原因和恢复信息。流式 `TOOL_CALL_ARGS_DELTA` 的原始 fragment 只属于 transport；名称精确匹配内置 `Write`/`Edit` 时，Core 可以附加 basename 与增删行估算，前端用同一个 tool call identity 提前显示“写入/编辑 文件名  +N / −N”的单行 active Tool，并在参数继续生成时原位更新数字。该准备态不提供 Chevron、detail/output 或代码正文，Write 不把未知的旧文件行数伪装成删除数；Edit 的 old/new 计数和 Write 的新增计数均为执行前估算，执行产生 patch 后同行改用 patch 的真实增删统计。其他工具或缺少安全派生字段的 delta 不创建 Tool 行；只有完整 `TOOL_CALL_ARGS` 可以按已知工具白名单派生稳定短摘要。参数只按已知类型展示并对 `password/token/secret/apiKey/authorization/cookie` 等敏感键脱敏，未知 Tool 不默认显示原始 args。展开后直接进入正文，不重复显示“Shell 详情/工具详情”等类型标题；该标题只保留为可访问名称。卡片使用主题化灰色 code surface 和终端语义文字：命令为 accent 色，普通输出为当前主题 code 前景的 dim 混色，成功/错误继续使用对应状态色。详情卡最高 320px，正文区是唯一内部滚动 owner，显示细滚动条、支持键盘滚动与文本选择复制；右上角只显示透明背景的复制图标，图标、细滚动条和首段正文分别保留独立空间，不得相互覆盖。卡片内部 wheel/touch 滚动不得驱动 RunStage follow 状态。卡片与批次内容列对齐，不形成多层阶梯缩进。旧 `output/outputLabel` 仅作为终态历史兼容回退，不能把 live active detail 冒充“工具输出”。该展示不改变工具、MCP、Skill 的 runtime ownership 或权限语义。
- `fileChange` item 当前不直接渲染；终态会由 deliverables summary 移除旧 file-change 叙事。
- `image_generate` / `video_generate` 不投影为普通文本 tool trace；同一稳定 tool-call identity 派生相互独立的媒体卡片，消费安全的 `media_status` 进度，完成后在本轮结果区保留可展开摘要，不新建 turn。小卡只显示图片或视频首帧入口，并在媒体加载后显示真实 `宽×高 · 时长 · 格式`（图片省略时长）；单击后在 `RunStage.overlay` 打开图片缩放或带原生 controls 的视频预览，视频立即尝试播放，被平台拒绝时显示明确播放按钮。更多菜单不再把当前媒体临时固定到专用右侧栏，而是只在 ready 交付态建立或激活右侧文件工作区临时 Artifact 文件标签；菜单按 RunStage 当前可见边界自动翻转和平移，不得被 Composer 遮挡或异常展宽，也不能改变默认单击、Artifact 顺序或 RunStage ownership。视频任务只展示 provider 提供的排队/生成状态，不伪造完成百分比；轮询窗口结束但 task 未终态时停止转圈，明确显示“状态待确认”并保持展开。
- 独立媒体卡宽度为 `128–144px`，以 8px 间距自动换行；组图生成中按 `max_images` 显示 2–15 张独立卡片，占位表示本次请求上限，不承诺最终精确返回 N 张。全部成功后按实际返回的 Artifact 数量删除未返回项；部分成功时仍保留请求位置，逐项显示 ready/error，ready 项立即可预览和交付。每个 ready 项由媒体 `naturalWidth/naturalHeight` 或 `videoWidth/videoHeight` 修正真实宽高比，不裁剪、不拉伸。
- final 后的媒体交付是另一个明确的用户任务：内嵌媒体生成明细随“执行过程”折叠，每个 ready Artifact 在终态交付列表中提供独立预览。媒体单击进入 Awaken 预览；更多操作和预览工具栏提供系统默认应用打开，以及 macOS Finder / Windows 文件资源管理器定位。前者是可回看的执行证据，后者是默认可见的正式交付，不是重复发布 Artifact。
- Subagent group 的标题显示 `subagent`，有活动子任务时标题右侧显示“停止全部任务”；各行只显示名称和状态，不显示角色、结果摘要或用量统计；点击后在右侧标签页查看自身过程、计划、结果或错误，具体选择、滚动与停止规则见本文 Inspector 标签页章节。
- Memory 回执只展示数量、scope/type/revision 或错误码，不平铺主题正文；Dream 回执只展示中文终态和有界统计。
- 新 run 不展示通用可交互 `ApprovalCard`。
- 历史通用 approval 只显示 `Legacy approval record` 工具轨迹，不提供恢复按钮。

## 输入与上下文入口的实现

- Enter 提交；Shift+Enter 换行；IME composing 时 Enter 不提交；
- 结构化 Skill token 与前后 plaintext 位于同一个 editing host；token 前文、token 间正文和尾文都可重新定位与编辑，token 本身保持原子不可编辑；
- 从右侧项目文件树“添加任务”的普通文件/文件夹使用同一原子 token 编辑链；只显示条目名称，路径 identity 不进入可见正文，具体授权和 effective input 规则由 [输入、斜杠菜单与附件](../消息输入与编辑/实现方案.md) 与 [右侧栏当前支持边界](../文件浏览与评论/需求文档.md) 拥有；
- `@` palette 提供 Computer Use capability；选择后输入面与 prompt bubble 只显示带显示器图标的原子 token，隐藏模型引导只由 Core 在提交时按固定 capability identity 注入 effective input；`/` palette 不再提供 Computer Use；
- busy 时主按钮停止当前 run；
- center/dock 复用同一 ComposerBar；
- center 首页在 ComposerBar 输入面下方显示与输入面外缘对齐的项目作用域低栏；字标、说明文案与输入面保持清晰但克制的纵向分隔。空 `projectId` 恢复显示为无图标的“选择项目”，代表电脑全局对话范围，不把“对话”伪装成项目或文件夹；其后列出侧栏同一 active 项目集合并使用文件夹图标。选中项目后，hover 整段控件或键盘聚焦清除按钮时，前置文件夹图标原位变成圆形 `X`；点击 `X` 直接清空项目目标、关闭菜单并回到“选择项目”，点击其余区域仍打开项目菜单。选择与取消项目都和侧栏双向同步，不借用默认 workspace；「创建项目」复用侧栏同一弹窗并支持可选的多文件夹组。dock 不显示该低栏；
- 多选本地附件、粘贴 PNG/JPEG/WebP；
- Slash Palette 由统一 Skill catalog 供数，展示所有 `loaded && userInvocable != false` 的来源；
- `/` 与 `@` 以当前 collapsed 逻辑光标为 trigger 结尾，可插入已有句子或 token segment 中；菜单跟随 trigger caret，选择后仅以原子 token 替换 trigger，前后正文保持原位；
- 未提交正文、token、附件与逻辑 selection 按 thread 在当前 Desktop 进程内隔离；切换到运行中或历史会话不得显示其他会话的草稿，返回原会话恢复自己的草稿；
- 模型选择是会话级 preference，不修改设置页 default；支持 effort 的模型按[输入、斜杠菜单与附件](../消息输入与编辑/实现方案.md)进入二级面板并选择真实档位；档位吸附时立即保存并把标签显示为 `模型名 · effort`，无档位模型不显示入口；有历史时提示缓存重建，busy 时禁用修改；
- workspace 展示和“上下文窗口”汇总入口；常驻入口为圆环占比指示，不常驻显示 label 或数值；仅指针 hover 展示「N% 当前使用」与「当前总输入 / 可用输入窗口」两行，不追加“可用输入”文字；打开完整面板期间以及关闭后面板焦点回到入口时不展示该 tip，指针离开入口后再 hover 才重新出现；同 identity 的最近完整主调用直接使用 provider inclusive input，不加入 output 或当前本地差量，无法使用实报 input 时回退当前本地估算；
- 点击或使用 Enter/Space 打开中文上下文面板（完整分类面板保留）；首行标题“上下文用量”与关闭按钮同行；其下左侧为「N% 当前使用」、右侧为「当前总输入 / 可用输入窗口 上下文用量」，再下为分类进度条；Core 分类只有系统提示词、内置工具、MCP、技能、记忆、任务检查点、对话七项，当前总输入相对七项本地和存在正残差时追加“其他/协议开销”；存在缓存或成本信号时，缓存状态、缓存率与成本紧接分类，输入/命中/未命中/输出 Token 置于默认折叠的“Token 明细”（计算与缺失值规则见[上下文与用量](../../02_主智能体闭环/上下文与用量/实现方案.md)），不添加“上次请求”标题或分隔线；面板不展示最近一次压缩、压缩状态/目标/预算、mandatory floor、供应商原生压缩、失败原因、缓存失效原因、encrypted opaque item、请求 body 或内部 boundary ID；有兼容完整 input usage 时，汇总与输入 Token 严格相等；无 `~`、“预计”、中文“约”、“本地估算”、模型窗口/输出预留/自动压缩阈值文案，不展示模型调用账本；
- compact started 后面板保持压缩前最后一份完整分类、汇总和缓存/成本明细，不消费 compact 过程估算或 summary 请求 usage；失败或取消继续保留旧值，不能退化为“暂无分类明细”。只有成功边界提交后生成的完整 `ContextUsageSnapshot` 才一次替换整份面板数据，不逐项跳变；
- 六项来源由 Core 的 v4 typed snapshot 决定：内置工具只含源码稳定工具和内置 Skill 工具包装；MCP 是用户经连接器/MCP 配置接入、服务器返回并实际下发模型的工具定义，connector provider identity 不改变其 MCP 分类；技能只是统一 Skill catalog 的模型可见 name/description/when-to-use；MCP result 与激活后的完整 Skill 正文进入对话；
- 切换 thread、完整重启或回放多个 run 时，Desktop 先用当前可运行 profile 让 Core 从耐久历史和当前 MCP/Skill/Memory 重建并 flush v4 snapshot，再读取 transcript；相同 projection 不重复写。没有可运行 profile 时保留该 thread 最后一个合法 snapshot，v1/v2 不补造分项；后续 run 因失败、取消或未进入模型而没有新快照时，不能把已恢复的窗口清空；
- Escape、关闭按钮和点击外部关闭面板并把焦点返回入口；亮暗主题与窄窗口均保持可读，窄窗口由面板内部滚动；
- token-only 提交。

### 文本选择与全选

- Awaken Desktop 的应用壳、侧栏、按钮、导航标题、状态文字、上下文用量面板和其他界面 chrome 默认不可选择，鼠标拖动不能把整窗 UI 文案染成文本选区。
- Awaken Desktop 不提供浏览器式 `Tab` / `Shift+Tab` 焦点轮转；Renderer 在 capture 阶段统一消费未修饰 Tab，Electron Main 同时提供窗口与 Office HTML webview 兜底，因此切换页面、设置分区、按钮、链接或表单控件都不会因 Tab 获得焦点或出现外置焦点框。Control、Command 或 Alt 修饰的组合键不由该规则消费。Design System 组件仍保留独立 Gallery、辅助技术和程序化聚焦需要的 `focus-visible` 语义，Desktop 不通过逐组件 `tabIndex` 或删除全局样式实现这项产品策略。
- 最终回答 Markdown、其中的代码、Prompt 气泡内的正文/token 标签/附件文件名，以及其它明确标记为可复制正文的阅读内容允许鼠标局部选择；Composer、设置表单和其他文本编辑控件保持原生编辑选区。
- macOS 的 `Cmd+A` 与 Windows/Linux 的 `Ctrl+A` 只全选当前获得焦点（或当前选区所属）的 textarea、文本 input、单一 `contenteditable` editing host，或带 `data-aw-select-all-root` 的 Prompt 可读根。焦点落在 atomic token 芯片内时仍全选其所属 Composer host。焦点与选区都不在这些宿主时，快捷键不创建跨侧栏、Workbench、overlay 或状态栏的文档级选区，并清除已有的整页 DOM 选区。
- Composer 与 Prompt 的复制纯文本包含可见的文件名、Skill/插件名与正文，按同一行流拼接，不把软换行写成硬换行；不包含 Skill 路径或 Computer Use 隐藏引导。Prompt 展开态复制入口使用同一可见拼装规则。全选快捷键不能把执行过程标题或回答 footer 元数据拼成一份隐式整页复制内容。

## 跨主回复的子任务活动

ThreadSession 同时管理 root run SSE 与 thread activity SSE。root 终态只结束前者；后者继续接收旧 run 的后台 child 事件，按 task/agent 和 canonical/source identity 路由。切换 thread 清理旧订阅与重连定时器；活动游标过期后从耐久 transcript 重新加载。

子任务的计划、当前上下文、用量和实际模型/effort 显示在自己的右侧标签页。用户任务问答仅由主 Agent 发起；MCP/ACP 授权与 Computer 复核按原身份使用公共专用控件。停止与后台生命周期遵守[子智能体协作](../../02_主智能体闭环/子智能体协作/实现方案.md)，关闭标签不取消执行。

## 撤回问题的投影与验证

`runtime/reducer.ts` 在本地 `run/cancelRequested` 和 cancelling snapshot/event 中标记 `withdrawn`，不立即清空原问题；终态清空 gate，迟到 requested 不得复活。`UserQuestionPrompt.tsx` 在 withdrawn 时只渲染原问题与选项，不渲染输入/提交；答案输入的 Escape 冒泡给卡片，IME 和已消费事件不再处理。`App.tsx` 的 answer/cancel 回调仍调用既有 API，并按原 thread/focus ownership 恢复 Composer 焦点。`run-narrative/projector.ts` 忽略临时问题开关事件，耐久 ask_user 工具记录独占历史；`runtime/stop-display.ts` 统一终态展示。

自动化覆盖 reducer 撤回/终态/迟到事件、停止来源、只读卡和旧 transcript 中性文案：`npm --workspace @awaken/desktop test`。真实验收由根 README 正式 Desktop 入口进入隔离任务，依次验证 Escape、答案框 IME、嵌套菜单、回答/Stop 竞争、切换会话、草稿光标与滚动；需同时回读 tool result 和 run_terminal。当前新增自动化与真实 OAuth/跨平台验收分开报告。
