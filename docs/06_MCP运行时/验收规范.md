# 验收规范

## 1. 自动化

至少覆盖：

- user/project/dynamic scope 合并、invalid/disabled、同名 owner 和 remove safety；
- stdio/HTTP/SSE initialize、list_changed、局部失败和注销；
- provider manifest/readiness/dependency 投影到 run snapshot；
- metadata-less 明确 read-only（包括 open-world read）自动；metadata-less/无效-metadata 的普通别名 mutation 与 annotations 自相矛盾者在 transport 前以 `unverified_mcp_provider_metadata` 拒绝；有效 metadata 的 ordinary mutation 自动；
- typed individual message auto；mass review；unknown recipient transport 前拒绝；
- remote delete contract 缺失 transport 前 unsupported、结果 recovery evidence 复核；
- artifact output contract/output schema gate；strict base64、hash、size、extension/MIME/kind/container、TaskScope writable+output、workspace/sensitive/protected/symlink；exact broker delta、replace Trash receipt、false-success 无 artifact、direct adapter TaskScope、cancel bounded cleanup、post-commit failure receipt truth和原始 bytes 不进入 Outcome；
- 隔离四路 fixture `TestIsolatedTypedMCPSkillScriptAndShellArtifactRoutes` 对比 Tool Catalog 中真实 `document_create` 与同为 `document.create` 的 MCP provider；installed Skill script/直接 Shell 明确走 supervised Shell 后再 `artifact_publish`，不冒充 typed capability。四路生成与登记同类 Markdown artifact，但该测试不是 Desktop/视觉验收证据；
- DOCX automation 还要用可打开的 OOXML ZIP container 通过 host bridge；该证据不外推为 PDF/PPT 渲染或 Desktop 验收；
- MCP prompt/resource 动态注册、调用时 fetch、list_changed、disconnect 注销；
- OAuth credential ref、重启恢复和 secret redaction。

聚焦命令：

```bash
go test -count=1 ./src/mcpclient ./src/connectors ./src/skills ./src/skillruntime ./src/agentcore
```

## 2. Desktop 验收

用隔离 profile 在真实 Awaken Desktop 验证：添加/覆盖/删除 user MCP、project override、动态 Connector、认证、工具调用、单人/群发消息、remote delete 拒绝、host-mediated artifact create/replace/cancel、prompt/resource Skill 出现/调用/断开。artifact 需要同时核对 live bytes、provider/hash/size、ArtifactDescriptor、observed change、Trash recovery 与 broker receipt，并明确它不是视觉/语义质量验证。验收必须记录 external call count 或 provider 侧证据，不能只看卡片。

## 3. 未通过边界

本轮若未执行 OAuth 真实 provider、重启 owner 竞态或 Windows/Linux 实机，只能报告自动化；WebSocket、透明 401 重试和统一 live generation 当前仍不支持。
