# 工具发现与执行 · 需求文档

模型通过统一工具目录使用本机和外部能力。用户需要知道工具能否使用、失败原因以及是否已经产生副作用。

## 工具如何进入任务

- 八个基础工具为 Bash、Read、Edit、Write、Glob、Grep、WebSearch、WebFetch。低频辅助工具和 MCP 工具按需检索加载。
- 缺少依赖、未认证和暂时故障分别显示，不能把未就绪工具当作可用能力。
- 普通工具默认自动执行，不提供通用逐工具审批或消息发送审核。远端权限与幂等性仍由工具和服务负责。
- 需要补充信息时向用户提问；取消回答后主任务可以继续。外部授权和计算机复核使用各自的专门交互。

## 失败与恢复

结果未知或只完成一部分时，先核对实际状态，不能盲目重发。外部授权完成后，由宿主验证，同一调用最多自动重放一次；再次要求相同授权时停止循环。

Bash 以当前用户权限执行，不提供工作区沙箱。只有实际使用文件工具的废纸篓路径时，才能承诺可恢复删除。当前生产审计查询尚不完整，不能把测试记录当作完整审计。

工具定义、权限决策、输出校验和验收见[实现方案](实现方案.md)。

## 完整结果与预览

较长工具结果可以显示有界预览，但完整正文必须先保存在当前 Agent 有权读取的结果存储中。模型拿到读取标识后可以分段核对；预览不能作为已经消费全文的证明。

## 子 Agent 与并行读取

普通 Agent 可以使用其权限内的完整工具能力，受限角色不会因此获得写入权限。互不依赖的内建只读调用可并行，媒体读取先检查整批预算；写入、外部副作用与可能改写输入的 Hook 继续按各自顺序执行。结果仍按原调用顺序显示和保存。
