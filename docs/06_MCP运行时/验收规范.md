# 验收规范

## 1. 自动化

至少覆盖：

- plugin/user/project/dynamic 四 scope 合并（plugin 最低，用户/项目同名覆盖）、invalid/disabled、同名 owner 和 remove safety；plugin scope 保持 Agent Plugins 翻译后的字面 command/URL/headers/args/env/cwd 与未知 placeholder，不进入 user/project 通用 `${VAR}` 展开；`enabled:false` 在 Manager 中恢复为 disabled 且不连接，toggle 写回 effective scope；删除 project override 后恢复同名 user fallback；user config 唯一读写 `AWAKEN_HOME/config/mcp-servers.json`，Electron `userData` 与其他旧路径不读取、不迁移、不 fallback；stdio 在配置 env 之后写入 filesystem-resolved `PLUGIN_ROOT` / `PLUGIN_DATA` 并覆盖同名项；
- Codex/Claude/Cursor MCP adapter 的 stdio/HTTP/SSE config、vendor root/data/userConfig variables、未解析 placeholder fail closed、component/server/tool override 恢复；Agent Plugins 只设置 tool override、未设置整个 server desired override 时，Store 重载后仍保持该工具停用；plugin runtime reconcile 对 identity/scope/config 完全相同的 server 是 no-op，不关闭 session或注销工具，删除插件配置时只移除 `plugin__` owner、不影响 user/project/dynamic；disabled tool 保留 inspection 但不进入 Registry；Plugin Hook `mcp_tool` 只调用同插件 ready tool；
- `AWAKEN_DEFAULT_WORKSPACE` 为空时 user MCP 配置读取、保存、更新、启停、删除和连接仍可用，project scope 不参与且不回退 cwd、用户主目录或最近项目；配置有效 default workspace 时才加载 `<workspace>/awaken.mcp.json` 并验证同名覆盖；
- 管理 API 接受纯中文/非 ASCII `mcpServers` 名称，保存原始 `displayName` 并生成稳定 ASCII-safe identity；接受单个裸 `http://`/`https://` Streamable HTTP URL，生成不含 query credential 的稳定 `remote_<hash>` identity，并拒绝缺 host 或非 HTTP(S) URL；server snapshot 与 Desktop 卡片显示 `displayName`，内部 tool route 仍使用 canonical identity；
- stdio/HTTP/SSE initialize、list_changed、局部失败和注销；含多段 `__` 的 Plugin server identity 必须完成真实 tools list/call，Manager 与 adapter 不把 owner 误拆成 `plugin`；合法点号 plugin name 必须保留 raw identity，同时以 model-safe canonical name 真实进入 Registry、run snapshot、MCP catalog、`tool_find` 和 pinned Runtime call；不安全或 `x0_` 开头的 server/tool component 必须可逆且无 sentinel 碰撞；注销 `...__local` 不得误删 `...__local__nested`，canonical 与旧 raw server wildcard permission override 都可命中；Agent Plugin fixed headers 只到配置 origin、不同 origin redirect 不携带、已有宿主/OAuth 同名 header 优先；`mcpServers.*` 的 `type: "streamable-http"`、`type: "http"` 与省略 type 都归一化为 canonical `servers.*.http`，未知 transport 返回列出受支持值的校验错误；
- provider manifest/readiness/dependency 投影到 run snapshot；
- 混合工具只读操作声明经过真实 tools/list serialization、Manager、ToolRuntime 与 Outcome normalization：同参数 query 可重复，穿插写入后仍可回查；execute 仅换 idempotency_key 仍在 transport 前拦截；未知/缺失/错误类型/大小写/空白选择值、无声明或伪造结果正文不降级；无效 metadata 告警、Artifact bridge 和整体写 annotations 不降级；
- 可选 error metadata 的真实 MCP serialization、provider 耗尽禁止宿主重试、host 拥有预算的只读恢复、未知/非 bool/超量/矛盾 metadata、原始 destructive 声明、mutation 和正文伪造均保持保守结果；MCP transport 完成与 ERP 等下游读取超时分别记录；
- metadata-less/无 annotations 的 read 与 mutation、无效 metadata、annotations 自相矛盾、message/group/broadcast 和 delete 均在 connected/auth-ready、schema 有效时直达 transport；至少覆盖 OfficeCLI 风格单一 `officecli(command)` tool；
- ToolRuntime 与 direct adapter 都不对 MCP 单发、群发、频道、广播或批量消息建立 review，不因未知 recipient 拒绝，也不要求 recoverable-delete contract/evidence；`trash_file` 自身的可恢复删除合同仍由 04 域独立覆盖；
- Go MCP SDK 推导的 nullable input/output schema 覆盖根 object 和嵌套 `type: ["null", "array"]`/`type: ["null", "string"]`；adapter 必须保留为等价 `oneOf`，input 仍完整投影 properties/items/required 而不退化成空 object，canonical 字段冲突时 output schema 与 `StructuredContent` 一致放入 `mcp_payload`，两种形状都不得产生虚假 `tool_output_schema_mismatch`；
- 未声明 MCP `outputSchema` 时，任意 object 形 `StructuredContent` 按未类型化 details 接收，不得因宿主的 no-details 默认值产生虚假 `tool_output_schema_mismatch`；
- artifact output contract/output schema 无效时记录 warning、普通 MCP 调用仍完成且不产生 Artifact；有效 bridge 继续覆盖 strict base64、hash、size、extension/MIME/kind/container、TaskScope writable+output、workspace/sensitive/protected/symlink、exact broker delta、replace Trash receipt、false-success 无 artifact、direct adapter TaskScope、cancel bounded cleanup、post-commit failure receipt truth和原始 bytes 不进入 Artifact Outcome；
- 隔离路由 fixture 对比普通 MCP provider、installed Skill 与本机 `Bash`/`Write`：本机生成文件后必须显式调用 `artifact_publish`，不能冒充已退役的 typed artifact capability。该测试不是 Desktop/视觉验收证据；
- macOS/Windows route fixture 覆盖 dead/alive loopback 环境代理、system PROXY/DIRECT 指令、NO_PROXY、proxy-only fail closed、MCP connect/config/enable 操作前校准、authenticated Core hot update；route generation 变化重新启用 failed stdio/HTTP/SSE，且已 connected stdio 先转 pending、等待在途 tool call 结束后重建 child，不自动重放调用，不重启 connected HTTP/SSE、disabled、needs-auth 或 in-process；
- DOCX automation 还要用可打开的 OOXML ZIP container 通过 host bridge；该证据不外推为 PDF/PPT 渲染或 Desktop 验收；
- MCP prompt/resource 动态注册、调用时 fetch、list_changed、disconnect 注销；
- OAuth credential ref、scope/name/canonical-endpoint identity、endpoint 变化与删除清理、重启恢复和 secret redaction。

```bash
go test -count=1 ./src/mcpclient ./src/connectors ./src/skills ./src/skillruntime ./src/agentcore
```

## 2. Desktop 验收

用隔离 `AWAKEN_HOME` 在真实 Awaken Desktop 验证：先以空 `AWAKEN_DEFAULT_WORKSPACE` 启动，确认配置弹窗可在「本地进程（stdio）」和「Streamable HTTP」两个模式间切换，未编辑的示例随模式切换，已粘贴的配置不会被切换动作覆盖；粘贴远程 JSON 或裸 URL 时模式提示自动切到 Streamable HTTP 且原文不被重写。分别粘贴纯中文 server 名的 `type: "streamable-http"` 无 secret JSON 和裸 URL fixture，确认 Core 以 `http` canonical shape 保存、卡片显示原中文名或 endpoint host、设置/工具路由继续使用稳定内部 identity；query credential 只允许用专用测试凭据，不能进入截图、日志或报告。随后确认设置页能显示 user MCP 的完整 JSON、方法与连接状态，并能添加、修改、enable/disable、删除后重启恢复；确认 Electron `userData` 或其他旧位置放置的同名配置不被读取、迁移或改写。若本次 Desktop 启动提供有效 default workspace，还需验证 project override 的读取、编辑、停用、删除与 user fallback；否则该部分只报告自动化证据。macOS 与 Windows 还需分别按 03 域代理矩阵，让一个远程 HTTP MCP 和一个会联网的 stdio MCP 在代理监听器退出后失败，再确认 route generation 更新后 failed server 自动重连；对已 connected stdio 还要在无调用和有在途调用两种状态下切换代理，确认无调用时及时更换 child，有调用时等调用收口后更换，旧 child 退出不注销新工具，Core PID 不变，且不自动重放当次调用。监听器恢复后的新 child 环境必须反映最新 route；不得用另一平台或 mock 推断实机结果。动态 Connector、认证、OfficeCLI 风格通用工具、群发消息、remote delete、host-mediated artifact create/replace/cancel、prompt/resource Skill 出现/调用/断开仍按对应可达入口验证；消息和删除应确认调用到达 provider，而不是出现 Awaken review/recoverable-contract 拒绝。artifact 需要同时核对 live bytes、provider/hash/size、ArtifactDescriptor、observed change、Trash recovery 与 broker receipt，并明确它不是视觉/语义质量验证。验收必须记录 external call count 或 provider 侧证据，不能只看卡片。

当前 macOS Desktop + 真实 `qwen3.7-plus` / Anthropic Messages 基线已覆盖两条动态 MCP 路径：合法点号 Plugin `awaken.acceptance.20260827` 保持 raw identity，`tool_find` 激活 canonical `mcp__plugin__awaken_acceptance_20260827__local-smoke__echo` 后实际回显 nonce，且 `PLUGIN_ROOT` / `PLUGIN_DATA` 均由宿主注入；远程钉钉 MCP 一次精确激活 4 个工具后四次调用都得到 `status=success`。后者四项都带 `tool_output_schema_mismatch` warning（provider 返回的 envelope 比注册 output schema 多 `status/data/error/meta/summary`），其中两个大示例另带 `output_truncated`；因此连通、动态 schema 注入与调用链通过，但 output schema 对齐和大结果续读仍是已知缺口，不能写成无告警全通过。

当前 macOS Desktop 已实测可选只读错误 metadata：隔离 provider 的一次下游 408 在 provider 内恢复一次后成功；持续 408 共两次读取后返回 mcp_provider_read_timeout / runtime / transport completed / side_effect none / retryable=false，模型按 do_not_retry 停止，没有追加调用。会话为 `thread_1788620646826324000_6`，该 fixture 使用模拟数据，不是外部 ERP 服务故障的实测；临时插件已移入 Trash。普通真实 ERP 查询另在 `thread_1788620603322343000_4` 完成，未发生超时。

当前 macOS Desktop 已验证混合工具的重复只读操作：通过正式入口重建并重启 Core，替换带 read-operations 声明的添慧仓储插件，在 `thread_1788681836508169000_2` 使用模糊编号 `0150-A` / `0150-B`，对主辅料的入仓、领料通知、出仓来源各按相同参数连续查询两次。12 次真实调用均成功，canonical side effect 均为 none，六组业务数据一致；独立 ERP 回读的已有采购、仓储、通知和库存与先前闭环一致。本次没有新增 ERP 写入。重复写入保护另由真实 MCP serialization + ToolRuntime + FailureSupervisor 自动化覆盖：查询前后均可重复，execute 仅更换幂等键仍在 provider transport 前阻断；这项计数夹具不是 Desktop 实际写入验收。
