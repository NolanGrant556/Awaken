# 文件操作与路径安全 · 实现方案

本文说明代码职责、数据与接口、异常恢复和验证方法。功能范围及用户操作见[需求文档](需求文档.md)。

## 平台实现

| 平台 | 当前实现 | 恢复语义 |
| --- | --- | --- |
| macOS | `rename` 到 `~/.Trash` | 同卷移动；返回实际路径；不是 NSWorkspace 完整 Finder 集成 |
| Windows | PowerShell 调用 Microsoft.VisualBasic FileIO | 发送到 Explorer Recycle Bin；目标仅经环境变量传入，失败则 fail closed；当前不返回可见 trashed path |
| Linux/其他 | fail closed | 不永久删除 |

macOS/Windows 都拒绝 symlink 和特殊文件。macOS 处理同名碰撞，跨卷 rename 返回 typed failure，不能 copy-then-delete；Windows 调用后复查原路径确已消失，否则判失败。恢复仍依赖系统回收站状态，Awaken 当前没有通用“还原”工具。

## 文件状态与媒体

- 部分文本读取也建立完整宿主文件快照，因此可用于后续 `Edit`/`Write` stale check。
- 同一路径的 mutation 由 thread state 串行；compare-and-write 防止外部修改或并发覆盖。
- 再次读取未变化文件返回 `file_unchanged`，仍刷新当前读取状态。
- 媒体 Base64 只存在于运行内存；持久化只保存 `storage_key`，由 03 域定义水合与缺失恢复。
- `Edit`/`Write` 产生 canonical change/diff，但永不自动发布 Artifact；最终交付文件必须显式调用 `artifact_publish`。

- `src/tools/read`、`edit`、`write`、`glob`、`grep`：五个模型基础文件工具。
- `src/tools/internal/textfile`、`filemutation`、`rgexec`：编码/原子写入/固定 rg 复用层。

## 必须保持的规则

- Renderer 传入的 path、Skill root 或 MCP metadata 不是授权事实。
- lexical `HasPrefix` 不能作为路径边界；必须使用平台路径规范化和祖先/realpath 校验。
- Workspace broker 顺序必须是 seal -> scan staged -> build plan -> validate protected/writable -> recheck live concurrent state -> Trash recovery -> publish。任一 delta 越界时整批 deny，在 Trash 和 live publish 前返回 `denied_writable_scope` 或 `denied_protected_root`、`side_effect_state=none`、`live_workspace_unchanged` 和 `trash_not_invoked`。
- broker 的 `workspace_scope_declared=true` 且 canonical writable set 为空时表示 workspace 内零可发布路径，不得回落扩大到 workspace；这是 `git_remote ls_remote` 的正常合同。
- Workspace broker 将 `WritableRoots` 与 `ProtectedRoots` 用于提交检查要求；MCP Artifact bridge 在进入 broker 前还必须满足 `OutputRoots`。
- `git_remote ls_remote` 显式声明零 writable roots；`git_remote clone` 不继承整个 workspace 的可写范围，而是把 broker request 再收窄为唯一 canonical destination。remote checkout 产生 destination 外 delta 或 symlink 时整批拒绝。
- `ProtectedRoots` 必须覆盖 scope 里的每一个 root；只为 `WorkspaceRoot` 生成保护项是不安全的。
- `ProtectedRootExceptions` 必须始终只包含 `<AWAKEN_HOME>/plugins`，以及在本次 scope 真有 root 落入时才出现的 `<AWAKEN_HOME>/sessions`。插件例外不覆盖 `<AWAKEN_HOME>/config/plugins.json`；两个例外内部的形状规则都不得跳过。
- roots 不得被重新当成路径围栏。越界访问由用户指令驱动，不引入审批；要收紧只能通过形状名单，而形状名单只作用于写，不作用于读。
- `Glob`/`Grep` 的 `project` 模式纠正共同父目录和项目外路径只约束默认意图，不是权限拒绝；`explicit_path` 必须继续允许用户点名的外部绝对路径。
- 第三方提议的路径与用户指令不同源，但当前**不**因此额外收紧：MCP Artifact bridge 已放开 `writable ∩ output` 约束，仅保留 `relative_path` 格式校验（相对、canonical、禁止 `..`）、symlink 组件拒绝和 `ProtectedRoots`。
- 不带 `path` 的搜索必须只覆盖 readable roots；把默认范围放大到全盘会让一次无范围搜索不可用。
- 项目 ID、项目名、cwd、精确文件夹组和 permission profile 必须出现在 provider 可见的结构化 environment context 里。只写进宿主侧 `runtime_snapshot` 不算下发：模型看不到的 roots 会退化成「只知道 cwd」，进而靠 `..` 向上级目录试探。
- `project_id` 是 scope 身份，`project_name` 只做模型可读上下文。任何路径解析或权限判定都不得从展示名派生。
- 写失败、删除失败或副作用未知时不得把目标状态写成已完成。
- Windows 盘符、UNC、反斜杠、大小写与非 ASCII 路径需要平台测试，不能从 Unix fixture 推断。

## TaskScope与路径安全：代码位置

- `src/tool/permission.go`、`sensitive.go`：TaskScope、敏感路径与 `ProtectedRootExceptions`。
- `src/runtime/run_service.go`：`normalizeWorkspace` / `normalizeWorkspaceForThread`、`scopeProjectID`、`buildProtectedRoots`、`buildProtectedRootExceptions`。
- `src/desktopdata/paths.go`：`PluginsRoot`、`SessionsRoot` / `SessionWorkspacePath` / `SessionOutputPath`，插件仓库与 session 工作目录路径的唯一构造点。
- `src/tools/internal/searchroots`：只读搜索工具的多根解析与展示路径规则。
- `src/prompt/system_prompt.go`、`runtime.go`、`templates/default_system.md`：项目名、文件夹组与作业范围约定的模型可见渲染。
- `src/agentcore/request_builder.go`：`projectFolderObservations`，把 scope 的 readable roots 投影成模型侧文件夹组。
- `apps/desktop/src/renderer/App.tsx`：`resolveRunProjectForRun` 决定每次 run 下发的 `project_id` 与 `project_name`，`resolveRunRootsForRun` 决定下发的 roots。两者都按「cwd 所属项目的任意文件夹」匹配，新建项目与改动文件夹组后由 `refreshProjects` 刷新的项目列表直接生效。同一个文件夹可以属于多个项目，所以路径不足以确定身份：优先采信侧栏当前选中的项目，只有它并不持有这个根时才回退到按路径查找，roots 必须取自被判定的那个项目，否则模型会看到另一个项目的文件夹组。
- `apps/desktop/src/main/project-files.ts`：右侧项目文件树/预览的 project/folder membership、relative path、lexical containment 与 realpath containment 只读检查要求；`project-file-preview-manager.ts` 只消费该解析结果并管理 opaque preview 生命周期。
- 各 typed tool：输入 schema 与具体路径类型。
- `src/tool/execution_broker.go`、`execution_broker_workspace.go`：dependency/git/MCP Artifact 的 canonical roots 与提交前全量 delta 检查要求。
- `src/tool/trash`：平台 recoverable-delete adapter。

## 当前支持的实现

删除统一使用 `trash_file`，支持单路径或明确路径列表。canonical schema 和 executor 都要求 `path` 与 `paths` 必须且只能提供一个；为兼容拒绝根级组合关键字的 OpenAI Chat/Responses 网关，wire schema 会把两项显示为带互斥说明的可选属性，但 ToolRuntime 仍按 canonical `oneOf` 在权限与执行前拒绝缺失或同时提供。成功结果返回 `original_path`、`method`，并在平台可观察时返回 `trashed_path`，同时写 observed `trashed` change；批量中途失败标为 partial/unknown，要求先检查原路径和 Trash，禁止自动改用永久删除。

## TaskScope与路径安全：当前支持的实现

Desktop 右侧项目文件树与预览使用另一条更窄的只读边界，不继承“工具可读任意绝对路径”的 Agent 语义。Renderer 只能请求当前 active `projectId` 已绑定文件夹中的一个相对目录或文件；Electron Main 每次从 Core 刷新项目事实，核对精确 folder membership，并同时执行 lexical containment 与 realpath containment。目录 symlink 可以作为叶子显示，但不能继续遍历或预览；未绑定文件夹、`..`、绝对路径和 symlink escape 全部 fail closed。目录 bridge 只返回目录项元数据；文本预览使用有界 typed IPC，二进制/HTML 预览使用 Main-owned 短生命周 opaque handle 和受控协议，不提供任意 `readFile(path)`。
