# Workbench 中间区域验收规范

## 1. 权威范围

本文唯一拥有 Workbench 当前自动化门禁、真实 Desktop旅程、AC编号、证据要求和 baseline更新规则。复核人员用 [复核清单](复核清单.md) 选择适用 AC，不在清单中重新定义行为。

## 2. 完成原则

Workbench改动只有同时满足以下条件才能宣称完成：

1. 相关权威文档已同步；
2. 纯决策/reducer/projector/Design System测试按 owner通过；
3. Desktop typecheck和 UI smoke按改动范围通过；
4. 真实 Awaken Desktop中执行适用 AC；
5. scroll、sticky、follow、composer测量等动态行为有录屏或连续关键帧；
6. 视觉变更有当前 HEAD的截图和 manifest；
7. 发现契约与真实行为不一致时记录产品/代码差异，不用改文档掩盖。

浏览器直接打开 renderer、Design Gallery、server render、静态 DOM和旧截图都不能代替真实 Desktop动态验收。

## 3. 自动化门禁

最小命令：

```bash
npm --workspace @awaken/desktop run test
npm run typecheck:desktop
git diff --check
```

按改动追加：

```bash
npm run typecheck:ui
npm run smoke:ui
npm run test:desktop-lifecycle
go test ./...
```

测试 ownership：

| 改动 | 必跑测试 |
|---|---|
| center/dock、turn、marker、scroll、prompt、Slash、附件 | `apps/desktop/src/renderer/App.test.ts` |
| event投影、tool状态 | `apps/desktop/src/renderer/run-narrative/projector.test.ts` |
| replay、thread、artifact、deliverables、command output | `apps/desktop/src/renderer/runtime/reducer.test.ts` |
| 交付物卡片 | `apps/desktop/src/renderer/deliverable-list.test.ts` |
| 安全打开 | `apps/desktop/src/main/artifact-open.test.ts` |
| Design System组件/样式 | UI typecheck + render smoke +相关组件测试 |

旧验收摘要不代表当前执行结果。

## 4. Desktop准备

1. 记录 HEAD、工作区状态、平台、主题和窗口实际尺寸。
2. 按根 README正式入口启动 Desktop。
3. 确认目标窗口标题为 `Awaken Desktop`，不要使用 Design Gallery或其他 Electron窗口。
4. 使用可删除的测试 thread/workspace；不要在验收中修改真实业务文件。
5. 验证前将窗口调整到可稳定容纳三栏的尺寸；响应式 AC另行缩窄。
6. 如果验证只要求只读，不点击连接、断开、安装、删除、模型保存、宠物选择等会修改 userData 的动作。

## 6. 动态行为判定

### 6.1 Anchor / sticky

- 以 prompt header在 RunStage顶部锚点的位置判断，不以页面截图裁切猜测。
- 旧 turn滚出锚点后 active marker必须同步。
- 多行prompt高度变化后旧header不得覆盖turn body。

### 6.2 Follow

- streaming期间先确认自动跟随；
- 再明确向上滚并等待内容增长；
- paused视图不能跳；
- passive layout变化不能让按钮消失；
- 恢复后必须到同一 native bottom，不出现额外空白底部目标。

### 6.3 Composer测量

分别触发 textarea多行、runtime panel、ask_user/mass-message gate适用状态，观察 output、marker、return随真实 ComposerBar/stack变化。不得只用 CSS检查替代。

## 7. Screenshot/VRT

捕获工具：

```bash
npm run capture:workbench -- --state center --no-open
npm run capture:workbench -- --state dock --no-open
npm run capture:workbench -- --state marker --no-open
npm run capture:workbench:vrt
```

工具只负责抓取真实窗口和写 manifest，不做像素差异判定，也不会证明状态准备正确。每张图必须人工确认对应状态。

### 7.1 Baseline manifest必填

- 当前 commit；
- capturedAt；
-平台和实际窗口坐标/尺寸；
- theme preference与生效主题；
- 状态准备步骤；
- screenshot SHA-256；
- capture mode/settle时间；
-人工 reviewer与结论。

### 7.2 当前 baseline状态

`验收基线/center.png`、`dock.png`、`marker.png` 是2026-07-05进入仓库的旧证据。它们在当前 HEAD重新准备三态、重拍并人工核对前标记为 `legacy-unverified`，不得宣称代表当前视觉。详细状态见 `验收基线/manifest.json`。

新图只有三态全部通过后才能原子替换旧图和 manifest。如果任一状态违反契约，保留旧图并报告差异，不替换 baseline。

## 8. 证据保全

正式知识库只保留当前 center/dock/marker baseline。任务过程录屏和临时关键帧放在 PR/任务附件或临时验收目录，不建立永久历史档案。交付报告必须列出实际命令、HEAD、证据位置和未通过项。

## 9. 停止条件

出现以下任一情况立即停止 baseline替换并报告：

- 中间区域整体滚动失效；
- latest prompt无法锚定或旧header遮挡；
- return层挡住scroll/wheel；
- output被composer覆盖；
- replay产生重复/丢失；
- 需要点击会修改真实 userData 的操作才能继续只读验收；
- 真实Desktop行为与权威文档冲突。
