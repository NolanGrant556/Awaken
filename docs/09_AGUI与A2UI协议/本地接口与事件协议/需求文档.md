# 本地接口与事件协议 · 需求文档

Desktop 通过本地 HTTP 和 SSE 读取、控制运行并恢复事件。Core 内部事件与对外协议分层，A2UI 当前只作参考。

代码、接口和验证方法见[实现方案](实现方案.md)。

## 当前支持

Awaken 使用 AG-UI 风格事件承载 run、message、tool、context、Skill、artifact 和主动提问。内部 Agent event 和 SemanticRecord 不是 wire；它们必须经过 mapper/projector 转成 `agui.Event`。

live SSE 与 durable replay 共用 semantic projector。transport cursor、semantic frame seq 和 journal seq 分离，断线恢复不得把 cursor 当业务顺序。

## A2UI

A2UI 仍是上游参考，不是当前 Awaken Desktop 的生产 UI schema/runtime。当前没有通过 A2UI surface/component tree 驱动 Workbench 的完整链路，不能把 AG-UI event 增量误称为 A2UI 已实现。

## 当前缺口

- 右侧 Inspector 尚未消费 provider/dependency/side-effect 详情；
- 旧 transcript 的审批记录只能作为通用 legacy card/unknown projection 回放，不能恢复为可操作审批；
- A2UI renderer、schema negotiation 和安全 component action 尚未实现。

## 地址与信任边界

本地 loopback 不等于已建立跨用户认证边界。新增高风险 route 必须同时评估 Electron 代理、请求来源、文件/凭据权限和审计，不得因“只在本机”绕过功能域安全合同。

## 子任务持续更新

主回复与子任务活动有各自的订阅和游标。用户允许后台执行时，主回复完成后仍能看到子任务的正文与状态。断线重载不会重复正文，旧会话事件不能进入当前会话；游标失效时从耐久记录恢复，不能伪造完成。

用户对任务的追加说明只交给主 Agent。本地接口不提供对子 Agent 的直接消息、继续和关闭操作；Agent 间协作仍走内部工具。子 Agent 不创建普通用户提问，授权与安全复核保持原专用接口。
