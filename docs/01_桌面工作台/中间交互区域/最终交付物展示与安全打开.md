# 最终交付物展示与安全打开

## 1. 权威范围

本文唯一拥有最终交付物在 Desktop Workbench中的筛选、排序、卡片、open/reveal和失败呈现。artifact producer/role由 04 域拥有，durable transcript由 03 域拥有，wire字段由 09 域拥有。

## 2. 产品规则

- 只在 run终态展示本轮 `deliverable + ready + 支持扩展名` 文件。
- 成功、失败、取消都保留已就绪交付物；失败/取消显示准确弱提示。
- 交付物位于最终回答之后，同一 turn内；不进入 composer或右侧占位 Inspector。
- 图片、视频全部以独立小卡片展示；非媒体文档 1–3个全部展示，超过3个默认前三个并可展开/收起。
- 文档主区域交给系统默认应用打开；媒体主区域进入 Awaken 预览层。更多菜单和媒体预览工具栏提供系统默认应用打开与文件管理器定位。
- PDF有独立 PDF icon、格式标识和类型文案。
- 输入附件不属于交付物，不复用安全打开入口。
- `Bash`、`Write`、Skill 或外部程序生成的受支持文档必须成功调用 `artifact_publish` 后才进入新 run 的交付物；内置 `image_generate` / `video_generate` 直接产生 typed ready media deliverable 和专用媒体卡，成功后不得再次调用 `artifact_publish`。文件 change 本身不自动升级。
- 图片、视频交付卡直接展示缩略图或视频首帧入口；完整图片查看和原生视频 controls 位于 `RunStage.overlay`。系统打开和定位的安全语义与文档交付物一致。
- 旧 typed Office/file producer 只用于历史 transcript 的保守回放；它们不是当前可调用工具。

## 3. 支持格式

```text
.doc .docx .md .xls .xlsx .csv .tsv .pdf .ppt .pptx .png .jpg .jpeg .webp .mp4
```

映射为 word、markdown、excel、pdf、powerpoint、image、video。扩展名比较不区分大小写；没有扩展名或未知扩展名不投影。

## 4. Artifact v2角色

- `deliverable`：用户最终打开使用的文件；
- `preview`：渲染预览、页面图和技术验证；
- `support`：源码、配置、脚本和过程文件。

PPT自动渲染的 PDF/PNG通常是 preview；只有 producer明确发布为 deliverable的 PDF才进入列表。不能依据“看起来像 PDF”把 preview提升为交付物。

新 run 只有 `artifact_publish`、内置媒体生成工具或有效 MCP Artifact bridge 明确产生的 `deliverable` 才进入列表。媒体工具的 ready Artifact 已是最终交付事实，不需要也不允许再经 `artifact_publish` 包装。`Edit`/`Write` change、`deleted/moved/patch/file_change` 和源码保持非交付事实；reducer 不扫描 workspace，也不从最终回答文本猜测文件。

旧 contract `<2` 允许 reducer按已固化 producer/extension规则保守归一化，并在 view model标记 `legacy=true`；其中可包括旧 `presentation_create`、`document_create`、`spreadsheet_create`、`office_export_pdf`、`apply_patch` 和 `text_edit`。安全打开仍要求 folded artifact最终为 ready deliverable；该兼容不恢复旧工具注册。

## 5. 终态汇总

Owner：`apps/desktop/src/renderer/runtime/reducer.ts` 的 `appendFinalDeliverableSummary()`。

规则：

1. 忽略没有 path 的记录并将 `\` 归一为 `/`；
2. 以 lower-case normalized path 折叠全部 Artifact，保留路径第一次出现顺序；
3. 同路径使用最后一次 artifact metadata，因此删除/移动/support/preview 终态会覆盖此前的 deliverable；
4. 对折叠后的最终状态过滤 role/status/extension；
5. 删除旧 `fileChange` narrative；
6. 追加稳定 id `deliverables:<runId>:summary`；
7. 无合格文件时移除同 id旧 summary；
8. replay同一终态不得重复列表。

## 6. UI组件边界

- `AwakenDeliverableList` 拥有前三项/展开和 terminal弱提示；
- `AwakenMediaItemCard` 拥有图片/视频独立卡片、真实宽高比、加载/失败状态和受控操作菜单；
- `AwakenMediaPreviewOverlay` 拥有图片缩放/拖动、视频 controls、同组切换和受控系统操作入口；
- `AwakenDeliverableCard` 拥有文档类型视觉，并为媒体交付组合 `AwakenMediaItemCard`；
- `App.tsx` 只把 durable identity、旧媒体兼容定位和 callbacks 传入；
- renderer不能持有可信文件路径，也不能直接调用 shell/open。

当前产品视觉合同为：列表项间距 `8px`；标准卡片最小高度 `88px`；文件图形宽 `48px`；更多菜单命中区 `44×44px`；菜单项使用 `11px/16px` 字号/行高并保持单行，popover 按内容展宽。PDF 通过扩展名/`fileType=pdf` 识别，使用独立图标、红色 `PDF` 格式标识和 `PDF` 类型文案，open/reveal 语义与其他文档一致。实现 owner 是 `Awaken Design System/src/components/AwakenDeliverableList/` 与 `AwakenDeliverableCard/`；这些数值是当前产品合同，不是 wire 字段。任何视觉调整必须同步组件、当前基线和真实 Desktop 验收，并继续满足 ellipsis、键盘和辨识度。

媒体交付卡宽 `128–144px`，以 8px 间距自动换行；每个 ready Artifact 各自拥有卡片。图片 `load` 后使用 `naturalWidth/naturalHeight`，视频 `loadedmetadata` 后使用 `videoWidth/videoHeight` 更新卡片 `aspect-ratio`，媒体保持 `contain`，不得固定为正方形、裁切或拉伸；ready 媒体直接贴合透明画布，不增加黑色衬底或内框。全部媒体始终展示；非媒体文档继续占满整行并遵循前三项展开规则。小卡不放置视频 controls，只显示播放入口；单击打开 `AwakenMediaPreviewOverlay`，其中背景与查看器 chrome 使用随主题变化的透明毛玻璃，图片画布不铺灰色实底，只有视频元素保留播放所需的深色底。图片支持适应窗口、原始尺寸、缩放和拖动，视频使用原生 controls，左右键或按钮切换同组媒体。Renderer只持有 Main签发的 `awaken-artifact://` opaque URL；不得接触 artifact真实路径。

## 7. 安全 open/reveal

当前 Artifact 请求为：

```ts
{
  threadId: string;
  runId: string;
  artifactId: string;
  artifactPath?: string;
}
```

`artifactPath` 只用于兼容早期 `image_generate` / `video_generate` 已把 ready 路径写入 durable `TOOL_CALL_RESULT`、但尚未发出 Artifact 事件的历史 run。它不是 Renderer 授权：Main 必须在同一 run 的媒体 tool result 中找到完全相同的 ready path，随后继续执行 deliverable、扩展名、realpath 和普通文件校验；任意未记录路径仍返回 `artifact_not_recorded`。新 run 始终优先使用 Artifact id。

已记录的 ready deliverable 不受 workspace、writable roots 或 output roots 的位置限制。路径是 Artifact 事实的一部分，不是 Renderer 传入的授权参数；只要 durable transcript 能按 `threadId + runId + artifactId` 找回该记录，Main 就对记录路径做完整性复验并打开。`artifact_publish` 成功产生的 ready 卡片不得再因所在目录被 open、reveal 或媒体预览拒绝。

Electron Main `artifact-open.ts` 必须：

1. IPC handler先验证请求 sender 是当前 Awaken 主窗口；
2. 读取 durable thread transcript；
3. 验证 thread identity；
4. 找到 run并确认状态为 `finished|error|cancelled`；
5. 优先 fold同 artifact id的 CREATED/UPDATED事件；仅在携带兼容路径时，才从媒体 `TOOL_CALL_RESULT` 恢复该条 ready deliverable；
6. 验证最终 role=`deliverable`、status=`ready`；
7. 验证记录路径的扩展名受支持；
8. 相对路径以 thread workspace解析；
9. `realpath()`解析真实目标；
10. 验证 realpath 目标的扩展名仍受支持且与记录扩展名一致；
11. 拒绝目录、缺失文件和 symlink 导致的扩展名变化；不按目标所在目录拒绝已记录 Artifact；
12. open使用系统默认关联，reveal使用系统文件管理器。

系统文案按 Desktop platform投影：macOS 显示“在 Finder 中显示”，Windows 显示“在文件资源管理器中显示”；两者都复用 Electron `shell.openPath()` 与 `shell.showItemInFolder()`，不得硬编码某个图片或视频应用。

内嵌媒体源使用同一 typed 请求。Main复验 durable artifact，或严格复验历史媒体 tool result 中的兼容 ready path，再验证 `deliverable + image|video`、扩展名/MIME映射、realpath 和普通文件，随后签发短时 opaque URL；媒体所在目录不影响签发。每次 GET/HEAD/Range读取前再次确认 canonical path仍为普通文件且长度未变。该源允许 run仍在生成最终回答时读取已经 ready 的媒体，但不会放宽 open/reveal 的 run终态要求。

`App.tsx` 按 durable identity 缓存 opaque `src`，但不得把它当作跨 surface 永久句柄：从 Skills / 连接器 / 定时任务等会卸载 Workbench 的内部画面返回同一 thread 时，必须清空并重新签发媒体源；卡片解码失败时通过 `onMediaError` 有限次续签。签发失败或续签耗尽时，媒体交付卡与媒体生成明细一致显示“预览不可用”，不得永久停在 ready 骨架。`AwakenMediaItemCard` 在挂载或 `src` 变化后检查 `img.complete` / 视频 metadata，避免 remount 错过 `load` 事件。

禁止硬编码 WPS、Office、LibreOffice或通过展示路径绕过 transcript。

当前打开链路**不读取 magic bytes、不探测 MIME，也不校验文件内容是否与扩展名真实匹配**。例如内容只是普通文本但文件名为 `report.pdf`，只要其他 identity/状态检查通过，当前会交给系统默认应用。内容级格式探测是明确未实现项，文档和验收不得把扩展名复验称为“真实格式校验”。

## 8. 领域错误

| code | 用户语义 |
|---|---|
| `runtime_unavailable` | 无法从本地 runtime读取 durable任务记录 |
| `artifact_not_recorded` | transcript中没有该 thread/run/artifact |
| `run_not_terminal` | run未结束 |
| `artifact_not_deliverable` | 不是 ready deliverable |
| `unsupported_type` | 记录扩展名不支持，或 realpath目标扩展名与记录不一致 |
| `file_not_found` | 文件移动、删除或不可访问 |
| `not_a_file` | 目标不是普通文件 |
| `no_default_application` | 系统未配置默认应用 |
| `open_failed` | open/reveal调用失败 |

UI只显示稳定消息，不泄露内部路径检查、系统命令或异常堆栈。

## 9. 当前不支持

- 未终态 run直接打开；
- preview/support卡片提升为最终交付物；
- 浏览器内嵌 Office/PDF编辑器；
- 把媒体绝对路径或 `file://` 暴露给预览组件；
- renderer直接打开任意路径；
- 无系统默认应用时自动选择第三方应用；
- 不在支持扩展名列表的任意文件。
- 通过 magic bytes、MIME 或内容解析确认文件真实格式；
