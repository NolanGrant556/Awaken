## Awaken 当前接入

- 火山方舟按量：provider ID `doubao`，卡片名「火山方舟」，Base `https://ark.cn-beijing.volces.com/api/v3`，Chat + Responses。无推理 Key 可调的稳定 `/models`；`ListFoundationModels` 是云账号 AK/SK 管理接口，当前不接入。
- 火山 Coding Plan：provider ID `volcengine`，Chat Base `/api/coding/v3`，Messages Base `/api/coding`。
- 火山 Agent Plan：provider ID `volcengine-agent-plan`，Chat Base `/api/plan/v3`，Messages Base `/api/plan`；账户还可配置图片/视频生成工具。
- 三种接入使用不同产品、凭据引用、模型目录和计费合同，不能互换。

## 鉴权、端点与模型

- 当前内置 route 使用 Bearer Key；按量 API、Coding Plan、Agent Plan 的 Key/账户不能混用。
- 按量推理 Key 能识别未开通的官方 Model ID，并返回 `ModelNotOpen`。这不是 ID 写错或 Base URL 错误；账号要在方舟控制台开通该模型。连接测试不得把该错误写成“模型不存在”。`doubao-seed-evolving` 等新模型常需单独开通，应先测当前代码默认模型或控制台已开通的模型；不要将本文的版本示例当作永久默认值。
- Doubao `model` 可是版本化精确 Model ID（豆包 Seed 与托管第三方都按[模型列表](https://docs.volcengine.com/docs/82379/1330310)日期 ID 调用），也可为自建 `ep-*` 推理接入点；identity、目录和能力来源不同。
- `doubao-seed-2-1-pro-260628` 等精确 ID 用于豆包 Seed 按量调用，UI 展示名不参与 transport。
- 按量计价页列出的托管第三方短名（`deepseek-v4-pro`、`deepseek-v4-flash`、`glm-5.3-flash`、`glm-5.2`）不能直接调用；选择器写入模型列表日期 ID：`deepseek-v4-pro-ga-260813`、`deepseek-v4-flash-ga-260731`、`glm-5-3-flash-260828`、`glm-5-2-260617`。短名只作读取/保存迁移别名。`glm-4.7` / `glm-4-7-251222` 已列入[第九批按量下线](https://www.volcengine.com/docs/82379/1350667)（EOS 2026-09-21），选择器删除。Coding Plan 短名（例如 `deepseek-v4-pro`）不得抄进 `doubao` 选择器。
- 这些托管 ID 走 `doubao` 的 `/api/v3` 与方舟推理 Key，不能和 DeepSeek / 智谱原厂 Key、也不能和 Coding Plan `/api/coding/v3` 混用。官方模型列表将上述日期 ID 标为 Chat + Responses；不把原厂视觉抄到方舟托管身份。模型列表给 `glm-5-3-flash-260828` 标了多模态理解和 128k 输出，视觉仍未写成当前能力。`InvalidEndpointOrModel` 表示方舟不认识该 selector（常见于计价页短名），与账号未开通的 `ModelNotOpen` 分开提示。
- Kimi、MiniMax 和旗舰 `glm-5.3` 出现在 Coding / Agent Plan，当前按量计价表没有 `glm-5.3`，不写入 `doubao` 清单。Coding Plan 已下线 ID 以[套餐下线公告](https://www.volcengine.com/docs/82379/2578687)为准，不进 `volcengine` 选择器。
- `ark-code-latest` 是套餐路由模型，实际后端可变，不能绑定固定 effort/capability。

## 上下文、多模态与工具

- 按量 Doubao 的视觉、视频、工具和上下文按模型列表/能力页与 Chat/Responses 协议判定。
- 推理 Key 没有稳定 `/models`，不能在保存连接时动态改写窗口。当前官方[模型列表](https://docs.volcengine.com/docs/82379/1330310)与[Seed-Evolving](https://docs.volcengine.com/docs/82379/2549861)写入能力表的上限：`doubao-seed-evolving` 1024k/256k；`doubao-seed-2-1-pro-260628` 与 `doubao-seed-2-1-turbo-260628` 256k/256k；2.0 Code/Pro/Lite/Mini 窗口 256k、最大输入 224k、输出 128k；按量 `deepseek-v4-pro-ga-260813`/`deepseek-v4-flash-ga-260731` 1024k/384k；`glm-5-3-flash-260828`/`glm-5-2-260617` 1024k/128k。新 profile 默认用该上限，用户只能调低。
- Coding Plan 的 `doubao-seed-evolving` 按同一官方 1024k 窗口写入，不继续用套餐通用 256k。
- Agent Plan 的图片/视频生成是独立工具配置，不是主模型 profile 的多模态输入能力。
- Responses 官方示例可能使用内置工具和服务端 state；Awaken 本地 tools 权限与恢复不能直接替换。
- PDF Read 没有当前协议 exact 原生 PDF 合同时走页面渲染回退。

## 提示词缓存

- 方舟提供专门上下文缓存 API，属于独立 API 合同；不能等同于 Chat/Responses 的通用 prompt cache 字段。
- Awaken 当前未把 Doubao 按量上下文缓存 API接入主会话 prompt-cache capability。
- 火山 Coding Plan Chat 当前仅以 `undocumented/response_probe_only` 观察缓存 usage，固定显示“未确认”，不声称命中。
- Agent Plan、Messages 和 Doubao Responses 的缓存都需独立官方证据和 adapter 实现。

## 推理开启关闭

- Doubao 深度思考开关、Chat/Responses 参数和支持模型以当前模型能力页为准。thinking 开关和 reasoning effort 分开。
- 官方[深度思考](https://docs.volcengine.com/docs/82379/1449737)为按量 Chat / Responses 列出 `thinking.type=enabled|disabled`，并给出 Seed、托管 DeepSeek 日期 ID 与 `glm-5-2-260617` 的 effort 表。Awaken 当前支持：exact `provider=doubao + https://ark.cn-beijing.volces.com/api/v3 + 该表 Model ID`（含已绑定这些 family 的 `ep-*`）在 `DisableReasoning` 时发送 `thinking.type=disabled`。title、compact、Memory recall 与 Hook prompt 走该线字段。省略 Responses 的 `reasoning` 仍不等于关闭思考。
- Coding Plan / Agent Plan 的 Chat/Responses、`glm-5-3-flash-260828`、无 family 的 `ep-*` 与自定义 Base URL 不继承该合同。Coding / Agent Plan 若走 Messages，仍按协议省略 thinking 块。
- 没有关思考合同时，title/compact 才降到已映射的最低 effort。自建网关或不在白名单的 Seed / 托管 DeepSeek GA 官方最低档是 `low`，仍走该 fallback。`ark-code-latest`、GLM-5.3-Flash 与无 capability 的 `ep-*` 仍 fail closed。

## 推理强度

- 官方按量合同：Chat `reasoning_effort`、Responses `reasoning.effort`；取值 `none|minimal|low|medium|high|xhigh|max`，部分档位按模型映射。复核日期 2026-09-12，来源[深度思考](https://docs.volcengine.com/docs/82379/1449737)。
- Awaken 当前支持：精确豆包 Seed 映射统一 `low | high | max` 到原生 `low | medium | high`。Evolving / 2.1 Pro / 2.1 Turbo 默认官方 `high`（Awaken `max`）；2.0 Code/Pro/Lite/Mini 默认官方 `medium`（Awaken `high`）。Composer 用原生标签。
- 托管第三方按官方[深度思考](https://docs.volcengine.com/docs/82379/1449737)日期 ID 映射：DeepSeek GA（`*-ga-*`）档位 `low/high`，默认 `high`，Awaken `high|max` → 原生 `high`；预览 `*-260425` 与 `glm-5-2-260617` 档位 `high/max`，默认 `high`；`glm-5-3-flash-260828` 不展示。计价页短名只作别名，不把智谱/DeepSeek 原厂视觉或三档 effort 抄过来。
- Coding Plan / Agent Plan 的 `ark-code-latest` 不展示 effort；路由模型切换后不能继续使用旧模型的档位。
- 只有 exact model + protocol 有官方参数和测试时才保留该映射。

## 用量、余额、限流与套餐

### 用量查询合同

- `doubao` D 类：Ark `GetInferenceUsage` 查询按量推理使用情况，可按时间范围/粒度查看窗口详情。
- `volcengine` D 类：Coding Plan 在 Ark 管理目录中存在 `GetSeatInfoUsage`、`ListSeatInfoUsages` 等 action；实现前必须从当前 API Explorer 或 SDK 刷新完整 schema，不根据名称猜字段。
- `volcengine-agent-plan` D 类：`GetAFPUsage` 查询个人 Agent Plan 的 5 小时、日、周、月额度；`ListSeatAFPUsage` 查询团队席位，`GetUsageDetails` 查询明细。
- 凭据：这些都是火山云控制面 API，使用云账号 AK/SK 与 HMAC-SHA256 签名，不是方舟推理 API Key；必须单独保存并最小授权。
- Awaken 当前：三个 provider 均未接入高权限管理查询；当前只有推理响应 token usage，不能显示成套餐余额。用量页按 provider 分别说明推理 Key 与云账号 AK/SK 的边界：豆包按量入口直达 `GetInferenceUsage`，Agent Plan 入口直达 `GetAFPUsage`，Coding Plan 入口直达官方套餐说明；在独立只读管理凭据链路完成前不自动读取这些接口。

- 按量 API 使用 per-request token usage 与方舟账单/价格；Coding/Agent Plan 按套餐额度、模型系数、周期和席位规则消费。
- 套餐 token 不按按量单价计算 `calculated_cost_usd`。
- 限流需区分按量 endpoint、推理接入点、Coding Plan、Agent Plan 和媒体任务；媒体 POST 的 unknown side effect 禁止盲重试。

## Awaken 落地规则

- 保持 `doubao`、`volcengine`、`volcengine-agent-plan` 三种 identity 隔离。
- Doubao Responses 当前固定 `store:false`，不使用官方示例的 `store:true`/`previous_response_id` 作为 thread authority。stateless 历史中的 message 显式带 `type=message`；已完成 assistant output message 与 `function_call` 必须带 `status=completed`，user input 与 `function_call_output` 不伪造状态。火山 Responses 会严格拒绝缺少该状态的第二轮 assistant 历史。
- 当前真实 Desktop 已验证豆包 Responses 的第二轮重放、`tool_find`/`calculator` 工具回路、标题、Memory recall、Subagent、跨 DeepSeek Responses 切换返回，以及完整 Core 重启恢复；正式数值与边界以 `docs/05_模型与供应商配置/模型配置与调用/实现方案.md` 为准。
- `ep-*`、豆包精确 Model ID 与托管第三方日期 Model ID 必须保留 transport selector 差异，不能用展示名或计价页短名替代。
- Agent Plan 媒体模型不进入 Composer 模型选择器；主模型 capability 与生成工具 capability 分开。
