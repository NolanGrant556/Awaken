# 主题选择方案

## 范围

主题选择属于 Awaken Desktop 的全局外观偏好，入口放在头像/余额弹出的 Settings surface 内，与模型配置并列为设置分区。

本轮支持三个主题偏好：

- 跟随系统：根据 macOS / Windows 的系统外观自动选择浅色或黑色；
- 浅色：当前 Awaken 既有主题，作为默认值；
- 黑色：基于设计系统 `--aw-*` token 的深色变量覆盖。

## 存储契约

主题偏好写入 Electron `userData/config/desktop-preferences.json`，由主进程负责读写，renderer 通过 preload bridge 调用。

renderer 同步维护 `localStorage` 镜像，用于启动时尽早给 `document.documentElement` 设置实际生效的 `data-aw-theme`，减少重启后的主题闪烁；主进程偏好仍是最终来源。

偏好值允许为 `system`、`light`、`dark`。`system` 是存储偏好，不直接作为 CSS 主题值；主进程通过 Electron `nativeTheme` 计算窗口背景，renderer 通过 `prefers-color-scheme` 计算实际生效主题。

## 样式契约

主题切换通过 `html[data-aw-theme="light" | "dark"]` 驱动。浅色主题不额外覆盖 token，保持现状；黑色主题优先在 `@awaken/design-system/tokens/tokens.css` 中覆盖语义 token，再用 Desktop renderer 样式补少量场景级硬编码色。`html[data-aw-theme-preference]` 可记录当前偏好，但不能代替实际生效主题。

不要在业务组件里按主题分支渲染不同结构；需要新增颜色时优先补充或复用语义 token。

品牌 wordmark 使用 `--aw-brand-wordmark-filter` 做主题化处理，黑色主题下应呈现白色字标。工作台顶部 chrome 使用 `--aw-surface-chrome`，黑色主题下必须与主工作区背景保持一致，避免出现一条更浅的横带。

底部 dock composer 不再使用大面积渐变遮罩或 `backdrop-filter` 覆盖历史内容。运行态中间区依靠 `RunStage` 的真实底部留白让输出自然停在 composer 上方，composer 本体通过 `--aw-composer-surface`、`--aw-composer-border`、`--aw-composer-shadow`、`--aw-composer-shadow-focus` 呈现层级。允许使用随 composer 宽度收缩的局部 `--aw-composer-halo` 渐变，让输入框边缘自然羽化；禁止重新引入全宽白色、灰色或黑灰透明渐变遮罩，否则会在主题切换和滚动内容下暴露矩形雾化区域。

## 验收

- Settings 中可以在“外观”页切换跟随系统/浅色/黑色；
- 切换后当前窗口即时生效；
- 关闭并重新打开 Awaken Desktop 后仍保持上次选择；
- 选择跟随系统后，macOS / Windows 系统外观变化时 Awaken 当前窗口跟随切换；
- 浅色主题视觉与本轮改动前一致；
- 黑色主题下主工作台、设置弹窗、余额弹层、composer 和常用按钮不出现大块白底或低对比文字；
- 黑色主题下 composer 附件删除按钮呈现白色底、黑色叉，能从深色附件卡片上清晰分离；
- 黑色主题下欢迎区 Awaken 字标为白色，顶部 chrome 不比主工作区更浅。
- 黑色主题下 center / dock composer 周围只允许局部羽化光晕，不出现白色或灰白色矩形渐变块。
- 浅色和黑色主题下底部 dock composer 可以有局部羽化渐变，但上方不出现全宽矩形雾化区域，历史内容依靠真实留白停在 composer 上方。
