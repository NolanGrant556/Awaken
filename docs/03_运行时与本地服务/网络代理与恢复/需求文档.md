# 网络代理与恢复 · 需求文档

Awaken 读取系统和继承的代理设置，识别失效代理并按执行环境同步。模型、后台网页取材、MCP 和外部 CLI 的恢复范围分别说明。

代码、接口和验证方法见[实现方案](实现方案.md)。

## 当前支持

Desktop Main 通过 Electron `session.resolveProxy` 分别解析 HTTP 与 HTTPS 的系统路由，但不再做 3 秒高频轮询。当前采用事件、操作边界和慢速兜底组成的混合机制：

1. macOS 由 Main 启动系统 `scutil` 订阅 `SCDynamicStore` 的 Global/Service `Proxies` 键；
2. Windows 由随 Desktop 打包的小型 `awaken-network-watch.exe` 使用 `RegNotifyChangeKeyValue` 监听当前用户、本机和 policy 的 Internet Settings；辅助进程只输出变化信号，不输出代理值；
3. Desktop 从休眠恢复、解锁或在 macOS 重新 activate 时触发一次校准；
4. 模型 run、模型/搜索连接测试、MCP 配置/启用/连接及 CLI 下载、状态、配置和授权命令在真正发起外部网络操作前调用 `forceReloadProxyConfig + resolveProxy`；500 ms 内的同一批操作合并为一次；
5. 原生观察器丢失信号或退出时，每 60 秒的 watchdog 仍会校准一次，观察器自身以有界延迟重启。

该入口在 macOS 使用系统网络设置，在 Windows 使用 Electron/Chromium 当前会话采用的系统代理设置；Renderer 不读取代理配置，也不持有 Core 控制地址或 token。稳定空闲时 watchdog 只产生每分钟两次本地 Chromium route 解析；只有存在 loopback 代理候选时才附加有界 TCP 探测。snapshot 语义没变时不热同步 Core，也不刷新 CLI readiness。

Main 同时保留启动时继承的 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 及其小写形式。默认策略为 `auto`：

1. `NO_PROXY` 命中以及 `localhost`、`127.0.0.1`、`::1` 始终直连；
2. 优先使用有效的继承环境代理；
3. 若该环境代理指向 loopback，连接前用 250 ms TCP 探测其监听器；监听器不存在时跳过这条陈旧代理，继续使用系统代理，系统路由允许直连时最终直连；
4. loopback 监听器恢复后自动重新采用该代理；
5. 非 loopback 环境代理不做静默直连降级，避免绕过企业代理或泄露原本要求经代理发送的流量。

可通过启动环境 `AWAKEN_PROXY_POLICY=direct|proxy|auto` 覆盖策略。`direct` 忽略代理，`proxy` 在没有可用代理时 fail closed，`auto` 是产品默认值。当前没有设置页开关；该变量是部署/诊断入口，不是每个模型或 Connector 的独立选项。

后台网页和 JSON 取材使用同一代理路由，逐跳重新选择路由并检查目标地址。具体限制见 [工具发现与执行](../../04_工具权限与审批/工具发现与执行/需求文档.md)。

## 必须保持的规则与当前缺口

- 代理判断与 Core 同步属于 Electron Main/Core，不得下放 Renderer，也不得由模型提交代理 URL；
- snapshot/control/log 不能包含代理凭据、provider key、CLI 输出、device code 或 token；
- loopback Core、MCP 本地 endpoint 与本地回调必须进入 bypass，不能被送到外部代理；
- system route 解析失败时，首次启动以可恢复的 direct snapshot 继续，后续刷新保留上一份有效 snapshot 并记录去敏 warning；
- 原生观察器不是唯一正确性来源；它启动失败时，操作前校准与 60 秒 watchdog 仍保留无感恢复路径；
- 当前 system snapshot 以两个固定 HTTP/HTTPS probe URL 解析 Chromium 指令。静态系统代理和常见自动代理配置可用，但按目标域名返回不同结果的复杂 PAC 尚未形成逐请求等价保证；
- 已开始输出、可能产生费用或外部副作用的模型/MCP/CLI 操作不因网络切换盲目重放；
- 本域只拥有 Desktop/Core 的系统代理 route 与新连接选择。主模型已经失败后的等待网络、流重试和 live `AWAKEN_PROVIDER_RECONNECT` 由 [02 运行终止与失败编排](../../02_主智能体闭环/对话运行与恢复/实现方案.md) 拥有，不能把 route 热切换写成一次 provider reconnect；
- Linux 的 Core 环境代理逻辑可复用，但 Linux Desktop 系统代理发现和发布验收不属于当前支持声明；
- macOS 与 Windows 的自动化合同已覆盖，两个平台的真实系统代理/PAC、企业证书和外部 provider 仍必须分别实机验收，不能互相推断。
