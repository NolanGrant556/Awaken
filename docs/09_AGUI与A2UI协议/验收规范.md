# 验收规范

## 1. 自动化

- Go `Event` JSON tags 与 mapper/projector golden；
- live/replay 对相同 SemanticRecord 生成同 frames/seq；
- tool snapshot/provider/readiness/dependency/side-effect 字段端到端；
- 五种 Skill event、activation/resource durable projection；
- Memory recall/mutation 的 live/replay 同类型、同 identity 且 `memories[]` 不含主题正文；Dream terminal 只通过 typed Desktop bridge/task list形成 Renderer 本地投影，不冒充 Core SSE frame；
- 消息工具不会产生 review requested/resolved event 或专用字段；
- unknown event 保留 raw type，不让 consumer 崩溃；
- MCP artifact 原始 base64 不进入 Outcome/journal/AG-UI；成功只投影 host-committed ArtifactDescriptor/change/receipt，hash/size/path/commit 失败无伪 artifact，且不得从基础容器验证推断视觉/语义 verified；
- Go/TS field parity，特别是 auth URL。
- Subagent lifecycle/progress 的工具数、provider-reported input/output/total tokens 与 started/finished 时间在 live/replay 同 frame，重复 tool-call/model-request identity 不膨胀累计值，Renderer 不自行扫描 child 文案补算。
- `AWAKEN_CONTEXT_SNAPSHOT` 的 typed contributions、分类求和/旧记录降级，以及 `AWAKEN_MODEL_USAGE` 的 `sentEstimatedInputTokens`、nullable raw/normalized usage、retry/fallback/pricing 字段在 live/replay 保持一致；
- `model_request`、`context_epoch`、`provider_opaque_state` 不产生 wire frame，prompt、路径、cache key 和 reasoning 不泄漏；

```bash
go test -count=1 ./src/protocol/agui ./src/agentcore ./src/runtime
npm --prefix apps/desktop test -- --run src/renderer/runtime/reducer.test.ts src/renderer/run-narrative/projector.test.ts
npm --prefix apps/desktop run typecheck
```

具体 Desktop test runner 参数以 package scripts 为准；若命令不匹配，记录实际替代命令。

## 2. Desktop 验收

真实 Awaken Desktop 中验证 live、断线重连、切换线程、重开、Skill inline/fork、provider failure、消息工具直接执行、artifact、Memory receipt 与 Dream task 重放的顺序/字段一致。检查网络帧、typed bridge 与 reducer/projector 状态，不能只凭最终文案；Dream 本地 receipt 不应出现在 Core SSE frame 中。
