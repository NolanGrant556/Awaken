# 零审批自动执行策略 Spec

> 来源：`docs/04_工具权限与审批/当前规范/零审批自动执行策略与落地路线.md`
> 本 spec 把该策略文档转成可实施的需求与验收契约。

## Why

当前 Awaken 的工具执行仍把 `ask -> 用户批准 -> 继续` 当作默认主路径：`PermissionBehavior` 显式包含 `ask`，`apply_patch` 在 headless 下被 `deniesStaticAllowInHeadless` 硬编码拒绝，删除走 `os.Remove` 永久删除，shell 用裸 `exec.CommandContext` 直接执行宿主机命令，且没有 `transform`、回收站、沙箱 adapter、subagent 继承或 `ExecutionProfile`。结果是：要么用户被频繁打断，要么安全只能靠 prompt 与 UI 弹窗兜底。

本 spec 的目标是把安全内置进 runtime，让 Agent 在默认零审批自动执行的前提下，仍被路径校验、回收站、敏感路径拒绝、profile 分级和多代理继承严格约束。

## What Changes

- **新增** `ExecutionIntent` / `ExecutionDecision` / `ExecutionProfile` 三层统一抽象，所有执行型工具走统一决策与执行器。
- **新增** `transform` 决策动作（在 `allow` / `deny` 之外），用于把高风险请求改写为更安全形式后再执行。
- **新增** 文件链（file_chain）作为日常文件增删改移动的主路径，默认自动执行，严格受 `workspace_root` / `writable_roots` 约束。
- **新增** 回收站删除语义：`TrashPath(path) error` 统一接口，删除默认进回收站，禁止任意工具直接 `os.Remove`。
- **新增** 敏感路径默认拒绝规则（`.git/`、`.env`、密钥/证书/凭据、Agent 元数据目录、runtime 本地配置目录）。
- **新增** shell 三层分级：`inspect_read_only` / `workspace_mutation` / `open_world_system`，并增加 shell→文件链 transform。
- **新增** 多代理继承契约：普通 subagent 继承父边界不可扩权；guardian/review agent 固定只读。
- **新增** 统一执行器层：`FileChainExecutor` / `ShellExecutor` / `McpExecutor` / `GuardianExecutor`。
- **新增** 平台 adapter 抽象：`SandboxAdapterMac/Windows`、`TrashAdapterMac/Windows`，同 contract 不同 backend。
- **新增** 统一观测层：执行工具、命中 profile、transform/deny、回收站删除、subagent 继承均可观测。
- **修改** `PermissionBehavior` 的 `ask` 不再是产品主路径，仅作为兼容保留。
- **修改** `AutoToolPolicy` 扩展 `transform` 动作与 `UpdatedInput` 改写链路。
- **修改** `apply_patch` 删除语义从 `os.Remove` 改为 `TrashPath`。
- **修改** `shell` 工具从裸宿主机执行改为经过 `ShellExecutor` + 平台 sandbox adapter。
- **移除** 「审批中心」作为主产品路径的定位。
- **移除** `apply_patch` 永久删除语义。
- **移除** shell 中硬编码工具名匹配作为主要安全手段。

## ADDED Requirements

### Requirement: 零审批执行决策模型

系统 SHALL 在工具执行前统一计算 `ExecutionDecision`，决策动作仅允许 `allow` / `deny` / `transform` 三种。`transform` 表示把高风险请求改写为更安全形式后再执行（例如 shell 文件写入→`apply_patch`、永久删除→移到回收站、越界写入→拒绝）。

主路径 SHALL NOT 把 `ask -> 用户批准 -> 继续` 作为默认交互。`PermissionBehavior.ask` 仅作为兼容保留，不再驱动主产品流程。

#### Scenario: 默认自动执行文件链
- **WHEN** Agent 调用文件链工具在 `workspace_root` / `writable_roots` 内执行非敏感路径写入
- **THEN** 系统返回 `allow` 并直接执行，不弹出任何审批 UI

#### Scenario: 越界写入被拒绝
- **WHEN** Agent 调用文件链工具尝试写入 `workspace_root` / `writable_roots` 之外的路径
- **THEN** 系统返回 `deny` 并返回结构化 `tool_result`，说明越界原因

#### Scenario: 永久删除被 transform 为回收站
- **WHEN** Agent 请求删除文件
- **THEN** 系统返回 `transform`，把删除改写为「移到回收站」后执行，不进行永久删除

### Requirement: ExecutionIntent 统一意图层

每次工具调用在真正执行前 SHALL 先被转换成统一的 `ExecutionIntent`，至少包含：`tool_name`、`tool_kind`、`requested_action`、`paths`、`network_scope`、`workspace_root`、`writable_roots`、`subagent_origin`。

`tool_kind` 至少分为：`file_chain` / `shell_command` / `mcp_app` / `review_agent`。

### Requirement: ExecutionProfile 统一执行 profile 层

所有工具执行 SHALL 落到共享的 `ExecutionProfile`，至少包含：`approval_policy`、`permission_profile`、`sandbox_policy`、`sandbox_permissions`、`network_policy`、`env_policy`、`visibility_policy`。

系统 SHALL 提供以下内建 profile：`guardian_read_only` / `workspace_read_only` / `workspace_write` / `open_world_restricted` / `danger_full_access`。

### Requirement: 统一执行器层

运行时 SHALL NOT 让工具直接碰宿主机，而是统一经过执行器：`FileChainExecutor` / `ShellExecutor` / `McpExecutor` / `GuardianExecutor`。每个执行器负责把自己负责的 `tool_kind` 落地到具体后端（文件系统、shell、MCP、guardian 通道）。

### Requirement: 文件链自动执行与边界约束

文件链（新建、修改、移动、删除文件）SHALL 默认自动执行，但 MUST 受以下约束：

- 只能在 `workspace_root` / `writable_roots` 内执行
- 强制经过 symlink 逃逸检查
- 敏感路径默认拒绝
- 删除默认进入回收站
- 不依赖 shell

#### Scenario: symlink 逃逸被拦截
- **WHEN** Agent 通过 symlink 写入到 workspace 之外的路径
- **THEN** 系统拒绝写入并返回结构化拒绝结果

### Requirement: 默认可恢复的删除语义

系统 SHALL 提供统一接口 `TrashPath(path string) error`。文件链中的删除与覆盖前删除 SHALL 一律使用「移到回收站」。任意工具 SHALL NOT 各自直接 `os.Remove`。

#### Scenario: 删除进回收站
- **WHEN** Agent 删除 workspace 内文件
- **THEN** 文件被移到回收站，事件流输出「已进入回收站」提示，不进行永久删除

### Requirement: 敏感路径保护

系统 SHALL 默认拒绝写入以下敏感路径：`.git/`、`.env`、密钥/证书/凭据文件、Agent 自身元数据目录、Desktop/runtime 的本地配置目录。该规则 SHALL 在所有 subagent 与所有 profile 下生效，不可被普通 subagent 绕过。

### Requirement: shell 三层分级

shell SHALL 至少分为三层：`inspect_read_only` / `workspace_mutation` / `open_world_system`。

- `inspect_read_only` 可在受控条件下自动执行
- 能落到文件链的写入请求 SHALL 优先 transform 到文件链
- `workspace_mutation` 不是日常主路径
- `open_world_system` 默认 MUST 受更强 profile 约束

### Requirement: MCP/app 风险注解

MCP / app 工具 MUST 有显式风险注解，至少包含：`read_only` / `destructive` / `open_world` / `requires_auth`。缺失风险注解时，系统 SHALL 默认按高风险处理，而不是默认放行。

### Requirement: 多代理继承契约

普通 subagent SHALL 默认继承父代理的 `workspace_root`、`writable_roots`、`permission_profile`、`sandbox_policy`、`network_policy`，且 SHALL NOT 自动扩权。

guardian / review agent SHALL NOT 继承父代理的高权限 profile，而是强制收紧到：`approval_policy = never`、`permission_profile = read_only`、`network_policy = restricted`。guardian 只做只读复核，不触发新的开放式执行链。

任一子代理 SHALL NOT 绕过敏感路径保护与回收站删除语义。

#### Scenario: 普通 subagent 不能扩权
- **WHEN** 父代理 profile 为 `workspace_write`，子代理尝试执行 `open_world_system` shell
- **THEN** 系统拒绝执行并返回结构化拒绝结果

#### Scenario: guardian 始终只读
- **WHEN** guardian agent 尝试调用任何写入工具
- **THEN** 系统拒绝执行

### Requirement: 共享权限模型与平台执行 adapter

Mac 与 Windows SHALL 共享同一套上层权限契约（`ExecutionIntent` / `ExecutionDecision` / `ExecutionProfile` / 文件链路径校验 / 敏感路径规则 / subagent 继承规则 / guardian 收紧规则 / 回收站抽象接口）。

平台差异 SHALL 仅体现在 adapter 实现层：`SandboxAdapterMac` / `SandboxAdapterWindows` / `TrashAdapterMac` / `TrashAdapterWindows`。系统 SHALL NOT 维护长期 mac/windows 平台主线分支。

某平台缺失可信 shell 隔离时，系统 SHALL 采取降级（文件链保持完整强约束、shell 收紧为更保守策略、无法可信隔离的能力直接 deny），而 SHALL NOT 静默裸奔。

### Requirement: 统一观测层

系统 SHALL 始终可观测以下信息：执行了哪个工具、命中了哪个 profile、哪个请求被 transform、哪个请求被 deny、删除是否进入回收站、subagent 继承了哪些边界。

### Requirement: 用户可见性

Desktop SHALL 至少展示：自动执行的工具调用、被系统拒绝的工具调用、transform 后的实际执行方式、文件改动列表、删除已进入回收站的提示、当前运行使用的 profile 摘要。UI SHALL 强调「系统已内置保护」，而不是「请你决定要不要继续」。

#### Scenario: 用户看到 transform 结果
- **WHEN** 系统把 shell 文件写入 transform 到 `apply_patch`
- **THEN** Desktop 展示原始请求、transform 后的执行方式与最终结果

### Requirement: 用户可随时停止 run

系统 SHALL 保留用户随时停止 run 的能力。停止 SHALL 通过 runtime 取消机制传播到正在执行的工具调用。

## MODIFIED Requirements

### Requirement: 工具权限决策

现有 `PermissionBehavior`（`allow`/`ask`/`deny`）与 `AutoToolPolicy`（`allow`/`deny`/`abort`）双层模型修改为：以 `ExecutionDecision`（`allow`/`deny`/`transform`）为统一决策出口，`PermissionBehavior` 退化为底层静态注解输入。`AutoToolPolicy` 扩展 `transform` 动作与 `UpdatedInput` 改写链路，`abort` 保留用于上下文取消。

`UseApprovalForAsk` 兼容标志保留，但 SHALL NOT 出现在主产品路径中。

### Requirement: apply_patch 删除语义

`apply_patch` 的删除路径从 `os.Remove(path)` 修改为 `TrashPath(path)`。`apply_patch` 纳入 `FileChainExecutor`，删除前 MUST 经过敏感路径检查与 symlink 逃逸检查。

### Requirement: shell 工具执行后端

`shell` 工具从裸 `exec.CommandContext("/bin/sh", "-c", ...)` 修改为经过 `ShellExecutor` + 平台 `SandboxAdapter`。硬编码工具名匹配（`isOpenWorldTool` 中的 `shell`/`web_search`、`safeReadOnlyCommandPaths`）SHALL 被三层分级与 profile 决策取代，不再作为主要安全手段。

## REMOVED Requirements

### Requirement: 审批中心作为主产品路径

**Reason**：零审批是产品目标，主路径不再依赖中途审批。继续把审批 UI 作为主路径与「默认自动执行 + 内置安全」的产品方向冲突。

**Migration**：`PermissionBehavior.ask` 与 `ApprovalRequested`/`ApprovalResolved` 事件保留为兼容通道，但不在主产品流程中触发；`UseApprovalForAsk` 默认关闭。

### Requirement: apply_patch 永久删除语义

**Reason**：本地桌面产品的默认预期是可恢复，永久删除与「默认可恢复」原则冲突。

**Migration**：所有删除统一走 `TrashPath`；用户明确要求永久删除时也不进入主产品默认路径。

### Requirement: shell 硬编码工具名匹配作为主要安全手段

**Reason**：硬编码工具名匹配（`shell`/`web_search` 等）无法承载分级与 transform，且与统一 profile 模型冲突。

**Migration**：由 shell 三层分级 + `ExecutionProfile` + `ShellExecutor` 取代。
