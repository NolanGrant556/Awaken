# 输入框斜杠菜单

## 范围

Composer Slash Palette 是 `ComposerBar` 内的通用输入增强能力，不是 Skill 专属入口。用户在 composer textarea 中输入 `/` 后，Desktop 通过统一 palette 展示可插入动作；第一期只接入 Skill provider，后续文件、工作目录、Prompt、Workflow、Connector 等 provider 应复用同一套 action、token 与提交结构。

该能力属于中间交互区域，但不改变 Workbench 主契约：

- `RunStage` 仍是唯一滚动、定位、overlay、composer 容器。
- palette 与 chip 都渲染在 `ComposerBar` 内，随 center / dock 两种 composer 形态复用。
- `ExecutionFeed` 只承载 narrative / turn，不放置 palette、chip 或业务控制按钮。
- 仍只承认 `variant="center"` 与 `variant="dock"`，Slash Palette 不是第三种 composer 形态。

## 通用抽象

`SlashAction` 表示 palette 中的一行候选项，字段包括 `id`、`type`、`label`、`description`、`keywords`、`disabled`、`disabledReason`、`preview` 与 `payload`。`type` 预留 `skill`、`file`、`workflow`、`prompt`、`connector`。

`SlashProvider` 表示一个候选项来源，接收当前 run 的 `workspaceRootForRun`，返回一组 `SlashAction`。Desktop App 只维护 provider 列表，并通过统一聚合函数生成 palette actions；palette 本身不关心 action 来自 Skill、File 还是 Workflow。

`ComposerToken` 表示用户选择后留在 composer 输入区里的结构化 chip，字段包括 `id`、`type`、`label` 与 `payload`。token 不写入 textarea 文本本身，提交 run 时通过 `composerTokens` 结构化字段传给 runtime。

如果某个 provider 的 action 选择后需要插入 chip，应在 action 上提供对应的 `composerToken`。第一期 Skill provider 会生成 Skill token；后续 File、Prompt、Workflow、Connector provider 可以定义自己的 token payload，而不需要改 palette、hover preview、chip 渲染或键盘删除逻辑。

第一期 Skill token payload 至少包含：

```ts
{
  skillId: string;
  sourceOrigin: "project" | "user";
  skillFilePath: string;
  rootDir?: string;
}
```

## Provider 接入规则

第一期只注册 `SkillSlashProvider`。后续新增 provider 时，应遵守：

- provider 只负责取数、过滤可见来源、构造 `SlashAction`、检索用 `keywords` 和可选 `composerToken`。
- palette 只负责展示、active 项、hover preview、键盘导航和选择事件。
- token chip 与用户消息气泡按 `ComposerToken.type` 做通用渲染；除非某类型需要新的视觉语义，否则不要在 ComposerBar 内写死具体业务类型。
- runtime 只消费它认识的 token 类型；新增 token 类型必须同步补充前后端 wire contract、校验和提交测试。

## Skill Provider 规则

Skill provider 使用当前 run 的 `workspaceRootForRun` 调用 `listSkills(workspaceRootForRun)`。

展示规则：

- 只展示 `sourceOrigin: "project"` 与 `sourceOrigin: "user"`。
- 不展示 MCP、bundled、internal 来源 Skill。
- `state: "shadowed"` 默认隐藏。
- `state: "available"` 可选择。
- 其他状态以灰态展示，不可选择，并使用 `unavailableReason` 作为禁用原因。

过滤规则：

- 输入 `/` 展示全部可见 action。
- 输入 `/xxx` 时按 action 的 `label`、`description`、`preview.path` 与 provider 提供的 `keywords` 过滤。Skill provider 会把 `whenToUse`、`skillFilePath`、Skill id/name/displayName 等字段放入 `keywords`。
- 在自然语言后输入空格加 slash 也会进入 slash trigger，例如 `你好 /` 展示全部 action，`你好 /doc` 按 `doc` 过滤。
- slash trigger 只识别输入末尾由开头或空白引出的 `/query`。如果 slash 后面已经继续输入普通文本，例如 `你好 /doc 后续文字`，则退出当前 slash trigger。
- 选择 action 或按 `Escape` 时只清除末尾 `/query` 片段，保留 slash 前面的自然语言文本。

## 视觉与交互

菜单行固定为紧凑单行：`icon + label`，超出使用 `...`，不换行。行内不展示 description，避免占用输入区空间。

鼠标 hover 某个 action 时，在菜单旁展示黑底白字 preview。preview 可包含较长 description 摘要与路径；description 使用行数截断，path 使用单行 `...`，不在 preview 内滚动。键盘移动 active 项不主动展示 preview。第一期 Skill preview 的 path 对应 `skillFilePath`。

选择带 `composerToken` 的 action 后，在 composer 输入区内生成 Codex 风格的轻量 token：透明背景、蓝色小图标加蓝色文字，不使用黑底胶囊。token 与自然语言输入位于同一条输入流，不额外占据独立一行。实现上，slash trigger 前的自然语言文本作为 inline 文本段渲染在 token 前，textarea 只承载 token 后继续输入的文本；提交时再把 inline 文本段与 textarea 文本合并为本次 prompt。token 的位置跟随触发 slash 的位置：如果从 `/doc` 选择，token 在后续输入文本前；如果从 `你好 /doc` 选择，token 在 `你好` 后面。token 文案显示名称，字号和行高与输入文字保持一致，超出使用 `...`。token 不展示鼠标删除按钮，删除通过键盘完成。

提交后，用户消息气泡也必须展示本次选择的 token，作为用户输入的一部分可见呈现，并且要保留选择时的 inline 顺序：在文本后输入 `/` 选择 action，气泡中也应显示为 `文本 + token`，不能默认把 token 前置。消息气泡里的 token 使用同样的轻量蓝色样式、单行省略，并保留 provider 提供的 title/path 作为 hover title；正文文本不包含 skill 路径，runtime 仍从结构化 `composerTokens` 获取能力信息。

键盘行为：

- `Escape` 关闭当前 slash trigger。
- `ArrowDown` / `ArrowUp` 在可选 action 中移动。
- `Enter` / `Tab` 选择当前 active action。
- 光标在 textarea 开头按 `Backspace` 删除相邻 chip；如果该 chip 前有关联的 inline 文本段，删除 chip 后该文本段回到 textarea 中，避免丢失用户已经输入的自然语言。
- 普通文本不触发 palette。

## 提交与运行时

前端提交 `composerTokens`，不把 Skill 路径塞进用户文本。无 token 的旧提交保持兼容。

后端在创建 run 前校验 Skill token：

- `skillId` 必须存在于当前 `workspaceRoot` 同步后的 SkillRegistry。
- Skill 来源必须是 `project` 或 `user`。
- Skill 状态必须是 `available`。
- 如果 token payload 带有 `sourceOrigin` 或 `skillFilePath`，必须与 registry 中的当前 Skill 定义一致。

校验通过后，runtime 从 Skill token 派生隐藏指令，要求本次 run 使用对应 `skill__<id>` 工具，并保留用户输入文本本身的语义。token-only 提交允许启动 run，线程标题优先使用 token label。

## 验收

单元测试至少覆盖：

- `/` 与 `/xxx` 触发和过滤。
- `前文 + 空格 + /query` 能触发并过滤，选择或取消后只移除末尾 `/query`。
- Skill provider 的 project/user 展示、MCP 隐藏、shadowed 隐藏、unavailable 灰态不可选。
- 选择 Skill 后生成正确 `ComposerToken`。
- Composer 中能渲染 palette、preview 与可删除 chip。
- 用户消息气泡能展示已选择的 Skill chip。
- `composerTokens` 能通过 start-run wire request 提交。
- 后端拒绝 unavailable、路径不匹配或当前 registry 不存在的 Skill。

真实 Desktop 验收按根 `README.md` 的正式入口打开 Awaken Desktop：

- 空态 center composer 输入 `/`，检查菜单、hover preview、选择 chip。
- 运行态 dock composer 重复验证。
- 选择项目 Skill 后提交一次真实任务，确认本次 run 可使用对应 `skill__<id>` 工具。
