# 运行终止与失败编排

## 1. 终态

run terminal 耐久事实可记录 finished、error、cancelled 或 recovery-only interrupted；其中 interrupted 在 wire/公开 run view 映射为 error，不扩展公开状态枚举。`needs_auth`、`needs_runtime`、`unsupported`、denied、review_required 是工具 Outcome/next action，不是通用 run approval 状态；Agent 可据此恢复、询问或结束。

取消传播到 model call、tool process、fork child 和等待中的专用 gate。已开始副作用在取消后必须根据 transport/process/side-effect state 标 none/partial/unknown，不能一律写 cancelled=未执行。

## 2. 失败监督

监督器使用 canonical Outcome：

- validation/policy/not_started：修正输入或换已支持路径；
- needs_auth/runtime：呈现 next action，完成外部准备后新调用；
- unsupported：换 provider/capability 或明确报告缺口；
- retryable transient 且无副作用：有界重试；
- partial/unknown：先检查外部状态并阻止原样重复；
- output schema mismatch/provider contract violation：保留诊断，不生成伪成功。

Shell 失败的 resource revision 由 `command + workdir` 生成不暴露命令文本的稳定摘要，不同恢复命令不共用粗糙 `unknown` 预算。已观测 mutation 成功，或另一个默认 direct Shell 非检查命令成功且返回 unknown side effects 后，旧 Shell 失败记录可清除，使 `pipeline 缺包失败 -> npm install -> 原样重跑 pipeline` 可以针对新环境恢复；副作用已证明为 none 的不相关只读成功不得清除恢复指令。

Skill 激活失败使用 Skill load/invocation error 和 diagnostics；旧的“按工具求交”“平台关键字冲突”“资源预加载缺失”不再是通用门禁。Skill 建议的工具不可用时表现为 provider/tool Outcome。

对 composer 显式 Skill token，失败终态之前已耐久保留完整 `user_message`；多 Skill 激活 records 以单批写入，批次失败时不泄漏部分 `skill_activated`。

## 3. Gate

`ask_user` 等待结构化答案；mass-message review 等待相同 envelope digest 的 approved/rejected。取消或重启不能自动批准。review resolution 未耐久时 transport 不开始。

## 4. 恢复

服务启动扫描未闭合 journal：补 interrupted terminal、为未闭合 tool call 生成 unknown/blocked recovery，不执行外部调用。live/replay projector 产生同一最终顺序。

## 5. 当前缺口

- 外部 provider 已产生副作用后撒谎/断线，Awaken只能检测 unknown/contract violation，不能普遍撤销；
- MCP connected call 的 401 透明 refresh/retry 未完成；
- 跨平台 child-process cancellation 和真实 Desktop 恢复需本轮实机证据。
