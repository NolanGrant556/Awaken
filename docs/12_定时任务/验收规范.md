# 定时任务验收规范

## 1. 当前状态

**实现已落地，真实 Desktop 验收已完成固定提醒主链路，完整门禁尚未完成。** 左侧一级入口、循环/日程任务、10 个内置模板、创建/编辑/启停/删除/立即执行/取消、专属线程、最近 50 条执行历史、Core 调度器与 misfire 恢复、Agent 与固定提醒两类任务均已实现。固定提醒以 `AWAKEN_SCHEDULED_NOTICE` 事件进入专属线程并在 Desktop 运行时触发原生通知。

当前不变量：

- 执行历史/系统通知点击打开 thread 时先退出扩展一级页面，再刷新 thread 权威列表并重放/定位 thread。
- 崩溃恢复中同一到期点的 `scheduled` 与 `misfire` 共享 occurrence 身份 `(task_id, scheduled_for)`，不会创建第二个 execution。
- DELETE 的版本检查、tombstone 写入与 `Idempotency-Key` receipt 在 Repository 的同一 store-lock 事务内完成；重试返回原 204。
- 用户取消在所有 pre-side-effect 边界写入 `cancelled` 终态；shutdown 保留非终态供恢复封口为 `interrupted`。
- 启动 reminder 在 Service/hub 两层均有 best-effort 内存缓冲，降低 Desktop 尚未连接 SSE 时的丢失概率；Core 完全离线或缓冲溢出后仍可能丢失。

**当前不支持（首版明确不包含）**：

- Desktop 完全退出后由操作系统唤醒；
- 秒级 Cron / Quartz 特殊字符 / 自然语言生成表达式；
- 同一任务并发多个 Agent run；
- 用户自定义模板；
- 任意 Connector/channel 作为投递目标；
- 把现有普通线程选为写入目标；
- 对漏掉的多个周期逐条补跑；
- 自动回答 `ask_user` 或自动完成外部授权。

**本轮真实 Desktop 已验证**：

- `DT-SCHED-01`：入口顺序“连接器 → 技能 → 定时任务”、页面入口和列表状态；
- `DT-SCHED-02` 的模板目录部分：循环/日程分类为 4/6，选择模板只打开预填编辑器；
- `DT-SCHED-03` 的固定提醒主链路：模板创建、按分钟触发、执行历史、专属线程跳转及 `AWAKEN_SCHEDULED_NOTICE` 卡片重放；
- `DT-SCHED-04` 的启停与暂停后手动执行：手动执行成功且任务保持暂停；
- `DT-SCHED-05` 的单次合并补跑：完整关闭并跨过一个到期点后重开，只出现一条 `misfire`；
- `DT-SCHED-07` 的进程边界：正式关闭入口停止 Desktop 与 Core，重开后按 misfire 恢复。

**仍待真实 Desktop 补齐**：Agent 模板的完整模型执行、运行中冲突/取消、原生通知点击、强杀后的 `interrupted`、项目/profile/`ask_user` 失败矩阵，以及窄窗口/深色主题/键盘可访问性。门禁补齐前不能将整个功能域标为“已验收通过”。

## 2. 自动化

### 2.1 Schema、Cron 与日程

必须覆盖：

- 五段 Cron 接受/拒绝、3/4/6 段拒绝、空表达式拒绝；
- `0/7` 周日与 `sun` 规范化，列表、范围、step；
- 每小时、每天、每周、自定义表达式；
- IANA timezone 有效/无效；
- DST 跳时与重复时间；
- 不重复、每 N 天、never/until/count；
- until 晚于 run_at、count/range 上限；
- 所有 next occurrence 都严格晚于基准或符合明确 misfire 计算；
- fake clock/timer，无真实分钟等待。

### 2.2 Repository 与恢复

必须覆盖：

- create/update/pause/resume/delete 的 version CAS；
- 同 idempotency key 重试只产生一个 task/execution；
- `state.json` 缺失/损坏从 journal 重建；
- journal 尾部半条截断、中段损坏 fail closed；
- 文件/目录权限、atomic replace、跨进程锁；
- prompt、API key 和 Authorization 不进入日志/错误/snapshot；
- orphan execution 从 queued/running 恢复为 interrupted；
- tombstone 后列表、get 和 scheduler 均不可见；
- 最近 50 条执行历史顺序和边界。

### 2.3 Scheduler

必须覆盖：

- start/stop 幂等；
- 单条坏定义不阻止 Core 和其他任务启动，坏任务变 invalid；
- pause 后没有 scheduled execution，resume 重新计算 next run；
- 手动执行暂停任务成功且不消费 count；
- 同一 occurrence 去重；
- 单任务防重入与全局 Agent 并发上限；
- 多个漏点合并一次；
- 宽限内 misfire 执行，宽限外 skipped；
- 一次性任务 success/skipped 后 completed；
- repeat count 对 scheduled/misfire 成败/跳过计数，manual 不计数；
- shutdown 不接收新 occurrence，活动 execution 可恢复封口。

### 2.4 Agent、提醒与边界

必须覆盖：

- 触发时按 project ID 重新解析 primary/all folders；
- 零文件夹项目使用 session workspace；
- removed/project operation/path missing 均 fail closed；
- 默认 profile 每次重新解析；显式 profile 缺失不 fallback；
- task definition、journal、wire 不出现 API key；
- Agent execution 进入稳定 dedicated thread，下一次继续同一 thread；
- 不同 task 使用不同 thread；
- thread busy 不写入其他 thread；
- reminder 不调用模型，写 scheduled notice 和 terminal；
- ask_user、外部授权、ACP permission 立即失败为 interaction required；
- timeout 触发 CancelRun 并形成唯一 terminal；
- Agent artifact 只存在正常 transcript，execution record 只引用 run/thread；
- 删除 task 不删除 thread/artifact。

### 2.5 HTTP、IPC 与 UI

必须覆盖：

- 所有 route 的 201/202/404/409/422/500 映射；
- snake_case/camelCase typed normalization；
- preload 只暴露窄方法，不暴露 Core URL 或任意 fetch；
- 主窗口来源校验；
- Renderer 乐观启停失败回滚；
- 页面卸载/切换不取消后台 execution；
- live reminder 只发一次系统通知，replay 不发通知；
- 通知点击聚焦并打开正确 thread；
- 模板目录恰好 10 项、ID 唯一、分类 4/6；
- 每个模板字段完整、时区正确、动态时间严格在未来；
- 模板选择不创建任务，只有编辑器保存才调用 create；
- 模板字段可编辑，保存 template origin；
- 导航顺序精确为连接器、技能、定时任务；
- 空、加载、失败、禁用、running、completed、invalid、历史空态均可观察。

建议聚焦命令在实现时补入真实 package 名；至少应包含：

```bash
go test -count=1 ./src/scheduledtask ./src/runtime ./src/server ./src/protocol/agui ./cmd/...
npm test --workspace apps/desktop -- --run
npm test --workspace "Awaken Design System" -- --run
npm run typecheck
npm run build
git diff --check
```

命令必须以实际 `package.json` scripts 为准；不存在的脚本不能留在完成声明里。

## 3. 真实 Desktop 验收

必须按根 README 正式入口打开真实 `Awaken Dev`，使用专用测试项目和可识别名称，留下截图/录屏或 manifest。

### DT-SCHED-01 导航与空状态

1. 确认左侧一级导航顺序为“连接器 → 技能 → 定时任务”。
2. 进入页面，确认空状态同时提供“创建任务”和“从模板创建”。
3. 切换连接器/技能/项目/thread，确认当前 run 和项目选择不被意外清空。

### DT-SCHED-02 从模板创建 Agent 任务

1. 打开模板窗口，切换循环/日程分类。
2. 选择“工作日科技新闻早报”或其他 Agent 模板。
3. 确认只打开预填编辑器、尚未出现在列表。
4. 选择测试项目，把计划改为 1–2 分钟内的未来时间并保存。
5. 确认列表、next run、template origin 和时区。
6. 等待执行，确认专属 thread 出现在正确项目下，正常展示用户 prompt、模型过程、工具和 terminal。
7. 打开执行记录并跳转同一 thread。

### DT-SCHED-03 从模板创建固定提醒

1. 选择“休息提醒”或“生日提醒”。
2. 修改为短期未来时间后保存。
3. 到期只出现 host-owned 定时提醒卡，不出现模型调用或 assistant 冒充文本。
4. Desktop live 时系统通知只出现一次；点击聚焦正确 thread。
5. 重开 thread 后卡片仍在，但不重复系统通知。

### DT-SCHED-04 生命周期

1. 创建、编辑、暂停、恢复。
2. 暂停期间等待一次到期点，确认不执行。
3. 对暂停任务立即执行，确认成功且任务仍暂停。
4. 运行中重复点击立即执行，确认稳定冲突提示。
5. 取消运行，确认 run 和 execution 均为 cancelled。
6. 删除任务，确认列表移除但 thread 与 artifact 保留。

### DT-SCHED-05 重启与 misfire

1. 创建一个 1 分钟循环任务，宽限设为 5 分钟。
2. 在下次到期前完整关闭 Desktop，跨过至少一个到期点后重开。
3. 确认只合并补一次 `misfire`，不按漏掉次数轰炸执行。
4. 改用 0 秒或很短宽限重复，确认只记 skipped。
5. 在 Agent 正在运行时强制结束开发 Desktop/Core，重开后确认 execution 为 interrupted，普通 transcript 恢复且不自动重放副作用。

### DT-SCHED-06 项目、模型与交互失败

1. 创建任务后修改项目主文件夹/文件夹集合，触发后确认使用新 TaskScope。
2. 移除项目，确认任务不在旧路径执行。
3. 禁用显式 profile 或移除 key，确认 `MODEL_PROFILE_UNAVAILABLE` 且不切 provider。
4. 使用必然触发 ask_user 或外部授权的 prompt，确认无人值守 run fail fast，页面给出可恢复提示。

### DT-SCHED-07 退出限制

1. 完全退出 Awaken，不留下 Core。
2. 到达计划时间，确认没有暗中运行或孤儿进程。
3. 重开后按 misfire 配置表现。
4. 页面说明与实际行为一致，没有“关闭后仍在后台执行”的声明。

## 4. 视觉与可访问性

- 页面在正常和窄窗口均无横向溢出；高密度列表不能照搬 Qwenpaw 2,840px 宽表格。
- 模板卡名称、说明、频率和动作层级清晰；10 项可滚动但窗口 header/footer 稳定。
- 编辑器长内容、时区和 Cron 错误就地显示，保存错误不丢表单。
- 开关、按钮、模板卡、dialog、history 均可键盘操作且有准确 aria label。
- 深浅主题、focus ring、success/error/disabled 对比度符合 Design System。
- Gallery 只能证明组件状态；最终产品闭环必须来自真实 Desktop。

## 5. 完成门禁

只有同时满足以下条件，才能把功能标为当前支持：

1. 首版范围的代码、文档、模板和错误恢复全部落地；
2. 当前支持/不支持与后续日历增强没有混写；
3. repository、scheduler、RunService、HTTP、IPC、Renderer 和 Design System ownership 未绕过；
4. 聚焦 Go/TypeScript 测试、typecheck/build 和 `git diff --check` 本次实际通过；
5. DT-SCHED-01～07 在真实 Desktop 本次执行并留证；
6. reminder live/replay、Agent thread、misfire、crash interrupted 和退出限制均与契约一致；
7. 没有凭据、userData、生成物或测试任务污染提交；
8. Windows/Linux 未实机时明确报告，不宣称跨平台全部通过。
