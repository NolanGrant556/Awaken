# 最终交付物卡片：产品与数据契约

## 产品语义

- 用户输入附件区域保持现状，不参与本功能改造。
- 任务终态不再展示全量 `File Changes`；只在最终回答之后展示本次 run 新增或修改且已就绪的用户交付文件。
- 支持 Word、Markdown、Excel、PDF、PowerPoint：`.doc`、`.docx`、`.md`、`.xls`、`.xlsx`、`.csv`、`.tsv`、`.pdf`、`.ppt`、`.pptx`。
- 成功、失败、取消三种终态均可展示已经成功生成的交付物；失败和取消必须附弱提示，不能把可用成果隐藏掉。
- 1–3 个文件全部展示；超过 3 个默认展示前三个，并提供展开和收起。

## 视觉与交互

- 卡片采用克制的紧凑密度：标准高度约 `88px`，文件图形宽约 `48px`，卡片之间保持 `8px` 间距。
- 主区域整块可点击并通过 `onOpen` 打开文件；更多菜单和展开/收起按钮的可操作区域不小于 `44px`。
- PDF 必须显示独立 PDF 图标、红色 `PDF` 格式标识和 `PDF` 类型文案，不能退化为无格式的通用文件卡。
- PDF 与 Word、Markdown、Excel、PowerPoint 使用同一安全打开链路，始终跟随系统默认应用。

## Artifact v2

Artifact 增加独立角色，不能复用现有 `kind`：

- `deliverable`：用户最终要打开和使用的文件。
- `preview`：技术验证、渲染预览、页面图片。
- `support`：源码、配置、辅助脚本和其他过程文件。

最终投影只接受 `deliverable + ready + 支持扩展名`。PPT 自动生成的 PDF/PNG 属于 `preview`；显式导出或 `artifact_publish` 发布的 PDF 才是 `deliverable`。

## 打开契约

Renderer 只提交 `threadId/runId/artifactId`。Electron Main 必须从 durable transcript 反查路径，并重新校验 run 终态、artifact 角色、扩展名、output roots、realpath、符号链接边界和普通文件状态。成功后按系统默认文件关联打开；不硬编码 WPS、Office 或 LibreOffice 路径。

## Workbench 边界

交付物卡片属于 terminal narrative item，继续位于 `ExecutionFeed` 的 turn 内；不修改 `RunStage`、composer、滚动控制、turn marker 或输入附件结构。
