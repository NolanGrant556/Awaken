# Tool Layer v2 迁移说明

更新时间：2026-07-11

## 迁移结果

本轮在保留 tool.Tool、legacy Execute(string) (string,error)、现有 transcript 和 AG-UI 映射的前提下，完成 additive v2 迁移。

### Definition

- resolved schema version：2
- 新增：purpose、when_to_use、when_not_to_use、recursive input_schema、tool-specific output_schema、side_effects、permissions、examples、failure_modes
- Registry 现在保存 Runtime + resolved Definition + Origin + Quality + Warnings 快照。
- RequestBuilder 只从 registry/resolved definition 编译模型名称、描述与 input schema。
- 注册模式：compat、strict_builtin、strict_all。
- GET /v1/tools 暴露完整 resolved v2 contract 和 definition quality；所有 resolved fields 都存在。动态外部工具无可验证元数据时，`examples` / `failureModes` 返回空数组，并以 `quality` / `warnings` 表达缺口。

当前静态 builtin catalog：

- 30 个可执行 builtin 全部有 resolved v2 contract；`spreadsheet_chart`、`document_render`、`pdf_render` 三个 `execute=nil` stub 已从 catalog 隐藏，不再向模型暴露不可执行能力。
- 30 个可执行 builtin 全部以 `strict_builtin` 注册；静态 catalog 质量计数为 strict=30、adapted=0、incomplete=0。
- 其中 17 个 typed artifact catalog 工具由共享 authoring path 生成完整 definition 与经同一 input validator 验证的代表性 examples，已纳入同一 strict gate。
- 运行时注入的 `skill_install` 已作为 strict builtin 注册；固定一方 `skill_resource_read` 以 `SourceSkill + strict_all` 注册。两者都已迁移为 OutcomeTool，不再使用 legacy result adapter。`skill_install overwrite_policy=replace` 由于底层 replacement 尚不可恢复、且当前没有通用 review 通道，现在在 permission 与 executor 两层 fail-closed 为 `unsupported/not_started`，不再让 danger 动作经 ArtifactWrite lane 零审批执行，也不伪造可继续的 review 流程。

### Result

ExecutionOutcome 保持唯一 canonical result，并新增：

- schema_version
- summary
- operation 与 side_effect_state
- changes[] 与 certainty/reversibility
- environment observation provenance
- warnings[]
- errors[] 与 stage/retry strategy
- next_actions[]
- tool-specific details

Runtime finalizer 现在：

- 用 registry 中与模型展示完全相同的 input schema 做执行前校验；v2/MCP 递归对象不再被 legacy 单参数逻辑错误解包；
- 对 strict definition 的 `details` 执行 output schema 验证，契约不匹配会成为 `tool_output_schema_mismatch` verification failure；
- 同步 canonical Outcome 与兼容 ToolExecutionResult 的 timing/content/truncation；
- 区分 permission 预测路径与 executor 实际变化；
- 对声明可变更但未观察到 delta 的成功调用返回 `side_effect_state=unknown`，不再误报 `none`；
- 把 artifact 合入 canonical Outcome；
- 保留 needs_auth/needs_runtime retryability 与恢复动作；
- 优先读取 typed trash change；v2/`OutcomeTool` 不从 `content` 推断变化，只有 legacy result adapter 可为旧返回保守推断并标记 `ChangeInferred`；
- 对不可能状态组合 fail closed；
- model payload 深拷贝后再投影，递归去除 secret-bearing typed keys，省略 artifact content，并为每个结构化字段设置 8 KiB 上限；超限仍返回合法 JSON 截断信封。

### Existing Tools

- list_files、grep_search、calculator、web_search、read_artifact、artifact_publish 已从 legacy result 迁移到 OutcomeTool。
- text_file_create、trash_file 已迁移到 typed change/details；trash 失败可表达 unknown side effects。
- 30 个可执行静态 builtin 除 runtime 专用的 ask_user 外都实现 OutcomeTool；ask_user 由 ToolRuntime 产生同一 canonical Outcome。
- ask_user 模型输入改为递归 questions schema，同时保留旧 questions_json transcript/call 兼容。
- MCP adapter 保留递归 input schema 与上游 output schema；成功 StructuredContent 进入 `details`，canonical 字段冲突会安全包入 `mcp_payload`；CallToolResult.IsError=true 映射为 transport completed + semantic failure，旧 Execute 返回 typed ToolError。
- apply_patch 直接从解析后的 add/update/move/delete 操作生成 exact typed changes；trash 的 original resource 与 trash destination 不再混为同一路径。
- artifact publish 使用 `published` 动作表达“发布已有交付物”，不再伪造文件 created；typed artifact create/edit 的 side effect 与 descriptor action 分开准确表达。
- typed artifact 成功 JSON 结果进入 schema-backed `details.result`，同时保留 path/status/preview 等高信号字段。
- 直接与 transform 执行路径共用同一 terminal gate：先完成 canonical Normalize 和 strict output verification，再决定 `completed`、artifact 发布与 success audit。`tool_output_schema_mismatch` 不会再留下伪成功事件或 ready artifact。
- ModelPayload 对已规范化的 v2 Outcome 只做深拷贝/去敏/限长投影，不用空 context 二次 Normalize，因此 mutation-capable success 的 `side_effect_state=unknown` 不会被降级为 `none`。
- 未注册工具返回 `unsupported/not_started/nonretryable` 并建议刷新 registry/切换工具；OutcomeTool 若同时返回 success outcome 与非空 Go error，transport/implementation error fail-closed 为 failed，不发布成功信号。
- `skill_resource_read` 在 registry 加载/安装时固化 resolved package root，读取前复验根身份，并从授权 project/home anchor 的 Go rooted filesystem handle 执行真实 open/read；包内符号链接或加载后替换的 package-root 符号链接都不能跳出授权根。`skill_install` 对显式 project_root 解析符号链接后再校验 workspace 边界并把已授权真实路径传给 installer。
- Skill 安装写入本身也通过 Go rooted filesystem handle 创建目录、写入随机 staging 并 rename，`.awaken` / `.awaken/skills` 符号链接不能把写入导向 workspace/home 授权根之外。
- `remote_git` 只接受无内联凭据的绝对 HTTPS URL，拒绝 local/file/ext/custom helper；ref 使用严格字符契约并在 Git option separator 之后传入。Git 子进程环境改为 allowlist，不继承 `GIT_CONFIG_*`、template/hooks、SSH/exec 或 TLS-bypass 变量，clone 强制空 template；同时禁止 ext/file/ssh/git/http 协议、system/global config 与交互凭据，防止远程 helper、option-like ref 或 ambient hook 绕过 Tool permission/shell policy。
- 用户/项目定义的动态 `skill__*` 仍经 compat resolver 和 legacy result adapter；稀疏或不可验证 metadata 显式标记 adapted/incomplete，不伪造 examples 或副作用。固定系统工具 `skill_install` / `skill_resource_read` 不在该兼容集合中。

## 兼容行为

- 未删除 Tool.Description()、Tool.Parameters() 或 Tool.Execute()。
- raw legacy definition 可缺 v2 字段；resolved view 必为 schema v2。
- snake_case canonical Outcome JSON 保持；AG-UI lowerCamelCase 由现有 projector 继续派生。
- 旧 v1/v2 transcript 不原地重写。
- content 继续返回人类可读/legacy payload；对 v2/`OutcomeTool` 它永不是状态、错误或变化事实源。只有 legacy adapter 可为兼容旧结果保守推断变化，且 certainty 必须为 `ChangeInferred`。
- journal 当前仍持久化 canonical Outcome；字段级 sensitivity/retention/access policy 是后续项，不将 model payload 去敏误报为持久化安全策略。
- provider 原生 tool-output strict 参数尚未启用；Awaken runtime 已对 strict definitions 的内部 `details` schema 做执行后验证。两者不是同一层。
- 默认 provider 仍隐藏 raw apply_patch；compat/grammar-capable exposure 契约不变。

## Rollout 与 rollback

Rollout：

1. 默认 registry 使用 compat，同时记录 quality/warnings。
2. 30 个可执行静态 builtin 与运行时 `skill_install` 由 `strict_builtin` gate 约束；固定一方 `skill_resource_read` 由 `strict_all` gate 约束。
3. 动态 MCP/Skill 不因上游 metadata 稀疏而中断注册，但 mutation/permission 不确定性保持可查询。
4. 后续对受控的官方 extension 做 strict certification；第三方动态工具继续使用 conservative adapter。

Rollback：

- v2 字段均为 additive；调用者可继续读取现有顶层 status/error/content。
- 可暂时把注册门禁退回 compat，不需要删除 v2 字段或改写 transcript。
- 不允许回滚 MCP IsError、实际变化路径、truncation 同步等协议真相修复。

## 剩余事项

- 为官方 MCP/connector 定义可验证的 side-effect/failure metadata；第三方 MCP 继续 conservative。
- 为用户/项目定义的动态 `skill__*` 增加可验证的 source-specific Outcome classifier；固定系统 Skill 工具已完成迁移。
- provider 支持时再编译 provider 原生 strict output schema；不能把 Awaken runtime 已执行的 details 验证误报为 provider 已验证。
- 建立固定 model/provider/tool-pool 的重复 tool-selection eval corpus。
- 增加 journal 字段级 sensitivity/retention 策略，不依赖 key-name redaction 作为唯一持久化安全层。
