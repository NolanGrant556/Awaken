# 凭据存储与恢复 · 需求文档

模型 API key 保存在本机凭据文件中。界面只显示配置状态，写入失败或文件不可读时应给出可执行的恢复方法。

代码、接口和验证方法见[实现方案](实现方案.md)。

## 范围

模型和组织用量管理密钥保存在 `~/.awaken/.env`。WebSearch 的免 key 渠道不使用该存储；MCP OAuth token 由系统 secrets backend 负责。

## 明文边界

API key 当前会存在于：

1. `~/.awaken/.env` 明文文件；
2. Electron Main 的读取调用栈和 `ModelProfileRunConfig`；
3. localhost run request；
4. `awaken-core` 的 `AgentConfig.ModelConfig` 与按 thread 缓存的 Agent；
5. 已条件注册的 Agent Plan 图片/视频 provider runtime 内存；
6. provider Authorization header 的请求构造内存。

当前没有显式 zeroization。以下位置禁止出现完整推理或管理 key：Renderer profile/account state、Desktop operation issue、日志、SemanticJournal、thread metadata、run/lifecycle snapshot、MCP metadata、错误事件或测试快照。Renderer 只接收 `has_key`、`has_management_key`、各自掩码、状态和推理 `credentialRevision`；尾号不是认证数据，也不能证明 `.env` 中当前仍有 key。Renderer 的 start-run 请求只携带 profile ID 与可选 effort，完整 profile/account secret 由 Main 解析。

## 状态与恢复

当前 profile 状态只有：

- `ready`：profile enabled 且本次实际读取到非空推理变量；显式 `authScheme=none` 的自定义 profile 不要求变量；
- `missing_key`：变量不存在或为空；
- `disabled`：profile 未启用；
- `unreadable`：`.env` 解析失败、权限拒绝或读取失败。

provider `401/403`、网络错误和额度错误发生在 key 已读取并进入 provider 层之后，不能改写为 `.env unreadable`。

## 当前不支持

- 不支持从旧 safeStorage/Keychain/DPAPI 密文或旧 `model-profiles.json` 自动导入；
- 不支持 workspace/thread 私有 key、session-only key、多 Agent Plan 账户、Google Cloud 服务账号或多 Desktop writer；
- 不支持对 `.env` 加密、系统钥匙串托管或主动内存清理；当前支持 profile/account key 轮换与 revision 递增，但不提供定时自动轮换；
- 不支持通过 Renderer 导出、复制或读取已保存完整 key；
- 不支持把 `keyLast4` 当成真实 key 存在性的替代检查。
