# 插件产品与架构契约

本文是 Awaken 插件能力的唯一产品与架构权威。插件层拥有方言识别、来源、安装树、配置、组件 inventory、完整性和 run generation；Skill、MCP、Hook、Subagent 与 instructions 的执行语义仍由各自功能域拥有，插件层不得建立第二套 runtime。

## 1. 当前支持

Awaken Desktop「扩展 > 插件」支持安装和管理以下 user-scope 包：

- Agent Plugins 1.0.0；
- Codex native `.codex-plugin/plugin.json`；
- Claude Code `.claude-plugin/plugin.json`，以及用户明确选择/来源带可信 Claude hint，或无其他 manifest 且唯一符合 Claude 默认目录形态的合法 manifestless 包；
- Cursor `.cursor-plugin/plugin.json`。

插件同时存在两类产品来源：用户通过 ZIP 安装的普通插件，以及随 Desktop 发布的 Awaken 内置插件。内置插件的唯一发行源位于 `apps/desktop/resources/builtin-plugins/<name>/`；其中 `plugin.json`、`.awaken/builtin.json` 和该插件声明的 setup/组件资源必须全部进入 Git，Desktop 开发与构建入口先执行 `scripts/validate-builtin-plugins.mjs`，缺失必需元数据时 fail closed，不能用维护者工作区中被忽略的本地文件继续启动或打包。`electron-builder.yml` 必须把该目录作为 `extraResources/builtin-plugins` 原样纳入安装包，Desktop 再通过 `AWAKEN_BUNDLED_PLUGIN_DIR` 交给 Core，用户登录 shell 中的同名变量会被清除。Core 启动时仍使用完整方言、containment 与 digest 校验把它复制到普通 Plugin Store，但会记录 `builtin/brandIcon/builtinOrder` 可信元数据。`.awaken/builtin.json` 只有从该发布目录同步时才生效，普通 ZIP 即使携带同名文件也不能取得内置身份。

内置插件首次出现时默认关闭；发布版本变化时替换只读 package tree，并保留用户的整体启用状态、组件偏好、变量和账号绑定。插件整体启停只控制该插件的技能、组件与运行时可见性；关闭插件不得调用 host Connector 的断开连接、清理 Keychain 凭据或取消账号绑定，重新开启时直接复用原已连接账号。内置 package 不能通过普通 ZIP 替换、卸载、MCP Source 编辑或 `plugin commit` 改写；用户只控制整体启停和其正常 setup/账号动作。`awaken-outlook` 是首个内置插件，排序为 0，显示名为「Outlook 邮箱」，引用 `catalogPlacement=plugin_only` 的 `awaken.microsoft.outlook` host Connector，并随包提供九个中文 Outlook 邮件 Skill，分别覆盖综合邮件、收件箱整理、回复草拟、订阅清理、任务提取、共享邮箱、附件、定时发送和邮箱组织；连接、审批等待、重连、退出登录和 Outlook MCP 都只在插件页面展示，连接器目录不重复出现。

九个 Outlook Skill 共同定义模型侧邮件操作协议，不建立新的工具权限系统：简单近期、文件夹/未读导航、自由文本搜索分别路由 `get_recent_emails`、`list_messages`、`search_messages`；列表预览足够时不得机械抓取全文，需要多封完整正文时使用一次 `get_messages_batch`；分页原样复用不透明 `nextCursor`，文件夹名称先经 `find_mail_folder` 解析，已读与分类优先使用各自专用工具。读取先限定邮箱/范围并唯一确定 message ID；新邮件、回复、转发与定时发送默认草稿优先，`to/cc/bcc` 使用邮箱字符串数组；真正外发前重新读取草稿和附件，展示发件邮箱、实际收件人、主题、附件、回复范围与发送时间。宿主存在提问用户工具时优先调用，不存在时输出摘要并停止等待；只有用户确认当前摘要后发送一次，摘要变化、批量范围变化或结果未知不得复用确认或自动重发。退订成功不隐含回复、移动或删除授权，整理/任务提取也不隐含发送。该协议只改善模型选工具和调用顺序，MCP tool 在 connected/auth-ready、schema 有效时仍按 07/06 域开放进入 provider。

Outlook 的通用读取／对象与发送确认步骤分别由 outlook-email 包内 references 拥有；专项 Skill 在进入发送时显式调用同插件的 outlook-email，读取其发送参考，避免把提到另一个 Skill 当作自动加载。同一份已展示、已确认且参数未变化的最终摘要不重复提问，原有发送确认与未知结果不重放边界不变。正常批量任务创建的草稿、文件夹、分类与计划保留为业务结果；只有用户明确授权清理的本次测试夹具可按精确 ID 清理。附件读取所需临时副本可写任务目录；明确保存意图与目标目录后由 Agent 解析绝对新路径、准备目录并使用唯一文件名，不能覆盖已有文件或把下载授权扩成外发。

Desktop 安装入口只接受用户点击选择或拖入的本地 ZIP。来源确定后自动完成格式、包内容与 digest 校验：不符合时在安装弹窗明确显示格式错误，通过时单一拖放区变为浅绿色并允许安装，不设置人工“检查插件”步骤。Core 的 `local_path` 目录输入只保留给受控 Plugin Creator 候选校验、安装与替换，不作为 Desktop 安装方式。ZIP 与受控候选目录复用同一 containment、预算、执行意图和 digest 门禁。多个合法 manifest 且 identity 冲突时必须由用户明确选择方言；不得按扫描顺序取第一个。

插件解析器不得把单一根 `SKILL.md` 加普通资源的包猜成 manifestless Claude Plugin；这种包返回 `SKILL_PACKAGE_SELECTED` 并由 Desktop 切到 Skill 安装、让用户确认 project/global 范围。manifestless Plugin 必须至少具有 Claude 插件专属默认目录或文件（`skills/`、`commands/`、`agents/`、`hooks/hooks.json`、`.mcp.json`）；带正式 Claude/Cursor manifest 的根 `SKILL.md` fallback 仍属于插件。相反，Plugin manifest 或插件 Skill 布局进入 Skills 安装器时由 08 域返回 `PLUGIN_PACKAGE_SELECTED`。两个 Store 都在 Core 边界 fail closed，Renderer 的自动页面路由不能替代这些校验。

安装树位于：

```text
~/.awaken/plugins/packages/<name>/   # PLUGIN_ROOT，只能通过安装/同名替换、受控 MCP Source 编辑或 commit 推进 digest
~/.awaken/plugins/data/<name>/       # PLUGIN_DATA，跨升级保留
~/.awaken/plugins/.staging/          # 隔离物化
~/.awaken/config/plugins.json        # v2 状态、override、变量引用、来源与迁移冲突
```

Core 向插件页提供安装来源、内置身份与排序、品牌图标键、方言、版本、digest、完整性与兼容事实；Skills、MCP Servers、Rules、Agents、Commands、Hooks、Variables、Apps 八组 inventory；`native | adapted | recognized_unsupported | ignored_by_dialect | invalid` 精确状态；以及组件级 desired/configuration/authentication/runtime/integrity。install/list/get 同时返回来源中立的 `setupItems` 与 `setupSummary`。Desktop 的常驻 Console 只投影来源中立的插件身份和紧凑组件目录，不展示厂商方言、物理来源、digest 或状态矩阵。所有组件详情使用与 Skill 一致的固定尺寸 Dialog，内容量只影响正文滚动，不改变窗口尺寸；标题统一只显示类型图标和组件名称，不重复显示第二行组件类型标签。用户点击 Skill 后只渲染 `SKILL.md` Markdown 预览，使用动作固定在预览滚动区之外的右下角 footer；其他组件继续按需提供 Source/Preview、诊断、资源、Variables、MCP tools 与 Rule/Command/Agent/Hook 控制。MCP Source 是安装包对应文件的逐字文本，不替换 `command`、`args`、`url`、`env`、`headers` 或源文件中已经存在的其他字面值；Secret Store 注入值不属于源文件，不得为展示而反向合并。精简展示不改变 Store、运行时校验或 fail-closed 判定，独立变量配置中的 Secret 仍只显示 configured/masked。

Skill/Rule/Command/Agent 的 Composer 动作必须同时满足：父插件启用、组件 desired 启用、完整性有效、配置就绪且 mapping 为 `native | adapted`。不满足条件的组件仍可检查详情、Source 和 Diagnostics，但 Desktop 不显示也不执行插入动作；`recognized_unsupported | ignored_by_dialect | invalid` 不能被 UI 包装成可运行入口。Renderer 的展示门禁和点击时防御校验只是第一层，Core 的 token/digest/logicalId 复验仍是最终安全边界。

整体 Plugin Composer 目录要求父插件已启用且 digest 有效。App 在 Desktop ready 后主动加载并持有来源中立的 Plugin catalog 快照；输入 `@`、打开 Plugin picker 或进入插件页都同步消费该快照，不能为了重验而清空 action/card 或展示整页 loading，catalog revision 触发的请求只在后台完成后原位替换。普通插件仍只在至少有一个可用 Skill 或 MCP 时进入 `@` 的「插件」分组；内置插件启用后即进入「内置」分组，并按 `builtinOrder` 稳定排序，尚缺账号或必填配置时条目可见但禁用，完成 setup 后原位变为可选择。`awaken-outlook` 为首个内置插件项，菜单使用 Microsoft 官方 Outlook 彩色产品图标；选中后的结构化 token 仍只保存稳定 pluginName/digest，不把图标或本地资源路径写入 prompt。

组件 desired mutation 与 inventory 共用同一 `switchable` 判定：组件必须 valid、配置就绪、属于 native/adapted 映射且不能是 Variable；任一条件不满足时 Core 拒绝 mutation，并返回 409 `COMPONENT_NOT_SWITCHABLE`。Variable 只能通过配置接口修改，不能通过组件开关写 desired。

插件整体 `enabled` 是所有组件的父级有效状态：关闭插件后，inventory 中每个组件的有效 `desiredState`、所有 MCP server 配置与 runtime projection 都必须为 disabled/off，不能被组件 override 或 legacy server toggle 覆盖。组件自身 override 继续持久化但不运行；重新启用插件时恢复这些偏好。父插件关闭期间 Desktop 锁定组件与 MCP tool 开关，避免把“保存将来偏好”误呈现为当前已经启用。

list DTO 不携带正文；详情按组件懒加载。logicalId 由来源路径和方言身份稳定生成，wire 使用无填充 base64url；revisionId 绑定 package digest 与 component source digest。

### 1.1 方言发现与优先级

- Agent Plugins 1.0.0 只按正式 `plugin.json`、`skills/` 和 `mcp.json` closed schema 解析。
- Codex native 按 manifest 声明或默认 `skills/`、`.mcp.json`、`hooks/hooks.json` 解析；根 `hooks.json` 不属于默认 Hook。legacy `commands/` 只接受 Markdown、非空 description frontmatter 与 4000-byte 门禁，仍以 Command 身份展示。
- Claude Code 的显式 `commands`/`agents` 替代默认目录，显式 `skills` 追加默认 `skills/`，Hooks/MCP 走各自 merge；根 `SKILL.md` fallback 只在默认 Skill 目录为空时使用。
- Cursor 显式声明替代该类默认发现；默认 rules/agents/skills/commands/hooks/MCP/variables 按官方路径和扩展名解析。Cursor Hook 有 `postToolUseFailure`、`sessionEnd` 和 `preCompact`，没有 `postCompact`。
- 来源方言不加载的文件必须保留为 `ignored_by_dialect`；已识别但没有安全 adapter 的组件保留为 `recognized_unsupported`，不能静默丢弃或伪装成可运行。

### 1.2 Skills

启用且完整性有效的 Skill 组件以精确 package selection 进入 08 域；组件 override 会从 discovery 移除单个 Skill。Catalog identity 为 `plugin__<plugin>__<skill>`。Composer 选择由 Core 重新解析，不信任 Renderer 路径。

Plugin Console 是 plugin Skill 唯一的管理与浏览入口；Skills 页面及统一 `/` Skill 菜单不投影 `sourceOrigin="plugin"`。这不改变 Store 的精确 root 供给、统一 Catalog、模型侧 `skill` 工具或组件启停。Composer 通过 `@ Plugin` 选择整个启用且 digest 有效、至少含一个可用 Skill 或 MCP server 的插件；只含 Skill 的插件仍可选择，Core 在 run start 重验 pluginName/digest 并提供优先使用该插件 Skill/MCP 的 host-owned 引导。Plugin Console 的组件级“在对话中使用”使用 Core 投影的 `plugin__<plugin>__<skill>` Catalog identity 生成普通 `type=skill`、`sourceOrigin=plugin` 的精确 token；Renderer 不按路径或显示名猜 identity，run start 仍由统一 Skill Registry 复验。Console 不提供把 plugin Skill 复制、派生或安装为普通用户 Skill 的入口。

### 1.3 MCP

四方言 MCP 都归一化为 06 域 `mcpclient` config。server identity 为 `plugin__<plugin>__<server>`；Manager 负责连接、OAuth/readiness、tools/list、调用和自动恢复。配置保存、插件/组件/tool mutation 与网络恢复都会走现有刷新链，刷新按 server identity、scope、插件包 digest 和完整配置做幂等协调：只有四者都匹配的 MCP session 才保持不动；同名插件包替换即使 command/cwd 未变，也必须因 digest 变化停止旧进程并从新包重建。另一个插件的 Skill、setup 或整体状态变化不得重启不相关 MCP。Plugin Console 不提供独立的手工 restart/reload 入口。插件变量只在方言允许的位置插值，未解析引用 fail closed。

插件通过 `host_connector` 声明使用宿主提供的 MCP 时，该引用同样归一化为插件 inventory 中的 `mcp_server` 组件，并在 Plugin Console 的「MCP 服务」分组展示名称、连接状态和真实 tools/list；不能因为 server runtime 由 Connector 域拥有就从插件详情隐藏。该组件保留插件 setup 的 logicalId、来源和 authentication gating，但运行 identity 必须由已注册 Connector ID 解析，不能信任插件伪造的任意 server name。共享账号、server 生命周期、组件/逐 tool 启停和凭据仍由宿主 Connector 拥有，因此此类 MCP 组件在插件页可查看但不可独立编辑、启停或修改 tool override；关闭或卸载一个引用插件也不得断开其他插件共享的宿主连接。Connector definition 的 `catalogPlacement=plugin_only` 表示插件页是该能力唯一用户入口；Core 仍保留共享 owner，`GET /v1/connectors` 与连接器目录不得重复投影。

Plugin Console 允许编辑 MCP 组件所属的整个源文件。保存请求只提交 Core 返回的 logicalId、当前 recorded digest 和完整文本；Renderer 不解析 JSON、不定位物理路径，也不直接写安装树。与当前文件字节完全相同的保存是成功 no-op，返回 `changed=false` 且不更新 digest、状态或运行时；其他修改由 Store 在 `.staging` 中复制完整包、写入候选文件，重新执行 containment、方言、identity、manifest 与 MCP component 校验。候选仍必须由同一方言/manifest 拥有且至少声明一个有效 MCP server。验证通过后 Store 再复核 live tree 与 recorded digest，通过 CAS 原子切换 package、状态与新 digest；旧 package 进入 Trash，失败恢复旧包和旧记录。成功通知统一刷新 Skill/MCP runtime、组件 inventory 与 composer catalog revision。无效文本、stale digest、digest drift 或 active generation 都不能改变 live package。

MCP server 发起 form/URL elicitation 时复用当前 run 的外部交互门；表单提交值只返回正在等待的 MCP call，取消或无可交互 run 时 fail closed。具体 schema、序列化和保密边界由 [06 MCP 配置、传输与生命周期](../06_MCP运行时/配置、传输与生命周期.md)拥有。

逐 tool override 独立于整个 MCP component 的启停 override 持久化和投影：用户只关闭某个 tool 时，不要求先切换 server/component；Store 重载后仍必须把它投影到 `DisabledTools`。它只影响中央工具注册和新 run snapshot，详情仍显示 disabled tool。`mcp_tool` Hook 只能调用当前插件已启用、ready 且未被逐 tool 停用的 server/tool，不能拼 shell。插件 MCP 和 Hook command 以当前登录用户身份运行，没有额外沙盒。

### 1.4 Rules 与 Commands

Rule Assembler 只产生 instruction fragment；最终排序、16 KiB 单源预算、32 KiB 总预算、digest 和 run 冻结由 `src/instructions` 拥有。优先级是：当前用户请求 > 手动 Plugin Rule > project AGENTS > global AGENTS > 自动 user-scope Plugin Rule。支持 always、file_globs、manual；`model_decides` 当前只允许手动加入。

Command 保留插件 namespace、argument hint 和 prompt template。Renderer 只保存 pluginName、digest、logicalId 与参数；Core 在 run 启动时重验并展开 `$ARGUMENTS`、零基 `$ARGUMENTS[n]`、兼容 `$0` 及既有一基 `$1..$n`。模板没有占位符但用户提供了参数时，按 Claude Code 行为在正文末尾追加 `ARGUMENTS: ...`，不能显示可输入参数却静默丢弃；`<required>` hint 或模板占位符缺参时拒绝，只有 `[optional]` hint 时允许空参数。stale digest、disabled/invalid component 同样拒绝启动。Console 只在 Core detail 明确返回 `acceptsArguments=true` 时显示参数输入，必填且为空时禁用插入动作。

### 1.5 Hooks

mapped 且 handler 可表达的 Plugin Hook 以 `SourcePlugin` 编译进后续新 run 的同一个 Hook snapshot。支持 Codex command、Claude command/http/mcp_tool/prompt/agent、Cursor command/prompt。事件是显式映射表；厂商 command 在编译期展开允许的根变量并拆为 argv，拒绝 shell operator；输入输出由方言 protocol adapter 转为统一协议。

Plugin Hook 复用 Awaken 统一 Dispatcher。tool event 的 handler 级条件也必须进入 matcher；`Bash(git commit:*)` 只能触发对应命令，不能因只保留外层 `Bash` 而扩大成所有 shell 调用。timeout 采用上游兼容语义：普通事件未声明时默认 600 秒，厂商声明正数 timeout 时原值生效，不再由插件编译层压缩为 10 秒；`SessionEnd` 对应的退出事件单独默认 1.5 秒且最多 3 秒。超时按既有 `timed_out` 回执与 failure policy 收敛，默认 `continue` 不阻塞后续模型运行。Dispatcher 的每 run invocation、累计墙钟和取消边界仍是统一宿主保护，它们不改写已编译 Hook 的单次 timeout。

command Hook 的配置级 `async`/`asyncRewake` 与 Claude stdout `{"async":true,"asyncTimeout":...}` 会建立有界后台 invocation：进程启动成功后立即返回 `scheduled`，完成后再写 durable completion 与 Plugin 回执，且在此期间继续持有对应 Plugin generation lease。异步 Hook 不得追溯阻断或改写触发操作；`asyncRewake` 的 model-facing feedback 作为不可信数据进入同一 thread 下一次 run，不自动发起新模型 run。`SessionEnd` 始终同步。后台 feedback 每 thread 最多 32 项/32 KiB，只在当前 Core 进程内保留；异步 command 最长 10 分钟，父 run 被取消时一并取消。prompt/agent/http/mcp_tool 当前仍同步。

当前只把 package/plugin scope Hook 编入新 run。Agent/Skill-scoped Hook 会保留 scope、owner 与诊断并保持不可运行，不能退化成 package Hook；待对应组件的 run-scoped activation bridge 完成后再进入当前 run。

回执复用 `hook_invocation_started/completed`，携带 plugin name/digest/logicalId/revisionId；异步调用在调度时只有 started，后台真正结束后才产生 completed。插件详情另保留当前 Core 进程内最近 512 条完成回执；不跨重启。失败/超时项可做诊断性重试，但不会重放原 run 输入。

### 1.6 Plugin Agents

Claude/Cursor Agent 编译成现有 `subagentruntime.Role`，agent type 为 `plugin__<plugin>__<agent>`。插件明确声明的 `maxTurns` 或 `timeoutSeconds` 原值保留；未声明时保持 unset，不再添加 Plugin 专属的 8 turn、32 次工具执行或 5 分钟限制。child 仍服从原生 Subagent 的统一 32 turn / 128 tool 上限、每 run 8 个任务/4 并发、root-only、深度、取消和父 run terminal barrier；这些宿主边界不由插件扩大。system prompt、read-only 与 tool allowlist/denylist 同样只收窄 child；background/isolation/model hint 不能扩大父 run 权限。并发、取消、消息、Journal、Workbench task group 和 Inspector 全部复用原生 Subagent。Composer token 和 invoke route 都重验 digest/logicalId；Plugin Console 只投影插件明确声明的限制，不把未声明的 `0` 解释为厂商要求，也不展示一套 Plugin 专属预算。

### 1.7 Variables 与配置

Variables schema、普通值和 Secret reference 存于 Store v2；Secret value 只进入 secret store。状态写失败会回滚本轮 secret 变更；reset 在状态提交后清理旧 ref。升级只迁移 key 和 type 都兼容的变量；不兼容值和消失的 override 进入 `migrationConflicts`。Secret Store 值永不进入 Renderer；用户或插件作者已经写在 MCP 源文件里的字面值属于该文件本身，Source 编辑器按原文展示和保存，但不会获得额外的运行时 Secret。

Claude 只按 `sensitive: true` 判定 Secret；Cursor 除显式 `secret/sensitive` 外，还把 key 含 `TOKEN`、`SECRET`、`PASSWORD` 或 `API_KEY` 的字段按 Secret 处理，以避免未标注凭据落入 `plugins.json`。配置 UI 显示 schema default、类型约束和依赖该变量的组件，但不会回显 Secret。

### 1.8 Setup 与本地鉴权

四方言统一归一化为 `SetupRequirement`，kind 为 `configuration | secret | oauth_pkce | oauth_device | mcp_oauth | cli_login | external_setup | host_connector | app_connector`，状态为 `ready | needs_configuration | needs_auth | authorizing | verifying | pending_admin_approval | expired | failed | unsupported`。Claude `userConfig`、Cursor Variables、远程 MCP OAuth 与 Codex Apps 从原声明生成；Agent Plugins 可使用 `plugin.json.extensions["io.awaken.setup"]`，四方言都可使用 `.awaken/setup.json`。同一 Agent Plugin 同时存在 extension 与 sidecar，或任意来源产生重复 setup ID 时，安装校验直接失败。

Awaken 声明只接受 configuration/secret、Authorization Code + PKCE、Device Authorization、已注册宿主 CLI Connector、已注册 Awaken host Connector 与外部设置页面。`host_connector` 必须只给出稳定 `connectorId` 和受其 gating 的组件，不得覆盖宿主 OAuth endpoint/client/scope/binding；账号由宿主 Connector 拥有，多个插件可以引用，卸载单个插件不退出共享账号。MCP OAuth 由远程 MCP 原声明和 discovery/CIMD/DCR 路径生成，App Connector 只由 Codex App 声明生成。公共 `client_id` 可直接声明；`client_secret` 只能引用 Secret Variable。凭据 binding 只允许 `mcp_transport`、`http_header` 与 `process_env`，且必须指向对应 MCP 或 Hook 组件；Skill、Agent、Command prompt 和模型上下文没有凭据 binding。

Plugin Auth Broker 完全运行在 Core 本机进程。PKCE callback 只监听随机 `127.0.0.1` 端口并校验 state；Device Flow 优先打开 `verification_uri_complete`，只有缺少完整地址时 Electron Main 才用原生弹窗显示 user code。非 loopback endpoint 必须使用 HTTPS；Core 的 OAuth client 对初始请求与 redirect 都执行 DNS/私网检查，并限制 redirect 数。Renderer 只接收脱敏 session 阶段、错误和过期时间，不接收 code、token、refresh token、client secret 或 Secret value。

`authorizing/verifying` session 由 Core 持有，其存活不依赖 Renderer 页面、Awaken 窗口焦点或系统浏览器是否在前台。Plugin Console 卸载时只停止本页轮询，不发送 cancel；重新进入时只能使用当前 `pluginName/setupId/digest/fingerprint` 查询匹配的活动会话并恢复观察，stale 页面不得认领旧会话。仅明确取消动作、会话超时或协议终态能结束授权。

管理员审批是授权会话的独立非就绪状态。provider 明确回调 `admin_consent_required` 等无歧义错误时 Core 自动进入 `pending_admin_approval`；外部系统浏览器停留在审批请求页且不回调时，Plugin Console 在活动 OAuth session 上提供“页面要求管理员审批”，由用户显式记录该事实。该标记只把 plugin/setup/fingerprint 与观测时间写入 `auth/plugin-approvals.json`，不读取浏览器、不产生凭据、不轮询客户租户；关联组件继续 fail closed。管理员批准后用户必须点击“批准后重新连接”完成新的 OAuth，只有真实 token 保存成功才为 ready。插件升级指纹变化、重新发起授权、退出登录或卸载都会清理对应标记。

插件账号 identity 固定由 `pluginName + setupId + requirement fingerprint` 产生。OAuth token、refresh token 与 client secret 保存到系统 Keychain；`auth/plugin-accounts.json` 和既有 credential metadata 只保存 credential ref、fingerprint、scope、expiry、revision 与待清理 tombstone。fingerprint 覆盖 flow、issuer/endpoints、client、resource/audience、scopes 和 bindings；任一变化产生新 identity，不复用旧账号。卸载先取消活动 session，清理变量 Secret 和当前/旧 OAuth ref；Keychain 删除失败且 tombstone 已写入时由下一次启动重试，不把真实凭据写入 tombstone。

`host_connector` 不使用上述 plugin-scoped identity，而是读取 Connector 域的共享账号与 runtime 状态。解析器为每个声明生成受同一 setup gating 的宿主 MCP 引用组件；插件 API 再用 Connector definition/status 解析显示名、真实 server identity、snapshot 和 tools/list。插件 setup 的 start/session/cancel 只是对宿主会话的脱敏代理；“退出登录”明确影响所有引用该 Connector ID 的插件。未知 ID 为 unsupported。Awaken 官方 Outlook 插件使用 `awaken.microsoft.outlook`，其 Outlook MCP 与九个 Skill 都在 Connector overall state 为 connected 时 ready。

configuration/secret 缺失或 authentication 未 ready 时，只阻止引用它的组件；其他已就绪组件仍可运行。普通 configuration 的 `process_env` / `http_header` binding 由 Plugin Store 在 runtime projection 时写入目标 MCP transport；配置 UI 可以回显普通值，但 ready 状态不得与实际 transport binding 分离。Secret/OAuth binding 在 runtime config 中只保留 opaque ref：HTTP Hook header 和 command Hook env 在执行前由 Core 解析，通用 OAuth 的 MCP transport 在每次请求前解析并刷新 token；Renderer、Source、诊断、日志、Journal 与模型都看不到 Secret/OAuth 值。插件进程仍继承当前登录用户本机文件与网络权限，但这不授予它读取其他插件或宿主账号凭据的能力。`cli_login` 只能引用 Registry 已注册的 CLI Connector，插件不能提供任意登录命令；`external_setup` 点击后仍必须用关联 runtime/Connector probe 证明 ready。

明确的 MCP `401`、`invalid_token` 或 `needs_auth` 才进入 Workbench `ExternalActionGate`。用户完成插件详情中的连接后，同一 tool call identity 对读写调用都只重放一次；第二次仍需授权返回 `plugin_auth_replay_exhausted`。timeout、断线、取消和结果未知不归类为鉴权失败，也不自动重放。MCP SDK transport 自身对成功完成的 OAuth handler 同样只执行一次协议级请求重试。

Core-owned host Connector 使用自己的 provider adapter 和错误码；Outlook 的第二次鉴权失败返回 `connector_auth_replay_exhausted`，不冒充插件账号失败。

Codex Apps 不是 OAuth 声明。当前只显示 App 名称、Connector ID、来源和 unsupported 诊断，不显示连接按钮，也不会解析到 OpenAI Connector runtime。

### 1.9 Generation、替换与卸载

每个 run 启动时获取当前 Plugin state digest 作为 `plugin_generation` 并持有 lease，直到 terminal worker 退出。同一 run 的 Rules、Hooks、Skill/MCP/Agent 都在该 lease 内装配。

存在活动 lease 时，安装、替换、卸载、commit、插件/组件/MCP tool/Rule/Variables 修改都返回 409 `RUNTIME_GENERATION_IN_USE`。用户等待或取消活动 run 后重试。该策略不热切换，也不让一个 run 混用两代。

Desktop 安装同名插件时默认进入替换流程，不要求用户勾选确认。替换先把旧包移入 rollback staging；新包和原子状态成功后旧包才进入 Trash，失败恢复旧包。替换成功后的 runtime projection 必须携带新 package digest，使仍指向同一绝对 command/cwd 的 MCP server 也停止旧子进程、注销旧 tools/list 并从新包重建；不能让 Trash 中的旧进程继续服务。卸载同样先将 package/data 合并 stage，状态提交后一次移入 Trash；Trash 或状态写失败时同时恢复包、数据和记录，不留半卸载。`PLUGIN_DATA` 跨升级保留；卸载成功后清理状态/secret。重启从持久状态恢复 override 和变量。

## 2. 当前不支持或已知缺口

- 只支持 user scope，不支持 project/managed scope 安装。
- 不提供 URL/Git 远程安装、Marketplace、插件目录聚合或候选索引；Desktop 新安装必须从本地 ZIP 开始。
- 本地 ZIP 来源没有上游版本发现协议，不提供“检查更新”接口或按钮；更新包由用户重新选择 ZIP，并走同名安全替换。
- Apps 只保留 inventory/source/diagnostic 和 `app_connector/unsupported` setup item；没有 OpenAI Connector 目录、账号授权或 Codex App runtime。
- 未映射 Hook 事件和厂商权限字段保持 unsupported/diagnostic。
- Plugin Agent 的 vendor model hint 不直接选择 endpoint；child 使用 Host 已解析的 Subagent purpose profile。
- Hook receipt 查询缓存不跨 Core 重启；Journal 有事实，但没有跨 thread receipt 索引。
- 活动 generation 当前阻止 mutation，没有并行保留多份 package generation并立即向新 run 发布升级。
- Linux/Windows 真实 Desktop、Trash、ACL、Hook/MCP 子进程和安装矩阵未完成，不能从 macOS 外推。

## 3. 不变量

- Renderer 不解析 manifest、不读安装目录或 Keychain、不拼 URL/command/argv，也不推断 ready；MCP Source 编辑只传递 Core 已读取的原始文本和用户修改后的完整文本。
- 安装检查不执行候选 Plugin component。
- installed tree 直接变化形成 digest drift，runtime projection fail closed；只有 digest-pinned install/replace 或 CAS commit 能签收。
- Secret Store 中的 secret value 不进入 Renderer、日志、Journal、模型、导出或 diagnostics；这不改写安装包源文件中本来存在的字面文本。
- mapping、desired、configuration、authentication、runtime、integrity 是不同状态。
- installed package 禁止任何未签收的直接修改；Plugin Console 的 MCP Source 保存必须经 staging validation、expected digest CAS、原子 package/state 切换和 Trash rollback。Plugin Console 不从插件树生成独立 Skill 副本；模型侧授权直改仍必须以 `plugin commit` 签收 expected digest。
- Plugin runtime 不扩大 TaskScope、Subagent boundary、MCP readiness、Hook budget 或 OS identity。
- 插件组件继承当前登录用户能够使用的本机文件与网络权限是 Awaken 的默认运行模型；安装弹窗不设置权限确认勾选，安全边界仍由零安装时执行、digest/CAS、运行时既有门禁和 fail-closed 不变量承担。
