# 本地主运行时准备链路

Awaken 的 `primary-runtime` 是 Work artifact 工具的本地依赖层，负责支撑 PPT、PDF、图片、Office 预览等非纯文本产物能力。它不是 shell，也不由模型临时安装依赖。生产环境由 RuntimeManager v2 拥有、探测并原子激活；文件存在不等于 ready。

## 所有权

生产环境唯一根目录：

```text
<AWAKEN_USER_DATA_DIR>/runtimes/primary-runtime/
├── versions/<bundleVersion>/<os>-<arch>/
│   ├── state.json          # resolved state（与模板分离）
│   ├── python/ ...
│   ├── node/ ...
│   ├── libreoffice/ ...
│   ├── poppler/ ...
│   ├── ffmpeg/ ...
│   └── packages/ ...
├── staging/                # 临时准备区；失败不得破坏 current
├── current.json            # active + previous known-good version key
└── state.json              # 可选宿主侧准备进度快照
```

`AWAKEN_USER_DATA_DIR` 解析顺序（Node/Desktop/Go 共用契约）：

1. 显式环境变量 `AWAKEN_USER_DATA_DIR`
2. 与 Electron `app.getPath("userData")` / `@awaken/desktop` 一致的平台规则：
   - macOS：`~/Library/Application Support/@awaken/desktop`
   - Windows：`%APPDATA%\@awaken\desktop`
   - Linux：`${XDG_CONFIG_HOME:-~/.config}/@awaken/desktop`

仅测试/开发允许用 `AWAKEN_PRIMARY_RUNTIME_ROOT` 覆盖 runtime root。禁止各脚本自行回退到 `~/.cache`。

`current.json` 记录 `active` 与 `previous` known-good version key。写入必须 temp write → fsync → atomic rename；**不使用目录 symlink 作为激活指针**。

## Manifest 模板与 resolved state

仓库模板固定在：

```text
apps/desktop/resources/runtime-manifest/primary-runtime.json
```

模板 `schemaVersion=2`，声明 `bundleVersion`、组件 `version` / `source` / `relativePath` / `probe`。平台与 arch 在 prepare 时写入 resolved `state.json`，不把激活路径写回仓库模板。

Node `check-primary-runtime` 与 Go `runtime_preflight` / Artifact 执行路径必须读取同一 `current.json` + `versions/<key>/state.json`，并对 readiness 得出相同结论。

## 准备生命周期

```text
discover sources
-> stage temporary directory under staging/
-> copy/install into staging（真实复制，禁止 wrapper/symlink 回 seed）
-> real probe every required component
-> write resolved state.json
-> atomic rename staging -> versions/<bundleVersion>/<os>-<arch>/
-> atomically update current.json（保留 previous known-good）
```

规则：

- executable path 存在但 target 失效、exit nonzero、或 probe 失败 → not ready。
- symlink / wrapper resolve 后必须仍在 Awaken-owned root 内，否则 not ready。
- staging 中途失败不得破坏 current；repair 失败回滚 previous known-good。
- 系统安装与显式 seed 只能作为复制来源，不得成为正式 RuntimeReady / current target。
- Windows Poppler 必须复制完整 `bin` 目录（含 DLL），不能只复制 exe。
- 生产执行路径默认不扫描 `PATH`，不读取 Codex 或其他产品 cache。

## Seed 与一次性迁移

- 仅允许显式 `AWAKEN_PRIMARY_RUNTIME_SEED_DIR` 作为 prepare 复制来源。
- 旧 `AWAKEN_PRIMARY_RUNTIME_CACHE_DIR` 只作一次性迁移别名，并输出 deprecated warning，不参与正式解析。
- 仅当 `current.json` 不存在时，允许把旧 `~/.cache/awaken-runtimes/primary-runtime` 迁入新 root；拒绝 Codex cache、越界 wrapper/symlink、probe 失败组件。
- 迁移结果写入：

```text
<AWAKEN_USER_DATA_DIR>/data/migrations/primary-runtime-v2.json
```

后续启动不重复迁移。

## 脚本

```bash
npm run prepare:runtime
npm run check:runtime
node scripts/check-primary-runtime.mjs --json
npm run test:runtime
```

`prepare-primary-runtime.mjs` 在 managed root 内 stage → probe → publish。`check-primary-runtime.mjs` 只验证 Awaken-owned current，不把系统安装或外部 cache 判为 ready。

## 启动与打包

`npm run dev:desktop` / `build:desktop` / Desktop `dist` 仍在启动或打包前调用 prepare/check。Electron supervisor 启动 `awaken-core` 时传入：

```text
AWAKEN_USER_DATA_DIR=<Electron userData>
AWAKEN_RUNTIME_MANIFEST=<bundled template primary-runtime.json>
```

Go 正式 Desktop 路径只接受 `AWAKEN_USER_DATA_DIR` 推导 managed root；测试/开发可用 `AWAKEN_PRIMARY_RUNTIME_ROOT`。模板 manifest 仅用于组件声明与 probe 规格，正式执行路径来自 `current.json` 指向的 version 目录。

## 可见性

RuntimeManager 产生宿主事件：

- `RuntimePrepareStarted`
- `RuntimePrepareProgress`
- `RuntimeReady`
- `RuntimeRepairFailed`

启动检查与 Artifact 调用前均可触发。内部安装 Python 包等依赖显示为宿主操作，不得伪装成模型主动 `pip`。

## 边界

- 不允许模型通过 shell 临时安装或扫描系统目录来补 runtime。
- runtime 缺失时工具应返回明确缺口，不能生成坏 PPT。
- `presentation_create` / `presentation_render` 使用该 managed runtime 生成 PPTX、PDF 与 PNG 预览。
- 删除或不存在 Codex cache 不得影响 Awaken readiness。
