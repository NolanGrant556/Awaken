# 技能包与加载契约

## 1. 权威范围

本文唯一拥有 Skill 包形态、frontmatter 语义、本地来源、发现和同 ID 覆盖规则。不负责安装事务、激活执行、MCP 请求细节或 Desktop 布局。

## 2. 用户入口与当前支持

Desktop 的“扩展”页面按项目级、全局级和 MCP 来源展示 Skill。用户也可以直接在以下目录维护本地包：

```text
<workspace>/.awaken/skills/<package>/SKILL.md
~/.awaken/skills/<package>/SKILL.md
```

加载器只扫描一级包目录；放在 skills 根目录的平铺 Markdown、隐藏目录和缺少 `SKILL.md` 的目录都会被忽略。包内可以包含 references、scripts、assets 等资源，入口固定为大写 `SKILL.md`。

当前来源只有：

| 内部来源 | UI scope | 产生方式 |
| --- | --- | --- |
| `project` | `project` | 当前 workspace 的 `.awaken/skills` |
| `user` | `global` | 用户目录的 `.awaken/skills` |
| `mcp` | `mcp` | 已连接 MCP server 的 prompt/resource 动态桥接 |

不存在 bundled/system 内置来源，也不扫描仓库外的其他“生态目录”。

## 3. 包标识与覆盖规则

1. 加载器以 frontmatter `name` 生成规范化 ID；本地加载或安装在 `name` 为空时，先使用包目录名或上传文件名生成 fallback，再进入 schema 校验。
2. 因此，底层 `ValidateSchema` 的确要求 `name` 非空，但“本地缺少 name 的包必定被拒绝”不是当前产品事实。fallback 行为由 `src/skills/skills_test.go` 锁定。
3. 本地 Skill 不得使用保留前缀 `mcp__`；该命名空间只供桥接 Skill 使用。
4. 项目来源优先于用户来源。同 ID 时高优先级条目成为有效条目，低优先级条目以 `shadowed` 状态保留在列表快照中。
5. MCP 条目由 bridge 直接注册到 registry；它们不写入本地包目录。MCP 生命周期边界见 [执行模式与 MCP 来源边界](./执行模式与MCP来源边界.md)。

`available`、`unavailable` 和 `shadowed` 是 registry 的当前可用性状态。`unavailableReason` 解释依赖或平台契约失败；它不代表包已从磁盘删除。

## 4. Frontmatter 契约

`SKILL.md` 必须以 YAML frontmatter 开始并有 Markdown 正文。当前字段按执行状态分为三组。

### 4.1 当前被执行链消费

| 字段 | 语义 |
| --- | --- |
| `name` | 名称；本地加载/安装允许由包名补齐，直接 schema 校验仍要求非空 |
| `displayName`、`description`、`whenToUse`、`version` | 列表、工具描述、激活提示和 receipt 元数据；`description` 必须存在 |
| `arguments` | `string/number/integer/boolean` 参数及 `${arg}` 替换 |
| `context` | `inline` 或 `fork`；当前 fork 会降级，见专项文档 |
| `toolPolicy` | 只支持 `mode: intersect`；`allow`/`deny` 只收窄父工具池 |
| `allowedTools` | 兼容别名；映射到 `toolPolicy.allow` 并产生弃用警告 |
| `requiredTools`、`requiredCapabilities` | 激活前校验有效工具和能力 |
| `requiredRuntimeComponents` | 调用平台 runtime preflight，缺失时 fail closed |
| `requiredResources` | 包内资源的模式、required、大小与 SHA-256 合同 |
| `requiredConnectors`、`requiredMcpServers` | registry 可用性依赖；生产接线限制见专项文档 |

`toolPolicy.allow` 为空表示继承当前父工具池，不表示开放进程全局工具。显式传入的空父工具池仍是空边界。

### 4.2 已解析但尚未执行

`model`、`effort`、`agent` 和 `hooks.postExecute` 当前只进入结构体，没有生产执行方。它们可以用于包兼容，但不得写成已生效的模型覆盖、角色绑定或生命周期回调。

### 4.3 运行时生成字段

`source`、`scope`、`rootDir`、解析后的真实根、文件路径、状态、shadow 信息、MCP binding 和 body fetcher 均由主机注入，不应由本地包伪造。桥接使用的 `mcpBinding` 不是本地作者入口。

## 5. 平台冲突与安全不变量

- Skill 不能通过工具策略扩张父 run 的工具集合。
- 包如果与平台保留工具契约冲突，加载后保持 `unavailable`，并以 `skill_platform_contract_conflict` fail closed。
- 资源路径必须保持在已解析包根内；加载时会防目录穿越、符号链接逃逸和加载后根目录替换。
- 包正文中的 `${AWAKEN_SKILL_DIR}` 由主机替换为包根；这不是任意环境变量插值。
- 任何新增来源都必须先定义来源优先级、持久化所有权、重启重建方式和冲突语义，不能直接把目录拼进扫描路径。

## 6. 异常与恢复

无效 YAML、非法参数类型、非法 context、非法资源模式或哈希、保留名称会使条目跳过或不可用；修正磁盘包后，在下一次本地来源 reload 或下一次 run 同步时恢复。单个坏包不应阻止其他包加载。

安装事务与 reload 时点见 [安装与激活契约](./安装与激活契约.md)。
