# 子智能体协作 · 实现方案

协作组由 Runtime 按 thread 持有，AgentCore 负责构造和运行 Agent，子任务工具只解析动作，Desktop 按明确身份投影。普通 Agent、Skill fork、Plugin Agent 与深度研究调研员使用同一构造路径。深度研究只绑定 `ResearchIntent` 并注入主编合同，不再用 Host spawn 收窄编制。

## 身份、策略与构造

`AgentID` 对应持续的上下文；`TaskID` 对应一次分配；`AttemptID` 对应一次执行。快照还包含 ParentAgentID、ThreadID、RunID、模型配置/模型 ID、实际 effort、binding source、配置 revision、角色 digest、scope digest、上下文方式、后台标识、关闭标识和 worktree 回执。

`Policy.Effective` 的产品默认值是 8 个活动 Agent（含 root）、128 个排队 assignment、最大深度 8。Core 启动参数 `--active-agents` 和 `--queued-assignments` 可设置容量。历史任务不占执行位。全部 Manager 调用都按同一个 `Policy` 归一默认值，不再保留按历史任务总数限流或按共享根目录排斥写任务的旧模式。文件冲突仍由类型化文件工具校验。

AgentCore 默认 256 轮、1024 次工具执行。继续同一 Agent 保留已使用预算；网络重试的 transport attempt 不重置它。explore/plan/review 与插件角色上限仍可收窄。深度研究不再给调研员另设 12 轮 / 16 次工具。

spawn 顺序：

1. 校验父身份、深度、角色与 workspace mode，冻结角色定义和 digest。
2. 根据当前配置解析模型、effort 和路由来源；精确配置 ID 不做名称猜测。Plugin/Skill model hint 只能匹配唯一可运行配置。
3. 在父工具边界捕获中立快照，固定权限、模型配置和构造闭包。排队任务不再读取正在变化的父 Runner。
4. 在锁内预留队列登记，保存并 flush `subagent_spawned`，再发布任务。
5. 先取得同 Agent 的单写者锁，再取得协作组执行位；取消后不得从 queued 回跳 running。
6. child 完成时先保存终态，再更新状态并唤醒等待者；写入失败保留最后耐久状态。

general 默认共享父工作区。explore/plan/review 及插件的 read-only、allowlist、denylist 只收窄权限。类型化 Write/Edit 保持文件级版本检查；worktree 重新校验仓库 common-dir、精确分支、目录和回执，不自动合并。worktree 为之后继续而保留，用户改动不被清理。变更清单使用 `git status --porcelain=v1 -z --untracked-files=all`，按 NUL 解析文件边界，重命名/复制记录取目标路径并消费原路径；不对状态输出做空白裁剪。状态不完整或格式无效时设置 `NeedsReview` 并保留 worktree。

## fork、消息与上下文

`ChildContextSeed` 保存版本、方式、来源 Agent、源序号、水位内祖先授权、中立消息、可用压缩 bundle、无密钥用途模型绑定和摘要校验值。fresh 不复制父对话；full 排除未配对工具；recent 取 N 个闭合用户任务，并保留更早及当前用户约束。

fork 不复制 provider opaque 状态、父用量、待处理子任务、活动 gate 或父计划服务。复制的消息保留 originAgentID，新的上下文先通过工具配对与 digest 校验，再按 child 实际执行模型的完整请求预算准入。

子任务当前指令通过带 `agent_id` 的 Host `awaken_assignment` 边界同时写入日志与模型消息。请求的系统信息给出当前 Agent 和父 Agent 身份；继承的 user 消息在请求投影中标注来源，内部旧 assignment 标签转义，原始日志不变。继承历史提供事实与适用的用户约束，父任务尚未执行的派生步骤不自动成为子任务。即使协议把相邻 user 消息合并，最后一条发给当前 Agent 的 assignment 仍明确执行范围，避免 full/recent fork 重复父任务的 spawn。

每个 child 有自己的计划、context revision、usage anchor 和 epoch 存储，详见[上下文与用量](../上下文与用量/实现方案.md)。当前历史读取只授权自身及 fork 时明确授予的祖先范围，兄弟任务和水位之后的父消息不在授权范围内。

消息先保存 `subagent_message_queued`，再入同 Agent 的收件箱；同一 Agent 合计最多 128 条待处理消息。运行边界保存 `agent_context_message` 后投影为 synthetic 输入，不冒充用户可见消息。`model_request.admitted_message_ids` 表示本次已携带，`turn_boundary.incorporated_message_ids` 与 context revision 在 flush 成功后确认提交。恢复时重新放回未提交消息，不把收到回执当成已执行。

任务终态通知先进入耐久记录，再进入交接；自动注入失败会重新登记未交付通知。status、wait 和通知共用结果事实。显式 status/wait 返回完整正文，自动通知和 UI 使用最长 32 KiB preview；Host 完整结果另存于终态记录的 result_content/result_digest，恢复校验 digest。Runner 将 terminal_subagent_task_ids 与工具结果一起提交，成功后才确认交付；重启按该记录恢复，offload 不删除交付凭据。大工具结果仍走所属 Agent 的 offload store。研究必须消费完整 typed 结果，不能解析 preview。

## 等待、停止与恢复

`Wait` 使用宿主通知。纯等候 children/input 时释放 Agent 执行位，恢复前重新取得；不持有模型请求位，也不靠模型轮询。`any` 优先返回尚未交付的终态；如果指定任务已全部结束，即使结果曾被读取也立即返回完成，只有仍有活动任务且没有新结果时才继续等待。父候选回答先保留一次，再追加子任务结果并进入整合轮次；子任务在模型调用期间结束和宿主开始等待后结束，遵守相同顺序。

`childCreatorConfig` 统一装配当前 Agent 的 thread/run 身份和构造服务。Runtime 或 Runner 在执行开始时绑定 creator；Skill 工具复用已有绑定，不用工具批次的短生命周期 context 重新绑定。独立 Skill 入口缺少 controller 时才创建并绑定。Skill 返回不会使后续派发失效，也不能清空 `EndAttempt`、`StopRun` 校验的 run 身份。

所有新 assignment 使用父执行的取消上下文。模型工具不再暴露 `background`；旧内部请求的该字段归一为 false，历史快照仍可读取。`waitForActiveSubagents` 不再排除旧 background 快照。父候选回答出现后，宿主等待结果并恢复模型汇总。

`EndAttempt` 关闭本次 creator 的创建入口。root 收尾停止本次 run 的全部后代并等待实际完成通道；没有固定宽限期后放行终态的路径。`CancelRun` 同时发出 root 取消与 `StopRun`，`StopAll` 保留会话级全部停止并封住续派。中间区域“停止全部任务”走 `CancelActiveAssignments`：只取消 queued/running 子任务，不设置 `stopped`，也不调用 root `RequestCancel`。用户停止会写入一条 root 专用 Host notice，并在各子任务终态里标明用户停止；Runner 在下一模型轮次或等待子任务返回时把它注入主 Agent 上下文。停止主执行时仍先封住创建入口，再取消运行项与排队项；已进入持久化的 spawn 也必须登记、取消并清理后才能结束。旧 run 的重复取消不能停止新 run。

`runTask` 取得执行位后，核对整组停止、Agent 关闭及原 creator/run 是否仍有效；运行态持久化后、调用 Starter 前再次核对。这样取消信号尚在传播时，排队任务也不能借刚释放的执行位启动。执行和资源 release 返回后才发布 terminal。取消宽限期到期只更新仍在停止的说明；`HasLiveWork` 继续检查实际完成通道。子任务启动的 Bash 后台进程由 assignment 清理回调取消并等待退出，Plugin generation 随后释放。`RunService` 对未经过 Runner terminal barrier 的 executor 也执行相同收尾。

followup 创建新 TaskID/AttemptID，复用 AgentID。父 Agent 的协作工具续派使用仍然活跃的当前宿主服务；已结束或已停止的 creator 不能续派，也不能用 followup 清除停止标记。新一轮由 root 重新绑定后才允许继续，并验证配置、scope digest、角色 digest 与 worktree。冷启动恢复原语义对话、消息、压缩、技能、工具激活和累计预算；不会自动重放中断动作。用户的后续消息仍交给主 Agent，由主 Agent 决定续派。深度研究 run 不借普通续派在 Stop 或重启后自动重开整次调查；该 run 内部的调研员续派与普通协作相同。其他专用 Host workflow 仍不借普通续派重开阶段。

Plugin generation 在实际 assignment 与异步 Hook 存活期间保留。空闲上下文缓存超过 16 个时可卸载具备耐久恢复能力的条目；关闭 Agent 释放对应缓存。已完成任务释放构造闭包，结束的父执行换成不持有旧对话的构造服务。历史快照和完整结果仍保留在协作组及日志，尚未做历史快照的分页卸载。

归档、回退、删除、项目清理和 inactive-thread 淘汰检查整个协作组。项目取消包含后台任务。关闭或回退后旧管理器和活动订阅失效，不能复活旧写入者。

## 模型请求与只读工具并行

LLM 请求池覆盖主调用、子任务、摘要、Hook 和深度研究主编循环，实际 transport 前申请，流结束/取消/失败后释放，退避不占位。默认 8 个在途请求、128 个排队项；`--model-requests` 与 `--account-model-requests` 是宿主配置，不从模型窗口猜测 RPM/TPM。compact/native 优先请求最多连续取得 3 次，随后给普通请求机会；组内遵循顺序，跨组按最近服务次序公平选择。

请求记录区分 logical call、transport attempt 与 provider request ID；用量可记录 prepare、排队、transport 和首 token 时间。当前没有完整 DNS/TLS/代理分段指标，不能把供应商波动归为代码性能收益。

无工具 Hook 且全部属于内建只读 Read/Glob/Grep/WebSearch/WebFetch 的批次最多并行 4 项。FailureSupervisor 的准入和结果更新、媒体预算预留、日志结果提交保持顺序。修改类、Skill、MCP 和混合批次保留串行。Core 共用 16 个读取资源位，重型 PDF/图片最多 2 项，等待媒体不会占住一般读取位。按原调用顺序提交结果，不按返回快慢重排。

Computer 的 root 清理不等待后台共享资源引用；子任务保留独立设备租约与控制归属，具体生命周期和跨轮次交互规则见[桌面观察与操作](../../10_计算机操作能力/桌面观察与操作/实现方案.md#子任务的资源与控制归属)。

## HTTP、事件与 Desktop

控制入口：

```text
GET  /v1/runs/{run_id}/subagents
GET  /v1/runs/{run_id}/subagents/{task_id}
POST /v1/runs/{run_id}/subagents/{task_id}/cancel
POST /v1/threads/{thread_id}/agents/stop
GET  /v1/threads/{thread_id}/activity
```

Desktop、Preload、Main、HTTP 与 RunService 不再提供直接向子 Agent 发消息、继续或关闭 Agent 的入口。主 Agent 和宿主编排通过内部 `SessionController.Followup`、`Message`、`CloseAgent` 操作，保留消息耐久化和身份校验。`MessageIdempotent` 具备带键去重原语，但当前模型工具调用没有传入稳定幂等键，重复提交消息的端到端去重仍是缺口。HTTP 只保留查看、单任务取消、停止全部子任务及活动订阅。`POST /v1/threads/{thread_id}/agents/stop` 只取消该会话活动子任务并通知主 Agent；停止主执行仍走 `POST /v1/runs/{run_id}/cancel`。

原 root SSE 在主执行终态结束。activity SSE 独立携带子任务事件，使用自己的游标；保留最近 4096 个事件，在同一锁内校验回放范围并登记订阅，慢订阅者断开后续传，过期返回 ACTIVITY_CURSOR_EXPIRED 并触发耐久 transcript 重载。canonical record identity 与 sourceEventId 负责双流去重，不能混用两个游标域。

普通 child 文本、工具、计划、上下文与 Computer 事件同时携带 task/agent/run 身份。子任务正文只进入其 narrative。所有 child 构造都隐藏 `ask_user`，包括插件角色；ToolRuntime 对旧上下文或显式调用再次返回 `ask_user_parent_required`，不建立用户 gate。子任务应结束当前分配并向父 Agent 报告信息缺口。MCP/ACP 授权和 Computer 安全复核继续进入专用 gate，答复返回原执行。正常 root 终态须经过后代清理屏障；活动流仍用于迟到事件、历史回放和新主执行中的明确续派，不代表旧子执行可脱离 root 运行。已失效的 gate 拒绝迟到答复。root SSE 结束后，原 Session 仍保留 child 事件供 transcript 回放；冷恢复与后续分配不能过滤原主回答。切换任务或活动游标过期时，从仍有效的问题对象补齐 gate。

`AwakenSubagentGroup` 只改变列表展示：标题使用 `subagent`，有活动任务且父级传入 `onStopAll` 时在标题右侧渲染“停止全部任务”；行内只渲染 description 与状态文案；running 显示“进行中”，completed 显示“完成”，失败和中断保留真实状态；cancelling 显示“正在停止”，cancelled 显示“已停止”。角色、结果和用量仍留在原 view model，供详情使用。选择回调仍传原 TaskID，停止全部只回传父级回调，不改变任务或状态处理。

子任务的右侧标签、文件切换、滚动、宽度与 Composer 保留规则见[工作台 Inspector 标签页](../../01_桌面工作台/工作台布局与运行展示/实现方案.md#subagent-执行详情属于-inspector-标签页)。`SubagentPanel` 只消费对应 `SubagentTaskView` 的过程、计划和用量；取消仍使用原 typed cancel，关闭标签只改变 Renderer 视图。
