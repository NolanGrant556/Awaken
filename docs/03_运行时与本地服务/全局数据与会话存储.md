# 全局数据与会话存储

## 权威范围

本文唯一定义 Desktop 全局数据根、线程 metadata、per-thread 日志、输入附件和删除边界。它不定义 run 的用户语义（02）、SemanticJournal 记录内容（本文下游的 [SemanticJournal 与重放](SemanticJournal与重放.md)）或凭据密文（05）。

## 路径合同

[`src/desktopdata/paths.go`](../../src/desktopdata/paths.go) 从 `AWAKEN_USER_DATA_DIR` 取得正式 Desktop 数据根；平台默认目录只用于没有 Desktop 注入时的受控 fallback。主要路径：

```text
<userData>/
├── data/threads.sqlite
├── data/threads/thread_<thread-id>.jsonl
├── data/auth/
├── data/migrations/
├── runtime-input-attachments/<thread-id>/...
└── config/
```

线程恢复只读取全局 SQLite 和对应全局 JSONL。当前实现不扫描 workspace 下的 `.awaken/transcripts`，也不把旧项目目录当第二份线程真相。

## SQLite 与 JSONL 分工

[`src/runtime/thread_store.go`](../../src/runtime/thread_store.go) 是存储协调 owner：

- SQLite 保存可索引 metadata、项目/线程关系、标题和 durable operation 所需状态。
- 每个 `thread_id` 有一份 JSONL，保存 v2 SemanticJournal 内容；旧 v1 JSONL 只通过兼容 adapter 读取/追加，不原地重写为 v2。
- 恢复线程要求 metadata 和精确 thread-id 对应的 JSONL，不能按目录猜测或拼接其他线程。

SQLite 使用 WAL、5 秒 busy timeout、foreign keys、单连接和 immediate transaction。线程列表合并当前内存快照与 SQLite metadata；最多 100 个非活动线程的内存保留只是 cache 淘汰，不删除持久数据。

## 输入附件

[`src/runtime/input_attachment.go`](../../src/runtime/input_attachment.go) 负责 runtime 输入附件：

- 图片支持 PNG/JPEG/WEBP，单个最大 8 MiB；内容写到 `<userData>/runtime-input-attachments/<thread-id>/`，文件权限为 `0600`。
- 普通文件必须是存在的绝对路径，当前保留路径引用，不复制或 base64 内嵌到线程目录。
- 删除线程时删除该线程保存的图片目录；外部普通文件引用不是 Awaken 所有物，不能连带删除。

附件图片文件、run metadata 和 SQLite preview 当前在 run goroutine 前写入；这是本文件唯一拥有的文件/metadata 时序。`user_message` 的 append 时点、Skill 预激活失败、附件/token payload 和 blob hydrate 只由 [SemanticJournal 与重放](SemanticJournal与重放.md) 定义。

runtime-owned 目录中存在附件文件不等于 journal 已建立历史关联；恢复不能凭目录扫描发明输入。新 v2 记录通过耐久 `storage_key` 定位 runtime-owned image blob，普通文件继续使用已记录的绝对路径引用；启动失败完整回滚仍不是已满足能力。

## 删除与并发

删除线程要求没有 active run；活动线程返回 busy。成功删除包括 SQLite metadata、对应 JSONL 和 runtime-owned 输入图片。项目删除可能通过 project service 的 durable operation 协调，但项目状态机属于 01 左侧栏域。

路径身份不能只做字符串比较；项目/线程删除必须复验规范化与平台文件身份，避免符号链接或路径复用把操作指向另一实体。

## 异常与恢复

- SQLite 打不开、schema 不完整或事务失败：启动/操作显式失败，不创建第二份 workspace 存储兜底。
- JSONL 尾部半条记录：恢复时可丢弃不完整尾行。
- JSONL 中段损坏：返回中段损坏错误，不跳过后继续拼出貌似完整的历史。
- metadata 存在但 JSONL 缺失/不可读：线程恢复失败并保留诊断，不伪造空会话。
- 删除部分完成：由 durable operation/state 继续收口；不能只根据 UI 行消失宣称磁盘已清理。

## 当前不支持与不变量

- 不支持 workspace transcript 自动导入或双向同步。
- 不支持把线程 cache 上限解释为持久保留策略。
- 不支持删除用户外部附件原文件。
- API key 不进入线程 metadata；模型 cache key 只可使用不可逆摘要。
- SQLite 是 metadata authority，SemanticJournal 是内容 authority；renderer cache 不能覆盖二者。
- v2 输入耐久化的已知时序缺口必须显式保留：Skill 预激活失败可缺 `user_message`。旧 count-only 记录不能猜造未保存的附件/token。
