# 本机依赖与文件生成 · 需求文档

文件生成按实际执行环境处理内容、格式和页面质量。依赖准备与文件质量分别判断，Desktop 启动不以 Office 依赖齐全为前提。

代码、接口和验证方法见[实现方案](实现方案.md)。

用户级共享依赖的统一发现、按需准备与跨项目复用属于[依赖与路径管理](../依赖与路径管理/需求文档.md)的开发中能力；完整覆盖和验证缺口由该功能说明，本文继续拥有文件生成与检查行为。

## 当前产品模型

官方 Office Skill 通过完整办公环境入口取得绑定解释器；未绑定的普通 Shell 仍遵守用户环境语义。固定办公包已完成本地候选的真实任务部署与复用验证，公开资源交付尚未完成，具体来源和选择规则只在[依赖与路径管理](../依赖与路径管理/实现方案.md)中定义。

用户项目自己的 `.venv`、`node_modules` 继续属于软件项目；不能因办公生成任务把支撑依赖安装到项目或 Skill 目录。外部安装保留用户所有权，文件生成成功不能证明受管包完整或首次下载可用。

## 当前依赖发现

run-start snapshot 观察当时的 PATH、通用 executable 和 workspace marker，不能视为所有 Office 组件已就绪。`load_workspace_dependencies` 返回的办公绑定和既有共享绑定可以用于后续执行，历史 snapshot 不反向改写；`Read` 的 Poppler 路线可消费绑定。doctor 仍按具体文件操作检查解释器、库和原生程序，helper 复用本次实际路径。

默认办公执行信息由宿主统一提供。helper 在 Awaken 内缺少绑定时停止系统扫描；完整包的资源交付和真实验收状态由依赖域说明，不能用外部软件执行成功掩盖缺口。

## 缺失与恢复

生成工具缺少依赖不是权限 gate。`Read` 缺 Poppler 返回 `needs_runtime`；Skill/Bash 保留真实 spawn/exit/stderr。普通办公任务通过共享准备入口恢复，不建议模型改用系统或项目安装命令。准备后继续使用实际绑定，不要求重建历史快照才能执行；业务错误、环境错误和授权错误分别处理。

保留的 typed `dependency_install` 只负责 provider 明确声明的 workspace Python/Node plan，继续使用 pinned executable、full sandbox、private staging、post-probe 和 recoverable commit；它不是通用 Work 环境管理器。

## 平台边界

- macOS：当前支持 login PATH、Homebrew 与当前用户应用；必须用真实 Desktop 验证依赖复用和安装后重试。
- Windows：代码只把已验证的 Git Bash 作为 POSIX Shell，明确排除系统 WSL `bash.exe` 启动入口，再按 pwsh/powershell/cmd 做执行前健康回退；环境快照同时观察 `py`、`python3` 与 `python`，Office doctor 从实际可用启动器进入并返回后续固定使用的绝对解释器。cross-build 不代替实机。
- Linux：遵循 PATH 与用户环境，不能从 macOS 验收推导发布结论。

## 当前事实

Core 当前没有 Office 后台 worker，也不注册 typed Office/PDF 生成或渲染工具。固定办公包尚未完成交付，当前共享组件管理与目标整包交付的区别由依赖域说明。Agent Plan 的 `image_generate` / `video_generate` 是独立媒体 provider，不属于 Office/PDF Work runtime 或 `artifact_publish` 文档发布链。

Agent 可按 Skill 使用当前用户环境中的 Python/Node/LibreOffice/Pandoc 等工具，通过 `Bash` 或 `Write` 处理和生成 Office/PDF 文档。bundled Office helper 支持 Python 3.9 及以上，并由各格式 doctor 按 route 返回本轮应复用的 Python/Node/LibreOffice/Poppler 绝对执行计划；这只是 Skill 内的依赖探测，不是 Core typed preflight。当前 Word 阅读由纯 Python 标准库 `read_docx.py` 解析 DOCX/DOTX OOXML，并把未完整覆盖的视觉或复杂结构写入 warning；接受修订、Excel 重算和 Word/PPT 视觉 QA 脚本各自拥有独立 LibreOffice profile、超时和结果合同。这些能力只在 Agent 显式执行对应 Skill route 时成立，也不意味着 Desktop 启动时已经准备 Python、LibreOffice 或 Poppler。其他缺失依赖仍按目标 route 的真实 doctor/执行错误恢复；没有执行对应脚本和逐页检查时，不获得版式验证或视觉 QA 证明。

受支持文档生成完成后必须调用 `artifact_publish`，由 04 域验证普通文件、symlink、扩展名和基础签名，并生成 deliverable Artifact；文件目录不是发布边界。发布证明文件身份和交付状态，不证明 Office 视觉质量。图片/视频不走这条链：专用媒体工具成功时自行产生 ready 媒体 Artifact，Bash/Skill 单独生成的任意媒体文件当前没有通用手动发布入口。
## 共享依赖与执行路径

当前普通 Office/PDF 默认指引已改为宿主整体准备办公包后返回路径；公开资源与产品验收状态由依赖域说明。环境就绪、文件生成、结构校验、发布和视觉检查分别判断；外部工具复用不算空白安装通过。目录、来源、安装和回收规则见[依赖与路径管理](../../03_运行时与本地服务/依赖与路径管理/需求文档.md)。
