# Workbench 叙事投影与重放

## 1. 权威范围

本文唯一拥有 Desktop 中 `event -> runtime reducer -> RunNarrative projector -> turn -> live/replay` 的投影规则。09 域拥有 wire event、cursor 与断线续传，03 域拥有 durable transcript 和 journal 语义顺序，04 域拥有 tool Outcome；本文只定义这些事实如何成为 Workbench narrative。

滚动和布局见 [交互状态机与滚动布局](交互状态机与滚动布局.md)。

## 2. 数据链

```text
Go runtime semantic record
  -> AG-UI-compatible Desktop event
  -> runtime/client subscription or transcript replay
  -> runtime/reducer.ts
  -> run-narrative/projector.ts
  -> committedItems + activeItem
  -> App.tsx filters planning
  -> groupNarrativeByTurns()
  -> ExecutionFeed
```

核心 owner：

- `apps/desktop/src/shared/agui.ts`：Desktop 接收字段类型；
- `apps/desktop/src/renderer/runtime/client.ts`：subscribe/reconnect/replay；
- `apps/desktop/src/renderer/runtime/reducer.ts`：run/thread view 与终态汇总；
- `apps/desktop/src/renderer/run-narrative/types.ts`：UI narrative union；
- `apps/desktop/src/renderer/run-narrative/projector.ts`：幂等投影；
- `apps/desktop/src/renderer/workbenchPresentation.ts`：turn grouping 和 execution-process segmentation；
- `apps/desktop/src/renderer/App.tsx`：组件选择，不重新解释协议。

## 3. Narrative 模型

`RunNarrativeState`：

```ts
{
  committedItems: RunNarrativeItem[];
  activeItem?: RunNarrativeItem;
  inspectorSelection?: InspectorSelection;
  seenEventKeys: string[];
}
```

当前 item：

| kind | 身份与作用 | Workbench 当前投影 |
|---|---|---|
| `prompt` | turn 起点，含文本、附件、tokens | `UserPromptBlock` |
| `planning` | 请求初始活动 | state 保留，UI 过滤 |
| `thinking` | reasoning summary | `ThoughtTrace` |
| `exploring` | read-only action group | `ToolTraceGroup` |
| `tool` | 单个工具或决策轨迹 | `ToolTraceLine` |
| `approval` | legacy approval 历史 | 只读 `ToolTraceLine` |
| `fileChange` | 旧文件变更投影 | 当前返回 null；终态汇总时移除 |
| `compactBoundary` | 上下文压缩边界 | compact boundary line |
| `answer` | assistant markdown，含 `isFinal` | `AssistantMessage` |
| `hint` | 取消等中性提示 | hint line |
| `deliverables` | 终态 ready deliverables | `DeliverableList` |

## 4. Prompt 与 turn

`run/requested` 立即创建 prompt 和 planning，使用户不必等网络返回才看到输入。prompt id 是 turn identity；附件和 `PromptNarrativeToken.leadingText` 必须一起保存。

当前保存合同尚未完整落地：live `run/requested` 直接带入附件和 token，但 v2 durable replay 返回的 run 没有 `inputAttachments` / `composerTokens`，所以重启后的 prompt 只恢复文本。这是已确认的未满足不变量，不得用 prompt 中的文件名文字猜造附件对象。

`App.tsx` 合并 committed + active 后过滤 planning，再由 `groupNarrativeByTurns()` 按 prompt 分组。第一个 prompt 前的恢复/系统 item 是 lead item，不伪造 turn。

## 5. Streaming item 生命周期

- 新 active item 到来时，旧 active item按适用状态 commit；
- text/reasoning delta 累积到稳定 message/run identity；
- message end 或 terminal event把 active answer commit；
- `RUN_FINISHED` 把最新属于该 run 的 done answer 标为 `isFinal=true`；
- transport interruption 不调用 terminal error projector；
- cancellation 先 settle active item，再幂等追加 `hint:run-cancelled:<scope>`；
- late cancellation 不删除已经 commit 的 answer。

隐藏 chain-of-thought 不由 Workbench自行生成；只显示 runtime 明确发出的 reasoning summary。

## 6. Tool 投影与 pairing

### 6.1 Read-only exploration

projector 把当前识别为 read-only 的 tool call 投影为 exploring action。action id 由 scoped tool call id 稳定生成；args delta、progress 和 result 更新同一 action，不制造重复行。

中心只显示 title、status 和短 detail。`App.tsx` 从 `runtimeState.toolResults` 选取 command output/result 第一条非空行补 detail；完整数据仍留在 reducer，当前右侧 UI 未接线。

### 6.2 普通工具

非 read-only tool 使用 `tool` item。`toolStatus` 是 Outcome 的 canonical 状态，UI display state 不得靠 content 文本猜测。deny、transform、needs-auth、needs-runtime、unsupported、recovery-required 等状态按 04 域语义投影。

### 6.3 通用 approval

新 run 不生成可交互 ApprovalCard。历史 `approval` item仍可从旧 transcript 重放，但只能显示标题、`Legacy approval record` 和只读状态。

mass-message review 与 ask_user 使用专用 reducer/UI，不属于 legacy approval item。

## 7. Execution process

`projectNarrativeTurnBodySegments()` 是当前过程折叠的唯一纯决策：

1. 找到第一个 `answer && isFinal === true`；
2. index `<=0` 时 turn body 保持一个 flat items segment；
3. index `>0` 时前缀成为 `executionProcess:<turnId>`；
4. answer 及后缀成为 `answer-and-after:<turnId>`；
5. per-turn open state由 `App.tsx` 控制，默认 false。

因此过程在 final answer 标记前实时可见，终态后才折叠。禁止在 projector 中提前删除过程 item，或用 CSS 隐藏来代替可访问 disclosure。

## 8. Artifact 与 deliverables

artifact event 先进入 reducer 的 `artifacts`；run终态时 reducer把交付物汇总作为 turn 尾部 narrative item投影，live与replay走同一分支。具体资格、去重、排序、稳定 identity、terminal状态和安全打开只由 [最终交付物展示与安全打开](最终交付物展示与安全打开.md) 拥有，本文不重复算法。

## 9. Replay 幂等

优先使用 `semanticSeq ?? seq`。一个 semantic record 可能投影 START/CONTENT/END 多帧并共享 seq，因此 seen key 包含：

```text
scope + stableSeq + event.type + frame identity
```

frame identity优先 message/tool/approval/artifact/compact id。不能只按 seq 去重，否则会丢同一 semantic record 的合法多帧。

没有 seq 的 text、reasoning、tool args delta、tool progress不生成粗粒度 seen key，避免误丢合法增量；其余无 seq event 使用 type/scope/id/content 组合。

`seenEventKeys` 只保留最近有界窗口（当前 projector 的 `MAX_SEEN_EVENTS`），不是持久化 journal 的替代品。

## 10. Thread view 与恢复

- 每个 thread 可在 reducer 的 `threadViews` 保存一份 runtime/narrative snapshot；
- 切线程前 scroll controller 清除旧 turn identity；
- `actionsForThreadTranscript()` 将 durable transcript 重放为 reducer action；
- 快速切线程由 load sequence 防止旧异步请求覆盖新选择；
- live reconnect 使用最后游标继续订阅，overlap 依赖 projector 幂等；
- terminal replay 恢复 done final answer和 deliverables；
- pending 专用 gate按各自 event pair恢复；legacy approval只读；
- 非终态 stream close进入 reconnecting，不提交普通 failed answer。

当前限制：

- WorkBench 不持久化精确 scrollTop、prompt expanded 或 execution-process open state；重开只保证已耐久叙事的身份与内容，不保证像素级阅读位置。
- 结构化附件与 composer token 当前没有完整进入 v2 durable run，因此 Desktop 重启后的 `actionsForThreadTranscript()` 无法将它们交给 `run/requested`。耐久来源只由 [03 SemanticJournal 与重放](../../03_运行时与本地服务/SemanticJournal与重放.md) 定义。

## 11. Inspector 数据与当前 UI 缺口

reducer 当前已保存：

- tool args/result/status；
- bounded command output + truncated flag；
- patch preview相关字段；
- turn diff；
- artifacts；
- `inspectorSummary.lastToolDecision`；
- narrative `inspectorSelection`。

这些是当前未接线的Inspector数据，不等于右侧UI已存在。当前Workbench只用部分tool record生成中心短detail；右侧仍是占位。见 `docs/01_桌面工作台/右侧栏/当前支持边界.md`。

## 12. 异常语义

| 事件/场景 | Narrative 处理 |
|---|---|
| `PROVIDER_AUTH_MISSING` | 清洗为模型 API key 提示 |
| `PROVIDER_REQUEST_FAILED` | 显示 provider 请求失败，不泄露 secret |
| 用户取消 | 保留内容、settle active、追加幂等 hint |
| stream interruption | recovery 状态，不生成 error answer |
| reconnect exhausted | terminal error answer + ready deliverables |
| tool failure | 同一 tool/action进入 error/blocked等 display state |
| duplicate replay | seen key / stable id upsert，不重复 |
