# Desktop宠物产品与架构

## 1. 权威范围

本文唯一拥有桌面宠物的用户入口、选择、浮窗、动画状态、通知、窗口几何、生命周期和模块ownership。宠物包格式、安全导入见 [包格式与导入](包格式与导入.md)，验证见 [验收清单](验收清单.md)。

## 2. 当前支持

- Settings > Pets列出Awaken已导入的宠物。
- 用户在Awaken中独立选择当前宠物；不跟随Codex当前选择。
- 唤醒/收起独立透明浮窗；收起不清空选择。
- 当前选择变更时，已打开浮窗原位热更新。
- 浮窗支持点击聚焦主窗口、拖动、80–224px缩放、多显示器位置恢复。
- 透明空白区域点击穿透；Windows/Linux使用window shape，其他平台使用ignore-mouse-events策略。
- 运行状态投影为9种标准sprite动画。
- running/waiting/failed/review通知气泡，点击导航到thread；running提供Stop。
- 第一次唤醒某宠物显示8秒welcome/waving，并持久化避免重复。
- 关闭/退出Awaken时按平台生命周期处置pet window。

## 3. 当前不支持

- Settings中没有“创建宠物”产品入口；内部 `createPet` bridge当前仅能生成透明本地模板，不是hatch/image-generation能力。
- 不生成或写入Codex宠物目录。
- 不导入/提取Codex内置宠物。
- 不读取Codex `selected-avatar-id` 或overlay bounds作为Awaken状态。
- v2第9–10行的16个look direction当前不播放。
- waiting气泡不直接回答问题/批准操作；除Stop外的action类型目前只聚焦主窗口。
- 宠物状态不进入Go runtime或AG-UI协议。
- Quick Chat、语音、voice orb不属于宠物功能。

## 4. 架构

```text
Codex custom packages
  -> CodexPetImporter
  -> PetStore (<userData>/data/pets + config/pets.json)
  -> Electron Main / PetWindowManager
  -> pet-overlay preload
  -> PetOverlay renderer

Workbench runtime state
  -> PetActivityProjector
  -> Electron Main
  -> PetOverlay renderer

Settings > Pets
  -> Desktop preload bridge
  -> Electron Main
  -> PetStore / PetWindowManager
```

| 层 | 唯一职责 |
|---|---|
| `apps/desktop/src/shared/pets.ts` | IPC/types、sprite常量、TTL和settings contract |
| Electron Main importer/store/validator | 文件发现、校验、复制、catalog/settings持久化 |
| `PetWindowManager` | BrowserWindow、位置/尺寸、screen、shape、IPC、runtime cancel |
| Workbench renderer projector | thread/run/gate状态投影为session activity |
| Pet overlay renderer | sprite、hover/drag/resize、bubble和本地交互 |
| preload | 最小隔离bridge |
| Go runtime | 不感知宠物 |
| Design System | 若复用，只提供纯UI，不读Electron/文件 |

## 5. Activity状态

业务状态：

```ts
type PetSessionStatus = "idle" | "running" | "waiting" | "failed" | "review";
```

映射：

- approvals/userQuestions/massMessageReviews非空，或thread approvalCount>0 -> waiting；
- run `running|cancelling` -> running；
- run `error|cancelled` -> failed；
- run `finished` -> review；
- 无上述状态 -> idle。

多session优先级：

```text
waiting > failed > review > running > idle
```

同优先级按 `updatedAtMs` 新到旧排序。active thread的subtitle优先当前assistant preview，其次active step、last tool decision、waiting提示；最多约96字符。

## 6. Sprite状态与优先级

九状态：

| row | state | frames | 触发 |
|---:|---|---:|---|
| 0 | idle | 6 | 无业务活动 |
| 1 | running-right | 8 | 向右拖动 |
| 2 | running-left | 8 | 向左拖动 |
| 3 | waving | 4 | 首次wake且无更高业务状态 |
| 4 | jumping | 5 | hover |
| 5 | failed | 8 | failed通知 |
| 6 | waiting | 6 | waiting通知 |
| 7 | running | 6 | running通知 |
| 8 | review | 6 | review通知 |

本地交互优先：drag方向 > hover；resize保持当前业务态。业务优先由通知排序决定。禁止把jumping解释为成功或把waving用于普通业务通知。

`idle`帧时长按6倍播放并无限循环；非idle播放3轮后进入idle loop。`prefers-reduced-motion`显示当前状态首帧。

## 7. 通知

当前TTL：

| 状态 | TTL |
|---|---:|
| running | 3分钟 |
| waiting | 30分钟 |
| failed | 15秒 |
| review | 15秒 |
| first-awake | 8秒 |

notification key为 `session key + turnKey/runId/current`。用户关闭后写入最多500个dismissed keys，同一turn不再出现；新turn可重新出现。主窗口聚焦时仅本地隐藏当前bubble并收起，不改业务状态。

当前action：

- 点击通知：激活对应thread；无thread则聚焦主窗口。
- running且有runId：Stop调用runtime cancel。
- 其他预留action：聚焦主窗口处理，不在pet window执行审批/回答。

## 8. 浮窗

Electron BrowserWindow：frameless、transparent、alwaysOnTop(screen-saver)、skipTaskbar、no shadow、non-resizable；显示用 `showInactive()`。macOS设置visible-on-all-workspaces/fullscreen并保持主app Dock身份。

窗口按overlay实际内容动态收缩：

- renderer ResizeObserver上报bubble+pet bounds；
- Main sanitize/min/max并以右下锚点resize，气泡出现/消失不移动宠物；
- Windows/Linux设置shape为交互区域；其他平台平时ignore mouse，hover/drag/resize/bubble时启用；
- recovery watchdog每3秒恢复always-on-top等可见性；
- 初次位置为主屏右下24px；
- screen add/remove/metrics change时clamp并持久化。

## 9. 拖动、缩放和持久化

- 4px内是点击，超过4px进入拖动；
- 水平delta决定left/right动画；
- 拖动使用稳定底边和cursor screen point，避免窗口因bubble resize向下漂移；
- resize从右下锚点，clamp 80–224px；
- settings保存selected、overlayOpen、width、import开关、welcomed、dismissed和 `placementByDisplay`；
- 恢复优先display id，其次近似work area；显示器不存在时选择当前匹配display并clamp；
- 历史DPI异常bounds先归一，不直接恢复巨大透明窗口。

## 10. 生命周期

- Windows/Linux关闭主窗口触发app quit，pet随before-quit dispose。
- macOS关闭主窗口保留app惯例；显式退出时dispose。
- before-quit先停止runtime/subscriptions/project worker，再dispose pet并exit。
- Tuck Away只hide并保存placement，应用和选择仍在。

## 11. 异常与恢复

| 场景 | 行为 |
|---|---|
| 无selected pet | Wake禁用；Main不创建window |
| selected pet从catalog消失 | 清空选择、关闭overlay并持久化 |
| overlay加载/always-on-top漂移 | watchdog恢复；不影响主Workbench |
| display移除 | clamp到可用display |
| renderer异常bounds | Main sanitize/cap |
| runtime不可用时Stop | 结构化错误留在Main日志/UI上下文，不把宠物崩溃 |
| source package删除 | 使用Awaken副本并显示warning |
