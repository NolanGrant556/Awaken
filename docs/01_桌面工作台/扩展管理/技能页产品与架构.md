# 技能页产品与架构

本文唯一拥有 Desktop Skills 管理页的视图顺序、内置资源同步、展示和失败降级。Skill 包格式、发现优先级、激活与 Core 删除安全边界由 [08 技能](../../08_技能/索引.md) 拥有。

## 当前支持

Skills 管理页有四个固定视图，顺序为 `Awaken Skills`、`项目 Skills`、`全局 Skills`、`Agents Skills`，每次进入页面默认选择 `Awaken Skills`。

- `sourceOrigin="bundled"` 只进入 Awaken Skills，来源标签为“Awaken 内置”；
- project 条目进入项目视图，并继续按项目根分组；
- user 条目进入全局视图；MCP 与其他动态/外部来源继续在全局视图的既有分区展示；
- `sourceOrigin="agents"` 进入 Agents Skills 视图，展示来自 `~/.agents/skills` 与 `<workspace>/.agents/skills` 的包；所有条目直接汇入同一个 Skill 卡片网格，不展示来源根标题、路径、数量徽标、折叠按钮或外层分组卡片。来源根只保留给 Catalog identity、搜索和项目级预览请求；agents 来源是只读兼容来源，可预览 `SKILL.md`，预览中不提供删除；
- bundled 同样只读；project/user 只有进入 `SKILL.md` 预览后才显示删除入口。任何来源的小卡片都不承载删除按钮，MCP 动态 Skill 没有本地文件，不提供详情按钮；
- 拥有本地 `SKILL.md` 和 Core `catalogEntryId` 的卡片主体是可聚焦的详情按钮；开关是独立兄弟操作，不会打开详情；
- 安装弹窗只提供 project/global，不允许把上传内容安装成 bundled；
- 资源根随附 `word` / `excel` / `ppt` / `pdf` / `code-search` / `PDF_Max` 六个 Skill 包；三个 Office 包使用中文主流程和按需 references，并随附 Awaken 自有的 doctor、Office/OOXML 校验与重算/渲染脚本。Word 的“接受全部修订”使用独立 LibreOffice profile 输出新文件，超时或任何 Word 文档部件仍残留修订节点必须失败；PPT 渲染拒绝非空旧预览目录并核对注册/渲染页数；Excel 重算只接受 `.xlsx`，在临时副本成功写回后原子替换目标，外链、宏和模板不静默降级。脚本只在 Agent 明确调用 `Bash` 后执行，Desktop 同步/发现/预览均不执行包代码；当前 macOS Desktop 验收基线已覆盖 Word、Excel、PPT 的模型实际生成、内容/结构/视觉 QA、`artifact_publish` 交付卡片和正式关闭/重开后的原线程回放；`code-search` 以内联上下文编排现有 `WebSearch`；`PDF_Max` 不携带 Typst 二进制，由 Agent 按正文检查固定 Awaken toolchain 路径和系统 PATH，缺失时安装固定受测版本；
- bundled 目录为空时显示“内置 Skills 未就绪，重启 Awaken 后重试”，不影响其他视图和 Desktop/Core 启动。
- Skills 页面由最外层 Desktop 内容区拥有唯一纵向滚动；居中的内容层只负责最大宽度与左右留白，不拥有独立滚动，因此页面滚动条始终贴近内容区右边界，而不会随内容列向内缩进。滚动 owner 使用对称的稳定 scrollbar gutter：无滚轮与有滚轮状态预留相同空间，切换来源或搜索结果导致纵向溢出变化时，标题、工具栏和卡片网格不得发生横向位移。
- Skills 工具栏缩窄时保持四个来源标签单行完整显示，搜索框在 `360px` 到 `160px` 之间优先随可用宽度收缩；视口进入窄屏断点后，标签和搜索框再切换为上下两行，避免用标签换行承担搜索框的固定宽度。
- Awaken、项目、全局与 Agents 的 Skill 条目全部直接消费 Design System `AwakenSkillCard`，不保留 Desktop 私有卡片实现。卡片固定为 `78px` 高，图标为 `36px`，描述只显示一行并截断，右侧使用 compact 开关；来源以弱化小字紧跟 Skill 名称，不显示“可预览 SKILL.md”文案，也不显示删除操作。内容长度或来源类型不得改变卡片高度。
- Skills 页面可见期间，Renderer 每秒只重新请求一次各已知项目根的 Skill Catalog；Core 的列表请求每次从本地来源重扫，因此 Finder、终端或其他进程对 Skill 包的新增与删除会自动反映到来源卡片、项目数量和已打开的项目窗口，不要求用户点击刷新。后台同步失败时保留最后一次成功快照，工具栏刷新仍作为显式重试入口；若当前预览条目从 Catalog 消失，项目预览回到同一个项目列表/空态，独立预览则关闭。
- Desktop 项目 Skills 视图与 Design System 的 Skills 组合都直接消费原子 `AwakenFolder`，使用 `dense` 尺寸并按可用宽度自动填充列；无论只有一个还是多个项目，文件夹都必须从容器左侧开始、按从左到右的顺序排列，让宽屏优先容纳更多项目，不得因空列折叠而将少量项目居中。文件夹名称在卡面和辅助技术 `aria-label` 中表达，按钮不添加会触发操作系统原生悬浮提示的 `title`。点击文件夹打开受控的 `AwakenProjectSkillsDialog`，主页面不再向下追加项目详情面板。项目名称只在窗口标题中出现，内容区不重复名称，只保留完整路径、数量和 Skill 卡片。项目窗口与记忆库浏览采用相同的持续挂载模式：点击卡片主体时保留同一个 Dialog 节点、遮罩和稳定尺寸，只把列表内容切换为 `SKILL.md` 预览；关闭预览后在同一窗口切回原项目列表并恢复卡片焦点，不卸载项目窗口，也不在主页面上另开第二个 Dialog。独立预览直接消费 Design System `AwakenSkillPreviewDialog`；项目窗口内的预览消费同目录导出的 `AwakenSkillPreviewContent` 与 `AwakenSkillPreviewDeleteButton`，两条路径不保留 Desktop 私有预览 DOM 或视觉 CSS。project/user 的删除入口只出现在预览底部；project 删除确认继续在同一项目窗口内切换，取消或成功删除并刷新后返回原项目列表。这些 Design System 组件只拥有 UI，项目数据、预览读取、删除、启停与过期请求隔离仍由 Desktop 注入。

### `SKILL.md` 只读预览

bundled、project、user、agents 等所有可预览本地来源统一使用约 `820 × 720` 的固定阅读 Dialog，只有视口不足时才自适应收缩，不随 Markdown 长短改变窗口高度。项目 Skill 在持续挂载的项目窗口内切换到该阅读比例，其他来源使用同尺寸独立预览；项目列表本身仍保持约 `980 × 640`。预览顶部固定展示图标、Skill 名称、紧邻名称的来源小字、说明和启停开关；中间只有带边框的 `SKILL.md` 阅读区滚动；project/user 在底部左侧显示删除入口，bundled/agents 不显示。没有“立刻试用”、复制、编辑或包内资源/脚本列表。关闭按钮保留 `aria-label="关闭"` 供辅助技术使用，鼠标悬停或键盘聚焦时不显示可见 tooltip 或原生 `title` 提示；Dialog 标题仍以 visually-hidden 形式提供给辅助技术。

正文是 Dialog 中唯一的纵向滚动容器，并作为初始焦点，因此鼠标滚轮、触控板、方向键、Page Up/Down、Home/End 都作用于完整文档。关闭后恢复卡片焦点；关闭或切换条目时回到顶部，较早请求晚返回时不得覆盖当前条目。

滚动内容固定按以下顺序展示：

1. 包含原始 `---` 分隔线、字段顺序和未知字段的完整 YAML frontmatter，以安全的 `<pre><code>` 文本直接排在正文流中，不添加独立卡片边框、圆角或底色；
2. frontmatter 之后的完整 Markdown 正文，支持 GFM 标题、列表、表格、代码块、引用和只读任务列表。

frontmatter 直接排在正文流中，不添加独立卡片边框、圆角或底色；fenced code block 保留代码容器的边框、圆角和底色。代码块与宽表格只允许自身横向滚动，不建立第二个纵向滚动区。预览关闭 raw HTML、脚本、Mermaid 执行和外部图片请求；相对链接不解析，只有 `http`/`https` 外部链接可点击。主题色、遮罩、代码、表格、引用、链接和滚动条全部来自 Design System token，Dialog 打开时切换浅色/暗色会立即继承新 token。

## 内置资源同步

Desktop 在启动 Core 之前同步内置资源：

```text
开发版 <appPath>/resources/system-skills
安装版 <resourcesPath>/system-skills
                    │
                    ▼
        ~/.awaken/skills/system-skills
                    │
                    ▼
 AWAKEN_BUNDLED_SKILL_DIRS（Desktop 固定注入）
                    │
                    ▼
        Core 现有 /v1/skills Catalog
```

Desktop 先清除登录环境继承的 `AWAKEN_BUNDLED_SKILL_DIRS`，再注入上述产品固定目标，Shell profile 不能改变产品内置来源身份。同步不新增 HTTP route、Core 特权或 Renderer 文件访问能力。

目标中的 `.manifest.json` 是 Desktop 内部协议，`schemaVersion` 固定为 `1`，包含 `appVersion` 和按 POSIX 相对路径排序的 SHA-256 文件表。每次启动都重新扫描源与目标；清单文件本身不能代替实际文件核对。缺失、修改、额外文件或版本变化都会触发完整目录替换。

同步只接受真实目录和普通文件，拒绝 symlink、特殊文件和源中的保留 `.manifest.json`。更新使用目标同父目录下的 staging、backup 与 rename；中断遗留会在下一次启动先恢复，交换失败则恢复最后完整目标。

## 失败与恢复

- 源缺失、源非法或首次同步失败：记录结构化 `system_skills_sync_failed`，Core 以无 bundled Skill 的状态继续启动；
- 已有完整目标但升级失败：保留或恢复旧目标，Core 继续使用它；
- 用户手工修改 Desktop-owned 目标：下一次成功同步按资源源覆盖；
- 目标同步成功但没有实际 Skill 子包：Awaken Skills 保持空态，不生成 invalid 卡片。
- 预览读取与 Catalog 同步之间发生文件消失、身份过期、路径/realpath 校验失败、非 UTF-8 或超过 2 MiB：读取请求在正文区域显示明确错误；后续 Catalog 同步确认条目消失后按上文退出该预览。不展示截断内容，也不回退为 Renderer 直接读文件。

## 当前不支持或待验收

- Typst `PDF_Max` 的真实模型端到端调用（生成文件 → strict compile → 逐页视觉 QA → `artifact_publish`）尚未完成实机验收；本轮 Office 验收不改变该缺口；
- Office 包内工作流目前只有 macOS 真实 Desktop 验收证据；Windows 与 Linux 仍无实机证据；
- 本合同不改变 MCP、Skills runtime、Workbench 布局或 Office 生成依赖；LibreOffice、Poppler 仍是用户机器上的系统依赖，不随 App 分发。

## Owner 与自动化

- `apps/desktop/src/main/system-skills-importer.ts`：路径、清单、校验、恢复与原子交换；
- `apps/desktop/src/main/runtime-supervisor.ts`：清理继承变量并注入固定 bundled 根；
- `apps/desktop/src/renderer/ExtensionsView.tsx`、`SkillPreviewDialog.tsx`：Tab、来源筛选、标签、空态，以及预览读取、过期请求隔离、项目窗口状态、启停和删除副作用适配；不拥有 Skill 卡片、项目窗口或预览的视觉 DOM/CSS；
- `Awaken Design System/src/components/AwakenDialog`、`AwakenMarkdownRenderer`、`AwakenFolder`、`AwakenSwitch`、`AwakenProjectSkillsDialog`、`AwakenSkillCard`、`AwakenSkillPreviewDialog`：大尺寸/隐藏标题/初始焦点、安全 Markdown、共享项目入口与开关原子视觉，以及完整项目窗口、预览内容、加载/失败状态和受控删除入口；
- `apps/desktop/electron-builder.yml` 与 `scripts/clean-desktop-package.mjs`：资源打包与源资源保留；
- 对应测试覆盖同步矩阵、Runtime 环境、Renderer 视图与打包生命周期；测试不使用真实 `~/.awaken`。
