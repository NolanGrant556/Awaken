# 安装与激活契约

## 1. 目录暴露

模型只看到一个 `skill` 工具，而不是每个 Skill 一个 tool schema。其输入是 Skill ID/名称与可选参数。目录描述预算约为模型上下文窗口的 1%，按约 4 chars/token 估算；默认上限约 8,000 字符，单条说明最多约 250 字符，超限时退化为 names-only。这样目录规模不会线性挤占任务上下文。

Desktop 管理面投影 `sourceOrigin`、锚定路径、状态、诊断、deprecated warning、shadowed owner、`userInvocable`、`modelInvocable` 与最近调用时间。Slash 只展示 `loaded && userInvocable != false` 的条目，不以来源限制 project/user；MCP、plugin 等来源满足条件时也可以出现。

## 2. 调用与正文加载

调用有两条入口：

- 用户显式 Slash token：即使 `disable-model-invocation` 为真仍可调用；
- 模型调用统一 `skill` 工具：`disable-model-invocation` 为真时拒绝。

Runtime 以 token 中的 Skill ID 查当前 registry，并核对当前来源与锚定路径；renderer 路径不是授权来源。激活成功后才更新最近调用时间。

正文在调用时从锚定 `SKILL.md` 或 MCP body fetcher 重新读取。注入上下文包含正文、包根和锚定路径，便于后续按需重读；安装时或目录发现时不 preload 全包资源。

用户从 composer 选择 Skill 时，成功的预激活还会产生 host-owned `ComposerSkillSelection`。该绑定只在当前 run 有效，包含 `skill_id`、registry 校验后的 `source`、`activation_mode`、`invocation=user_composer`、Skill 绝对包根和 `SKILL.md` 绝对路径。

RequestBuilder 在 Skill 正文之后追加该选择块，因此正文不能伪造宿主选择。单选时，用户说“这个”或“刚选的 Skill”直接指向该 identity；多选时按 token 顺序保留并标记单数指代歧义。历史恢复、model-invoked Skill 和 fork child 可持有各自 SkillContext，但不会冒充父 run 的本轮 composer 选择。

## 3. 包资源

`skill_resource_read` 对包内文本资源提供专用读取边界：

- discovery 在 `SkillDefinition.SourceRoot` 记录 host-owned source root，并同时固定包 `ResolvedRootDir`；读取时重新解析当前包 realpath，包根改变即拒绝；
- project/user/managed/additional/plugin/bundled 和 nested legacy 都从 source-root `os.Root` 打开，包必须是该授权 root 的单层子包；flat legacy command 与 MCP Skill 不暴露本地包资源；
- 拒绝 symlink escape、目录、特殊文件和包外路径；
- 单文件最大 2 MiB；
- 只返回 UTF-8 文本；二进制返回 `skill_resource_binary`，调用者改用对应 file/artifact 工具。

`skill_resource_read` 不返回二进制字节；binary assets 仍转交匹配的 file/artifact provider，并继续受其 TaskScope/readiness 契约约束。

## 4. 工具与依赖语义

Skill 激活不会修改 `RunToolAvailabilitySnapshot`，也不会注册 per-Skill 工具。`allowed-tools`、required tools/capabilities/runtime、connector/MCP readiness 都只作为选择提示、诊断或 receipt。真正能否执行由父 run 的固定工具快照、provider readiness 和被选工具的实际合同决定；Skill 不得通过正文扩大 typed provider 的权限，但默认 raw Shell 本身就是当前登录用户的本机执行面，不要求 Skill 专项授权。

这意味着“Skill 可加载”与“它建议的某个执行路径当前可用”是两件事；后者失败时返回结构化工具结果，不回写成 Skill `unavailable`。

Skill 包中的 `.py`/`.mjs`/`.sh` 等脚本在 discovery、安装或激活时都不由宿主自动执行。它们在用户/模型根据 Skill 工作流显式发出 Shell 调用时，以当前登录用户的真实本机环境执行。这条路径可以读写 Skill root、用户缓存和 workspace 外目录，也可以访问网络；它不再依赖 private Workspace staging、Seatbelt 或 TaskScope 先行批准。Shell receipt 只证明直接本机进程事实，不冒充全部脚本副作用的可恢复保证。

首次初始化由 Skill 正文指导 Agent 自行执行，例如在包根 `npm install` 或 `pip install`。依赖可驻留在用户级 Skill 目录中供后续 run 复用；Awaken 不需要根据 `package.json`、requirements 或某个 Skill ID 建立私有安装器。

## 5. SemanticJournal、压缩与重启

成功激活在执行前写入 `skill_activated`；资源读取写 receipt。inline Skill 上下文可从耐久记录重建：

- 压缩时按最近调用优先；
- 单 Skill 最多约 5,000 tokens；全部 Skill 合计最多约 25,000 tokens；
- 被截断的上下文保留锚定路径和重读提示；
- 服务重启从 semantic records 恢复 run 的 SkillContextBlocks。

fork 的正文属于 child，不注入父 run 的后续上下文；父子调用记录不得互相污染。

## 6. 安装边界

`skill_install` 当前支持 `content`、`content_base64`、`local_path`、`remote_url` 和 `remote_git`，目标只有 project（默认 `<workspace>/.awaken/skills`）或 global/user（`~/.awaken/skills`）。包可以是 `SKILL.md`、zip 或含唯一根 `SKILL.md` 的目录；最多 1,000 个文件、解包内容 50 MiB，拒绝 symlink、路径逃逸和非法包。

`remote_git` 只接受无 inline credential 的绝对 HTTPS URL，可选安全 ref/subpath；Git 禁用 credential helper、交互、file/ssh/git/http protocol，并使用最小环境。这是 `skill_install` typed provider 自身的来源合同，不限制 Agent 在 Skill 已安装后按正文使用默认 Shell 准备依赖。

同 ID 默认 `abort`。显式 `replace` 通过 staging、旧包 backup 和新包原子 swap，再将旧包移入平台 Trash；Trash 失败会回滚新旧包并 fail closed，不永久删除。Outcome 记录 `previous_package_trashed_path`（平台可提供时）。安装后默认 reload registry，也可显式关闭。安装成功的 next action 指向统一 `skill` 工具，并携带 `input_hint.skill`。安装器不得在发现、解包或激活阶段擅自执行包代码；Skill 进入 Agent 上下文后，初始化命令由 Agent 通过普通 Shell 调用显式执行，并以真实命令输出进行恢复。

## 7. 代码 owner

- `src/skillruntime/catalog_tool.go`、`manager.go`、`resource_tool.go`：调用、正文和资源边界。
- `src/skillruntime/install_tool.go`、`install_git.go` 与 `src/skills/install.go`：受控来源、包校验、原子安装和 Trash replace。
- `src/agentcore/skill_context.go`、`composer_skill_selection.go`、`request_builder.go`、`agent.go`、`runner.go`：运行上下文、当前 composer 选择绑定、压缩恢复和 fork 接线。
- `src/runtime` SemanticJournal 链路：耐久顺序与重启恢复。
