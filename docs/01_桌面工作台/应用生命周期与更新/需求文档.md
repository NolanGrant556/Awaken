# 应用生命周期与更新 · 需求文档

Desktop 负责应用启动、窗口、退出和更新安装。自动更新的实现状态与正式发布、真实升级验收分别记录。

代码、接口和验证方法见[实现方案](实现方案.md)。

## 范围与实现状态

本节说明 Awaken Desktop 应用版本、GitHub Releases 更新源、更新状态机、左侧栏更新交互、下载与重启安装边界、失败恢复以及发布准入契约。Desktop 通用进程生命周期、签名、公证和安装包验收仍由 [Desktop 生命周期与发布架构及验收契约](实现方案.md) 拥有；本文只增加其上的版本和更新协作。

### 无签名安装包更新

从 `0.1.2` 起，ad-hoc macOS 和未签名 Windows 安装包使用独立的 `unsigned` 更新通道。已发布的 `0.1.1` 内置更新器关闭，不能被远程激活；用户需要先手动安装一次新基线。开发版、Gallery 与普通本地包仍不检查更新。

客户端仅从本仓库的公开普通 Release 发现更高版本，不接受草稿或预发布。提示、下载进度、“稍后”和重启确认沿用侧栏入口。仅点击下载才开始下载；重启前仍须确认所有任务已停止。macOS 使用对应架构 ZIP，Windows 使用 x64 NSIS，下载大小和 SHA-256 必须符合该版本的清单。此通道不验证 Apple 或 Windows 发布者身份；HTTPS 和同一 Release 的校验值用于来源和传输完整性校验，不能证明发布账号未被入侵。

macOS 在可写安装目录中准备新应用，关闭旧客户端后替换并重启。新应用无法创建主窗口时恢复旧应用；无写权限时保留原版本并提示失败，不修改用户数据或自动提权。Windows 打开安装向导，用户仍须确认系统权限和安装步骤；取消或安装失败时可继续打开旧版本。网络、元数据、校验或准备失败时保留当前可运行版本并允许重试。重启后需重新检查和下载，不复用上次“已下载”提示。

该通道的本次自动化与真实安装验收范围由[实现方案](实现方案.md#无签名更新通道)记录；签名稳定通道的验收结论不由此改变。

### 稳定更新的目标行为

下面这些行为已经接到安装版代码。本仓库 Release 还没有带 `latest*.yml` 的稳定版本，正式发布 workflow 也还没有一次成功记录，所以签名稳定通道仍未完成验收。

- 稳定版更新以 `NolanGrant556/Awaken` 的公开 GitHub Releases 为唯一发布源。`vX.Y.Z` 正式版提供 `latest*.yml`；`ci-<commit>` 预发布不提供更新索引，客户端不使用。客户端不携带 GitHub Token。
- 首发范围为安装版 macOS arm64/x64 和 Windows x64 NSIS；Windows arm64、开发版、ad-hoc 包和 Linux 禁用更新器。Windows arm64 只能在独立构建、签名、安装与升级矩阵通过后扩展，不从现有 resources 理论支持推导已发布。
- 发现新版本时只提示，不立即下载。用户点击 `aw-sidebar-profile` 中的更新按钮后才在后台下载；下载完成后必须提示“立即重启”或“稍后”，不在用户仍工作时强制退出。
- 只接受签名、公证/平台验签、版本和元数据全部通过的更新；失败时保留当前可运行版本。
- 安装包发布在公开的 `NolanGrant556/Awaken` Release 上。DMG、ZIP、NSIS 及其承载的客户端实现和资源可被任何人下载分析。任何不能公开的密钥、算法材料或服务端能力都不得进入安装包。

## 产品行为与界面契约

### 自动检查

1. 只有 `app.isPackaged`、版本为严格 stable SemVer、平台/架构受支持且包内 `awakenUpdateChannel=stable` 时启用更新管理器。`Awaken Dev`、Gallery、普通本地包、普通本地包和测试 fixture 默认写入/读取 `disabled`，不访问 GitHub；显式 `unsigned` 安装包按[无签名安装包更新](#无签名安装包更新)处理。
2. Renderer ready 后延迟首次检查，不阻塞窗口、Core 启动或恢复会话。安装版运行期每 6 小时最多自动检查一次；网络恢复或应用再次激活只在距上次尝试超过 30 分钟时补检。
3. 稳定版只接受非 draft、非 prerelease 且 SemVer 严格高于当前版本的 Release；禁止降级、同版本覆盖或从 Renderer 替换 feed URL。
4. 检查失败不弹出阻断式错误，不影响主产品路径；只在用户已看到更新或主动重试后显示可操作错误。

### `aw-sidebar-profile` 更新入口

`AwakenSidebar` 的 `aw-sidebar-profile` 保留底部固定区 ownership，更新按钮放在账户按钮上方、分隔线下方，不进入中部项目滚动容器。它与个人菜单是两个独立按钮，点击更新不得触发 `onProfileClick`。

| 状态 | 按钮表现 | 用户操作 |
|---|---|---|
| `disabled` / `idle` / `checking` / `current` | 不显示 | 无 |
| `available` | “更新到 vX.Y.Z”，使用现有强调色但不抢占个人入口 | 开始下载 |
| `downloading` | “正在下载 X%”，原位显示进度，不改变指针 | 防止重复请求 |
| `downloaded` | “重启完成更新” | 打开重启确认框 |
| `error` | “更新失败，点击重试” | 按错误阶段重新检查或下载 |

存在运行中或正在取消的主任务/子任务时，不得静默终止它们。当前确认框首次打开时“立即重启”仍可点击；用户点击后 Main 才现查 activity snapshot。若返回 `active_runs`，则不执行 shutdown，确认框保持打开并说明需等待任务结束或先使用现有取消入口，同时禁用当前框内的再次重试；关闭后从侧栏重新打开可再发起一次 Main 现查。更新管理器不新增绕过 run ownership 的强制取消。

## 运行中的有界退出

退出时撤回正在等待的问题并保留运行停止来源。等待清理时不显示已经停止；Core 真正退出后才释放所属进程。超时、强制终止或清理错误阻止更新安装，允许用户查看失败原因。重开只恢复已有记录，不自动重发模型或有副作用调用。具体期限与 owner 分工见[本地服务管理](../../03_运行时与本地服务/本地服务管理/实现方案.md)。
## 共享依赖与执行路径

依赖资源使用独立的不可变发行版本，用户不需要 GitHub 凭据。依赖准备不进入 Desktop 稳定更新通道；当前依赖资源尚未公开发布。目录、来源、安装和回收规则见[依赖与路径管理](../../03_运行时与本地服务/依赖与路径管理/需求文档.md)。
