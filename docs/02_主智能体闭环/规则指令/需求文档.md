# 规则指令 · 需求文档

用户可维护全局和项目 AGENTS.md。每次运行固定使用一份指令快照，运行中修改文件不会悄悄改变已开始的任务。

代码、接口和验证方法见[实现方案](实现方案.md)。

## 当前支持

Awaken 在每次 `StartRun` 中读取两种用户指令：

- 全局来源固定为 `~/.awaken/AGENTS.md`；
- 项目来源固定为当前项目主文件夹的 `<primary-root>/.awaken/AGENTS.md`。

多文件夹项目只把主文件夹作为项目指令 authority。次文件夹的 `.awaken/AGENTS.md` 仍可在右侧文件工作区按普通 Markdown 查看和编辑，但不进入模型上下文。切换主文件夹不会改变已经开始的 run；下一次 `StartRun` 从新的主文件夹读取。

首版不发现根目录 `AGENTS.md`、`AGENTS.override.md`、嵌套目录文件，也不提供 `/init`。缺失来源是正常状态，不产生 warning。

## 优先级与模型上下文

优先级固定为：Awaken system/安全规则 > 当前用户直接指令 > 项目 AGENTS > 全局 AGENTS。非冲突规则合并，项目规则覆盖全局冲突项。AGENTS 内容不能扩大 TaskScope、工具池、Hook/Computer policy、凭据或路径权限；ToolRuntime 和对应安全 owner 始终是最终执行边界。

RequestBuilder 使用 `ContextEnvelope.UserContextItems` 生成 request-only synthetic user prefix。该前缀位于 conversation messages 之前，当前直接 user message 仍具有更高优先级；正文不拼入 system prompt，不追加到 Conversation，也不进入 `user_message`、SemanticJournal 或 AG-UI。默认 system prompt 只包含稳定的作用域、优先级和冻结规则。

## 边界、截断与诊断

每个来源最多向模型注入 16 KiB，两个来源合计最多 32 KiB。超限内容保留有界前缀并在 16 KiB 总预算内追加明确截断标记；摘要记录 original/applied bytes 和 `truncated=true`。非法 UTF-8 使用 U+FFFD 替换并产生 warning。

加载前后核对 regular-file identity、size 和 modification time；读取中变化会重试一次，仍变化则跳过。不可读、非普通文件或解析后的路径越出对应全局/项目根时跳过该来源。单一来源失败时继续使用另一来源并把 snapshot 标为 `partial=true`；两个来源都失败仍允许 run，但安全摘要和 Composer 必须显示 diagnostics。

## 用户入口

Settings 导航的“全局规则”栏目拥有全局 `AGENTS.md` 编辑入口。页面使用极简文档布局，顶部只用一行显示文件图标、文件名和启用状态，不向用户展示本机路径；其余只保留 Markdown 编辑器、UTF-8 字节用量和底部操作，不重复展示功能简介、路径卡片、覆盖关系卡片或独立安全说明。编辑器显示 16 KiB 模型注入上限，使用受控高度且不允许纵向拖大，长内容在编辑器内部使用与设置框架一致的轻量滚动条，常用窗口高度不因编辑器产生右侧整页滚动条。冲突时项目规则优先、仅影响新任务和不得写入密钥三项必要提示压缩为底部单行；保存/删除、revision 冲突恢复和成功状态复用同一状态位置。

项目文件继续由右侧文件工作区拥有。`.awaken/AGENTS.md` 随普通目录树自然展示并复用 Markdown 预览/编辑；主文件夹缺失该文件时显示“创建 AGENTS.md”。Main 必须重新查询 active project 和当前 primary folder，原子创建 `.awaken/AGENTS.md`，初始内容仅为 `# 项目指令`，绝不覆盖已有文件；成功后直接打开编辑标签。不在添加项目时自动创建。

次文件夹中的同名文件是普通 Markdown：文件行明确标记“普通 Markdown”，可显示、编辑，但不显示生效标识，也不计入当前运行来源。

## 保存与冲突

全局页面使用 Core `expected_revision` CAS。收到 `INSTRUCTION_REVISION_CONFLICT` 时保留本地草稿，提示重新加载后人工合并，不静默覆盖外部内容。

项目 Markdown preview 返回 `contentDigest`。保存 `.awaken/AGENTS.md` 必须携带 `expectedDigest`；Main 在原子 replace 前复核当前 digest。外部内容已变化时返回 `FILE_CHANGED`、current digest 以及 current/submitted content，编辑器保留两个版本并允许重新加载或恢复本地草稿。其他 Markdown 保持现有保存语义。

## 运行摘要与界面可见性

Composer 输入框下方不显示 AGENTS 来源数量，RunStage 也不提供本次快照来源面板。用户只通过 Settings 的“全局规则”和右侧项目文件工作区管理规则；保存、删除或切换主文件夹仍只影响下一次运行。

Renderer 仍接收并保留安全的 `instruction_snapshot` 摘要，供 SSE 重连、transcript replay 和运行恢复保持一致，但不展示正文、来源路径卡片或独立 Composer 状态。来源加载失败仍不会阻断 Composer 提交；旧 run 没有摘要时不补造。
## 共享依赖与执行路径

主 Agent 与子 Agent 都应先取得普通办公任务的完整共享环境，按返回路径执行，不在业务项目私装任务支撑依赖。软件项目自身的构建依赖仍遵守项目约定。目录、来源、安装和回收规则见[依赖与路径管理](../../03_运行时与本地服务/依赖与路径管理/需求文档.md)。
