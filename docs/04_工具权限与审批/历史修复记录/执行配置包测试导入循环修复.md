唯一剩余的阻塞是 `go test ./src/tool/profile/...` 出现的 **测试导入循环**。本计划仅修复该循环并完成最终验证与汇报，不再新增功能。

## 当前状态分析

### 循环成因（已通过探索确认）

- `src/tools/shell/executor.go`（第 13 行）`import "awaken/src/tool/profile"`，用于调用 `profile.WithEnvPolicy` / `profile.EnvPolicyFromContext` / `profile.EnvMinimal`（子任务 1.5 引入）。
- `src/tool/profile/intent_test.go`（第 1 行）声明为 `package profile`（**内部测试**），第 11 行 `import shelltool "awaken/src/tools/shell"`，用于构造 `shelltool.ShellTool{}`。

Go 内部测试（`package profile`）会被并入 `profile` 包的导入图，于是形成：

```
profile (含 intent_test.go) → tools/shell → profile
```

编译报错：
```
package awaken/src/tool/profile
        imports awaken/src/tools/shell from intent_test.go
        imports awaken/src/tool/profile from executor.go: import cycle not allowed in test
FAIL    awaken/src/tool/profile [setup failed]
```

### 关键事实（探索确认）

1. `intent_test.go` 是 profile 包中**唯一**导入 `tools/shell` 的文件（也是唯一导入 `tools/apply_patch` 的文件）。
2. profile 包其余 4 个测试文件（`context_test.go`、`registry_test.go`、`profile_test.go`、`decision_test.go`）均为 `package profile`，但都不导入 `tools/shell`，不参与循环，**无需改动**。
3. `intent_test.go` 引用的 profile 符号**全部是导出符号**：`InferToolKind`、`InferNetworkScope`、`BuildExecutionIntent`、`ToolKindFileChain`/`ToolKindShellCommand`/`ToolKindMcpApp`/`ToolKindReviewAgent`、`ActionWrite`/`ActionDelete`/`ActionMove`/`ActionExecute`、`NetworkScopeOpen`/`NetworkScopeNone`/`NetworkScopeRestricted`、`SubagentOrigin`、`ExecutionIntent`（及其导出字段 `ToolName`/`ToolKind`/`RequestedAction`/`Paths`/`NetworkScope`/`WorkspaceRoot`/`WritableRoots`/`SubagentOrigin`，`SubagentOrigin` 的 `AgentID`/`ParentAgentID`/`IsGuardian`/`Depth`）。
4. `intent_test.go` 中唯一的辅助函数 `mustMarshalArgs` 定义在该文件内部，不依赖其它内部测试文件的私有 helper。
