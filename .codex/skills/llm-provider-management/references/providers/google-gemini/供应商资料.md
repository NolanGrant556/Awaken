## Awaken 当前接入

- provider ID：`google`；access type：`api`。
- 推理 Base URL：`https://generativelanguage.googleapis.com/v1beta/openai`。
- 当前默认模型：`gemini-3.6-flash`。
- 当前只走 Google 的 OpenAI-compatible Chat；模型目录使用 Google 原生 Models API。
- 当前协议合同确认图片输入；Gemini 原生 PDF/video/cached content 不自动成为此 Chat adapter 的能力。

## 三协议兼容矩阵

| 协议 | 官方合同 | Awaken 当前 | 结论 |
| --- | --- | --- | --- |
| Chat Completions | Google 提供 OpenAI compatibility | 已接入 `openai_chat` | 支持当前兼容子集 |
| Responses | 当前 Awaken 供应商入口未声明 | 未接入 | 不支持；官方若新增也需独立 adapter 验证 |
| Messages | 无 Gemini 原生合同 | 未接入 | 不支持 |

## 鉴权、端点与模型

- Awaken 当前兼容入口使用 Bearer API Key；官方也可能展示 `x-goog-api-key` 的原生调用方式，不能跨 route 混用。
- Chat endpoint：兼容 Base URL 下的 `/chat/completions`；模型目录走原生 Models API，不从兼容 `/models` 猜 capability。
- 区分 Gemini Developer API 与 Vertex AI；项目、区域、鉴权、配额和 endpoint 不同。
- 模型 ID、preview/stable 版本、窗口和下线日期以当前模型页为准。

## 上下文、多模态与工具

- 官方原生 Gemini 支持图片、文档、视频和 function calling 的范围很广，但 Awaken 当前必须按 OpenAI compatibility 页收窄。
- 当前只确认兼容 Chat 的图片输入；原生 PDF/video 不标为当前支持。PDF Read 使用页面渲染回退。
- 兼容层的 tool schema、tool choice、并行调用和 stream 事件需单独测试；不能引用原生 SDK 示例证明。
- context window、output limit 和 thinking 参数按 exact model 解析。

## 提示词缓存

- Gemini 原生 GenerateContent 支持显式 context cache；当前文档也描述某些 API 的隐式缓存。
- Awaken 当前 OpenAI-compatible Chat 未接入原生 `cached_content`，`src/llm/prompt_cache_capability.go` 也未为 Google 建立 exact wire 合同。
- 因此当前写作：供应商原生支持，Awaken 兼容 Chat 未接入；不得显示“已命中/未命中”缓存徽标。

## 推理开启关闭

- Gemini thinking 使用 `thinkingConfig`/`thinking_level` 等原生合同；当前 OpenAI-compatible Chat 明确接受顶层 `reasoning_effort`。
- 是否能关闭取决于模型和协议。不要把 `thinking_level=minimal`、预算 0 和通用 `thinking=false` 视为同一行为。

## 推理强度

- 先看 exact model 的 thinking level，再按 OpenAI compatibility 的映射发送 `reasoning_effort`。
- Awaken 当前内置 Gemini 模型展示统一 `low | high`，默认 `high`；Core 只对白名单中的 `google + gemini-* + openai_chat` 发送这两个原生值，不伪造 `max`。
- 原生 `thinkingConfig` 字段不能直接注入通用 Chat adapter；需要另建 provider/base/protocol/model 白名单。

## 用量、余额、限流与套餐

### 用量查询合同

- A 类：API usage 随响应返回；配额和 rate limit 按项目、模型和计费层级变化。
- D 类：Cloud Monitoring 的 `projects.timeSeries.list` 可查询 `generativelanguage.googleapis.com` 下的 token、quota usage/limit/exceeded 等项目级指标。
- E 类：AI Studio Dashboard 显示项目使用情况和预付余额；当前官方 billing 文档没有给普通 Gemini API Key 公开余额 endpoint。
- 凭据：Cloud Monitoring 需要 Google OAuth/服务账号、project ID 与例如 `roles/monitoring.viewer` 的只读权限，不能拿普通 Gemini inference API Key 调用。
- Awaken 当前：未接入 Google 管理查询，并正确提示“普通 API Key 没有公开余额接口”；未来可新增独立管理凭据查询 usage/quota，但预付余额仍需引导 AI Studio。

- Google AI Studio 免费层、付费 Gemini API 与 Vertex AI 不是同一套餐或 quota 域。
- 缓存、长上下文和多模态 token 计费以当前 pricing 页为准；不要长期复制数字。
- 显示本地请求 usage 时要标清来源，不能冒充 Cloud Monitoring 或账单数据。

## Awaken 落地规则

- 始终区分“Gemini 原生能力”与“OpenAI-compatible Chat 当前能力”。
- provider route 负责兼容 Base URL，Google catalog strategy 负责原生模型目录；两者缓存 identity 不混用。
- 新增 native Gemini adapter 是架构扩展，不是给现有 Chat profile 多加几个 capability 标记。
- 连接测试不能证明 native PDF、video、cache 或全部 thinking 档位。
