## 安全与行为矩阵

| 场景 | 最小证据 |
| --- | --- |
| Definition/exposure | strict/adapted 质量；普通与 compat 工具池；池外调用拒绝 |
| profile/scope | allowlist、篡改替换、writable/output、symlink、敏感路径 |
| 本地只读 | workspace 内外绝对路径与 attachment 歧义，确认现有宽边界 |
| decision/outcome | allow、deny、needs-auth/runtime、unsupported、mass-message review、transform guard |
| pairing | 每种阻断/取消/失败仍产生一一对应 tool result |
| failure supervisor | retryable/non-retryable、resource variation、turn/run budget、recovery directive |
| Shell | exit/neutral/timeout、direct delete/Office 拒绝、无 OS sandbox/无进程树终止/自由文本不完整脱敏的诚实边界 |
| typed files | digest 冲突、atomic text_edit、非事务 patch partial、trash failure fail-closed；确认 trash 路径门禁当前缺口 |
| artifact | producer、runtime missing、失败无假 artifact、持久化与安全打开 |
| audit | sink 写入测试；同时确认 run audit endpoint 当前为空的已知缺口 |

## 真实 Desktop

在专用测试 workspace 执行只读搜索、typed 文本创建/编辑、可恢复删除、一个 Shell 诊断、一个 artifact 任务和一个预期失败。观察 tool activity、最终 status、diff/artifact 和重启重放一致性。

群发消息只用 mock/fixture 走审核，不连接真实账号或发送消息。不得点击会修改用户 MCP、模型、Skill、宠物或 connector 状态的操作。普通 run 不应出现通用 ApprovalCard；若出现，记录为当前产品/代码差异，不把旧文档恢复为规范。

## 完成条件

- 测试同时覆盖请求侧和执行侧 gate，不能只测 policy 返回值。
- 所有失败/取消/阻断保持 tool pairing 和 canonical outcome。
- Shell、只读 roots、`trash_file` 路径门禁、Windows trash、audit query、自动 transform 等已知限制没有被写成已支持。
- Desktop 卡片、模型续轮、SemanticJournal 对同一 outcome 的结论一致。
- 删除/外发/凭据相关测试只在隔离环境，且无永久删除 fallback。
