# 外观与主题 · 实现方案

本文说明代码职责、数据与接口、异常恢复和验证方法。功能范围及用户操作见[需求文档](需求文档.md)。

## 存储与启动

最终来源是Electron Main `DesktopPreferencesStore`：

```text
<userData>/config/desktop-preferences.json
{ "version": 1, "theme": "light|dark|system" }
```

无文件、无效JSON或未知 theme 归一到 light。旧文件中残留的 `fontScale` 字段在读取时忽略，下次写入时不再写出。Renderer另写 localStorage 镜像 `awaken:appearance:theme`，用于React初始状态和减少启动闪烁；main加载成功后覆盖镜像状态。镜像不是最终来源。启动时会清除旧的 `awaken:appearance:fontScale` 镜像和 `html[data-aw-font-scale]`。

DOM应用：

```text
html[data-aw-theme="light|dark"]
html[data-aw-theme-preference="system|light|dark"]
style.colorScheme = light|dark
```

`apps/desktop/src/main/window-background.ts` 的浅色／深色窗口底色分别为 `#F8F8F8`／`#1A1A1A`，与 renderer canvas 对齐，避免启动和加载时出现另一档底色。

主进程保存后只同步更新主窗口背景，避免主窗口在透明/加载阶段露出错误底色；独立透明浮窗（如宠物窗口）保留自身透明背景，不随主题更新。

## 样式职责

- `Awaken Design System/src/tokens/tokens.css` 定义颜色、surface、text、border、status、composer 等通用语义；`base.css` 只持有全局基础规则和共享动画。
- WorkbenchShell、ExecutionFeed、UserPromptBlock、ThoughtTrace、ToolTraceLine、MarkdownRenderer、MermaidDiagram、InspectorRail、TaskWelcome、ComposerBar、SearchSettings 的选择器由各组件自己的 CSS 拥有；局部规则引用 `base.css`，不反向导入整个组件集合。
- 源码 `tokens/components.css` 是兼容 import 入口。`scripts/copy-design-system-assets.mjs` 将编译后的完整 CSS 写入发布目录的同名文件，外部 consumer 不依赖源码组件路径。Desktop 只导入 `tokens.css` 与 `index.css`，避免重复加载同一组件样式；旧公共包入口继续兼容其他 consumer。
- 相同选择器的重复声明按原先后顺序合并；Composer 已与内联值一致的宽度、颜色、字号和行高不使用 `!important`，必要的 padding/overflow 优先级保留。
- 浅色 canvas/work/detail 使用 `#F8F8F8`，navigation/panel/code 使用 `#F0F0F0`，raised/composer 使用白色；深色 canvas/work/chrome 使用 `#1A1A1A`，navigation/detail 使用 `#1F1F1F`，panel/composer 使用 `#242424`，raised 使用 `#292929`。正文主色分别为 `#2F2F2F` 与 `#DEDEDE`；次要和辅助文字保持在 canvas/navigation/composer 上至少 4.5:1 对比度（禁用文字不计入）。设置 shell/main 使用 canvas，表单和弹层继续使用各自语义表面，不把整个设置页当 raised 白色卡片。
- 全产品布尔启停统一使用 Design System `AwakenSwitch`：开启为成功绿色，关闭为中性灰色。关闭只是状态而不是错误，不得以危险红色表达；业务组件只持有状态和回调。
- Desktop renderer只做场景级覆写，不在业务组件按主题分支渲染不同DOM。
- 设置框架及通用设置页布局/样式由 Design System 的 `AwakenSettings` 和各设置组件拥有；Desktop 注入真实状态和回调，并拥有 Computer、Hook、ACP 等产品专用面板。导航条目仍只由 `AwakenSettingsNavItems` 定义。
- 记忆分区的 `AwakenMemoryLightFlow` 只接收 renderer 已解析出的当前生效 `AwakenTheme`；不得为该装饰新增独立主题偏好或设置入口。
- 新颜色先寻找/补充语义token，禁止到处新增hex/rgb magic value。
- 浮层层级只用 `--aw-z-dialog`、`--aw-z-popover`、`--aw-z-tooltip` 三个token表达，禁止在组件里写裸 `z-index` 数字。`AwakenDialog`、`AwakenPopover`（含 `AwakenDropdown`）、`AwakenTooltip`、`AwakenProjectHoverCard` 都 portal 到 `document.body`，彼此在根堆叠上下文里是兄弟；菜单/提示/悬浮卡随时可能由对话框内部控件触发，必须排在对话框之上，否则会挂载成功但被背板遮住，表现为「点了没反应」。
- brand wordmark使用 `--aw-brand-wordmark-filter`。
- 模型厂商图标由共享 `AwakenProviderLogo` 直接显示本地资源，不对任何品牌按主题添加滤镜；图标容器使用不被深色覆盖的 `--aw-provider-logo-surface`、`--aw-provider-logo-border` 与 `--aw-provider-logo-shadow`，固定白色底座与中性细边框、轻阴影。未提供 brand 时，同一组件显示名称首字母，文字使用固定的 `--aw-provider-logo-foreground`；consumer 不再各自创建主题化占位底座。此规则同时用于设置、Composer 与用量面板，不改变 Awaken 自身 wordmark 的主题规则。
- 顶部chrome使用 `--aw-surface-chrome`，dark时不得比主工作区明显更浅。

## Composer主题边界

Dock composer依靠RunStage真实底部留白避让内容；不得用全宽大面积渐变或 `backdrop-filter` 遮住历史。

允许随composer宽度收缩的局部 `--aw-composer-halo` 羽化；禁止重新引入白/灰/黑的全宽矩形雾化区。composer层级使用：

- `--aw-composer-surface`；
- `--aw-composer-border`；
- `--aw-composer-shadow`；
- `--aw-composer-shadow-focus`。

该边界同时受中间区域架构/验收约束。

## 异常与恢复

- 主偏好读取失败：保留localStorage镜像或默认light；
- 保存失败：renderer回滚并提示；
- 未知存储值：归一light；
- system matchMedia不可用：renderer fallback light；
- Main与renderer短暂不同步：最终以main返回偏好收敛。

自动化：

- `apps/desktop/src/main/window-background.test.ts`：显式/系统主题、窗口隔离、原生窗口与 CSS canvas 色值一致，以及三档正文在主要背景上的 4.5:1 对比度。

- `apps/desktop/src/main/desktop-preferences-store.test.ts`：默认、dark、system、未知 theme，以及旧文件残留 `fontScale` 被忽略。
- `apps/desktop/src/renderer/settings/DesktopSettingsDialog.test.ts`：全窗口设置框架、无外层 Dialog，以及三种主题选项和 selected 状态；外观页不含“显示大小”。
- `Awaken Design System/src/components/AwakenThemeChoiceGroup`：Settings 主题选择的 UI-only 实现；Desktop 持有偏好保存与回滚。
- `apps/desktop/src/renderer/settings/MemorySettingsPanel.test.tsx`：记忆光流随当前生效主题渲染，且不改变既有 Memory 设置入口。
- `npm run typecheck:desktop`、`npm run typecheck:ui`、`npm run smoke:ui`。

真实Desktop：

1. 三种偏好逐一切换并确认即时生效；
2. 重启后保持；
3. system下切换OS外观；
4. 检查主工作台、Settings、popover、center/dock composer、按钮、附件；
   同时确认 Settings 覆盖内容窗口、保留原生窗口按钮，左右分栏没有外层弹窗卡片、右上角关闭按钮或底部关闭栏，并可通过“返回应用”和 `Escape` 返回；双击标题、导航、标签与说明不产生文字选择，搜索/配置输入框和显式可复制正文仍可选择；
5. dark下wordmark白色、chrome无浅色横带、附件删除按钮可辨识；
6. light/dark均无全宽矩形composer雾化。

当前中性色板的本机真实验证覆盖 macOS 正式开发入口、1440×903 窗口：浅色／深色首页、历史正文与行内代码、center/dock 输入框、账户主题菜单、外观设置页、深色上下文浮层，以及深色偏好重启保留。两处入口选中状态同步，设置页 Escape 返回正常。截图为本机临时证据 `/tmp/awaken-theme-acceptance/` 中的 `light-home.png`、`dark-home.png`、`light-conversation.png`、`dark-conversation.png`、`light-settings.png`、`dark-settings.png` 和 `dark-context.png`；不随仓库分发，临时目录清除后需按上述步骤重新采集。此次仅切换并确认了“跟随系统”选项，未切换操作系统外观；Windows/Linux、窄窗口、全部设置分区、附件删除与运行中长对话未重新验收，不能由这组截图推断通过。

Desktop 外观生命周期由 `apps/desktop/src/renderer/useDesktopAppearance.ts` 统一持有，`desktopAppearance.ts` 封装偏好/系统主题读取，`desktopStorage.ts` 封装本地镜像访问；App 只把这一份主题和保存动作传给设置与账户视图。Main 仍是桌面偏好的持久化 authority。
