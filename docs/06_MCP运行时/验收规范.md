# 验收规范

## 1. 自动化

至少覆盖：

- user/project/dynamic scope 合并、invalid/disabled、同名 owner 和 remove safety；`enabled:false` 在 Manager 中恢复为 disabled 且不连接，toggle 写回 effective scope；删除 project override 后恢复同名 user fallback；user config 唯一读写 `AWAKEN_HOME/config/mcp-servers.json`，Electron `userData` 与其他旧路径不读取、不迁移、不 fallback；
- `AWAKEN_DEFAULT_WORKSPACE` 为空时 user MCP 配置读取、保存、更新、启停、删除和连接仍可用，project scope 不参与且不回退 cwd、用户主目录或最近项目；配置有效 default workspace 时才加载 `<workspace>/awaken.mcp.json` 并验证同名覆盖；
- stdio/HTTP/SSE initialize、list_changed、局部失败和注销；
- provider manifest/readiness/dependency 投影到 run snapshot；
- metadata-less 明确 read-only（包括 open-world read）自动；metadata-less/无效-metadata 的普通别名 mutation 与 annotations 自相矛盾者在 transport 前以 `unverified_mcp_provider_metadata` 拒绝；有效 metadata 的 ordinary mutation 自动；
- typed individual message auto；mass review；unknown recipient transport 前拒绝；
- remote delete contract 缺失 transport 前 unsupported、结果 recovery evidence 复核；
- artifact output contract/output schema gate；strict base64、hash、size、extension/MIME/kind/container、TaskScope writable+output、workspace/sensitive/protected/symlink；exact broker delta、replace Trash receipt、false-success 无 artifact、direct adapter TaskScope、cancel bounded cleanup、post-commit failure receipt truth和原始 bytes 不进入 Outcome；
- 隔离四路 fixture `TestIsolatedTypedMCPSkillScriptAndShellArtifactRoutes` 对比 Tool Catalog 中真实 `document_create` 与同为 `document.create` 的 MCP provider；installed Skill script/直接 Shell 明确走 supervised Shell 后再 `artifact_publish`，不冒充 typed capability。四路生成与登记同类 Markdown artifact，但该测试不是 Desktop/视觉验收证据；
- DOCX automation 还要用可打开的 OOXML ZIP container 通过 host bridge；该证据不外推为 PDF/PPT 渲染或 Desktop 验收；
- MCP prompt/resource 动态注册、调用时 fetch、list_changed、disconnect 注销；
- OAuth credential ref、scope/name/canonical-endpoint identity、endpoint 变化与删除清理、重启恢复和 secret redaction。

聚焦命令：

```bash
go test -count=1 ./src/mcpclient ./src/connectors ./src/skills ./src/skillruntime ./src/agentcore
```

## 2. Desktop 验收

用隔离 `AWAKEN_HOME` 在真实 Awaken Desktop 验证：先以空 `AWAKEN_DEFAULT_WORKSPACE` 启动，确认设置页能显示 user MCP 的完整 JSON、方法与连接状态，并能添加、修改、enable/disable、删除后重启恢复；确认 Electron `userData` 或其他旧位置放置的同名配置不被读取、迁移或改写。若本次 Desktop 启动提供有效 default workspace，还需验证 project override 的读取、编辑、停用、删除与 user fallback；否则该部分只报告自动化证据。动态 Connector、认证、工具调用、单人/群发消息、remote delete 拒绝、host-mediated artifact create/replace/cancel、prompt/resource Skill 出现/调用/断开仍按对应可达入口验证。artifact 需要同时核对 live bytes、provider/hash/size、ArtifactDescriptor、observed change、Trash recovery 与 broker receipt，并明确它不是视觉/语义质量验证。验收必须记录 external call count 或 provider 侧证据，不能只看卡片。

## 3. 未通过边界

本轮若未执行 OAuth 真实 provider、Windows/Linux 实机或 project-default-workspace Desktop 路径，只能逐项报告自动化；WebSocket、透明 401 重试和统一 live generation 当前仍不支持。
