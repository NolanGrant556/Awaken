## Awaken 当前接入

- provider ID：`anthropic`；access type：`api`。
- Base URL：`https://api.anthropic.com`；协议固定 `anthropic_messages`。
- 当前默认模型从 Awaken provider catalog 读取，见上方模型资料更新规则；本文不重复维护默认模型名称。
- 通过分页 Models API 同步目录；capability 仍按 exact model 与当前协议归一化。
- `src/llm/anthropic_messages.go` 负责 content blocks、tools、thinking/signature、stream 和 usage。

## 三协议兼容矩阵

## 鉴权、端点与模型

- Header：`x-api-key: <ANTHROPIC_API_KEY>`、`anthropic-version`、`content-type: application/json`。
- endpoint：`POST /v1/messages`；目录：`GET /v1/models`。
- 模型别名和带日期 ID 的稳定性不同。耐久 profile 使用精确 ID 时，不要在恢复时静默改成另一个模型。
- Bedrock、Vertex AI 和兼容网关是不同 provider route，不等于当前 Anthropic 直连合同。

## 上下文、多模态与工具

- 图片、PDF、tool use 和上下文窗口均按模型页与 Messages content block 合同判定。
- Read 原生 PDF 需要 `document`/PDF 合同和 exact model 能力；否则使用 Poppler 页面回退。
- thinking block 与 tool block 的顺序、signature 和历史重放必须保持；不能只保存可见文本。
- server tools、client tools 和 Awaken 本地 tools 权限不同，不能因名称相同直接互换。

## 提示词缓存

- 官方支持自动缓存和显式 `cache_control`；检查当前模型、最小 token、TTL 和可缓存 block 类型。
- Awaken 当前 Messages 合同使用 system block 的 `cache_control: {type: "ephemeral"}` 显式断点。
- usage 归一化 `input_tokens`、`cache_read_input_tokens`、`cache_creation_input_tokens`；三者按官方口径计算非缓存输入，不能把 read/creation 重复加入总输入。
- 修改 tools、thinking、effort、图片或前缀内容可能使缓存失效；更新时复核官方失效表。

## 推理开启关闭

- thinking 配置是独立合同，可能是 enabled、adaptive 或由模型默认控制。
- thinking 开启后，历史中的 thinking block/signature 可能必须原样返回；Awaken 不得丢弃后再伪造。
- 标题、压缩、Memory 辅助请求要关闭 thinking 时必须使用该模型当前允许的字段；不支持关闭就采用安全预算而不是发送无效字段。

## 推理强度

- `output_config.effort` 与 thinking 开关不同；effort 控制 token 使用倾向，不能替代 thinking 类型。
- Awaken 的 `low | high | max` 只有在 exact model capability 给出映射时显示。
- effort/thinking 改变会影响缓存 identity；辅助请求默认不得继承主调用的高 effort 而不受控。

## 用量、余额、限流与套餐

### 用量查询合同

- A 类：per-request usage 来自 Messages 响应，只描述本次请求。
- C 类：组织用量使用 `GET /v1/organizations/usage_report/messages`，成本使用 `GET /v1/organizations/cost_report`，支持时间桶和分页。
- 凭据：使用独立 Admin API Key，并发送 `x-api-key` 与 `anthropic-version`；标准 Claude API Key 不可代替。个人账户不可用该组织 API，Claude Enterprise Analytics API 又是另一套凭据合同。
- Awaken 当前：已用单独保存的 Anthropic Admin API Key 查询最近约 7 天的组织用量与成本。

- 429 可能受请求、输入 token、输出 token、加速层级或 spend limit 影响，读取官方 Header 和错误类型。
- Batch、prompt cache、长上下文和 service tier 的计价可能不同；按当前 pricing 页和组织账单解释。
- Claude 订阅产品与 Claude API 余额不是同一套餐，不能用网页订阅登录态替代 API Key。

## Awaken 落地规则

- Anthropic 直连只公开 Messages；不要在 UI 显示 Chat 或 Responses。
- Messages adapter 是 thinking signature 和 cache block 的唯一 wire owner；Renderer 只消费统一 reasoning/text 事件。
- 新模型从 Models API 出现不等于 images/PDF/tools/effort 已知；稀疏目录与官方能力表分开合并。
- 管理 Key 只能查询组织用量/成本，Renderer 不得取得明文。
