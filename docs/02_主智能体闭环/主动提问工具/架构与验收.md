# 主动提问工具架构与验收

## 功能定位

`ask_user` 是主智能体在信息不足、需要用户确认偏好或必须让用户做选择时使用的内置工具。它不是通用审批机制，也不恢复旧 `ApprovalCard`；它是 agent loop 内的一次主动澄清：

```text
LLM tool_call ask_user
-> ToolRuntime 拦截并校验 questions_json
-> runtime session 发出 UserQuestionRequested
-> AG-UI 映射为 AWAKEN_USER_QUESTION_REQUESTED
-> Desktop 在 RunStage composer slot 渲染问题卡片
-> 用户回答
-> POST /v1/runs/{run_id}/user-questions/{question_id}/answer
-> runtime session 发出 UserQuestionResolved
-> ToolRuntime 得到答案并回写 tool_result
-> Runner 继续下一轮 LLM
```

## 工程边界

- 工具注册位于 `src/tools/ask_user/`，通过 `src/tools/tools.go` 作为 builtin tool 加载。
- `ToolRuntime.Execute()` 是唯一拦截点；不要在 runner、server 或 Desktop 中绕过工具执行入口。
- 等待与恢复由 `src/runtime/session.go` 的 `AwaitUserQuestion` / `ResolveUserQuestion` 承担。
- HTTP 入口是 `POST /v1/runs/{run_id}/user-questions/{question_id}/answer`，只接受非空 `answer`。
- 协议映射位于 `src/protocol/agui`，事件名为：
  - `AWAKEN_USER_QUESTION_REQUESTED`
  - `AWAKEN_USER_QUESTION_RESOLVED`
- Desktop renderer 只消费 runtime/AG-UI 事件并通过 Electron bridge 回答问题；`@awaken/design-system` 不感知 runtime、SSE 或 Electron。

## Workbench 契约

主动提问卡片必须挂在 `RunStage` 的 composer slot 里，与群发消息审核卡片同级。它不能放进 `ExecutionFeed`，也不能在 `RunStage` 外新增独立定位容器。

当前 Desktop 实现：

- `App.tsx`：`UserQuestionPrompt` 渲染问题卡片，支持单选、多选、其他文本输入和多题回答。
- `runtime/reducer.ts`：维护 `userQuestions` active list；收到 resolved、terminal 或 cancelling 状态后清理。
- `run-narrative/projector.ts`：把 requested/resolved 投影为 narrative runtime notice。
- `styles/workbench.css`：只定义 composer slot 内卡片样式。

## 输入格式

工具参数为 `questions_json` 字符串，支持以下两种 JSON：

```json
{"questions":[{"question":"选择主题","options":[{"label":"深色"},{"label":"浅色"}],"multi_select":false}]}
```

```json
[{"question":"选择主题","options":[{"label":"深色"},{"label":"浅色"}]}]
```

约束：

- 至少 1 个问题。
- 每题必须有问题文本。
- 每题必须有 2 到 4 个选项。
- 选项 `label` 必填。
- 多选题用 `multi_select: true`。

## 与审批机制的区别

`ask_user` 不代表工具审批，也不能用于绕过零审批工具策略。它只收集缺失信息或用户偏好。文件写入、shell、MCP、连接器和群发消息仍按工具权限与运行时策略执行；其中群发消息仍只能走专用 `AWAKEN_MASS_MESSAGE_REVIEW_*` gate。

## 验收清单

代码级验收：

```bash
go test ./src/tools/ask_user ./src/agentcore ./src/runtime ./src/server ./src/protocol/agui
npm run typecheck --workspace=@awaken/desktop
npm run test --workspace=@awaken/desktop
```

产品级验收：

1. 按根 `README.md` 使用 `npm run open:desktop` 打开 Awaken Desktop。
2. 发送一个需要模型主动澄清的问题。
3. 确认中间区域底部 composer slot 出现问题卡片。
4. 选择选项并提交。
5. 确认卡片消失，run 继续执行，最终回答能使用用户选择。

Workbench 视觉验收：

- 空态 center composer 不应被主动提问卡片影响。
- 运行态 dock composer、`ExecutionFeed`、turn 分组和 marker rail 不应因问题卡片出现而错位。
- 多题卡片只在卡片内部扩展，不新增 `RunStage` 外层布局。
