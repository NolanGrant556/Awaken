# Desktop生命周期与发布架构及验收契约

## 权威范围

本文唯一拥有Desktop单实例、进程ownership、生成物清理、打包和发布验收。实际启动命令及成功确认只由根README入口契约拥有；本文不复制第二套运行说明。

## 当前产品目标

同一OS用户会话只能有一个Awaken产品实例。`apps/desktop/dist-electron`是生成物，不是开发入口；Design Gallery也不是产品窗口。

## 单实例ownership

1. Electron Main 在 ready 前把 dev 与 packaged 的 userData 固定到同一稳定身份；身份值由 [安全凭据存储与恢复契约](../../05_模型与供应商配置/安全凭据存储与恢复/架构与恢复契约.md) 唯一记录。
2. dev 与 packaged 使用该契约记录的同一 Application ID 和同一 identity payload。第二进程不得初始化窗口、runtime supervisor、project trash worker 或 pet window，只激活已有实例。
3. README 开发入口优先：启动 dev stack 前检查 Awaken 安装版主进程，先发出正常终止并等待；超时才强制停止。无法确认安装版已退出时，开发入口必须失败关闭，不能并行启动。
4. macOS 激活现有开发窗口时只能按已经识别的 Electron PID 激活。禁止通过 `open -a Electron.app` 激活，因为该调用在没有匹配实例时可能启动一份无项目参数的 Electron。
5. 生命周期脚本只能停止进程，不能删除 `/Applications`、用户自行安装的应用或其数据。安装副本的物理清理由用户或明确授权的维护任务负责。

旧版本不一定实现当前单实例协议，因此README入口的进程收拢是兼容防线；当前单实例锁是持续运行期间的主防线。

## Runtime与窗口清理

- renderer不感知runtime URL；Electron Main supervisor负责随机loopback启动、health、stop。
- 退出时先标记quitting，停止project worker，abort subscriptions，stop supervisor，dispose pet window，再 `app.exit()`。
- Windows/Linux关闭主窗口触发quit；macOS关闭窗口保留应用惯例，退出时仍执行完整清理。
- 生命周期脚本只能停止明确识别的进程，不能删除安装包或userData。

## 干净打包

`npm run dist:desktop` 是当前工作区的跨平台本地打包入口。`npm run dist:desktop:release` 是 macOS 签名发布入口。二者都必须先运行 `clean-desktop-package.mjs`，清除：

- `apps/desktop/dist`
- `apps/desktop/dist-electron`
- `apps/desktop/resources/bin`
- `apps/desktop/resources/runtime-archive`

清理后必须重新构建 UI 和当前平台所需的 `awaken-core`。发布 runtime archive 必须由同一次发布构建产生。`resources/runtime` 是 managed runtime seed 输入，不属于可无条件清空的输出。

macOS 与 Windows 发布任务必须在各自平台的全新 checkout / CI workspace 中运行。禁止把旧 `dist-electron`、旧 archive、另一架构的手工 App 或用户机器中的安装目录复制进 staging。代码签名和公证属于发布门禁；本地未签名产物不能标记为正式安装包。

## 当前不支持/不等同正式发布

- 本地未签名产物不等同正式安装包。
- `dist-electron/Awaken.app`截图不等同README开发实例验收。
- 不允许跨平台复制staging产物。
- auto-update不由本文宣称已支持。
- 本地生命周期测试不替代签名、公证、Gatekeeper或Windows安装/卸载门禁。

## 自动化验收

```bash
npm run test:desktop-lifecycle
npm --workspace @awaken/desktop test -- desktop-instance.test.ts
npm run typecheck:desktop
```

测试必须覆盖：

- macOS 安装版主进程识别，不把 Electron Helper、dev Electron 或 `awaken-core` 当作竞争实例。
- Windows `Awaken.exe` 主进程识别。
- 正常终止竞争实例后才继续开发入口。
- 清理旧 package output，同时保留 managed runtime seed。
- dev / packaged 单实例 payload 使用同一个 application id。

## 真实Desktop验收

1. 按根 README 正式入口关闭 Desktop，确认托管会话、dev Electron 和 dev `awaken-core` 均停止。
2. 按同一入口启动 Desktop，确认只出现一个 README 开发实例和一个窗口。
3. 再次按同一入口启动，确认只激活已有 PID，Electron PID 不变。
4. 按 README 入口的状态检查方式确认没有竞争中的 packaged Awaken。
5. 不把 `dist-electron/Awaken.app` 的窗口或截图作为验收证据。

发布验收还需核对目标平台、架构、签名和runtime manifest；macOS执行签名、公证、Gatekeeper，Windows执行安装、卸载、代码签名。任何未执行项必须明确标为未验收。
